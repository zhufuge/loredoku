# v0.7.14 — 题面：把作者要说的话，放在玩家看得见的地方

> **状态**：已实施（2026-10-28）。
> **来源**：`添加谜题游戏的全局线索配置（可多条，加到 data 中）和展示 / 添加游戏页的描述展示 / 添加结束语配置和展示`
> **范围**：`packages/shared`（三条上限常量 + schema 两个字段 + `PuzzleDraft` 类型）、
  `packages/web`（基本信息抽屉、谜题 store、游戏页左栏的题面 + 结算弹窗）。
> **无服务端改动、无迁移**：两个字段落在已有的 `puzzles.data` JSON 里，行结构没变。

## 0. 一句话

谜题一直有 `description`，但玩家侧只把它当一个工具提示（`title={game.name}` 那一类），
**全局线索**和**结束语**此前根本无处存放。这一版把三样东西收进同一处「题面」：
作者在「基本信息」抽屉里写，玩家在游戏页左栏读到描述与线索（标题下面、名册上面），
通过时再读到最后一句。

## 1. 三件事，其实是两个时刻

需求列了三条，但它们落在同一局游戏的两端：

| 时刻 | 内容 | 玩家在做什么 |
|---|---|---|
| 开局到中盘 | 描述 + 全局线索 | 一边看盘一边核对条件 |
| 通过那一刻 | 结束语 | 已经解完，愿意读一句作者的话 |

所以配置放在一起（抽屉里的「题面」一块，§3），展示却拆成两处 —— **不能合并**：线索
是**边解题边查**的，必须在视野里（§4）；结束语是**结算之后**的，提前出现就是剧透（§5）。

## 2. 数据：`clues` 与 `ending`

```jsonc
{
  "version": 2,
  "name": "雾港之夜",
  "description": "夜里下过雨，青石板上只剩五盏灯还亮着。",
  "clues": ["同一行里没有重复的编号", "阴影里没有编号，也没有人"],
  "ending": "灯灭了，花园还在。",
  "linkageColors": [],
  "characterSlots": [],
  "rosterCols": null,
  "map": { }
}
```

| 键 | 形状 | 默认 | 上限 |
|---|---|---|---|
| `clues` | `string[]` | `[]` | 8 条，每条 120 字 |
| `ending` | `string` | `""` | 200 字 |

**为什么不塞进 `characterSlots[].clue`**：那条 `clue` 属于**一个头像**（「他不在中央」），
渲染在参与者抽屉里，玩家要点开某一位才看得到。全局线索属于**整盘**（「每条斜线上的
编号都不同」），必须一直可见。两者共用一个字段会把「谁的条件」这件事说糊，撤销粒度
也会串（改一条全局线索不该记在某位参与者的历史里）。

**8 条不是随手定的数**：题面可用宽 228px（256 栏减 `pl-4` 16 与 `pr-3` 12）、行距 1.75，
一条线索在这个宽度上大约占一到两行；八条加一段描述已经到了 `max-h`（340px）的边上（§4.2）。
再多就得滚动，而一段需要滚才能读完的线索表，会逼玩家把视线从盘面挪开去做「找线索」这件事。
真要第九条，通常说明它该并进描述里。

**只加可选字段，不升 `PUZZLE_JSON_VERSION`**：老数据缺这两个键 → 解析时补默认；
新数据在老解析器里会被 strict 拒掉，但它本来也只会出现在新版本里。版本号留给
「老数据必须被改写才能读」那种变化（v1 → v2 的 `map` 换形状，见 `docs/data-json.md` §6.2）。

## 3. 配置：基本信息抽屉里的「题面」

`PuzzleInfoDrawer` 多了一块，排在「基本」之后、「参与者布局」之前：

- **全局线索**：一行一条，序号是位置（不是数据里的字段），行尾一个删除按钮，
  下面一个「新增线索」。新增会先插一条空行 —— 点了就有地方写，不必先想好措辞。
  计数用 `n / 8`，到顶时「新增」直接禁用，而不是等保存时才报错。
- **结束语**：三行文本框，带 `n / 200` 计数。

它和抽屉里其它字段一样是**草稿制**：改完点「保存」才进 store（一个撤销步、随草稿落库），
`取消` / 切面板的未保存确认、`isDirty` 判定都自动覆盖到了。

**空行必须在这里就消失。** 比较与提交都过一遍 `normalizeClues`（trim + 去空）：

- 只加了一行却什么都没写 → 归一化后与已提交值相同 → `dirty` 为假，不会凭空多一个撤销步；
- 真写了东西 → 落库时空行被丢掉，游戏页不会渲染出一行空白。

## 4. 展示一：题面在左栏，标题下面、名册上面

`components/game/GameBrief.tsx`。左栏从上到下是一条**不间断的读列**：

```
撕扇 4x4                                    00:12     ← 标题 + 尺寸 + 用时
午后的怡红院忽然静了。宝玉寻不着那把…              ← 描述（作者的话）
1   暖阁两人、雪地两人、桥径两人…                  ← 线索（这一局多出来的条件）
┌──────┐ ┌──────┐                                ← 参与者
└──────┘ └──────┘
```

四段之间**没有一条横线** —— 包括原来标题区那条 `border-b`（它正好压在参与者框头顶）。
它们读起来是同一段话的四个部分：哪一局 → 要我做什么 → 比基本规则多出什么条件 →
这些人怎么站。一条线会把「条件」和「人」切成两个不相干的区域，而线索说的正是这些人。

### 4.1 初稿的浮纸为什么撤掉了

v0.7.14 初稿是压在画布左上角的 272px 纸片（折叠、记忆、三个事件拦截一整套）。它解决了
「题面和盘面要同时看」，但代价是那张纸要么盖住玩家最常看的一角，要么被收起来 —— 两条
路都得付钱。

左栏本来空着一段：题面钉在名册**上方**之后，名册自己滚动、题面不会滚走，「同时看得见」
和「不遮挡」就同时成立了。折叠随之失去理由 —— 按钮、`localStorage['loredoku.gameview.brief']`、
`UI_Z.gameBrief`(15)、三个 `stopPropagation` 一并删掉（组件也不该再叫 Sheet）。

### 4.2 排版上的四条

| 项 | 值 | 理由 |
|---|---|---|
| 左边缘 | 16px（`pl-4`） | 标题行是 `p-3 + pl-1`，游戏名正落在 16px。描述若从 12px 起头，这 4px 挨着五行文字会读成「没对齐」 |
| 描述 | `text-xs` / `leading-[1.75]` / `text-muted-foreground`，收起态 `line-clamp-3` | 作者的话，颜色退一档；超过三行折起来（§4.3） |
| 线索 | 一张纸条：`rounded-md border bg-card shadow-paper`（悬停抬 2px 换 `shadow-lifted`），**按字宽收身、居中**，正文 `text-foreground/90`，**无序号** | 纸条自己一条一条摞着，边界已经说明「换了一条」；颜色深一档 —— 它是拿来用的条件。收身与居中见 §4.3 末 |
| 高度 | `max-h-[min(46vh,340px)]`，超高自己滚 | 描述上限 500 字；该滚的是题面，不能把名册挤没 |

描述与线索之间只隔 `mt-2.5`，没有线：纸条的边框已经说了「换段了」，再画一条是重复。
没有描述时（01–03 那三关）线索自己起头，不留空档；两样都没有就整块不渲染，标题与名册
之间不留一段空白。

实测（1440×900）：标题与描述的左边缘都在 **16px**，线索纸条居中（不再贴在 16px 上），
参与者卡片在 **8px**（名册 padding）；最后一条线索到第一张卡片 20px（题面 `pb-3` 12 +
名册 padding 8）。

### 4.3 描述折起来，线索摞成纸条

第二轮的两处改动，都是「让名册多留一点地方」：

**描述可折叠。** 默认 `line-clamp-3`，真放不下才在右下挂一枚「展开全文 ⌄」（11px、
无边框、靠右）。三件事值得记：

1. **先夹上、再量。** `scrollHeight > clientHeight` 是唯一判据，但不夹的时候两者相等 ——
   第一版写成「先量、溢出才夹」，于是永远量不出溢出，四行长文就那么摊着。顺序反过来
   就对了：三行以内的短描述被 clamp 没有任何变化，白夹一次没成本。
2. **只在收起态量。** 展开后 `clientHeight` 等于全文高度，量出来是「没溢出」，按钮跟着
   消失 —— 然后就再也收不回去。代价是展开着的时候不重判，而侧栏宽度本来只随参与者
   列数变，可以接受。
3. **靠右，不是靠左。** 贴着正文左边缘、行距又和正文一样时，「展开全文」会被读成第四行
   （实测就是这样）；推到右边，它才从行文里出来，站到「更多」的位置上。

**线索是一张纸条。** 外框 + `shadow-paper`（静置纸影），悬停时抬 2px 并换成 `shadow-lifted`；
序号整条删掉：

- 它们是**同时成立的条件**，不是步骤。给 1 / 2 / 3 会让玩家按序读，而解题时真正要对照的
  是「这一条和盘面哪一处有关」，顺序只是作者的写法。
- 入场上浮 4px + 淡入，`--motion-slow`(260ms) / `--motion-ease-out`，每条错 45ms（封顶 6 条）。
  八条同时冒出来只读到「一堆」，错开才数得清有几条。
- 用 `translate` 不用 `transform`（同一个理由记过三次了：`transform` 关键帧会覆盖整条
  transform）；`both` 必写，否则延迟期间会先闪一下再淡入。
- **悬停抬起 2px、影子加深**（`hover:-translate-y-0.5` + `hover:shadow-lifted`，180ms）。
  只动**物理层**：没有 `cursor-pointer`、没有主色描边、没有放大 —— 那三样是「点下去会发生
  什么」的承诺，而它不是按钮（`docs/design-system.md` §3.9 第 4 条）。影子加深 + 一两像素
  的位移读作「这张纸被抬起来一点」，用的还是它落下时那套纸的语言。
  180ms 而不是 120ms：位移只有 2px，太快像抖动；和入场那 260ms 也接得上。
- `prefers-reduced-motion` 下把**延迟**清零（`*` 那条只压时长，延迟还在；而 `both` 会让
  纸条在延迟里停在 `opacity: 0` —— 等于「进来什么都看不到」）。悬停的过渡由 `*` 那条
  压到 0.01ms，剩下的是一张直接换影子的纸 —— 抬升是装饰，不做静态替代。

**纸条按自己的字宽收身，居中**（第三轮）。之前它撑满 228px 的栏、文字靠左，一条十几字的
线索右边会空出半张纸 —— 读起来像「表格里的一行」，而不是一句条件。改成 `w-fit mx-auto
text-center` 之后，宽窄由内容决定，摆正中间，像一枚标签；长线索有 `max-w-full` 兜着，
换行而不是溢出到名册上。

代价要说清：**左边缘那条规矩对线索不再成立**。§4.2 里「同一列的文字共用一条左边缘」
管的是**行文**（标题、描述），纸条是**物件** —— 物件按自己的大小居中，行文才要对齐。
一条、两条时看不出差别；真到七八条长短不一时，纸条会呈一条参差的竖列（这正好是桌上
一叠便笺的样子）。若作者更想要齐边，把 `w-fit` 去掉、留 `text-center` 即可。

## 5. 展示二：结束语只在通过时说话

结算弹窗仍是 v0.7.11 的那一个，只在**通过**分支里多一段：

```
提交通过
用时 04:12。
───────────────
灯灭了，花园还在。      ← 楷体 14px / 行高 1.9
[关闭] [再玩一次]
```

三个刻意的选择：

- **没有标签**。不写「结束语：」—— 那是作者的声音，不是界面在解说。一条细线把它和
  上面的用时分开，就够说清「这是另一件事」。
- **楷体 14px**。`.font-kai` 在这个尺寸上笔锋认得出，又不会像标题那样抢；（`.impeccable.md`
  原则 5：手写体只做点睛）。实测计算值 `font-family: 霞鹜文楷`、`14px / 26.6px`。
- **只出现在通过时**。未通过的分支一个字都不加：那一屏正在告诉玩家「谁不对」，
  多一句话只会让人以为自己也快赢了。开局时更不该出现 —— 那是剧透。用例断言了
  开局时 `document.body.textContent` 里根本没有那句话。

## 6. 名册卡片：触碰悬浮，主题色从头像铺开

第三轮的另一半，改的是**参与者卡片**（`components/map-editor/ParticipantPanel.tsx`），
四条要求来自同一句反馈：不要两层高亮线 / 触碰悬浮 / 卡片里铺满主题色的淡透明色 /
从圆头像慢慢过渡铺开。

### 6.1 两层线是怎么来的

原来是两条颜色落在同一条边上：

```
┌─────────────┐   ← 外面 4px 处的 2px 主色环（选中）
│ ┌─────────┐ │   ← 2px 纸色缝隙
│ │ 1px 主色 │ │   ← 卡片自己的描边（选中时也是主色）
```

悬停时更挤：`hover:border-primary` 改的正是那 1px，而「指针激活」的 2px 环同时存在 ——
两条线叠在同一个边缘上，扫一眼只剩「粗了一圈」，分不出哪个状态。

第一步（同日）：描边收成透明，只留外面那道环。第二步（用户接着说「点击选中高亮时，
外出蓝色高亮线和内部中间不要有空白」）：那圈纸色缝隙本来就是「框浮在外面」的错觉，
现在把描边改回主色 —— 1px 描边 + 2px 外扩同色**相接**，是一条 3px 的连续边，中间没有
任何空白，也不是两条线（同一色、无间断，扫视读作一条）。

与「指针激活」的 2px 单环因此改由**粗细**区分，另外还有抬起 2px 与反色徽标两条不同
维度的线索 —— 不必再去数「中间有没有缝」。

| 状态 | 线 | 填充 |
|---|---|---|
| 静置 | 1px `border-border` | `bg-background` |
| 悬停 | 指针激活那一道 2px（若父层传了），否则无线 | 主题色 0.16，从头像铺开 |
| 选中 | 一道 3px：1px 主色描边 + 2px 主色外扩（无缝）+ 向下投影 | 同上（不收回） |

实测（选中卡的左边缘剖面，x 从外到内）：

```
… 240,240,237 │ 50,99,133 │ 50,99,133 │ 50,99,133 │ 228,231,218 …
   纸           ←─── 3px 主色，无间断 ───→           卡内（已铺开主题色）
```

### 6.2 那层色：`@property --tint-r` + 半径

`index.css` 新增 `.participant-tint` 与 `@property --tint-r`。卡片里第一个子节点是一层
绝对定位的 `span`，背景是一条以**头像圆心**为心的径向渐变，半径 `--tint-r` 从 0.5px
长到 320px：

- **它是底色，不是膜**：`z-index: -1` 让这层沉到内容下面，卡片根节点用 `isolate` 接住
  这个负层级。少了这两行，绝对定位的兄弟会排在普通流内容之上 —— 那层颜色糊在头像上，
  头像像被换了张图（用户：「主题色铺开不要覆盖头像」）。负层级又不能没有 `isolate`：
  没有它，`-1` 会穿到祖先 stacking context 里、沉到卡片自己的底色下面，于是什么都看不见。
  实测头像圆盘边缘像素在悬停前后都是 `126,154,94`，一动不动；染色的只有圆盘外的卡纸
  （`248,246,242 → 228,231,218`）。
- 卡片 110×196，头像圆心在 (55, 55)，到最远的那个角约 **151px**；渐变在 55% 处仍是
  实色（176px），所以铺到最后整张卡是**均一的一层**，右下角不会留一块没染到的淡角。
- 只动**半径**，不做整层 `scale`：缩放会把渐变的软边一起放大，中途扫出一圈生硬的边
  —— 纸背光（v0.7.13 §10.4）踩过同一个坑。
- 只做整层淡入也不行：那是「颜色本来就在、刚才只是透明的」，读成闪烁，看不出「从哪儿
  开始的」。半径从圆心长出去，才看得见这层色属于**这枚头像**。
- 收敛方向走基线规则（`--motion-retract` 520ms），铺开走 `[data-tint='on']`
  （`--motion-tint` 560ms + `--motion-ease-spread`）。开关是根节点上的 `data-tint`，
  悬停与选中都算「点亮」；React 里不留「正在收回」的状态，属性一撤颜色自己缩回去。

透明度定 **0.16**：0.12 与纸底只差 15 个色阶（并排才看得出），0.20 开始读成一块色卡、
把 11px 的线索文字压下去。白色的参与者退回主色 —— 白上加白等于什么都没发生。

### 6.3 抬起 2px，但影子不是 `--shadow-float`

`--shadow-float` 配 28px 扩散，是给对话框 / 抽屉写的。落到 110px 宽、格间距 14px 的
名册里，那层影子会漫到左右邻居的缝里，看着像整片都脏了。所以新增一档
**`--shadow-hover`**：只把影子推下来 4–8px，够说明「这张卡片离了纸面」，又不出自己那一格。

抬起用 `translate`（不是 `transform`）：选中时那次鼓起（`roster-select-pop`）动的也是
`translate`，同一条轨才接得上 —— 抬起不会在动画开头被抹平，落下也不跳。影子与位移都
补间 180ms，指针扫过一排卡片时是「一张一张慢慢落下来」，不是三张里有影、一张没有。

### 6.4 角上的序号徽标：两条弧要合成一条

用户第三轮看的是放大截图：「高亮环和序号间有白色区，应该是和内部圆角没对上」。两件事叠在
一起，第二件是第一件的后果：

1. **圆角确实没对上。** 徽标贴在 **padding box** 的角上（`position:absolute; top/left: 0`，
   也就是描边内侧 1px），那一圈的内圆角比外圆角小 1px。徽标却一直沿用卡片的外半径
   `6px` —— 弧比内弧切得更深，两段弧之间露出一道**真**的 1px 纸白月牙。选中时徽标是主色、
   描边也是主色，那道白就格外刺眼。改成 `PARTICIPANT_SLOT_RADIUS - 1`（5px）。
2. **改成 5px 之后还剩一道。** 两段弧现在同心了，但各自都要抗锯齿：交界那一像素，描边
   盖一半、徽标盖一半，纸白漏出约 35%（1x 截图里是一像素的浅线，放大后就是「一道弧」）。
3. **1px 同色外扩。** 徽标填主色时加 `box-shadow: 0 0 0 1px hsl(var(--primary))`：外扩把
   弧半径从 5 推到 6，正好落在卡片的外弧上 —— 两条边合一条，抗锯齿只剩在轮廓上（和卡片
   其它三个角一样）。只在填色时加；纸白徽标加这一层会盖住卡片自己的描边。

实测（1x 设备像素，选中卡左上角 15× 放大）：改前有一道浅弧；改后整块是一个实色角，外沿
一条平滑的边；未选中态卡片的细框仍然连续，没有缺口。

## 7. 向后兼容：旧版本行没有这两个键

已发布的游戏读的是**冻结的谜题版本行**，服务端 `toDetail` 只做层级归一
（`absorbLegacyPuzzleDraft`），**不补字段**。v0.7.14 之前发布的每一行都没有
`clues` / `ending`，所以读取侧三处都写了 `??`：

| 位置 | 处理 |
|---|---|
| `PuzzleDraft` 类型 | 两个字段声明为**可选**（`clues?: string[]` / `ending?: string`），类型本身就说清「可能没有」 |
| 游戏页 | `detail?.puzzle?.clues ?? []`、`(detail?.puzzle?.ending ?? '').trim()` |
| 谜题 store | `init` / `applyDraft` 读进来时给 `[]` / `''` —— 抽屉的草稿与 dirty 比较都假设它们是 `string[]` / `string` |

另有一步别处没有的清理：`GameBrief` 自己再滤一遍空串。导入的文件（§2）允许带空行，
schema 不替作者删内容，所以这一层得有人兜。

新增用例钉的都是**能失败的**部分：

- **schema**：缺键 → 默认空；trim 与顺序；8 条 / 120 字 / 200 字三处上限；旧 payload 能过。
- **抽屉**：已提交值能回填；新增 / 删除的是**被点那一行**而不是最后一行；只加空行不算编辑
  （`dirty` 为假、保存禁用）；提交前 trim 且丢空行；第 9 条时「新增」禁用；结束语 trim 后才出抽屉。
- **题面**：没内容就不渲染（含纯空白描述）；描述排在线索**之前**；线索渲染的是原文、**不带序号**；
  没有描述时线索自己起头；旧数据里的空行被跳过；描述**放不下才出「展开全文」**，
  点一下展开 / 再点收起，且展开后按钮不消失（用假尺寸造溢出，同 `ClampedText.test.tsx`）。
- **游戏页**：题面在**左栏**（不在 `<main>` 里）、文档顺序是标题 → 题面 → 名册，且结束语
  **开局不可见**；通过时弹窗给出结束语且不带「结束语：」标签。
- **参与者卡片**：选中只留一道线（有 `border-transparent`、没有 `border-primary`）；铺开的
  颜色来自参与者**本人**的主题色（`#7E9A5E → rgba(126, 154, 94, 0.16)`），白色退回主色，
  圆心落在头像正中（`--tint-y: 55px = 8px 内边距 + 94px 头像的一半`）。
  悬停那半条（`translate` / `data-tint`）在 jsdom 里测不了 —— 它不给 `:hover` 算样式，
  由上面那两行 CDP 实测兜着。

## 10. 看过没做

- **谜题只读预览页（`PuzzleViewPage`）不显示题面**。它是作者的检查页，玩家看不到；
  要看效果就部署一版 —— 少一处「两份实现各自漂移」的机会。
- **线索不能排序、不能富文本**。现在只有「写、改、删」；顺序就是录入顺序。要排序得先
  决定它是「列表」还是「有身份的条目」（后者要 id、要迁移），这一版不值得。
- **不在编辑器画布上实时预览题面**。抽屉是 320px 宽的右栏，题面在游戏页是 256px 的
  左栏（`pl-4` 起头），在抽屉里模拟会失真；等有多人协作或频繁调参的需求再说。
- **结束语不进游戏列表 / 部署对话框**。它是「一局结束时的一句话」，不是游戏的简介。
