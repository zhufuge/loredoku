# 一次手势 = 一串动作：按住滑动 · 搬家 · 计时 · 结算（v0.7.11）

> **状态**：**已实施**（2026-10-27）。
>
> 需求原文（三块）：
> ```
> 游戏页面
> - 点击放置参与者编号和禁止符号或使用清除橡皮擦时，可以按住鼠标滑动，划过的格子进行对应点击的操作。
> - 去掉 参与者 5/5 这个标题行
> - 提交状态不记录，提交通过不改成勾

> - 长按参与者放置和清除时，计时圈不是从点击开始就出现，延迟一下再出现，避免单点时就出现。
> - 不用提示已恢复上次摆放
> 谜题编辑+游戏页面
> - 已选中的参与者的高亮，优化
> - 点击选中时的一刻，增加视觉动效
> 部署页面
> - 不需要前往谜题列表按钮

## 0. 一句话

这九条需求其实在说同一件事：**游戏页把「一次点击」当成了唯一的输入单位**，
而人手上的动作是**连续**的 —— 想排一排 `×` 要按十几次，想改主意只能先擦再放，
想看看自己玩了多久则根本无从查起。这一轮把输入从「点」放宽到「手势」：按住划过
的格子依次落笔（§1），长按另一个格子把头像**搬**过去而不是报错（§3），
计时从打开页面的那一刻走到按下提交的那一秒（§4），提交则从「打个勾」变成一次
**结算**（§5）。顺带把三处「说了但没说清」的地方改掉：进度环不再为单点闪一下（§2.1）、
选中态从「碰一下」里分出来（§7）、部署页不再需要绕去谜题列表（§8），
路径撞车也从「一句话让你自己想办法」变成一次选择（§9）。

## 1. 按住滑动：一个手势，多格落笔

`main` 上的指针处理原先只有「按下起长按定时器 / 抬手走 click」两条线。现在是三条：
按下记一笔 `paintRef`，滑动跨格就落笔，抬手收尾。

```ts
paintRef.current = { start: cell, lastKey: cellKey(cell.x, cell.y), painted: false };
```

**按下那一刻不落任何东西。** 这是整段代码里最不直观的一行，理由只有一个：
放置态下按下的那一格还可能变成**长按**（放头像）。若按下即落编号，长按的起点就是
一个「编号格」，画面上会先闪一个编号再变成头像 —— 一个手势做了两件事。

真正落笔发生在**指针进入第二个格子**时，而且起点要先补上：

```ts
if (!paint.painted) {
  paint.painted = true;
  cancelCellPress();                                  // 滑出第一格 = 拖动，不是长按
  dispatchCell(paint.start.x, paint.start.y, 'number', { quiet: true });
}
paint.lastKey = key;
dispatchCell(cell.x, cell.y, 'number', { quiet: true });
```

### 1.1 三个细节

**`paintedRef` 吞掉手势的尾巴。** 浏览器在 `pointerup` 之后还会补一记 `click`。
按住滑动时若照常处理它，最后一格会被「切换」两次（放上又取消）—— 看起来像涂掉了
自己刚涂的那一格。所以一笔真正的滑动会置 `paintedRef`，随后到来的 `click` 直接返回。

**划太快时补一笔。** 手指（或鼠标）从 A 甩到 B 而中间没触发 `pointermove` 是常见的，
`onPointerUp` 里因此也检查了一次落点：

```ts
if (paint && !paint.painted && !cellPressRef.current?.fired) {
  const cell = toCell(event.clientX, event.clientY);
  if (cell && cellKey(cell.x, cell.y) !== paint.lastKey) { /* 起点 + 落点各补一格 */ }
}
```

**滑动时静默。** `dispatchCell` 新增 `options.quiet`：划过一行十余格，
其中几格可能不可站立，弹十几个 toast 既挡住棋盘又说不清是哪一格。
单点（`quiet` 不传）仍然照常说明原因 —— 那一次点击是玩家明确的意图，需要解释。

### 1.2 为什么棋盘一律读 `placementRef.current`

一次滑动会在**同一个事件循环**里连着调用好几次 `dispatchCell`。读渲染闭包里的
`placementState`，第二次调用会拿着旧棋盘把第一次的结果覆盖掉 —— 表面上「划了三格
只留下一格」。所有写操作因此共用一个镜像 ref + `updatePlacement`，读的永远是此刻。

## 2. 长按：环延迟出场，落笔有回执

### 2.1 环不再为单点闪一下

上一版（`v0.7.10.md` §3）按下即挂载进度环。问题是**单点根本不会长按**，它却会在
按下的第一帧闪出一圈 —— 那是在预告一件不会发生的事。

```ts
export const GAME_LONG_PRESS_MS = 500;
export const GAME_PRESS_RING_DELAY_MS = 160;   // v0.7.11
```

环延迟 160ms 才挂载，因此只画**剩下的 340ms**（`durationMs = 500 - 160`）：
画满的那一帧仍然是头像落下的那一帧，与上一版完全一致。抬手早于 160ms 就什么都不闪。
格子环与清除按钮环共用同一个延迟 —— 同一个手势在界面上只能有一种样子。

### 2.2 盖章：放下的东西「落下」一次

编号与 `×` 放下的一刻各播一次 180ms 的缩放（0.5 → 1.08 → 1），类名 `place-pop`。
它是**一次性**的，所以不挂在棋盘状态上，而是一张「格子键 → 参与者编号」的脉冲表：

```ts
export type GamePlacementPulse = Readonly<Record<string, number | null>>;
```

为什么是表而不是「最后一格」：按住滑动会连着放好几格，单值会让前一格在动画播到一半时
被摘掉类，缩放猛地弹回原样 —— 看起来像闪了一下。每格 400ms 后自己过期
（`GAME_PLACE_PULSE_MS`，比动画长，留一点余量给同帧的其它格子）。

`×` 的脉冲值是 `null`（编号是 1 起的正整数，不会与它混淆）。

**为什么用 `scale` 属性而不是 `transform`**：见 `v0.7.10.md` §6.3 —— SVG 上
`transform` 的关键帧会覆盖元素自身的 `transform`，把这个字形移走。CSS 侧配套
`transform-box: fill-box; transform-origin: center;`，否则缩放绕的是 SVG 的原点。

## 3. 搬家：长按另一个格子

「已经放在这里了」以前是一条**拒绝**（`'elsewhere'`）。它假设玩家的每一次长按都是
最终答案，而实际动作是「不对，是那边」—— 玩家改主意不是错误。

```ts
const previousAvatar = avatarCellOf(state.board, input.participantId);
if (previousAvatar) delete board[cellKey(previousAvatar.x, previousAvatar.y)];
board[key] = { kind: 'participant', index: input.participantId };
```

`PlacementBlock` 因此少了 `'elsewhere'`：唯一性由「搬家」满足，而不是由「报错」满足。
被拒绝的路径仍然存在（不可站立、`×`、编号满格），只是不再是这一条。

### 3.1 自动 `×` 的回滚：给 `×` 加一个 `auto` 标记

同行同列的 `×` 是**派生**的：某位头像站在那里，它的整行整列就不许放东西。头像搬走
之后，那些 `×` 就没有依据了 —— 留在棋盘上等于告诉玩家「这一行还是不能放」。

区分「自动补的」与「玩家点的」靠一个新标记：

```ts
z.object({ kind: z.literal('forbidden'), auto: z.boolean().optional() })
```

`pruneAutoForbidden` 只删**带 `auto`** 且**不在任何头像的行列上**的格子：
玩家自己点的 `×` 一条都不动；另一位头像仍然占着的行 / 列也照旧保留（那些格子的
「不能放」依然成立）。搬家的落子与擦掉头像都各走一次这个清理，且都与本次操作合并为
**一个**撤销步。

> 为什么不用「重算整张棋盘」：重算会把玩家手动放的 `×` 一并抹掉，那是另一件事。

## 4. 计时：累计毫秒，不是开始时间戳

```
打开游戏 → 开始走 → 关掉页面 → 记到本地 → 第二次进来接着走 → 点提交 → 停表
```

存的是**累计用时**而不是开始时间戳。跨会话的墙钟差里混着吃饭、睡觉、关电脑的时间，
那不是玩家在想的时长。键与摆放存档同构（`loredoku.game.timer.{slug}`），
指纹也共用（`gridSize` + `participantCount`）—— 同一路径重新部署成另一个谜题后，
旧计时不再属于这一局，整条作废。

| 时机 | 动作 |
|---|---|
| 每秒 | `setInterval` 只刷新**显示**（`mm:ss`，超过一小时补 `h:`） |
| 每 5 秒 | 落盘一次（意外关闭最多丢 5 秒） |
| `pagehide` / `visibilitychange:hidden` | 各补一次 |
| 点提交 | `pauseTimer()` → 停表并立刻落盘 |
| 再玩一次 / 重新开始 | `resetTimer()` → 归零 + **删键**（不写「用了 0 秒」） |

显示用 `tabular-nums`：秒针每跳一次，整行否则会左右抖一下。

## 5. 提交 = 结算

提交不再是「打个勾」。勾是一个要记住的状态，而它只会在下一次进来时变成一句谎话
（玩家看到自己没做过的勾）。所以：**提交状态不落盘**，按钮也不变。

弹窗只有一个 `result`，两种结局：

| | 标题 | 内容 | 按钮 |
|---|---|---|---|
| 通过 | 提交通过 | 用时 `mm:ss` | 关闭 / **再玩一次** |
| 未通过 | 提交未通过 | 只说**谁不对** | **继续游戏** / 重新开始 |

### 5.1 「只说谁不对」

原来的清单把每一处同类 / 同列 / 位置条件都摊开写（十几条），像一张调试报告。
`summarizeIssues` 按参与者归并：同一个人有多条问题时只留一句 —— 没上场的说
「未放置」，其余一律说「位置不对」。归并规则：`unplaced` 优先（一个还没放下的人，
谈位置没有意义）。

### 5.2 三个动作的语义

- **再玩一次**（通过后）：清棋盘 + 清历史 + 重新计时；
- **重新开始**（未通过时选它）：同上 —— 需求原话就是「再玩一次和重新开始，
  重新计时，清空历史记录」；
- **继续游戏**：只关弹窗，接着走表、接着摆。

「清空历史记录」是字面意义上的：`past` / `future` 都丢掉，重开这一局之后撤销
不会把上一局的摆放捞回来。

## 6. 存档瘦身：版本 2

`submitted` 从 `StoredGameProgress` 里删掉，`GAME_PROGRESS_VERSION` 从 1 升到 2，
旧存档整体作废（宁可空白，不可错乱）。空盘一律删键 —— 不再留一条「{}」的记录。

## 7. 名册：选中从「碰一下」里分出来

「预览激活」（指针路过）与「选中」（手上正拿着的那一位）此前共用同一圈 2px 主色环，
只靠深浅区分，读不出来。选中改为**双环**：

```
0 0 0 2px hsl(var(--background)), 0 0 0 4px hsl(var(--primary))
```

里圈纸色把卡片与外环隔开，卡片底色转成 `bg-primary/10`，点中的一刻播一次
180ms 的鼓起（`roster-select-pop`，1 → 1.045 → 1）。游戏页传
`selectedSlotIndex={mode.kind === 'placing' ? mode.participantId - 1 : null}`。

同页顺带删掉「参与者 5/5」那一行（新 prop `hideHeader`）：那是编辑器的语法
（这块面板是「参与者」这个资源本身），玩家端名册头上已经有「游戏名 + 尺寸」了。

## 8. 部署页：自己发起部署

页头的「前往谜题列表」删掉了 —— 它唯一的用处是绕路去做这件事，而绕过去之后还要
自己找回那一版。空状态的主按钮同样是「部署」。

弹窗第一位就是**谜题版本**，选中之后名称 / 访问路径 / 封面 / 难度全部按那个版本回填：

```tsx
<GameDeployDialog puzzle={null} versions={versions} resolveExistingGame={existingGameFor} … />
```

- 版本列表只取 `kind: 'version'`（草稿行部署不了，列出来只会让人点了才发现），
  已部署的那一版在选项里标注「（已部署，将覆盖）」；
- `resolveExistingGame` 让「某个版本已经部署过」的那条部署参与回填 —— 同一个版本
  再部署就是覆盖它，路径应当沿用已公布的那一条；
- 未选版本时整张表单禁用（`busy`），而不是填完才在提交时失败。

## 9. 路径冲突 = 一次选择

「访问路径已被占用，请更换」这句话把问题推回给了作者：他想要的往往是「这条链接
就归我」，于是得先去部署页把对方撤掉，再回来重填一遍。

### 9.1 服务端：结构化说明 + `overwriteSlug`

不再只抛一句中文。冲突时 `error.details` 带一份 `GameSlugConflict`：

```ts
{ kind: 'slug-taken', slug, name, puzzleName }
```

前端要弹一个带**覆盖**按钮的弹窗，它得知道被占的是哪条路径、占位的是哪个游戏，
才说得清「覆盖谁」。靠正则匹配消息文本做这件事，是迟早会坏掉的做法。

`deployGame` 的 body 多一个 `overwriteSlug`：为真时 `resolveSlug` 返回
`replaceGameId`，`upsertGame` 在同一个事务里先把占位那条**假删**（`deleted_at`）——
部分唯一索引 `uq_games_slug_active` 随即释放 slug —— 再删自己的旧行、插新行。
覆盖是假删而不是硬删：与「取消部署」同一种退场方式，只是由一次部署顺带完成。

### 9.2 前端：AlertDialog + 原样重发

`useDeployGame` 多一个可选参数 `onSlugConflict`：传了它的调用方（部署弹窗）收到
结构化说明后弹出「覆盖 / 取消」，没传的调用方保持原样直接 toast。冲突时**不发**
那条 toast，否则一句话和一个弹窗会同时说同一件事。

确认覆盖时**原样重发**上一次的请求，只多一个 `overwriteSlug` —— 让作者只回答
「覆盖吗」，而不是重新填一遍表单。

## 12. 看过没做

- **滑动擦除的「一笔撤销」**：现在按住滑动每一格是一个撤销步（十格 = 十步）。
  合并成一步需要在手势结束时把中间态压成一条历史，而玩家往往希望在滑动中途就能
  逐步回退 —— 两种期待互相矛盾，先保持逐步。（记成债）
- **`v` 键 / 长按的键盘等价物**：游戏页目前没有键盘放置，滑动的键盘对应物
  （按住 Shift + 方向键）一并留到有需求时再说。
- **计时的暂停按钮**：需求只要求「打开走、关掉存、提交停」，没有暂停。
  中途手动暂停会让「用时」变成一个可以被修饰的数字，暂不提供。
- **提交未通过时高亮出错的人**：现在只说名字，棋盘上不做任何标记。加标记等于
  泄露答案（「这个人位置不对」本身就是信息），所以停在这里。

## 13. 编号是草稿，头像才是落子

需求把同一件事说了两遍（「编号不算参与者」/「标号不能代表参与者」），落在代码里
是两处判断：

### 13.1 判卷只认头像

`validatePlacement` 里原本读 `participantPlacementAt`（没有头像时，**唯一**的
候选编号也算「他在这儿」）。这是 v0.4.1 的宽容：只点了一格的人不该被报「没放」。

但宽容的前提是「提交」只是一次自查。现在它是一次**结算**（§5），结算就不能拿
草稿当交卷 —— 编号是玩家自己数格子时的铅笔痕，它甚至可能落在错的格子上。

```ts
// 之前
const coord = participantPlacementAt(board, participantId);
// 现在（v0.7.11 第二批）
const coord = avatarCellOf(board, participantId);
```

`participantPlacementAt` 保留下来：画面上仍然成立（联动高亮、提示层都按它指的
地方画），只是不再决定交卷的结果。`unplaced` 的两句文案没动 —— 「尚未确认（N 格
只有候选编号…）」现在读起来正好是它字面的意思。

### 13.2 按钮：没放完就点不动

新增 `allParticipantsPlaced(board, slots)`：名单上每位非空槽都必须有头像。页面
用它禁用提交按钮，标题也从「提交当前摆放（先校验）」换成「还有参与者没放好，
放完才能提交」。

为什么是禁用而不是「点了再告诉你还差谁」：还差谁，**名册里就写着**（已放的卡片
淡下去，亮着的就是没放的）。让玩家先按一下再读一份清单，是把一件已经看得见的事
又念了一遍。`submit()` 里同时留了一道守卫，防的是快捷键、旧闭包与测试。

## 14. 放不进去的格子：手势根本不开始

上一版的顺序是「环先画，500ms 后动作被拒，再把环收回」。问题在**环画满的那一帧**
—— 玩家读到的是「按成功了」，收回只是补救。

现在 `startCellPress(x, y, participantId)` 在挂定时器之前就问一次
`placementBlockReason(..., variant: 'image')`：

- `non-standable`（格内有不可站立的物品）、`forbidden`（已经标了 `×`）、
  `avatar`（这位自己的头像）→ **直接返回**：没有环、没有 toast、棋盘一格不动。
- 别人的头像格**不在**这个名单里 —— 长按落在那里是「换人站这儿」（整格替换），
  与「编号盖掉头像」不是一回事。

短按（编号）走另一条：`describeBlock` 里 `'forbidden'` 也改成了 `null`。既然
悬停时提示层已经不画那个编号（见 §15.2），点下去再弹一句「请先清除」就是自相
矛盾。非站立格保留说明 —— 那是玩家可能真的没看出来的事。

## 15. 编号不再盖掉一张脸

### 15.1 规则

`placementBlockReason` 的 `participant` 分支重写：

```ts
if (placement.kind === 'participant') {
  if (hasParticipant(placement, participantId)) return 'avatar';   // 自己的头像
  return variant === 'image' ? null : 'avatar';                    // 别人的头像：只有长按能换人
}
```

改之前，点别人的头像格会走九宫格追加，`placeParticipant` 的 `numbers` 分支整格
替换 —— 那张脸当场被三个编号顶掉。旧用例还专门钉过这个行为
（「appends a second participant as a number, hiding the avatar」），这次一并改写。

### 15.2 悬停也不再预告

`resolveToolHint` 在放置态下，遇到 `forbidden` 或 `participant` 格返回 `null`。
提示层的职责是「松手会发生什么」；既然什么都不会发生，就不该有那一格字。

## 16. 计时挪到标题行

右栏底部那三行统计（已放置 / 可回退 / 用时）里，用时其实不是统计，是**这一局的
元信息**。它现在在左栏标题行最右边，与「游戏名 + 尺寸」同一行：

```tsx
<div className="flex items-baseline gap-2 pl-1">
  <p className="min-w-0 flex-1 truncate text-sm font-semibold">…</p>
  <span className="shrink-0 text-sm font-semibold tabular-nums text-muted-foreground"
        data-testid="game-timer">{formatElapsed(elapsedMs)}</span>
</div>
```

- **不要图标**：`Timer` 已从 import 里删掉。秒表图标在这里只占宽，字体数字本身
  就是秒表。
- **粗体淡色**：`font-semibold` + `text-muted-foreground`。它要让位给标题，但
  `tabular-nums` 保证秒针跳动时数字不左右抖。

## 17. 继续游戏 = 秒表继续

`submit()` 停表；「继续游戏」`resumeTimer()`。这条本来就有，补的是**另一条出口**：
点右上角 × 或按 Esc 关掉未通过的弹窗，此前秒表就停在那儿 —— 同一个动作（回去
接着玩）两条路径，其中一条把玩家的成绩冻住了。`closeResult` 现在按 `result.kind`
分叉：`failed` 关窗即续表，`passed` 关窗保持停表（那一局已经结算）。

## 18. `×` 自己的一支动效

编号的 `place-pop` 是「盖章」（0.5 → 1.08）；`×` 的语义是**划掉**，跟着盖章
一起动会读错。新增 `.forbidden-pop`：

```css
@keyframes forbidden-pop {
  from { opacity: 0; scale: 0.35; rotate: -18deg; }
  60%  { opacity: 1; scale: 1.16; rotate: 4deg; }
  to   { scale: 1; rotate: 0deg; }
}
```

`rotate` 与 `scale` 都是独立属性，不会像 `transform` 那样把 SVG 文字的 `x`/`y`
坐标整条覆盖（这个坑在 v0.7.10 §6.3 记过）。`transform-box: fill-box` 让旋转以
字形自己的中心为原点。

顺带修了一处：放 `×` 时先看 `canPlaceForbidden` 与「这一格已经是 `×`」，只有
真的放下了才 `markPulse` —— 否则一个没放上去的 `×` 也会播一次「刚放下」。

## 19. 选中的高亮，第二版

第一版的双环（2px 纸色缝隙 + 2px 主色）解决了「选中 vs 预览」的**定义**问题，
但扫一眼还是不够快：两者都是主色环，要停下来数层数。这一版加了两条**不同维度**
的线索，并刻意避开发光：

| 线索 | 做法 | 为什么 |
|---|---|---|
| 抬起 | `translate: 0 -2px` + `zIndex: 1` | 「从纸页上抽起一张」是纸的语言，和 `.impeccable.md` 的「手作 · 纸感」同源 |
| 投影 | 第三层 `0 14px 22px -16px hsl(var(--primary) / 0.65)` | **落在下方**、负 spread —— 是影子，不是光圈。发光描边是设计上下文明令避开的 AI 味 |
| 徽标反色 | 主色底 + `--primary-foreground` 字 | 徽标本来就在左上角最显眼处，「手上是哪位」不需要再判断 |

`roster-select-pop` 的鼓包也跟着改了：`scale 1 → 1.045 → 1` 之外加了
`translate 0 → -4px → -2px`，让「胀大」变成「拎起再落下」。幅度仍然压在 4.5%
以内 —— 110px 的格子挨着格子，超过 6% 就顶到邻居。

还有一处顺带的口径修正：**已落子的卡片淡到 45%，但被选中时不淡**。游戏里把
一位已经站上台面的参与者重新拿在手上，是为了给他搬家 —— 那一刻淡下去的正是
最该看清的一格，双环、抬起和反色徽标会被一起压暗。

## 20. 描述：被截断时才提示

新增 `components/common/ClampedText.tsx`，用在谜题 / 地图的网格卡片（两行）与
列表行（一行）。

- **只有真的溢出才挂提示**：`scrollHeight > clientHeight + 1`（或横向）比较一次。
  短描述悬停时弹出一片与原文一字不差的纸，不是帮助，是噪音。
- **鼠标悬停 / 键盘聚焦**走全站统一的那只 `Tooltip`（320ms、纸片外观）。
- **触摸**没有 hover：`pointerType !== 'mouse'` 时抬手直接打开全文，点空白处关闭。
- 重新测量挂在 `resize` + 节点自己的 `ResizeObserver` 上 —— 同一页里卡片被挤窄
  （网格/列表切换、侧栏开合）时窗口尺寸没变，文字却可能从放得下变成放不下。
- 不再溢出时**浮层一起收掉**，否则它会挂在那儿展示一段已经看得见的文字。

一个实现细节：无论是否溢出都包在 `Tooltip` 里（没溢出时 `onOpenChange` 吞掉
「打开」请求）。在「裸 span / 触发器里的 span」之间切换会重挂载节点，刚量到的
那对尺寸随旧节点一起丢掉，`ResizeObserver` 就永远盯着一个已经不存在的元素。

# 第三批：`×` 是一支开关（v0.7.11 追加）

> 需求原文（同日第三批）：
> ```
> 禁止符号点已经放置了禁止符号的格子时，清空该格子的禁止符号
> ```

## 22. 同一格再点一次 = 收回

`×` 工具此前只能加、不能减：点一个已经有 `×` 的格子，`placeForbidden` 直接
原样返回。撤销一个点错的 `×` 要走一段绕路 —— 切到橡皮（擦掉**整格**）、再切
回来。两次工具切换只为了一个单格动作，而橡皮擦整格这件事本身还多一层心理成本。

新增 `toggleForbidden(state, input)`（`lib/gamePlacement.ts`）：

- 格子里是 `×` → 删掉它，`commit` 一步（可撤销）；
- 否则走 `placeForbidden`，所有原有规则（不可站立、头像格、编号格整格替换）不变。

为什么可以放心在**同一个工具**里反向操作：`×` 是唯一「只代表自己」的格子内容。
编号要留着（它们是数格子的草稿），头像要留着（那是人对面），只有 `×` 擦掉不会
伤到任何别的标记。橡皮的价值在「一格混了多种标记」，`×` 格不是这种格子。

### 22.1 自动补的 `×` 也能收回

`pruneAutoForbidden` 只回滚「失去依据」的自动 `×`，从不阻止玩家手动取消一个
仍然站得住脚的排除项 —— 玩家说这一格可以放，就是可以放。下一次有头像落下时，
`placeParticipant` 会按**当时**的行列重新补，所以这个「取消」不是永久性的
破坏，只是一次局部的表态。

收回自动 `×` 时**不跑** `pruneAutoForbidden`：删掉一格不会让任何别的格子失去
依据（与擦头像不同，没有需要连带回滚的东西）。

### 22.2 滑动也走这条开关

`dispatchCell` 是点击与滑动共用的入口，所以按住划过的 `×` 格会一起收回 —— 与
「划过的格子执行对应的点击操作」是同一句话，不需要为滑动单独写一条规则。
`paintedRef` 照旧吞掉抬手后补的那记 `click`，避免最后一格来回切两次。

### 22.3 悬停预览仍然是 `×`

`resolveToolHint` 在 `×` 工具下遇到已经有 `×` 的格子，**继续**返回
`{kind:'forbidden'}` —— 中途曾试过换成 `{kind:'eraser'}`（「这一下会擦掉它」），
但那是错的：

- 指针压到哪一格，工具就还是**那一支**。换字形等于让同一支笔在格子之间改变
  身份 —— 「同一个箭头按下去方向会反过来」都比这好解释。
- 提示层的职责是「这一格归这支工具管」，不是预告这个格子上唯一那一种编辑的
  方向。方向的答案在松手之后就有：`×` 没了。

所以 `×` 工具从头到尾只画一种字形；开关的语义（§22）由结果说明。
