## 1. BUG-G01 点击「基本信息」后残留一个空信息框

**现象**：编辑器里点击某个方块 → 弹出该格的信息框；再点左上角「基本信息」→ 打开基本信息抽屉；
关闭基本信息抽屉后，**屏幕上还留着一个信息框**，但因为选区已被清空，框里只有一句空态文案
「在画布上点击格位、区域标签或左侧参与者框查看详情」。

**根因**（三处叠加）：

1. `EditorCanvas.selectCellAt` 在选中格子的**同时**还会设置区域焦点：
   ```ts
   onSelect({ type: 'cell', x: hit.x, y: hit.y });
   onSelectRegion(regionAt(regions, hit.x, hit.y)?.id ?? null); // ← 额外写了 selectedRegionId
   ```
2. `EditorPage` 用一条 effect 决定信息框开合，条件是「三个焦点轴任一非空」：
   ```ts
   if (editor.selection || editor.selectedRegionId !== null || editor.selectedSlotIndex !== null) {
     setInfoOpen(true);
   }
   ```
3. 而 `onOpenMapInfo` 只清了其中两个轴：
   ```ts
   editor.setSelection(null);
   editor.setSelectedSlot(null);
   setUnplacedCharacterId(null);
   setInfoOpen(false);
   // ← 漏了 editor.setSelectedRegion(null)
   ```
   于是 `selectedRegionId` 仍非 `null` → effect 条件再次成立 → `setInfoOpen(true)`，
   信息框在基本信息抽屉**下层**（z-20 vs z-30）被重新打开；抽屉关闭后它就暴露出来。

**规则**

1. `onOpenMapInfo` 打开基本信息抽屉时，必须**同时清空三个焦点轴**：
   `selection` / `selectedRegionId` / `selectedSlotIndex`（外加 `unplacedCharacterId`）。
2. 信息框的开合改由纯函数 `infoDrawerOpen({ infoOpen, mapInfoOpen, selectedSlotIndex })`
   （`lib/editorFocus.ts`）决定：`mapInfoOpen` 为真时**恒为 false**，
   避免「抽屉开着、信息框也开着」的双层弹框。
3. 提取纯函数后补单测：抽屉开着 → 信息框恒关；抽屉关着 → 信息框跟随三个焦点轴。
4. 不改 `selectCellAt` 的既有语义（点格子同时选中区域是 v0.3.x 的既定行为，
   预览页与区域工具都依赖它）。

**验收**

- 点击方块 → 信息框出现；点「基本信息」→ 信息框**立即消失**，只有基本信息抽屉；
- 关闭基本信息抽屉 → **不再**出现任何信息框（空态文案也不出现）；
- 关闭基本信息抽屉后重新点击方块 → 信息框正常弹出；
- 焦点在参与者槽位 / 区域标签时打开基本信息 → 同样不残留信息框。

## 2. OPT-G01 预览页标题改为地图名称，版本作为标签

**现象**：预览页标题是 `{notes ?? '作品'} v{versionNo}`——把**发布备注**当成了标题，
既不是地图名称，也无法一眼看出这是哪张地图的哪个版本。

**规则**

1. `MapVersionDetail`（`packages/shared/src/types/domain.ts`）新增字段 `projectName: string`。
2. `versionService.getVersion` / `versionRepository.getVersion` join `map_projects.name`
   （与 `listAllVersions` 取 `project_name` 的写法一致），详情接口回填该字段。
3. 预览页顶栏标题改为**地图名称**；版本号改为**标签**（`v{N}` 徽标，`variant="secondary"`），
   与标题同行展示。
4. 发布备注（`notes`）不再占据标题位；如备注非空，以次要文本形式展示在标题下方。
5. 浏览器 `document.title` 同步为 `{地图名称} · Murdoku Maker`。

**验收**

- 预览页标题 = 发布该版本时的地图名称；标签显示 `v1` / `v2` …；
- 地图改名后重新发布，预览页标题随之变化；
- 老数据（发布时地图名为空）回退为 `'未命名地图'`，不出现空标题。

## 3. 术语与新增图层（SPEC-G01 / SPEC-G02）

游戏页面引入两个新图层。按《画布图层优先级规范》§1 的命名规则
（中文名 / 英文名 / 代码常量名三者在文档、代码与界面文案中必须一致），
两个暂定名在本版正式命名如下：

| 层号 | 中文名 | 英文名 | 代码常量名 | 定义 |
|---|---|---|---|---|
| 4 | 工具提示层 | Game Tool Hint Layer | `gameToolHint` | 游戏中跟随指针的**待放置预览**：禁止符号 / 清除橡皮 / 参与者标号 |
| 5 | 游戏放置层 | Game Placement Layer | `gamePlacement` | 游戏中被玩家放置的内容：参与者图片、参与者标号、禁止符号 |

> 命名依据：二者都是**游戏页面专属**图层（编辑器与预览页不渲染），因此常量名带 `game` 前缀；
> 英文名同样带 `Game` 前缀，避免与既有的 `mouseCursorBox` / `operationCursorBox` 混淆。

**层序**（用户要求：区域标签层 > 工具提示层 > 游戏放置层 > 物件图层）：

```
鼠标光标框 > 操作光标框 > 区域标签 > 工具提示层 > 游戏放置层 > 物件图层 > 画布外框
> 网格分隔线 > 区域轮廓线 > 不可站立遮罩 > 区域高亮线 > 方块高亮 > 背景高亮 > 背景图层 > 画布底色
```

**z-index 重新编号**（15 层，严格递减；编辑器 affordance 临时层仍在
`operationCursorBox − 1 / − 2`，不受影响）：

| 层号 | 名称 | 旧 z-index | 新 z-index |
|---|---|---|---|
| 1 | 鼠标光标框 `mouseCursorBox` | 46 | 46 |
| 2 | 操作光标框 `operationCursorBox` | 45 | 45 |
| 3 | 区域标签 `regionLabel` | 42 | 42 |
| 4 | **工具提示层 `gameToolHint`** | — | **41** |
| 5 | **游戏放置层 `gamePlacement`** | — | **40** |
| 6 | 物件图层 `objectLayer` | 40 | 38 |
| 7 | 画布外框 `canvasFrame` | 39 | 36 |
| 8 | 网格分隔线 `gridSeparator` | 38 | 34 |
| 9 | 区域轮廓线 `regionOutline` | 36 | 32 |
| 10 | 不可站立遮罩 `nonStandableMask` | 35 | 30 |
| 11 | 区域高亮线 `regionHighlight` | 32 | 28 |
| 12 | 方块高亮 `cellHighlight` | 30 | 26 |
| 13 | 背景高亮 `backgroundHighlight` | 28 | 24 |
| 14 | 背景图层 `backgroundLayer` | 20 | 20 |
| 15 | 画布底色 `canvasBase` | 10 | 10 |
| — | 区域填充（表外遗留）`REGION_FILL_Z` | 22 | 22（= `backgroundLayer + 2`，仍夹在 20 与 24 之间） |

**规则**

1. `MAP_LAYER_ORDER` 扩为 **15 项**，`gameToolHint` 插在 `regionLabel` 之后、
   `gamePlacement` 插在 `gameToolHint` 之后（顺序即优先级）。
2. 同步更新 `docs/layer-priority.md`：§1 命名表、§2 次序表、§3 各层行为定义（新增两节）、
   §4 叠加与遮挡规则、§7 验收清单。
3. 同步更新 `canvasLayers.test.ts`：`MAP_LAYER_ORDER` 的 `toEqual` 断言改为 15 项，
   并补两条相对关系断言：
   `layerZ('gameToolHint') < layerZ('regionLabel')`、
   `layerZ('gamePlacement') < layerZ('gameToolHint')`、
   `layerZ('gamePlacement') > layerZ('objectLayer')`。
4. 既有相对关系全部保留（只改数值不改次序），因此其余断言无需修改。
5. **游戏页面不渲染「操作光标框」层**；「鼠标光标框」层保留（跟随指针，
   在放置 / 禁止 / 清除三种操作态下都提供当前格反馈）。

**验收**

- `MAP_LAYER_ORDER` 15 项、`MAP_LAYER_Z` 严格递减、无重复值；
- 游戏页面：工具提示层的图标压在游戏放置层之上，二者都压在物件图层之上、区域标签之下；
- 编辑器与预览页层序表现完全不变（回归）。

## 4. FEAT-G01 游戏首页

**规则**

1. 新增路由 `/games`，页面组件 `packages/web/src/pages/GamesPage.tsx`。
   **与 Murdoku Maker 主站不是同一个页面**：它是一个独立的、面向玩家的入口。
2. 布局为**卡片网格**（简约风格）：响应式列数（≥1280px 4 列、≥768px 3 列、其余 2 列），
   卡片间距 20px，无多余装饰。
3. 每张卡片展示四要素，缺一不可：
   - **封面**：16:10 圆角矩形，`object-cover`；无封面时显示占位底色 + 地图名称首字；
   - **名称**：游戏名称（部署时填写，默认取作品名称）；
   - **难度**：`Very Easy / Easy / Medium / Hard / Expert` 五档，各配一个颜色徽标；
   - **规格**：`n×n`（部署时作品快照的 `gridSize`）。
4. 点击卡片 → 跳转 `/games/:gameId`。
5. 空态：一张居中的占位卡 + 「还没有部署任何作品」+ 前往作品管理页的链接。
6. **独立顶层路由**（v0.4.0 验收补充）：`/games` **不使用 `AppShell`**，与
   `/games/:gameId`、`/editor/:projectId` 同级；玩家从这里看不到地图 / 物品 /
   角色 / 作品等制作端模块，只能通过链接进入（作品页「已部署」徽标、游戏页
   「返回」按钮）。页面自带整版布局（`min-h-screen` + `max-w-7xl` 容器）。

**验收**

- `/games` 与 `/projects` 是不同页面、不同布局；
- 卡片四要素齐全；难度五色可辨；`n×n` 与部署时的作品一致；
- 点击卡片进入对应游戏页面；空态可正常显示。

## 5. FEAT-G02 作品部署

### 5.1 数据模型（新表 `map_games`）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `bigIncrements` | primary | 游戏 ID |
| `project_id` | `bigInteger` | notNullable, **unique**, references `map_projects(id) on delete cascade` | **同一张地图只能部署一个版本** |
| `version_no` | `integer` | notNullable | 部署时选取的作品版本号 |
| `name` | `varchar(100)` | notNullable | 游戏名称（默认取作品名称，可改） |
| `cover_path` | `text` | nullable | 封面图片相对路径 |
| `cover_mime` / `cover_size` / `cover_width` / `cover_height` | | nullable | 封面元数据（与 `cards` 表一致） |
| `difficulty` | `varchar(16)` | notNullable | 五档之一 |
| `grid_size` | `integer` | notNullable, `check(2..24)` | 部署时的画布尺寸，供首页卡片直接展示 |
| `created_at` / `updated_at` | `timestamptz` | notNullable, default now | |

**规则**

1. **相同地图只能部署一个版本**：`project_id` 建唯一索引；再次部署同一地图时
   **新版本覆盖旧版本**（同一事务内 `delete` 旧行 + `insert` 新行，`id` 重新分配）。
2. 部署时把作品快照（`map_versions.data`）**冗余拷贝**到 `map_games.snapshot`（`jsonb`）：
   游戏页面读快照渲染，作品后续重新发布**不影响**已部署的游戏（除非再次部署）。
   > 这与预览页「永远读最新版本」不同，是刻意设计：游戏一旦部署就是一份可玩的固定副本。
3. 部署入口在作品管理页（`/works`）每一行的操作列，按钮文案「部署」。
4. 已部署的作品在表格中做标识：行内显示一个「已部署」徽标（`variant="secondary"`），
   点击徽标可直接进入该游戏的游戏页面。

### 5.2 部署弹窗

点击「部署」弹出对话框（沿用 `ui/dialog.tsx`，**禁止点击遮罩关闭**）：

| 字段 | 控件 | 默认值 | 约束 |
|---|---|---|---|
| 游戏名称 | 文本输入 | 作品名称（`projectName`） | 必填，≤100 字，去首尾空格 |
| 封面图片 | 图片上传 + 预览 + 「移除」 | 空（可留空） | 复用 `middleware/upload.ts` 的 `imageUpload`，`UPLOAD_MAX_SIZE` / `UPLOAD_ALLOWED_MIME` |
| 难度 | 五选一徽标组 | `medium` | `veryEasy / easy / medium / hard / expert` |

底部按钮：「取消」/「部署」。部署成功后 toast 汇报，并刷新表格（该行出现「已部署」徽标）。

### 5.3 难度定义

| key | 英文 | 中文 | 颜色 |
|---|---|---|---|
| `veryEasy` | Very Easy | 极简 | `#22C55E` |
| `easy` | Easy | 简单 | `#84CC16` |
| `medium` | Medium | 中等 | `#EAB308` |
| `hard` | Hard | 困难 | `#F97316` |
| `expert` | Expert | 专家 | `#EF4444` |

> 五档构成绿 → 黄绿 → 黄 → 橙 → 红 的渐进色阶，色盲友好度与既有调色板
> （`DEFAULT_LINKAGE_COLORS`）不冲突。难度颜色为**徽标底色 + 白字**，
> 不使用渐变、不加图标。

### 5.4 API

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/projects/:projectId/games` | 部署（upsert，同地图覆盖）。body: `{ versionNo, name, coverPath?, coverMime?, coverSize?, coverWidth?, coverHeight?, difficulty }` |
| `GET` | `/api/games` | 游戏首页列表（按 `created_at` 倒序） |
| `GET` | `/api/games/:gameId` | 游戏详情（含快照，供游戏页面渲染） |
| `POST` | `/api/games/:gameId/cover` | 封面上传（`multipart`，字段名 `file`） |

> `POST /api/projects/:projectId/games` 走 `projectController` / `gameService`，
> 与既有 `/api/projects/:id/versions` 并列；`/api/games` 是跨项目的平铺入口，
> 与 `/api/versions`（作品平铺）同构。

**验收**

- 同一地图部署两次 → 表中只有一行，`version_no` 为后一次的值；
- 不同地图各自部署 → 互相独立；
- 表格中已部署行有徽标，未部署行没有；
- 弹窗默认名 = 作品名称，可修改后生效；
- 难度五档可任选，徽标颜色正确；
- 封面可上传、可预览、可移除、可留空。

## 6. FEAT-G03 游戏页面（左中右三栏）

路由 `/games/:gameId`，组件 `packages/web/src/pages/GamePage.tsx`。
**不使用 `AppShell`**（独立全屏布局，与编辑器 `/editor/:projectId` 同级的顶层路由）。

```
┌────────────┬───────────────────────────────┬────────────┐
│ 左上：      │                               │ 右侧：      │
│ 游戏信息    │      中间：地图画布            │ 工具栏      │
│ + 返回      │      （预览地图 + 放置交互）    │ 禁止 / 清除 │
├────────────┤                               │ 回退 / 提交 │
│ 左下：      │                               │            │
│ 参与者面板  │                               │            │
└────────────┴───────────────────────────────┴────────────┘
```

### 6.1 左上：游戏基本信息 + 返回

- 返回按钮（`ArrowLeft` 图标 + 「返回」）→ 回到 `/games`；
- 游戏名称、封面缩略图、难度徽标、`n×n` 规格；
- 不提供编辑能力（游戏是固定副本）。

### 6.2 左下：参与者面板

- **与作品预览页的参与者模块一摸一样**：直接复用 `ParticipantPanel`（`readOnly` 模式），
  矩阵卡片布局、主题色圆头像、序号、线索区、单个 `boxShadow` 高亮框；
- **保留全部联动效果**：hover / click 走与预览页同一套 `reduceLinkageActivation` 状态机，
  区域高亮线 / 方块高亮 / 背景高亮 / 参与者框高亮表现一致；
- 新增操作：**点击参与者 → 进入「放置」状态**（见 SPEC-G03）；
- **放置态与悬停的关系**（v0.4.0 验收补充）：放置态下把鼠标移到**另一张**未点击的
  卡片上，只临时切换联动预览（显示该参与者的 hover 效果、取消已武装参与者的
  hover 效果）；移开后**恢复**已武装参与者的联动。放置状态本身不随悬停结束而退出
  （见 SPEC-G03 §9.4）。

### 6.3 中间：地图画布

- **与预览页的地图一摸一样**：复用 `MapLayers` 的全部 13 个既有图层 +
  `MapRulerStrips` 标尺；联动高亮、区域标签、不可站立遮罩等表现完全一致；
- 新增**游戏放置层**与**工具提示层**（SPEC-G01 / SPEC-G02）；
- **不渲染「操作光标框」层**；
- **画布固定自适应**（v0.4.0 验收补充）：空白处**不可拖拽平移**，也没有
  放大 / 缩小 / 重置视图——容器变化时按 `canvasInsets({ showRulers,
  showBottomBar: false, rulerSize })` 重新适应并居中；格内光标为 `pointer`，
  空白处为默认光标。

### 6.4 右侧：工具栏

| 按钮 | 图标 | 行为 |
|---|---|---|
| 禁止符号 | `X`（红色） | 进入「禁止操作」状态（SPEC-G04） |
| 清除工具 | `Eraser` | 进入「清除」状态；**长按 → 清空全图放置层** |
| 回退操作 | `Undo2` | 回退上一步放置操作 |
| 提交操作 | `Send` / `Check` | 提交当前摆放；**校验逻辑预留到后续版本** |

- 四个按钮纵向排列，等宽，激活态 `bg-accent` 高亮；激活态互斥（见 SPEC-G04）；
- 工具栏底部显示一步数统计：「已放置 N 个 / 可回退 M 步」；
- 除四个工具按钮外只保留一个**标尺开关**（v0.4.0 验收补充：缩放 / 重置视图
  按钮与空白拖拽平移一并移除，画布固定自适应）。

**验收**

- 三栏布局在 1280×800 下不出现滚动条；中间画布自适应剩余空间；
- 左下参与者面板与预览页视觉与联动完全一致（源码 + 行为双重断言）；

## 7. SPEC-G01 游戏放置层

### 7.1 格子内容模型

每个格子的放置内容是下面三种**互斥形态**之一（`null` 表示空格）：

```ts
type CellPlacement =
  | { kind: 'participant'; index: number }        // 参与者图片，index = 槽位序号（1 起）
  | { kind: 'numbers'; entries: number[] }        // 参与者标号列表，可多个
  | { kind: 'forbidden' }                          // 禁止符号
  | null;
```

| 形态 | 渲染 |
|---|---|
| `participant` | 参与者图片居中绘制，四周留 `objectPadding`；`<img>` 一律 `draggable={false}` |
| `numbers` | 方格分为 **9 宫格（3×3）**，从左到右、从上到下依次填充；字号约 `cellSize / 4`，字体颜色取该参与者的主题色，黑色描边（描边宽度随字号缩放） |
| `forbidden` | 黑色粗体大 `×`，居中，**不超出格子**；同时**激活该格的不可站立遮罩** |

**标号数值**：`entries[i]` 是该参与者在其作品参与者槽位中的序号（1 起），
与左下参与者面板卡片右上角显示的序号一致。

### 7.2 放置规则

1. **有不可站立物品的格子不能放置**（`collectNoStandCells` 命中即拒绝）。
2. **短按（点击）放置标号**：该格的 9 宫格里追加一个标号——空格得到第 1 格，
   已有其他参与者标号则按顺序续接；**该参与者的标号已存在则无效果**；
   第 10 个起不再接受（9 宫格已满）。
3. **长按（≥ `GAME_LONG_PRESS_MS`）放置头像**：整格替换为该参与者的图片
   （`{ kind: 'participant' }`），即「确认这格就是这位参与者」，原有标号被覆盖；
   该格已是同一头像时无效果。
4. 放置禁止符号：绘制 `×`；若该格原有标号，**先清除标号再替换为 `×`**。
5. 清除：把该格放置内容置为 `null`（同时取消该格的不可站立遮罩激活）。
6. 放置层**不接收指针事件**（与其余绘制层一致）；交互由画布容器统一分发。
7. 头像与标号两种落点都拒绝：不可站立格、有 `×` 的格。

**验收**

- 短按空格 → 该格出现参与者标号（9 宫格第 1 格）；
- 长按空格 → 该格出现参与者头像；
- 短按另一位参与者的同格 → 标号追加；长按同格 → 替换为该参与者头像；
- 连续放置多个参与者到不同格 → 各自独立；
- 禁止符号替换已有标号；清除后恢复空格；
- 不可站立物品格点击 / 长按无任何效果（三种操作态下都无效果）；
- 9 宫格第 10 个标号被短按拒绝，但长按仍可确认（整格替换）。

## 8. SPEC-G02 工具提示层

**规则**

1. 该层只在**鼠标悬停在画布格子上**时渲染一个图标，**移出格子立即清空**；
2. 图标内容由当前操作态决定：

| 操作态 | 悬停时展示 | 例外 |
|---|---|---|
| 放置参与者 | 该格的 9 宫格**第 1 格**展示该参与者标号，样式同放置层标号 | 无 |
| 禁止操作 | `×` 图标（**深绿色字体 + 黑色描边**） | **该格已放置参与者时不展示** |
| 清除 | 橡皮图标 | 无（**该格已放置参与者也展示**） |
| 无操作态 | 空 | — |

3. 提示层图标**不随点击消失**：它与放置层是两个独立的逻辑，
   放置层发生变化不影响提示层当前图标（只有「移出格子」会清空它）。
4. 提示层**不接收指针事件**。
5. 橡皮图标：SVG 绘制（斜置圆角矩形 + 中间金属箍），颜色 `#374151`，描边 `#000000`。

**验收**

- 三种操作态下悬停格子分别出现 标号 / × / 橡皮；
- 移出格子后图标消失；
- 已放置参与者的格子在禁止态下不显示 `×`，在清除态下仍显示橡皮；
- 点击格子完成放置后，鼠标不动 → 提示层图标仍在。

## 9. SPEC-G03 参与者放置联动

### 9.1 进入 / 退出放置状态

1. **点击左下参与者面板的卡片** → 该参与者进入「放置」状态：
   - 参与者卡片保持高亮（`boxShadow` 单框，与预览页一致）；
   - **同时触发该参与者的原有联动效果**（区域高亮线 / 方块高亮 / 背景高亮 /
     参与者框高亮），与预览页点击参与者的表现完全一致；
   - 工具栏的四个按钮**全部取消激活**（放置态与工具态互斥）。
2. **再次点击同一参与者**，或**点击其他工具按钮**，或**按 `Esc`** → 退出放置状态，
   参与者卡片高亮恢复常规样式。
3. 放置状态下，鼠标在画布上移动仍显示「鼠标光标框」（层 1 保留）。

### 9.2 点击 / 长按格子

| 格子状态 | 短按（点击） | 长按（≥ 500ms） | 悬停 |
|---|---|---|---|
| 有不可站立物品 | 无效果 | 无效果 | 无效果 |
| 有禁止符号 | 无效果 | 无效果 | 无效果 |
| 已有该参与者的标号 | 无效果 | **该格替换为该参与者头像** | 提示层展示该标号，移出消失 |
| 已有标号（其他参与者） | **追加**该参与者标号 | **该格替换为该参与者头像** | 提示层展示该标号，移出消失 |
| 空格 | **放置该参与者标号**（9 宫格第 1 格） | **放置该参与者头像** | 提示层展示该标号，移出消失 |

> **v0.4.0 验收补充**：短按与长按是同一次「放置参与者」手势的两种落点——
> **短按放编号**（候选，可多个），**长按放头像**（确认这格就是这位参与者）。
> 长按定时器与工具栏清除按钮同源（`GAME_LONG_PRESS_MS = 500`）；长按生效后，
> 同一手势末尾的 `click` 必须被吞掉，否则会既放头像又放编号。

> **需求二义性裁定**：原文「格子上有参与者 → 点击和触碰都无效果」与
> 「格子已有标号 → 点击追加该参与者标号」在字面上冲突（放置参与者会同时产生图片和标号）。
> 本版统一收敛为：**「有参与者」判定的是「该格是否已包含该参与者的标号」**——
> 即重复放置同一参与者无效；放置**不同**参与者则追加标号。
> 这样 9 宫格多标号（原文「标号可放多个」）才可达，两条规则也同时成立。
> 渲染上：该格只有 1 位参与者且为头像形态时显示其头像；标号形态（含仅 1 个
> 标号）显示 9 宫格标号（避免头像与标号互相遮挡）。

### 9.3 与工具栏的关系

放置态与「禁止 / 清除」两个工具态**互斥**：进入任一方状态会自动退出另一方。

### 9.4 放置态下的悬停（v0.4.0 验收补充）

1. 参与者 A 处于放置态时，鼠标移到**另一张**未点击的卡片 B 上：
   - 触发 B 的 hover 联动效果（区域高亮线 / 方块高亮 / 背景高亮 / 参与者框高亮）；
   - 同时**取消** A 当前显示的 hover 效果（联动预览同一时刻只属于一位参与者）；
   - **A 的放置状态保持不变**。
2. 鼠标移开 B：**恢复** A 的联动效果（`reduceLinkageActivation` 重新点击激活
   A），玩家始终能看到「谁正被武装」。
3. **只有**再次点击参与者（A 自身 → 退出；其他 → 切换）或点击工具按钮，
   才退出 A 的放置态；悬停的进入 / 移开**不会**退出。

**验收**

- 点击参与者 → 卡片高亮 + 联动效果出现 + 鼠标进画布有反馈；
- 短按空格 → 该格出现标号 1（9 宫格第 1 格）；
- 长按空格 → 该格出现参与者头像；
- 短按另一位参与者的同格 → 标号追加（9 宫格第 2 格）；长按同格 → 替换为该参与者头像；
- 重复短按同一参与者的同格 → 无变化；长按已是该头像的格 → 无变化；
- 不可站立格 / 有 `×` 格 → 短按、长按都无变化；
- 再次点击该参与者 → 退出放置态，高亮恢复；
- `Esc` → 退出放置态；
- 放置态下悬停另一参与者 → 显示其 hover 效果；移开 → 恢复原参与者的效果，
  放置态仍在。

## 10. SPEC-G04 工具栏状态机

四个工具按钮 + 参与者放置态构成一个**互斥单选**的状态机：

```
            ┌───────────── click participant ─────────────┐
            ▼                                            │
        [ idle ] ◄──── click again / Esc / other tool ────┘
            │  click 禁止符号                click 清除
            ▼                                  ▼
      [ forbidden ]                        [ clearing ]
            │  click again / other tool        │  click again / other tool
            └──────────────► [ idle ] ◄────────┘
```

### 10.1 禁止符号（辅助判断排除选项）

1. 点击进入「禁止操作」状态；**按钮保持高亮**；
2. 鼠标进入地图即建立联动：触碰格子在工具提示层展示 `×`（**该格有参与者时不展示**）；
3. 点击格子：
   - 该格**有参与者** → **无效果**；
   - 其他格子 → 放置层放置 `×`；**该格原有标号时先清除标号再替换**；
   - 放置后**停留在禁止状态**（可连续点多个格子）；
4. 提示层图标此时**不消失**（提示层与放置层逻辑相互独立、可共存）；
5. 再次点击按钮，或进入其他状态 → 退出，按钮高亮恢复。

### 10.2 清除工具（清除放置层）

1. 点击进入「清除」状态；**按钮保持高亮**；
2. 鼠标进入地图即建立联动：触碰格子在工具提示层展示橡皮图标
   （**该格有参与者也展示**）；
3. 点击格子：若放置层有内容则清除（含参与者图片与标号），
   **提示层图标不消失**；无内容则什么都不做；
4. 清除后**停留在清除状态**；
5. **长按清除按钮 → 清空地图上所有放置层内容**（一次性操作，长按阈值 500ms，
   松手前显示「清空全部」的按压反馈；清空后停留在清除状态）；
6. 再次点击按钮，或进入其他状态 → 退出。

### 10.3 回退操作

1. **所有放置类操作都记录进历史栈**：放置参与者 / 追加标号 / 放置 `×` /
   单格清除 / 清空全部。
2. 点击「回退」→ 撤销栈顶一步；历史栈空时按钮禁用（`disabled` + tooltip「没有可回退的操作」）。
3. 重做栈在**新的放置操作发生时清空**（标准撤销语义）。
4. 清空全部记作**一步**（回退一次即恢复整图）。

### 10.4 提交操作

1. 点击「提交」→ 记录一次提交（提交时把当前摆放快照存入历史栈顶，标记为已提交）。
2. **提交校验预留到后续版本完善**：本版只做「可提交」的最小闭环
   （toast「已提交」+ 按钮变为「已提交」态 + 禁用回退到提交点之前）。
3. 提交**不锁定**画布：玩家提交后仍可继续摆放并再次提交（校验规则后续版本定义）。

**验收**

- 四个按钮 + 参与者卡片构成互斥单选，任选一个其余全部取消高亮；
- 禁止态可连续点多个格子；有参与者的格子点击无效；
- `×` 替换标号；提示层图标在放置后仍在；
- 清除态点击有内容的格子 → 内容消失，提示层图标仍在；
- 长按清除按钮 → 全图清空（一步回退可恢复）；
- 回退按钮在有空历史时可点、空历史时禁用；清空全部只需一步回退；
- 提交后按钮变「已提交」，回退不能越过提交点。

## 14. 实现备注（交付说明）

本版需求全部达成。以下记录**实现与规格的差异或补充点**：§14.1 ~ §14.5 为首轮
交付时的补全，§14.6 ~ §14.10 为 v0.4.0 验收反馈后的修订，均不构成功能偏差。

### 14.1 工具栏视图簇（§6.4 的补充 → 已按验收反馈移除）

首轮交付时右侧工具栏在四个工具按钮之外附加了视图簇（标尺开关 / 缩小 / 百分比 /
放大 / 重置视图）。**验收反馈要求移除**：画布固定自适应，不需要平移与缩放，
也不应该出现这些按钮。现行工具栏 = 四个工具按钮 + 一个**标尺开关** + 步数统计；
中列画布同时去掉了「空白处拖拽平移」与 `ctrl + 滚轮` 缩放。

### 14.2 提交屏障的实现方式（§10.4）

规格表述为「提交时把当前摆放快照存入历史栈顶，标记为已提交」。实现改为
**屏障计数** `submittedPastLength`：

- 提交只记录「此刻历史栈长度」，**不再向历史栈压入额外快照**；
- `canUndo = past.length > submittedPastLength`，`undo` 最多回退到提交点；
- 历史栈因超上限 `GAME_PLACEMENT_HISTORY_MAX` 被截断时，屏障计数同步前移。

> 原方案（压入快照）会导致下一步 `commit` 再次压入同一棋盘而被
> `boardEquals` 判为「无变化」而跳过，提交屏障随即失效。屏障计数语义等价且
> 不占用撤销步，纯函数单测 29 例全部覆盖。

### 14.3 新增常量 `GAME_FORBIDDEN_FONT_RATIO = 0.62`

规格 §11.4 只给了标号字号比例。放置层禁止符号的字号（`cellSize × 0.62`）在实现时
补为常量，与既有 `scaleFontSize` 的 clamp 规则保持一致（§11.4 表已同步）。

### 14.4 封面上传的两段式时序

部署弹窗支持「先部署、后传封面」：`useDeployGame` 的 `mutationFn` 先调
`POST /api/projects/:projectId/games` 拿到 `id`，再调 `POST /api/games/:id/cover`。
规格 §5.2 的 API 表已含该接口，此处仅明确**前端两步串行**的顺序。

### 14.5 难度徽标配色落地

难度颜色为**徽标底色 + 白字**（`GAME_DIFFICULTY_COLORS[level]`），无渐变、无图标，
与规格 §5.3 一致；卡片与部署弹窗、游戏页信息区共用同一常量。

### 14.6 BUG-G01 验收补充：焦点切换先关基本信息抽屉

首轮修复只保证了「关闭基本信息抽屉后不残留信息框」。验收发现的相反路径仍有问题：
抽屉开着时点方格 / 参与者，抽屉**不消失**，信息框被一直压制，直到手动关闭抽屉
才弹出。修法：`EditorPage.guardMapInfo` 的非脏分支补 `setMapInfoOpen(false)`——
所有「把焦点交给别处」的路径（画布 `onSelect`、参与者 `onActivateClick` /
`onSelect`、区域标签 `onSelectRegion`）都经此守卫，因此点哪一处都会先关抽屉
（有未保存修改时仍走 FEAT-E01 的三选确认），信息框随即接管。

### 14.7 游戏首页改为独立顶层路由

规格 §4 原写「顶栏沿用 `AppShell`，导航新增『游戏』入口」。验收要求游戏首页
**不和其他模块放在一起**：只能通过链接访问，且看不到其他模块。现已把 `/games`
移出 `AppShell` children，成为与 `/games/:gameId`、`/editor/:projectId` 同级的
顶层路由；`AppShell` 导航移除「游戏」项；`GamesPage` 自带整版布局。

### 14.8 参与者编号从 1 开始

`ParticipantPanel` 回调传的是 **0 起**槽位序号，而放置层 / 提示层 / 主题色表都按
**1 起**消费（`slots[participantId - 1]`、`themeColors` 键为 `index + 1`）。
首轮把面板序号直接塞进 `mode.participantId`，导致第一位参与者编号显示为 0。
现已统一：`handleCardClick` 里 `participantId = index + 1`，与 SPEC-G01 §7.1
「index = 槽位序号（1 起）」及面板左上角显示的序号一致。

### 14.9 放置态下的悬停联动（§9.4）

规格原未定义「放置态中悬停另一张卡片」的行为。验收补充后实现为：
`onDeactivateHover` 在放置态下不派发 `leave`，而是对该参与者**重新点击激活**
（`reduceLinkageActivation` 的 `click`），从而移开悬停卡片后恢复已武装参与者的
联动；进入悬停仍走既有 `enter`（自动结束当前激活并转为 hover）。放置态本身只由
再次点击参与者或工具按钮退出（`handleCardClick` / `applyMode`），共享状态机
`lib/linkageActivation.ts` **未改动**，编辑器与预览页行为零影响。

### 14.10 短按放编号 / 长按放头像（§9.2 的验收补充）

规格原文只有「放置参与者」一种手势（空格 → 图片 + 第 1 个标号）。验收要求拆成
两种落点，实现为 `placeParticipant` 的 `variant: 'number' | 'image'`：

- **短按（点击）→ `number`**：往该格 9 宫格追加一个标号；空格得到第 1 格；
  该参与者标号已存在则无效果；第 10 个拒绝；
- **长按（≥ `GAME_LONG_PRESS_MS`）→ `image`**：整格替换为该参与者的头像，
  即「确认这格就是这位参与者」；该格已是同一头像时无效果；
  不可站立格与有 `×` 格两种落点都拒绝。

`canPlaceParticipant` 随之增加 `variant` 参数：长按是「替换」语义，因此
**9 宫格已满不构成阻碍**（短按仍拒绝）；「已含该参与者」在长按下反而是
**提升**（标号 → 头像），仅「已是同一头像」才算无效果。

页面侧（`GamePage`）新增 `cellPressRef`：放置态下在格子上按下即启动 500ms
定时器，到点派发 `dispatchCell(x, y, 'image')` 并置 `fired`；`pointerup` 只作废
定时器并**保留** `fired`，让紧随其后的 `click` 识别「这一手是长按」并把自己
吞掉——否则同一手势会既放头像又放编号。移出画布 / 指针中断则连 `fired` 一起丢
（不会再有 click 收尾）。非放置态下长按不启动，行为与改动前一致。
