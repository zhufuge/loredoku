## §1 禁用工具栏按钮：禁用光标 + 一句「为什么不能点」

### 1.1 问题

工具栏的「回退」「提交」在不可用时是 `disabled`。基类 `Button` 有一句
`disabled:pointer-events-none`（shadcn 的老习惯，为的是别让禁用按钮还吃 `hover:bg-*`），
于是：

- `cursor-not-allowed` 写在按钮上不生效 —— 指针根本没打到它；
- `title` 也不弹 —— 禁用的表单控件不派发 hover，Chrome 不显示原生提示。

结果是玩家点了一枚灰按钮，既没有「不能点」的光标，也没有「为什么」。

### 1.2 做法

两枚按钮各包一层 `<span>`：

```tsx
<span
  className={cn('block w-full', !canUndo(placementState) && 'cursor-not-allowed')}
  title={canUndo(placementState) ? undefined : '当前没有可以回退的步骤'}
>
  <Button ... disabled={!canUndo(placementState)} title={...}>…</Button>
</span>
```

禁用的按钮 `pointer-events: none`，指针于是落到外面这层 span 上：`cursor-not-allowed`
与 `title` 都由 span 出。**启用时** span 不带 title、不带光标类，提示仍由按钮自己的
`title` 负责 —— 两条路径互不干扰。

按钮上仍保留同一句 `title`（禁用时）只为让测试选择器稳定，不参与显示。

### 1.3 文案

| 按钮 | 启用时提示 | 不可用时提示 |
| --- | --- | --- |
| 回退 | 回退上一步 | **当前没有可以回退的步骤** |
| 提交 | 提交 | **尚未将人物放置完全** |

（提交在「已放完、可提交」时是 `提交`；没放完才是那句禁用提示。这是 v0.9.0 §18
定下的「提交」文案，未改。）

### 1.4 只动这两枚

放大 / 缩小 / 重置 / 标尺那一簇是 `IconButton`（Radix Tooltip），到缩放边界时同样
禁用、也同样吃不到 hover —— 但用户这次只点名「回退 / 提交」，且没给那几枚的提示文案，
所以**没动**。将来要补，做法一样：外面包一层 span，把 `label` 挂上去。

## §2 画布阴影：36px，并且进风格配置

### 2.1 从常量到风格

v0.8.7 §6 的阴影是两个常量：偏移 `CANVAS_SHADOW_OFFSET_PX`、颜色取
`canvasFrame.color` 再压 0.3 透明。v0.9.0 §16 只把偏移从 6 调到 24。

这一版把**偏移与颜色都搬进 `MapStyle`**：

```ts
export interface MapStyleCanvasShadow {
  offset: number;   // 画布像素，随 zoom 缩放
  color: string;    // #RRGGBB
}
```

- **默认 36px**（`CANVAS_SHADOW_OFFSET_PX = 36`），颜色默认 `LINE_COLOR`（`#000000`）。
- 透明度仍固定 `CANVAS_SHADOW_ALPHA = 0.3`：颜色只收 `#RRGGBB`，不开放 alpha ——
  「颜色 + 一层固定淡度」比再放一个透明度滑块好解释。
- 偏移可调区间 `MAP_STYLE_SHADOW_OFFSET_MIN = 0` ~ `MAX = 120`（0 = 不投阴影），
  一律取整。

`canvasShadowStyle(style)` 现在读 `style.canvasShadow`：

```ts
const { r, g, b } = hexToRgb(style.canvasShadow.color);
const offset = style.canvasShadow.offset;
boxShadow: `${offset}px ${offset}px 0 rgba(${r}, ${g}, ${b}, 0.3)`
```

### 2.2 三处配置入口，同一份数据

`MapStyle` 同时是**地图级缺省**与**主题缺省风格**的形状（`themes.data.style`），所以加进
`MapStyle` 之后三处自动对齐：

1. **地图「基本信息」抽屉 → 线条区**：新增「画布阴影」行，偏移（px）+ 颜色（`ColorField`）。
   插在「画布外框」下面 —— 影子是外框投下的，挨着放最顺手。
2. **主题概览页「地图初始样式」表单**：`MAP_STYLE_FIELDS` 里加了两项，`THEME_STYLE_FIELDS`
   自动派生，`WRITE_SPECS` 补 number/color 规格，`FIELD_HINTS` 补解释（测试会盯着「没有
   `unknown`」与「每项都有解释」）。
3. **差异弹窗**：`canvasShadow.offset / color` 进「边框」组 —— 主题与本图差在这两项时，
   作者能看到「画布阴影偏移 24px / 36px」这样的对照。

### 2.3 兼容：旧存档没有 canvasShadow

`resolveMapStyle` 对新块做了缺省与夹取：

```ts
canvasShadow: {
  offset: typeof canvasShadow.offset === 'number'
    ? clampCanvasShadowOffset(canvasShadow.offset) : fallback.canvasShadow.offset,
  color: color(fallback.canvasShadow.color, canvasShadow.color),
}
```

zod 的 `mapStyleSchema` 也给了 `.default(() => ({ ...DEFAULT_MAP_STYLE.canvasShadow }))`；
旧草稿 / 旧主题（没有这个键）解析出来就是 36px 黑色。

### 2.4 顺手修的一处兼容

`MAP_STYLE_FIELDS` 的 `read` 是直接取属性（`style.canvasShadow.offset`）。地图编辑器的
风格一定经 `editorStore` 的 `resolveMapStyle`，没问题；但**主题概览页**与
`ThemeStyleRow` 之前是 `theme.data.style ?? DEFAULT_MAP_STYLE` —— 老主题的 `style` 是
旧形状（有值、但缺 `canvasShadow`），`??` 不会触发，随后读字段就拿到 `undefined`。

- `ThemeOverviewPage`：`style` / 表单初值都改成 `resolveMapStyle(theme.data.style)`；
- `ThemeStyleRow`：先判 `theme.data.style` 是否存在（保留「主题还没设缺省风格」的语义），
  存在再 `resolveMapStyle`。

这样老主题打开表单、比对差异都不会炸，保存时也顺手把新键补齐。

## §3 清除工具：悬停预览与按钮同一张图

### 3.1 问题

「清除」按钮（`toolIcons.clear`）在作者配了图时画的是那张上传图，但指针移到格子上
时，工具提示层（`MapGameToolHintLayer`）仍然画内置的 SVG 橡皮 —— 按钮上是 A，指针
底下预告的是 B。禁止符号早在 v0.8.6 就统一过（按钮图 = 预览图），清除这一枚当时漏了。

### 3.2 做法

- `MapGameToolHintLayer` 新增可选 `clearIcon`（`ToolIconRender | null`）：
  `hint.kind === 'eraser'` 且 `clearIcon` 存在时画那张图（`objectFit: contain`，
  以格子中心为准）；没配图仍走原来的 SVG 橡皮。
- `GamePage` 把 `toolIcons.clear` 传给提示层。

与禁止符号的差别在**角色**：禁止符号是「将要落下的东西」的预告，铺满大半个格子；
清除图标是**光标**，只需要说明「这一格归清除工具管」。

### 3.3 更大 + 白描边（同日追加）

第一版让上传图与内置字形共用 42% 的 footprint。看下来偏小，而且作者上传的图标
多半是「深墨画在透明底」，落在有纹理的地图上会和底纹糊在一起。改为：

- **尺寸 42% → 60%**（`GAME_TOOL_HINT_CLEAR_ICON_RATIO`），仍居中、不溢出格子；
  内置 SVG 橡皮不变（仍是 42%、无描边）—— 它本来就和按钮的 lucide 图标同形。
- **白色描边**：4 向硬 `drop-shadow`（上 / 下 / 左 / 右各一道 `#ffffff`），半径按
  格子大小取（`max(1, cellSize * 0.02)`），放大后描边同比例变粗。描边跟着图片的
  alpha 走，不会把透明区涂白。
- 白边让图标从地图里「浮」出来：一眼看得出是工具，不是地图内容。

### 3.4 验证

- `GamePage.test.tsx` 用例：配了 `puzzle.toolIcons.clear` → 短按清除按钮进入清除态
  → 指针移到画布 → `<main>` 里出现同 `src` 的 `<img>`（按钮图标在 `<aside>`，所以
  `main img` 只可能是提示层）。断言同时钉住：宽度 = 格子宽 × 0.6、`filter` 含 4 道
  `#ffffff` 的 `drop-shadow`。
- 注意：仓库自带的演示包（`dist-player/hlm`）**没有任何一题配清除图标**，真页面上
  看到的仍是内置橡皮 —— 这条链路由 jsdom 用例覆盖，不靠肉眼。

## §4 游戏页操作吐司精简：全删

### 4.1 清单与结论

对局中玩家实际能见到的吐司只有两条（详见本节末尾的清单）：

1. 放置编号时该格已满 → `该格编号已满（最多 9 个）`（error）
2. 长按清除按钮清空全部成功 → `已清空全部放置`（success）

另有一处**永远不可达**的文案：`duplicate` 分支的 `该格已有编号 ${编号}` —— 短按
「已有该编号」是 toggle 删除，`placementBlockReason` 已不返回 `duplicate`。

用户判断后决定：**A + B 全删**（上面两条 + 死分支），于是对局中**不再有任何操作吐司**。

### 4.2 改动

- `dispatchCell`：被拒时不再拼提示、不再 `toast.error`，只剩 `return false`。
  随之删除 `describeBlock` 整个函数（含 `duplicate` 死分支与三条已静默的分支）。
- 长按清空：删掉 `toast.success('已清空全部放置')`；棋盘当场变空就是反馈。
- `quiet` 机制一并退场（它唯一的用途是滑动时压掉吐司），`dispatchCell` 的
  `options` 参数与六个调用处的 `{ quiet: true }` 全部移除。
- `GamePage.tsx` 不再 `import { toast } from 'sonner'`。`main.tsx` 的全局
  `<Toaster>` 保留 —— 制作端（部署、封面、资源等）仍在用。

放置规则本身**不变**：不可站立 / `×` 格 / 头像格 / 满格仍然挡，只是不说话了。
（这也是 v0.7.11 → v0.9.0 §18 一路把拒绝改静默的终点：最后一枚会说话的也收了。）

### 4.3 验证

- web **967 / 69** 全过（本次不新增用例：删掉的是提示，既有的「没有 toast」断言
  仍然成立）。
- `npm run typecheck` 三 workspace 全过；`build` 与 `build:player` 通过 —— 播放器
  `vendor-ui` 的 chunk hash 变了，正是 `sonner` 从这个入口的依赖图里消失。
- 对局页（含播放器）现在没有任何 `toast.*` 调用点。

## §5 物品描边：宽度 + 颜色进配置（默认关闭）

### 5.1 需求

「物品描边添加配置宽度和颜色，在主题和地图配置中添加，主题是缺省的，默认无描边。」

### 5.2 数据

`MapStyle` 新增一块：

```ts
export interface MapStyleItemOutline {
  width: number;   // 基准宽度，随方格尺寸等比缩放；0 = 不描边
  color: string;   // #RRGGBB
}
```

- 出厂 `{ width: 0, color: #000000 }` —— **默认无描边**。
- 因为 `MapStyle` 同时是**地图级缺省**与**主题缺省风格**（`themes.data.style`）的形状，
  加进来之后三处自动对齐：地图「基本信息」抽屉、主题概览页「地图初始样式」、风格
  差异弹窗（新增「物品」组）。
- zod：`width` 夹在 `0 ~ 12`，`color` 收 `#RRGGBB`；缺键按 `DEFAULT_MAP_STYLE` 补齐，
  所以老主题 / 老草稿解析出来就是「不描边」。
- 前端 `resolveMapStyle` 同样补齐并夹取；`MAP_STYLE_FIELDS` 里多了
  `itemOutline.width / color` 两项，差异弹窗与主题表单自动带上它们。

### 5.3 渲染

- `MapItemLayer` 新增 `itemOutline` 入参；`itemOutlineFilter(outline, cellSize)`
  生成 **4 向硬 `drop-shadow`**（上 / 下 / 左 / 右），颜色取配置值，宽度先经
  `styleLineWidth` 按方格尺寸缩放 —— 与线宽同一套规矩。
- 这是**剪影描边**：跟着物品图片的 alpha 走，透明背景的物品得到一圈贴着实物的边，
  而不是一个矩形框；色块物品（`bgColor`）则得到矩形描边。
- `width === 0` 时返回 `undefined`，DOM 上**不挂 filter** —— 默认状态与改动前逐字节
  一致，不会因为多一个零宽 filter 触发离屏渲染。
- 有描边时容器的 `overflow` 放开为 `visible`：drop-shadow 会朝四周扩出几像素，
  原本容器会在边框盒处切掉。
- 四个画布入口都传 `style.itemOutline`：游戏页、地图版本预览、谜题预览、编辑器。

### 5.4 验证

- `MapAssetLayers.test.tsx` 新增 3 条：宽度 0 不挂 filter；宽度 > 0 时图片带 4 道
  `drop-shadow` 且颜色取配置；色块同样带描边。
- `mapStyle.test.ts` 新增 3 条：出厂宽度 0 且 filter 为 `undefined`；4 向 + 颜色 +
  基准宽度不缩放；宽度被夹在 `0 ~ 12`。
