# v0.11.4 — 区域标题跟着亮、列表按名字排、物品提示到最上层

## 0. 范围与口径

用户提了三件事（`m05054`、`m05323`）：

1. 触发区域高亮时，不仅区域边框高亮线出现，**区域标题**也要高亮。
2. 资源、角色列表按首字母排序（中文按拼音首字母）；资源 / 角色列表页和地图 /
   谜题编辑页里的都要按这个排序，**多形态放一起**。
3. 物品 tip 标签出现在**地图最上层**，且标签**默认在鼠标上方**。

口径：

- **区域标题的「高亮」就是它自己那份 hover 样式**（`hoverColor` / `hoverFontSize`
  / `hoverStrokeColor`）。不另造一套高亮配色 —— 作者已经在区域样式里配过一次
  「被指着时长什么样」，再加一套只会让两处打架。
- **悬停与联动高亮是同一件事**：这块区域正被指着。两者共用同一个判定，不写两条
  分支。
- **排序在前端做**，不动接口、不动数据库、不加 `sort` 参数。列表页与编辑器读的
  是同一份查询结果，前端排一次就都对了。
- **中文拼音序用 `Intl.Collator('zh-CN')`**，不引拼音库：它的中文序就是拼音序，
  而拼音序天然与「按首字母分组」一致（比较两个音节时先比首字母、再比余下部分）。
- **「多形态放一起」= 排资源、不排形态**。一个资源的几个形态必须挨在一起，形态
  之间的相对次序仍由资源自己声明。
- **参与者槽位、画布上已放置的物品不排**：那里的顺序是作者排的位置（1 号、2 号、
  第几格），属于谜题内容，不是「库」。
- **名字纸片不塞进 `MAP_LAYER_Z` 那 16 层**：那 16 层是**画布内容**的次序，纸片是
  「读物品名字」的 affordance，与编辑器那些拖拽 / 框选反馈同一类。为它单独立一个
  常量 `ITEM_NAME_TIP_Z`，取鼠标光标框 +1（= 47），16 层的层号一个都不用动。
- **纸片的位置用画布绝对坐标**：既然它已经独立成层，就没必要再相对物品框换算，
  少一层减法也就少一处「padding box 与 border box 差几像素」的坑。

## 1. 区域标题跟着联动高亮一起亮

### 1.1 改之前

区域高亮分两路，各自为政：

| 层 | 文件 | 认什么 |
|---|---|---|
| 边框高亮线 | `packages/web/src/components/map/MapOverlayLayers.tsx` 的 `MapHighlightLayer` | `highlight.regionBorders` |
| 标题 | `packages/web/src/components/map/MapOverlayLayers.tsx` 的 `MapRegionLabelLayer` | 只认 `hoveredRegionId` |

于是联动高亮（选中参与者 → 关联区域）时，线亮了、标题纹丝不动。作者配的
`hoverColor` 那一套等于白配了一半。

### 1.2 改法

`MapRegionLabelLayer` 多一个入参，与 `hoveredRegionId` 并列：

```ts
export function MapRegionLabelLayer({
  regions,
  cellSize,
  style,
  hoveredRegionId = null,
  highlightedRegionIds = NO_HIGHLIGHTED_REGIONS,
  onHover,
  onSelect,
}: {
  // …
  highlightedRegionIds?: readonly string[];
}): JSX.Element
```

每块区域判一次「是不是正被指着」，三处样式统一读这一个布尔：

```ts
const hovered = hoveredRegionId === region.id;
/** 悬停与联动高亮是同一件事 —— 这块区域正被指着，标题就亮。 */
const lit = hovered || highlightedRegionIds.includes(region.id);

color: lit ? label.hoverColor : label.color,
fontSize: scaleFontSize(lit ? label.hoverFontSize : label.fontSize, scale),
WebkitTextStroke: `${strokeWidth}px ${lit ? label.hoverStrokeColor : label.strokeColor}`,
```

三个调用点把 `regionBorders` 摊成 id 清单传下去（`undefined` 时用模块级空数组，
免得每次渲染造一个 `[]`）：

```tsx
highlightedRegionIds={highlight?.regionBorders.map((border) => border.regionId)}
```

- `packages/web/src/components/game/GameBoardLayers.tsx`（游戏页）
- `packages/web/src/pages/PuzzleViewPage.tsx`（谜题预览）
- `packages/web/src/components/map-editor/EditorCanvas.tsx`（地图编辑）

`packages/web/src/pages/MapViewPage.tsx` 没有联动高亮（只有悬停），不传 —— 悬停那条
路本来就会点亮标题。

### 1.3 为什么复用 hover 样式

`hoverColor` / `hoverFontSize` / `hoverStrokeColor` 本来就是「这块区域被指着时长
什么样」。联动高亮的语义与悬停完全同构，复用之后：

- 作者只配一处，两种触发看到的是同一个效果；
- 不需要在区域样式里加第三套字段，也不必维护两套默认值；
- 现有的 `transition`（`font-size` + `-webkit-text-stroke-color`）自动生效，亮起来
  不是硬切。

## 2. 资源 / 角色列表按名字排序

### 2.1 为什么用 `Intl.Collator('zh-CN')`

`zh-CN` 的中文排序就是拼音序。实测（Node，ICU 78.3）：

```
输入：鸳鸯 袭人 宝钗 探春 晴雯 黛玉 平儿 贾宝玉 王熙凤 李纨 麝月 湘云
输出：宝钗 黛玉 贾宝玉 李纨 平儿 晴雯 麝月 探春 王熙凤 袭人 湘云 鸳鸯
        B    D    J     L    P    Q    S    T     W     X    X    Y
```

首字母正好是递增的 —— 因为拼音序比较两个音节时先比首字母、再比余下部分，所以
「按首字母分组」是它的自然结果，不必自己维护一张拼音表（漏字）也不必引第三方
库（多背几十 KB）。

两条已知次序，是 CLDR 的中文规则，不是本仓的偏好：

- 汉字排在拉丁字母**之前**（`阿` < `apple`）；
- 数字与符号在汉字之前（`123` < `阿`）。

### 2.2 `packages/web/src/lib/nameOrder.ts`

```ts
export interface NamedRow {
  name: string;
  code?: string;
  id?: number;
}

export function compareByName(a: NamedRow, b: NamedRow): number
export function sortByName<T extends NamedRow>(rows: readonly T[]): T[]
```

`compareByName` 依次比 **`name` → `code` → `id`**。后两级是为了确定性：不同资源
可以同名，只靠 `sort` 的稳定性会跟着服务端的返回次序漂，重新取一次数顺序就可能
变。`sortByName` 返回新数组，react-query 的缓存不就地改。

### 2.3 四个落点

| 页面 | 文件 | 排什么 | 排在哪 |
|---|---|---|---|
| 资源列表页 | `packages/web/src/pages/AssetsPage.tsx` | 资源 | 页面（`useAssets` 之后） |
| 角色列表页 | `packages/web/src/pages/CharactersPage.tsx` | 角色 | 页面（`useCharacters` 之后） |
| 地图编辑 | `packages/web/src/components/map-editor/AssetPalette.tsx` | 资源 | `buildTiles()` 里 |
| 谜题编辑 | `packages/web/src/components/puzzle/PuzzleEditorLeftPanel.tsx` | 角色 | `visible` 里 |

两个列表页排**在页面层**而不是列表组件里，因为页面上还有一段「没选中就选第一个」
的逻辑，挑的是 `assets[0]` / `characters[0]`：它得和列表第一行是同一份数据，否则
打开页面时高亮的是一条、右侧详情里是另一条。

```ts
const { data: rows, isLoading, isError, error, refetch } = useAssets(params);
const assets = useMemo(() => (rows ? sortByName(rows) : rows), [rows]);
```

两个编辑器排**在各自的列表组件里**，因为组件拿到的就是那一份查询数据、没有别的
顺序诉求，排在自己的渲染路径上最不容易漏。

### 2.4 多形态成组

`AssetPalette` 的瓦片是**形态**（一个形态一块，见 v0.6.1 §8.5），所以这里排的是
**资源**、不是瓦片：

```ts
for (const asset of sortByName(assets)) {
  if (assetLayerFor(asset) !== layer) continue;
  const multi = asset.variants.length > 1;
  for (const variant of asset.variants) {
    tiles.push({ key: `a${asset.id}f${variant.id}`, asset, variant, variantId: variant.id, multi });
  }
}
```

先排资源、再摊形态，同一个资源的几个形态必然相邻，形态之间的次序仍是资源自己
声明的那个（`sortOrder`）。若改成「把瓦片按名字排」，`宝箱·关着` 与 `宝箱·打开`
会被别的资源隔开 —— 那正是这次要避免的。

### 2.5 没排的列表，以及为什么

| 列表 | 为什么不排 |
|---|---|
| 参与者槽位（`ParticipantPanel`） | 顺序是作者排的「1 号、2 号」，属于谜题内容 |
| 联动对话框里的角色 / 物品（`ParticipantDrawer` 的 `characterOptions` / `itemOptions`） | 前者来自槽位，后者是画布上已放置的物品（带坐标），顺序表达「位置」 |

## 4. 物品名称提示：到最上层、默认在指针上方

### 4.1 改之前

纸片的 `<span>` 渲染在**物品自己那个 `div` 里**。那层带 `zIndex`（`itemLayer` = 38），
是个**层叠上下文** —— 里面放什么都被钉在 38 这一档，于是：

| 盖在纸片上面的 | z-index |
|---|---|
| 鼠标光标框 | 46 |
| 区域标签 | 42 |
| 工具提示层 | 41 |
| 游戏放置层 | 40 |

位置也是贴指针**右下** `+14 / +18`。

### 4.2 为什么单独立一个常量，而不是往 `MAP_LAYER_Z` 里塞一层

`MAP_LAYER_ORDER` / `MAP_LAYER_Z` 那 16 层描述的是**画布内容**谁压谁。纸片不是内容，
它是「读物品名字」的标注，与 `docs/layer-priority.md` §2 末尾那条「编辑器专属的拖拽 /
框选反馈挂在临时层」同一类 affordance。

所以：`packages/shared/src/constants/grid.ts` 新增

```ts
export const ITEM_NAME_TIP_Z = MAP_LAYER_Z.mouseCursorBox + 1; // = 47
```

代价是零 —— 16 层的层号一个没动，`game.test.ts` 里「`mouseCursorBox` 是最大值」那条
断言也不用改（纸片不在 `MAP_LAYER_Z` 里）。结案遮罩跟着从 `mouseCursorBox + 1` 改成
`ITEM_NAME_TIP_Z + 1`（48），保持「遮罩压在所有 affordance 之上」：同值时靠 DOM 顺序，
而遮罩渲染在棋盘**之前**，纸片会反过来压住遮罩。

### 4.3 `MapItemLayer` 的返回结构

从「一个 div」改成 fragment：

```tsx
<>
  <div style={{ zIndex: MAP_LAYER_Z.itemLayer }}>{/* 物品们 */}</div>
  {tip ? (
    <div style={{ zIndex: ITEM_NAME_TIP_Z }}>
      <span data-testid="item-name-tip" style={tip.style}>{tip.name}</span>
    </div>
  ) : null}
</>
```

纸片要算的那点东西（锚点、名字、样式）收进一个 `describeTip(key)`，它只读
`cells` / `assetsById` / `cellSize` / `gridSize` / `pointer`，不新增 hook。

### 4.4 位置：画布绝对坐标，默认在指针上方

独立成层之后，壳子在 `left-0 top-0`，纸片直接用画布坐标 —— 原来那套「相对物品
padding box 再减 `left/top`」的换算，以及为 padding box / border box 差几像素而写
的百分比，一起删掉。

`placeTip(anchorX, y, above, gridPx)`：

- 横向以 `anchorX` 居中；离画布左 / 右边不足 56px 时改成从锚点**向右 / 向左展开**
  （`translateX(0 / -50% / -100%)`），保证整片纸留在画布内；
- 纵向 `translateY(-100%)` 表示「底边贴在 `y` 上」（上方），`0` 表示「顶边贴在 `y` 上」
  （下方）—— 不必知道纸片真实宽高。

两个调用口：

| 场景 | 锚点 | `y` | 翻下方 |
|---|---|---|---|
| 有指针（鼠标） | 指针 `x` | `指针 y − 18` | 指针头顶不够约 50px 时用 `指针 y + 18` |
| 无指针（触屏、测试） | 物品框中线 | `物品上边 − 6` | 上边不足 32px 时用 `物品下边 + 6` |

翻边仍然用**预算**而不是实测宽高：提示要跟着指针动，等一帧量尺寸会追不上指针。

### 4.5 浏览器实测（`preview:player` + 1254×620）

悬停「假山石」：

| 量 | 值 |
|---|---|
| 纸片所在层的 `z-index` | 47 |
| 纸片 rect | `x 524, y 200, w 51, h 26` |
| 指针 | `(549, 244)` |
| 纸片底边 | `200 + 26 = 226 = 244 − 18` ✓ |
| 纸片中线 | `524 + 51 / 2 = 549.5 ≈ 549` ✓ |

即「正上方居中」，且盖在红色光标框（46）与物品之上。

## 5. 没做的

- **不做首字母分组标题**（A / B / C 那种小标题）。用户要的是「按首字母排序」，
  不是「按首字母分节」；列表是虚拟滚动 + 紧凑行，加分组头会牵动行高与定位。
- **不改接口排序**。没有加 `?sort=name`，也没有改 SQL 的 `order by` —— 前端排
  一次，列表页与编辑器都覆盖到，且不需要迁移。
- **不处理多音字**。`重`（`重庆` / `重复`）读哪个音由 collator 的规则决定，不由
  我们按词判定；要按词判定就得引入词典，代价与收益不成比例。
- **不动参与者槽位与已放置物品的次序**，理由见 §2.5。
- **不改纸片的长相与 0.32 秒延迟**。这一版只动「它在哪一层」「它在哪一边」。
- **不做触屏长按出名字**。触屏没有 hover，现在的回退是「有坐标就贴坐标、没坐标就
  贴物品框」，没有为触摸单独造一条手势。
- **不给纸片加动画**。翻边 / 收放仍是瞬间切换 —— 加过渡会让「跟着指针动」变糊。
