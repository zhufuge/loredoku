# 地图编辑器系统需求文档（v0.5.3）

**文档类型**：版本需求与验收（本文档只定义需求、设计与验收口径，不含代码实现）
**修订记录**：2026-10-16 首版 —— **提示下移 + 品牌 Logo + 封面方形 + 谜题行内编辑 + 创建即启用 + 谜题编辑器六项打磨**
**适用范围**：全局（Toast / `AppShell`）、地图列表（`/projects`）、游戏（`/play`、`/play/:slug`）、谜题（`/puzzles`、`/puzzles/:id/edit`）、物品（`/items`）、角色（`/characters`）
**前置版本**：v0.5.2（`docs/v0.5.2.md`）
**实现载体**：`packages/shared` + `packages/server` + `packages/web`（本版无迁移、无表结构变更）

> **本版主题：提示别挡手，品牌要露脸，谜题编辑器该顺的地方都顺一遍。**
>
> - **提示下移**：保存 / 发布 / 上传的 toast 不再压在工具栏那一排按钮上。
> - **Logo**：`LOREDOKU-logo.svg` 进头部、进游戏首页、进游戏页。
> - **封面**：地图卡片与游戏卡片的封面按**方形**展示（画布本就是 `n × n`），不再被裁掉上下。
> - **谜题行内编辑**：列表操作列直接给「编辑」。
> - **创建即启用**：新建物品 / 角色时只要交了图片或选了纯色块，落地就是启用态。
> - **谜题编辑器**：角色框能收能筛、主题色有色板、参与者抽屉从头部栏下方开始、标尺不再压住信息框、联动里选物品看到的是名称与业务 ID、位置条件保存后不再冒出方格信息栏。
>
> 一句话记法：**提示躲开手，Logo 到处在，封面不裁图，谜题页能直接改，谜题编辑器六处补平。**

## 3. SPEC-N04 · 卡片封面方形展示

### 3.1 依据
画布是 `n × n` 正方，导出的封面天然是方形；`aspect-[16/10]` + `object-cover`
会把方形封面的上下裁掉，地图上边缘与底边的内容在列表里看不见。

### 3.2 处理
| 文件 | 改动 |
| --- | --- |
| `components/project/ProjectGridCard.tsx` | 封面按钮 `aspect-[16/10]` → `aspect-square` |
| `components/game/GameCard.tsx` | 同上 |
| `pages/GamesPage.tsx` | 加载骨架 `aspect-[4/3]` → `aspect-square`，与实际卡片一致 |

`object-cover` 保留：方形框配方形图本就 1:1，非方形封面仍按惯例居中裁切。

### 3.3 验收
- 两处卡片源码为 `aspect-square` 且不再出现 `aspect-[16/10]`；
- `ProjectCards.test.ts` / `GamesPage.test.ts` 的断言同步改为 `aspect-square`。

## 5. FEAT-N06 · 创建带外观即自动启用

### 5.1 现状
`itemRepository.create()` / `characterRepository.create()` 把 `is_active` 写死为
`false`（OPT-305：未上传图片先停用）。v0.5.2 起新建弹窗已能直接选图 / 选纯色块，
「建完还得再点一次启用」这一步就成了纯粹的重复劳动。

### 5.2 规则
单一真源沿用 v0.5.1 的 `hasAppearance(imagePresent, bgColor)`：

```
isActive = hasAppearance(file !== null, appearanceMode === 'color' ? bgColor : null)
```

即：**选了图片 → 启用；选了纯色块 → 启用；什么都没选 → 停用（维持 OPT-305）**。

### 5.3 处理
| 层 | 改动 |
| --- | --- |
| shared · `schemas/item.ts` | `createItemSchema` 新增 `isActive: z.boolean().optional()` |
| shared · `schemas/character.ts` | `createCharacterSchema` 新增 `isActive: z.boolean().optional()` |
| server · `itemRepository` / `characterRepository` | `Create*Data` 新增 `isActive?: boolean`；`create()` 写 `data.isActive ?? false` |
| web · `api/items.ts` / `api/characters.ts` | `Create*Payload` 新增 `isActive?: boolean` |
| web · `CreateItemDialog` / `CreateCharacterDialog` | 提交时按 §5.2 计算并随 create 一起发出 |

### 5.4 上传失败的兜底
图片上传失败时，若该项**仅因为这张图**才被启用（即没有纯色块兜底），
补一次 `isActive: false` 的更新，避免留下「启用但没有外观」的记录。
纯色块不受影响——它不依赖图片。

### 5.5 验收
- 两个 create schema 接受 `isActive` 且缺省不影响旧调用；
- 两个新建弹窗的提交体里出现 `hasAppearance(`；
- `api.test.ts` 断言 `POST /items` 带 `isActive: true` 时新行 `is_active = true`。

## 6. 谜题编辑中（FEAT-N08 ~ FIX-N13）

> 以下六条全部发生在 `/puzzles/:id/edit`。

### 6.1 FEAT-N08 · 角色框可收起展开 + 角色筛选

| 项 | 处理 |
| --- | --- |
| 折叠 | 头部「角色」行变成按钮（ChevronLeft / ChevronRight），`collapsed` 为真时只渲染头部，宽度收成 `w-10`；再点一次恢复 `w-[280px]` |
| 筛选 | 头部下方常驻一个搜索框（`Search` 图标），按**名称**或**业务 ID** 不区分大小写匹配 |
| 空态 | 筛选无命中时显示「没有匹配的角色」，与「暂无角色」区分 |
| 状态归属 | `collapsed` / `keyword` 都是 `PuzzleEditorLeftPanel` 自己的 UI 状态，不进 store、不进撤销栈 |

### 6.2 FEAT-N09 · 主题色调色板

新增 `components/ui/color-palette.tsx`：一组 `THEME_COLOR_PALETTE` 色块 + 当前值高亮
（`scale-110 border-primary`），`onSelect(color)` 回调。

- `ThemeColorDialog`（参与者主题色）：把内联的色板换成该组件，行为不变；
- `PuzzleInfoDrawer`（联动主题色）：每一行在取色器与十六进制输入框之上加一排色板，
  点色块即 `patchEntry(index, { color })`。

### 6.3 FIX-N10 · 参与者信息框从头部栏下方开始

**根因**：`ParticipantDrawer` 的 `<aside className="absolute inset-y-0 right-0 z-30 …">`
是 `PuzzleEditorPage` 最外层 `<div className="flex h-screen flex-col overflow-hidden">`
的直接子节点，而该容器**没有** `relative` —— 绝对定位落到初始包含块（视口）上，
于是抽屉从视口顶端一直拉到底，把 `h-14` 的头部栏压在下面。

**处理**：把 `ParticipantDrawer` 移进 `<div className="relative flex min-h-0 flex-1">`
（头部栏的兄弟节点，本身已 `relative`），`inset-y-0` 便从头部栏下沿起算。
`EditorInfoDrawer` / `PuzzleInfoDrawer` 本来就在 `<main>` 内，不受影响。

### 6.4 FIX-N11 · 标尺 z-index 低于方格信息框

**现状**：`MapRulerStrips` 两个条带是 `z-30`，`EditorInfoDrawer` 是 `z-20`，
同在 `<main>` 内 → 标尺字符画在信息抽屉上面。

**处理**：在 shared 加一组 UI 层常量，`MapRulerStrips` 与抽屉统一引用，杜绝再次漂移：

```
UI_Z = { ruler: 10, infoDrawer: 20, drawer: 30 }
```

- `MapRulerStrips` → `zIndex: UI_Z.ruler`；
- `EditorInfoDrawer` / `PuzzleInfoDrawer` → `UI_Z.infoDrawer`；
- `ParticipantDrawer` → `UI_Z.drawer`（仍在最上）。

### 6.5 FIX-N12 · 联动 · 物品列表展示名称（业务 ID）

| 位置 | v0.5.2 | v0.5.3 |
| --- | --- | --- |
| `LinkageDialog` 物品选项 | `#{item.itemId} {item.name} × {n}` | `{item.name}（{item.code}） × {n}` |
| `ParticipantDrawer.describeLinkage` 的 item 分支 | `物品 · {name ?? #id}` | `物品 · {name ?? #id}`（不变，兜底仍在） |

`LinkageItemOption` 增加 `code: string`，由 `ParticipantDrawer` 从 `itemsById` 带上；
`item.code` 为空时退化为只显示名称。

### 6.6 FIX-N13 · 位置条件保存后不再冒出方格信息栏

**根因**：`EditorCanvas` 里 `selectCellAt()` 会同时回调 `onSelect` 与 `onSelectRegion`。
`PuzzleEditorPage` 的 `onSelect` 在 `positionPickSlot !== null` 时提前 return（正确），
但 **`onSelectRegion` 没有这道拦截** —— 只要点中的格子属于某个区域，就会
`puzzle.setSelection({ type: 'region', regionId })`，于是 `infoOpen` 变真，
抽屉一关方格信息栏就冒出来。

**处理**（两道）：
1. `onSelectRegion` 同样在 `positionPickSlot !== null` 时提前 return；
2. `saveParticipant` 保存后主动收尾：`setPositionPickSlot(null)`、
   `puzzle.setSelectedSlot(null)`、`puzzle.setSelection(null)`、`setInfoOpen(false)`
   —— 保存即关闭抽屉，且不留任何会让信息栏复活的焦点。

## 8. 实现期裁定

| # | 裁定 | 理由 |
| --- | --- | --- |
| R1 | toast 用 **`offset` 下移**而不是改到 `bottom-*` | 右侧仍是动作最少的一侧；移到底边会压住编辑器底部工具条与信息抽屉的「保存 / 取消」，比现在更糟。64px 刚好越过 `h-14` 头部栏。 |
| R2 | 封面取**方形** | 画布 `n × n`，封面天然方形；方形框不再裁切。若要回到宽幅，改回 `aspect-[16/10]` 一处即可。 |
| R3 | 「编辑」按钮放操作列**首位** | 它是该行最高频动作；表头五列与列序按 SPEC-K02 保持逐字一致，只在列内插入。 |
| R4 | 自动启用沿 **`hasAppearance`**（v0.5.1 已有）计算，不在 UI 另立规则 | 与「删图 / 删头像时有色块不停用」同一套判定，语义一致、不会两套漂移。 |
| R5 | 上传失败且无纯色块 → 回退停用 | 保持 OPT-305 的不变量「启用 ⇒ 一定有外观」，不让半成功状态留在库里。 |
| R6 | 参与者抽屉**移进 `relative` 行容器**而不是给外层补 `relative` 再用 `top` 偏移 | 移动一个 JSX 节点比硬编码 56px 稳；后者会在头部栏高度变化时再次错位。 |
| R7 | 新增 `UI_Z` 常量组统一三个抽屉 / 标尺的层级 | 现在的 `z-20` / `z-30` 散落在三个文件里，正是这次漂移的成因；收进 shared 后再改层级只需动一行。 |
| R8 | 角色框折叠 / 筛选状态留在组件内 | 纯视图状态，进 store 会污染撤销栈（v0.5.0 起 `puzzleStore` 只装谜题自己的数据）。 |
| R9 | 联动物品标签保留 `× n` 实例数 | 它是「同一物品在画布上有几个」的唯一可见信息，与 id 无关，不在本次删除范围。 |
| R10 | 本版**不加迁移** | `isActive` 只是 create 路径的可选入参，老调用缺失即走 `?? false`，与现状完全一致。 |
