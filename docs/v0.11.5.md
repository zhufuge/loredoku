# v0.11.5 — 区域格子可以改了

## 0. 范围与口径

一句话：**地图编辑器里，已有区域的格子现在能改** —— 加格、减格，改完再保存。

在此之前只有「创建区域」这一条路：圈选 → 对话框 → 落库。想改一块已经存在的区域，
只有一条**没有写在任何界面上**的捷径：选中区域后 `Shift` + 点击，逐格 `toggleRegionCell`。

本次要做的是正门。口径六条：

1. **草稿式会话，不是「点一下改一格」**。会话期间只改一份草稿，画布按草稿预览，
   确认时才落库。作者要「先把这块补成凸字形看看」，逐格立即落库意味着点错十次就要
   撤销十次。
2. **草稿存「编辑之后的完整格子集」**，不存「新增 / 移除」两个增量集。区域本来就不
   允许重叠，最终要的也正是一份格子列表；两个增量集还要在提交时合并，反而多一层
   可能对不上的状态。
3. **一笔之内方向固定**：起点格已在草稿里 → 这一笔整段移除；`Alt` 永远强制移除。
   复用 `brushStrokeErases`，与区域笔刷同一条规则 —— 画到一半不会反过来把刚加的擦掉。
4. **提交前的校验与创建一致**：至少一格 + 四邻接连通。**去掉格子也可能把区域切成
   两块**，那正是这次编辑最容易踩的坑，所以不能只在创建时查。
5. **整段编辑只占一步撤销**。store 里一个新动作 `setRegionCells(id, cells)` 一次性
   写入，而不是循环调 `toggleRegionCell`。
6. **占用了别人的格子就从那边挪走**（与创建时的「覆盖」同义），被搬空的区域随之
   消失，toast 报出挪走几格。区域永远不重叠这条不变量不因编辑而破。

## 1. 会话怎么走

| 环节 | 行为 | 代码 |
|---|---|---|
| 入口 | 区域信息框「包含 N 格」徽标右侧的 **「编辑格子」** 按钮 | `EditorInfoDrawer.tsx` 的 `RegionEditBranch` |
| 开始 | 抄一份格子草稿；工具切到「选择」；选中这块区域 | `seedRegionCellEdit(region)` |
| 画布上 | 点按 / 拖动 → 一笔格子报给页面 | `EditorCanvas` 的 `regionEdit` 分支 |
| 工具条 | 「编辑「{名称}」· `+a` / `−b` · 共 `n` 格」+ 取消 / 保存格子 | `RegionCellEditBar.tsx` |
| 保存 | 校验 → 写 store（一步撤销）→ toast → 清会话 | `commitRegionCellEdit` |
| 取消 | 点取消 / 换工具 / 区域没了 → 丢弃草稿 | `cancelRegionCellEdit` + 一个 effect |

**为什么入口在信息框而不是工具条**：改格子是「对这块区域做的事」，与「现在拿的是什么
工具」无关。作者是**先选中区域**、看着它的样式、才想起来「这条边多了一格」—— 入口就
长在那块区域的信息里。

**为什么会话期间强制「选择」工具**：区域工具会把画布上的点击当**圈选**（`regionDraftSelection`）、
橡皮会把格子当**内容**擦掉。这两件事在会话里都会把作者的意图吃掉，所以开始会话时
一律把工具切回选择。

## 2. 三个新文件 / 一处新动作

### 2.1 `lib/regionEdit.ts` —— 纯函数，全部可单测

```ts
export interface RegionCellEdit { regionId: string; cells: Set<string>; }
export function seedRegionCellEdit(region: DraftRegion): RegionCellEdit
export function strokeRegionCellEdit(edit: RegionCellEdit, keys: readonly string[], erase: boolean): RegionCellEdit
export function regionCellEditCells(edit: RegionCellEdit): Coord[]
export interface RegionCellEditDelta { total: number; added: number; removed: number; }
export function regionCellEditDelta(edit: RegionCellEdit, region: DraftRegion): RegionCellEditDelta
export function regionCellEditProblem(cells: readonly Coord[]): string | null
```

几条约定：

- `strokeRegionCellEdit` **不改入参**，每次返回新的一份 —— 否则 React 看不到变化。
- `regionCellEditCells` 先按行、再按列排序，写进 store 的次序稳定，撤销 / 重做比对
  不会因为 Set 的迭代顺序而抖动。
- `regionCellEditProblem` 的两句话直接给作者看：`区域至少要留一格` /
  `区域必须是连通的（四邻接），当前编辑把区域切成了几块`。

### 2.2 `stores/editorStore.ts` 的 `setRegionCells`

```ts
setRegionCells: (id, cells) => {
  // 区域已经没了（撤销、换版本、别处删掉）就别记一步空撤销。
  if (!get().regions.some((region) => region.id === id)) return;
  commit((next) => {
    const keys = new Set(cells.map(([x, y]) => coordKey(x, y)));
    next.regions = next.regions
      .map((region) => {
        if (region.id === id) {
          return { ...region, cells: [...cells], labelCell: computeLabelCell(cells) };
        }
        const kept = region.cells.filter(([x, y]) => !keys.has(coordKey(x, y)));
        if (kept.length === region.cells.length) return region;
        return { ...region, cells: kept, labelCell: computeLabelCell(kept) };
      })
      .filter((region) => region.cells.length > 0);
  });
},
```

`labelCell` 一并重算 —— 区域的标题挂在最底行（`computeLabelCell`），删掉最后一行却
不重算，标题就会浮在区域外面。

### 2.3 `EditorCanvas` 的第四个笔画分支

`Interaction` 多一支 `{ kind: 'regionEdit'; keys: Set<string>; erase: boolean }`，
按下时先于橡皮 / 选择判定：

```ts
if (regionEdit) {
  node.setPointerCapture(event.pointerId);
  const key = coordKey(coord.x, coord.y);
  const erase = brushStrokeErases(regionEdit.cells.has(key), event.altKey);
  const keys = new Set<string>([key]);
  interactionRef.current = { kind: 'regionEdit', keys, erase };
  setBrushCells([[coord.x, coord.y]]);
  return;
}
```

松手时 `onRegionEditStroke?.(keys, interaction.erase)` —— 画布不知道草稿长什么样，
它只负责「这一笔画了哪几格、方向是哪边」。

**预览**：`region-edit-preview` 层画在 `DRAFT_OVERLAY_Z`（与圈选预览同层）。绿框
（`rgba(34,197,94,0.28)` + 1px `rgb(22,163,74)` 内描边）标 `data-region-edit="add"`，
红框（`rgba(220,38,38,0.24)` + 1px `rgb(220,38,38)`）标 `remove`。移除那部分**不在
草稿里**（草稿存的是编辑之后的集合），所以必须拿「已提交的格子 − 草稿」算出来 ——
否则作者只能看到「加了什么」，看不到「少了什么」，而这次编辑恰恰最怕手滑删掉一块。

### 2.4 `RegionCellEditBar`

与创建区域时的 `RegionSelectionBar` 同一处（画布顶部居中）、同一副样子。多两件事：
说清**在编辑哪一块**（画布上同时有好几块区域，蓝/红预览不一定指着名字），以及把
**差量**摆出来 —— 编辑是「改」一块已有区域，作者想确认的是加了几格、减了几格。

## 3. 会话什么时候结束

| 触发 | 结果 |
|---|---|
| 点「取消」 | 丢弃草稿 |
| 点「保存格子」 | 校验通过则写入并结束；不通过则**留在会话里**，toast 说明原因 |
| 切换工具（离开「选择」） | 丢弃草稿 —— 画布的点击语义已经变了 |
| 删除这块区域 | 丢弃草稿 |
| 撤销 / 换版本让这块区域消失 | 丢弃草稿（一个 effect 兜底，`editor.regions` 里找不到就清） |

## 5. 没做的

- **不做「拖一个矩形框批量加格」**：区域不一定矩形，套索 / 矩形选择会引入第二套选区
  概念；先给点按与拖动，够用再说。
- **不在会话里改名称 / 样式**：那些走原来的「保存」，两条路各管一件事，避免一次保存
  同时提交两种修改。
- **不自动修复不连通**：切成两块时只报错，让作者自己决定补哪一格 —— 自动补一格会
  悄悄改掉作品。
- **不动那条 `Shift` + 点击的捷径**：它有测试、有注释，是老作者的手感；只是不再是
  唯一的路。
- **不做键盘逐格增删**：`Alt` 已占用（强制移除），方向键在画布上是平移。
