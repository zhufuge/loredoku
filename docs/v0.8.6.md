## 1. 概览页

### 1.1 「缺省风格」改叫「地图初始样式」

原来那个名字要读者先知道「缺省」是 default 的旧译，再猜「风格」是这个空间的什么属性。
而这个区块全部的用途只有一句：**新建的那张图会长什么样**。

改了标题，也改了同一概念在别处的说法 —— 术语只留一个：

| 位置 | 原来 | 现在 |
|---|---|---|
| 概览页卡片标题 | 缺省风格 | 地图初始样式 |
| 概览页弹窗标题 | 缺省风格 · 红楼梦 | 地图初始样式 · 红楼梦 |
| 地图「基本信息」抽屉 · Theme 行 | 主题的缺省风格 | 主题的地图初始样式 |
| 风格差异弹窗（`ThemeStyleRow`） | 主题还没有缺省风格 / 与主题的缺省风格完全一致 | …还没有初始样式 / 与主题的初始样式完全一致 |

后两处不是这次点名的区域，但**同一个东西两页两个名字**比一个拗口的名字更糟：作者在抽屉里
读到「缺省风格」，转头去概览页找不到它。

### 1.2 去掉副标题，按钮改叫「编辑」

两张卡片原来都是「标题 + 一句口径 + `编辑xxx`」：

- 地图初始样式：「新建地图时抄这一份；已经画好的图不受影响。」
- 难度分级：「部署关卡时从这几档里挑，顺序即由易到难。」

这两句都在解释一个**已经摆在眼前的清单**，占掉的却是第一屏。删掉之后卡片头只剩标题和
一个按钮，视线从标题直接落到内容上。

按钮统一成「编辑」—— 它紧挨着上面那行标题，眼睛已经把两者连起来了，再复述一遍主语只是更长。

**但可访问名不能只有「编辑」**：两个同名按钮对屏幕阅读器是读不出区别的两句话。所以视觉
文案是「编辑」，`aria-label` 仍是「编辑地图初始样式 / 编辑难度分级」（`CardHead` 里按标题拼）。

### 1.3 「方格大小」不属于风格

这一条不只是从清单里删一行。

**为什么它不是风格**：方格大小由画布尺寸和「定尺寸」那一刻算出来的值决定（`null` = 按画布
自适应），一张图一个数。同一个 `168px` 在 4×4 和 20×20 的图上完全是两种粗细。它和线宽、
颜色不是一类东西 —— 后者是「这套世界长什么样」，前者是「这张图有多大」。

**但只删清单会撒谎**。主题的 `data.style` 里仍然存着 `cellSize`，「设为主题风格」会把当时
那张图的值一并写进去，新建地图时又会被拷过去。入口藏起来了，值还在暗中决定新图的格子大小。
所以三处一起改：

| 位置 | 改动 |
|---|---|
| `lib/themeStyleFields.ts` | `THEME_STYLE_FIELDS` 过滤掉 `cellSize`（27 项 → 26 项）。只过滤**显示**，字段仍在 `MAP_STYLE_FIELDS` 里 —— 差异弹窗还要拿它去比对 |
| `server/service/mapCanvasService.ts` | 拷主题风格进新草稿时 `cellSize: null`。其余字段照旧来自主题 |
| `pages/ThemeOverviewPage.tsx` | 弹窗里的「恢复默认」改成 `resetThemeStyle()`：只把**表单上看得见的**字段拨回出厂值 |

第三条是顺手补的一个坑：原来是 `setStyle(DEFAULT_MAP_STYLE)`，那会把 `cellSize` 也拨回
`null`。作者按了「恢复默认」，一个他看不见、也改不到的字段被改掉了，保存后新图的格子尺寸
就跟他以为的不一样。改不到的东西不该被顺手改掉。

顺带删掉两处死代码：`StyleFieldControl` 里 `cellSize` 的「自适应」分支（它是唯一可空的字段，
已经不在表里），以及从没有被调用过的 `isAdaptiveField()`。

### 1.4 「地图初始样式」的版式

那张卡原来是一个 `sm:2 / xl:3` 列的三列网格，而**每个组标题 `col-span-full`**。于是每组都
必须另起一行，组尾必然剩下空格：

| 组 | 项数 | 三列下空出来的格 |
|---|---|---|
| 网格 | 2 | 1（整行只填了三分之二） |
| 边框 | 5 | 1 |
| 标签 | 9 | 0 |
| 光标 | 7 | 2 |

右半边四个洞，加上每组一条通栏小标题，读起来像一张没对齐的表。除此之外还有三处：

- 行是 `justify-between`，值贴着列右边缘 ——「4px」和「#000000」**左边缘参差**，而这一列值
  本来就是拿来竖着扫的；
- 26 行每行一条 `border-b/60`，纸面被切成格子，可每行只有二十来个字；
- 值只有 10px 等宽字，颜色块 10px：这是整块**正文**，却被排成了注脚。

改法（`ThemeOverviewPage` + `StyleValue`）：

| 位置 | 原来 | 现在 |
|---|---|---|
| 外层容器 | `grid sm:grid-cols-2 xl:grid-cols-3`，组标题跨列 | `columns-1 lg:columns-3`，**组是栏里的一段**，`break-inside-avoid` |
| 组标题 | 10px、`text-muted-foreground` | 10px + `tracking` + `text-foreground/70` + 通栏细线 —— 组在栏里上下相接，只靠位置已经分不开 |
| 行 | `div` + `justify-between`，值贴列右边缘、左边缘随长度参差 | `dl` 的 `dt` / `dd` 走同一套 `grid-cols-[1fr_max-content]`：标签占满左侧，值贴栏右边缘 —— **同一组里所有值的右边缘成一条竖线**（颜色都是 7 位十六进制，色块因此也排成一列） |
| 行分隔线 | 每行 `border-b` | 没有 —— 行距 4px + 折行 18px 已经够分开 |
| 值 | 10px 等宽 | 12px 等宽 + `tabular-nums`，色块同步到 12px |

为什么是**多栏**而不是「四个组各占一格」：四组的行数是 2 / 5 / 9 / 7，四栏并排时「网格」
那栏底下空七行，比原来的洞还难看。多栏让浏览器按高度自己分（实际落成 2+5 / 9 / 7），
既没有洞，也不用写「哪组进哪栏」的映射表 —— 那种表每加一组就要跟着改一次。

为什么只在 `lg` 以上分三栏：`md` 两栏时四段只能落成 7 行 / 16 行两栏，一高一矮比单栏更难看。
窄屏一栏竖着读，本来就是清单该有的样子。但**单栏不能沿用右对齐的列宽**：一栏宽 500+，值贴
右边缘的话标签与值之间空出大半行，读一行要横跨半屏。所以 `lg` 以下换成
`grid-cols-[max-content_1fr]` —— 标签按内容宽、值紧跟其后；代价是组与组之间的值差 9px 左右
（每组的「最长值」不同），单栏里没人拿它竖着扫，这点参差可以接受。

实测（1440，真页面）：

| | 改前 | 改后 |
|---|---|---|
| 卡片高度（1440） | 469px | **413px** |
| 三栏宽度（1440） | 383 / 383 / 383，含 4 个空格 | 373 / 373 / 373，**无空格** |
| 栏内对齐（1440） | 值与标签之间隔着大半列空白，分组之间也对不齐 | 值贴栏右边缘，同一组内的右边缘成一条竖线 |
| 值字号 | 10px | 12px |
| 900 宽（单栏） | 值贴右边缘，与标签隔 400px | 值紧跟标签（组间差 9px） |

1440 与 1024 下都没有截断，深色界面下组名、标签、值三层对比度都够（标签 `muted-foreground`、
值 `foreground`、组名 `foreground/70` + 细线）。

### 1.5 红楼梦的初始样式改成撕扇子那套

`hlm` 之前只配了 `accent` 与 `difficultyLevels`，`data.style` 是空的 —— 概览页那张清单渲染的
一直是 `DEFAULT_MAP_STYLE`（12px 黑框、`system` 标签字体），而空间里真在用的那张图
「撕扇子作千金一笑」是另一套深褐纸面。作者看到的是「没配过」，建新图拿到的也是那套出厂值。

现在把 `maps/12453`（4×4，draft）的 `data.style` 整份拷进 `themes.data.style`：

| 字段 | 值（改前是出厂值） |
|---|---|
| 画布外框 / 网格分隔线 | `#4A3F35` 4px / `#B8AD9C` 2px |
| 区域轮廓 / 高亮 | `#6B6257` 4px / `#F4A83A` 4px |
| 标签 | 霞鹜文楷 24px `#7A6E60`，描边 4px `#F7F1E6`；悬停 28px `#F4A83A` |
| 光标 | 白框 2px + 阴影 `rgba(0,0,0,0.15)`，阻挡色 `#9E3D3D`（正是这个空间的门牌色）；操作光标 `#3B82F6` 2px，外扩 1px |
| 标尺 | 24px / 间距 24px |

一处值得解释：`cellSize` **照抄了 168**，虽然 §1.3 刚说完它不是风格。理由不在渲染，在**比对**：
地图信息抽屉里那枚「与主题初始样式」的差异是按整份 `MAP_STYLE_FIELDS` 算的（含方格大小），
只把这一项留成 `null`，撕扇子那张图就会显示「差 1 项：方格大小」—— 而它正是被抄的那一张。
抄进来不会暗中生效：新图的初始样式由服务端统一置 `cellSize: null`（`mapCanvasService` 那条），
概览页也不列它。库里多存一个不生效的数，换作者在抽屉里看到「完全一致」。

改完重新读了一遍：`themes.hlm.data.style` 与 `maps/12453/map` 的 `draft.style` **逐键相同**
（包括嵌套四层的光标框），`accent` 与 `difficultyLevels` 原样保留。

### 1.6 样式编辑弹窗：照「地图基本信息」抽屉的骨架

§1.4 改的是**清单**，这一条改的是清单旁边那个「编辑」打开的**弹窗**。它原来是一张铺开在
672px 里的大表：

- 标签贴着左边缘、控件贴着右边缘，中间空出一百多像素 —— 一行读起来要横跨半屏；
- 「网格 / 边框 / 标签 / 光标」只是一句 10px 灰字，26 行之间连一条分隔都没有；
- 光标那七个字段平铺成七行：「阻挡色」离「鼠标光标框线宽」隔着三行，读者得自己回想它
  属于哪个框；
- 一条解释都没有 —— 同一批字段在抽屉里每个都有一个问号。

| 位置 | 改前 | 改后（＝抽屉） |
|---|---|---|
| 宽度 | `max-w-2xl`（672px） | `max-w-sm`（384px） |
| 头 / 脚 | 标题浮在 `p-6` 里，按钮跟着内容流走 | 头 `px-4 py-3` + 下边框，脚 `px-4 py-3` + 上边框，正文自己滚 |
| 分区 | `h4`，10px 灰字 | `section` + 下边框，`h3` 加粗 + 问号（`Hint`） |
| 行 | 手写 `flex justify-between gap-3` | `Row` —— 抽屉用的同一个组件 |
| 光标七项 | 平铺 | 两个 `rounded-md border p-2` 小节：鼠标光标框 / 操作光标框 |
| 阴影环 | 单个 160px 文本框 | 色块 + 128px 文本框（抽屉同一副面孔） |
| 解释 | 一条都没有 | 26 条，跟着字段走 |

三处值得解释：

**宽度为什么是 384 而不是抽屉的 320。** 抽屉的 320 是「画布已经占满剩余宽度」的妥协；
弹窗打开时整页被压暗，不必再跟谁抢地方。384 刚好放得下「标签 + 问号 + 色块 + `#RRGGBB`」
而不换行，再宽就又回到「标签与控件各站一头」。

**为什么把 26 条解释一起搬过来。** 抽屉里「区域高亮线和区域轮廓线差在哪」点一下问号就有
答案，弹窗里只能猜 —— 同一批字段，凭什么一处有解释一处没有。文案写在
`lib/themeStyleFields.ts` 的 `FIELD_HINTS` / `THEME_STYLE_GROUP_HINTS`，不写在页面里：
字段表是 `MAP_STYLE_FIELDS` 派生的，解释跟着字段走，将来加一项不会漏掉那行问号。

**为什么没把抽屉的表单抽成公共组件。** 抽屉里还有名称 / 描述 / 封面 / 画布尺寸 / 区域
编辑器，弹窗一个都没有；两边的字段集合也不同（弹窗不列方格大小，抽屉列）。抽公共组件的
做法是加十几个 `showX` 开关，那比两处各写一遍更难读。这一版选择**字段表同源**（标签、
顺序、解释、怎么写回去都只有一份），而不是 JSX 同源。

实测（1440，真页面）：

| | 改前 | 改后 |
|---|---|---|
| 弹窗尺寸 | 672 × 788 | **384 × 728** |
| 正文滚动高度 | 1004px（四段无分隔） | 1169px（四段各有下边框） |
| 四段高度 | 86 / 222 / 392 / 256 | 113 / 257 / 437 / 362 |

正文仍然要滚 —— 26 项本来就装不进一屏，抽屉也一样。浅色、深色各截了一张：分区标题走
`foreground`、行标签走 `muted-foreground`、小节边框走 `border`，三层都还分得开；
`rgba(0,0,0,0.15)` 这种长值在 128px 的框里能完整显示（原来是 96px，被截成 `rgba(0,0,0,`）。

## 2. 地图编辑：标尺默认收起

### 2.1 为什么可以默认关

标尺是画布外面那两条 `C1 C2 C3…` / `R1 R2 R3…` 的带子，它回答的问题（「这是第几列」）只在
数格子时才有意义。而它占的正是画布能用的高度与宽度 —— 一张 20×20 的图在窗口里能不能一屏
放下，取决于这两条带子在不在。

原来的缺省是「不隐藏就展示」，也就是所有人第一次进编辑器都先看见它。

### 2.2 改法：翻一个判断，不动开关

`MapEditorPage` 里那个开关一直在（底栏那枚标尺按钮），偏好也存在 `localStorage`。这次只翻
了判断的**方向**：

```diff
- return window.localStorage.getItem('loredoku.editor.ruler') !== 'hidden';
+ return window.localStorage.getItem(RULER_STORAGE_KEY) === 'visible';
```

「可配置」就是这枚按钮：点开一次记成 `visible`，之后一直是展示的。所以：

- **从没点过开关的人**（绝大多数）：从此默认收起；
- **点过的人**：`localStorage` 里已经存着 `visible` 或 `hidden`，判断结果与以前一致。

键名、组件状态、底栏按钮都没动 —— 变的只是「没有记录时算哪一边」。

### 2.3 实测

无头 Chrome（CDP）跑真实页面，`localStorage.clear()` 后进 `/hlm/maps/12453/edit`：

| 步骤 | `loredoku.editor.ruler` | 画布外的标尺带 |
|---|---|---|
| 清空后首次打开 | `hidden`（挂载时写回） | 无 —— 图直接贴着画布左上 |
| 点底栏那枚标尺按钮 | `visible` | `C1 C2 C3 C4` / `R1 R2 R3 R4` 齐出，按钮同时高亮 |

一个值得记下的观察：**关掉标尺后图本身几乎没变大**。方格大小是自适应的，多出来的 28px 会
被重新算进格子尺寸 —— 所以真正的收益不是「图变大了」，而是图外面不再有两条与它无关的带子，
左侧起点往左挪了约 26px。

## 3. 难度分级：数字档位 + 可改颜色

### 3.1 为什么换成数字

v0.8.3 的一档是 `{ key, label }`：`key` 落进 `games.difficulty`（`varchar`），名字只负责
展示。但 `key` 只有两个来源 —— 内置五个英文词，或者「添加一档」生成的 `tier-1`。它**不带
顺序**，所以「第几档」只能看数组下标：作者删掉中间一档，徽章的坡按新下标重算，后面每一档
都换了颜色；而 `tier-1` 与 `tier-3` 读起来像有先后，其实两者毫无关系。

数字把这两件事并成一件：`level` 既是身份，也是顺序。删掉第 2 档，第 3 档仍然是 3，落库的
关卡仍然读得到自己那一档；空出来的 2 就空着，不会被谁顶替。

### 3.2 存什么、映射在哪

| 位置 | 形状 |
|---|---|
| `themes.data.difficultyLevels[]` | `{ level, label, color? }`，按 `level` 升序 |
| `games.difficulty` | `smallint`（原 `varchar(32)`），存 `level` |
| 资源包 manifest `games[].difficulty` | 同一个数字 |

档位名与颜色都在主题里 —— 同一个数字在不同空间可以叫「初」，也可以叫「Very Easy」。
找不到对应档位时不报错：徽章显示「第 N 档」+ 中性灰。这是「作者删了那一档、而关卡还写着
它」唯一诚实的表达。

### 3.3 颜色：一颗 hex，两套主题各混各的

`color` 可选。没选过就还落在原来那条五档热力坡上 —— **存量主题因此一个像素都不变**，不必
补数据。选过则由它混出徽章的两个值：

```
底色 = color-mix(in srgb, <hex> 20%, hsl(var(--card)))
字色 = color-mix(in srgb, <hex> 42%, hsl(var(--foreground)))
```

混的是 token 而不是写死的白与黑，于是浅色界面得到淡彩块 + 深字、深色界面得到暗彩块 + 浅字，
一颗色两套都读得下去（v0.7.8 把五个 hex 换成 CSS 变量，正是为了不让绝对色在另一套主题里
变成亮补丁）。20% / 42% 是折中：同一颗色在暗底上会被吃掉更多，浅色下就比内置坡略深一点 ——
一个比例不可能两边都精确，这一档差异不值得让作者去挑两种颜色。

实测（青 `#0F766E`、紫 `#7C3AED` 分别给第 1、3 档）：

| 档 | 浅色底色 / 字色（`color(srgb …)`） | 对比度 |
|---|---|---|
| 初 | `0.807 0.886 0.875` / `0.104 0.263 0.241` | **8.10 : 1** |
| 通 | `0.893 0.839 0.974` / `0.284 0.164 0.450` | **8.22 : 1** |

「恢复默认色」（↺）删掉 `color` —— 回到坡上，不是回到某个写死的 hex。

### 3.4 界面上不动的那几件事

- **数字只读。** 它落库，改一次，库里那些关就全对不上。所以弹窗里只显示 `1 2 3 …`，不给
  输入框 —— 一个能改身份的输入框，出错时没有任何东西能替那些关卡改回来。
- **没有上移 / 下移。** 数字就是顺序，「把这一档挪到前面」等于改掉两档的数字，也就是把用到
  它们的关卡一起搬家。真要往中间插一档，是删掉重建、再重新部署那几关（§6 第 6 条）。
- **添加接在最大一档后面**（`nextDifficultyLevel`），不补空档：删掉第 3 档后空出来的 3 可能
  还被某条部署指着，补上去等于让一条旧关卡莫名换了难度。

### 3.5 迁移（`20260101000044_v086_difficulty_levels`）

两处，顺序不能反：

1. `themes.data.difficultyLevels`：按**当时的数组顺序**编 `1…N`，丢掉 `key`。那也正是
   v0.8.3 取坡上颜色的顺序 —— 所以迁移之后，每一条已部署的关卡仍落在同一个徽章上。
2. `games.difficulty`：先加 `difficulty_level smallint`，按所属主题的「旧标识 → 档位」
   映射回填，再删旧列、改名、`SET NOT NULL`。

三条细节：

- **认不出的旧标识**先按内置五档算（`expert` → 5），再不行落 1。它们是早就被删掉那一档的
  孤儿；编个数字只是为了让列能变成 `smallint`，界面仍会显示「第 N 档」。
- **`deleted_at` 非空的行也一起换**：列换类型是整列的事，跳过假删的行只会让一次回滚拿到
  半截数据。
- `down` 把 `1…5` 换回内置那五个名字、其余换回 `tier-N`，主题那份数据也改回 `key`。名字
  未必是原来那个，但档位本身还在，徽章长得一样。

真库上跑了 `rollback → migrate` 往返：44 行（15 / 2 / 20 / 6 / 1）在三次转换前后逐一相同，
`hlm` 的分级也从 `初 / 平 / 通 / 灵 / 仙` 原样回来。

### 3.6 播放页的徽章也认这份字样

概览页里明明配着「初 / 平 / 通 / 灵 / 仙」，玩家在 `/play` 上看到的还是「极简 / 简单 /
中等 / 困难 / 专家」。

**不是徽章不会读分级** —— `DifficultyBadge` 默认读 `useWorkspace().theme`。可播放页在
`WorkspaceLayout` 外面（v0.8.0 §18 就把播放页列在「不在工作空间里」那一组），上下文是
`null`，于是每一枚徽章都落回内置五档。后果不止「名字不一样」：主题删过档、或者序号到了 6
以上，玩家那边直接显示「第 N 档」+ 中性灰 —— 作者在概览页看到的是好好的五个徽章。

改法只有一句：**分级得由页面给**。

| 位置 | 改动 |
|---|---|
| `hooks/useThemes.ts` | 新增 `useDifficultyTiersByCode()`：取一次 `/themes`，摊成 `code → 分级` 的表，返回查表的函数（引用跨渲染稳定，它要当 props 传进每张卡） |
| `components/game/GameCard.tsx` | 多一个可选 `tiers`，原样转给 `DifficultyBadge` |
| `pages/GamesPage.tsx` / `ThemePlayPage.tsx` | 各查一次，按**每张卡自己的** `themeCode` 传下去 |

三件容易走歪的地方：

- **按卡查，不是页面级取一份。** `/play` 的「单个游戏」段会把多个主题的关卡并排摆（现在
  库里就是 `default` 与 `hlm` 两家共 12 关）。写死一份，另一半就显示成别人的叫法。
- **不塞进 `MapGameSummary`。** 那要 `games` 接口去读 `themes.data`：一条列表因为一句展示
  文字牵上另一个聚合，而且同主题的十几关会各带一份一模一样的分级。
- **一次请求，不是每张卡一次。** 主题是个位数，整份列表比分头取还小；二十几张卡各
  `useQuery` 一次只是看着整齐。

实测（真库，两家主题同时在线的 12 关，无合辑）：

| 主题 | 关卡数 | 徽章 |
|---|---|---|
| `default`（没配过分级） | 4 | 极简 / 中等 / 极简 / 中等（内置五档的兜底还在） |
| `hlm`（`初 / 平 / 通 / 灵 / 仙`） | 8 | 初 / 通 ×7 |

改动前 `hlm` 那 8 关一律是「简单」或「中等」—— 数字对得上，字全错。

## 4. 禁止符号：上传一张图，主题给缺省

### 4.1 为什么放谜题、又为什么在主题里给缺省

禁止符号住在**放置层**：它不在画布上，是玩家标记「这格排除」的结果。主题风格
（`MapStyle`）那二十几项全在描述**画布长什么样** —— 线宽、颜色、区域标签字体、光标框。
把符号塞进去，等于让一套「地图长什么样」的配置再去管一个游戏交互的记号。所以它和
`linkageColors`、名册布局、题面住在同一层：**这一关的视觉语言**，也就是谜题自己的草稿。
放在草稿里还有一个直接好处：版本行发布即冻结 —— 改图 / 换图只影响此后重新发布的关卡。

但同一个主题的关卡通常该有同一种记号，逐关手传是在重复同一件事。所以主题的 `data` 里
再放一份**缺省**：新建谜题那一刻被抄进草稿。它和 `style` / `linkageColors` 走的是同一条
S3 快照式规则（v0.8.0 §5）—— **不是运行时兜底**。理由在「主题不版本化」：如果做成兜底，
改一次主题会把已上线的游戏一起改掉，而「已发布的内容不改」是这个仓库的硬约定。

代价写在界面上：缺省只对**新建**谜题生效，改动不追溯存量（概览页卡片下一行小字说明了它）。

### 4.2 存什么

| 位置 | 形状 |
|---|---|
| `PuzzleDraft.forbiddenSymbol` | `{ path: string } \| null`，缺席 / `null` = 默认 `×` |
| `ThemeData.forbiddenSymbol` | 同一形状；新建谜题的缺省 |

- 只存 `storage/uploads` 下的**相对路径**（`puzzles/12/forbidden-symbol/<uuid>.webp`、
  `themes/3/...`），不存 URL：`PUBLIC_BASE_URL` 会随端口 / 域名变，写进 JSON 的绝对地址
  换个环境就指向别人的服务器。渲染时用 shared 的 `fileUrlFromPath` 拼站内地址。
- 上传那一刻服务端就把它转成长边 ≤ 256px 的 webp（保留透明通道），**只存这一张**：
  它画在格子里，用不着原图 + 缩略图两份。256 是「4K 屏的格子也够清楚」与「别让一份谜题
  JSON 变成几 MB」的折中。
- **不升 `PUZZLE_JSON_VERSION` / `THEME_DATA_VERSION`**：只加可选字段（`docs/data-json.md`
  §6.2 的规矩）。旧版本行没有这个键，读的时候就是「默认 ×」。
- 上一版「从资源库挑图」的设计（`assetId` / `variantId`）整个退场：`themeScope` 与
  shared `bundle.renumberPuzzleDraft` 里为它加的两段一起删掉 —— 上传图不是数据库行引用，
  主题边界与重编号都管不到它。

### 4.3 三个端点

| 端点 | 行为 |
|---|---|
| `POST /api/puzzles/:id/forbidden-symbol`（multipart `file`） | 只写文件、**不写库**；返回 `{ path, url }` |
| `POST /api/themes/:code/forbidden-symbol` | 写文件 + 写 `themes.data.forbiddenSymbol`，返回更新后的 `Theme`（**即时保存**） |
| `DELETE /api/themes/:code/forbidden-symbol` | 清掉 `themes.data.forbiddenSymbol`，返回 `Theme` |

三处值得解释：

- **谜题端点为什么不写库**：值是**草稿 JSON** 的一部分，落库走既有的「保存」按钮。抽屉里
  选完文件就上传，拿到的 path 只是本地草稿；这一刻点「取消」，文件就留在 uploads 里没人
  引用 —— 与换封面时旧图不删是同一种代价（§6 第 17 条）。
- **谜题端点为什么允许版本行 id**：`?v=` fork 态还没有可写的草稿行（保存才 fork 出新行），
  但这个端点不碰行、只把文件落到 `puzzles/<id>/`。值真正进库是 fork 保存那一步。
- **主题端点为什么即时保存**：主题没有草稿 / 版本的二分，`data` 就是当前值；上传 / 移除
  当场生效，概览页因此不需要「保存」。

路径进 JSON 前过 schema：至少两段、不许 `..` —— 它最终会被 `resolveUploadPath` 拿去读文件。

### 4.4 界面

- **谜题编辑器**「基本信息」抽屉（位置不变：基本之后、题面之前）：64px 预览 + 「选择图片 /
  更换」+「移除（回到默认 ×）」+ 一行说明。选完文件**立即上传**，返回的 path 写进抽屉的
  本地草稿 —— 与名称 / 描述 / 调色板同一个「保存」、同一个撤销步；上传中按钮显示「上传中…」
  并禁用「保存」，失败保留原值、在控件旁显示一行红字。
- **主题概览页**新增一张「禁止符号」卡片（「地图初始样式」之后、「难度分级」之前 —— 三者里
  前两个都是「新建内容长什么样」）：有图 → 62px 预览 + 更换 / 移除；没有 → `×` 占位 +
  上传图片。上传 / 移除**即时保存**，卡片下那行小字写明「只作新建谜题的默认，不追溯」。
- **新建谜题**（服务端 `createPuzzle`）：从 `themes.data.forbiddenSymbol` 深拷贝一份进草稿；
  主题没配就不写这个键。这条没有界面，是「主题默认」的全部语义。

### 4.5 玩家侧：按钮与两层都画同一张图，没配置就回退

- **工具栏按钮**（`GamePage` 右列第一枚）：配了图就画同一张图（20 × 20、`object-contain`），
  没配才退回那枚红色 `X`。这一处原来写死 `X`，理由是「它是**工具**（进入哪个模式），不是
  **符号**（格子上的结果）」—— 这条理由站不住：这个工具的全部用途就是「落下一枚作者配的
  符号」，按钮上画着写死的 `×`，配了图的作者看到的是「工具栏和画布不是一回事」。工具按钮
  上是什么，落下去就该是什么（v0.6.4 给编号立下的同一条规矩）。
- **放置层**（`MapGamePlacementLayer`）：配了图就把 `forbidden` 那格里那枚 `<text>×</text>`
  换成 `<img>` —— `object-contain`、四周内缩 9% 格宽、`data-testid` 与 `forbidden-pop`
  动效仍挂在同一个元素上。没配图时原来那支 SVG 分支**一个字没改**。
- **工具提示层**（`MapGameToolHintLayer`）：悬停预览也画同一张图。不然「悬停时是绿 ×、
  落下变图」像换了个功能 —— v0.6.4 给编号立的规矩（预告的就是落下的）同样适用。
- **回退**：缺席 / `null` → `×` 字形，不画空白。旧版本行（没有这个键）、作者清回默认、
  主题没配而谜题也没上传，三条路走的是同一个出口。
- **深色界面翻一次**（`dark:invert dark:hue-rotate-180`）：这些图多半是**深墨画在透明底上**
  —— 作者是照着浅色的地图纸挑的，直接放在 `bg-background`（深色下近黑）上等于没有。只写
  `invert` 的话，一枚红印在深色下会变成青色；补一道 `hue-rotate(180deg)` 把色相转回来，
  黑墨变白墨、红印仍是红印。

**一个只有真页面才能逮到的坑**：工具提示层的预览最初量到 `0 × 152` —— 图片是绝对定位的，
父级浮层是 `0 × 0`，Tailwind preflight 的 `img { max-width: 100% }` 于是以父级宽度 0 为上限，
把预览压成 0 宽。它在 DOM 里、在 jsdom 测试里都「存在」，屏幕上却看不见。修法是给预览包一个
**一格大小**的定位盒，让 `max-width: 100%` 的含义回到「不超过这一格」。

### 4.6 资源包

导出的包里，这一关的符号文件落在 `files/symbols/<gameKey><ext>`，该关 JSON 里的 path 被改成
**包内相对路径**（与资源图同一条约定，播放器将来用 `resolveFile` 拼包根）；文件缺失会让打包
中止（`bundle-incomplete`），与资源 / 角色图片缺图同一条完整性约定。包里没有把主题缺省单独
带一份 —— 每关的 JSON 已经带着它自己那张。

### 4.7 实测

无头 Chrome（CDP）跑真页面。数据是**接口新建的一套临时主题**（主题 + 一张 96px 的红圈图 /
角色 / 4×4 地图版本 / 谜题），流程全走真实界面：主题卡片 → 抽屉继承 → 真实文件输入上传第二
张图（蓝）→ 抽屉保存 → 工具栏保存 → 发布 → 部署 → 游戏页；量完截图后逆序拆掉，不在既有
主题里留数据。

| 项 | 量到的值（1440 × 900） |
|---|---|
| 概览页「禁止符号」卡片 | 高 130px；预览 62 × 62（原图 96px） |
| 抽屉里继承到的图 | `<img>` 62 × 62，src 指向 `themes/<主题 id>/forbidden-symbol/...` |
| 抽屉里上传后 | 预览 src 换成 `puzzles/<谜题 id>/forbidden-symbol/...`，保存后草稿 JSON 里就是这条 path |

| 工具提示层预览 | 同一张图，159 × 159，落在悬停的那一格（不是刚放下的那格） |
| 换主题缺省之后 | 已建谜题的 path 不变，`themes.data` 变成新图（不追溯） |

立刻变成蓝色那张；游戏页落下的与悬停预览的是同一张图，放置格同时激活阻挡遮罩（层的行为没变）。

工具栏那枚按钮是补做之后单独量的（真库、`/play/theme/hlm/puzzle-hlm-sishan`，这张谜题的图是
一支手绘的墨色 ×）：按钮里的 `<img>` 是 **20 × 20**、`naturalWidth` 256、无破图；深色下
计算样式是 `filter: hue-rotate(180deg) invert(1)`，截图里是一只白色的手绘 ×，与下面几枚线性
工具图标的粗细相当（它更亮一点：图是纯白，图标走 `muted-foreground`，与原来那枚红 × 的
「被强调」位置一致）。换一关没配图的（`/play/puzzle-dao`）仍是那枚红色 `×` 字形。

## 6. 没有做的

1. **主题风格里的 `cellSize` 没有被删掉。** 它还在 `MapStyle` 里（`MAP_STYLE_FIELDS`、
   `mapStyleSchema`、差异弹窗都要它），只是不再能从这个空间的概览页改，也不再被拷进新图。
   真正的来源只剩一个：某张图「设为主题风格」时，那个值会被一起写进去。想彻底不让它进
   主题风格，得在 `ThemeStyleRow` 写入时剥掉 —— 那是另一个决定。§1.5 整份照抄之后，`hlm`
   的主题风格里因此存着 `168`：它不会被任何一张新图用到（服务端统一置 `null`）。
2. **只改了地图编辑器的标尺缺省。** 地图预览、谜题编辑、谜题预览、游戏页各有自己的
   `localStorage` 键与缺省（都还是「展示」）。它们是**看的人**的偏好，改不改是分开的决定。
3. **抽屉里的「方格大小」没动。** 它是这张图的真实字段（`MapStyle.cellSize`），也正是现在
   唯一该有的入口。
4. **「恢复默认」不再能恢复方格大小。** 那条路本来就只有 `cellSize` 会走向一个非默认值 ——
   现在它不在表单上，按了也不会变。要回到自适应，去地图的「基本信息」。
5. **`aria-label` 与视觉文案不一样。** 这是为了可访问性（两个「编辑」按钮不能同名），代价是
   屏幕阅读器读出的名称比屏幕上的字长。命令菜单、自动化脚本按 `aria-label` 找按钮时要记住这点。
6. **档位数字在界面上改不了，也不能往中间插一档。** 数字是关卡记着的那个值，改它等于搬走
   用到它的那些关。要调整只能「删掉重建 + 重新部署」，或者直接改接口 / 库 —— 后者没有护栏，
   `themeDataSchema` 只保证不重复、在 1…99 内。
7. **颜色只存一颗，浅色深色共用。** 20% / 42% 那两个比例就是为此折中的：同一种色在暗底上
   比在浅底上淡，浅色下会比内置坡略深一档。想要两套各自精确，得存两颗色 + 一个主题模式判断。
8. **删掉一档不会给后面的重编号。** 空档保留（第 3 档删了，第 4 档还是 4），老关卡因此显示
   「第 N 档」+ 中性灰而不是被塞进相邻那一档。这是有意的：重编号等于让所有关卡换难度。
9. **资源包 manifest 里的 `difficulty` 从字符串变成数字。** `formatVersion` 没有跟着升 ——
   目前只有导出、没有导入，manifest 是给人看的清单；将来若做导入，需要按版本分支认两种写法。
10. **播放页为分级多取了一次 `/themes`。** 整份主题列表连四个计数一起回来了，计数那部分用
   不上。真嫌重，得给列表接口加个「只要 `data`」的写法 —— 为一句展示文字改接口，暂时不值。
11. **多栏的栏底是参差的。** 三栏各自 7 / 9 / 7 行，浏览器只保证「不留洞」和「一组不被劈
   开」，不保证三栏一样高 —— 第二栏（标签，9 项）会低出二十来行。要齐平只能给每栏指定
   高度、或者砍组，那两样都比这点参差贵。
12. **清单没有行分隔线，也没做斑马纹。** 行距 22px、每行二十来个字，靠间距已经分得开；
   再加横线就回到原来「网格纸」的样子（§1.4 的改前）。如果将来行里的值变多、变长，这条
   结论要重估。
13. **§1.5 改的是本机这台开发库里的 `hlm` 那一行**（`themes.data` 是 JSONB，整份覆盖）。
    别的环境要同样的效果，得再 PATCH 一次；这一版没有写种子、也没有迁移 —— 数据不是代码。
14. **同一句解释在仓里有两份。** §1.6 把 26 条 hint 写进了 `FIELD_HINTS`，而
    `MapInfoDrawer` 那边仍是写在 JSX 里的字符串（有些措辞更细）。两边今天说的是同一件事，
    改文案时容易只改一处。要收成一份，得先让抽屉那张表也吃 `FIELD_HINTS` —— 它的字段集合
    与弹窗不同（多了方格大小与画布尺寸），不是单纯的搬运。
15. **阴影环的文本框宽了 32px。** 弹窗里给 128px、抽屉里仍是 96px：抽屉那一栏 272px 宽，
    96px 的框放 `rgba(0,0,0,0.15)` 会截掉尾巴。两边这一处**不**完全相同，是有意为之。
16. **主题缺省不追溯。** 只在新建谜题那一刻抄一次；已经存在的谜题、已发布的关卡保持它们
    自己的值。这是 S3 快照式的代价 —— 想做「一键把这个主题已有的谜题都换成新图」，得单独
    一个批量动作，而且它改写的是草稿（已发布关卡要重新发布才会变）。
17. **上传的文件不随行删除。** 换一张图 / 清回默认 / 删掉谜题，旧文件都留在 `storage/uploads`
    下（与封面换图同策略）。它们很小（≤256px webp），但确实是孤儿；要清理得先确认没有别的
    行还引用同一条 path（复制谜题、fork 出来的草稿会共用同一张）。
18. **图片加载失败没有 `onError` 回退。** 渲染层能处理「没配置 / `null`」，处理不了「路径在、
    HTTP 404 / 断网」—— 那种情况浏览器会画一枚破图。文件由本服务的 uploads 提供，正常路径上
    不会 404；真要兜，得给 `<img>` 挂 `onError` 换成字形，那会把「渲染回退」从纯函数挪进
    组件状态。
19. **服务端不校验「这条 path 的文件真的在」。** 保存草稿时不查（打包时查：缺文件中止）。
    手写 JSON 塞一条不存在的 path 能存进去，游戏页那块就是破图 —— 与封面「只记路径」同一种
    态度。
20. **谜题预览页不出现禁止符号。** 那一页没有棋盘、没有玩家放置，符号无处可画；它只在
    游戏页（以及资源包播放器的将来实现）上有意义。
21. **玩家侧没有「自定义」入口。** 符号是作者的配置，玩家不能改 —— 与「禁止 / 清除」两个
    工具一样，属于这一关的规则，不是读者的偏好。
22. **上传中的极小窗口。** 文件已经上传完、但「保存」还没点的这段时间，值只在本页内存里；
    关掉页面这个文件就成了孤儿（第 17 条）。页脚「保存」在上传中会禁用，但 imperative 的
    deferred switch（切面板前的自动保存）没有专门拦这一帧。
23. **工具栏按钮认的是图，不是那套语义色。** 它画作者配的图，所以 `text-destructive`
    （原来那枚红 ×）失效了 —— 悬停 / 激活时变的是按钮底色，图本身不动。深色下靠
    `invert + hue-rotate` 翻一次，代价是**彩色图会被这套滤镜改写**：它不是「按明暗只翻墨色」，
    是一件全局滤镜，红印会被转到相近的色相但纯度略变。要绝对忠实，只能给按钮垫一块浅色
    底板 —— 那在深色工具栏里更像画错的图。
24. **按钮上的图固定 20 × 20（`h-5 w-5`），按内容裁边没做。** 作者那张图自带的透明留白
    不会被裁掉，所以「画得满」的图看起来比线性图标大一圈，「画得小」的就不够醒目。要按
    内容裁边得在 canvas 上量一遍 alpha，为 20px 的按钮不值。
