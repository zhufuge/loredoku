# v0.11.3 — 字体跟着字走、玩家第一眼、结算卡的图标与标题

## 0. 范围与口径

用户一次提了六件事，都是「玩家看到的那一面」：

1. 构建 player 时，读取使用特殊字体的字段，裁剪出用到的文字（主题名、结算成功标题、
   结语等等），没用到的字不打包。
2. 播放器列表页进入时先出 loading，等内容、字体、封面都加载完再展示内容。
3. 竖屏下长按清除按钮，事件不冒泡到棋盘。
4. 播放器列表页的日夜切换按钮放到 logo 标题行右边。
5. iOS 上「定案」的字变大了，且与印章一起向右偏（列表页与游戏页都有）。
6. 结算卡那行「🎉 恭喜结案」拆成两部分在主题里配置：图标（可文字、可图片，默认
   当前那个庆祝 emoji，上传图片覆盖文字）与通过标题（默认「解题成功」）。

口径：

- **字体裁剪在构建期做**，不进运行时。`subset-font` 是 Node 侧的东西，而「用到了
  哪些字」在构建那一拍已经全部可见。产物里仍然是**静态字体文件**，浏览器一侧
  没有新逻辑、没有新依赖。
- **不引入字体下载服务**。切出来的还是一份 woff2，走 Vite 的资源管线。
- **默认值只在内置那一层**。主题里没配的键就是没有这个键，读取时兜底成默认值 ——
  不把默认值抄一份写进库（抄进去之后，默认值将来一改，存量主题就停在旧版本）。
- 结算卡的图标与标题是**两份配置**，不是一个字符串：图标将来可能是图，标题永远
  是字。
- 尺寸问题一律**不用 `zoom`**。iOS Safari 对 `zoom` 的处理不可靠，这一版把「比例」
  全部落到字号与 em 上。

## 1. 字体按「这一包真正用到的字」裁剪

### 1.1 起因与量级

`packages/web/src/assets/fonts/霞鹜文楷-Regular.woff2` 是整份 GB2312 一级字表，
951928 字节（930 KB）。而一个主题包实际画出来的汉字只有几百个：主题名、关卡名、
线索、结语、区域名，加上界面自己那几十句文案。

实测（hlm 主题包，99 个文件）：

| 字符来源 | 字数 | 裁出的字体 |
|---|---|---|
| 只扫包里的 JSON | 493 | 114560 B |
| 只扫 `src/` 源码（294 文件） | 1501 | 327112 B |
| 包 JSON + 产物 chunk 与样式 | 764 | 162940 B |

第三行就是采用的方案：**包里的 JSON + 构建产物本身的文本**。不读 `src/`，因为压缩
之后的 chunk 才是真正跑在浏览器里的那一份；也不必判断「哪个源码文件进播放器」。

### 1.2 `packages/web/scripts/fontSubset.mjs`

```js
export const ALWAYS_INCLUDED   // ASCII 0x20–0x7e + 中文常用标点
export function collectCharacters(value, into = new Set())   // 递归收字符串里的每个字符
export function buildSubsetText(sources)                     // 合并、去重、按码位排序
export function findFontAssets(bundle)                       // 产物里的 .woff2/.woff/.ttf/.otf
export function collectOutputText(bundle)                    // chunk.code + 文本类 asset
export function renamedFontFile(fileName, hash)               // 扩展名前插 -<hash8>
export function replaceReferences(source, from, to)           // 原样与 encodeURI 两种写法
export function fontSubsetPlugin()                            // Vite 插件
```

三条要点：

- **`ALWAYS_INCLUDED` 不是保守，是必需**。数字与拉丁字母是运行时拼出来的（计时、
  `9x9`、`correct/total`），扫不到但一定会画；破折号、引导号、间隔号是作者正文里
  的常客。漏一个字就是一个豆腐块。
- **按码位排序**。同样的输入必须产出同样的字节，否则每次构建字体哈希都变，发布
  出去就是「一个字节没改也整包重传」。
- **必须排在 `bundleAssets()` 后面**。同一个 `plugins` 数组里的先后就是
  `generateBundle` 的先后；字符集要算上包里的 JSON，而那是 `bundleAssets` 在
  `generateBundle` 里 `emitFile` 进来的。`renderStart` / `load` 都拿不到压缩后的
  chunk 全文。

### 1.3 为什么必须改名

Vite 给资源起的哈希是**原文件**的，这里替换掉了文件内容 —— 名字不变就成了
「同名不同内容」，浏览器会拿缓存里那份旧字表继续画，新主题里多出来的字就是豆腐块。
所以按剪切后的内容算一个 8 位哈希、插到扩展名前，再把产物里所有 chunk / 文本
asset 的引用换掉（原样与 `encodeURI` 两种写法都换，中文文件名两种都可能出现）。

最坏情况是旧缓存指向一个已不存在的字体 —— `font-family` 那串栈里还有楷体兜着，
结果是「换个字体」而不是「画出方块」。

### 1.4 实测

```
[plugin loredoku:font-subset] 字体裁剪：assets/霞鹜文楷-Regular-CfZXyrS6.woff2
  930 KB → assets/霞鹜文楷-Regular-CfZXyrS6-1b5a62c4.woff2 161 KB（17%，764 个字）
```

产物里旧名的引用为 0 处。`emptyOutDir: false` 会让历史 chunk 留在目录里（旧截图
可能撞见写着旧名字的那种），正式发布走 `npm run publish:player`，它先删再建。

## 2. 列表页先出加载件，等齐了再画内容

### 2.1 为什么「等字体」是单独一件事

`registerBundledFonts()` 只往 `document.fonts` 里**登记**，不下载。字体真正到位是
第一次有文字用到它的时候。播放器列表页整页都是 `.font-kai`（品牌字标之后紧跟主题
名），于是「内容先出来 → 字体后到 → 字形刷一遍」在慢网上看得见。

`lib/fonts.ts` 新增：

```ts
export async function loadBundledFonts(): Promise<void>
```

采样串是 `'格物定案解题成功红楼梦'` —— 必须是汉字，拉丁字符会命中一个更小的子集而
不是汉字那份。每一族 `load()` 的错误都吞掉（取不到就退回系统楷体），最后
`await document.fonts.ready`。

### 2.2 `hooks/useBundledFontsReady.ts`

```ts
export function useBundledFontsReady(): boolean
export function resetBundledFontsReadyForTest(): void
```

- 结果缓存在**模块作用域**：一个产物只装一份字体，翻回列表页不重新等。
- 失败也算就绪。字体取不到该退回系统楷体，不该把玩家卡在加载页。
- 已经就绪过直接返回 `true`，不产生「先 false 再 true」的多余一帧。

### 2.3 三件事都齐了才放内容

```ts
const fontsReady = useBundledFontsReady();
const coversReady = useImagePreload(gameCoverUrls(games));
const loading = isLoading || !fontsReady || (games.length > 0 && !coversReady);

if (loading && !isError) {
  return <LoadingScreen caption="正在加载主题…" />;
}
```

- 骨架屏换成**整屏加载件**（`LoadingScreen`，左上角是先出字标、随后是 LOREDOKU
  那串字）。玩家从站外点进来，先亮字标再看内容，中间不会有「半天没动静」的空白。
- 早退放在页头**之前**是刻意的：主题名本身是 `.font-kai`，先画出来再换字形正是
  这里要消灭的那一帧。
- `!isError`：包读不出来是配置错误，那一刻已经没什么可等 —— 立刻把原因说清楚，
  别让玩家对着字标等一份永远不会到的包。

## 3. 竖屏长按清除：事件不外传

`components/game/GameToolRail.tsx` 的清除键（`title="清除放置，长按清空全部"`）三个
指针处理器都改成先截断再调回调：

```tsx
onPointerDown={(event) => { event.stopPropagation(); onStartClearPress(); }}
onPointerUp={(event) => { event.stopPropagation(); onEndClearPress(); }}
onPointerLeave={(event) => { event.stopPropagation(); onEndClearPress(); }}
```

竖屏下这一枚沉在底部横条里，与棋盘同在一个 `flex` 列 —— 按住不放的 800ms
（`GAME_CLEAR_LONG_PRESS_MS`）里，指针事件会沿 React 树冒泡上去，让外层当成「在
棋盘上按住了一格」，于是长按清空的同时又在格子上下了一手。截在按钮这一层：
长按清空是按钮自己的手势，与棋盘无关。

## 5. iOS 的定案：撤掉 `zoom`，改成缩字号

### 5.1 症状与成因

iPhone 上「定案」两个字反而变大，印章整体向右偏。观察到的形态指向外层那个
`style={{ zoom: scale }}`：`zoom` 在 iOS Safari 上不可靠（旧版本直接不认，认了的
版本也把它当缩放整页处理），比例没生效，而 `translate` 那点位移仍是绝对像素 ——
视觉上就是「字大 + 印偏」。

### 5.2 改法

`components/game/VerdictMark.tsx` 把比例落到**字号**上，这一块内部所有尺寸都是 em：

```tsx
const ratio = Number.isFinite(scale) && scale > 0 ? scale : 1;
const baseRem = large ? 8 : 4.5;               // 原 text-9xl / text-7xl
<div style={{ fontSize: `${baseRem * ratio}rem`, …(shift ? { translate } : null) }}>
```

配套三处：

- 字 `<span>` 上删掉 `text-9xl` / `text-7xl`。Tailwind 的 `text-*` 自带字号，会盖掉
  容器那个值 —— 那样比例就只对印生效，字一点不变。
- 印的边长改成显式的 em（`large ? 12 : 6` 乘比例）：原来 `h-48 w-48` 是固定 rem，
  撤了 `zoom` 之后必须自己乘比例，否则印比字大。
- `stampOffset` 与 `shift` 传进来的 px 也乘比例 —— 那是「按 1 倍字号算的位移」，
  不缩的话同样的 72px 会把印推出字列外。

纯字号缩放不碰 `transform`，与印的 `stamp-press` 关键帧互不干扰，也不需要任何
浏览器特性检测。异常比例（0 / NaN）退回 1：字号变成 0 让整块消失，是比「比例不准」
更糟的失败。

## 6. 结算卡的图标与标题，拆成两份主题配置

### 6.1 数据

`packages/shared/src/types/domain.ts`：

```ts
export interface ThemeVerdict {
  iconText?: string;              // 图标用文字（支持 emoji）
  icon?: UploadedImage | null;    // 图标用图片，有图时覆盖文字
  title?: string;                 // 通过标题
}
// ThemeData 末尾
verdict?: ThemeVerdict | null;
```

常量（`constants/game.ts`）：`THEME_VERDICT_ICON_FALLBACK = '🎉'`、
`THEME_VERDICT_TITLE_FALLBACK = '解题成功'`、`THEME_VERDICT_TEXT_MAX_LENGTH = 24`。

### 6.2 默认值在读取时兜底，不写进库

`packages/shared/src/verdict.ts`：

```ts
export interface VerdictStyle { iconText: string; iconPath: string | null; title: string; }
export function resolveVerdictStyle(verdict: ThemeVerdict | null | undefined): VerdictStyle
```

空串与全空白都退回默认 —— 那是「把输入框清空」的表达。`icon.path` 是空串时当作
没有，别拿它去拼一个空地址。

为什么不在新建主题时抄一份默认值进库：默认值将来还会变（换一个 emoji），抄进库里
的那些主题就永远停在旧那一版了。

### 6.3 上传通道

照 `ring` 那一对抄（`POST /:code/ring` + `DELETE`）：

| 层 | 新增 |
|---|---|
| 路由 `router/themes.ts` | `POST /:code/verdict-icon`、`DELETE /:code/verdict-icon`、`PATCH /:code/verdict` |
| 控制器 `controller/themeController.ts` | `uploadVerdictIcon` / `removeVerdictIcon` / `updateVerdict` |
| 服务 `service/themeService.ts` | `uploadVerdictIcon` / `removeVerdictIcon` / `updateVerdictText`（三项全空时把整个 `verdict` 键删掉） |
| 图像 `utils/image.ts` | `processVerdictIconImage` → `processSymbolImage(owner, 'verdict', buffer)`，长边 256 |
| schema | `themeVerdictSchema` 进 `themeDataObjectSchema`（那个对象是 `.strict()`，不加就判「多余键」）、`updateThemeVerdictSchema` |

改**文字**走单独的 `PATCH`，与换图分开：换图不该顺手把标题也写一遍。

### 6.4 进包

`service/bundleService.ts` 与 `ring` 同一条路：有图就 `files.take(..., 'files/verdict/verdict<ext>')`
并写进 `manifest.theme.verdict.icon`；文件不在了就在打包时中止（400 +
`bundle-incomplete`），不流出一个「玩家打开才发现图 404」的包。只配文字时 manifest
照样有 `verdict`，但包里一条 `files/verdict/` 都没有。没配的主题一个键都不多
（`'verdict' in manifest.theme === false`）—— 与 `ring` / `checkStyle` / `difficultyLevels`
完全一致的「没配就不写键」，所以不动 `BUNDLE_FORMAT_VERSION`。

播放器一侧没有新逻辑：`PlayerBundleProvider` 加一句
`themeVerdict: () => manifest?.theme.verdict ?? null`，`apiGameSource` 加
`themeVerdict: (themeCode) => verdictOf(themeCode)`（`useVerdictByCode` 是既有的
`*ByCode` 范式）。`GameSource` 接口里多这一个读点。

### 6.5 主题概览页

`components/theme-overview/GameMarksCard.tsx` 末尾加一段：图标预览（有图就画图，
否则画文字）、「结算图标」的说明（`已上传图片，图片覆盖文字` / `默认 🎉；可改文字
（支持 emoji）`）、上传 / 更换 / 移除，以及两个输入框（`aria-label="结算图标文字"`、
`aria-label="结算标题"`）。

输入框里放的是**作者显式填过的那份**（没填过就是空串），默认值只出现在
`placeholder` —— 比把默认值填进 state 更诚实：作者能看出「这一项我没配」。
两个框都**失焦**才提交，且只在值变了才发请求；空串也发（那是「改回默认」）。

### 6.6 结算卡

`components/game/GameDialogs.tsx` 的通过面标题：

```tsx
<DialogTitle className="flex items-center gap-2 font-kai text-2xl font-semibold tracking-[0.1em]">
  {verdictIconUrl ? (
    <img data-testid="verdict-icon" src={verdictIconUrl} alt="" aria-hidden="true" … />
  ) : (
    <span data-testid="verdict-icon" aria-hidden="true">{verdictIconText}</span>
  )}
  <span data-testid="verdict-title">{verdictTitle}</span>
</DialogTitle>
```

默认文案从 v0.9.7 的「恭喜定案！」改成「解题成功」（用户指定的默认值）。图标与
标题是两个节点，不是一个字符串 —— 图标将来是图，标题永远是字。

## 8. 没做的

- **不做运行时子集化**。`subset-font` 是 Node 侧依赖，进不了浏览器；产物里仍是
  一份静态 woff2。
- **不裁多份字体**。目前只有一份文楷；将来若加第二族，`fontSubsetPlugin` 会按
  `findFontAssets` 找到几个就裁几个，但字符集是同一份（不按 `font-family` 分辨
  「哪个字用哪种字体」—— 那需要把 CSS 里的字体栈也解析一遍，收益不明显）。
- **不等图片之外的资源**。列表页等的是「包 + 字体 + 封面」，不等界面里的图标 SVG
  （那些是内联 `<svg>`，不是网络请求）。
- **结算卡的图标只接受上传图或一段文字**，不做「多张图轮换」。
- **iOS 真机复验留给发布之后**。能确认的是成因（`zoom` 不被可靠支持）；实际上
  iPhone 上看是否彻底对了，要在部署后看一眼。
