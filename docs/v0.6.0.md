# v0.6.0 — 规范命名：资源 / 物品 / 阻挡

> 本版**不改行为**：只把「资源库 / 画布物品层 / 阻挡标记」这一组长期混乱的名词在代码、
> 文件、数据库与文案里一次性对齐。现状说明在
> [`docs/map-management-and-editor.md`](./map-management-and-editor.md)，本文只回答
> 「为什么这么改、改了哪些」，改完功能那份要同步。

## 0. 一句话

`items` 这张表里放的东西，用户叫「物品」，但「物品」这个词在代码里同时指了三样不同的东西
——资源库里的一行、画布上放的物件、联动指向的目标。本版把三者的名字拆开：**资源库一行叫
`asset`（资源）**，**画布上放的叫 `item`（物品）**，**联动指向叫 `asset`（指向资源，不是
指向某一格上放的物品）**。顺手把「可站立」这个双重否定的字段改成正向的「阻挡」。

## 1. 需求与裁定

| # | 需求 | 裁定 |
|---|---|---|
| 1 | 物品页 → 资源；`items` → `assets` | 资源库整层改名：表 / 文件 / API / 页面 / hook / 组件 / 类型 / 常量 / 查询键全部 `asset`（§2） |
| 2 | 物件 → 物品；`object` → `item` | 画布层改名：`cells.object` → `cells.item`、图层 `objectLayer` → `itemLayer`、`objectRef` → `itemRef`（§3） |
| 3 | `category` → `type`（`background` / `item`） | 列改名 + 值改 `'object'` → `'item'`；类型名 `ItemCategory` → `AssetType`（§2、§4） |
| 4 | `canStand` → `blocking`（**取反**） | `blocking = NOT canStand`；背景资源恒定不阻挡；「可站立」这个双重否定从模型里消失（§4） |
| 5 | 文本、文件名、API 全量替换 | 文案「物品页」→「资源」、「物件/物体」→「物品」；代码与接口全量对齐（§2、§3、§5） |

**语义取反的落地**（最易错处）：

- 旧：`canStand = false` 表示「不可站立」（要打阴影遮罩、游戏里不能放参与者）。
- 新：`blocking = true` 表示「阻挡」（同样的行为，正向表达）。
- 背景资源（`type === 'background'`）**恒定不阻挡**，`blocking` 字段对它无意义。前端用
  `blockingFor(type, blocking)` 兜底：背景恒返回 `false`，物品类型才回吐真实值。
- 收集阻挡格子的逻辑也同步取反：`collectBlockingCells` 收集 `blocking === true` 的格子
  （旧 `collectNoStandCells` 收集的是 `canStand === false`）。

**不改的东西**（有意为之）：

- `DEFAULT_ITEM_CATEGORY = 'object'`、`DEFAULT_ITEM_FIT_MODE = 'cover'` 两个常量**保留**，
  但值冻结 —— 历史迁移 `20260101000019_v052_item_fields.ts` 直接 import 它们，改值就得改
  历史迁移，越界（与 v0.5.9 的 `CARD_ROTATIONS` 同一理由）。
- `stores/editorStore.ts`、`stores/puzzleStore.ts` 保持原名（与 v0.5.9 的 editorStore 同理）。
- `items` 表的主键序列仍叫 `items_id_seq`（PG 的 `RENAME TABLE` 不改序列名，见 §4）。

## 3. 画布层：`object` → `item`

画布上放的「物件」改叫「物品」，与「资源」区分开。这一层是真形状变更，所以
`MAP_JSON_VERSION` 从 3 升到 4。

| 层 | 旧 | 新 |
|---|---|---|
| 草稿格 | `cells[k].object` | `cells[k].item` |
| 锚点引用 | `itemId`（`object.itemId` / `background.itemId`） | `assetId` |
| 占位引用 | `objectRef` | `itemRef` |
| 类型 | `DraftObjectRef` / `DraftAnchorObject` | `DraftAssetRef`（`assetId`）/ `DraftAnchorItem` |
| 图层 | `EditorLayer.object` | `EditorLayer.item`；`EDITOR_LAYERS = ['background', 'item']` |
| 图层常量 | `objectLayer` | `itemLayer` |
| 遮罩常量 | `nonStandableMask` | `blockingMask`；`NO_STAND_SHADOW_COLOR` → `BLOCKING_SHADOW_COLOR` |
| 内边距 / 悬停 | `OBJECT_PADDING_*` / `OBJECT_HOVER_*` | `ITEM_PADDING_*` / `ITEM_HOVER_*` |
| 组件 | `MapObjectLayer` / `MapNonStandableMaskLayer` | `MapItemLayer` / `MapBlockingMaskLayer` |
| 文件 | `MapItemLayers.tsx` | `MapAssetLayers.tsx` |
| 函数 | `collectObjectCells` / `collectNoStandCells` / `hasObject` / `canPlaceItemOnLayer` / `placeObject` / `clearObjectAt` / `resolveObjectAnchor` | `collectItemCells` / `collectBlockingCells` / `hasItem` / `canPlaceAssetOnLayer` / `placeItem` / `clearItemAt` / `resolveItemAnchor` |

**联动目标**：`ParticipantTarget.type` 的 `'item'` → `'asset'`，`PARTICIPANT_TARGET_TYPES =
['character', 'asset', 'cell', 'region']` —— 联动指向的是**资源**（资源库里的一行），不是
某一格上放的物品实例。

`object` 一词的歧义处理：JS 的 `typeof x === 'object'`、zod 的 `z.object(...)` 都**保留**
（那是语言 / 库自身的词，不是领域名词），只有领域里的 `cell.object` / `layer === 'object'`
/ `objectRef` 等才改名。

## 4. 数据库迁移

`packages/server/src/db/migrations/20260101000025_v060_assets_and_item_layer.ts`，
整个迁移在**一个事务**里，任一步失败整体回滚：

| 步骤 | up | down |
|---|---|---|
| 表 | `items` → `assets` | 反向 |
| 列 | `category` → `type`、`can_stand` → `blocking` | 反向 |
| 列值 | `type` 的 `'object'` → `'item'`；`blocking = NOT blocking` | 反向 |
| 索引 | `idx_items_category` → `idx_assets_type` | 反向 |
| 图片目录 | `storage/uploads/items/` → `assets/`，`image_path` 前缀同步（两个目录名都是 5 字符） | 反向 |
| 画布 JSON | `maps.data` 与 `games.snapshot.map` 里 `object` → `item`、`itemId` → `assetId`、`objectRef` → `itemRef`、`version` 3 → 4 | 反向 |
| 联动目标 | `puzzles.data` 与 `games.snapshot` 里联动 `type: 'item'` → `'asset'` | 反向 |

「磁盘目录 + 库里前缀」「列名 + JSON 键名」两件事必须放在同一个迁移里 —— 只改其一会让旧图
404 或旧引用失配。目录已手工搬过的环境（目标已存在）跳过搬运。

已知遗留（有意不动）：`items_id_seq` 主键序列仍带旧表名（PG `RENAME TABLE` 不改序列名，
功能无影响，改它要 raw SQL、收益仅可读性，与 v0.5.9 的 `map_projects_id_seq` 同一理由）。
