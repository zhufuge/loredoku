# v0.11.6 — 列表页按主题、两行可配置、难度过滤

## 0. 范围与口径

一句话：**游戏列表页现在属于某个主题** —— `/hlm/play` 只列红楼梦的关卡，两行统计
（「N 关可玩」/「已通过 N 关」）由主题自己配，并多了一排按主题分级的过滤。另有两件
顺手的小事：竖屏那个描述弹框不再顶一行标题；谜题编辑页的「引入新地图」弹框改为每次
打开才去取版本列表。

口径五条：

1. **`/play` 不消失，但它只是入口**。裸 `/play` 现在做的是「挑一个主题再换成带编码的
   地址」（`ThemeEntryRedirect module="play"`），真正的列表页在 `/:themeCode/play`。
   保留裸地址是因为老链接、书签、以及「还没选过主题」这一态都要有落点。
2. **主题编码进地址，而不是进 store**。列表页、关卡页、工坊跳转、游戏返回都从 URL 里
   读 `themeCode` —— 可分享、可刷新、可后退，也不用担心「上次看的主题」这个隐式状态
   跟地址打架。
3. **两行统计是主题配置，不是写死的句子**。「N 关可玩」和「已通过 N 关」各是一个带
   `{n}` 的模板；没配就用内置那句。同一个数字在两句里说的不是同一件事，所以是两条
   独立模板而不是「一句 + 前缀」。
4. **过滤是纯前端筛选**，不重新请求。一页几十张卡，本地 `filter` 比一次往返快得多，
   也不会因为切档把封面重新加载一遍（`useImagePreload` 只等**当前这一档**的封面）。
5. **「全部」用 `null` 表示**，不是 `0`：难度 `level` 从 1 起，0 在这套数据里不是一个
   合法档位，用它当哨兵会和「数据坏了」混在一起。

## 1. 竖屏的描述弹框不再有标题

`GameDescriptionDialog` 的 `<DialogHeader>` 加了 `sr-only`，`DialogTitle` 本身留着。

- **为什么去掉**：玩家刚点的就是头部那枚「谜题描述」图标，弹框里再顶一行同样的字，
  等于把同一件事说两遍，还占掉一行高度 —— 竖屏本来就窄。
- **为什么不是直接删掉 `DialogTitle`**：Radix 的 Dialog 没有标题会往控制台报警，读屏
  也只会念出一段没有名字的文本。`sr-only` 让标题对眼睛消失、对读屏仍然在。

## 2. 列表页按主题

### 2.1 路由

```tsx
{ path: '/play', element: <ThemeEntryRedirect module="play" /> },
{ path: '/play/:slug', element: <GamePage /> },
{ path: '/:themeCode/play', element: <GamesPage /> },
{ path: '/:themeCode/play/:slug', element: <GamePage /> },
```

静态段永远压过动态段，所以 `/play`、`/play/:slug` 不会被 `/:themeCode/play` 抢走；
`/play/theme/:themeSlug` 那两条旧合辑地址仍在，重定向到新的落点。

`ThemeEntryRedirect` 的入参放宽成 `ModuleKey | 'play'`：`'play'` 不是工作空间模块，但
「先挑一个主题、再换成带编码的地址」这件事与 `/maps`、`/puzzles` 那几条一模一样。

### 2.2 地址里的主题编码往哪儿流

| 去处 | 取值 | 代码 |
|---|---|---|
| 列表页筛选 | `useParams<{ themeCode?: string }>()` | `GamesPage.tsx` |
| 卡片链接 | `/${code}/play/${slug}` | `GamesPage.tsx` |
| 进工坊 | `workshopPath('overview', code)` | `GamesPage.tsx` |
| 游戏页返回 | `source.listHref(detail?.themeCode ?? params.themeCode ?? null)` | `GamePage.tsx` |

`GameSource.listHref` 从 `listHref()` 变成 `listHref(themeCode?: string | null)`：

- 工坊那份（`apiGameSource.ts`）：`themeCode ? \`/${themeCode}/play\` : '/play'`。
- 播放器那份（`PlayerBundleProvider.tsx`）：`() => themeHrefOf(code)` —— 包里只有一个
  主题，可选参数用不上，签名兼容即可。

**为什么游戏页的返回优先用 `detail.themeCode`**：从裸 `/play/:slug` 直接打开的链接，
地址里没有主题编码，但关卡自己知道它属于哪个主题 —— 返回时应该回到那个主题的列表，
而不是再让玩家挑一次。

## 3. 两行统计由主题配置

### 3.1 数据与常量

```ts
export interface ThemeGameListTexts { playable?: string; passed?: string; }

export const THEME_GAME_LIST_PLAYABLE_FALLBACK = '{n} 关可玩';
export const THEME_GAME_LIST_PASSED_FALLBACK = '已通过 {n} 关';
export const THEME_GAME_LIST_COUNT_TOKEN = '{n}';
export const THEME_GAME_LIST_TEXT_MAX_LENGTH = 24;
```

`ThemeData.gameList` 与 `ThemeData.verdict` 并列；`themeGameListSchema` 用 `.refine`
要求**非空文案必须含 `{n}`**（空串合法 = 用内置那句）。少了占位符的那句会失去关数，
在输入框旁边说清楚比存进去之后才发现好。

### 3.2 渲染

`packages/shared/src/gameList.ts`：

```ts
export function resolveGameListTexts(list: ThemeGameListTexts | null | undefined): GameListTexts
export function formatGameListCount(template: string, count: number): string
```

`formatGameListCount` 用 `split(TOKEN).join(String(count))` 而不是 `replace` —— 一句里
写两次 `{n}` 也两处都换。

进包：`BundleManifestTheme.gameList`，服务端 `bundleService` 原样透传（纯字符串，
不落盘）。播放器列表页读 `manifest.theme.gameList`。

### 3.3 编辑入口

主题概览页「难度分级」卡下面多一张「游戏列表文案」卡（`GameListTextsCard`）：

- 两个输入框，**失焦即存**（只有一句话、没有别的字段要一起提交，与结算标题同一手感）。
- 每格下面带一行「预览：6 关可玩」，用 6 与 3 两个样例数字。
- 存的是 `useUpdateTheme` 的整份 `data`，不新增端点。
- 清空 = 回到内置那句；把内置那句原样敲进去则算**显式配置**（存下来的是那句本身）。

## 4. 难度过滤

`packages/web/src/components/game/DifficultyFilter.tsx`，工坊列表页与播放器列表页共用：

```tsx
<DifficultyFilter tiers={tiers} value={difficulty} onChange={setDifficulty} />
```

- 「全部」打头（`value === null`），后面是这个主题的分级叫法（`resolveDifficultyTiers`）。
- `tiers.length === 0` 时整条不画 —— 只剩一枚「全部」的过滤条是噪音。
- 按钮带 `aria-pressed`，容器 `role="group"` + `aria-label="按难度筛选"`。

两处列表页的差异只有一个：工坊那边 `tiers` 来自 `theme.data.difficultyLevels`，播放器
那边来自 `manifest.theme.difficultyLevels`。统计行都按**全部关卡**算，所以切档时
「已通过 N 关」不会跟着变 —— 它说的是这个主题的进度，不是这一档的。

## 5. 「引入新地图」弹框改为按打开请求

`usePublishedVersions(enabled = true)` 多了一个开关，`PuzzleMapSwapDialog` 传 `open`。

- **为什么**：那枚弹框是常挂的（`open` 只控制内容显不显示），于是**打开谜题编辑页就会
  去取一次已发布地图版本列表** —— 而大多数时候作者只是来改线索的。
- `staleTime` 没设，所以每次重新打开都会再取一次：地图可能刚在另一个标签页发布过，
  这个弹框最怕的就是列出过期的候选。

**两条教训（写进测试里了）**：

- 断言 `onBlur` 时必须 `input.focus(); input.blur();` —— React 的 `onBlur` 挂的是
  `focusout`，直接派发 `blur` 不触发。
- 路由用例只能钉「命中哪条路由 + params」，不能钉 `element.type`：页面是懒加载的
  `LazyPage` 包着的。

## 7. 没做的

- **不做按主题分页 / 搜索**：一页几十张卡，过滤已经够用。
- **不在裸 `/play` 上做「主题选择页」**：仍按上次进入的主题直接跳过去，没有主题时去
  设置页（与 `/maps`、`/puzzles` 同一条既有规则）。
- **过滤状态不进地址**：切一档难度不会改 URL，刷新后回到「全部」。
- **不把「已通过 N 关」做成进度条**：那是另一种表达，等真有人要再说。
- **不动谜题编辑页自己那次 `usePuzzleVersions`**：它要算下一个版本号，必须在页面加载
  时就取 —— 只有「引入新地图」那个弹框可以等。
