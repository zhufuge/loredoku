# 需求 + 设计：地图编辑器 · 区域标签字体族 / 预览入口 / 信息框占据空间（v0.7.4）

> **状态**：**已实施**（2026-10-23）。需求即本文，设计即本文；实施记录见 §9。
>
> 需求原文：
> ```
> v0.7.4，编写文档，并开发
> 地图编辑器-基本信息
> - 添加区域标签的字体font-family选择
> - 去掉区域信息模块的定位按钮
> - 头部添加预览按钮，点击后进入预览页面
> - 信息框占据编辑区，信息框弹窗时不是悬浮在编辑区上，而是占据空间
> - 区域轮廓线和区域高亮线大小限制最小值改为1
> ```

## 0. 一句话

五件事，全在地图编辑器里：

1. **区域标签多一个「字体」下拉** —— 列的是**具体字体**（`系统默认` + `packages/web/src/assets/fonts/` 里的每一款，构建时自动发现），草稿里存的是**字体名**，不是 CSS 字符串；地图级缺省 + 区域级覆盖都支持。
2. **区域信息模块的「定位」按钮删除** —— 面板底部的动作收成「保存 / 删除」两个。
3. **头部加「预览」** —— 先落库、再进 `/maps/:id/views`；预览页的返回键回到编辑器。
4. **右侧面板占据空间** —— 两个信息框从「浮在画布上」改成「从画布那儿拿走 320px」，画布跟着收窄并自动重新适配。
5. **区域轮廓线下限 4 → 1** —— 区域高亮线的下限本来就是 1，这次把两者一起钉进测试。

## 1. 改之前是什么样

- **区域标签只有「字号 + 颜色」**：地图级 `regionLabel` 与区域 `style.label` 都是 `fontSize` / `strokeWidth` / 颜色那几项，字体由 CSS 继承界面字体，作者改不了。地图上的中文标签在深色画布上全靠 700 字重 + 描边撑着，没有「换一种气质」的余地。
- **区域信息模块三个按钮**：`保存 / 定位 / 删除`。`定位` 只是 `canvasRef.centerView()` —— 把视图重置回居中。
- **头部没有预览入口**：想看效果得先保存 → 回地图列表 → 找条目 → 点眼睛（v0.7.2 起）。作者在「调一个 1px 的线宽」这件事上的循环是五步起。
- **两个右侧面板都是浮层**：`EditorInfoDrawer` 与 `MapInfoDrawer` 都是 `absolute inset-y-0 right-0 w-80`，关着时挂一条 `translate-x-full` 滑走。打开面板，画布**视口一点没变**，右侧 320px 被盖住 —— 盖住的那几列既看不见也点不到，而调样式时最想看的恰恰是「贴着面板那一侧」。
- **区域轮廓线下限是 4**（`REGION_BORDER_WIDTH_MIN = 4`）。当年这条下限的用意只是「轮廓线必须比网格分隔线（2）粗一档」，于是 1~3 这个区间整段不可达。

## 2. 区域标签的字体

### 2.1 选具体字体，存字体名

下拉里列的不是「无衬线 / 衬线」这类抽象类别，而是**具体字体**：`系统默认` 加上
`packages/web/src/assets/fonts/` 里的每一款。作者要的是「换一款字」，不是「换一个
字体分类」—— 后者在 Windows 与 macOS 上画出来根本不是同一件东西。

草稿里存的是**字体名**（`WenKai`、`霞鹜文楷`），不是拼好的 CSS `font-family`：

- 草稿是可移植的 JSON（导出 / 导入 / 版本快照 / 谜题副本），存名字才可能在换机器、
  改字号、改描边之后还是同一款字体；
- 拼好的回退链一进 JSON 就没法和区域覆盖、地图级缺省合并了 —— 字符串之间没有「部分
  覆盖」这回事；
- 名字能校验。`MAP_STYLE_FONT_FAMILY_NAME_PATTERN` 只管长度（≤64）与字符集，把**引号、
  逗号、分号、圆括号**挡在门外 —— 拼回退链时唯一能注入 CSS 的位置就是字体名，而
  `fontFamilyStack` 会给它加引号。名字来自别的构建时最多回退成系统字体，不会变成一段
  可执行的样式。

`system` / `sans` / `serif` / `kai` / `mono` 这几个**内置 key** 仍然合法：老草稿存的就是
它们，`fontFamilyStack` 也仍然给它们各自的回退链。选择器里只保留「系统默认」一项 ——
其余四项是抽象的字体类别，和「选具体字体」正好相反；老草稿里的 `serif` 会以
「衬线（当前）」的形式补在列表尾部，不会因为找不到选项而被 `<select>` 静默显示成第一项
（那会让作者看到「系统默认」高亮，画布上却是另一种字）。

### 2.2 两个目录：源文件与产物

字体不能只有「一个目录」—— 源文件和要打包的产物是两种东西，混在一起就会有人把
24.7 MB 的 TTF 直接放进打包路径。

```
packages/web/
  fonts-source/               源文件 .ttf / .otf，**不进 git**（.gitignore）
    霞鹜文楷-Regular.ttf
  src/assets/fonts/           产物 .woff2，进 git，被 import.meta.glob 收走
    霞鹜文楷-Regular.woff2
    README.md
```

`src/assets/fonts/` 下的文件由 `import.meta.glob` 在**构建时**扫出来（`lib/fonts.ts`）：
加字体 = 加文件，不需要清单、不需要改代码。**只收 `woff2` / `woff`** —— 把 `ttf` / `otf`
也收进来，等于给「绕开子集化」留了一道后门，而 `dist/` 会老老实实背上那 24.7 MB。

源文件到产物之间只有一步：`npm run fonts`（`scripts/build-fonts.mjs`），见 §2.6。

| 文件名 | 字族 | 字重 |
|---|---|---|
| `WenKai-Regular.woff2` | `WenKai` | 400 |
| `WenKai-Bold.woff2` | `WenKai` | 700 |
| `Noto-Serif-SC-Bold.woff2` | `Noto Serif SC` | 700 |
| `霞鹜文楷.woff2` | `霞鹜文楷` | 400 |

规则是 `<字族>[-<字重>][-<字形>]`，只剥**尾部**的词：

- 至少留一段当字族，所以 `Noto-Serif-SC` 这种自带连字符的字族不会被拆错；
- 认不出的后缀（`-Display`）留在字族里 —— 把不确定的词猜成字重，会把两款不同字体
  合进同一个名字，那比名字难看重得多；
- 同一字族的多份文件按字重 / 字形挂成同一款字体的多个 face，下拉里只出现一次；
- `ttc` 浏览器普遍不支持，忽略。

产物文件名由源文件名决定，所以想让下拉里显示中文，源文件名就用中文。

命名约定写在目录里的 `README.md`（面向「往目录里丢文件的人」，不是需求文档）。

### 2.3 注册与加载

`registerBundledFonts()` 在 `main.tsx` 里调一次，把每个 face `document.fonts.add(
new FontFace(...))` 进字体集：

- 用 `FontFace` 而不是往页面插 `<style>`：不用拼 CSS 文本，也不会和 CSP 的
  inline-style 规则打架；
- **不主动 `load()`**：注册只是让字族可用，真正的下载发生在第一次有文字用到它时。
  十款中文字体不会在首屏一起拉，只用系统默认的草稿一个字节都不下；
- `font-display: swap`：字体没到之前先画回退链，到了再换，不出现空白方块。

产物是 `dist/assets/<name>-<hash>.woff2`，服务端对 `/assets` 挂的是 `immutable` + 一年
缓存（`packages/server/src/app.ts`），所以那 924 KB 只下这一次。

### 2.4 三级结构与兜底

- **地图级缺省** 在「地图基本信息 → 区域 → 区域标签 → 字体」，schema 默认 `system`；
- **区域覆盖** 在区域信息框，`regionLabelOverrideSchema.fontFamily` 是可选的，和别的
  字段一样「只记差异」；
- 两个方向各有一个收口：`resolveMapStyle`（读草稿）与 `resolveRegionStyle`（合并区域
  覆盖）都走 `isMapStyleFontFamilyName`。**形状不对的名字不抛错也不透传**，回落到上一级；
  **形状对、但本构建没带的名字照原样保留**，渲染时按 `"WenKai", <系统回退链>` 往下找 ——
  草稿可以带着一台机器上没有的字体继续存在，画出来只是换了回退字体。

### 2.5 UI

区域标签那块保持五行结构，只有第一行换了内容：

```
区域标签
  字体     [系统默认 ▾]
  字号     [32] [颜色]
  描边     [10] [颜色]
  高亮     [36] [颜色]
  高亮描边 [10] [颜色]
```

- 下拉是原生 `<select>`（`components/ui/select.tsx`），选项由 `fontFamilyOptions()` 生成；
  宽度从 `w-28` 放到 `w-40`，字体名比「无衬线」长得多；
- 「字体」这个词原来指的是字号，改名成「字号」后不再撞名；`MapInfoDrawer` 与区域信息框
  用的是同一个 `RegionStyleEditor`，两处自动一致；
- 目录为空时提示语直接说「把 .woff2 放进 packages/web/src/assets/fonts/」—— 只有一个
  「系统默认」的列表配一句「选字体」，是最让人不知道下一步干什么的组合。

### 2.6 体积：25 MB 的 TTF 到底怎么处理

霞鹜文楷 Regular 的 TTF 是 **24.7 MB**。这不是「大一点」，是两三个数量级：

| 形态 | 体积 | 怎么来的 |
|---|---|---|
| 源 TTF | 24.7 MB | 全字集、未压缩 |
| 全量 woff2 | 7.7 MB | 只换容器（`--charset full`，30 秒级） |
| GB2312 二级（7712 字含符号） | 1.6 MB | 裁字，`--charset gb2312` |
| **GB2312 一级 + 符号 + ASCII（默认）** | **924 KB** | 裁字，`--charset common` |
| 只 ASCII | 21 KB | 极端裁字 |

**裁字才是那一刀，woff2 只是 3 倍。** 所以 `scripts/build-fonts.mjs` 的主语是「裁」，
顺带输出 woff2。

为什么可以裁：区域名是短文本，日常地名 / 关卡名落在 GB2312 一级（3755 字）之内，
默认字集加上符号区与 ASCII 一共 4704 字。**缺字不会变豆腐块** —— 渲染时字体名后面
挂着整条系统回退链（§2.1），缺的那个字由下一款字体补上，代价只是局部字形不一致。

脚本的三个旋钮：

| 参数 | 作用 |
|---|---|
| `--charset common` | 默认。3755 汉字 + 符号区 + ASCII |
| `--charset gb2312` | 6763 汉字，有大量生僻地名的成品 |
| `--charset file:chars.txt` | 按给定字表裁，内容已封版时可以做到几十 KB |
| `--budget 600 --strict` | 单款超过 600 KB 就以非零码退出，适合放进 CI |

字表是**算**出来的，不是贴进去的：`new TextDecoder('gbk')` 遍历 GB2312 的编码区间。
贴 6763 个汉字进源码既没法审阅，换字集还得整段重贴。

**如果裁完还是嫌大**，下一步不是继续抠默认字集，而是按需子集：服务端拿到某张地图的
全部区域名（本来就知道），用同一套 harfbuzz 现裁，返回 20~40 KB 的 woff2。没做，因为
它要求服务端持有源字体、多一条带缓存的字体路由，并把「字体清单」从构建期常量改成
运行时请求 —— 在标签只有几个字、又已经懒加载 + 一年缓存的前提下，924 KB 换这套
复杂度不划算。真到了那一步，`resolveFontFamilyName` / `fontFamilyStack` 这两层不用动，
只换 URL 的来源。

## 3. 去掉区域信息的「定位」按钮

点开一个区域的入口本来就在画布上（点标签、点左面板条目），面板里再放一个「把视图重置回居中」的按钮，等于让作者为了看清刚点开的区域先**离开**它。何况 §5 之后面板不再压住画布，被遮住半边的情况也消失了。

- 删除 `EditorInfoDrawer` 的 `onLocateRegion` prop（连同两个页面里的 `canvasRef.current?.centerView()` 传参）；
- 底部动作变成 **保存 / 删除** 两个按钮，各占一半宽度；
- 视图居中仍有三条入口：底部工具条的「适应画布」、`Ctrl/Cmd + 0`、拖空白处平移 —— 一个都没少。

## 4. 头部「预览」按钮

### 4.1 入口

`EditorToolbar` 新增可选 `onPreview?: () => void`，不传即不渲染。按钮排在「版本历史」右侧，图标 `Eye`，标题「预览（只读，先保存当前修改）」。

两类宿主**不传**：

| 宿主 | 为什么没有 |
|---|---|
| 谜题编辑器 | 它预览的是谜题玩法（`/puzzles/:id/view`），从谜题列表进；地图预览不是它的动线 |
| 地图编辑器的 fork 态（`?v={n}`） | 这一屏的数据源是**版本快照**，库里那条 `maps` 行的 `draft` 可能是 `null`。预览页按 `:mapId` 读行，读不到这份快照 —— 按钮给出去只会显示「该草稿还没有画布」 |

### 4.2 点击之后

```
抽屉有未保存草稿 → 先应用（save()）
  └─ 名称为空 → 停下，留在抽屉里补完
有 dirty（画布 / 未写库的基本信息）→ persist() 保存
  └─ 保存失败 → 停下，不跳
navigate('/maps/:id/views', { state: { from: 'editor' } })
```

**为什么先保存而不是弹「未保存」确认**：预览页读的是服务端那一行的 `data`，不保存就等于给用户看上一版；而「有未保存的修改，离开将丢失」这个问句的答案，在用户点「预览」的时候已经写好了 —— 他就是要看现在的样子。把同一个念头问两遍只是多一次点击。

**为什么要 `setTimeout(0)` 再 `navigate`**：`useUnsavedChangesGuard` 的 `useBlocker` 读的是**渲染闭包**里的 `dirty`。`persist()` 落地后同一 continuation 里立刻 `navigate`，闭包里还是旧值，会被自己拦下来。这与 `forkAndSave` 里换 URL 的处理是同一处坑、同一个写法。

### 4.3 预览页的返回键

`MapViewPage` 读 `location.state.from === 'editor'`：返回键回 `/maps/:id/edit`、标题「返回编辑器」；直接打开这条 URL（列表点眼睛、版本历史「查看效果」）仍回地图列表。**只在 `state` 里带标记，不加查询参数** —— 预览 URL 还是要能干净地分享 / 刷新。

## 5. 信息框占据空间

### 5.1 布局

改之前（两个面板都是 `absolute`，盖在画布上）：

```
┌───────────┬──────────────────────────────────┬────────┐
│ 资源 | 区域 │                                  │ 信息框 │  ← 320px 压在画布上
│           │              画布 100%            │ 320px  │
│           │        ┌─ 底部工具条 ─┐           │        │
└───────────┴──────────────────────────────────┴────────┘
```

改之后（面板是编辑区那一行的**兄弟节点**，画布让出 320px）：

```
┌───────────┬───────────────────────────┬────────────────┐
│ 资源 | 区域 │                           │ 信息框 / 基本信息 │
│           │        画布（收窄）        │      320px      │
│           │   ┌─ 底部工具条 ─┐         │  （占据空间）    │
└───────────┴───────────────────────────┴────────────────┘
```

- 页面结构从「`<main>` 里一堆 absolute」变成 `<main class="flex">` 下面三块：画布区（`flex-1`，内部仍相对定位，装着画布与两条浮在画布上的工具条）→ `EditorInfoDrawer` → `MapInfoDrawer`。
- 面板宽度 `w-80`（320px）、`max-w-[50vw]`、`shrink-0`：窄屏上不能把画布挤没；`max-w` 取一半是「两个都得能用」的下限。
- 关掉时不渲染面板本体（不再留一条 `translate-x-full` 的浮层）。信息框收起时仍保留右侧那条 8px 窄条，点它展开。
- z-index 只用 `UI_Z`：信息框 `infoDrawer`（20），基本信息 `drawer`（30）—— 后者高于窄条，两个都开时窄条不会压在面板上（页面逻辑本来就保证二者互斥，这只是不让层次出岔）。
- 副作用（预期内）：底部浮动工具条居中的是**画布区**而不是整行，所以它始终在「看得见的画布」正下方。

### 5.2 画布会自动重新适配

`EditorCanvas` 一直挂着 `ResizeObserver` + 自适应居中（OPT-A01）：容器一变窄，它就重算方格边长、重新居中，并把结果回报给「基本信息」的方格大小字段。所以打开面板 = 画布**缩着小一点但仍然完整可见**，不是被裁掉一截。

视口被用户接管过（滚轮 / ± 按钮 / 拖动过画布）时，自适应会让位 —— 那是既有规则，本版不动：此时打开面板，画布只是少一块可看区域，视图不跳。

### 5.3 为什么谜题编辑器还是浮层

`EditorInfoDrawer` 加了 `layout?: 'split' | 'overlay'`，默认 `split`。谜题编辑器显式传 `overlay`：

谜题编辑器的右侧面板有**三个**（信息框 / 参与者信息框 / 谜题基本信息），后两个仍是 `absolute` 浮层。只把信息框改成占据空间，同一块区域里会同时存在「会挤压画布的板」和「压住画布的板」，拖动参与者槽位时画布宽度还会忽宽忽窄。要么三个一起改，要么一个都不改 —— 本版需求只点了地图编辑器，所以选后者，把混搭留给「谜题编辑器布局统一」那一版。

## 6. 区域轮廓线 / 高亮线的下限

| 常量 | 改前 | 改后 | 谁读它 |
|---|---|---|---|
| `REGION_BORDER_WIDTH_MIN` | 4 | **1** | `mapStyleSchema.regionOutline.width`、`regionOutlineOverrideSchema.width`、`clampRegionBorderWidth`（编辑框 `min`） |
| `MAP_STYLE_LINE_WIDTH_MIN`（区域高亮线） | 1 | 1（不变） | 高亮线的地图级 / 区域级 schema、`clampLineWidth` |

- 高亮线的下限**本来就是 1**，这次只是把它和轮廓线一起钉进测试（`canvasLayers.test` / `mapStyle.test` / `regionStyle.test`），避免两条线的区间再各自漂移。
- 上限都不动（12）。
- 缩放的既有语义让 1 有意义：线宽按 `cellSize / BASE_CELL` 缩放，大格子上 1 基准值画出来是 1.x px；小格子上它仍会被 `LINE_WIDTH_MIN` 兜住，不会变成看不见的 0。
- 默认值也不动（轮廓 12、高亮 12）—— 改的只是**允许范围**。

## 7. 顺手修掉的一处：区域标签没读区域自己的样式

v0.7.0 把区域样式做成三级，轮廓线、高亮线都按 `resolveRegionStyle(地图级, region.style)` 渲染，**唯独标签层（`MapRegionLabelLayer`）一直只读地图级那一段** —— 区域自己设的字号 / 颜色 / 描边在画布上完全不生效，只有编辑框里看得到。

新字段让这个洞变成硬伤：区域级 `fontFamily` 若照旧不生效，「区域标签的字体选择」就有一半是假的。所以本版把标签层改成与另外两层同一条路（逐区域解析），并补了组件测试（`MapOverlayLayers.test.tsx`）。

影响面：编辑器、地图预览、谜题预览、游戏页共用这一层，四处一起修正；对没写过标签覆盖的区域，解析结果与地图级完全相同，视觉零变化。

## 8. 明确不做

- **不做自定义 `font-family` 输入框**：理由见 §2.1（不可移植、无法校验、需要知道对方装了什么字体）。
- **仓库里不放任何字体二进制**：目录与约定留好，字体由部署者自己按授权放进去；不带文件时
  下拉里只有「系统默认」，功能不缺一块。
- **不改预览页的缩放 / 平移行为**（沿用 v0.7.2 的手形默认打开、无滚轮缩放）。
- **不动谜题编辑器的布局**（§5.3）。
- **不改基本信息抽屉的字段与保存语义**：抽屉的「保存」仍然只应用到页面，写库统一由工具栏「保存」完成。
- **不把区域信息框做成可拖拽宽度**：固定 320px，与左面板对称。
