## 1. 一致性：工具条不再说谎

### 1.1 视图开关下沉到「草稿」标题，版本恒为列表

**问题**：地图 / 谜题页的工具条有「网格 / 列表」切换，摆在工具条里会被读成**页面级**偏好，
但它只包住草稿块 —— 版本块恒为 `Card + ListRow`。切到网格后仍看到一列版本行，用户的判断
只能是「切换没生效」。

**走过的弯路**：先试的是「让版本块也吃切换」（`renderOrderBlock` 共用一套渲染）。实现能跑，
但方向不对——版本是**冻结快照**：`v{n}` 徽标 + 「以此为底稿新建」在列表里一行读完，做成
4:3 大封面卡片反而像一件可选的作品，而主按钮「以此为底稿新建」正好落在最显眼的位置，
误触代价是凭空多出一条草稿。

**做法**：作用域交给位置，而不是交给文案。

- `components/common/ViewToggle.tsx`：两枚 32px 分段按钮（`aria-pressed` 表达选中，
  按 `docs/design-system.md` §3.4 的例外不套悬浮提示），从工具条**下沉到「草稿」标题右侧**。
  它挨着哪一块，就只管哪一块 —— 没有草稿时它也不出现（没有作用对象）。
- `hooks/useStoredView.ts`：两个列表页原本各自复制了一份 `readStoredView` + 持久化 effect
  （键名不同、逻辑一字不差），收成一个 hook，键名仍各记各的
  （`loredoku.maps.view` / `loredoku.puzzles.view`）。
- `renderOrderBlock(entries, page, totalPages, onPage, viewMode)`：多收一个视图参数，
  草稿块传当前偏好、版本块**恒传 `'list'`**。两块的卡片、行、分页条仍共用同一套实现。
- 工具条只剩关键词与排序，右侧不再有那个「以为管全页」的开关。

覆盖：`pages/MapsPage.versions.test.tsx` 5 例 —— 网格下只有草稿出卡片（封面区计数 = 1，
版本若也变卡片会是 2）、列表下两块都是行、切回来草稿跟着变、无草稿时开关不渲染、
偏好仍持久化。

### 1.2 分页条：一个数字只说一次

**问题**：每块各印一行「第 1 / 2 页 · 共 30 个」+ 两个描边按钮。一页上出现两行，而「共 30 个」
在 section 标题（`版本 30`）里已经写过一次。

**做法**：新增 `components/common/ListPager.tsx` —— 只留「当前位置」：

```
‹  1 / 2  ›
```

条数交回标题，块的分界靠 `space-y-8` 与标题承担。只有一页时整条不渲染（「1 / 1」是噪音）。
按钮是 32px 的 ghost 图标按钮，与工具条同一档。

### 1.3 控件高度：四档，且只允许四档

| 档 | 值 | 用在哪 | 代码写法 |
|---|---|---|---|
| T1 | 28px | 面板 / 抽屉里的图标按钮（刷新、收起、抽屉关闭） | `h-7 w-7`（`PANEL_ICON_BUTTON_CLASS`） |
| T2 | 32px | 工具条图标按钮、分段控件内的按钮、分页箭头 | `h-8 w-8` |
| T3 | 36px | 紧凑文字按钮（`size="sm"`）、底栏胶囊按钮 | `h-9` |
| T4 | 40px | 标准控件：输入框、下拉、主按钮、`size="icon"` | `h-10` |

**修掉的越档**：`LinkageDialog` 里 6 个 `h-6 text-xs`（24px）的片段按钮升到 T1。24px 的点击
目标在桌面端已经偏小，而它旁边就是 40px 的输入框，视觉上像「贴在行里的小标签」。

### 1.4 部署页的错误态

`部署列表加载失败` 是六个列表页里唯一不给原因的一个。改成与其余五页同构：显示
`error.message`（服务端中文） + 「重试」。顺带把加载骨架从 `h-20` 改到 `h-16` —— 行高是 64，
骨架高 80 会让加载完成时整页跳动 16px。

## 2. 快捷键：修的是边界，不是功能

`useEditorShortcuts` 里已经有的：`Ctrl+S`、`Ctrl+Z`、`Ctrl+Shift+Z`、`Ctrl+0`、`Space`、
方向键、`Esc`。这一轮补的是**谁有资格拿到这次按键**：

1. **`<select>` 没被拦**。焦点在下拉里按 V / R / E（选地区、选形态时很自然会按），会顺带切换
   编辑工具，而工具条在屏幕另一端 —— 用户只会觉得「按了个键，工具自己变了」。
   现在 `INPUT` / `TEXTAREA` / `SELECT` / `contentEditable` 一律让位。
2. **模态框打开时快捷键穿透**。在「联动条件」「版本历史」里按 `Ctrl+Z`，撤销的是**弹窗背后**
   的画布，弹窗里的输入却不变 —— 一次误按改掉了看不见的东西。现在只要有
   `[role="dialog"|"alertdialog"][data-state="open"]`，画布快捷键整体让位。
3. **`Space` 抢按钮**。原来是无条件 `preventDefault()`，于是键盘焦点停在工具条任一按钮上时，
   按 Space 激活不了它 —— 对只能用键盘的人，这等于把整条工具条锁死。现在焦点在可激活元素
   （`button` / `a[href]` / `role=button` 等）上时直接放行。
4. **补 `Ctrl+Y`**：Windows 用户的重做习惯。之前提示上写着“重做 (Ctrl+Shift+Z)”，但它其实
   一直没生效过 —— 现在生效了。

`hooks/useEditorShortcuts.test.tsx` 7 例，逐条钉住上面四种场景 + 两个对照组（画布上 Space
仍是平移预备、输入框里 Ctrl+Z 仍是文本撤销）。

## 3. 形状：圆角、凹面、两层暖影

### 3.1 `--radius` 8 → 6px

```css
--radius: 0.375rem;   /* lg = 6px · md = 4px · sm = 2px */
```

8px 圆角 + 通用投影是 SaaS 卡片的配方。压到 6px 之后三级台阶各差 2px，形状更像「切出来的
纸边」。徽标的 `rounded`（4px）不变，它本来就在最小档。

### 3.2 凹面必须有可见的下沉

| 变量 | 浅色 | 变化 | 为什么 |
|---|---|---|---|
| `--background` | 96.5% → **96%** | −0.5 | 纸底略微压深，与卡片（99%）之间留 3 个点 |
| `--muted` | 94% → **92%** | −2 | 缩略图占位、代码块这类「凹进去的表面」原来贴着底色，三层只剩两层可读 |
| `--accent` | 87% → **85.5%** | −1.5 | ghost / 列表行的悬停底，需要看得出「这一行被指到了」 |

### 3.3 说明文字抬到真能过 AA

压深之后，`text-muted-foreground` + `hover:bg-accent` 的组合只有 **3.99:1**（列表行悬停时
的描述文字）。这在此之前就已经是 4.13 —— 一个没人量过的欠账。

| 变量 | 原值 | 新值 | 结果 |
|---|---|---|---|
| `--muted-foreground`（浅） | 30 9% 41% | **30 9% 37%** | 悬停底上 4.67，纸底上 5.85，卡片上 6.21 |
| `--muted-foreground`（深） | 34 10% 62% | **34 10% 64%** | 深色悬停底上 4.72 |

代价是全站 226 处说明文字确实变深了一点 —— 但「安静」不等于「读不出来」。

### 3.4 两层阴影，且是**暖色**

Tailwind 的 `shadow-sm/md/lg/xl` 用 `rgb(0 0 0 / α)`：黑影子落在米黄纸上会发灰发脏。这是
「皮肤换了、质感没换」的最后一处。改成两个变量：

| Token | 语义 | 用在哪 |
|---|---|---|
| `shadow-paper`（`--shadow-card`） | 静置的纸：几乎只有一条贴边接触影 | `Card`、资源瓦片悬停、参与人头像 |
| `shadow-lifted`（`--shadow-float`） | 离开纸面：接触影 + 大范围扩散 | 对话框、三个右侧抽屉、底部胶囊工具条、下拉菜单、`GameCard` 悬停 |

**踩到的坑（与 v0.7.8 的 `/12` 同源）**：一开始写的是 `shadow-[var(--shadow-card)]`。Tailwind 的
任意值阴影**先判断是不是颜色**，`var(...)` 分不出来，于是编译成
`--tw-shadow-color: var(--shadow-card)` —— 类存在、产物里查得到、页面上一点阴影都没有。
写进 `theme.boxShadow` 才正确。另外 `shadow-card` 这个名字会和调色板里的 `card` 撞车
（同时生成「阴影」和「阴影颜色」两条工具类），所以叫 `shadow-paper` / `shadow-lifted`。

## 4. 字级：从「方括号字号」到六档

### 4.1 梯级

| 档 | 字号 | 行高 | 用途 |
|---|---|---|---|
| `text-2xs` | 11px | 16px | 徽标、计数、`格`、快捷键提示 |
| `text-xs` | 12px | 16px | 元信息：时间、尺寸、描述、副标题 |
| `text-sm` | 14px | 20px | **正文、按钮、表单、列表主行** |
| `text-base` | 16px | 24px | 列表页的 section 标题（`草稿 12` / `版本 30`） |
| `text-lg` | 18px | 28px | 对话框标题 |
| `text-2xl` | 24px | 32px | 页标题（`PageHeader` 的 `h1`） |

- **81 处方括号字号**（`text-[10px]` 19 + `text-[11px]` 62）全部收成 `text-2xs`，产物里
  `.text-2xs{font-size:.6875rem;line-height:1rem}`。
- 10px 并入 11px：中文 10px 在 1x 屏上已经在糊，而这两档之前没有任何语义分工 —— 谁写哪个
  全看当时手边是哪个。
- section 标题 14 → 16：原来标题 24 之后直接掉到 14，中间没有台阶，层级只能靠「变灰」来分。
- 唯一留在梯级外的字号是 `GenderBadge` 的 ♂/♀ **符号** 13px（12 会缩成小点、14 会抢过徽标
  文字）；代码注释里写了它是「光学尺寸，不是文字档位」。

### 4.2 霞鹜文楷第一次进界面

字体早就随构建走（`assets/fonts/霞鹜文楷-Regular.woff2`，925 KB，`registerBundledFonts()` 在
`main.tsx` 注册），但过去只服务**画布里的区域标签**。`.impeccable.md` 写的「东方 · 手作」
一直压在一个看不见的 `<select>` 里。

现在用在两处：`PageHeader` 的 `h1`、404 的 `h1`。

```css
.font-kai {
  font-family: '霞鹜文楷', 'Kaiti SC', 'STKaiti', 'KaiTi', ui-serif, serif;
  font-synthesis-weight: none;
}
```

- **`font-synthesis-weight: none`**：文楷只有 400 一档，浏览器默认会给粗体做「糊边加粗」，
  楷体的笔画一糊就成了劣质国风。宁可不加粗 —— 标题的重量交给字号。
- **代价**：首屏多 925 KB（`font-display: swap`，不阻塞渲染；服务端对 `dist/assets` 是
  immutable + 一年缓存）。只在标题上用它，所以只下载一次、只有一款。
- 404 顺带从 `text-3xl`（30px，全站唯一一处）收到 24px —— 梯级里没有 30 这一档。

## 5. 图标按钮：一个提示，一个真源

### 5.1 为什么要有自己的 Tooltip

全站 100 处 `title=`，其中大部分挂在**纯图标按钮**上。原生 title 有 ~1 秒延迟、样式不可控、
深色下是系统对话框的样子，键盘焦点停留时也不出现。一个每天用一小时的工具，最常点的 28px
按钮反而最不好认。

`components/ui/tooltip.tsx`：Radix Tooltip + 项目 token（`bg-popover` / `border` /
`text-2xs` / `shadow-lifted`），**portal 到 body** —— 编辑器的左面板、抽屉、底栏都是
`overflow-hidden`，就地渲染的浮层会被裁掉一半（这也是不用纯 CSS tooltip 的原因）。

**自带 Provider**，而不是要求应用根节点包一层：Radix 缺 Provider 会直接抛错，于是任何单独渲染
按钮的测试都会因为「忘了包 Provider」而崩（本轮 5 个测试文件就是这么红的）。代价是相邻按钮
之间没有共享的 grace period，每个按钮各自计 320ms —— 够快，也够安静。

### 5.2 `IconButton`：`label` 是唯一真源

```tsx
<IconButton variant="ghost" icon={<Undo2 className="h-4 w-4" />} label="撤销" shortcut="Ctrl+Z" side="top" />
```

过去「提示」和「可访问名」分散在 `title` 和（偶尔才有的）`aria-label` 里：同一排按钮，有的
两样都有、有的只有 title。现在只写一次 `label`，`aria-label` 由它派生；`shortcut` 挂在提示
右侧，`side` 决定出现方向（底栏在屏幕下缘，必须 `top`）。

落地 **54 处**：编辑器工具栏（返回 / 导入 / 导出 / 引入新地图 / 版本历史 / 预览）、两个底栏
（工具、撤销重做、标尺、缩放、适应）、地图与谜题的列表行 / 网格卡的每个动作、共用的
「更多操作」、面板刷新、两个查看器的返回与缩放簇、部署页的复制与取消部署、游戏端左栏的
返回 / 缩放 / 标尺、主题切换。

**分层级**：提示默认从下方出（按钮多在页面上缘），底栏与游戏端左栏改 `top` / `right`；
`TooltipContent` 提到 `z-[60]` —— 对话框是 `z-50`、抽屉是 `UI_Z` 的 20/30，靠「后挂载
所以压得住」不算数，同一个对话框里再开一层浮层就会翻车。

**三条有意不换的例外**（共 17 / 71 个图标按钮）：

| 例外 | 位置 | 理由 |
|---|---|---|
| 行内微按钮（24px，11 处） | 抽屉 / 对话框列表行里的删除、行内动作 | 多数**只在 hover 时出现**：鼠标进场 → 按钮显形 → 再停 320ms 才出提示，而指针一离开行就消失。提示跟着按钮一起闪，比没有更吵。保留 `title`（它本身就能给出可访问名）。 |
| 分段控件（4 处） | 地图 / 谜题页的网格·列表切换 | 两个按钮互斥、状态本身就是信息；本轮补了 `aria-pressed`，不再套提示。 |
| 分页箭头（2 处） | `ListPager` 的 `‹ ›` | 只有「上一页 / 下一页」一义，`aria-label` 足够。 |

**没换的 `title`**（96 处中约 79）大多是「被截断文本的补全」（名称、路径、时间），那不是
按钮提示，换掉反而多一层噪音。

### 6.1 看过但没做

- **编辑器零响应式**：280 + 画布 + 320 三列，1024 宽时画布只剩 424px，没有降级提示。
  要做得先决定「窄屏是收起左面板还是给提示」，属于另一轮。
- **`VirtualList` 固定 480px**：1366×768 上左栏底部落在折线以下。改成视口自适应会牵动
  主从页的高度契约。
- **抽屉头 44px vs 面板头 40px**、**导航 `z-30` 绕过 `UI_Z`**：都是 v0.7.8 记下的旧债，
