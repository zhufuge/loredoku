# 地图编辑器系统需求文档（v0.5.2）

**文档类型**：版本需求与验收（本文档只定义需求、设计与验收口径，不含代码实现）
**修订记录**：2026-10-16 首版 —— **列表虚拟化 + 区域标签放大 + 物品字段瘦身 + 创建即传图 + 基本信息默认值**
**适用范围**：物品模块（`/items`）、角色模块（`/characters`）、地图编辑器（`/editor/:projectId`）
**前置版本**：v0.5.1（`docs/v0.5.1.md`）
**实现载体**：`packages/shared` + `packages/server` + `packages/web`（**三包全动**：删除表 / 字段 + 迁移）

> **本版主题：列表再长也不卡，标签高亮要更醒目，物品表单瘦一圈。**
>
> - **虚拟列表**：物品 / 角色列表只渲染可视区的几十行，滚动才补，长列表不再一次性请求全部图片。
> - **区域标签**：高亮时字号**变大**（32 → 36），且字号上限放开——设 32px 就该真的是 32px。
> - **物品瘦身**：详情里的「扩展信息（meta）」与「触发信息」连同背后的 `items.meta` 字段与
>   `item_triggers` 表一并删除；「可站立」只在**物体**类型上出现（背景类型恒定可站立）。
> - **创建即传图**：新建物品 / 角色时就能直接上传图片，不必先建后传。
> - **默认值**：基本信息里的线宽 / 字号整体调粗调大（见 §7）。
>
> 一句话记法：**列表只画看得见的，标签高亮往大走，物品表单只剩要用的。**

## 1. FEAT-M01 物品 / 角色列表虚拟滚动

### 1.1 目标

列表可能很长（几百上千条）。现在每一行都会渲染一个 `<img>`，浏览器会一次性发起全部缩略图请求——
首屏卡、流量浪费。改成**虚拟列表**：容器固定高度、可滚动，只渲染可视区内的行（外加少量 overscan），
行随滚动回收 / 复用。

### 1.2 方案（不引入新依赖）

新增 `packages/web/src/components/ui/virtual-list.tsx`：

```ts
interface VirtualListProps {
  count: number;          // 数据总行数
  rowHeight: number;      // 固定行高（px）
  height?: number;        // 视口高度（px），缺省 480
  overscan?: number;      // 上下各多渲染几行，缺省 6
  className?: string;
  renderRow: (index: number) => ReactNode;
}
```

- 外层 `<div>`：`overflow-y-auto` + 固定 `height`，监听 `onScroll` 记录 `scrollTop`；
- 内层占位 `<div>`：高度 = `count * rowHeight`，保证滚动条长度正确；
- 可视行用 `transform: translateY(paddingTop)` 定位，`paddingTop = startIndex * rowHeight`；
- `startIndex = max(0, floor(scrollTop / rowHeight) - overscan)`，
  `endIndex = min(count, ceil((scrollTop + viewportHeight) / rowHeight) + overscan)`。

### 1.3 落地

| 位置 | 改动 |
| --- | --- |
| `ItemListPanel` | 行高 **64px**，行内容保持缩略图 + 名称 + 分类徽标 + 尺寸（`h-16` 定高） |
| `CharacterListPanel` | 行高 **64px**，行内容保持头像 + 名称 + 性别徽标 |
| `ItemsPage` / `CharactersPage` | 不变——两个页面把数组原样传进面板即可 |

### 1.4 验收

- 1000 条数据时，`document.querySelectorAll('img')` 的数量远小于 1000（只渲染可视区）；
- 滚动到底部，最后一行可达且选中态正常；
- 键盘 / 鼠标选中、URL `?id=` 回显不受影响。

## 2. FIX-M02 区域标签：高亮时字号**变大**

### 2.1 现状问题

`MapRegionLabelLayer` 用 `hovered ? label.hoverFontSize : label.fontSize` 取值，
但两者都被 `scaleFontSize` 压到 28px 上限（见 §8），于是**高亮看起来「没变大」甚至「相对变小」**。

### 2.2 规则

1. **高亮字号恒不小于基准字号** —— `resolveMapStyle` 里把 `hoverFontSize` 收敛到
   `max(hoverFontSize, fontSize)`；任何来源（旧草稿、导入 JSON、手工改错）都不会出现「高亮更小」。
2. 默认值本身满足：基准 **32px** → 高亮 **36px**（§7）。
3. 上限放开（§8）后，32 / 36 在任意 `cellSize` 下都能如实呈现。

## 4. FEAT-M04 背景类型物品恒定可站立

### 4.1 规则

> **背景（background）类型的物品一定可站立；「可站立」只对物体（object）类型展示与勾选。**

- 分类切到「背景」时：`canStand` 强制 `true`，表单里**不渲染**该勾选框；
- 分类为「物体」时：勾选框照旧；
- 列表行只在物体类型时追加「· 可站立」；
- 后端兜底：`create` / `update` 时 `category === 'background'` → `can_stand = true`；
- 存量数据回填：迁移里 `UPDATE items SET can_stand = true WHERE category = 'background'`。

### 4.2 落点

- shared：`canStandFor(category, canStand)` 纯函数（放 `src/lib` 或 `constants` 旁），供三处共用；
- server：`itemRepository.create` / `itemRepository.update`；
- web：`CreateItemDialog`、`ItemDetailForm`、`ItemListPanel`。

## 6. SPEC-M06 图片填充方式（`fitMode`）的去留裁定

**结论：在使用，保留。**

- 渲染侧：`MapLayers` 的背景层与物体层都读 `item.fitMode` 决定 `object-fit`
  （`contain` → 完整留白，否则 `cover` 裁切填满）；
- 数据侧：`items.fit_mode` 列存在且有默认值，`ItemDetailForm` 的「图片填充方式」下拉可改、可存；
- 因此**不删除**，本版不动它。

## 8. FIX-M08 去掉区域标签字号的上限

### 8.1 现状

`packages/web/src/lib/canvasScale.ts` 的 `scaleFontSize` 把结果夹在 `[FONT_SIZE_MIN, FONT_SIZE_MAX]`
（`9 ~ 28`）。于是「基本信息」里把区域标签设成 32px，实际画出来还是 28px——**改了跟没改一样**。

### 8.2 规则

- `scaleFontSize` **只保下限**（`FONT_SIZE_MIN`），不再设上限；
- `FONT_SIZE_MAX` 一并移除（含引用它的测试断言）；
- 线宽仍保留 `[LINE_WIDTH_MIN, LINE_WIDTH_MAX]`——那是为了不画出 0 宽或糊成一片的线，与字号诉求不同。

## 12. 交付标准

1. 物品 / 角色列表为虚拟滚动，长列表下只请求可视区图片；
2. 区域标签高亮字号 ≥ 基准字号，且默认 32 → 36；
3. 物品详情无「扩展信息」「触发信息」；`items.meta` 与 `item_triggers` 已删除；

6. `fitMode` 经核查确认在用并保留（§6 有据）；
7. 基本信息 11 项默认值等于 §7 新表；
8. 区域标签字号上限已去除，设 32px 即渲染 32px（按 `cellSize` 等比缩放）；
9. 三包 typecheck / build / 全量测试通过，迁移可回滚可重放。

## 13. 实现期裁定

| # | 裁定 | 理由 |
| --- | --- | --- |
| R1 | **`fitMode` 保留不删** | 核查确认在使用：`MapLayers` 的背景层与物体层都读它决定 `object-fit`，`ItemDetailForm` 可改可存（§6）。 |
| R2 | 默认值**只改 `DEFAULT_MAP_STYLE` 引用的新常量**，不动 `BORDER_WIDTH` / `INNER_LINE_WIDTH` / `CANVAS_OUTER_BORDER_WIDTH` / `RULER_FONT_SIZE` 等老常量 | 老常量仍被 `canvasMetrics` 与 `canvasLayers.test.ts` 的常量表引用；新增 `STYLE_DEFAULT_*` 一组语义化常量，职责清楚、不牵连既有渲染兜底。 |
| R3 | `FONT_SIZE_MAX` **直接删除**而不是抬高 | 需求原话是「去掉限制」。只留 `FONT_SIZE_MIN` 保底；线宽的 `[0.5, 12]` 仍然保留（线宽需要上限，否则会糊成一片，与字号诉求不同）。 |
| R4 | `hoverFontSize` 在 `resolveMapStyle` 里被抬到 `max(hover, base)` | 一处收敛，任何来源的「高亮更小」都不可能出现，比在每个调用点判断可靠。 |
| R5 | 虚拟列表**零依赖自研** | 行等高的索引算术足够，没必要引第三方；行高 64px 收进 shared 常量 `LIST_ROW_HEIGHT` 供两个列表共用。 |
| R6 | 创建即传图走**先建后传两步串行** | 与地图封面同一套路（`POST /items` 拿 id → `POST /items/:id/image`）；上传失败只 toast，不吞掉已创建的记录。 |
| R7 | 「背景恒可站立」在 **schema transform + repository + 三处 UI** 同时兜底，并在迁移里回填存量 | 单靠 UI 隐藏挡不住 API 调用；`canStandFor()` 一个函数三处共用，不会漂移。 |
