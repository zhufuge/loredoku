## 0. 一句话

第一条：放置态结束的那一刻，界面上还有三样东西在说「这位正被拿着」——名册卡外面那道
2px 主色环、棋盘上他名下的一片联动高亮、以及被 `activeParticipantId` 放大的 1.3× 头像。
头像已经落定，这三样都该跟着手势一起退场。

第二条：**禁止符号从「建题时拷一份」变成「读取时跟随」**。谜题不配就用主题的，两边都
没有才是那枚 `×`；作者因此不必每建一题都去上传一次，主题换图也对跟随的关卡立刻生效。

后三条是界面上的三件小东西，共用同一条思路 —— **能由已有数据推出来的，就不要新字段**：
画布的投影颜色取自外框色（换框色影子自己跟着换）、工具按钮图标复用禁止符号那一套
`{ path }` 与「谜题 → 主题 → 内置」的三级兜底、物品提示把「贴物品」改成「贴光标」。

## 1. 现象与根因

**现象**（真页面，无头 Chrome + CDP 量的）

| 时刻 | 名册第一张卡 | 主题色铺开 | 棋盘联动高亮 | 棋盘上的头像 |
|---|---|---|---|---|
| 点开这张卡 | 3px 连续主色边 + 抬起影 | `data-tint="on"` | 1 层（`z-index: 26`） | — |
| 长按 650ms 头像落下（**改前**） | 选中边退掉了，但**仍有一道 2px 主色环** | 收回 | 还在 | `scale(1.3)` |
| 头像落下（**改后**） | 无 | 收回 | 无 | 原尺寸 |

**根因**不是徽章或样式，是**两条状态只退了其中一条**。点卡做两件事：

```ts
setMode({ kind: 'placing', participantId });
setActivation(state => reduceLinkageActivation(state, { type: 'click', participantId: index }));
```

头像落下之后，`modeAfterPlacement` 只把 `mode` 收回 `idle` —— 于是「选中」那道边退了
（`selectedSlotIndex` 变 `null`）—— 但 `activation` 还停在 `click` 上，而它管的是另外三样：
名册卡的 2px 环（`isActive`）、`activeParticipantId` 传进画布后的头像放大、以及
`showHighlight` 的联动高亮。

更可惜的是，这条规矩**本来就写过**：`applyMode` 里已经有一句「离开放置态就 `escape`」
（SPEC-G04，切工具时用）。`dispatchCell` 收尾时绕开了它，直接 `setMode`。

## 2. 改动

`pages/GamePage.tsx` 的 `dispatchCell`，放置分支的最后三行：

```diff
   const nextMode = modeAfterPlacement(mode, variant);
-  if (nextMode !== mode) setMode(nextMode);
+  if (nextMode !== mode) applyMode(nextMode);
```

`applyMode` 是那个「切模式 + 离开放置态就 `escape`」的唯一入口。改完，放置收尾与切工具、
再点同一张卡取消，走的是同一条规则，不必在三处各写一遍 `reduceLinkageActivation`。

**短按（放编号）不走这条**：`modeAfterPlacement` 只对 `variant === 'image'` 把模式收回
`idle`，编号落下后模式不变，卡片继续亮着 —— 那位参与者确实还在手上，编号只是草稿。

## 4. 禁止符号：谜题不配就跟随主题

**改前**：主题那张是「新建谜题那一刻抄一份」的缺省（v0.8.6 §4）。于是 ① 每建一题都要
在抽屉里配一次（否则只有创建时恰好有主题缺省才带图）；② 主题后来换了图，已经建好的
谜题一律停在建题那一天 —— 因为草稿里已经有一份自己的副本。

**改后**是一句话的**解析顺序**，写在 `lib/forbiddenSymbol.ts`：

```
谜题自己的 forbiddenSymbol  →  主题的 data.forbiddenSymbol  →  内置的 × 字形
```

三处消费它的地方都走这一个函数：

| 位置 | 表现 |
|---|---|
| 游戏页·放置层 | 格子里画那张图（原 `×` 字形的分支只在两边都没有时走） |
| 游戏页·工具提示层 | 悬停预览画同一张（v0.6.4 的规矩：预告的就是落下的） |
| 游戏页·工具栏按钮 | 按钮上也画同一张（v0.8.6 §4.5 之后一直是） |
| 谜题抽屉·禁止符号 | 预览画**这一题最终会用的那张**，`data-source="theme"` 时说明写着「这一题没有单独配置」 |

**服务端不再拷贝**（`puzzleService.createPuzzle`）：草稿里保持没有这个键，「跟随」才是
真的跟随。**资源包补上那一张**（`bundleService`）：包里必须自带文件，否则「线上跟着主题
画图、包里退回 ×」，同一关在两种运行环境里长得不一样；谜题自己配了就不看主题那份。

**实测**（真库，无头 Chrome + CDP）：

| 关卡 | 谜题自己的 | 主题的 | 工具栏按钮里画的 |
|---|---|---|---|
| `puzzle-hlm-shilin-very-easy` | 无 | `themes/2/.../cdfc2a6d….webp` | `<img>`，`naturalWidth` 256，src 就是主题那张 |
| `puzzle-hlm-sishan` | `puzzles/4355/.../7a258b59….webp` | 同上 | 仍是**自己**那张（覆盖生效） |
| `puzzle-dao`（`default` 主题没配） | 无 | 无 | `×` 字形（`svg`） |

抽屉（`/hlm/puzzles/5237/edit` → 基本信息）：预览框里是主题那张墨色 X，
`data-source="theme"`，说明是「这一题没有单独配置，玩家看到的是主题那张（在主题概览页的
『禁止符号』里换）」，「移除」呈灰色不可点 —— 没有自己的那份可移除。

**测试**：web **920 / 65**（+6）、server **221 / 14**（这条净 +1）。
（这三条之后的数字见 §8 末尾的收尾统计 —— 本轮又加了投影、图标、提示三组。）

- `lib/forbiddenSymbol.test.ts`：顺序三条（自己优先 / 跟随 / 都没有）+ 空路径按「没配」；
- `PuzzleInfoDrawer.test.tsx`：跟随主题时预览是主题那张且 `data-source="theme"`、
  自己配了则覆盖、移除后回到跟随；
- `GamePage.test.tsx`：两边都没有 → `×`、只有主题有 → 主题那张、两者都有 → 自己的；
- `api.test.ts`：新建谜题**不拷贝**、主题换图后草稿依旧没有自己的那份；
- `themeBundle.test.ts`：谜题没配 → 包里 `files/symbols/<slug>.webp` 有条目、关卡 JSON

## 6. 画布投影：外框色 + 透明度，向右下 6px

**需求是「边框色 + 透明度的向右向下一点的阴影」。** 关键词是「边框色」—— 作者不该为了
一道影子再配一次颜色，所以**不新增字段**：

```ts
// packages/shared/src/constants.ts
export const CANVAS_SHADOW_OFFSET_PX = 6;
export const CANVAS_SHADOW_ALPHA = 0.3;
```

`lib/mapStyle.ts` 的 `canvasShadowStyle(style)` 把 `style.canvasFrame.color` 拆成 rgb，
拼一句 `6px 6px 0 rgba(r, g, b, 0.3)`。四张画布（游戏页 / 地图预览 / 谜题预览 / 地图
编辑器）各自把这一句摊进 `MAP_LAYER_Z.canvasBase` 那一层 —— 也就是那张「纸」自己的底，
不是另起一个装饰层。

**不走 `--shadow-paper` / `--shadow-lifted` 那三档**，理由与「深色下上传图要反相」同源：
那三档是**界面**的材质，随浅色 / 深色切换；画布上的影子属于**作品**，同一张地图在两种
界面下应该是同一张纸。所以它是硬影（`0` 模糊）、颜色跟主题走、透明度写死。

**实测**（`/play/theme/hlm/puzzle-hlm-sishan`，1440×900，CDP 截图 + `sharp` 逐像素，
取画布下边界那条竖线，从纸面一路读到页面底色）：

| 界面 | 纸面（画布内） | 画布边缘那一圈 | 影子带 | 页面底色 |
|---|---|---|---|---|
| 深色 | `184,173,156` | `107,98,87`（4px） | `43,38,32`（3px） | `31,28,24` |
| 浅色 | `184,173,156` | `107,98,87`（4px） | `193,188,182`（3px） | `245,243,238` |

影子带的颜色与算式对得上：`0.3 × (74,63,53) + 0.7 × 底色` —— 深色
`(43.9, 38.5, 32.7)`、浅色 `(194.3, 189.0, 182.6)`，与量到的差 1 以内。算式里那个
`74,63,53` 正是 `#4A3F35`（这套主题的外框色），计算样式读出来的也是
`rgba(74, 63, 53, 0.3) 6px 6px 0px 0px`。

**为什么写的 6px、看到的是 3px。** 外框是 `<rect>` 的描边，**以画布边界为中心**画
（`stroke-width` 实测 5.6），外半边落在纸外 —— 正好压住影子的头 2.8px。影子剩下
约 3px 从外框外沿露出来。这不是 bug，是「6px 偏移 + 骑在边界上的外框」相加的结果；
要让影子更厚就调 `CANVAS_SHADOW_OFFSET_PX`，但得先知道这 2.8px 的损耗会一直在。

## 7. 工具按钮图标：清除 / 撤回 / 提交 也进两级配置

与禁止符号**同一套**：谜题配了自己的就用，没配跟随主题，都没有才画内置图标。

```ts
export const GAME_TOOL_ICON_KINDS = ['clear', 'undo', 'submit'] as const;
```

`ThemeData.toolIcons` / `PuzzleDraft.toolIcons` 都是 `{ clear?, undo?, submit? }`，每一枚
复用 `forbiddenSymbolSchema`（`{ path }`）—— **不是三个平铺字段**：一次上传只改一枚
（`{ ...data.toolIcons, [icon]: { path } }`），作者换「清除」不该把「撤回」抹掉；三枚都
清空时整个 `toolIcons` 键删掉，与「从没配过」同一个写法。

| 位置 | 表现 |
|---|---|
| 主题概览页 · 工具按钮图标卡 | 三行，各自上传 / 移除，一行一枚；说明写着「缺哪枚就用内置图标」 |
| 谜题抽屉 · 工具按钮图标 | 三段，每段一枚预览 + `data-source`（`puzzle` / `theme` / `builtin`）+ 「移除」 |
| 游戏页 · 工具栏 | 配了画 `<img data-testid="clear-tool-icon">`，没配画 `TOOL_ICON_FALLBACKS` 里的 lucide 图标 |
| 资源包 | `files/icons/<slug>-<icon>.<ext>`，某一枚缺只跳过那一枚并记 `problems` |

解析顺序收在 `lib/toolIcons.ts`，内置那三枚（`Eraser` / `Undo2` / `Send`）提到
`TOOL_ICON_FALLBACKS`，游戏页 / 概览页 / 抽屉三处共用一份 —— 否则三处各写一枚，
换图标要改三遍。

服务端两条端点，`:icon` 走 `toolIconParamSchema`（枚举）：拼错是 **400**，不是「传上去了
但哪儿也没变」。图片与禁止符号共用 `processSymbolImage`（按所有者分目录、长边缩到
256、只写一张 webp），目录是 `.../tool-icons/<icon>/`。

**测试**：`lib/toolIcons.test.ts` 5 条（顺序四条 + `resolveToolIcons` 只收已配置项）、
`GamePage.test.tsx` 3 条（都没配 / 主题三枚 / 谜题覆盖一枚）、`api.test.ts` 3 条
（主题三枚各写各的、谜题只写文件、`:icon` 拼错 400）、`themeBundle.test.ts` 3 条
（三枚进包、跟随主题、某一枚缺失则中止）。

## 8. 物品名称提示：贴光标，320ms

两处改动，一个理由：提示原来**挂在物品上方**（离眼睛要看的地方远），而且要等 **1000ms**。
现在贴光标右下角 `+14 / +18`，延迟 `ITEM_NAME_TIP_DELAY_MS` 从 1000 降到 **320**。

**为什么敢缩短。** 当初取 1s 是怕「提示雨」—— 指针扫过一片物品，名字一个个冒出来。
但那个顾虑的前提是「提示出现在物品头顶」：扫过去是一片固定位置的纸片在闪。跟手之后，
提示是**跟着指针走的一张纸**，划过时读起来是「这件叫什么」的即时回答；再拖一秒才出，
反而像卡了一下。320ms 也对齐全站 `Tooltip`（300~400ms 那一档）。

**坐标。** 提示层在 `overflow-hidden` 的画布里，落笔前要判边界，所以要的是**画布坐标**
而不是格坐标 —— `lib/grid.ts` 新增 `clientToCanvasPoint()`，与 `clientToCell` 的区别只有
一条：**不除 `cellSize`**（先减平移，再按 `zoom` 折回）。四个画布各加一份 `hoverPoint`
（`onPointerMove` 写、`onPointerLeave` / 换图清空），传给 `<MapItemLayer pointer=…>`。

**翻边用预算，不用实测尺寸。** 提示要跟着指针动，等一帧量出宽高再放会追不上；所以
右侧留 `TIP_EDGE_BUDGET_PX = 56`、下方留 `TIP_FLIP_MIN_TOP_PX = 32` 的余量，越界就翻到
指针左上，最后再夹进画布。少算一点顶多是贴边多留几像素白，算多了才会被切掉 ——
两个方向的代价不对称，就按代价小的那边取。

**实测**（同一关，九件物品逐个悬停，CDP 派发真实 `mouseMoved`）：

| 指针 | 提示左上角 | Δ | 出现耗时 |
|---|---|---|---|
| 575, 316 | 589, 334 | +14, +18 | 338ms |
| 575, 510 | 589, 528 | +14, +18 | 342ms |
| 575, 644 | 589, 662 | +14, +18 | 337ms |
| 743, 308 | 757, 326 | +14, +18 | 340ms |
| 743, 686 | 757, 704 | +14, +18 | 368ms |
| 911, 501 | 925, 519 | +14, +18 | 344ms |
| 911, 689 | 925, 707 | +14, +18 | 329ms |
| 1062, 182 | 1076, 200 | +14, +18 | 340ms |
| 1079, 644 | 1093, 662 | +14, +18 | 345ms |

九件全部 `+14 / +18`（位移没有累积误差，说明坐标换算里那点 padding 补偿是对的），
耗时 `329~368ms` —— 320 的定时器 + 轮询间隔。这张表里没有翻边：这一关的九件都不在
「贴右 / 贴下 56 / 32px」的范围内，翻边那条分支只走了代码、没走到像素。

**收尾统计**（全量）：`shared 268 / 21`、`server 227 / 14`、`web 932 / 66`，
`typecheck`、`build` 通过。

## 9. 代价与没有做的

1. **退的是「整手」，不是「这一位」。** 想接着给同一位放编号，得重新点一次卡。这是有意的：
   头像落定 = 这位已经就位，再把他的高亮与放大留在屏幕上，只会让玩家以为操作还没完成。
2. **联动高亮没有留残影。** 它跟着 `activation` 一起走，所以「刚看过谁的联动」不留痕 ——
   要看再看一次卡。真想要「刚才那一下」的余韵，得另立一份短时状态，那是另一个决定。
3. **没有动落定动效。** `.place-settle` 仍是抬手 400ms 内挂在那一格上（v0.7.11），
   与触碰态无关；它的收场没有提前也没有延后。
4. **只在游戏页修。** 谜题 / 地图**预览**页的放置走的是另一套（编辑器 store），
   本轮没有它们的落子手势，也就没有同一个问题 —— 将来若把「长按落下」搬过去，
   这条规矩要一起搬。
5. **主题换图对已发布的关卡也生效。** 跟随的关卡读的是**当前**主题数据，版本行里只有
   「这一题自己那张」。这与「发布即冻结」的常规不一样，是这条需求的直接后果：要冻结，
   就得在发布时把主题那张写进版本行 —— 那就又回到「每建一题配一次」。
6. **存量谜题不会自动跟随。** v0.8.6 期间建的谜题，草稿里已经抄了一份自己的副本；
   它们在抽屉里显示成「自己的」。要让某一题回到跟随，点一次「移除」即可（不会删文件）。
7. **播放页与谜题编辑器各多取一次 `/themes`。** 两个页面都在 `WorkspaceLayout` 外面，
   拿不到上下文里那份 `theme`，只能按编码去查 —— 走的是与难度分级同一个
   「列表摊成表」的 hook，缓存命中时不再发请求，但冷启动那一次仍是整份列表。
8. **不判断文件在不在。** 解析只看 `path` 有没有值；文件被人手动删了就是一枚破图
   （v0.8.6 §6 同一条）。

下面是本轮后三条带来的：

9. **画的 6px，看到的是 3px。** 外框那条线是 SVG `<rect>` 的描边，**以边界为中心**画
   （实测 `stroke-width: 5.6`），于是外框的一半探到框外 2.8px，正好压住影子的头 2.8px。
   剩下的 3px 才是眼睛看到的。想让影子更厚，就调 `CANVAS_SHADOW_OFFSET_PX`，但**先接受
   这条损耗**再调 —— 否则会以为「设了 10 结果只有 7」是个 bug。
10. **深色界面下它是「亮晕」，不是暗影。** 影子色取外框色（这套主题是 `#4A3F35`，
    L\* 约 27），而深色页面底色是 `rgb(31,28,24)`（L\* 约 11）—— 0.3 混出来
    `rgb(43,38,32)`（L\* 约 16），比底色**亮** 5 个 L\*。所以深色下读起来是一圈暖光，
    浅色下才是真正的影子。这是「颜色取自外框、透明度写死」的直接后果；要两种界面
    都是暗影，就得让影子色跟着界面走（那画布就不再是「同一张纸」了）。
11. **影子只有一个旋钮。** 颜色跟外框色、透明度与偏移在 `constants.ts` 里写死，作者
    只能在「换外框色 → 影子跟着换」这一层间接影响它。没有做成主题字段，是因为作者配的
    是**这张地图长什么样**，不该再管「这张纸在界面上怎么摆」。
12. **提示的翻边没有测试。** `v0.8.3 §16` 已把「名称提示」那一组删掉（当时判定为外观），
    这轮没有恢复 —— 位置靠 §8 那张九件的实测表兜着。翻边分支更是在真实数据上没被触发
    （九件都不贴边），将来若要钉它，得先造一个贴着画布边角的物品。
13. **提示可能压住物品。** 翻边与夹紧用的是**预算**（56 / 32px）而不是实测宽高：
    名字长到接近 `max-w-48`（12rem）时，纸片比预算宽，贴右边的时候会盖住被悬停的那件。
    纸片 `pointer-events-none`，不影响继续操作，只是挡了一眼。
14. **工具图标一次只能换一枚。** 三个端点各自上传，没有「一次换全套」，也没有「把主题
    那三枚复制到这一题」——「复制」正是本轮要从禁止符号身上去掉的那件事（§4）。
15. **包里三枚图标是平铺的。** `files/icons/<slug>-<icon>.<ext>`，同一关最多三张、名字
    带关卡 slug；同名的关卡不会重复（slug 唯一），但也没有按主题归档 —— 与
    `files/symbols/` 同一档处理。
