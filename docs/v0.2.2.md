## 1. BUG-101 未保存离开拦截：点「离开」无效果

### 1.1 现象
- 编辑器修改内容后点击浏览器返回（或页面「返回」按钮）；
- 确认弹窗**已正确出现**；
- 点击弹窗上的「离开」按钮后：**弹窗不关闭、页面不返回、无任何反应**；
- 点击「取消」也表现异常（弹窗不关闭）。

### 1.2 根因分析

结合 v0.2.1 的实际表现（弹窗能出现 → `useBlocker` 已生效），问题集中在「弹窗交互 → blocker 状态转换」环节：

1. **弹窗 `open` 的受控方式错误**
   若 `AlertDialog` 使用 `open={blocker.state === 'blocked'}` 且 `onOpenChange` 回调中调用 `blocker.reset()`，则在点击「离开」时：
   - Radix AlertDialog 会先触发一次 `onOpenChange(false)`；
   - 该回调中调用 `blocker.reset()` 把 blocker 状态从 `blocked` 重置为 `unblocked`；
   - 弹窗随即卸载；
   - 用户代码中 `requestAnimationFrame(() => blocker.proceed())` 在下一帧执行时，`blocker.state` 已非 `blocked`，`proceed` 是空操作或抛错。
   **结果：弹窗既不关闭、页面也不返回。**

2. **`requestAnimationFrame` 引入的时序竞态**
   在 React 18 并发渲染下，rAF 回调可能在弹窗被 Radix 卸载之后才执行，或与 Strict Mode 的双次挂载冲突。

3. **弹窗按钮未使用 `AlertDialogAction`**
   若「离开」是普通 `<button>`，点击时会触发 Radix 的默认关闭流程，导致上述 1 中的问题被放大。

4. **`blocker.proceed` 引用不稳定**
   部分 `react-router-dom` 版本中，`blocker` 对象每次渲染都会变化，直接闭包捕获会导致调用旧的 `proceed`。

### 1.3 修复要求

#### 1.3.1 重构 `useUnsavedChangesGuard` Hook

```ts
import { useBlocker } from 'react-router-dom';
import { useEffect, useRef, useCallback } from 'react';

export function useUnsavedChangesGuard(dirty: boolean) {
  const blocker = useBlocker(
    ({ currentLocation, nextLocation }) =>
      dirty && currentLocation.pathname !== nextLocation.pathname
  );

  // 用 ref 持有最新 blocker，避免闭包陈旧
  const blockerRef = useRef(blocker);
  useEffect(() => { blockerRef.current = blocker; }, [blocker]);

  // 浏览器关闭/刷新
  useEffect(() => {
    if (!dirty) return;
    const handler = (e: BeforeUnloadEvent) => {
      e.preventDefault();
      e.returnValue = '';
    };
    window.addEventListener('beforeunload', handler);
    return () => window.removeEventListener('beforeunload', handler);
  }, [dirty]);

  const open = blocker.state === 'blocked';

  const confirmLeave = useCallback(() => {
    const b = blockerRef.current;
    if (b.state !== 'blocked') return;
    // 同步调用，不用 rAF
    b.proceed();
  }, []);

  const cancelLeave = useCallback(() => {
    const b = blockerRef.current;
    if (b.state !== 'blocked') return;
    b.reset();
  }, []);

  return { open, confirmLeave, cancelLeave };
}
```

#### 1.3.2 弹窗组件写法要求

**禁止**在 `AlertDialog` 上使用 `onOpenChange` 去调用 `blocker.reset()`，因为 Radix 在点击任意按钮（包括 Action）时都会先触发它，从而破坏状态机。

正确写法：

```tsx
<AlertDialog open={open}>
  <AlertDialogContent
    // 关键 1：不传 onOpenChange
    onEscapeKeyDown={(e) => { e.preventDefault(); cancelLeave(); }}
    onPointerDownOutside={(e) => e.preventDefault()}
  >
    <AlertDialogHeader>
      <AlertDialogTitle>有未保存的修改</AlertDialogTitle>
      <AlertDialogDescription>
        离开将丢失当前修改，确定离开吗？
      </AlertDialogDescription>
    </AlertDialogHeader>
    <AlertDialogFooter>
      {/* 关键 2：使用普通 Button，不用 AlertDialogCancel/Action */}
      <Button variant="outline" onClick={cancelLeave}>取消</Button>
      <Button variant="destructive" onClick={confirmLeave}>离开</Button>
    </AlertDialogFooter>
  </AlertDialogContent>
</AlertDialog>
```

#### 1.3.3 关键约束清单

| 编号 | 约束 |
|---|---|
| C1 | 弹窗 `open` 严格等于 `blocker.state === 'blocked'`，不使用任何本地 state |
| C2 | **禁止**给 `AlertDialog` 传 `onOpenChange`，防止 Radix 内部关闭流程与 blocker 状态机冲突 |
| C3 | 「离开」/「取消」使用普通 `<Button>`，**不使用** `AlertDialogAction` / `AlertDialogCancel` |
| C4 | 「离开」处理器中**同步**调用 `blocker.proceed()`，**不使用** `requestAnimationFrame` / `setTimeout` |
| C5 | 通过 `useRef` 持有最新 `blocker` 引用，避免闭包陈旧 |
| C6 | 页面内「← 返回」按钮必须使用 `navigate(-1)` 或 `navigate('/projects')`，禁止 `window.history.back()` |
| C7 | `blocker.proceed()` 执行后再没有任何代码触碰 blocker 状态 |

#### 1.3.4 兜底机制（保留）

- `popstate` 监听：若 500ms 后 URL 仍在编辑器路由、`dirty === true`、`open === false`，则 `navigate(-1)` 强制返回；
- 控制台对该兜底触发打 `warn` 日志，方便排查。

### 1.4 验收标准

| 场景 | 期望 |
|---|---|
| 修改后点浏览器返回 | 弹窗出现 |
| 弹窗点「离开」 | 弹窗立即关闭，成功返回上一页 |
| 弹窗点「取消」 | 弹窗关闭，停留编辑器 |
| 修改后点页面「← 返回」 | 同上三种行为一致 |
| 弹窗点遮罩 / 按 Esc | 等同「取消」，停留编辑器 |
| 修改后刷新 / 关闭标签页 | 浏览器原生 beforeunload 提示 |
| 未修改时点返回 | 不弹窗，直接返回 |

## 2. BUG-102 区域选择交互重构

### 2.1 现象
1. **每次只能选中一个格**：点击一处只高亮一格，无多选能力；
2. **开启区域工具即自动创建**：切换到「区域」工具后点击画布任意处，直接弹出「创建区域」弹窗，缺少确认环节；
3. 用户无法在创建前预览、增删、调整选区。

### 2.2 期望交互（重构为「选区 → 确认 → 创建」三阶段）

#### 2.2.1 阶段一：选区构建（Selection Building）

- 切换到「区域」工具（`R`）后，进入**选区构建模式**，此时**不弹出任何创建弹窗**；
- 画布顶部出现一条**选区操作条**（Selection Bar），实时显示：「已选 N 格」，以及右侧按钮 `[清空] [确定创建] [取消]`；
- 用户通过以下任意方式构建选区：

| 操作 | 行为 |
|---|---|
| 单击空格 | 加入选区；再次单击同一格 → 从选区移除（toggle） |
| 拖拽（矩形） | 拖出矩形范围内所有格**加入**选区 |
| `Shift + 拖拽` | 拖出矩形范围内所有格**从选区移除** |
| `Alt + 单击` | 该格从选区移除 |
| 自由笔刷（可选开关） | 按住拖过加入；`Alt + 拖过` 移除 |

- 选区实时高亮：`rgba(59,130,246,0.25)` 半透明蓝罩 + 1px 蓝色内描边；
- 选区状态存于 `EditorStore.regionDraftSelection: Set<"x,y">`；
- **切换工具 / 按 Esc / 点「取消」** → 清空选区并退出构建模式。

> 说明：本版**不强制**保留多边形模式（可后续迭代）；矩形拖拽 + 单击 toggle + Alt 减选已满足"任意连通形状"的主要用例。

#### 2.2.2 阶段二：确认创建

- 点击选区操作条上的「确定创建」按钮：
  - 若选区为空 → Toast 提示"请先选择至少一个方格"；
  - 若选区**不连通**（非 4-邻接连通）→ 弹窗提示"区域必须是相连的方格"，并提供高亮显示不连通的分量；
  - 若选区与已有区域格子**冲突** → 弹窗提示，提供「覆盖」/「跳过冲突格」/「取消」；
- 校验通过 → 弹出「新建区域」信息弹窗。

#### 2.2.3 阶段三：填写区域信息

新建区域弹窗字段：

| 字段 | 组件 | 默认值 | 校验 |
|---|---|---|---|
| 区域名称 | Input | 空 | 必填，≤100 字，项目内唯一 |
| 区域标识 ID | Input | 自动生成 `rg_xxxxxx` | 必填，项目内唯一，仅字母数字下划线 |
| 描述 | Textarea | 空 | 选填 |
| 颜色 | ColorPicker | `#000000` | 必填 |
| 边界线宽 | Slider | 4 | 4~12 |
| 填充透明度 | Slider | **0** | 0~1 |

- 点击「确认」→ 写入区域，清空草稿选区，退出构建模式，进入「选择」工具；
- 点击「取消」→ 仅关闭信息弹窗，**保留草稿选区**，允许用户继续调整后重新点「确定创建」。

#### 2.2.4 状态机

```
[选择工具] --按 R--> [区域工具/构建模式]
                          |
                          |--单击/拖拽--> 更新 regionDraftSelection
                          |--Esc/取消--> 清空选区 → [选择工具]
                          |--确定创建--> 校验
                                          |--失败--> Toast/冲突弹窗（保留选区）
                                          |--成功--> 打开信息弹窗
                                                      |--取消--> 保留选区
                                                      |--确认--> 写入区域 → [选择工具]
```

### 2.3 状态定义

```ts
interface EditorState {
  // ... 其他字段
  activeTool: 'select' | 'region' | 'character' | 'eraser' | 'pan';
  regionDraftSelection: Set<string>;        // "x,y"
  regionDraftMode: 'idle' | 'building' | 'confirming';
}
```

`activeTool === 'region'` 时自动进入 `building`。

### 2.4 验收标准

| 场景 | 期望 |
|---|---|
| 切换到区域工具，不点击 | 无弹窗，顶部出现选区操作条 |
| 单击多格 | 每格高亮，计数同步更新 |
| 单击已选格 | 该格取消选中 |
| 拖拽矩形 | 范围内所有格加入选区 |
| `Alt + 单击` | 该格移除 |
| 点「清空」 | 选区清空 |
| 点「确定创建」（空选区） | Toast 提示 |
| 点「确定创建」（不连通） | 弹窗提示不连通 |
| 点「确定创建」（正常） | 打开信息弹窗 |
| 信息弹窗点「取消」 | 关闭弹窗，选区保留，仍在构建模式 |
| 信息弹窗点「确认」 | 区域创建成功，切换到选择工具 |

## 3. BUG-103 点击已放置角色，右侧未展示角色信息

### 3.1 现象
- 在地图上有已放置的角色；
- 使用「选择」工具点击角色所在格；
- 右侧信息抽屉**未展示角色信息**，或仅展示格子信息；
- 期望：抽屉展开并显示该角色的详情，同时可编辑地图关联信息。

### 3.2 根因分析

1. **命中检测缺失/顺序错误**：点击事件仅按图层（背景/物件）查找物品，未把「角色」纳入命中检测优先级；
2. **角色与格子选中未分离**：`selection` 状态未区分 `type: 'cell' | 'region' | 'character'`，导致抽屉始终按格子内容渲染；
3. **角色层 `pointer-events` 被关闭**：角色 DOM 若加了 `pointer-events: none`，则点击穿透到单元格，命中丢失；
4. **抽屉渲染分支缺失**：`InfoDrawer` 组件缺少 `selection.type === 'character'` 分支。

### 3.3 修复要求

#### 3.3.1 命中检测优先级

在画布的 `pointerdown`（选择工具、非拖拽态）中，按以下顺序命中：

```
1. 区域名称标签（labelCell 上的胶囊，pointer-events: auto）
2. 已放置角色（角色层 DOM）
3. 物件层物品
4. 背景层物品
5. 空格
```

- 角色层 DOM 必须 `pointer-events: auto`；
- 角色的点击热区不小于 `cellSize × cellSize`；
- 命中角色时，禁止冒泡到单元格。

#### 3.3.2 Selection 状态类型化

```ts
type Selection =
  | { type: 'cell'; x: number; y: number }
  | { type: 'region'; regionId: string }
  | { type: 'character'; characterId: number; x: number; y: number };
```

- 点击角色 → `selection = { type: 'character', characterId, x, y }`；
- 点击区域标签 → `selection = { type: 'region', regionId }`；
- 点击其他格 → `selection = { type: 'cell', x, y }`；
- 点击空白 → `selection = null`。

#### 3.3.3 右侧抽屉渲染分支

`InfoDrawer` 必须按 `selection.type` 分三种渲染：

**分支 A：`type === 'cell'`**（沿用既有布局）
```
坐标：C{x+1}, R{y+1}
【背景层】 缩略图 / 名称 / ID / 触发信息
【物件层】 缩略图 / 名称 / ID / 多格尺寸 / 可站立标识
【角色】   若该格有角色 → 头像 + 名称 + 「查看详情」按钮
【所属区域】 名称 + 区域 ID（点击选中该区域）
[清空本格] [清空物件层]
```

**分支 B：`type === 'region'`**
```
名称 / 区域 ID / 颜色 / 边界线宽 / 填充透明度 / 包含格子数
[编辑] [定位到区域] [删除]
```

**分支 C：`type === 'character'`**
```
┌─ 角色信息 ─────────────────────┐
│ [头像 96×96 圆形]              │
│ 名称：村民A                    │
│ ID：villager_a                 │
│ 坐标：C3, R4                   │
│ 是否可站立：是（或红色警告）    │
│                                │
│ ── 地图关联信息 ──             │
│ dialog   [村民A的对话]  [删除] │
│ questId  [q001]         [删除] │
│ [+ 添加字段]                   │
│                                │
│ [保存关联信息]  [从地图移除]   │
└────────────────────────────────┘
```

- 「地图关联信息」为自由键值对编辑器，保存后写入 `placedCharacters[].mapMeta`；
- 「从地图移除」→ 该角色回到槽位（若槽位已满则提示）；
- 「是否可站立」若为否 → 显示红色警告文本"该格不可站角色，请调整位置或物品"。

#### 3.3.4 抽屉自动展开

- `selection` 从 `null` 变为任意非空值 → 抽屉自动展开；
- `selection` 变为 `null` → 抽屉收起；
- 用户手动收起抽屉后，再次点击任意对象仍会重新展开。

#### 3.3.5 联动高亮

- 选中角色 → 画布上该角色外发光 + 轻微放大（`scale 1.06`）；
- 选中角色 → 左侧槽位区对应槽位（若有）高亮边框；
- 选中角色 → 若与某区域关联，区域边框同时高亮。

### 3.4 验收标准

| 场景 | 期望 |
|---|---|
| 选择工具点击已放置角色 | 右侧抽屉展开，展示角色信息 |
| 编辑并保存关联信息 | 数据写入 `placedCharacters[].mapMeta`，刷新后保留 |
| 点击角色所在格但未命中角色层 | 展示格子信息，且「角色」区块有查看入口 |
| 点击区域名称标签 | 抽屉展示区域信息 |
| 点击空白格 | 抽屉展示格子信息 |
| 点击画布外空白 | 抽屉收起 |
| 角色在不可站立格上 | 抽屉内显示红色警告 |
