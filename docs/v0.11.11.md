# v0.11.11 — 背景也能联动

## 0. 范围与口径

一句话：谜题编辑器的角色「联动 → 资源」里，**背景层**与**背景修饰层**的资源也列得出来了；
选中之后的效果和物品一样 —— **方块高亮**。

口径五条：

1. **只有一种效果**：方块高亮（不透明、覆盖整格，含背景图层与背景修饰层）。v0.3.4 起那条
   「背景联动 → 背景高亮（只换背景层、物品层照旧露着）」不再产出。
2. **选择器按资源聚合**：同一个资源放在几层、几格，仍然只有一行 `名称（业务 ID）× N`；
   后面用 `· 背景` / `· 背景修饰` 标出层，两层都有就是 `· 物品 / 背景`。只落在物品层的行
   不加标签 —— 那是绝大多数行，标签只在需要区分时出现。
3. **指定实例按格坐标列**：同一格、同一资源占了背景层和物品层时只算**一个**实例
   （勾的是格子，不是图层）。
4. **只是编辑器换了提示**：`asset` 联动存的仍是 `{ id, scope, instances }`，`puzzles.data`
   不升版本，导出包不变。玩家侧的高亮由同一份 `resolveHighlight` 算，所以编辑器预览、作品
   预览、游戏页、播放器一起变。
5. **图层表不动**：`MAP_LAYER_ORDER` 仍是 16 层，背景高亮层（第 14 层）保留但**没有产出者**（§2）。

## 2. 设计裁定

**为什么背景联动不再走「背景高亮」。** 这是用户这一版直接要的效果：背景与背景修饰的联动
「效果也是触发方块高亮」。方块高亮本来就覆盖整格、也画在背景修饰层与背景图层之上，一眼能
看出是哪一格被点亮；而背景高亮只替换背景色块，背景修饰与物品还压在上面，反应不明显。

**为什么 `backgroundHighlight` 层留着不删。** 删一层不是删一个分支：`MAP_LAYER_ORDER` 是
shared 里的 16 层常量，`schemas/game.test.ts` 断言的是精确层表，`docs/layer-priority.md`
§1 / §2 / §3 / §4 与检查清单都要重排，四个画布页面都经过 `MapHighlightLayer`。这一版的需求
是「让背景也能联动」，没要求退役图层；先把产出者摘掉（`resolveHighlight` 里不再填
`backgroundHighlights`），层原样留着。真要收回，是下一版整层删的事：`layer-priority.md`
那一节的写法照着 v0.7.0「区域填充退役」来。

**为什么按 `assetId` 聚合、而不是「层 + 资源」两行。** 联动目标只存 `assetId`：拆成两行会
生成两条一模一样的联动，删了一条另一条毫无差别。层标签只做提示，不影响存进去的东西。

**为什么实例要按坐标去重。** 同一格同一资源能同时占背景层与物品层（v0.10.9 起三者可同格
并存）。不去重的话「指定实例」里会出现两个 `3,4` 复选框、React key 也会撞。

## 5. 没做的

- **没退役背景高亮层**：理由见 §2；要收就整层删（`MAP_LAYER_ORDER`、`MapHighlightLayer`、
  `HighlightState.backgroundHighlights` 与 `layer-priority.md` 一起）。
- **没在「指定实例」里标层**：勾的是格子；同一格两层都是这个资源时，标了也分不开。
- **没动服务端 / JSON / 导出包**：背景与背景修饰的资源引用本来就在画布引用闭包里
  （`themeScope`），`validatePuzzleReferences` 也没有分层特判。
- **没动标尺的持久化语义**：只是缺省变了；某个浏览器以前把开关写成 `visible`，就仍然显示，
  想看到新缺省得清掉对应的 `loredoku.*.ruler`。
- **没改 v0.10.10 §7.4 那条记录**：历史需求文档不动，这一版把当时漏掉的补上。

## 6. 补：位置条件选不中多格物品的第二格

- **症状**：给角色加位置条件时，2 格宽的炕（`w: 2`）点右半格，加进列表的还是左边那格 ——
  同一格加两次，第二格永远选不中。
- **原因**：画布点击统一走 `hitTestCell`，它按设计把**多格物品的覆盖格解算回锚点格**
  （选中物品 / 打开信息框要的是整个物品）。位置条件要的恰恰是「点中的那一格」。
- **修法**：`hitTestCell` 增加 `exactCell`；`EditorCanvas` 增加 `selectExactCell`（默认 `false`），
  只有谜题编辑器在「添加位置」拾取态打开它。选物品、选区域、信息框那些路径行为不变 ——
  锚点解算仍是默认值。
- **验证**：`EditorCanvas.hit.test.tsx` 两条（默认覆盖格回到锚点 / `selectExactCell` 时按原格上报）、
  `hitTest.test.ts` 一条（同一个覆盖格两种参数的结果不同）。
