# v0.11.2 — loading 等到位、竖屏手势与 Safari 描边

## 0. 范围与口径

用户报的问题，都是「页面自己知道得比它显示的多」这一类：

1. 游戏列表与游戏页的 loading 撤得太早 —— 数据（JSON）一到就撤，图还没有。
2. 竖屏下地图的上下留白比左右宽。
3. 竖屏下参与者的卡框吃掉了触摸手势，名册划不动。
4. 部分浏览器（Safari / iOS Safari）看不到物品的描边。

同版后续又收了四条：

5. 还没选参与者、也没选工具时，点 / 扫格子也要有光标框、物品抬起与物品名 tip（触屏
   点一下同样要出）。
6. 「· 格物」应该跟在 LOREDOKU 图标后面，而不是跟在标题后面。
7. loading 该等的是「**当前这一页用到的**资源」，不是整张资源表。
8. 竖屏的地图上下留白、游戏页标题行再各收一档。

口径：

- **不改数据层**。四个 query（`useGame` / `useAssets` / `useCharacters` / `useCatalog`）本来
  只等 JSON，这一点是对的 —— 该等的是「这一页要画的图」，不是「所有图」。
- **不预渲染**，不引入新依赖。预加载用浏览器自己的 `Image()`，没有任何库。
- 竖屏的留白、手势仍然只由**一处常量 / 一个判定**决定，不在组件里另写数字。
- 悬停反馈与「现在拿的是什么工具」**无关**：空手也照画。页面层只保留一个「结案了
  就全停」的总闸（`hoverEnabled = !interactionLocked`），不在每个图层里各判一遍。

## 1. loading 等「这一页的资源」

### 1.1 为什么要单独预加载

最直接的想法是「渲染出来的 `<img onLoad>` 数一数」。这条路是死的：

```
loading 没撤 → 卡片 / 画布不渲染 → <img> 不存在 → onLoad 永远不触发 → loading 永远不撤
```

v0.11.2 的开发过程中确实踩到了这个死锁（列表页的骨架屏把卡片挡住，两个新用例
一直红）。所以预加载与渲染必须**分开**：先自己建 `Image` 对象把图拉下来，等到位了
再撤 loading、再渲染。

### 1.2 `hooks/useImagePreload.ts`

```ts
useImagePreload(urls: (string | null | undefined)[]): boolean
```

- 空值 / 重复地址剔掉；签名（地址拼成的字符串）为空时**立刻算就绪** —— 没有图要等。
- 一张 `load` 或 `error` 都算「不必再等」：一张 404 的图不该把玩家永久卡在 loading 上。
- 入参数组每次渲染都是新引用，所以依赖用**内容签名**，不是数组本身 —— 否则每次
  渲染都会重新拉一遍、永久不就绪。
- 签名变了（换关 / 数据换了）要重新等，上一轮的就绪不能顶替这一轮。

### 1.3 收哪些图：`lib/pageImages.ts`

```ts
boardImageUrls({ cells, assetsById, slots, charactersById, mark, toolIcons, ringImage }): string[]
gameCoverUrls(games): string[]
```

只收**这一页画的时候真的会用到**的那一张，口径与图层一致（`MapAssetLayers` 取的是
`imageThumbUrl ?? imageUrl`，预加载也取同一张，否则等完缩略图、画的时候还要再等原图）：

- 资源：遍历这一关的 `cells`，把 `background` / `decoration` / `item` 三处的 `assetId`
  与 `variantId` 拿去问 `resolveAssetVariant`（与图层同一个函数：锚点指定了形态就用它，
  否则退回第一形态）。**不是整张资源表** —— 表里躺着别的关卡的几百张图，等它们等于
  让玩家盯着 loading 等无关的素材。
- 角色：只收 `characterSlots` 里坐着的那些人的头像，缩略图优先，同样不是整张角色表。
- 标记 / 工具图标 / 校验圈：各一张。
- 列表页：每张卡的封面。

色块资源（只有 `bgColor`、没有图）不进清单。`assetsById` / `charactersById` 是
`useGameContent` 已经建好的 `Map`，这里直接复用，不另做一次索引。

### 1.4 三处页面

| 页面 | 撤 loading 的条件 |
| --- | --- |
| `pages/GamesPage.tsx` | 列表数据到齐 **且** 封面都就绪 |
| `pages/GamePage.tsx` | 一关的数据 + 资源表 + 角色表 + 清单到齐 **且** 画布上的图都就绪 |
| `player/PlayerHomePage.tsx` | 包清单到齐 **且** 封面都就绪（与工坊那边的列表页同一条） |

`GamePage` 的 `LoadingScreen` 文案保持「正在加载游戏…」不变；玩家看到的差别是
**loading 消失的那一帧，盘面已经画好了**，而不是先空着再一张张跳出来。

### 1.5 loading 撤掉之后棋盘要自己重排

上面那条 loading 门带出一个副作用：**`<main>` 的挂载被推迟了**。视口那条挂载
effect（量容器、算格子、挂 `ResizeObserver`）原来只依赖 `containerRef`（引用稳定
的 ref 对象）与 `gridSize`，于是出现这样的先后：

```
① 关卡 JSON 还在路上   gridSize = 0，没有 <main>，effect 空转 return
② JSON 到了、资源没到   gridSize 0 → 9，effect 重跑一次 —— <main> 仍然不存在，再空转
③ 资源到了             <main> 长出来，gridSize 没变 → 没有任何依赖变化，effect 不再跑
```

结果 `fit()` 一次都没真正跑过：`autoCellSize` 停在初值 `DEFAULT_CELL_SIZE`（32）、
`pan` 停在 `{0, 0}`，棋盘就小小地贴在左上角（用户报「地图缩小在左上方，应该是自
适应计算的时机不对」）。依赖里加 `gridSize` 也救不了 —— ② 就已经跑完了。

修法是把「**可以量了**」显式传进去：`useGameViewport` 多一个 `ready: boolean`，
`GamePage` 传 `!resourcesLoading`，它与 `containerRef`、`gridSize` 一起进依赖。
③ 那一拍 `ready` 由 `false` 翻成 `true`，effect 重跑，`fit()` 与观察者这时才真正
落地。

`resourcesLoading` 因此上移到视口调用之前（原来在渲染前才算），两处共用同一个值。
更彻底的替代方案是把 `containerRef` 换成 callback ref（节点一挂载就触发），但那要
动 `toCell` / `zoomBy` / 页面里所有 `containerRef.current` 的读法，收益不值。

## 2. 竖屏上下留白

`lib/canvasSize.ts`：

```ts
export const PORTRAIT_MARGIN_X = 8;
export const PORTRAIT_MARGIN_Y = PORTRAIT_MARGIN_X;   // 本轮先改成 4
export const PORTRAIT_STAGE_EXTRA = 24;               // 本轮从 32 收到 24
```

origin 是 8 / 12。本轮用户要求「上下再减小一些」，于是 `PORTRAIT_MARGIN_Y` 不再跟着
`PORTRAIT_MARGIN_X`，单独降到 **4**，`PORTRAIT_STAGE_EXTRA`（棋盘下方那条缝，下面就是
线索与名册）从 32 收到 **24**。左右仍是 8。

`portraitInsets()` 因此四面不再同值：

```ts
{ top: PORTRAIT_MARGIN_Y, right: PORTRAIT_MARGIN_X, bottom: PORTRAIT_MARGIN_Y, left: PORTRAIT_MARGIN_X }
```

`hooks/useGameViewport.ts` 里用它们的注释同步改写，`canvasSize.test.ts` 的断言改成拿常量算
（`gridSize * cell + PORTRAIT_MARGIN_Y * 2 + PORTRAIT_STAGE_EXTRA`），不再写死 16 / 24
这类推导出来的数字，也不再假设「上下等于左右」。

## 3. 竖屏名册：卡片把手势还给浏览器

`components/map-editor/ParticipantPanel.tsx` 的卡片根节点原本一律 `touch-action: none`。
那是**编辑器**要的：按住卡片拖拽换位，不能被浏览器解释成滚动。但竖屏玩家页里
名册是只读的，这条只剩副作用 —— 手指落在参与者框上上下划，浏览器不接管手势，
`overflow-auto` 的容器就收不到滚动。

改成：

```ts
touchAction: compactPortrait ? 'auto' : 'none'
```

编辑器（`compactPortrait === false`）保持 `none`，拖拽换位不受影响；两档都有用例
（`ParticipantPanel.test.tsx`）。

## 4. 空手时点格子也要有反馈

用户要的是「**没选参与者、也没选工具时，点格子同样要有鼠标光标框、物品抬起、物品名
tip**」—— 空手也得能看清这一格是什么，不必先点一个工具。（这一条第一版读反了，把
空手时的悬停整体关掉，随后按原意改回。）

反馈本身的来源没变，仍是三处：`MapMouseCursorBoxLayer` 画光标框、`MapItemLayer` 的
`lifted` 抬 4px、`tipOn` 弹名字，页面 `<main>` 的 `cursor` 读 `hoverEffects.cell`。
问题在**触屏**：点一下只会给 `pointerdown` / `pointerup`，中间没有 `pointermove`，
而悬停状态只在 `onPointerMove` 里写。于是手指按下去那一拍，三样反馈一样都不出。

做法是在 `onPointerDown` 里补写悬停状态，并且**放在 `if (mode.kind === 'idle') return;`
之前**（空手时也要写）：

```ts
const pressed = toCell(event.clientX, event.clientY);
setHover(pressed);
setHoverPoint(toCanvasPoint(event.clientX, event.clientY));
if (mode.kind === 'idle') return;
const cell = pressed;
if (!cell) return;
```

`setHover` / `setHoverPoint` 已在 `onPointerMove` 里各写一次，这里只是把同一条通道接到
按下的那一刻：鼠标上「划过去」与「点一下」从此得到同一组反馈。

页面层仍留着一个总闸 `hoverEnabled = !interactionLocked`，但**只表达「结案了」** ——
它挡的是 v0.9.7 那条：定案遮罩自己 `pointer-events-auto` 接住指针后事件会冒泡回
`<main>`，不在这里归零，光标框与物品抬起就会隔着遮罩亮起来。

用例在 `pages/GamePage.test.tsx` 的 `v0.11.2 空手时格子照常有悬停反馈`：棋盘正中放一件
带图的物品，一条派发 `pointermove`（鼠标划过去），一条**只派发 `pointerdown`**（触屏
按下去），两条都钉「光标是 pointer / 有 tip / 物品抬了 4px」。第二条是这次的反证：把
`onPointerDown` 里补写那两行去掉，它立刻以 `expected 'default' to be 'pointer'` 失败。

## 5. 「· 格物」跟着 LOREDOKU 图标

`components/layout/BrandLogo.tsx` 本来就带 `withWordmark`：图标后面加「· 格物」。只是
播放器的首页与游戏页没传这个开关，于是「· 格物」落在了 `<h1>` 标题里（用户报「加在
图标后面，不是标题后面」）。

- `player/PlayerHomePage.tsx`：`<BrandLogo height={16} withWordmark />`，`<h1>` 只留主题名。
- `components/game/GamePlayerAside.tsx`：桌面端那枚 logo 也加 `withWordmark`。

## 6. 竖屏标题行再收一档

`components/game/GamePlayerAside.tsx` 头部：竖屏内边距 `max-md:py-2` → `max-md:py-1`，
标题与计时在竖屏降到 `text-xs`（`max-md:text-xs`，标题另加 `max-md:leading-tight`）。
桌面档不变。

## 7. Safari 看不到物品描边

`lib/mapStyle.ts` 的 `itemOutlineFilter` 原来把线宽按格子尺寸缩放后直接写进
`drop-shadow`。竖屏格子约 49px 时，作者配的 6 只剩 2.45px —— Chrome 画得出，
Safari 的离屏合成会把这种小数宽度的软边缘抹掉，看起来就是「没有描边」。

两处改动：

1. **宽度取整并保底 1px**：`Math.max(1, Math.round(scaled))`，缩放后不是正数就整条
   不画（返回 `undefined`）。
2. **只在有描边时提升合成层**：`MapAssetLayers.tsx` 给色块与 `<img>` 加
   `willChange: 'filter'`（仅当 `outlineFilter` 存在），让 Safari 稳定地走带滤镜的
   合成路径，而不是把滤镜折进普通绘制。

没有改描边的算法与颜色，只改了「宽度怎么落成像素」与「谁负责合成」。

## 9. 没做的

- **不做首屏之外的预取**。只等「这一页会画到的图」，不顺手把别的关卡、别的主题的
  图拉下来。
- **不等字体**。`document.fonts.ready` 是另一件事（文字排版抖动），本版没动。
- **Safari 的真机验证留给发布后**。本机能做的是宽度取整与合成层提示这两条已被
  证实的成因；真机上是否彻底消失，要在部署后看一眼。
