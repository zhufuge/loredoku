# v0.10.0 — 游戏列表与游戏页面的移动端适配

> **状态**：已实施（2026-11-11）。
> **来源**：用户的一条——
>
> > - 游戏列表和游戏页面做移动端适配
>
> 适配的判据不是「手机上能打开」，而是**手机上能玩**：375×812（iPhone SE / 13 mini
> 那一档）竖屏下棋盘要占掉主要面积、落子要能点到、定案遮罩要看得全。改前实测

## §1 游戏列表：窄屏收紧间距、页脚可折行

列表页本来就没坏 —— 两列卡在 375 下排得下。坏的是密度：`gap-5`（20px）在 320px
屏上两条槽就吃掉 40px，卡正文 `p-4` 在 148px 宽的卡里也偏挤，页脚「2 × 2 + 难度 +
时间」三样挤在一行。

| 位置 | 桌面 | 窄屏（< 640） |
|---|---|---|
| 页面内边距 | `px-6 py-6` | `px-4 py-5` |
| 区块间距 | `space-y-8` | `space-y-6` |
| 卡片网格槽 | `gap-5` | `gap-3` |
| 卡正文内边距 | `p-4` | `p-3` |
| 空态 / 错误卡 | `p-12` | `p-8` |
| 卡封面首字（无封面时） | `text-4xl` | `text-3xl` |

三处额外改动：

1. **页头 `flex-wrap`**。品牌 + 「N 个游戏可玩。」在左，「主题切换 + 进入工坊」在右；
   320 宽时两坨加起来超过一行，`justify-between` 会把它们硬挤到重叠。加 `flex-wrap`
   后右侧整块掉到下一行，两侧都留得住。
2. **卡页脚 `flex-wrap` + `gap-y-1`**。`n × n`、难度徽章、时间三样在 148px 里放不下；
   允许折行后难度和时间分到第二行，比缩字号好读。
3. **`sm:` 断点而不是 `md:`**。列表页的容器是 `max-w-7xl`，两列卡在 640px 就已经很宽了 ——
   640~767 这一段还按手机密度排会显得空。列数（`md:grid-cols-3 xl:grid-cols-4`）不动，
   那是 v0.4.0 定的，与本次无关。

## §2 游戏页：三栏在窄屏改成「上抽屉 / 中棋盘 / 下横条」

### 2.1 问题：三栏是写死的宽度

改前三栏都在一行里，且全都不缩：

| 栏 | 宽度来源 | 375px 屏上实际 |
|---|---|---|
| 左（题面 + 名册） | `style={{ width: rosterWidth }}`，`rosterPanelWidthFor` ≥ 256 | 256 |
| 中（棋盘） | `flex-1` | **35** |
| 右（工具栏） | `w-[84px] shrink-0` | 84 |

左栏里还嵌着 `ParticipantPanel` 自己的 `<aside>`，也是固定宽度 —— 两段 256 并排，
中列直接没地方了。

### 2.2 形态

`< md`（768 以下）：

- **左栏变成顶部横条**：`max-md:!w-full`。`!` 是必须的 —— 宽度是算出来的**内联像素值**
  （`GamePage.test.tsx` 有一条用例钉着 `aside.style.width === '375px'`），只有 important
  能盖过内联样式。`style.width` 本身一个字没改，桌面端完全照旧。
- **题面与名册收进抽屉**：左栏标题块末尾多一枚按钮（`md:hidden`，窄屏才画），
  `aria-label="题面与参与者"`、`aria-expanded` 跟着开合变，配 `text-2xs` 的一行字 +
  Chevron 上下箭头。抽屉本身是 `<div className={cn('min-h-0 flex-1 flex-col md:flex',
  briefOpen ? 'flex' : 'hidden')}>` —— 桌面靠 `md:flex` 永远展开，与改前逐像素一致。
- **右栏变成底部横条**：`max-md:w-full max-md:flex-row max-md:flex-wrap`，
  四枚工具 48px → `h-11 w-11`（44px，苹果要求的最小可点尺寸）方钮，视图簇
  （放大 / 百分比 / 缩小 / 重置 / 标尺）跟在后面同一行折行。

保留 `mt-auto`：`GamePage.test.tsx` 断言右栏最后一个子元素带它。横条里它被
`max-md:mt-0` 盖掉，桌面端照旧把这一簇压到底边。

- **根容器 `h-screen` → `h-dvh`**。`100vh` 在 iOS Safari 里是「地址栏收起后」的高度，
  用它在竖屏上底部会切掉一条 —— 正好是刚搬到底部的工具横条。`dvh` 跟着可视区走。

### 2.3 抽屉的默认状态与收放时机

抽屉默认**关**。手机上的第一需求是看到棋盘，题面点一下就有。

选完人自动收：`handleCardClick` 在 `setMode({ kind: 'placing' })` 之后调
`setBriefOpen(false)`。选了人下一步就是落子，抽屉继续占着上半屏会让棋盘只剩一条缝。
桌面端 `md:flex` 恒展开，这个状态对那一侧没有影响。

名册自己横向滚动（wrapper 加 `max-md:overflow-x-auto`）：24 人的谜题名册矩阵宽 747px，
一列列折到竖排会把抽屉推到顶满整屏。横着划比竖着刷更快找到某个人。

## §3 定案遮罩按棋盘边长等比缩

### 3.1 问题

结案后的「定案」遮罩版式是照桌面定的：`text-9xl`（128px）的两个字、192px 的印、印往
右上让开 `{ x: 150, y: -50 }`。桌面上棋盘 480 起，压得住。手机 2×2 棋盘只有 236px 见方 ——
两个字竖着顶出遮罩，「再玩一次」被压在下面点不到。

### 3.2 做法：`lib/verdictMark.ts`

```ts
export const VERDICT_BASE_BOARD = MAX_CELL_SIZE * 2;   // 480
export const VERDICT_MIN_SCALE = 0.5;

export function verdictMarkScale(boardSize: number): number {
  if (!Number.isFinite(boardSize) || boardSize <= 0) return 1;
  const ratio = boardSize / VERDICT_BASE_BOARD;
  if (ratio >= 1) return 1;
  return Math.max(VERDICT_MIN_SCALE, ratio);
}
```

- 参照尺寸 = 「两格都顶到 `MAX_CELL_SIZE`」= 480，也就是桌面小棋盘的样子。
- 比它大的棋盘**不放大** —— `large` 档再往上放会盖满整屏。
- 下限 0.5：再小「定案」就成一行小字了，那时宁可让印偏出去一点。
- `GamePage` 里 `const verdictScale = verdictMarkScale(total)`（`total = gridSize * cellSize`
  是棋盘渲染出来的真实边长，缩小/平移都不会误判），传给 `VerdictMark` 的 `scale`。

### 3.3 为什么用 `zoom` 而不是 `transform: scale`

`VerdictMark` 根上挂的是 `style={{ zoom: scale }}`：

- **`transform` 会被印的关键帧覆盖**。`stamp-press` 那段 `@keyframes` 写的就是**整条**
  `transform`（`scale` + `rotate`），外面再挂一条 `transform: scale(n)` 会在动画期间被
  整条替换掉 —— 印先跳回原尺寸再弹。`zoom` 与 transform 正交，互不干扰。
- **`transform` 只缩视觉，不缩盒子**。遮罩里 `flex flex-col gap-6` 排下来，按钮位置是按
  元素盒子算的；盒子不缩，按钮还停在按 128px 字算的地方，照样被挤出去。`zoom` 连布局
  尺寸一起缩，`gap-6` 与按钮位置自然就正常了。

### 3.4 效果

| 视口 | 棋盘边长 | `verdictScale` | mark 盒子 |
|---|---|---|---|
| 375×812，2×2 | 236 | 0.5 | 160×64 |
| 320×568，2×2 | 182 | 0.5 | 160×64 |
| 1280×800，桌面 | 480 | 1 | 320×128（与改前一致） |

## §5 没做的

- **没给编辑器做响应式**。`docs/design-system.md` §5.10 那条「编辑器零响应式」还在账上，
  用户这次只说游戏列表和游戏页面。
- **没做 JS 宽度判断 / `useMediaQuery`**。全部走 Tailwind 断点，纯 CSS。
  `testing/matchMedia.ts` 那个桩的 `matches` 恒等于 dark 参数、不认宽度 query ——
  一旦引入 JS 媒体查询就得先扩桩，能不碰就不碰。
- **没碰触摸设备的长按菜单**（`docs/v0.7.10.md:453` 记的那条遗留）：棋盘容器仍然没有拦
  `contextmenu`，iOS / 安卓的长按菜单还可能打断「清除」的长按清空。它与「适配屏幕尺寸」
  是两件事，留给专门的一版。
- **没改列表页的列数**（`md:grid-cols-3 xl:grid-cols-4`）。那是 v0.4.0 定的版式，
  在 375 下两列本来就没问题。
- **没改播放器**。`PlayerHomePage` 有自己的一套卡片网格；播放器里的游戏页因为是同一个
  `GamePage` 组件，这次改动自动覆盖。
- **没给抽屉加动画**。开合是即时的 `flex` / `hidden` 切换 —— 抽屉盖住的是棋盘上方一块
  空间，动画期间棋盘要重算尺寸，容易和画布的 `ResizeObserver` 抢帧。
