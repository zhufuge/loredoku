## §1 定案弹窗标题

`DialogTitle` 从「定案」改成「🎉 恭喜定案！」（`aria-hidden` 的庆祝表情 + 文字）。
结案是值得高兴的一刻，板着脸只写两个字说不出这层意思。

字距从 `tracking-[0.3em]` 收到 `0.1em`：加了表情和四个字之后，原来的宽字距会把
`max-w-md` 的卡撑得松散。

## §2 最后离开时间改成相对时间

`formatRelativeTime(iso, now?)`：

| 距离 | 显示 |
|---|---|
| < 60 秒 | 刚刚 |
| < 60 分 | `N 分钟前` |
| < 24 小时 | `N 小时前` |
| ≤ 7 天 | `N 天前` |
| > 7 天 | 具体日期（`11-10 15:04`） |
| 未来时刻 | 刚刚（设备时钟被拨过，不显示负数） |

**分档只到「天」**：再往上（周 / 月）对「我上次玩到什么时候」没什么帮助，超过
7 天直接写日期更准。

它现在读的是 `leftAt`（墙钟 ISO），**不是** `timer.elapsedMs`。v0.9.6 把这一格
写成离开时的计时读数（`00:30`），v0.9.7 用户明确要「刚刚 / 1分钟前之类」——
计时读数退到 `title`（悬停仍可看到「上次离开时计时 02:00」），版面留给相对时间。

## §3 超过一小时用 `hh:mm:ss`

`formatElapsed` 之前小时不补零（`1:03:07`）。改成 `pad(hours)` → `01:03:07`，
与 `mm:ss` 那两段等宽统一；秒针跳到 10 点以后整行不会左右抖。

- 未超过一小时：`03:07`、`59:59`（不变）
- 超过：`01:00:00`、`01:03:07`、`10:00:00`

游戏页计时、列表卡片完成用时都走这同一个函数，不会各写一套。

## §4 定案字大、印盖住一点字

`VerdictMark`（卡片封面与地图遮罩共用）改成：

```
定案          ← 大号楷体（卡片 text-4xl / 遮罩 text-7xl）
  [印]        ← z-10 压在字之上，-mt-[0.35em] 上提盖住下缘，仍倾斜 −8°
```

上提量按 `em` 走，两处因此自动同比例叠压 —— 没有写死像素，卡片与棋盘尺寸差
那么多也不会一处叠太多、一处叠不上。

**深色遮罩下的可读性**（这条是实施时发现并补的）：`bg-black/60` 压下去之后，
`text-foreground`（浅色主题下是深色）与作者那枚深墨印都会糊进黑底。于是
`VerdictMark` / `VerdictStamp` 加了 `onDark`：
- 文字 → `text-background`（浅色）
- 印 → `brightness-0 invert`（先压成纯黑再翻白），与浅色主题下
  `dark:invert dark:hue-rotate-180` 那套互斥，不会叠两种染色

卡片（浅底）保持原样。

## §5 遮罩改用一般遮罩颜色

`verdict-scrim` 从 `bg-background/85` 改成 `DIALOG_OVERLAY_TINT_CLASS`
（`bg-black/60`）—— 与四处校验遮罩、弹窗 overlay 同一档 token。用户选的是
「与校验遮罩/弹窗一致」那一项。

v0.9.6 那档浅色、过实，读起来像另一套东西；改成深黑半透明后，棋盘被压暗、
「定案」与印浮在上面，与「这一局结束了」的语气一致。

## §6 未开始的游戏不展示时间

`GameCard` 只有 `completed` / `lastLeftAt` / `lastLeftElapsedMs` 三者有其一时才画
【时间图标】+ 时间格。之前那一格写 `00:00`，会让「没玩过」看起来像「玩了 0 秒」。

`CompletionTime` 的第三种分支从返回 `00:00` 改成返回 `null`，
`game-no-time` 这个 testid 一并撤掉。

## §8 时间图标只配完成用时（第二、三批）

`GameCard` 画时间格的判定与 `CompletionTime` 返回非 `null` 的条件**完全同一份**：
`completed || lastLeftAt`。

之前判定里还多一个 `lastLeftElapsedMs != null` 分支 —— 那是给 v0.9.6 之前「只有
计时存档、没有 `leftAt`」的旧数据留的，但 `CompletionTime` 现在读的是 `leftAt`
（§2），这条分支会画出**一个图标却没有文字**。删掉。

**图标本身再收一层**（用户追加「展示最后离开时间时，不展示图标」）：

| 情况 | 版面 |
|---|---|
| 已完成 | 🕐 + 完成用时（图标说的是「这是一份成绩」） |
| 只玩过、没完成 | 只写「3 分钟前」，**不画图标** |
| 没玩过 | 整格不出现 |

相对时间本身就说清了「什么时候」，再挂一枚时钟会把它读成一份计时读数 ——
图标在那里是噪音。

## §9 定案卡不演鼠标光源（第二批）

`GameCard` 的封面在 `completed` 时：
- `onPointerMove` 不挂（`followPointerWithGlow` 不执行）；
- `LIGHT_LAYERS` 三层光整组不渲染。

理由：光斑是「挑关卡时找手感」的，定案卡是既成事实；盖着「定案 + 印」的封面上
再浮一层光，两件装饰抢同一块地方，也让「结案」读起来像还能再玩一次。
没完成的卡照旧发光，不是把整站光源关掉。

**同一条理由再收一层**（用户第四批「定案卡也不需要 hover 放大缩小封面」）：
封面 `img` / 无图占位的 `div` 上的 `group-hover:scale-[1.1]` 与
`group-focus-visible:scale-[1.1]` 在 `completed` 时都不挂。封面一推进，
「定案 + 印」跟着一起胀，同样读成「还能再点进去玩一局」。
卡片外层的 `hover:border-primary/30 hover:shadow-lifted` 保留 —— 那是
「这张卡可以点」的提示，不是封面自身的几何动作。

真浏览器实测：真实 hover 定案卡后封面 `transform` 仍是 `none`；未完成卡仍带
缩放类。

## §10 结案后不接指针（第二批）

用户：「定案的游戏里，有地图遮罩，就不要有鼠标和地图及物品人物的交互」。

**做法是在容器上挡指针，而不是给十几个 handler 各加一个 `if (finished) return`**：
后者每加一个新交互都要记得再守一次，漏一个就是同一个 bug 的重演。

| 位置 | 处理 |
|---|---|
| 左栏 `aside` | `interactionLocked && 'pointer-events-none'` —— 名册卡 hover / 点击武装、题面 |
| 中列 `main` | 同上 —— 格子 hover / 放置 / 长按 / 缩放 / 平移 |
| 右侧视图簇 | 放大 / 缩小 / 重置视图 / 标尺四枚 `disabled={toolsLocked || …}` |
| 右侧四枚工具按钮 | v0.9.6 已由 `toolsLocked` 置灰 |
| 定案遮罩 | `pointer-events-auto` 显式恢复，接住指针；「再玩一次」是这一屏唯一能点的东西 |

**例外（用户第五批）**：左栏头部那一行（返回箭头 + 品牌 + `ThemeToggle`）用
`pointer-events-auto` 显式恢复 —— 「定案游戏里，可以点击返回和切换日夜模式」。
CSS 允许父 `pointer-events-none` 之下的子元素重新启用指针，所以只需要给头部
那个 `p-3` 容器挂一个类，题面 / 名册仍然锁着。返回是 `navigate`，主题开关是
`useTheme().cycle`，两者都不碰棋盘，不违反「不要有地图及物品人物的交互」。

另外在 `finished` 转真时清一次残留状态（`hover` / `hoverPoint` / `labelRegionId` /
`activation` / `mode`）：玩家可能是「鼠标正停在某格上」时通过的，指针被挡住之后
那个格子的操作光标框不会自己收到 `pointerleave`，会一直亮在遮罩底下。

### 深色主题下的一处修正（实施时发现）

v0.9.7 第一批把 `onDark` 的文字色写成 `text-background` —— 浅色主题下是浅色，但
**深色主题下 `--background` 是墨色**，白字变黑字糊进 `bg-black/60`。这正是
`index.css` 「光照两端」那段注释说的「换成主题 token 会让方向随主题反转」。

改成两档各取该主题下的近白：

```
text-primary-foreground dark:text-foreground
浅色主题 → 40 30% 98%      深色主题 → 38 20% 92%
```

两种主题都在真浏览器里截图确认过白字清晰。

## §11 隔着遮罩的 hover 交互（第六批）

用户反馈：「定案游戏当前还能隔着地图遮罩与地图的方格/物品等交互，要去掉 hover 交互」。

**根因**：v0.9.7 第二批只在 `<main>` / `<aside>` 挂了 `pointer-events-none`。CSS 的
`pointer-events` 只挡 **hit-testing**，而结案遮罩自己 `pointer-events-auto` 接住了
指针 —— 事件于是沿 React 树**冒泡**回 `<main>` 的 `onPointerMove`，`setHover` 照样
写状态，光标框 / 物品抬起 / 区域高亮就隔着遮罩亮起来。

修法是两层，缺一不可：

1. **所有入口 handler 短路**：`onPointerDown` / `onPointerMove` / `onPointerUp` /
   `onWheel` / `onClick` 各加 `if (interactionLocked) return`；名册的
   `handleActivation` / `handleCardClick` 同理。
2. **从源头掐掉渲染**：`hoverEffects` 的 `useMemo` 在 `interactionLocked` 时给
   `resolveHoverEffects` 传 `hover: null`（得到 `NO_HOVER_EFFECTS`）；传给
   `MapItemLayer` 的 `hover` / `pointer` 和 `MapRulerStrips` 的 `hover` 也一并置
   `null`。这样不管冒泡把 state 写成什么，画出来的都是「没有 hover」。

`interactionLocked`（连带 `finished` state）因此提到了组件最前面的 state 区 ——
`hoverEffects` 的 `useMemo` 要读它，声明必须更早，否则 TDZ。

真浏览器实测：真实指针在遮罩上移动后 `main` 的 `cursor` 仍是 `default`、
`item-name-tip` 不出现、棋盘存档没被落笔。

## §12 定案字更大、印章用原色（第六批）

用户：「定案游戏里的『定案』字体大小可以再大一些，印章使用原色压在字上。
列表卡片封面也一样」。

`VerdictMark` 是两处共用的组件，所以一次改动两处一起生效：

| | 之前 | 现在 |
|---|---|---|
| 字（卡片 / 遮罩） | `text-4xl` / `text-7xl` | `text-5xl` / `text-8xl` |
| 印上提量 | `-mt-[0.35em]` | `-mt-[0.55em]` |
| 印尺寸上限 | 46% | 52% |
| 印颜色 | 按主题 / 遮罩翻色（`dark:invert` / `brightness-0 invert`） | **原色，不翻** |

**印章保持原色**：之前为了深墨印在深底上能看清，按主题或遮罩翻过色；但一枚红印
被翻成白色就不再是作者盖的那枚了。两处现在用同一张原图、同一个 −8° 角度，
不随主题变。深底上的可读性交给印自己的透明底与下面那层大号白字衬。

真浏览器实测：遮罩里 `stampFilter: none`、红色原印明显压在更大的白字下缘；
列表卡片同样 `filter: none`，浅色 / 深色两种主题下都不再翻色。

## §13 没做的

- **不把庆祝图标换成图片 / 表情包资源**。用 Unicode 🎉（`aria-hidden`）：它不依赖
  资源包、不需要新上传目录，在深色下也不会变疤。作者要换成自定义图再说。
- **不给相对时间做「秒级自动刷新」**。「3 分钟前」在页面上停几分钟才跨档，为它
  挂一个每秒 `setState` 会白白重渲染整页卡片。
- **不把 > 7 天的相对时间继续做「N 周前 / N 月前」**。见 §2：日期更准。
- **不给「未开始」留一个占位图标**。用户说「不展示时间」，连图标一起省掉才干净。
- **不改完成记录 / 计时存档的结构**。这一版全是显示层，v0.9.6 的键照读。
- **不把左上角的返回、主题开关一起锁掉**。用户明确要这两个在结案时仍可点；
  它们不碰棋盘，与「不要有地图及物品人物的交互」不冲突。
