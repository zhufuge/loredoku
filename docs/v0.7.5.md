# 需求 + 设计：地图编辑器 · 已放置物品的展示变换（v0.7.5）

> **状态**：**已实施**（2026-10-23）。需求即本文，设计即本文；实施记录见 §9。
>
> 需求原文：
> ```
> v0.7.5
> 地图编辑器
> - 添加已放置的物品（非背景类资源），可以等比例调整展示大小和偏移位置（可超出当前格子范围）;在格子的信息框内配置
> ```

## 0. 一句话

物品放到格子上之后，还能**等比例放大 / 缩小**并**按格偏移**，允许画到脚位之外；三个控件都在格子的信息框里。

关键是把「**占格**」和「**展示**」拆开：`w × h`（脚位）继续决定占几格、擦除范围、碰撞；新增的 `scale` / `offsetX` / `offsetY` 只决定**这张图看起来多大、歪到哪儿**。所以「一棵 3 格高的树」不必再做成 1×3 的形态 —— 1×1 的树放大 3 倍就够，占格仍是一格。

## 1. 改之前是什么样

- **物品的矩形就是它的脚位**：`cellRectStyle(x, y, cellSize, anchor.w, anchor.h)`，`w` / `h` 来自形态的 `widthCells` / `heightCells`，放下去就锁死。想画得更大，只能回去改形态的占格 —— 而那会同时把占格、擦除范围一起改掉。
- **大到跨格的装饰物只能靠形态**：一棵 1×3 的树，在数据上和「一堵 1×3 的墙」没有区别。作者想要的往往只是「图大一点」，付出的却是「占三格」。
- **想做「石头半嵌进墙里」只能在图片里留白**：位置微调没有入口，美术改一次图才能挪 4px。
- **信息框的格子分支是只读的**：缩略图、名称、`w×h`，可编辑的一个都没有。
- 顺带一个旧毛病：多格物品只有**锚点**带 `item`，其余脚位格是空占位 —— 所以鼠标停在 2×2 的中间那格时，信息框显示「物品层 空」。

## 2. 边界

| 做 | 不做 |
|---|---|
| 一个等比 `scale`（25% ~ 400%） | 宽高分开的非等比缩放 —— 像素画被拉扁只会让人回去改图 |
| 以**格**为单位的 `offsetX` / `offsetY`（-4 ~ +4 格） | 以像素为单位的偏移 —— `cellSize` 可调，像素偏移换个格子大小就错位 |
| 允许画到脚位之外，不裁切 | 旋转、翻转、透明度 |
| 只作用于**物品层** | 背景层 —— 它恒 1×1 铺满，缩放它等于把格子线也弄乱 |
| 存在脚位锚点上，跨格共享一个变换 | 每格独立变换：同一个物品被拆成几块各缩各的，接缝对不上 |

## 3. 数据模型

`DraftAnchorItem` 加三个**可选**字段：

```ts
interface DraftAnchorItem {
  assetId: number;
  formId?: number;
  w: number;      // 脚位（占格），不变
  h: number;
  scale?: number;      // v0.7.5 展示倍数，1 = 填满脚位
  offsetX?: number;    // v0.7.5 以格为单位的偏移，可负
  offsetY?: number;
}
```

**放在锚点，不放在每个脚位格。** 一个 2×2 的物品只有锚点携带 `item`，其余三格是空占位；把变换复制到每一格，等于给「同一个物品」留了四份可能互相矛盾的真相。

**缺键 = 恒等。** 老草稿一个字节都不用改，渲染时 `resolveItemTransform` 补 `1 / 0 / 0`。

**边界常量**（`packages/shared/src/constants.ts`）：

| 常量 | 值 | 说明 |
|---|---|---|
| `ITEM_SCALE_MIN` / `_MAX` | 0.25 / 4 | 25% ~ 400% |
| `ITEM_SCALE_STEP` | 0.05 | 输入框的步长（显示为 5%） |
| `ITEM_OFFSET_MIN` / `_MAX` | -4 / 4 | 格；±4 格已经能横穿大半张图 |
| `ITEM_OFFSET_STEP` | 0.05 | 5% 格 |
| `DEFAULT_ITEM_SCALE` / `DEFAULT_ITEM_OFFSET` | 1 / 0 | 恒等的定义 |

**夹取在两处各做一次**：schema（写入口，越界直接拒）与 `resolveItemTransform`（读入口，手改 JSON / 老构建写的值夹回来并保留两位小数）。渲染和 store 都走后者，所以「画布上看到的」和「写回草稿的」永远是同一个数。

**`MAP_JSON_VERSION` 不升。** 三个字段是可选的、可加的，缺键即恒等 —— 没有迁移可做。反过来（老客户端读新草稿）会被 `.strict()` 拒掉，那是「旧版本读不了新草稿」，不是数据损坏，和 v0.7.4 放宽 `fontFamily` 时同一个判断。

## 4. 渲染

`MapItemLayer` 的盒子从「脚位矩形」换成「展示矩形」（`itemRectStyle`）：

```
width  = w * cellSize * scale
height = h * cellSize * scale
中心   = ((x + w/2) * cellSize + offsetX * cellSize,
          (y + h/2) * cellSize + offsetY * cellSize)
left/top = 中心 - 尺寸/2
```

**缩放围绕脚位中心，不是左上角。** 绕左上角放大会让物品一路往右下长，作者得同时拧「大小」和「偏移」才能把它摆回原地 —— 两个旋钮互相污染。以中心为锚点，`scale` 只管大小，位置只由偏移决定。

**恒等变换逐像素相同**：`scale=1`、不偏移时算出来就是 `x*cellSize / y*cellSize / w*cellSize / h*cellSize`，与旧的 `cellRectStyle` 一致，老草稿渲染零位移（有测试钉住）。

**不裁切**：盒子本身就是展示矩形，`overflow: hidden` 只负责裁掉悬停上浮那 4px（和以前一样），放大 / 偏移后的图形不会被自己的盒子切掉。

**只改一个地方，四处生效**：编辑器画布、地图版本预览（`MapViewPage`）、谜题预览（`PuzzleViewPage`）、游戏页（`GamePage`）都渲染同一个 `MapItemLayer`。占格、擦除、碰撞读的仍是 `w × h`，那些逻辑一行没动。

两个保留的旧语义：

- **悬停仍按脚位判定** —— 悬停到隔壁格子上方的「探出部分」不该点亮这个物品；
- **点击仍选锚点** —— 盒子的 `onClick` 交回的是锚点坐标，所以放大的物品探到哪儿，点它都选中它自己，橡皮擦也照样一次擦掉整块脚位。

## 5. 写入路径

新 store 动作 `setItemTransform(x, y, patch)`：

1. `findItemAnchor(cells, x, y)` 找脚位锚点 —— 信息框可能停在任何一格（2×2 的中间那格也是合法选中），只有锚点带 `item`；
2. `resolveItemTransform({ ...当前, ...patch })` 夹边界、留两位小数；
3. **与默认值相同的字段不写**，三个全默认时 `item` 上根本没有这三个键（草稿保持干净，也为以后「重置」留了统一的判定）；
4. 解析后与当前值完全一致 → **直接返回，不进撤销栈**。

第 4 条是必要的：`NumberField` 每次按键都提交，拖到边界上继续打字会连续提交同一个夹取后的值，撤销栈里会堆一串一模一样的步骤。区域样式那边也有同样的行为，但那边是「草稿 + 保存」，这里**即时生效**，所以更明显。

**为什么即时生效，不像区域那样「草稿 + 保存」**：调大小 / 挪位置是看效果的活，改完要立刻在画布上看到；一个「保存」按钮会把它变成「试一下 → 保存 → 不对 → 再改」的循环。代价是每一步都进撤销栈，`Ctrl+Z` 一步一次，可控。

## 6. UI

格子的信息框（`EditorInfoDrawer` 的格子分支）里，「物品层」多了一组控件：

```
物品层                              [复位]
[缩略图] 古树 · 形态名         2×2
大小      [150] %
偏移      [0.25] X 格  [-1] Y 格
```

- **大小**是百分比（25 ~ 400，步长 5），存的时候除以 100；`NumberField` 写穿到 store，拖步进箭头立刻见效；
- **偏移**两个输入框共用一行，正数向右 / 向下，负数向左 / 向上，单位「格」；
- **复位**只在真有变换时出现，一次把三个字段打回默认；
- **只读环境**（谜题编辑器）不给控件，只在有变换时留一行摘要：`展示 150% · 偏移 (0.25, -1) 格`；
- **顺手修掉的旧问题**：信息框现在用 `findItemAnchor` 取物品，所以停在脚位里的**任意一格**都能看到并编辑那个物品，而不是显示「空」。

## 7. 与既有机制的关系

- **撤销 / 重做**：走既有的 `commit`，一步一次；「复位」也是一步；
- **多格占位**：`placeItem` 清掉脚位里所有 `item` 再写锚点，新放置的物品天然是恒等变换 —— 不会继承上一个物品的缩放；
- **擦除**：`resolveEraseTarget` 改成复用 `findItemAnchor`，行为不变（先物品后背景），代码少了一段重复的脚位扫描；
- **导入 / 导出 / 版本快照 / 谜题副本**：`toDraft` 原样带走格子对象，三个字段自动跟随，没有任何白名单需要补；
- **服务端**：`draftAnchorItemSchema` 收下这三个可选字段，`.strict()` 的格子 schema 不会再把新草稿拒掉。

## 8. 明确不做

- **非等比缩放**（宽高分开）：要的是「图大一点」，不是「把树拉扁」。
- **旋转与翻转**：会和占格、碰撞、悬停判定全部打架，收益也远小于成本。
- **背景层的变换**：背景恒 1×1 铺满格子，缩放它等于让格子线错位。
- **同格多物品**：数据模型仍是一格一个物品锚点，这次不动。
- **每格独立变换**：跨格物品共享一个变换，否则接缝处会出现「同一张图被拆成几块各缩各的」。
