## 0. 一句话

在这之前，「动效」在这个仓库里**不是一个概念**：一条 `highlight-fade` 关键帧、七处手写
毫秒（`duration-200` ×6、`duration-150` ×1）、四条互不相干的缓动、以及
**一条 `prefers-reduced-motion` 都没有**。这一轮把动效收成四档时长 + 三条曲线，补上四个
真缺口（确认删除弹层没有动画、列表行菜单硬切、按钮按下无反馈、主题切换整站跳色），
第一次给「减少动态」偏好兜底，然后把同一套 token 用到最需要过程的那一秒上 ——
**500ms 长按，从「只有结果」变成「看得见的过程」：环画满的那一帧，头像落下去。**

**没有做页面入场、没有做交错上浮。** 理由不是省事，是原则 6 写下的取向，见 §7.1。

## 1. 四档时长、三条曲线

取值在 `index.css` 的 `:root`，映射在 `tailwind.config.ts`。

| Token | 值 | 用途 | 落在哪 |
|---|---|---|---|
| `duration-fast` | 120ms | **反馈**：按下、悬停变色、图标 | 按钮、输入、列表行、画布内悬停抬升 |
| `duration-base` | 180ms | **状态**：弹层进出、抽屉、交叉淡入 | `sheet-fade`、`place-settle`、保存遮罩 |
| `duration-slow` | 260ms | **结构**：整块位移 | 三个右侧抽屉（320px 全滑） |
| `duration-image` | 360ms | **画面**：内容的展开，不是控件的响应 | 两张网格卡的封面缩放 |

| Token | 值 | 语义 |
|---|---|---|
| `ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 默认出场：指数减速，起步快、收尾长 |
| `ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 来回切换（展开 / 收起、选中移出） |
| `ease-in` | `cubic-bezier(0.7, 0, 0.84, 0)` | 离场：加速离开 |

`duration-image` 是唯一**按用途命名**的一档，因为它是唯一一类「内容的动效」而不是「控件的
动效」。前三档都在管界面如何响应你，它管画面如何展开：网格卡的封面默认 `scale-[1.2]`
（`overflow-hidden` 切掉四边），悬停时缩回 1 展示全部 —— 20% 的行程在 180ms 里前 70ms 就
走完过半（`ease-out` 起步接近垂直），看起来像被拽回去。360ms 配合 `ease-in-out`（两头均速、
中间快）才有「摊开」的观感。它不怕慢：卡片的 `hover:border-primary` 在 120ms 内已经把
「选中了」说清楚，封面不承担即时反馈的责任。

**不用回弹与弹性曲线**（`cubic-bezier(0.34, 1.56, 0.64, 1)` 那类）。它们会让注意力跑到动画
本身而不是内容上；更实际的原因是，这个工具一天要开关几十次对话框，每次回弹一下，
半小时后就成了噪音。

### 1.1 关键一步：把 `DEFAULT` 指过去

真正让「一套动效」成立的，不是新加三个类，而是把 Tailwind 的 `transitionDuration.DEFAULT`
与 `transitionTimingFunction.DEFAULT` 也指向 token：

```ts
transitionDuration: { DEFAULT: 'var(--motion-fast)', fast: …, base: …, slow: …, image: … },
transitionTimingFunction: { DEFAULT: 'var(--motion-ease-out)', out: …, 'in-out': …, in: … },
```

全仓 **41 处裸写 `transition-colors`**，原本各自吃 Tailwind 的 150ms +
`cubic-bezier(0.4, 0, 0.2, 1)`。指过去之后这 41 处**一个字都不用改**就统一了 —— 需要别的
节奏的地方才显式写 `duration-base` / `duration-slow` / `duration-image`。产物里可以直接验证：

```css
.transition-colors{transition-timing-function:var(--motion-ease-out);transition-duration:var(--motion-fast)}
```

### 1.2 顺手清掉的残留

`tailwind.config.ts` 里的 `accordion-down` / `accordion-up` 删掉了 —— 仓库里没有 accordion
组件，那是 shadcn 脚手架带进来的。`blink` / `glow` 保留：它们与 shared 的
`EFFECT_TYPES`（`highlight | glow | blink | tooltip`）逐字对应，是联动效果的状态提示，
目前还没有调用点，但删掉会让那组枚举失去后半截。

## 2. 补齐四个状态缺口

### 2.1 确认删除：最常出现，却唯一没有动画的弹层

**问题**：`AlertDialog`（**12 个文件在用**，删除地图 / 谜题 / 资源 / 角色 / 版本、取消部署
全走它）里一条 `animate-*` 都没有，而普通 `Dialog` 是淡入的。同一个界面上两套动作并存，
读起来像两代人写的。

**做法**：与 `Dialog` 完全对齐 —— 遮罩淡入、面板淡入，180ms 进、135ms 出。

**刻意不做位移与缩放**：面板靠 `-translate-x-1/2 -translate-y-1/2` 居中，而任何
transform 关键帧都会**覆盖整条 `transform`**，动画期间面板会偏离中心半屏 ——
200ms 内斜着滑进来再跳回中心，比不动更糟。`zoom-in-95` 在提示与菜单上是合适的，
在这里不行。这条约束写在 `index.css` 的注释里，避免下次有人「顺手加个缩放」；
同一个坑在 §3.6 又出现了一次。

### 2.2 列表行的「更多操作」菜单

每行一枚的 portal 菜单（`components/common/EntryActionsMenu.tsx`），此前是「啪」地整块
出现在鼠标边：眼睛还没从按钮移开，一列菜单已经压在那儿了。补 120ms 淡入 + 从右上角
轻微放大（`origin-top-right` 对齐它的定位方式：菜单右边缘贴按钮右边缘、向下展开）。

**没有出场动画**：关闭时节点直接卸载，要退场就得按住卸载 100ms 左右，而菜单项点下即执行 ——
让人等它消失是净损失。退场本来就该比入场快。

### 2.3 按钮按下去没有反馈

之前按钮只有颜色变化。在 `ghost` / `outline` 这两种「背景本来就是纸色」的变体上，
按下去几乎看不出来 —— 点了没反应，人会再点一次。现在统一加 `active:translate-y-px`：

- **不是缩放**：`scale(0.98)` 会让文字在动画中途重新栅格化、发虚；
- **不参与 `transition`**：按下应当立刻发生，回弹也立刻，120ms 的过渡会让按压变「软」；
- 语义也贴：不是「被按扁」，是**把纸按进桌面**。

### 2.4 悬停才出现的删除按钮

`RegionList` 的行内删除（24px 微按钮，v0.7.9 §5 记的三条例外之一，所以保留 `title`）
原来从 `opacity-0` 到 1 是硬切，鼠标扫过列表时一串图标集体闪一下。补 `transition-opacity`
之后，顺手补了 `focus-visible:opacity-100` —— 键盘用户 tab 到它时，焦点环原本画在一个
**全透明**的按钮上，等于这行的区域删不掉。

### 2.5 主题切换：整站颜色跳变

点一下主题按钮，一屏米黄瞬间变成夜墨，夜里看着刺眼。

**做法**：`lib/theme.ts` 新增 `applyThemeTransitioned` —— 给 `<html>` 挂
`data-theme-transition` 180ms，让背景 / 描边 / 文字 / 填充 / 阴影在窗口内渐变，窗口过了
就摘掉。`index.css` 里对应的规则在窗口内用 `!important` 压过各组件自己的
`transition-colors`，否则一半元素快一半元素慢，看着像闪烁。

三个触发点接上：用户点击、系统外观变化（`system` 模式下）、另一个标签页改了主题。
**首屏不挂窗口** —— `applyTheme` 保持原样，首屏没有「上一个颜色」可过渡，挂上去只会让
页面加载时先淡一遍。

## 3. 长按的那半秒：进度环

游戏页有两处「按住才生效」的操作，阈值都是 500ms（`GAME_LONG_PRESS_MS`）：

| 手势 | 按住 500ms 之后 | 之前的表现 |
|---|---|---|
| 在棋格上长按 | 放上参与者头像（SPEC-J02） | 界面一动不动 |
| 在清除按钮上长按 | 清空全部放置（SPEC-G04） | 界面一动不动 |

这半秒里没有任何反馈。用户能做的只有估摸着数秒：

- 按早了 —— 抬手，什么都没发生，而且**紧接着到来的 `click` 会被当成短按**，于是又放了一个编号。
  一次「想放头像」的操作变成了「放错了一个编号」。
- 按晚了 —— 手指或手腕在等一个不知道何时结束的计时。

这不是审美问题，是**可操作性**问题：界面上没有第二处需要人盲数半秒的地方（连按钮的
`active:translate-y-px` 都是立刻的），而最短的那个临界值偏偏只能猜。

`components/common/PressRing.tsx`。从 12 点开始顺时针画，画满的那一刻动作发生。
三件事因此变得确定：**按下已被识别**（弧出现了）、**还差多久**（弧的长度）、
**现在松手会取消**（弧停下并消失）。

### 3.1 几何

| 项 | 值 | 来由 |
|---|---|---|
| 半径 | `size × 0.38` | 留一圈空隙，不贴着格线；中心 24% 的区域仍空着，不挡编号预览 |
| 线宽 | `max(2, size × 0.06)` | 9×9 格子在 1366 屏上约 70px，得 4.2px；15×15 的小格退到 2px 下限 |
| 起点 | `rotate(-90 …)` | 从正上方开始读，是钟面的直觉 |
| 端点 | `stroke-linecap: round` | 弧的头是圆的，不像被切断 |
| 总长 | `stroke-dasharray = 2πr` | 一整圈；`stroke-dashoffset` 从整条走到 0 |

地图格子上的环多画一条底轨（`trackColor`），且**比弧宽 2px**。它不只是「还剩多少」的刻度：
进度弧是白色的，没有这层深色垫底，白弧压在浅色地图（白墙、雪地）上就没了边。宽 2px
正好给出一条连续的黑边，同时不吞掉弧本身的粗细。

### 3.2 为什么是 CSS 关键帧，不是 `requestAnimationFrame` + `setState`

进度是 500ms 的连续量。用 rAF 更新 React state 意味着 60fps 的重渲染，而这个环挂在棋盘容器
里 —— 一次重渲染会带着整个图层栈走一遍（背景、物品、区域轮廓、放置层…）。

这里改成：`stroke-dasharray` 定总长，`stroke-dashoffset` 交给一条 CSS 关键帧。动画完全跑在
合成线程上，**整段长按期间 React 一次都不重渲染** —— 只有按下与抬手各一次 state 更新。

```css
.press-ring-arc {
  animation: press-ring-fill var(--press-ring-duration, 500ms) linear forwards;
}
@keyframes press-ring-fill {
  from { stroke-dashoffset: var(--press-ring-length, 0); }
  to   { stroke-dashoffset: 0; }
}
```

两个值都从组件的内联 CSS 变量来（周长、时长）。时长与页面上的 `GAME_LONG_PRESS_MS` 同源，
所以**环画满的那一帧就是动作发生的那一帧**，不需要各自维护一个魔法数。

### 3.3 为什么必须 `linear`

全站其他动效都走指数减速（`--motion-ease-out`）。这里是全套里唯一一条直线，理由不是风格：

环的长度就是**剩余等待时间**。缓动会让前段飞跑、后段拖住 —— 用户读到的时间比实际短，
于是提前松手，又回到「白按一次」。进度条用缓动不是「更顺滑」，是在说谎。

这一条写进了 `design-system.md` §1.6 的硬约定第 4 条。

### 3.4 取消即卸载，不做倒放

抬手 / 指针移出 / 手势中断时，页面把 `cell` 置空，组件随之卸载，动画自然消失。

不做「倒着画回去」的收尾：倒放会被读成「刚才那一下还算数吗」。取消的正确表达是**消失**。

### 3.5 为什么不是新图层

环压在棋盘之上，需要 z-index。但**没有**登记成第 16 层，用的是
`MAP_LAYER_Z.regionLabel + 1`（= 43）：

- 《画布图层优先级规范》§2 末段已经给临时 affordance 留了口子 —— 编辑器的拖拽 / 框选反馈
  挂在 `operationCursorBox − 1 / − 2`，明确「不属于本规范的 15 层」。
- 一个手势反馈不值得把公共契约重排：`MAP_LAYER_ORDER` 是全仓共享的类型来源，动它要改
  shared 的两个测试、规范表的两处表格、单行次序图，以及所有后续层号。

压在区域标签之上，是因为环被地图上的文字截断会读成「画错了」。

### 3.6 落定：头像不是「出现」，是「放下去」

环画满 → 头像顶上来。直接出现会读成「画面刷新了一下」，所以给 180ms 的淡入 + 轻微放大
（`scale 0.86 → 1`），读成「放下去了」—— 与按钮的 `active:translate-y-px`（按进纸里）
是同一套物理直觉。

两个实现细节：

1. **用独立的 `scale` 属性，不用 `transform`**。这个元素身上还挂着激活态的
   `transform: scale(1.3)`（v0.6.4 §3，摸名册卡片时放大该参与者的头像）。transform 关键帧
   会把整条 `transform` 覆盖掉，动画期间头像先跳回原尺寸再弹起来 —— 与 §2.1 里
   居中弹层不能用 transform 动画是同一个理由（见 §6.3）。
2. **只给「刚刚放下」的那一格**。`settleKey` 由 `pressCell` 推出：环还在（抬手前）就说明
   这一格是刚放的，抬手即清，窗口自然结束，不必再记时间戳。

为什么不给所有头像都挂入场动画：进页面时棋盘是从本地存档恢复的，十几个头像同时弹一下，
会读成「刚刚发生了一连串操作」。只有这一格是真的刚放下的。

### 3.7 两处长按，画同一圈环

清除按钮的长按也接上了同一个 `PressRing`（40px、`primary` 色、无底轨）。

它们是同一个手势，就该在界面上只有一种样子 —— 用户在格子上学会了「圈满才生效」，走到
工具栏不需要重新学一遍。按钮上的环不画底轨：纯色背景上弧本来就清楚，再加一圈是噪音。

### 3.8 环是一句承诺：`dispatchCell` 开始返回结果

承诺做不到的时候，不能留着满环 —— 那读起来像「已经放好了」。

原先 `dispatchCell` 是 `void`，`placementBlockReason` 拒绝时只弹一个 toast。现在返回
`boolean`（是否真的执行），长按的定时器回调据此决定收不收环：

```ts
press.timer = window.setTimeout(() => {
  press.fired = true;
  if (!dispatchCell(x, y, 'image')) setPressCell(null);   // 被拒：环立刻收回
}, GAME_LONG_PRESS_MS);
```

现有调用方（`onClick` 里的短按）忽略返回值，行为不变。

## 4. 退掉一圈多余的框（地图头像）

地图上激活参与者（名册悬停 / 点击的那一个）的头像，去掉那圈
`box-shadow: 0 0 0 2px hsl(var(--primary))`。**只留放大。**

> 与 §3 的环无关：那圈是手势的时间刻度，这圈只是高亮描边。

v0.6.4 §3 给「触碰参与者 → 在地图上认出他」加了两个信号：头像 `scale(1.3)` 放大，
外加一圈 2px 的主色环。当时两者是同一份设计里的两条腿：放大负责「动」，环负责「说清楚是谁」。
现在只剩前者，理由是三条。

### 4.1 圆框套在方头像上

环画在包裹层上：`inset: 0` 铺满整格 + `borderRadius: 50%` + `0 0 0 2px`。方框加
50% 圆角，描出来是一个**内切于格子的圆**。

而里面真正的头像有两种：

| 头像来源 | 渲染 | 形状 |
|---|---|---|
| 纯色块（`character.bgColor`） | `rounded-full` + `backgroundClip: content-box` | 圆形，但被 `padding` 内缩 |
| 上传图片 | `objectFit: cover`，无圆角 | **方形**，同样 `padding` 内缩 |

于是圆环和内容在两种情况下都不贴合：对色块，环比色块大一圈（色块被 padding 缩进去了）；
对上传图片，环是一个圆、图是一个方，环从图的四角外侧切过去。它不像「描边」，像一块
另贴上去的形状。

### 4.2 它是棋盘上唯一不用主题色的东西

棋盘里其余所有属于某个参与者的东西都走**主题色**：格子里的编号字形、名册卡片、
名册里的徽章。只有这圈环是固定的 `--primary`。

在一个 9×9 或 15×15 的格子上，2px 环 + `borderRadius: 50%` 让头像的可见占位向外鼓出
4px，很容易先被读成「这一格的边框」或「这个人的背景框」，而不是「这个人是当前那位」——
格子本身已经有边线，多一个同尺寸的框只会和格线打架。

### 4.3 放大已经够了，而且它自带对照组

`scale(1.3)` 不是孤立出现的：同格子里别人的编号字形保持原尺寸（`GAME_ACTIVE_PARTICIPANT_NUMBER_SCALE`
只作用于激活者自己的字形），旁边的人都静止 —— 有静止的邻格在，1.3 倍的动静读得出来。
环加在这个基础上是**重复表达**，不是补充信息。

```diff
  transform:
    placement.index === activeParticipantId
      ? `scale(${GAME_ACTIVE_PARTICIPANT_AVATAR_SCALE})`
      : undefined,
  transformOrigin: 'center',
  transition: 'transform var(--motion-fast) var(--motion-ease-out)',
- borderRadius: '50%',
- boxShadow:
-   placement.index === activeParticipantId
-     ? '0 0 0 2px hsl(var(--primary))'
-     : undefined,
```

`borderRadius: '50%'` 一并删掉：它不是为了头像的形状（色块自己带 `rounded-full`，
图片是方的），只是为了给那圈 `box-shadow` 定形。留着它等于在代码里留一句
「这个盒子本该是圆的」的谎话。`transform` + 120ms 过渡（`--motion-fast`）不动。

### 4.4 没动的同类环

`components/map-editor/ParticipantPanel.tsx` 的 `isActive` 分支有一模一样的
`0 0 0 2px hsl(var(--primary))`，**保持原样**。那里的环画在参与者**矩形卡片**的边框上
（FIX-E04：一张卡只画一个框，高亮优先、其次激活），它就是这个卡的边框本身，不存在
「圆框套方图」的问题，也不跟卡片里的主题色抢 —— 卡片的主题色画在头像和徽章上，
不在边框上。名册卡片和地图头像是两个不同的东西，一个框有意义，另一个没有。

## 5. 减少动态（此前完全没有）

全仓此前**一条 `prefers-reduced-motion` 都没有** —— 系统里开着「减少动态效果」的用户，
进这个工坊照样会被抽屉滑动、对话框淡入、卡片缩放推一遍。前庭功能障碍影响约三分之一
的中年以上人群，这不是可选项。

规则是把时长压到接近 0，**而不是 `display: none`**：状态变化本身不能取消（点了没反应
更糟），只是不再「演」。

**四类必须保留**（在媒体查询里显式重新打开）：

| 保留项 | 为什么 |
|---|---|
| `.animate-spin`（放慢到 1.4s） | 「还在等」不能用静止表达，静止等于卡死 |
| `.animate-pulse`（放慢到 2.4s） | 骨架屏同上 |
| `.highlight-fade`（保持 1s） | 纯透明度、零位移，是「匹配在哪」的唯一信号 |
| `.press-ring-arc`（保持原速） | 弧长就是「还要按多久」，压到 0.01ms 会让它瞬间画满，用户以为按一下就够了 —— 这个手势等于废掉（§3.3） |

反过来，`.place-settle`（§3.6）**照常被压掉**：它是纯装饰，压掉之后头像直接出现在该在的
位置，功能一点不缺。

还有一处特异性陷阱：主题过渡那条规则带属性选择器，特异性高于 `*`，同为 `!important`
时它会赢 —— 于是「减少动态」的用户反而会看到 180ms 的整站渐变。媒体查询里显式压掉。

## 6. 静默失败（坑）

### 6.1 `duration-*` 压不动 `animate-in`

第一版给 `Dialog` 写的是 `duration-base` + `animate-in fade-in-0`，构建通过、类都在，
**但没有生效**。原因：tailwindcss-animate 把 `animation-duration` 一起写进了变体选择器，
而 `.data-\[state\=open\]\:animate-in[data-state=open]` 的特异性是 **0,2,0**，
`.duration-base` 是 0,1,0 —— 永远压不过。

这和 v0.7.9 的 `shadow-[var(--x)]` 是同一类坑：**类存在、产物里查得到、页面上没效果**。
所以弹层改用自己的一对关键帧：

```css
.sheet-fade[data-state='open']  { animation: sheet-in  var(--motion-base) var(--motion-ease-out); }
.sheet-fade[data-state='closed']{ animation: sheet-out calc(var(--motion-base) * .75) var(--motion-ease-in) forwards; }
```

顺带拿到插件给不了的一件事：**退场 135ms、入场 180ms**（规范建议退场约为入场的 75%）。

### 6.2 主题窗口用属性，不用类

`<html>` 的 `class` 只有 `dark` 一个语义 —— `index.html` 的内联脚本靠它上色，
`theme.test.ts` 也钉着「`className` 只可能是 `dark` / 空」。往里面塞一个临时类，等于让
一个瞬时状态混进那份契约。改用 `data-theme-transition` 属性，测试一行都不用改。

### 6.3 同一个坑的另一面：`transform` 整条被覆盖

关键帧里的 `transform` 不是「叠加」，是**替换**。仓库里踩了两次：

| 位置 | 元素身上原本的 transform | 后果 | 解法 |
|---|---|---|---|
| 居中弹层（§2.1） | `-translate-x-1/2 -translate-y-1/2` | 动画期间面板偏出中心半屏，结束后跳回 | **只动透明度**，不加位移与缩放 |
| 落定头像（§3.6） | `scale(1.3)`（激活态） | 头像先缩回原尺寸再弹起来 | 改用独立的 `scale` 属性（CSS 属性，与 `transform` 互不覆盖） |

判断方式很简单：**给一个已经有 transform 的元素加动画前，先看它身上那条 `transform` 是谁写的。**
如果不是动画自己写的，就换一个不同名的 CSS 属性（`scale` / `translate` / `rotate`），
或者只做 `opacity`。

## 7. 看过没做

### 7.1 页面入场动画（明确不做）

`animate` 技能的建议清单里有「页面加载编排、交错显现、滚动触发」。这一轮全部没做，
因为原则 6 写的是「动效服务状态，不服务气氛 —— 不加滚动视差、不加无意义的入场动画」。
补充两条具体理由：

- 单次会话以十分钟到一小时计，**同一页一天要进几十次**。入场动画第一次看是惊喜，
  第二十次是延迟。
- 比装饰更值得花的力气在别处：等真的做「慢」了再来加。

### 7.2 画布内 `font-size` 过渡（保留）

`MapOverlayLayers` 的区域标签悬停时会改 `font-size`（120ms），这是**布局属性**，
按通用规范应该改成 `transform: scale()`。没改：区域标签的字号与描边是**作者的作品**，
换成缩放会把 `-webkit-text-stroke` 一起放大，等于悄悄改了作者设定的观感。节点数在几十个
量级，重排代价可接受。**这条写在这里，是为了让它是一个决定，而不是一个疏漏。**

### 7.3 骨架屏 → 内容的交叉淡入（不做）

需要两块同时挂载 + 交接透明度，会引入布局跳动与额外的挂载状态；而骨架本身的
`animate-pulse` 已经表达了「还在取」。列表页另有 `placeholderData: previous`
（地图 / 谜题 / 游戏）兜住换页与搜索，不会闪。

### 7.4 四个列表页没有「重新取数时变淡」

`MapsPage` / `PuzzlesPage` 在 `isFetching && !isLoading` 时把内容压到 `opacity-60`，
而 `AssetsPage` / `CharactersPage` / `DeploymentsPage` / `GamesPage` 没有这个反馈。
这属于**状态反馈不统一**，归一致性（v0.7.9 §1 那条线）而不是这一轮 —— 两者混在一起做，
会让这次的 diff 说不清是「动效」还是「反馈」。

### 7.5 `blink` / `glow` 关键帧仍无调用点

留给 shared `EFFECT_TYPES` 的联动效果（闪现 / 呼吸），见 §1.2。

### 7.6 游戏页其余操作（逐项看过）

| 位置 | 想法 | 为什么没做 |
|---|---|---|
| 短按放编号 | 编号出现时淡入 / 弹一下 | 连续点几个格子是常态（「打字」式输入），动画互相打断会拖成慢动作。编号是即时反馈，快就是它的价值 |
| 撤销 / 重做 | 棋盘变化做过渡 | 撤销的对象是任意一格，没有稳定的「靶子」可动画。真要做好得先记录每一步的 diff，属于渲染架构改动，不是动效 |
| 提交 | 按钮 Send → Check 的切换 | `active:translate-y-px` 已经是按下反馈，再叠一层图标切换属于「庆祝」，与原则 6 的取向不符 |
| 悬停格子 | 工具提示层的出现 | 提示跟着指针走，跟着动会变成拖影 |
| 缩放 | 给 zoom 加过渡 | 拖拽与 Ctrl+滚轮是连续手势，过渡会让画面「追」指针，手感变糊 |
| 游戏页的其余操作 | — | 其余都是「点一下立刻生效」，不缺过程信息；缺过的只有长按那半秒 |

### 7.7 两处已知边界（记成债）

**触摸设备上的系统长按菜单**：棋盘容器没有拦 `contextmenu`。移动端 Safari / Chrome 在按住
图片或文字约 500ms 后会弹自己的菜单，与这里的阈值撞在同一段时间上 —— 菜单一弹，环就断了
（`design-system.md` 债务 5.14）。这一轮没有顺手 `preventDefault`：画布上的右键在当前契约里
没被占用，但「要不要禁掉右键菜单」是一个新的交互决定，不该夹在动效改动里做。桌面端
（本工具的主场景）不受影响。

**键盘完全无法操作棋盘**：这一页的 `keydown` 只处理 Escape（退出当前模式）与空格（平移）。
放编号、放头像、放禁止符号、清除，全都只由指针触发 —— 长按尤其如此，没有键盘等价物。
环解决的是「过程不可见」，不是「入口不可达」；后者是一整条无障碍债（`design-system.md`
债务 5.13），需要给棋盘做可聚焦的格子网格与键盘导航，比动效大得多。

## 10. 玩家端的纸背光（overdrive）

游戏列表页是全站唯一**对外**的页面（玩家从链接进来，看不到工坊）。它的卡片此前也是
三张网格卡里最静的一张：地图卡悬停换边框色 + 封面缩回，谜题卡同上，而游戏卡只有一档阴影。

这一节给游戏卡补上悬停的动作，尺度按「玩家停留几十秒」定 —— 制作端那套「坐一小时不累」
的克制在这里可以松一档，但**没有**松到发光、粒子、3D 倾斜。

这一节写过五版。第一版（§10.2）被用户判为「确实太轻了」，第二版（§10.3 起）推翻重做：

> 「确实太轻了，再大胆一点，添加动效，标题下的线可以不用（效果不好）」

第三版（§10.7）撤掉了第二版加的两个位移 —— 光留着，几何退回原地。第四版（§10.9）按
「加回图片缩放、遮罩改成圆形展开」再改一次：几何只留封面这一处，光的边界从方变圆。
第五版（§10.10）把光圈从 260ms 拉到 480ms、又拉到 700ms，并换掉曲线 —— 慢下来，同时让
中段真的有事发生。第六版（§10.11）补上指针离开时的「收回」：光不是淡出，是缩回光心。

### 10.1 悬停时发生的事

| 动作 | 时长 / 曲线 | 为什么是这个量 |
|---|---|---|
| 封面**推进 10%** | `--motion-image` 360ms · `ease-in-out` | 第四版加回来的。卡片本身仍然不位移 —— 一个手势里只留一个几何动作（§10.7 的教训），所以指针扫过边缘时不会再「往上抬 + 往外胀」 |
| 光**从指针处开出来** | 光圈半径 `--motion-glow` **700ms** · `ease-spread`；淡入 120ms | 半径从 46.7% 长到 146%，圆的边界从光心向外推。淡入比张开快，所以看到的是「已经亮起来、还在漫开」，不是「先透明再长大」。第五版把 260ms 一路拉到 700ms 并换了曲线，理由见 §10.10 |
| 指针**离开时收回** | 光圈半径 + 圆形取景框同步收 `--motion-retract` **340ms** · `ease-retract`；`opacity` 冻到最后一刻才落 | 光池收紧是「看得见」的那件事，取景框收掉的是泛起来的外圈。退出比进入短一半：铺开可以从容，撤走不能让人等（§10.11） |
| 光**跟随指针** | 位置无过渡（跟手） | 跟手才像一束光；加过渡光标一动光就要「追」 |
| 描边转 `primary/30`、阴影换 `--shadow-float` | `--motion-base` 180ms · `ease-out` | 只有颜色和影子在变，卡片不离开纸面，也不追着指针跑 |
| `n×n` 转前景色 | `--motion-base` 180ms | 卡片「醒过来」的下半句：视线从封面落回信息区时，那里也有东西刚变过 |

**删掉的：标题下那根墨线。** 第一版用 `scale-x` 从左侧划出一条 `h-px` 主色线，用户的
评价是「效果不好」。回头看它有两个问题：一是它和光说同一件事（「你在看这一张」），却是
另一种语言（几何线条 vs 光照），并在视觉上把那行标题「压」住了；二是 1px 的线在 300px
宽的卡上只有 30px 长的一段是可见的，剩下全糊在文字底下。**一个手势只留一套说法。**

### 10.2 第一版为什么太轻（算术，不是口味）

第一版的配方是 `soft-light` + 纯白 35%、半径 200px。它「几乎看不见」不是参数没调够，
而是**撞到了混合模式的天花板**：

W3C 的 `soft-light` 在光源侧（`Cs > 0.5`）的定义是
`B = Cb + (2Cs - 1) × (sqrt(Cb) - Cb)`。取 `Cs = 1`（纯白、不透明度拉满）：
`B = sqrt(Cb)`。奶油色地图封面 `Cb ≈ 0.93`，所以 `B = 0.964` —— **最多只能抬 3.4 个色阶**，
无论怎么加不透明度。实测剖面里那几个 `+2.1`、`+1.9` 正是这个数。

结论：**在 93% 亮的纸上，任何「只加光」的方案都到不了「看得见」。**

第一版还试过这些，全部证伪：

| 配方 | 结果 |
|---|---|
| `soft-light` + 主色（石青） | **不可见**。日间主色是 L36% 的深青，拿去「提亮」实测差 0 个色阶 |
| `screen` + 主色 | 奶油色封面上变成一块**青斑** —— 染色，不是照光 |
| `screen` + 暖白 | 亮底上只抬 **3 个色阶**（`screen` 的增量与底色的剩余空间成正比） |
| 纸雾挖空（纸色径向渐变从中心挖洞） | 整张封面**褪色发灰**，红色斜带被洗成粉色 |

### 10.3 定稿：一减一加

想让纸上出现一盏灯，唯一的办法是**把灯照不到的地方压下去** —— 对比度，不是亮度。
所以重心从「光」挪到「影」，两层各自负责一半：

| 层 | 混合 | 渐变 | 职责 |
|---|---|---|---|
| `.paper-shade` | `multiply` | `146% 146% at 光心`，`transparent 18%` → `hsl(26 46% 25% / .72)` | 暖色暗角。**「看得见」主要靠这一层** |
| `.paper-core` | `normal` | `150px circle`，`hsl(42 100% 95% / .42)` → 透明 | 近白热斑。在光心点一下，给眼睛一个落点 |

```css
.paper-shade {
  background-image: radial-gradient(
    146% 146% at var(--glow-x, 50%) var(--glow-y, 50%),
    transparent 18%,
    hsl(26 46% 25% / 0.72)
  );
  mix-blend-mode: multiply;
}
.paper-core {
  background-image: radial-gradient(
    150px circle at var(--glow-x, 50%) var(--glow-y, 50%),
    hsl(42 100% 95% / 0.42),
    transparent 100%
  );
}
```

两个颜色都不是随手取的：

- **减光用暖褐（`26 46% 25%`）而不是纯黑。** 纯黑乘上去是「去色」，封面会发灰；暖褐乘上去
  像纸落在自家影子里 —— 阴影也该有纸的温度。
- **加光用近白偏暖（`42 100% 95%`），不偏青。** 偏青会把米黄的纸染成一块蓝。
- 这两个是**光照的两端**，不是配色，与 `--shadow-card` 里那几条 `hsl(28 30% 20% / 0.04)`
  同性质。换成任何主题 token 都会让方向随主题反转：夜间 `--background` 是墨色，
  「加光」会变成「加阴影」。

**这一版也试过、并删掉的：一层大光晕（`soft-light` 暖白，半径 440px → 225px）。**
它在 300px 见方的封面上覆盖了整张，等于把整张纸均匀抬亮：结果是**封面发灰、红色斜带褪成
粉色**，「一束光」的形状反而更糊。`.paper-core` 保留了「加光」这一半，但它半径只有 150px，
是一个点，不是一层纱。

**暗角强度扫过三档**（0.56 / 0.66 / 0.72，同一张封面连续截图比对）：0.56 在浅色封面上
仍然偏轻，0.76 开始把四角压出「脏」的灰边，0.72 是最后一档还读成「影子」的。

### 10.4 光从指针处「开」出来

第一版的光是淡入的。这一版让它在淡入的同时**从小到大张开**：`scale(0.62) → 1`，
`transform-origin` 就设在光心。

为什么这样成立：梯度中心与缩放的轴心是**同一个点**（都取 `--glow-x / --glow-y`），
所以缩放时那个点的位置不动，动的只有它周围的半径 —— 看起来是光在漫开，而不是整层纸在
缩放。如果轴心留在正中（默认值），光心会随着缩放朝卡片中心滑动，那就成了「镜头推近」。

`transform-origin: var(--glow-x, 50%) var(--glow-y, 50%)` 里的变量是 `px` 值，直接可用；
`50%` 只是还没拿到指针坐标时的兜底。

### 10.5 坐标走 CSS 变量，不走 state

`--glow-x / --glow-y` 由 `onPointerMove` 直接写到封面元素上。指针每秒移动几十次，若每次
`setState`，这张卡上的封面图、徽章、标题、尺寸要全部重新 reconcile 一遍，换来的只是
光斑动了；写 CSS 变量只让合成层重绘，**整段悬停期间 React 一次都不渲染**。

rect 每次移动都重读一次，不做「进入时缓存」：读之前没有写样式或改 DOM，布局是干净的，
这次读不触发重排；而缓存要在滚动、缩放、窗口变化、换页时各自失效一次，边界比省下的
开销贵。

`mix-blend-mode` 要落在一个独立的混合组里 —— 封面容器加了 `isolate`，否则 `multiply`
会一直乘到页面底色上，卡片浮在米色页面上和在白色对话框里会长得不一样。

### 10.6 减少动态：钉在正中，缩回原尺寸，但不删光

跟随指针是运动，张开也是运动，两样都收掉：媒体查询里 `--glow-x / --glow-y` 被钉成
`50% 50%`（在光层自己身上重新声明 + `!important`，声明值胜过继承值，不必去动那行 JS），
`transform: none` 把张开压掉。

**但没有把光去掉** —— 一张有光的静止封面正是这张卡悬停时唯一的气质，删掉就只剩一档
阴影。静态替代，不是减法。

### 10.7 第三版：撤掉两个位移

第二版定稿后，用户的判断是：

> 「游戏卡不要有跳起和图片缩放两种动效，看起来很晃」

两处位移（卡片 `-translate-y-1`、封面 `scale-[1.1]`）和徽章的 1px 上浮全删。它们不是
调狠了，而是**方向撞车**：指针扫过卡片边缘时两者同时起、同时收，卡片往上抬、封面往外
胀，同一块像素被两股相反的位移拉扯 —— 眼睛读到的是「抖」，不是「活」。而「你在看这一
张」这件事，光已经在说了；**同一拍里两个几何动作是重复表态，还互相拆台。**

删掉之后悬停只剩「颜色 + 影子 + 光」，**容器没有任何位移**：实测悬停前后卡片与封面
容器的 `getBoundingClientRect()` 四项全等、`transform` 都是 `none`。
（第四版把缩放还给封面里那张 `img` 本身，容器仍然不动 —— 所以这条结论按「容器」量，
不按图量。）
这条比「删得对不对」更值得钉住 —— 以后再想加回位移，先看看它是不是又想和光抢着说话。

> 顺带一句：`hover:shadow-lifted` 本身会让人「感觉」卡片浮起来，那是影子的语言，
> 和位移不冲突，所以留着。

**同一条消息里还报了另一个 bug：「难度的背景色没有了」。** 根因不在卡片，在
`shared/constants.ts`：v0.7.8 把 5 个 hex 换成 `var(--difficulty-*-bg)`，但 `index.css`
里存的是 HSL **三元组**（`26 62% 91%`，与 `--background` 等所有 token 同一约定）。内联
`background-color: var(--difficulty-hard-bg)` 展开成 `background-color: 26 62% 91%` ——
不是合法颜色值，浏览器**整条丢弃**，于是徽章只剩文字。修法是在常量里补上 `hsl(...)`，
而不是把变量改成完整颜色值：三元组是给 `hsl(var(--x) / <alpha>)` 复用的，改了会断掉
约定。**同一处错误同时存在于部署列表行和部署对话框的难度按钮上**，改常量这三处一起好。

### 10.8 没做

| 想法 | 为什么没做 |
|---|---|
| 地图 / 谜题卡也加跟随光 | 那是制作端，一次编图几十分钟，四张封面各自跟着光标跑会持续抢注意力。那两张卡已有「边框转主色 + 封面缩回」的语言，够用 |
| 3D 倾斜（`perspective` + 最大 3°） | 网格里四张卡各自倾斜时，整片区域一直在晃，玩家扫视时找不到稳定参照 |
| 光斑外再加光晕 / 发光 | 这一版试过，见 §10.3 结尾：一层大光晕把整张封面抬灰、把红带洗粉。要「更亮」只能加对比，不能加纱 |
| 标题下的墨线（第一版有） | 用户看过实物后判定「效果不好」，删掉。理由见 §10.1 |
| 悬停时播放封面动图 / 视频 | 一次四张同时动，比静止封面更耗电也更吵 |

### 10.9 第四版：加回封面推进，暗角改成圆形展开

> 「加回图片缩放。图片增加阴影遮罩时，不要方形展开，可以改成圆形展开」

**封面推进回来**，卡片抬起仍然不回。理由和第三版同一条：两个几何动作撞在同一拍上才
晃，一个不晃。所以 `GameCard` 的卡片 class 里 `-translate-y` 永远不许再出现，缩放留给
封面 —— 这条写成了用例（`封面推进，卡片不动`），钉的是组合不是单个类名。

**暗角为什么之前是方的。** 光层是 `inset: 0` 的绝对定位 div，早期用
`transform: scale(0.62) → 1` 让它「张开」。问题是缩放缩的是**这一层的矩形**，而
`radial-gradient(146% 146% at …)` 在这个矩形边界上还没走完 —— 边界处颜色突然断掉，
于是张开过程中出现一块**带直角硬边的方纸**，从光心往外推（并排截了四个进度，A 列
60/140/260ms 都能看到那条直边）。

四种改法里选的是**缩半径**，不是缩元素：

| 改法 | 结果 |
|---|---|
| 给层加 `border-radius: 50%` 再缩 | 圈是圆了，但终态四角吃不到暗角（圆内切于封面），取景被改掉 |
| 层做成远超封面的圆、缩它 | 圆的外沿会扫过封面，出现一圈**硬边暗环**，像涟漪不像光 |
| 只淡入不张开 | 最省事，但「光从指针处漫开」这件事没了 |
| **缩 gradient 的半径** | 任意时刻的光都是一张平滑的径向场，边界从方变圆；`--glow-r: 1` 时半径仍是 146%，**终态与上一版逐像素一致** |

半径要能补间，就得让 `--glow-r` 成为一个**数值**而不是一串 token：自定义属性默认不
参与插值，`transition` 写了也等于瞬跳。于是用 `@property` 把它注册成 `<number>`
（必须声明在顶层，进 `@layer` 在部分引擎里不生效），初值 0.32，悬停到 1：

```css
@property --glow-r { syntax: '<number>'; inherits: false; initial-value: 0.32; }

.paper-shade {
  background-image: radial-gradient(
    ellipse calc(var(--glow-r) * 146%) calc(var(--glow-r) * 146%)
      at var(--glow-x, 50%) var(--glow-y, 50%),
    transparent 18%, hsl(26 46% 25% / 0.72));
  mix-blend-mode: multiply;
}
```

封面是正方形容器，椭圆两支相等的百分数就是**正圆**（`circle` 不接受百分数，这是
唯一能在不知道元素尺寸的前提下写「圆」的形式）。热斑同步用同一个变量：
`circle calc(var(--glow-r) * 150px)` —— 46px 的小点到 150px，两层一颗心。

> 代价：`background-image` 每帧重绘，不像 `transform` 走合成层。480ms、一张卡、悬停
> 时一次，实测没有掉帧；换成列表里几十张卡同时动画才需要另想办法。

`prefers-reduced-motion` 那条跟着改：不再 `transform: none`（已经没有 transform），
改成 `--glow-r: 1 !important` + `transition-property: opacity` —— 光圈一步到位，只留淡入。

### 10.10 第五版：光圈慢下来（一半是时长，一半是曲线）

> 「圆形展开可以慢一点」

只把 260ms 调大是不够的。原来的曲线是 `--motion-ease-out` = `cubic-bezier(0.22, 1, 0.36, 1)`，
控制点几乎垂直冲天：**15% 处已经走完 55%，30% 处 83%**。260ms 的光圈在 100ms 内就看起来
已经铺满，剩下 160ms 只有像素级的余量。也就是说观众看到的从来不是 260ms，是「啪地一下」；
把时长翻倍但曲线不改，得到的只是「啪」得慢一点，中段仍然是空的。

所以这一次同时换了两样：

| | 旧 | 新 |
|---|---|---|
| 时长 | `--motion-slow` 260ms | `--motion-glow` **700ms** |
| 曲线 | `--motion-ease-out` `(0.22, 1, 0.36, 1)` | `--motion-ease-spread` `(0.33, 0, 0.25, 1)` |

实测 `--glow-r` 的插值（`getComputedStyle` 逐帧采样，700ms 一次悬停）：

| 时刻 | 旧（260ms + ease-out） | 新（700ms + spread，实测） |
|---|---|---|
| 70ms | 0.85 | **0.33** |
| 140ms | 0.98 | **0.43** |
| 210ms | 1.00 | **0.57** |
| 280ms | 1.00 | **0.71** |
| 350ms | 1.00 | **0.82** |
| 490ms | 1.00 | 0.95 |
| 700ms | 1.00 | 1.00 |

旧曲线在 210ms 之后就没有内容了；新曲线到 350ms 才走完一半，光铺开这件事第一次能被眼睛
跟住。之后又从 480ms 提到 700ms —— 光铺得比界面慢，是这张卡唯一的「非控件」气质。

**慢起手为什么不像卡顿。** 光层有两条平行的轨：不透明度 120ms（`--motion-fast`）、半径
700ms（`--motion-glow`）。指针一进封面，灯先亮起来（70ms 时 0.93）；半径再从光心往外铺。
观众读到的是「灯已经开了，光还在往外走」—— 正是 §10.4 想要的顺序。如果两条轨都慢，才会
显得没反应。

**`--motion-glow` 是第五档时长**，也是全仓第二档「按用途命名」的（第一档是 `image`）。
前四档量的都是界面如何响应你，它量的是一次物理扩散。`--motion-ease-spread` 同样只在
这一处用：起手匀、中段快、收尾长，专门给「从一点摊开成一整片」用。

退出方向不共用这一档（§10.11）：铺开可以拖到 700ms，收回超过半秒就像页面卡住了。

### 10.11 第六版：离开时把光收回去

> 「同时添加鼠标离开时遮罩收回的效果」

原来离开只是 `opacity` 120ms 淡出 —— 光「没了」，但没有「被收走」。要做成收回，得让光圈
在消失之前先缩一段，所以退出的时长、曲线和进入彻底分开（CSS 的过渡用「变化之后」那一侧的
声明，基线规则管离开、`:hover` 那条管进入，天然可以两套）。

**试过的三条路：**

| 做法 | 结果 |
|---|---|
| 只把半径缩回去（`--glow-r` 1 → 0.32） | 圆的边界确实往回退了，但 `--glow-r` 越小、暗角铺得越满：四角的暗度从 15% 一路涨到 46%，光池收紧的同时整张封面在变暗，读成眨眼 |
| 只加圆形遮罩、半径冻住 | 遮罩先切掉的正是外圈，而外圈是暗角最深的地方，看起来只是「影子从边上淡掉」，A/B 同帧对照过，几乎看不出在动 |
| **两个一起**（定稿） | 半径负责把光池收紧（看得见的那件事），遮罩负责把泛起来的外圈裁掉（别让封面整体变暗） |

实测（340ms，逐帧采样）：两条轨同时衰减，opacity 全程保持 1 到最后一刻才落。

| 时刻 | `--glow-r` | `--glow-w` |
|---|---|---|
| 40ms | 0.987 | 0.980 |
| 85ms | 0.919 | 0.881 |
| 130ms | 0.803 | 0.711 |
| 170ms | 0.709 | 0.571 |
| 215ms | 0.555 | 0.345 |
| 255ms | 0.459 | 0.204 |
| 300ms | 0.351 | 0.046 |
| 340ms | 0.321 | 0.001 |

**遮罩半径不能写死。** 它得正好等于「指针到最远那个角」的距离：指针在正中时约 0.71 倍
边长，贴着角时 1.41 倍。给小了，静止悬停时最远那个角落进羽化区，暗角被打薄（实测差 67/255，
肉眼能看出四角发亮）；给大了，收回的前半段在封面之外空转，看起来没反应。所以这个值由
`GameCard` 在每次 `pointermove` 里算（连同 72px 的羽化一起写进 `--glow-reach` /
`--glow-feather`），CSS 只负责按 `--glow-w` 缩放。

羽化是定宽的：`#000 calc(100% - var(--glow-feather))`。写成百分比的话，窗口越小边缘越硬，
收到最后会变成一圈刀切。之所以不用更省事的 `clip-path: circle()`，也是因为它没有羽化 ——
收的过程中会露出一圈清清楚楚的圆弧，那是「擦除」，不是「光收回去」。

**`opacity` 用「1ms 时长 + 340ms 延迟」拖到最后再落**：不然光还没收完就淡没了，收回等于
白做。落的那一刻窗口已经关到 0，画面里没东西，所以这一步看不见。

**`--glow-r` 必须显式写进退出过渡**，虽然它的目标值和基线一样是 0.32。`:hover` 一撤，
浏览器会立刻把它弹回 0.32；不给它一条过渡，收回还没开始暗角就已经收紧一圈（这就是上表
第一行「像眨眼」的来源）。它和 `opacity` 一样，是**先冻住、最后一刻才落**的角色。

**减少动态那条规则里新增了 `--glow-w: 1 !important`**：基线里它是 0（收回之后的状态），
漏了它，开了「减少动态」的用户永远看不到这张卡的悬停光 —— 遮罩一直关着，而且不会报错。
