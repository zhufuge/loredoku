## 1. 修复

### FIX-C01 区域高亮线渲染为斜线

**现象**

区域激活时，高亮线本应沿区域边界线内侧绘制水平 / 垂直线，实际渲染出斜线：

```html
<line x1="106.25" y1="310.25" x2="199.75" y2="306"
      stroke="#90CAF9" stroke-width="3.4" stroke-opacity="0.9"
      stroke-linecap="round"></line>
```

- `y1 = 310.25`、`y2 = 306`，两端 y 坐标不相等 → 斜线；
- `x1 = 106.25`、`x2 = 199.75`，两端 x 坐标也不相等。

**根因分析**

`MapLayers.RegionInnerBorder` 对每条边的偏移实现为：

```ts
x1 = edge.x1 + inset                                   // 无条件加，错
y1 = edge.y1 + inset                                   // 无条件加，错
x2 = edge.x2 - (edge.x2 !== edge.x1 ? inset : 0)
y2 = edge.y2 - (edge.y2 !== edge.y1 ? inset : 0)
```

**固定轴（两端相等的那一维）只在一端被平移了 `inset`，另一端没动**，于是每条边都获得斜率
`inset / 边长`。

复现（`cellSize = 102` → `scale = 0.85` → `inset = 6×0.85/2 + 4×0.85/2 = 4.25`，区域取 `[[2,2],[3,2]]`）：

```
{"x1":208.25,"y1":208.25,"x2":204,   "y2":301.75} !! 斜线 !!
{"x1":208.25,"y1":208.25,"x2":301.75,"y2":204}    !! 斜线 !!
{"x1":208.25,"y1":310.25,"x2":301.75,"y2":306}    !! 斜线 !!
{"x1":412.25,"y1":208.25,"x2":408,   "y2":301.75} !! 斜线 !!
{"x1":310.25,"y1":208.25,"x2":403.75,"y2":204}    !! 斜线 !!
{"x1":310.25,"y1":310.25,"x2":403.75,"y2":306}    !! 斜线 !!
```

第三条 `(208.25, 310.25) → (301.75, 306)` 与「现象」给出的 `<line>` **同形**（x 相差 102 = 一格）。

> 说明：与「端点小数未取整」「方向向量 / 法向量用错」「`linecap` 圆角」「区域凹凸」均无关——
> 相邻边共享的端点本来就是完全相同的小数，量化到 0.5px 只会把「4.25px 的斜」变成「4px 的斜」。

**修复要求**

1. **内缩算法重构** —— 对区域外轮廓的每条边，拆成「法向平移」+「切向收缩」两步：

   | 边朝向 | 法向（两端取同一值） | 切向（两端各缩 `d`） |
   |---|---|---|
   | 上边（`!has(x, y-1)`） | `y1 = y2 = y + d` | `x1 = x + d`、`x2 = x + size - d` |
   | 下边（`!has(x, y+1)`） | `y1 = y2 = y + size - d` | 同上 |
   | 左边（`!has(x-1, y)`） | `x1 = x2 = x + d` | `y1 = y + d`、`y2 = y + size - d` |
   | 右边（`!has(x+1, y)`） | `x1 = x2 = x + size - d` | 同上 |

   - 其中 `d` 为内缩距离 = **区域边界线宽的一半 + 高亮线宽的一半**（即紧贴区域边界线内侧、向内扩展）；
   - 法向方向由 `buildRegionEdges` 已有的 `has()` 判断直接决定（朝区域内侧），不需要另算法向量；
   - 切向两端各缩 `d`，保证拐角处相邻边相接而不外溢；
   - 任何情况下不允许两端坐标都不相等。

2. **线段生成复用**
   - 复用区域边界线的 `buildRegionEdges` 输出的线段，按上述规则内缩；
   - 内缩逻辑抽成**纯函数** `buildRegionInnerEdges(cells, size, inset)`（放在 `lib/region.ts`），
     组件只负责渲染，便于单测。

3. **线段类型调整**
   - `stroke-linecap` 由 `round` 改为 `square`，与区域边界线保持一致，拐角无缝、无圆角溢出。

4. **断言与测试**
   - 单元测试对每条生成的线段断言 `x1 === x2` 或 `y1 === y2`；
   - 覆盖单格、矩形、L 形（凹）、十字形（多连通）等区域形态。

**验收**
- 区域高亮线为严格水平或垂直；
- 任一 `<line>` 要么 `x1 === x2`，要么 `y1 === y2`；
- 相邻线段拐角无缺口、无错位；
- 非矩形区域沿实际边界正确内缩。

## 2. 优化

### OPT-C01 地图自适应再增加 24px 外边距

**变更**

v0.3.6 的可用高度计算为：

```
availableH = 编辑器高度 - 底部工具条留白 72px - 顶部标尺 28px - 内边距 32px
```

v0.3.7 在**四边各**再增加 `EXTRA_MARGIN = 24px`：

```
availableH = 编辑器高度 - 底部工具条留白 72px - 顶部标尺 28px - 内边距 32px - 24px × 2
availableW = 编辑器宽度 - 左侧标尺 28px        - 内边距 32px        - 24px × 2
```

> 取「每边各 24px」而非「总额 24px」，是为了满足「四周留白更充裕 / 匀称」——只减一处会让
> 底部（本就 88px）与顶部差距更大。实现上并入 `canvasInsets()`，与既有 inset 一起计算。

**效果**
- 画布与容器四周留白更充裕；
- 底部与工具条的间距更宽松；
- `cellSize` 计算同步受影响（可能触发下限 90px，允许平移查看）。

**验收**
- 画布与工具条间距比 v0.3.6 增加 24px；
- 大 `n` 值下画布仍不遮挡工具条；
- 四边留白均不小于 40px（左 68 / 右 40 / 上 68 / 下 112，`EXTRA_MARGIN` 增量四边一致）。

### OPT-C02 标尺字符边距与字号

**变更**

| 项 | v0.3.6 | v0.3.7 |
|---|---|---|
| 标尺与地图的间距 | 0px（贴边） | **6px** |
| 标尺字符基础字号 | 15px | **17px** |
| 标尺字符悬停字号 | 15px | **17px** |
| 标尺字符操作字号 | 17px | **19px** |

**间距实现**
- 顶部标尺底边与地图方格顶边之间保留 `RULER_GAP = 6px` 间隙；
- 左侧标尺右边与地图方格左边之间保留 6px 间隙；
- 间隙背景透明，不填充颜色；
- 实现方式：标尺条**外移** `RULER_GAP`（`left = pan.x - RULER_SIZE - RULER_GAP`、

**字号与 `scale` 的关系**
- 字号仍随 `scale` 缩放（见 OPT-C05），并随画布 `zoom` 一起缩放（标尺在缩放容器之外，见 v0.3.6 §3.3）；
- 上表数值为 `BASE_CELL = 120`、`zoom = 100%` 时的基准值。

**验收**
- 标尺字符与地图之间有可见间隙（6px），不再贴边；
- 字号明显大于 v0.3.6；
- 悬停 / 操作状态的样式仍生效。

### OPT-C03 图层优先级调整

**背景**

v0.3.6 把「地图最外边框」单独抽成 `MapCanvasFrameLayer`，并用
`overflow: visible` + `translate(-w/2, -w/2)` 把它**整条画在画布矩形之外**。
因此它虽然层级高于物体层，也**不会**遮挡区域名称或物品图，与内部分隔线也完全不重叠。

所以本项**不改渲染效果**，只做一件事：**把外框正式登记为独立图层**，并明确它位于物体之下、
内部分隔线之上。

**完整图层优先级（由上至下）**

| 序号 | 图层 | z-index |
|---|---|---|
| 1 | 当前方格辅助提示框（鼠标框 / 操作框） | 44 |
| 2 | 区域名称 | 42 |
| 3 | **不可站立物体阴影** | 41 |
| 4 | 物体 | 40 |
| 5 | **地图最外边框** | 39 |
| 6 | 边框（内部分隔线） | 38 |
| 7 | 区域边界线 | 36 |
| 8 | 区域高亮线 | 32 |
| 9 | 方块高亮 | 30 |
| 10 | 背景高亮 | 28 |
| 11 | 背景 | 20 |
| 12 | 空方格 | 10 |

> 说明：
> - 表内 12 层与 `constants.ts` 的 `MAP_LAYER_ORDER` **一一对应**（v0.3.7 起含 `canvasFrame`）；
> - **不可站立物体阴影位于物体之上**（v0.3.5 OPT-A03 §3.1「蒙版位于物体图之上」），本表序号 3；
> - 区域填充（`regionFill`，z = 22）是 v0.2.5 的遗留图层，不在本表内。

**关键点**
- 区域名称位于**物体之上、地图最外边框之上**，不被任何边框线遮挡；
- 地图最外边框位于物体之下，不遮挡物品图；
- 内部分隔线（Border）位于地图最外边框之下；两者在几何上并不重叠，仅为层级语义的统一。

**验收**
- 区域名称字体完整可见，不被外边框或内部分隔线切割；
- 物品图不被外边框遮挡；
- 最外边框仍清晰可见；
- `MAP_LAYER_ORDER` 为 12 项，z-index 沿该顺序严格递减。

### OPT-C04 区域名称字体加大并缩放

**变更**

| 项 | v0.3.6 | v0.3.7 |
|---|---|---|
| 基础字号 | 14px | **17px** |
| 悬停字号 | 16px | **19px** |
| 字体描边宽度 | 4px | 4px（不变） |
| 字号是否随 cellSize 缩放 | **是**（14 / 16px 基准） | 是（17 / 19px 基准） |

> v0.3.6 已实现随 `cellSize` 缩放（`scaleFontSize(..., scale)`），本项只是提高基准字号；
> 悬停字号同步由 16px 提到 19px，保持 v0.3.5「悬停放大」的 +2px 关系——若只提高基础字号，
> 悬停时反而会变小。

**缩放公式**
```
fontSize = base × (cellSize / BASE_CELL)     // base = 17（悬停 19）
```
- 约束：沿用项目全局字体 clamp **最小 9px、最大 28px**（`scaleFontSize`），不另设区域专属下限；
- 描边宽度同比例缩放（`scaleLineWidth`），受全局线条 clamp 约束。

**验收**
- `n = 2` 时区域名称明显大于 v0.3.6；
- `n = 24` 时字号缩小但清晰可读；
- 悬停时字号**大于**基础字号；
- 描边保持清晰，白字黑边可辨识。

### OPT-C05 线宽基准值统一

**背景**

v0.3.6 已把全部线条接入 `scale = cellSize / BASE_CELL` 的缩放
（`scaleLineWidth(BORDER_WIDTH, scale)`、`CANVAS_OUTER_BORDER_WIDTH`、
`cellCursorShadow(blocked, cellSize)`、`OPERATION_CURSOR_OUTLINE_WIDTH`）。
本项不再「补做缩放」，而是**校准基准值**并统一 clamp 口径：

| 要素 | v0.3.6 基准 | v0.3.7 基准 | 说明 |
|---|---|---|---|
| 内部分隔线（Border） | 2px | 2px | 不变 |
| 画布最外边框 | 6px | 6px | 不变，= 区域边界线默认宽 |
| 当前鼠标所在框线（内描边） | 1px | **2px** | 加粗一倍；外侧那圈覆盖 Border 的灰色阴影环另计 |
| 当前操作方格框线（Outer Line） | 2px | 2px | 不变 |
| 区域边界线 | `borderWidth`（默认 6px） | 不变 | 区域属性 |
| 区域高亮线 | 4px | 4px | 不变 |

**统一约束**

所有线条共用项目全局 clamp（`LINE_WIDTH_MIN` / `LINE_WIDTH_MAX`）：

```
缩放后宽度 = clamp(base × scale, 0.5px, 12px)
```

- 不再为单个要素设置独立的 min / max（全局 clamp 已覆盖全部要素：
  上限 12px 恰好等于外框 6px × scale 2）；
- 不可站立阴影无颜色 / 透明度缩放；其**内缩量**随 `borderWidth × scale / 2` 缩放，
  以便不盖住随 `scale` 变宽的 Border。

**实现要点**
- 所有线条宽度在渲染时按当前 `cellSize` 计算；
- 用户缩放画布（`Ctrl + 滚轮`）不触发重算（`scale` 只与 `cellSize` 有关，与 `zoom` 无关）；
- 常量集中在 `constants.ts` 中管理（见 §3）。

**验收**
- `n = 2` 时所有线条明显加粗；
- `n = 24` 时所有线条变细但仍清晰；
- 鼠标框内描边比 v0.3.6 明显（基准 1px → 2px）；
- 画布缩放时不出现双重缩放。

### OPT-C06 物体层物体向内缩小

**变更**

- 物品图在格内的渲染区域由原来的**铺满整格**改为**内缩一定边距**；
- 内边距：`padding = OBJECT_PADDING_BASE × scale`（`BASE_CELL = 120` 时为 4px，随 cellSize 缩放）；
- 缩放系数约束：`padding` 最小 2px，最大 12px。

**视觉示意**
```
原：┌──────────┐          新：┌──────────┐
    │██████████│              │  ┌────┐  │
    │██████████│              │  │████│  │
    │██████████│              │  └────┘  │
    └──────────┘              └──────────┘
    （铺满整格）                （内缩 padding）
```

**说明**
- 内缩仅适用于**物件层**（`object`）物品；
- **背景层**（`background`）物品仍铺满整格，作为底色；
- 多格物品的内缩应用在其整体占位矩形的外边缘，而非每个单格内缩；
- 内缩后物品图**仍沿用物品自身的 `fitMode`**（`cover` / `contain`，v0.2.3 起的逐物品属性），
  不得写死为 `cover`。

**验收**
- 物件层物品四周可见明显内边距，与格边界线不贴合；
- 背景层物品仍铺满整格；
- 多格物品内缩仅作用于整体外缘；
- `fitMode = contain` 的物品仍以完整图案居中显示。

### OPT-C07 点击方格时清除参与者触发效果

**问题**

当前当用户通过参与者框触发联动效果（悬停或点击激活）后，再点击画布上的方格：
- 参与者的联动效果**仍持续显示**；
- 用户难以判断当前触发的主体。

**修复要求**

1. **点击方格的行为**
   - 点击画布任意方格（含空格、画布外空白）时：
     - **清除当前参与者的触发效果**（无论激活方式为悬停还是点击）；
     - 恢复 `activeParticipantId = null`、`activationMode = null`；
     - 方格进入**选中态**（操作提示框 + 右侧信息抽屉）。

2. **触发主体切换规则**

   | 当前状态 | 用户操作 | 新状态 |
   |---|---|---|
   | 参与者 A 悬停激活中 | 点击方格 X | 清除 A，选中 X |
   | 参与者 A 点击激活中 | 点击方格 X | 清除 A，选中 X |
   | 参与者 A 点击激活中 | 点击参与者 B | 清除 A，激活 B |
   | 参与者 A 点击激活中 | 点击同一参与者 A | 清除 A |
   | 无激活 | 点击方格 X | 选中 X |

3. **方格选中态的语义**

   - **方格本身没有「配置」联动**：联动配置只挂在参与者槽位上
     （`CharacterSlotEntry.linkages: ParticipantTarget[]`，v0.3.3 MOD-801 起的扁平结构）；
   - 因此点击方格**不触发任何联动高亮**，只清空参与者激活并让方格取得焦点；
   - 要继续查看某参与者的联动，重新悬停 / 点击该参与者框即可；
   - 若该方格所属的区域或覆盖的物品正被某参与者引用，这些联动只在**该参与者被激活时**显示，
     与方格选中态互斥。

4. **状态机更新**

   ```
   [无焦点]
     --点击参与者 P--> [激活参与者 P（点击模式）]
     --悬停进入参与者 P--> [激活参与者 P（悬停模式）]（不改变抽屉焦点）
     --点击方格 X--> [选中方格 X]

   [激活参与者 P]
     --点击方格 X--> 清除 P → [选中方格 X]
     --悬停进入方格 X--> 保持 P（不切换）
     --悬停移出画布--> 若 P 为悬停模式，清除 P

   [选中方格 X]
     --点击参与者 P--> 清除 X → [激活参与者 P]
     --点击另一格 Y--> [选中方格 Y]
   ```

   > 实现约定：「选中方格」复用**现有 `selection`**（v0.3.5 OPT-A05 的操作提示框 + 信息抽屉），
   > **不新增状态轴**；`reduceLinkageActivation` 的状态形状保持不变。
   > 互斥规则抽成纯函数 `reduceEditorFocus(focus, event)`（`lib/editorFocus.ts`）以便单测。

5. **与右侧抽屉的协同**
   - 点击方格后，右侧抽屉切换为方格信息（背景层 / 物件层 / 所属区域等）；
   - 点击参与者后，右侧抽屉切换为参与者信息（此时 `selection` 被清空）；
   - 二者互斥。

6. **Esc 键**
   - 按 `Esc` → 清除所有焦点（参与者激活 + 方格选中）；
   - 右侧抽屉收起。

**验收**
- 参与者触发联动时，点击画布方格 → 参与者联动消失，方格进入选中态；
- 方格选中后，点击参与者 → 参与者激活，方格选中态消失；
- 两个状态互斥，无叠加；
- `Esc` 可清除任意焦点。
