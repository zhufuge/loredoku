## 1. 修复

### FIX-D01 区域高亮线渲染为斜线

**现象**

与 v0.3.7 FIX-C01 完全一致：区域被激活（悬停或联动）时，本应沿区域边界线内侧绘制的水平 / 垂直线
渲染成了斜线。

```html
<line x1="106.25" y1="310.25" x2="199.75" y2="306"
      stroke="#90CAF9" stroke-width="3.4" stroke-opacity="0.9"
      stroke-linecap="round"></line>
```

**根因（真正的根因）**

v0.3.7 已按正确结论写了纯函数 `buildRegionInnerEdges(cells, size, inset)`，但**没有替换掉组件里的旧
算式**，`MapLayers.tsx` 的 `RegionInnerBorder` 仍是：

```ts
// ❌ 仍然存在于代码中
x1={edge.x1 + inset}
y1={edge.y1 + inset}
x2={edge.x2 - (edge.x2 !== edge.x1 ? inset : 0)}
y2={edge.y2 - (edge.y2 !== edge.y1 ? inset : 0)}
```

**固定轴（沿边不变的维度）只在一端被平移了 `inset`，另一端不动**，于是每条边都获得斜率
`inset / 边长`。`buildRegionInnerEdges` 在 `lib/region.ts` 中已是导出状态但**无人调用**——这是
「修复写了、但没接线」的典型形态。

复现（`cellSize = 102` → `scale = 0.85` → `inset = 6×0.85/2 + 4×0.85/2 = 4.25`，区域取 `[[2,2],[3,2]]`）：

```
旧算式（6 条边全部斜线）：
{"x1":208.25,"y1":208.25,"x2":204,   "y2":301.75} !! 斜线 !!
{"x1":208.25,"y1":208.25,"x2":301.75,"y2":204}    !! 斜线 !!
{"x1":208.25,"y1":310.25,"x2":301.75,"y2":306}    !! 斜线 !!
{"x1":412.25,"y1":208.25,"x2":408,   "y2":301.75} !! 斜线 !!
{"x1":310.25,"y1":208.25,"x2":403.75,"y2":204}    !! 斜线 !!
{"x1":310.25,"y1":310.25,"x2":403.75,"y2":306}    !! 斜线 !!

纯函数（6 条边全部轴对齐）：
{"x1":208.25,"y1":208.25,"x2":301.75,"y2":208.25} 水平 ✓
{"x1":208.25,"y1":208.25,"x2":208.25,"y2":301.75} 垂直 ✓
{"x1":208.25,"y1":310.25,"x2":301.75,"y2":310.25} 水平 ✓
{"x1":412.25,"y1":208.25,"x2":412.25,"y2":301.75} 垂直 ✓
{"x1":310.25,"y1":208.25,"x2":403.75,"y2":208.25} 水平 ✓
{"x1":310.25,"y1":310.25,"x2":403.75,"y2":310.25} 水平 ✓
```

**修复要求**

1. `RegionInnerBorder` 必须调用 `buildRegionInnerEdges(cells, cellSize, inset)` 取几何，组件内
   **不得**再出现任何对端点的手工 `± inset`；
2. `stroke-linecap` 使用 `square`（`round` 会在拐角处溢出圆头）；
3. 删除组件内已无引用的旧算式，避免「两份几何来源」；
4. **补充源码级回归断言**：测试用例读取 `MapLayers.tsx` 源码，断言不含 `edge.x1 + inset`
   形态的片段，且包含 `buildRegionInnerEdges(`。

**验收**

- 任意区域（矩形 / L 形 / 十字形 / 回字形）激活后，高亮线全部严格水平或垂直；
- 每条线段满足 `x1 === x2 || y1 === y2`；
- 拐角无缺口、无交叉外溢；
- `cellSize` 取 90 / 120 / 240 时表现一致；
- 源码断言通过（防止再次「写了没接线」）。

## 2. 新增：地图基本信息编辑

### FEAT-D01 入口与交互

**入口**

编辑页顶栏（`EditorToolbar`）的右侧按钮组新增一个「基本信息」按钮（图标 + 文案），
点击后在**画布右侧**弹出「地图基本信息」抽屉。

**交互**

| 行为 | 结果 |
|---|---|
| 点击「基本信息」 | 右侧抽屉打开，展示当前地图的基本信息编辑页 |
| 抽屉已打开时再次点击 | 抽屉关闭（按钮为切换态） |
| 点击抽屉右上角 × | 抽屉关闭 |
| 按 `Esc` | 抽屉关闭（若同时存在其它浮层，按浮层优先级由外向内逐层关闭） |
| 抽屉打开时 | 抽屉是覆盖层（不挤压画布），因此**不会**触发画布重算；窗口自身尺寸变化仍会重算自适应方格尺寸 |

**与既有抽屉的关系**

编辑器右侧已有两个抽屉（`EditorInfoDrawer` 方格 / 区域信息、`ParticipantDrawer` 参与者信息）。
三者互斥：打开「基本信息」时关闭另外两个；反之亦然。

**抽屉内容分区**

1. **画布**：`n`（画布尺寸）、方格大小；
2. **线条**：地图最外边框、边框 border、当前鼠标所在框、当前操作方格框、区域边界线、区域高亮线；
3. **区域名称**：字体大小、字体描边大小、字体颜色、描边颜色、高亮字体颜色、高亮描边颜色；
4. **联动主题色**：调色板列表（可增删改）。

每个分区内的控件都是「**缺省值**」语义：修改后立即作用于当前地图展示，并作为后续新建对象的取值依据。

### FEAT-D02 地图基本信息统一管理的常量

**总原则：缺省值 + 覆盖**

- 地图基本信息保存的是**地图级缺省值**；
- 逐对象的设置（区域自身 `borderWidth`、参与者主题色、物品图）仍然优先；
- 「区域边界线」是唯一例外，见下方说明。

**字段与语义**

| 分区 | 字段 | 含义 | 缺省值 | 取值范围 | 作用于 |
|---|---|---|---|---|---|
| 画布 | `n` | 画布尺寸 `n × n` | 项目当前值 | 2 ~ 24 整数 | 立即 |
| 画布 | 方格大小 | 方格宽度覆盖值；`null` 表示按自适应计算 | `null`（自适应） | 90 ~ 240 整数 | 立即 |
| 线条 | 地图最外边框 | 线宽 / 颜色 | 6px / `#000000` | 1 ~ 12 / `#RRGGBB` | 立即（全局） |
| 线条 | 边框 border | 线宽 / 颜色（内部分隔线） | 2px / `#000000` | 1 ~ 12 / `#RRGGBB` | 立即（全局） |
| 线条 | 当前鼠标所在框 | 线宽 / 颜色 / 被阻挡颜色 / 阴影环颜色 | 2px / `#FFFFFF` / `#EF9A9A` / `rgba(0,0,0,0.15)` | 1 ~ 12 / `#RRGGBB` | 立即（全局） |
| 线条 | 当前操作方格框 | 线宽 / 颜色 / 外扩距离 | 2px / `#90CAF9` / 1px | 1 ~ 12 / `#RRGGBB` / 0 ~ 8 | 立即（全局） |
| 线条 | 区域边界线 | 线宽 / 颜色 | 6px / `#000000` | 4 ~ 12 / `#RRGGBB` | 立即（全局，见下） |
| 线条 | 区域高亮线 | 线宽 / 颜色 | 4px / `#90CAF9` | 1 ~ 12 / `#RRGGBB` | 立即（全局） |
| 区域名称 | 字体大小 | 基础字号 | 17 | 9 ~ 48 整数 | 立即（全局） |
| 区域名称 | 高亮字体大小 | 悬停字号 | 19 | 9 ~ 48 整数 | 立即（全局） |
| 区域名称 | 字体描边大小 | 描边宽度 | 4 | 0 ~ 12 | 立即（全局） |
| 区域名称 | 字体颜色 | 基础字色 | `#FFFFFF` | `#RRGGBB` | 立即（全局） |
| 区域名称 | 描边颜色 | 基础描边色 | `#000000` | `#RRGGBB` | 立即（全局） |
| 区域名称 | 高亮字体颜色 | 悬停字色 | `#FFFFFF` | `#RRGGBB` | 立即（全局） |
| 区域名称 | 高亮描边颜色 | 悬停描边色 | `#90CAF9` | `#RRGGBB` | 立即（全局） |
| 联动主题色 | 调色板 | 列表项 `{key, label, color}` | 红 `#EF9A9A`、蓝 `#90CAF9` | 2 ~ 12 项 | 立即（全局） |

**关键规则**

1. **线宽是「基准值」，仍随方格尺寸等比缩放**。表内线宽的基准为 `BASE_CELL = 120`
   （v0.3.6 OPT-B03），实际渲染宽度 = `clamp(基准值 × cellSize / 120, 0.5, 12)`。这保证同一份
   配置在 `n = 2`（大格）与 `n = 24`（小格）下观感一致。
2. **字体同理**：实际字号 = `clamp(基准字号 × cellSize / 120, 9, 28)`。
3. **方格大小覆盖后，`scale` 以覆盖值为准**（`scale = 覆盖值 / 120`），因此所有线宽 / 字号都跟着变。
4. **区域边界线是全局样式**：
   - **颜色**由基本信息统一决定（所有区域边界线同色）；
   - **线宽**在基本信息里修改时，**同步写入所有现存区域的 `borderWidth`**，并成为新建区域的缺省值；
   - 区域自身的 `borderWidth` 仍可在「编辑区域」对话框里单独覆盖（覆盖后不再跟随全局）；
   - 区域自身的 `color` 仍决定**区域填充**颜色（`fillOpacity > 0` 时可见），不再参与边界线配色。
5. **不可修改项**：参与者主题色（`THEME_COLOR_PALETTE`，15 色）、物品图片本身、方格尺寸的上下限
   （90 ~ 240）不属于本页范围。
6. 每个字段都必须 clamp 到表内范围；落库前再经 zod 校验，越界即拒绝保存。

### FEAT-D03 方格大小

**语义**

- **默认值**：首次打开编辑器时按自适应算法算出的整数方格宽度
  （`computeCellSizeForInsets`，clamp 90 ~ 240，见 `lib/canvasSize.ts`）；
- 用户可手工填写一个整数覆盖它；
- **修改后按该值渲染画布**（不再走自适应），并且所有随方格尺寸缩放的线条 / 字体立即按新值重算；
- 范围仍受 `MIN_CELL_SIZE = 90` ~ `MAX_CELL_SIZE = 240` 限制；
- 提供「恢复自适应」按钮：把覆盖值置回 `null`，并立即重算。

**与窗口尺寸的关系**

- 覆盖值生效时，窗口尺寸变化**不再**改变方格宽度；
- 覆盖值为 `null` 时，行为与 v0.3.7 一致（`ResizeObserver` + `centerView()` 重算）。

**验收**

- 填写 90 / 120 / 240 后画布立即按对应尺寸渲染；
- 填写 60 或 400 被 clamp 到 90 / 240；
- 非整数（如 123.4）按四舍五入取整；
- 点「恢复自适应」后窗口 resize 能再次改变方格宽度。

### FEAT-D04 联动交互主题色可扩展

**语义**

- 调色板是**地图级**配置，列表项为 `{key, label, color}`；
- 默认至少包含 **红**（`#EF9A9A`）与 **蓝**（`#90CAF9`）两项；
- 支持**新增**（自动分配 `key`）、**改色**、**改名**、**删除**；
- 至少保留 2 项，最多 12 项；
- `key` 必须匹配 `^[a-z][a-z0-9_-]{0,31}$` 且在本图内唯一，用于在联动的 `color` 字段中引用；
- 已有的 `ParticipantTarget.color` 存的是 **`key`**（历史数据就是 `red` / `blue`，因此向后兼容）；
- 保存时校验：所有联动目标的 `color` 必须存在于本图调色板中，否则拒绝（zod 交叉校验）。

**UI 规则**

- 删除某项时，若被现有联动引用，提示「已有 N 处联动使用该颜色」并**要求确认**；确认后把这些联动
  改指向第一项（保留其余字段）；
- 条目数量已等于下限（2）时，删除按钮禁用；`resolveMapStyle` **不会**把用户删掉的默认色重新加回来
  （2 项下限由 schema 与 UI 共同保证，而不是由解析兜底）；
- 修改某项 `color` 时，所有引用该 `key` 的联动**立即换色**（引用的是 `key`，不是色值）。

**验收**

- 新增一项后，联动配置对话框出现第三个色选项；
- 改色后画布上已激活的联动高亮立即变色；
- 删除被引用的颜色先弹确认；确认后相关联动指向剩余第一项；
- 只保留一项时删除按钮禁用（下限 2）。

### FEAT-D05 缩放按钮语义

**现状**

底栏的放大 / 缩小按钮调用 `editor.setZoom()`，只改变画布容器 `transform: scale()`，
**不修改任何地图数值**。这一语义在 v0.3.8 明确固定下来，并补充说明文字。

**规则**

| 控件 | 作用 | 是否修改数值 |
|---|---|---|
| 缩小 / 放大按钮 | 整体缩放**查看**比例，范围 25% ~ 400% | 否 |
| 百分比按钮 | 重置为 100% | 否 |
| 「适应画布」按钮 | 重算自适应方格尺寸并把缩放置为 100% | 是（仅当方格大小为自适应时） |
| 基本信息里的「方格大小」 | 修改方格实际渲染尺寸 | 是 |

**实现要求**

- 缩放按钮与方格大小配置**互不写入**：`setZoom` 不得触碰 `style.cellSize`，反之亦然；
- 按钮 `title` 明确为「整体缩小查看（不修改方格大小）」/「整体放大查看（不修改方格大小）」；
- 底栏百分比只反映查看缩放，不反映方格大小。

**验收**

- 点放大 3 次后，基本信息里的方格大小数值**不变**；
- 点「适应画布」或 `Ctrl+0` 时缩放回到 100%；
- 修改方格大小后，底栏百分比**不变**。

## 3. 图层优先级（SPEC-D01）

完整的图层顺序、z-index、遮挡规则与术语表见 **《画布图层优先级规范》**（`docs/layer-priority.md`）。

本版对图层表做两处调整：

1. **`cellCursor` 拆成两层**：`cellMouseCursor`（当前鼠标所在框）在上、`cellOperationCursor`
   （当前操作方格框）在下，二者可在同一格叠加；
2. **`noStandShadow` 从「物体之上」下移到「区域边界线之下、区域高亮线之上」**，与本版指定的
   优先级一致（该顺序**优先于** v0.3.5 §3.1 的旧约定）。

调整后的 13 层（自顶向下）：

```
当前鼠标所在框 > 当前操作方格框 > 区域名称 > 物体 > 地图最外边框 > 边框 border
> 区域边界线 > 不可站立物体阴影 > 区域高亮线 > 方块高亮 > 背景高亮 > 背景 > 空方格
```

> **关于阴影下移后的可见性**：物件层物品图带内边距（v0.3.7 OPT-C06，四周留白 2 ~ 12px），
> 阴影仍可在物品图四周的留白处看到；阴影本身仍为 `rgba(0,0,0,0.18)` 并内缩至 Border 内侧。

## 4. 数据结构与迁移

### 4.1 草稿新增 `style` 字段

```jsonc
{
  "version": 2,
  "gridSize": 6,
  "cells": { "0,0": { "object": { "itemId": 3, "w": 1, "h": 1 } } },
  "regions": [],
  "characterSlots": [ /* … */ ],
  "style": {
    "cellSize": null,
    "canvasFrame": { "width": 6, "color": "#000000" },
    "border": { "width": 2, "color": "#000000" },
    "mouseCursor": {
      "width": 2, "color": "#FFFFFF", "blockedColor": "#EF9A9A",
      "shadowColor": "rgba(0,0,0,0.15)"
    },
    "operationCursor": { "width": 2, "color": "#90CAF9", "offset": 1 },
    "regionLabel": {
      "fontSize": 17, "strokeWidth": 4,
      "color": "#FFFFFF", "strokeColor": "#000000",
      "hoverFontSize": 19, "hoverColor": "#FFFFFF", "hoverStrokeColor": "#90CAF9"
    },
    "regionBorder": { "width": 6, "color": "#000000" },
    "regionHighlight": { "width": 4, "color": "#90CAF9" },
    "linkageColors": [
      { "key": "red",  "label": "红", "color": "#EF9A9A" },
      { "key": "blue", "label": "蓝", "color": "#90CAF9" }
    ]
  }
}
```

**兼容性**

- `style` 在 zod schema 中是**可选字段**，缺失时按上表缺省值解析（`resolveMapStyle(undefined)`）；
- 编辑器在保存时**始终写回完整 `style`**（`editorStore.toDraft()` 已包含解析后的样式）；
  服务端允许缺省，以兼容 v0.3.7 及更早的导入包；
- 已有草稿与已发布作品**无需迁移脚本**：读取时补缺省值；
- `MAP_JSON_VERSION` 由 1 提升为 **2**，仅表示「可能包含 `style`」，`version = 1` 的旧数据仍被接受；
- 画布尺寸调整（`resizeDraft`）必须**保留** `style`。

### 4.2 联动颜色字段

- `ParticipantTarget.color`：由 `enum('red' | 'blue')` 放宽为**调色板 key**（正则校验），
  再由 `mapDraftSchema.superRefine` 校验该 key 存在于 `style.linkageColors`；
- 历史数据 `red` / `blue` 命中默认调色板，无需迁移。

### 4.3 无 SQL 迁移

`style` 存在草稿 JSON（`map_projects.draft_data` / `map_versions.data`）内，**不新增表或列**。
