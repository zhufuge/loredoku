# v0.8.1 — 地址、选料与路径：把工作空间的边界补严

> **状态**：已实施（2026-10-29）。
> **来源**：用户列出的七项 —— 编辑/预览路由带主题段、编辑器选料按主题隔离、
  日夜模式跨页一致、`/:code/basic` 改名、部署路径去难度、新建弹窗预填主题前缀、
  部署页恢复 v0.8 前的平铺样式。
> **范围**：`packages/web` 为主；`packages/shared`（slug 三函数）、
  `packages/server`（部署兜底派生）跟着 slug 一起改。无迁移。

## 0. 一句话

v0.8.0 把主题变成了工作空间，但边界上留了几道缝：编辑器和预览页的地址不带主题段
（主题是「记住的」而不是「说出的」）、编辑器里的选料还看得见别的世界、日夜模式和
工作空间记忆共用一个键导致设置被悄悄改写、访问路径里掺着难度。这一版把缝补上。

## 1. 编辑 / 预览路由进工作空间

| 之前 | 现在 |
|---|---|
| `/maps/:mapId/edit` | `/:themeCode/maps/:mapId/edit` |
| `/maps/:mapId/views` | `/:themeCode/maps/:mapId/view` |
| `/puzzles/:puzzleId/edit` | `/:themeCode/puzzles/:puzzleId/edit` |
| `/puzzles/:puzzleId/view` | `/:themeCode/puzzles/:puzzleId/view` |

地图预览段从 `views` 统一成了 `view`（谜题本来就是 `view`，四条地址现在一个形状）。

四条新路由仍是**整屏页**（外壳之外），不是工作空间的子路由 —— 它们只是借了
`/:themeCode` 这一段地址。`themeCode` 在页内有两个用途：

1. **拼跳转**：编辑器里「预览」、保存后 replace、版本历史的「编辑此版本」、
   列表页的进编辑器，全部用 `fullscreenPath(code, …)` 拼 —— 不再依赖
   「记住的编码」；
2. **筛选选料**（§2）。

旧地址（`/maps/12/edit` 这类书签）由 `FullscreenLegacyRedirect` 落到**记住的**
工作空间；记不住就去挑主题入口，不编造编码。

## 2. 编辑器的选料按主题隔离

地图编辑器、地图预览、谜题编辑器、谜题预览四个整屏页的资源 / 角色列表全部带上
地址里的 `themeCode`：

```
MapEditorPage   useAssets({ isActive: true, themeCode })
MapViewPage     useAssets({ themeCode })
PuzzleEditorPage useAssets({ themeCode }) + useCharacters({ themeCode })
PuzzleViewPage   useAssets({ themeCode }) + useCharacters({ themeCode })
```

之前这些列表是**全库**的 —— 在红楼梦的编辑器里能选到默认主题的大树，画布上一放，
导出的资源包里却没有它。工作空间的边界应当跟人走到最后一层：**画一张图用的料，
只能是这个世界的料**。

## 3. 日夜模式被工作空间记忆覆盖（根因修复）

现象：在系统配置里把日夜改成日间，回到工坊又变回夜间。

根因不是状态机，是**两个功能共用一个 localStorage 键**：

| 功能 | 键 | 写什么 |
|---|---|---|
| 日夜模式（`lib/theme.ts`） | `loredoku.theme` | `light` / `dark` / `system` |
| 工作空间记忆（`lib/workspace.ts`） | `loredoku.theme` | 主题编码，如 `hlm` |

于是每次进工作空间，`rememberThemeCode('hlm')` 都会把日夜模式的值**改写成
`hlm`**；`readStoredTheme()` 读到非法值回退「跟随系统」，系统是深色就是夜间。
设置页里改的「日间」在返回工坊的一瞬间被静默清掉。

修法：工作空间记忆换键 `loredoku.lastTheme`，日夜模式独占 `loredoku.theme`。
存过脏数据的浏览器自愈（读到 `hlm` 回退 `system`），不需要迁移。

## 4. `/:code/basic` → `/:code/overview`

「basic」是 §18 起草时的占位词，语义上这页是**概览**。改名三件套：

- 路由子路径 `basic` → `overview`，索引重定向跟着改；
- `ThemeBasicPage` → `ThemeOverviewPage`（文件、组件、测试）；
- `WORKSHOP_MODULES` 的 key、`AppShell` 导航项、`ThemesPage` 的卡片链接、
  `workshopPath('overview')` 的调用点。

旧地址 `/hlm/basic` 不留重定向 —— §18 上线还不到一天，不值得为它立碑。

## 5. 部署访问路径不再带难度

`/play/{slug}` 的形状从 `puzzle-{中段}-{难度}` 变成 `puzzle-{中段}`：

- `composeSlug(middle)` / `buildDefaultSlug({ name })` 不再拼难度后缀；
- `splitSlug(slug)` 剥掉前缀之后，把**任何一个**已知难度后缀剥掉 —— 存量路径
  （`puzzle-x-hard`）回填中段时得到 `x`，重新部署才不会把后缀写死进新路径；
- 服务端 `resolveSlug` 的兜底派生同样只看名称；部署弹窗的路径输入组去掉
  只读难度后缀，难度仍是**表单字段**（部署之后可以改，地址不动）。

理由：路径是给持链接的人的承诺，改个难度不该把对外地址改掉 —— 难度是这关的
属性，不是它的地址。存量路径**继续有效**（服务端不做任何改写）；
重新部署时弹窗会明写「原访问路径将失效」。

## 6. 新建弹窗预填主题前缀

资源 / 角色的「业务 ID」输入框默认填 `${themeCode}_`（如 `hlm_`），作者只敲
后半段。同一个编码在不同主题里各自存在，前缀替作者把「这东西属于哪个世界」
写进 ID。地图与谜题没有业务 ID 字段，不涉及。

## 7. 部署页恢复 v0.8 之前的平铺样式

v0.8.0 §16.4 的「按主题分组卡片」撤掉，回到 v0.7 的形状：**一张卡、一行一条** ——
合辑一段在上，单局一段在下（64px 行：缩略图 / 名称与来源 / 难度徽章 / 尺寸 /
路径 / 时间 / 操作）。

撤的理由：这一页在 §18 之后本来就**只在一个工作空间里**，标题就是这个主题，
分组头「红楼梦 · 8 关在线 · 导出包」等于把页头抄一遍。「导出包」上移到页头
（它本来就是主题级动作）。数据口径不变：工作空间里只列当前主题的行；已进合辑
的单局不重复列；页头计数 = 单局行数。

## 9. 未做

1. **业务 ID 强制带主题前缀**：预填只是默认值，作者可以删掉前缀。真要强制
   得动 schema 校验（`${themeCode}_` 开头），而业务 ID 创建后不可改，存量数据
   全都不合新规 —— 得配一条数据回填，先不做。
2. **旧整屏地址的精确重定向**：`/maps/12/edit` 落到「记住的主题」，如果那张图
   不属于它，编辑器照常打开（图是按 id 寻址的），只是选料列表按记住的主题筛 ——
   两个不一致时空空如也就是症状。要根治得让重定向先查一次地图归属，多一次
   往返，等真有人撞上再说。
3. **存量带难度路径的批量改写**：不改。老链接是承诺，服务端不动它们。
