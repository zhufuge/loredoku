## 1. FIX-E01 发布成功后画布复位

**现象**

点击「发布」，发布成功后画布（缩放与位置）跳回默认状态，用户此前对好的视图丢失。

**根因**

`EditorPage` 用以下条件判断是否需要把服务端数据重新灌入编辑器：

```ts
const sameDraft =
  initKeyRef.current === id &&
  editor.updatedAt === data.updatedAt &&
  editor.currentVersionNo === data.project.currentVersionNo &&   // ← 元数据也参与判断
  editor.status === data.project.status;                        // ← 元数据也参与判断
if (sameDraft) return;
editor.init(...);          // init() 会重置 zoom / pan
```

而发布（`versionService.publishProject` → `versionRepo.createVersion`）只会更新
`map_projects.current_version_no` 与 `status`，**不会**触碰 `draft_updated_at`
（`GET /map` 的 `updatedAt` 正来自该列）。于是「草稿没变、只是版本号变了」被误判为「地图变了」，
触发全量 `init()`，`zoom = 1` / `pan = {0,0}` 把画布复位。

**修复**

把判断抽成纯函数 `resolveEditorInit()`（`packages/web/src/lib/editorInit.ts`），返回三种动作：

| 条件 | 动作 | 行为 |
|---|---|---|
| 项目 ID 不同 | `init` | 全量重新初始化 |
| `updatedAt` 不同（草稿真变了） | `init` | 全量重新初始化 |
| `updatedAt` 相同，但版本号 / 状态不同 | `sync-version` | **只刷新版本徽标**，视图保持不变 |
| 全部相同 | `none` | 什么都不做 |

**验收**

- 发布成功后画布的位置与缩放**完全不变**，顶栏徽标变为「已发布 vN」；
- 他人在别处保存过草稿（`updatedAt` 变化）时仍会重新加载；
- 从作品历史恢复草稿后正常重新加载。

## 2. FIX-E02 区域高亮线断开

**现象**

区域被激活（悬停或联动）时，高亮线在**每一条直线段上都是断开的**，只有拐角处看起来相连，
整体像虚线。v0.3.8 已修掉「斜线」，但这不是同一个问题。

**根因**

`buildRegionInnerEdges`（v0.3.7 引入、v0.3.8 接线）的做法是：**逐条格边独立内缩** ——
法向平移 `inset`，切向两端**各缩 `inset`**。于是

- 一条横跨 `k` 格的直边被拆成 `k` 条独立线段，相邻线段之间各留出 `2 × inset` 的缺口；
- 凹角处（L 形、十字形、蛇形）两条线段各缩 `inset`，同样留缺口；
- 只有**凸角**上同一格的横竖两条边会在 `(px + inset, py + inset)` 处相交，看起来是「只有角落连着」。

`inset = 圈宽/2 + 高亮宽/2`（`cellSize = 150` 时约 6px），所以缺口就是 12px 左右，肉眼可见。

**修复**

新增纯函数 `buildRegionHighlightPaths(cells, size, inset)`，把「逐边内缩」换成
「**追踪闭合轮廓 → 偏移支撑线 → 重建顶点**」：

1. 每条不与相邻区域格共享的格边都变成一条**有向边**（行进方向保证区域内部在右侧，即顺时针环路）；
2. 有向边按端点首尾相接**串成环路**；一个自相交点（对角相触）处有多条候选边时，**优先取最右转**，
   保证环路正确分离；
3. 每条边的**支撑线**沿自身法向向内平移 `inset`；新顶点 = 相邻两条偏移直线的**交点**。
   直角折线的相邻边互相垂直，交点必然唯一，因此：
   - 直线段：相邻共线边的偏移线是同一条直线，顶点落在原处 → 线段**连续**；
   - 凸角 / 凹角：偏移线交于一点 → 拐角**闭合**；
4. 每个环路输出一条 `M … L … Z` 的闭合路径。

`inset` 上限为 `size / 2`，避免单格区域被翻面。

**实测**（`cellSize = 100`、`inset = 5`）

```
单格     → M 5 5 L 95 5 L 95 95 L 5 95 Z
两格横排 → M 5 5 L 100 5 L 195 5 L 195 95 L 100 95 L 5 95 Z          ← 中点在 x=100 处相连
L 形     → M 5 5 L 95 5 L 95 205 L 295 205 L 295 295 L 5 295 Z      ← 凹角在 (95,205) 闭合
回字形   → 2 条环路（外轮廓 + 洞）
```

渲染改为 `<path d=… fill="none" strokeLinejoin="miter" strokeLinecap="butt">`。

**验收**

- 任意区域（矩形 / L 形 / 十字形 / 回字形 / 蛇形）激活后高亮线为**一条连续闭合折线**；
- 每条线段满足 `x1 === x2 || y1 === y2`（即相邻顶点必有一轴相同）；
- 相邻顶点中不存在「斜线」；拐角处无缺口、无溢出；
- `cellSize` 取 90 / 102 / 120 / 240 时表现一致。

## 3. FEAT-E01 基本信息改为草稿表单

**原问题**

「地图基本信息」抽屉里的每一个控件都是**即时生效**：改一个数字就写一次草稿、进一次撤销栈，
用户无法「一组改动一起生效」，误触也无法回退到打开抽屉时的状态。

**新交互**

| 行为 | 结果 |
|---|---|
| 修改任意字段 | **只写本地草稿**，画布不变化；「保存」按钮由禁用变为可用 |
| 点击「保存」 | 草稿整体写入地图（一次撤销步），抽屉关闭 |
| 点击「取消」/ 右上角 × | 若**没有**未保存修改，直接关闭；若有，先弹确认 |
| 点击画布方格 / 参与者槽位 / 顶栏「基本信息」 | 同上：有未保存修改时先弹确认 |
| 按 `Esc` | 抽屉打开时先处理抽屉（同样先确认），不清理方格 / 参与者焦点 |
| 未保存确认弹框 | 「继续编辑」/「放弃修改」/「保存并继续」三个动作 |

**实现要点**

- 抽屉内部持有 `draft`（`resolveMapStyle` 的副本），仅在 `open` 由假变真时从 `style` 重新播种，
  因此**取消后再次打开一定回到已提交状态**；
- 抽屉通过 `forwardRef` 暴露 `MapInfoDrawerHandle { isDirty(); save(); discard(); }`，
  `EditorPage` 用 `guardMapInfo(proceed)` 包裹所有「关闭抽屉 / 把焦点交给别的面板」的路径；
- 抽屉内部维护 `settledRef`：`save()` / `discard()` 之后 `isDirty()` 立即返回 `false`，
  避免父级在同一事件回调里读到尚未刷新的脏标记而重复弹框；
- 「保存」按钮位于抽屉**底部**，与「取消」并列（`footer` 固定在滚动区之外）。

**「保存」的语义**

与编辑器一致：**保存 = 写入当前草稿**（可通过 `Ctrl+Z` 回退），持久化仍由顶栏「保存」完成。
「画布尺寸」不在草稿内 —— 它会裁剪越界内容，因此沿用既有的独立确认流程。

**验收**

- 改一个字段后，画布无任何变化，「保存」可用；
- 保存后画布变化，且 `Ctrl+Z` 一次即可回退整组改动；
- 有未保存修改时点 ×、点「取消」、点画布、点参与者槽位、按 Esc 都会先弹确认；
- 「继续编辑」保持抽屉与草稿不变；「放弃修改」回到已提交状态；「保存并继续」先保存再执行原操作。

## 4. FEAT-E02 标尺文本大小与间距

**新增字段**

`MapStyle.ruler: { fontSize, gap }`

| 字段 | 含义 | 缺省值 | 范围 |
|---|---|---|---|
| `fontSize` | 标尺文本基准字号 | 17px | 9 ~ 32 整数 |
| `gap` | **文本到地图的间距** | 6px | 0 ~ 32 |

**渲染规则**

- 字号 = `clamp(fontSize × cellSize / 120, 9, 28) × zoom`（与其它字体同一套缩放与上下限）；
- 操作格所在行列的字号 = 基准字号 **+2**（沿用 v0.3.6 的 17 / 19 关系，常量
  `RULER_ACTIVE_FONT_DELTA`）；
- 标尺条高度 = `max(RULER_SIZE(28), 最大字号 + gap + 6)`（`rulerStripSize`），
  并把该高度传给 `canvasInsets({ rulerSize })`，保证画布不会压住标尺；
- 文字贴向画布一侧对齐（上标尺 `items-end + paddingBottom: gap`，左标尺
  `justify-end + paddingRight: gap`），因此 `gap` **就是**文本与地图之间的实际距离。

**验收**

- 文本大小 9 / 32 生效且被 `[9, 28]` 的全局字体上下限约束；
- 文本到地图的间距 0 / 32 可见变化，且文本不会溢出标尺条；
- 操作格所在行列始终比普通文本大 2px；
- 缩放画布时字号随之放大，间距保持不变。

## 7. FIX-E03 弹框不再点击遮罩关闭

`DialogContent`（`packages/web/src/components/ui/dialog.tsx`）默认
`onInteractOutside={(event) => event.preventDefault()}`，因此点击半透明遮罩层不再关闭弹框，
避免误点时丢掉已填写的内容。`Esc` 与关闭按钮仍然有效；需要旧行为的调用方可自行覆盖该属性。

`AlertDialog`（确认类弹框）本身即不响应遮罩点击，无需改动。

**验收**

- 区域编辑 / 联动配置 / 调整画布尺寸 / 角色信息等弹框，点击遮罩不再关闭；
- `Esc` 与右上角 × 仍可关闭。

## 8. FIX-E04 参与者槽位单一高亮框

**现象**

参与者槽位高亮时出现**两层边框**：槽位容器额外画了一圈 `ring-2 ring-primary ring-offset-1`，
头像又画了 `3px` 参数色描边，两层叠在一起显得重复。

**修复**

- 槽位容器最多画**一圈** `box-shadow`（无 `ring-offset`，紧贴边框）：
  - 该槽位角色被引用 → 参数色（`0 0 0 2px <联动主题色>`）；
  - 否则该槽位自身的联动正在预览中 → 主题色 `hsl(var(--primary))`；
  - 两者互斥，永不同时出现；
- 头像不再绘制任何高亮描边，只保留 `scale(1.08)` 放大与「白色主题色时的 1px 浅灰描边」；
- 编辑器参与者面板与作品预览页保持一致。

**验收**

- 高亮槽位只有一层边框；
- 被引用角色的颜色 = 该联动引用的主题色；
- 白色主题色头像仍有 1px 浅灰描边，放大动效保留。

## 9. FIX-E05 「边框 border」修改不生效：核查结论

**核查过程**

1. 用 `renderToStaticMarkup` 直接渲染 `MapGridSeparatorLayer`，传入自定义
   `gridSeparator: { width: 9, color: '#FF0000' }`：输出为
   `<line stroke="#FF0000" stroke-width="7.5">` —— **样式确实生效**；
2. 用 jsdom + `react-dom/client` 模拟真实交互（输入数值 → `input` → `focusout` / `Enter`、
   拖动颜色选择器），`onSetStyle` 均被调用且携带正确的 `border` 更新 —— **控件接线也没有问题**；
3. 因此「不生效」的实际原因指向**语义歧义**：界面上同时存在「地图最外边框」与「边框 border」，
   而用户通常把「边框」理解为画布最外圈的那条框线，于是在改「边框 border」时盯着最外圈看，
   自然看不到变化。

**处理**

- 按 SPEC-E01 把两个名字改成不会混淆的规范名：
  - 「地图最外边框」→ **画布外框**（Canvas Frame，最外一圈，画在画布矩形之外）；
  - 「边框 border」→ **网格分隔线**（Grid Separator，格与格之间的内部分隔线，相邻格共享一条）；
- 两处都补 `title` 说明，明确「外框只画最外一圈，网格分隔线只画格与格之间」；
- 本版起这两个字段的修改统一在「保存」时生效（见 FEAT-E01），不再有「改完没感觉」的中间态。

> 结论：**没有发现代码缺陷**。若改名后仍能复现「改网格分隔线看不到变化」，
> 请提供当时的 `n`、方格大小与两个字段的取值，可据此进一步定位
> （该场景只剩「分隔线被物件图/背景图完全覆盖」这一种可能，此时应检查图层顺序）。

## 11. 数据结构与迁移

### 11.1 `style` 子字段改名（需要迁移）

v0.3.8 起草稿可以带 `style`，其字段名在本版改名。为兼容已保存的草稿与已发布作品，
在 `packages/shared` 提供**读取期别名**：`mapStyleSchema` 在解析时把
`border` / `regionBorder` / `mouseCursor` / `operationCursor` 这四个旧键映射到新键
（新键优先，旧键仅在缺失对应新键时生效），并在保存时只写新键。

> 之所以用读取期别名而不是 SQL 迁移：`style` 存在草稿 JSON 里（`map_projects.draft_data`
> 与 `map_versions.data`），别名方案对**历史作品快照**同样有效，且不需要改动任何表结构。

### 11.2 `ruler` 新增

`MapStyle.ruler` 为新增字段，缺失时取缺省值 `{ fontSize: 17, gap: 6 }`，
老草稿与老作品渲染效果不变。

### 11.3 无 SQL 迁移

本版**不新增表、不新增列**，也不需要迁移脚本。
