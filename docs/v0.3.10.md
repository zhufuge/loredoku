## 1. FIX-F01 基本信息中的全部数据都要保留

**现象**：「地图基本信息」抽屉里的字段都能改，但其中**画布尺寸**并不属于草稿：改动它会跳到
另一套「调整画布尺寸」确认流程，抽屉的「保存」只写样式，不写尺寸。于是「基本信息保存了」
和「画布尺寸保存了」是两件事，用户无法从抽屉本身判断哪些数据真的落库。

**根因**：v0.3.9 起抽屉被改成草稿表单（FEAT-E01），但 `onRequestResize` 仍复用 v0.3.8 的
外部流程——画布尺寸被排除在草稿与 `onCommit` 之外。

**规则**

1. 抽屉是一个完整表单：**画布尺寸与所有样式字段同属一份草稿**，`保存` 一次性提交。
2. `onCommit` 签名扩展为 `(style: MapStyle, gridSize: number) => void`；父页面据此：
   - 样式写入 `editor.setMapStyle`；
   - 尺寸不同则写入 `editor.setGridSize`；
   - **立即把整份草稿（样式 + 尺寸 + 其余地图数据）保存到服务端**，然后关闭抽屉。
3. `isDirty()` / 「保存」按钮的可用态同时比较样式草稿与尺寸草稿。
4. `discard()` 同时回滚样式草稿与尺寸草稿。
5. 持久化必须是**全量**的：`editor.toDraft()` 已输出完整 `style`（`resolveMapStyle` 补全所有
   字段），本版不再接受「只保存部分字段」的路径。

**验收**

- 修改画布尺寸 + 任一线条宽度，点「保存」→ 两者都出现在随后保存到服务端的草稿里；
- 只改画布尺寸，「保存」可用；只改样式，「保存」可用；
- 「取消」后画布尺寸恢复为打开抽屉时的值。

## 2. FIX-F02 数值控件实时写入草稿

**现象**：以「线条 → 网格分隔线 → 线宽」为例，用输入框右侧的微调按钮（或键盘上下键）
把 2 加到 3 之后，「保存」仍然是灰的；必须把焦点移出数值框（或按回车）让 `blur` 触发提交，
按钮才可用。

**根因**：`NumberField` 内部维护一份**文本草稿**，只在 `onBlur` / `Enter` 时才 `commit`。
点击微调按钮不产生 blur，所以上层草稿（以及 `dirty`）毫无变化。

**规则**

1. `NumberField` 在**每次 `change`** 时就把可解析的数值提交给上层草稿（实时更新），
   `onBlur` / `Enter` 仍保留，用于兜住非法输入与失焦收敛。
2. 提交的值仍走各自的 clamp（线宽、字号、间距、方格大小、画布尺寸），因此越界输入会被
   立即收敛到合法区间。
3. 「保存」按钮不再需要额外交互即可点亮。

**验收**

- 点击线宽微调按钮 +1 → 「保存」立即可用，无需回车；
- 输入 `abc` → 不失焦也不提交，失焦后回退到原值；
- 输入 `999` → 实时收敛到上限，草稿记录的是收敛后的值。

## 3. FIX-F03 画布尺寸首次进入编辑器即保存

**现象**：新建项目后第一次进入编辑器，`map_projects.grid_size` 有值，但草稿里的
「地图基本信息」（`style` 块）从未落库——`draft_data.style` 为 `null`。此时发布作品，
样式靠 `resolveMapStyle(undefined)` 现场补默认值；一旦以后调整过默认值或迁移，
「编辑器里看到的」和「草稿里存的」就不是同一份数据。

**根因**：`style` 只在用户显式保存时才写入草稿，没有任何「首次进入即固化」的动作。

**规则**

1. 编辑器初始化完成后，若本次加载的草稿**没有 `style` 块**（即基本信息从未保存过），
   且当前没有用户改动（`!editor.dirty`），则自动保存一次地图：
   写入整份草稿（含 `resolveMapStyle(undefined)` 补全的样式与 `gridSize`）。
2. 自动保存只做一次（每个项目一次），成功后 `markSaved` 并刷新版本信息。
3. 已有 `style` 的项目不触发自动保存。
4. 自动保存给出轻量 toast，让用户知道发生了什么。

**验收**

- 新建项目首次进入编辑器 → 草稿 `style` 落库（重新进入编辑器，基本信息里的值与默认值一致，
  且刷新页面不再触发自动保存）；
- 老项目（已有 `style`）进入编辑器 → 不触发自动保存，不产生多余的写入。

## 4. FIX-F04 `input type="color"` 去掉黑色边框

**现象**：基本信息里的颜色控件（原生取色器）外围有一条接近黑色的边框，在一排浅色控件里
非常突兀。

**规则**

1. 新增共享组件 `packages/web/src/components/ui/color-input.tsx`：
   `type="color"` 去掉 `border`，只保留圆角与极淡的内描边（`ring-1 ring-border`），
   并清掉浏览器默认的色板内边框（`::-webkit-color-swatch` / `-wrapper`）。
2. 基本信息中所有颜色输入（画布外框、网格分隔线、鼠标光标框、操作光标框、区域轮廓线、
   区域高亮线、区域标签、联动主题色、阴影环）统一改用该组件。
3. 行为不变：仍是受控组件，`onChange` 直接提交上层草稿。

**验收**

- 界面上不再出现黑色取色器边框；白色取色块仍有可辨轮廓；
- 所有颜色控件走同一组件（源码断言）。

## 5. FIX-F05 去掉画布尺寸确认弹窗与提示文本

**现象**：在基本信息里改画布尺寸会弹出「调整画布尺寸」大弹窗（滑块 + 预览网格 + 影响清单），
并且抽屉里还有一行「调整画布尺寸会先弹出确认，确认时会先保存草稿。」的说明文字。
用户已明确不需要这套确认。

**规则**

1. 基本信息中的画布尺寸**不再弹确认框**：输入即改，随「保存」一起提交（见 FIX-F01）。
2. 删除该行提示文本；提示内容并入标签后的问号图标（SPEC-F01）。
3. 底部工具条的「调整画布尺寸」入口与弹窗**保持原样**（那是另一条路径，带影响预览，
   缩小画布有破坏性，保留确认更安全）。
4. 越界内容的移除发生在保存时，由 `editor.setGridSize` 完成，并以 toast 汇报移除数量。

**验收**

- 基本信息里改画布尺寸 → 无弹窗；点「保存」→ 尺寸生效并落库；
- 缩小尺寸导致内容越界 → toast 提示移除数量，地图可撤销。

## 6. SPEC-F01 提示文本改为标签后的圆形问号图标

**现象**：各字段的说明文字零散落在标签的 `title` 属性或字段下方的灰色小段落里，
布局不统一，也容易被忽略。

**规则**

1. 每个需要说明的标签后面跟一个**圆形问号图标**（`HelpCircle`，14px，`text-muted-foreground`），
   悬停显示完整说明（沿用 `title`，并补 `aria-label` 便于读屏）。
2. 原先游离在字段下方的说明段落，内容并入对应图标的提示文本，**段落删除**，
   避免同一句话出现两遍。
3. 图标只加在**有说明的标签**上；「线宽 / 颜色」这类子行不加。
4. 提示文案使用《画布图层优先级规范》§1 的规范中文名与英文名。

**验收**

- 画布、方格大小、画布外框、网格分隔线、鼠标光标框、操作光标框、区域轮廓线、
  区域高亮线、区域标签、标尺、联动主题色均有问号图标；
- 抽屉内不再有游离的说明段落；
- 图标可悬停出提示，且不遮挡控件。

## 7. FIX-F06 性别符号 ♂ / ♀ 加粗

**现象**：`GenderBadge` 的性别符号与旁边的文字一样细，在 13px 的符号上显得发虚。

**规则**：符号字号保持 13px，`fontWeight` 提升到 `700`；颜色（男浅蓝 / 女浅粉）不变。

**验收**：编辑器与预览页所有出现性别符号的位置均为加粗字形。

## 8. FIX-F07 预览页参与者区与编辑页一致

**现象**：编辑页左侧是「矩阵卡片」式的参与者区（主题色圆头像 + 序号 + 线索区 + 单框高亮），
预览页却是一条 256px 宽的纵向列表（40px 圆头像 + 名称 + 「参与者框 #N」），
两处的布局、尺寸、信息层级完全不同。

**根因**：预览页单独实现了一份列表，没有复用 `ParticipantPanel`。

**规则**

1. `ParticipantPanel` 增加**只读模式** `readOnly`：
   - 不注册拖拽（无 `setPointerCapture`、无 `onDrag*`）；
   - 不渲染「×」移出按钮；
   - 槽位光标为 `pointer`（而非 `grab`）；
   - 其余渲染（矩阵布局、列数自适应、序号、主题色圆头像、线索区、单个 `boxShadow` 高亮框、
     `hover:border-primary`）与编辑页**完全同一套代码**。
2. 预览页改为直接渲染 `ParticipantPanel`（`readOnly`），删除自建的列表 DOM；
   激活 / 悬停高亮仍走预览页自己的 `reduceLinkageActivation` 状态机。
3. 头部文案统一为「参与者 已用 / 总槽位」；空态文案在只读模式下为「该作品暂无参与者」。
4. 所有交互回调（`onSelect` / `onDrag*` / `onClearRequest`）在只读模式下改为可选，
   组件不再强制传入。

**验收**

- 同一份作品在预览页与编辑页的参与者区：卡片尺寸、间距、列数、头像大小、序号位置、
  线索区高度、高亮框样式一致；
- 预览页无法拖动、无法移出参与者；
- 悬停 / 点击的高亮与激活行为与编辑页一致。

## 9. FEAT-F01 预览页支持显示 / 隐藏标尺

**现象**：预览页没有标尺，读者无法按行列描述位置；编辑器里则一直有（且可切换）。

**规则**

1. 预览页顶栏新增「标尺」开关按钮（`Ruler` 图标，`title="显示 / 隐藏标尺"`），
   默认**显示**，与编辑器默认一致；状态存 `localStorage`（键 `murdoku.workview.ruler`）。
2. 抽出共享组件 `packages/web/src/components/map/MapRulerStrips.tsx`，
   编辑器与预览页共用同一份实现（列标尺 / 行标尺、`buildRulerGlyphs`、`rulerStripSize`、
   `paddingBottom/Right = style.ruler.gap`、透明无边框、随 `scale × zoom` 缩放）。
3. 预览页没有「操作光标框」，因此标尺的 `operationIndex` 恒为 `null`，
   只有「悬停行列变深灰」一档。
4. 标尺开关切换后重新执行一次自适应（`fit`），保证留白随之变化。

**验收**

- 顶栏按钮可切换标尺；关闭后画布重新撑满可用区域；
- 标尺字号与间距取自作品快照里的 `style.ruler`（见 FEAT-F02）；
- 编辑器标尺表现不回退（共用组件）。

## 10. FEAT-F02 预览页尺寸一律按保存的基本信息渲染

**现象**：预览页虽然读了 `style`，但自适应时调用的是 `canvasInsets()`（不带 `showRulers` /
`rulerSize`），等于**没有给标尺留位**；于是预览页的方格大小与「编辑器里保存时的观感」
并不一致。

**根因**：`canvasInsets` 的参数没有被传下去， ruler 相关预留宽度恒为 0。

**规则**

1. 预览页 `fit()` 传入 `canvasInsets({ showRulers, rulerSize: rulerStrip })`，
   与编辑器用同一个函数、同一套预留（编辑器另有 `showBottomBar`，预览页没有底部工具条）。
2. 方格大小取 `effectiveCellSize(autoCellSize, style)`——`style.cellSize` 有覆盖值就用覆盖值，
   否则用本次自适应值（已在 v0.3.8 落地，本版补齐留白后真正与编辑器一致）。
3. 所有线条 / 字号 / 颜色 / 标尺配置均来自快照里的 `style`，不使用任何页面级常量覆盖。
4. `rulerStrip` 由 `rulerStripSize({ maxFontSize, gap })` 依据 `style.ruler` 计算，
   与编辑器完全一致。

**验收**

- 编辑器保存后立即发布，预览页的方格大小、四周留白、标尺厚度与编辑器一致；
- 修改 `style.ruler.fontSize` 后，预览页标尺条随之变厚，画布留白随之变化。
