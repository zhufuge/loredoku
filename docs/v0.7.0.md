# 需求 + 设计：地图编辑器与区域样式重构（v0.7.0）

> **状态**：**已实施**（2026-10-20）。设计即本文；落地记录见 §7，与设计的偏差见 §7.2。
> 需求原文：
> ```
> 优化
> - 已选中状态的图标底色不够明显
> 地图展示优化
> - 网格分割线与画布外框的位置
> - 网格框最外描边线 = 画布外框
> - 地图放大到一定程度，标尺有部分被遮挡
> 地图编辑器使用优化
> - 选区域，默认启用自由笔刷，删除矩形选中按钮和功能
> - 选错了不能清除单个，添加再次选中已选中的格子时清除
> - 画笔选区域，鼠标划过的地方选中
> - 将平移功能及按钮加到工具栏中
> - 选中橡皮擦时，资源和区域可用，但点击某个资源或区域按钮时，取消橡皮擦功能，切换到对应功能
> 地图编辑器-区域
> - 左边区域模块内，编辑按钮的弹窗内容，放到点击某个项区域后的右边信息框中
>   （和点击地图的区域标签弹窗内容合并），点击区域标签和点击列表项的弹窗一致
> - 内容从编辑中的区域颜色，边界线宽，填充透明度改为：
> - 区域轮廓线
> - 区域高亮线
> - 区域标签
>   - 字体 - [输入框（填写字体大小）] 颜色[输入框（颜色#rrggbb)]
>   - 描边 - [输入框（填写描边大小）] 颜色[输入框（颜色#rrggbb)]
>   - 高亮 - [输入框（填写字体大小）] 颜色[输入框（颜色#rrggbb)]
>   - 高亮描边 - [输入框（填写描边大小）] 颜色[输入框（颜色#rrggbb)]
> - 基本信息框的内容也改成相同的布局
> - 区域信息框，内容默认填入基本信息框数据，保存时，与基本信息相同时不配置到区域信息里，不同才记录
> - 展示时，已区域信息为主，基本信息数据为缺省值
> ```

## 0. 一句话

四件事：

1. **区域样式三级化**——区域的外观从「颜色 + 边界线宽 + 填充透明度」三项，换成
   **轮廓线 / 高亮线 / 标签（字体 / 描边 / 高亮 / 高亮描边）** 三组；地图级
   「基本信息」是缺省值，区域只记**与缺省不同的字段**（`DraftRegion.style`
   深 partial）。**编辑弹窗搬进右边信息框**，与点区域标签打开的是同一个面板。
2. **区域工具只剩自由笔刷**——矩形选中按钮与功能删除；起点格已选中的笔画整段
   清除，单个错格不再无处可改。
3. **画布与标尺归位**——网格最外一圈描边线与画布外框合成同一条线；放大后标尺
   薄轴贴边，不再被容器拦腰裁掉。
4. **工具栏补平移**，选中态改用主色 + 光环；橡皮擦不再锁死左侧面板，点资源 /
   区域即切回对应工具。

## 1. 改之前是什么样

- 区域的 `DraftRegion` 直接存 `color` / `borderWidth` / `fillOpacity`：每建一个区域就
  复制一份地图级缺省，改地图级缺省对存量区域毫无影响（旧代码靠 `setMapStyle` 向所有
  region 镜像 `borderWidth` 硬撑）。
- 区域编辑是一个独立 `Dialog`（`RegionDialog` 的 edit 模式），左侧列表还有个铅笔按钮；
  点画布上的区域标签与点列表项走的是两条路。
- 区域工具有「矩形 / 自由笔刷」两个子按钮，矩形模式点错一格只能整个「清空」重来。
- 画布外框（`MapCanvasFrameLayer`）用 `translate(-w/2)` 把描边画在画布边界**外侧**，
  与「网格最外一圈 = 画布外框」的诉求相反；网格分隔线则以方格中心对齐，两条线位置
  口径不一致。
- 标尺带子是 `absolute` 且随 `pan` 整体平移，容器 `overflow: hidden`；放大后
  `0 < pan < rulerStrip` 时带子薄轴伸出容器，贴容器边锚定的文字被裁掉一半。
- 橡皮擦激活时左侧面板 `pointer-events-none`——想擦完直接放东西，必须先手动切回
  选择工具。

## 3. 设计：区域样式三级化

### 3.1 数据形状

```ts
// shared/src/types/domain.ts
interface DraftRegion {
  id: string;
  name: string;
  cells: Coord[];
  labelCell?: Coord;
  /** 只记与地图级缺省不同的字段；全同则整个键缺席。 */
  style?: RegionStyleOverride;
}

interface RegionStyle {
  outline: RegionLineStyle;     // { width, color }
  highlight: RegionLineStyle;
  label: RegionLabelStyle;      // 8 字段，见下
}
interface RegionStyleOverride {
  outline?: Partial<RegionLineStyle>;
  highlight?: Partial<RegionLineStyle>;
  label?: Partial<RegionLabelStyle>;
}
```

`RegionLabelStyle` 新增 `hoverStrokeWidth`（`STYLE_DEFAULT_REGION_LABEL_HOVER_STROKE_WIDTH
= 10`）——需求里的「高亮描边 - 描边大小」此前没有对应字段。`color` / `borderWidth` /
`fillOpacity` 三个旧字段从 `DraftRegion` 删除；`MAP_JSON_VERSION` 6 → **7**。

### 3.2 单点合并与单点反推

- `resolveRegionStyle(base, override?)`（`web/src/lib/regionStyle.ts`）：所有渲染链路
  的唯一取值口。outline 宽走 `clampRegionBorderWidth`（4~12 自有区间），highlight 宽走
  `clampLineWidth`；hover 字号对**解析后**的 fontSize 套 FIX-M02「永不更小」规则。
- `regionStyleOverride(style, base)`：反推最小差异，全同返回 `undefined`——**保存时的
  唯一出口**，所以「与基本信息相同不记录」是结构保证，不靠调用方自觉。

### 3.3 存量数据：迁移 + 吸收双轨

- 迁移 `20260101000030_v070_region_style.ts`（单事务逐行重写 `maps.data` 与
  `games.snapshot.map`）：旧 `borderWidth` 与行内地图级缺省**不同**才记
  `style.outline.width`；`color` / `fillOpacity` 直接丢弃（填充层整个退役）。
- 吸收层 `mapDraftCompat.absorbLegacyMapDraft` 读同款形状（未跑迁移的旧客户端 payload
  也能读）。纯转换放 `server/src/service/regionStyleMigration.ts`，可脱离 DB 单测，
  与 `draftLinkageMigration` 同一模式；up/down 互为逆运算。

### 3.4 填充层退役

区域填充（`MapRegionFillLayer` + `REGION_FILL_Z` + 填充透明度）整条链路删除——新模型里
区域只有「线」没有「面」，`REGION_FILL_OPACITY_*` / `REGION_BORDER_WIDTH_DEFAULT` /
`REGION_TRANSPARENT_FILL_OPACITY` 常量一并清理。`docs/layer-priority.md` §2 表格与
§3.7 / §4.4 同步改写。

## 4. 设计：信息框布局（两个框同一套）

```
区域轮廓线    [线宽 4~12] [颜色]
区域高亮线    [线宽 1~12] [颜色]
区域标签
  字体        [字号 9~48] [颜色]
  描边        [描边 1~12] [颜色]
  高亮        [字号 9~48] [颜色]
  高亮描边    [描边 1~12] [颜色]
```

- 共享组件 `RegionStyleEditor`（`web/src/components/map-editor/`）+ 从 `MapInfoDrawer`
  抽出的 `StyleFields`（`NumberField` / `ColorField` / `Hint` / `Row`）。**一个实现，
  两个宿主**：地图基本信息（值 = 地图级缺省本体）与区域信息框（值 = 解析后的区域样式）。
- 区域信息框的表单用解析值播种，`保存` 把解析值交给 store，由
  `regionStyleOverride(input.style, next.style)` 反推——**编辑器自己不算差异**。
- 字号 / 高亮字号在编辑器里就维持「高亮 ≥ 常规」，与渲染端 FIX-M02 同一条规则，
  避免两个框对不上。

## 7. 实施记录（2026-10-20）

### 7.1 落地清单

与 §5 落点表一致。DB 实测：up 后 92 个 region 与期望逐字段 0 差异（15 个
`borderWidth = 6` 的行其地图级缺省也是 6 → 正确地不记 override）；down 后与原始快照
0 差异；再 up 稳定（JSON 串差异仅为 pg 行序与键序）。

### 7.2 与设计的偏差

- **标尺不需要宿主测量**：原设计打算用 `ResizeObserver` 量容器尺寸再决定薄轴位置；
  实际推演发现「薄轴负值即被 `overflow: hidden` 拦腰裁」只取决于 `pan` 与带厚，
  `max(0, pan - rulerStrip)` 已足够，长轴仍跟随棋盘（远端裁剪是应有行为），glyph 相对
  长轴边定位故对齐不受影响。比原设计更简。
- **`RegionInput.style` 收解析值而非 override**：store 的 `createRegion` /
  `updateRegion` 自己调 `regionStyleOverride(input.style, next.style)`，编辑器只管展示
  与收集解析值——差异计算只有一个出口。
- **`EditorInfoDrawer` 的 dirty 上报**：区域表单的未保存修改原先随对话框一起被模态
  拦住，搬进抽屉后需要显式上报（`onRegionDirtyChange`）才能进离开编辑器拦截。

## 8. fix：工具栏选中态与图标按钮底色（2026-10-20 晚，用户反馈）

§7.1 把「已选中状态的图标底色不够明显」做成了主色（`variant="default"`）+ 主色光环，
用户反馈**太过明显**。本轮调整：

- **选中态回淡灰**：`secondary` / `accent` 在浅色主题同值 `hsl(210 40% 96.1%)`
  （≈ slate-100），选中与悬停都几乎看不出底色。统一下沉一档到 **slate-200**
  （`#e2e8f0`，同色相深一档，仍是淡灰），深色主题对称取 slate-700；悬停时选中项再深到
  slate-300 / slate-600。去掉主色与光环。
- **未选中态悬停也加深**：从 `hover:bg-accent`（≈ slate-100）改为半透明
  `slate-200/70`（深色 `slate-700/70`）。
- **两个常量单点收口**：`web/src/lib/toolbarButtons.ts` 的
  `TOOLBAR_ICON_ACTIVE_CLASS` / `TOOLBAR_ICON_HOVER_CLASS`，编辑器与游戏页共用，
  保证同一档手感。
- **覆盖面**（用户要求「其他编辑页面和游戏页面的图标按钮也加深一点」）：
  - `EditorBottomBar`（地图编辑器 + 谜题编辑器画布共用）：四个工具按钮、「物品」开关、
    标尺开关、尺寸按钮、缩放 / 适应 / 撤销 / 重做；
  - `PuzzleBottomBar`（谜题编辑器画布工具条）：同构的一套；
  - `EditorLeftPanel` 的「资源 / 区域 / 角色」tab（选中态 `bg-secondary` → slate-200）；
  - `PuzzleEditorLeftPanel` 的展开 / 收起小图标按钮；
  - `GamePage`：右栏工具栏（禁止符号 / 清除 / 撤销 / 提交 / 缩放簇 / 标尺开关，激活态原为
    `bg-accent`）+ 左上角返回按钮。

抽屉与对话框内的关闭按钮、列表项 hover 等不属工具栏，未动。

## 9. fix：标尺文本 / 工具互斥 / 区域列表信息框（2026-10-20 晚，用户反馈）

### 9.1 放大后标尺文本仍展示不全

§3 的 `clampRulerStripStart` 只修对了一半：它修掉了「薄轴伸出容器被拦腰裁」，但**行标尺
的薄轴是水平的**——`rulerStripSize` 一直只按「字形高度 + 间距」定条厚，而 `R12` 这类标签
宽 ≈ 3 × 0.62em，只要字号 > ~7px 就比条子宽，条子自己的 `overflow: hidden` 把标签左边裁掉。
zoom 1 时被 `RULER_SIZE = 28` 的下限掩着，一放大就露出来（默认样式 zoom 1 裁 ~12.6px，
zoom 2 裁 ~31px）。

- **行条按标签宽度定尺**：新增 `rulerLabelWidth(gridSize, fontSize)`（与 v0.6.4
  `glyphFontSize` 同一套字宽模型，抽到 `lib/textWidth.ts` 的 `textEmUnits` /
  `estimateTextWidth` 两边共用）；`rulerStripSize` 加可选 `maxLabelWidth`。
  两个薄轴从此**各自定尺**：列条 = 字形高度 + 间距，行条 = max(字形高度 + 间距,
  标签宽 + 间距 + 2)。
- **薄轴起点改「贴棋盘边，放不下就贴视口边」**：`clampRulerStripStart` 换成
  `rulerStripStart(boardEdge, stripSize, textExtent, gap)` =
  `max(boardEdge - size, textExtent + gap - size)`。贴不上时条子向内移，直到标签
  **开口边正好在视口边缘**——标签完整，代价是轻微压住棋盘边上的几列（替代方案是裁标签）。
  比 §8 的 `max(0, …)` 少压一点，且任何 `boardEdge` 下标签都不再被裁（回归用例遍历
  -500 ~ 500 钉住「要么贴棋盘、要么贴视口边」）。

### 9.2 区域 / 平移工具下，左面板照常可点，点击即取消当前功能

- 删掉 `panelsLocked`（原先区域工具激活时左面板整块半透明锁死，资源和区域点不到）。
- `onSelectAsset`：原来只有橡皮擦会退，现在**任何非 select 工具**下点资源都先
  `setTool('select')` 再选中——store 的 `setTool` 离开区域工具时本来就清圈选草稿，
  所以这条打断路径不会留下不能确认也不能取消的半截选区。
- `onSelectRegion`（区域列表）：同样先取消当前工具再聚焦。

### 9.3 点区域列表项，信息框空白

左面板列表点击只调了 `editor.setSelectedRegion(id)`，**没设 `selection`**——抽屉的打开
条件是 `infoOpen`（由「任一聚焦轴非空」的 effect 置 true），而区域分支渲染要求
`selection.type === 'region'`，于是抽屉弹出来却是空的。画布上的区域标签没问题，因为它走
`onSelect({type:'region'})` + `onSelectRegion(id)` 两个 prop。

修法：列表点击与标签点击**同一套动作**（抽成 `regionFocusSelection(regionId)`，由
editorFocus 单测钉住）。没有把 `setSelectedRegion` 改成顺便写 `selection`——`selectCellAt`
是先写 `selection`（cell）再写 `selectedRegionId`（所在区域），store 里合并会反过来覆盖格子焦点。

## 12. fix：区域轮廓线贴边被 SVG 视口裁掉（2026-10-20 晚，用户反馈）

图层换位后暴露出来的一条老问题：铺到画布最外沿的区域，边界那条轮廓线比其它三边**细一半**，
看起来像在画布外框里又多出「一圈线」。

- 根因不在图层，也不在画布外框：`MapRegionOutlineLayer` 的 `<svg width={total} height={total}>`
  默认 `overflow: hidden`。描边以轮廓线为中心（`strokeWidth/2` 在内、`strokeWidth/2` 在外），
  落在 `x = 0 / total`、`y = 0 / total` 上的边有一半在视口外，被裁掉后只剩半条宽。
  画布外框一直靠 `overflow: visible` 规避同一问题，区域轮廓线漏了这一步。
- 修法：区域轮廓 SVG 加 `overflow: visible`——即「往外扩展」，几何一点没动，
  贴边的边整条画出，与其余轮廓同宽。四页（编辑器 / 预览 / 游戏 / 谜题预览）共用同一组件，
  一处改全部生效。
- 回归：`MapRegionLayers.test.tsx` 断言 SVG `overflow === 'visible'`，并渲染「角上一格」
  确认 4 条边里贴边界的 2 条都在（几何不被裁剪逻辑改写）。

## 13. fix：未选中资源时不展示芯片（2026-10-20 晚，用户反馈）

> 未选中资源时，不展示图片框和「未选择资源」文本。

§10 原设计给未选中态留了虚线方块 + 文案占位（理由是「槽位不跳动」）。实际看下来
工具条上常态挂着一块虚线框反而更像加载失败 / 未配置状态，用户要求直接不要。

- **未选中 = 整块不渲染**：`selectedAsset && selectedForm` 才渲染芯片，否则 `null`。
  虚线占位框与「未选择资源」文案一并删除，`ImageIcon` 导入随之移除。
- **分组分隔线保留**：芯片后面的 `|` 分隔线**不跟着条件走**——它分隔的是「物品组」与
  「标尺 / 尺寸组」，与芯片在不在无关。否则未选中时 `物品` 会和标尺粘成一组。
- **副作用**：未选中时点击芯片展开面板的入口消失了；此时左面板必然可见（选中态本来
  就只从面板里来），展开入口不需要存在。
- 回归：`EditorBottomBar.test.tsx` 第 3 例由「占位文案」改写为「不渲染芯片」——
  断言 `未选择资源` 不在 DOM、没有 title 含「资源面板」的按钮，同时确认物品开关 /
  `12×12` / `100%` 仍在（分隔线与其余控件不受影响）。
