## §1 提交之后的逐人校验

### 1.1 时序

`submit()` 不再同步结算：它先把 `validatePlacement` 的结果按参与者摊成一份
`CheckItem[]`（每位一项：位置 + 通过与否），进入 `checkRun` 状态，然后每
`GAME_CHECK_STEP_MS`（480ms）揭一位 —— 圈画上，再等下一拍。全部揭完才把 `result`
置上、弹结算卡。

- 每位的圈从 0 扫到满用 `GAME_CHECK_RING_SWEEP_MS`（360ms）——「正在核对这一位」；
  到下一位的间隔 480ms 里含扫完后的一小段停顿，节奏上先看见结论再翻页。
- `runId` 每次提交递增：`PressRing` 靠 `seq` 强制重建节点，同一格连按两次也要从头扫。
- 提交期间 `readyToSubmit` 挡住二次提交，`main` 加 `pointer-events-none` 锁掉画布；
  重新开始 / 关闭弹窗 / 继续游戏三个出口都会清掉 `checkRun`，不留半截状态。

### 1.2 遮罩

需求原话是「除了地图外其他地方加透明遮罩」。实现：校验进行中（`checkRun && !result`）
给 `aside`（人物栏 + 线索栏）盖一层 `bg-background/70`（`data-testid="check-scrim"`，
`UI_Z.saveMask` 层级）。地图不动 —— 它是主角。弹窗打开后遮罩撤掉（Radix 弹窗自己
有 overlay），`4-end` 实测 `scrim=false` 而 `1-step0` 有，行为正确。

### 1.3 圈

`MapGameCheckLayer` 复用 `PressRing`（v0.9.2 已支持 `imageUrl` 图模式）：

- 通过 → `passColor` 的圈；未通过 → `failColor` 的圈。**两档都走同一段扇形
  扫描**（`GAME_CHECK_RING_SWEEP_MS`）—— 扫描说的是「正在核对这一位」，不是
  结论本身；原始需求里「没通过则是圈住」若要做成不扫描，见 §7。
- 圈图（作者上传的那张）在**两种结果下都画**：§5 起它是唯一载体 —— 整张被染成
  结果色；没配图时才回落到内置的本色细弧。两者互斥，不会同时出现。

## §2 校验样式进主题配置

- `themes.data.checkStyle = { passColor, failColor, ring?: { path } } | null`，
  主题级一档 —— 校验是「这个世界怎么回应你」，不做谜题级覆盖。
- 主题概览页「提交校验」卡：**校验通过色 / 校验未通过色**两个取色器（即时保存，
  `PATCH /themes/:code/check-style`），**校验圈**一张图（上传 / 更换 / 移除，
  长边 256 的 webp，存 `themes/<id>/check-ring/`）。移除只删图，颜色留着。
- 老主题没配 → `resolveCheckStyle` 落回内置绿 `#16A34A` / 红 `#DC2626`；
  取色器写坏的值（空串、`#GGG`）在这里挡掉，不会让 CSS 静默丢声明、圈「看不见」。
- 导出包：圈图只装一份 `files/check/check-ring.<ext>`（与计时环同一款「主题级一张」
  的处理），路径进 `manifest.theme.checkStyle`；颜色是 JSON 原样进包。

## §3 定案卡

通过的那一面换了写法：

- 标题**「定案」**（楷体、`tracking-[0.3em]`），`sr-only` 的描述兜住无障碍；
- **不报用时**、不写「校验通过」—— 局已经结束，界面该说的是「结案了」，不是再念
  一遍成绩。用时对玩家没有下一步动作可指导。
- 结束语成为卡上唯一的正文（作者的话不加标签），标题与正文之间补一条细线。
- 右上角**印章**：只在作者给「提交」配了图时才有（内置 lucide 勾是一枚界面图标，
  盖上去像把按钮按进纸里，不是一个印）。`.stamp-press` 420ms：从 1.7 倍 −18° 落到
  0.92 倍再回弹到正位、停在 −8°（盖下去总有一点点歪）。`transform-origin 60% 40%`
  让落点偏右上，像手劲。
- 按钮是「关闭 / 再玩一次」。

未通过的那一面保持 v0.7 的清单（谁不对 + 继续游戏 / 重新开始）—— 那是「还在改」
的状态，不配「结案」的仪式。

## §4 × 悬停预览的白描边

- 悬停预览的 `×`（没配图时的内置字形）从黑描边改成 `stroke="#FFFFFF"`—— 它跟着
  指针走、压在地图照片上，黑边在暗处等于没有边（与 v0.9.1 §5 给清除图标立过的
  规矩同一条）。
- **已放置的 `×` 仍是黑边**：内容与预告用两种描边区分 —— 指针底下那枚是「将要
  落下的东西」，落下去的那枚是「棋盘的一部分」。
- 配了图的禁止符号，悬停预览也走 `hintOutlineFilter`（4 向硬 `drop-shadow`，
  跟 alpha 走），与清除图标同款。

## §5 结果色染到已上传的圆圈图片上

> 同日追加。用户：「通过和未通过的颜色引用到图片上，如果有图片的话」；
> 看完第一版后又纠正一句「**是给已上传的圆圈图片染色**」—— 按这句把实现改定，
> 本节记录的是改定后的形态。

### 5.1 问题与纠正

§1 里配了圈图时，图铺满整格、按原色画；结果色只在旁边那道细弧上。作者上传的
多半是一枚红章 —— 一圈红章 + 一道绿弧，两个信号互相打架。

第一版我给图加了「亮度 × 结果色」的染色，却**仍保留那道结果色细弧**，等于还是
两个载体。用户要的是：颜色就由**那张已上传的圆圈图片**自己承载，不在图外面再
补一圈；而且「染色」要染出作者挑的那个颜色，不该被图片本身的深浅改写。于是
定成两条：

1. 有图 → **只画这张图**，整张换成纯结果色；不画细弧。
2. 没图 → 才回落到内置的本色细弧（v0.9.3 之前的行为）。

### 5.2 做法

`PressRing` 新增可选 `imageTintColor`（只收 `#RRGGBB`），图模式下给 `<image>`
挂一条 `feColorMatrix`：

```
R' = 0·R + 0·G + 0·B + 0·A + r
G' = 0·R + 0·G + 0·B + 0·A + g
B' = 0·R + 0·G + 0·B + 0·A + b
A' = A
```

前三行的常数项就是结果色的三个分量（0~1），第四行只搬 alpha。于是图里每个
像素不论原色深浅都变成同一个绿 / 红，而**形状、镂空的字、透明区完全不变**；
也不会像 `feFlood` 那样把透明背景涂成方块。

- `colorInterpolationFilters="sRGB"`：SVG 滤镜默认在 linearRGB 里算，不指定会让
  颜色与主题配置页取色器看到的不是同一个值。实测染色后像素精确等于配置色。
- 不用「亮度 × 结果色」了：深色章染出来会发暗，那不是「给图片染色」，是给图片
  调了个深色。纯色剪影这一步没有抹掉信息 —— 上传的是圆圈，镂空与透明靠 alpha
  表达，与颜色无关。

`MapGameCheckLayer` 里 `ringUrl` 一个 `if/else` 把两份渲染彻底分开：有图走染色图，
没图走细弧，两者都吃同一个 `sweepMs`（扇形揭开的节奏不变）。每位的结果色仍是
`mark.passed ? passColor : failColor`。**长按计时环不传色** —— 它只报进度、不报
结论，图保持作者画的样子；这次能力是加在 `PressRing` 的可选入参上，不是默认行为。

非法颜色（空串、`#GGG`）返回 `null`、不挂滤镜：SVG 丢掉一条非法声明是静默的，
宁可显示原图，也不要「图忽然不见了」。

### 5.3 验证

- `PressRing.test.tsx` 新增 5 条：矩阵本身（RGB 系数全 0、常数项是结果色、alpha
  行原样）、三个分量的 `#RRGGBB` 换算、非法颜色 `null`、传色时 `image` 挂
  `filter` 且扇形遮罩仍在、**不传色时没有滤镜元素**（长按环不受影响）。

## §7 没做的

- **不给校验加声音**。动效已经把节奏交代清楚，声音是另一档信息。
- **不把遮罩盖到顶栏**。「除了地图外的其他地方」落实为左栏（人物 + 线索 + 工具）；
  顶栏的返回箭头在结算前仍然可用 —— 退出永远是玩家的后路，不该被自己的提交堵死。
- **未通过目前也带扫描**。需求原话是「通过 → 扇形加载圈住；没通过 → 圈住」，
  但代码里那位唯一的一枚 `PressRing`（有图是染色图、没图是细弧）都用 `sweepMs`，
  因此两种结果都扫满一圈。它读起来是「正在核对这一位」而不是结论；若要严格按
  原话让未通过一拍到位，是下一处小改动（给失败的那一枚传 0 时长 / 不加动画）。
- **定案卡不显示用时**（需求明说不要）。作者若想要成绩，那是另一个功能，这一版
  没做。
- **染色不保留原图的明暗与纹理**。按 ③ 的澄清，染色是把整张圆圈图片换成结果色；
  形状只由 alpha 表达（透明区、镂空的字都还在）。若上传的是一张带渐变层次的
  照片式圆环，那些层次会消失 —— 换来的好处是颜色精确等于取色器里那一个。
- **不把结果色也画到长按计时环上**。计时环只报进度、不报结论，`imageTintColor`
  是可选入参，那一支不传。
