## 1. 需求澄清

### CLAR-601 性别仅男 / 女

#### 1.1 字段定义变更

`characters` 表 `gender` 字段：

| 项 | v0.3.0 | v0.3.1 |
|---|---|---|
| 枚举值 | `male` / `female` / `other` / `unknown` | **`male` / `female`** |
| 默认值 | `unknown` | **`male`** |
| 可空 | 否 | 否 |
| 缺失时行为 | 展示为"未设置" | **按 `male` 处理** |

#### 1.2 数据迁移

- 已存在数据中 `gender ∈ {other, unknown}` 或为空的记录 → **统一更新为 `male`**；
- 数据库约束：`CHECK (gender IN ('male', 'female'))`；
- 迁移脚本需在事务中执行，并记录变更行数。

#### 1.3 接口与校验

- `POST /api/characters`、`PATCH /api/characters/:id` 的 Body 中 `gender` 仅接受 `male` / `female`；
- 未传或 `null` / `undefined` → 服务端**归一化为 `male`**，不返回错误；
- 传其他值 → 返回 `40001 参数校验失败`；
- `GET /api/characters` 返回的 `gender` 一定为 `male` 或 `female`，不会出现空值。

#### 1.4 前端表单

- 角色管理页表单「性别」改为**单选按钮组**或**分段控件**：
  ```
  [ 男 ]  [ 女 ]
  ```
- 默认选中「男」；
- 无「其他」「未设置」选项。

#### 1.5 展示

- 列表项、详情、编辑器中的性别标签：
  - 男：`♂`；
  - 女：`♀`；
  - **不再存在无性别标签的情况**（任何角色一定有其一）。

**验收**
- 新建角色默认性别为男；
- 尝试通过接口提交 `other` / `unknown` / 空值 → 分别返回 400 或被归一化为男；
- 历史数据中 `other` / `unknown` / 空 已被迁移为男；
- 列表中每个角色都有 ♂ 或 ♀ 标签。

### CLAR-602 角色槽位区更名「参与者」并采用矩阵布局

#### 2.1 名称变更

| 位置 | v0.3.0 | v0.3.1 |
|---|---|---|
| 编辑器左侧栏区域标题 | 角色槽位 | **参与者** |
| 槽位单项 | 槽位 | **参与者框** |
| 计数文案 | `已放置 x/n` | **`参与者 x/n`** |
| 组件名 | `CharacterSlotColumn` | **`ParticipantPanel`** |
| 空状态 | 「从角色抽屉拖拽到槽位」 | **「从角色列表拖拽到参与者区」** |

> 说明：本版澄清——参与者是**"待加入地图的角色集合"**的展示容器，与"已放置在地图上的角色"在数据上仍是同一个 `characterSlots` 数组，仅视觉与命名调整。

#### 2.2 布局重构：单列 → 矩阵

**原布局**：竖直单列，`n` 个槽位线性排列（在 `n = 24` 时会出现极高的竖条，视觉不平衡）。

**新布局**：根据 `n` 计算最佳矩阵行列数，使整体宽高比接近**黄金分割（约 1 : 1.618 或 1.618 : 1）**。

**计算规则**

给定 `n`，寻找整数 `cols ∈ [1, n]`、`rows = ceil(n / cols)`，使得：

```
aspect(cols, rows) = cols / rows
目标：|aspect - 0.75| 或 |aspect - 0.6| 或 |aspect - 1/1.618| 最小
即：让矩阵的宽高比接近 3:4、3:5 或黄金分割的倒数
```

**简化实现（推荐）**：以黄金分割 `φ ≈ 1.618` 为目标，从 `cols = 1` 遍历到 `n`，取 `|cols / rows - 1 / φ|` 最小的一组；若出现并列，取 `cols` 更小者（更窄更高，与"左栏"更契合）。

**示例**

| n | rows × cols | 实际宽高比 |
|---|---|---|
| 4 | 2 × 2 | 1.00 |
| 6 | 3 × 2 | 0.67（约 2:3） |
| 8 | 3 × 3 | 1.00 |
| 9 | 3 × 3 | 1.00 |
| 12 | 4 × 3 | 0.75（3:4） |
| 16 | 4 × 4 | 1.00 |
| 20 | 5 × 4 | 0.80（4:5） |
| 24 | 6 × 4 | 0.67（约 2:3） |

> 4 的倍数可优先考虑 `cols = ceil(sqrt(n * φ))`；非整数时 `rows` 向上取整，最后一行为短行（居中排列）。

**单元格尺寸**
- 单元格保持正方形，边长自适应容器宽度：
  ```
  cellSize = (panelWidth - gap * (cols - 1)) / cols
  ```
- 面板宽度由内容自适应，但受左栏布局约束（建议最小 120px、最大 240px）；
- 若 `n` 较大导致单元格过小，设最小单元格尺寸 36px，超出时容器出现纵向滚动。

**排列顺序**
- 按 `characterSlots` 数组顺序 **从左到右、从上到下** 填充；
- 最后一行若不满，**整体居中**（不左对齐），视觉更平衡。

**计数显示**
- 面板顶部显示 `参与者 x/n`，`x` 为当前已放置到地图的参与者数量，`n` 为总数量（= `gridSize`）。

#### 2.3 交互保持

- 拖拽参与者框中的头像 → 到画布可站立格；
- 悬停参与者框显示 `×`，点击移除（BUG-402 修复）；
- 参与者框支持拖拽重排（LAYOUT-01）；
- 单击参与者框 → 在**右侧信息抽屉**展示该参与者信息（详见 CLAR-603）。

**验收**
- 左侧栏标题显示「参与者」；
- 面板为矩阵布局，宽高比接近 3:4 / 3:5 / 黄金分割；
- `n = 6` 时为 3 行 × 2 列，`n = 24` 时不超过 6 行 × 4 列；
- 最后一行不满时居中排列；
- 拖拽、移除、重排、点击全部正常。

### CLAR-603 参与者不进入地图，改为信息编辑

#### 3.1 需求修正

**v0.3.0 的行为**：
- 参与者（已放置在地图上的角色）点击 → 弹出 `ParticipantDialog` 弹窗编辑联动配置。

**v0.3.1 的行为**：
- **取消"放置到地图"这一操作**；
- 参与者**不进入地图**，不占据格子，不参与发布校验的"角色位置"逻辑；
- 点击参与者框中的头像 → 在**右侧信息抽屉**中展示该参与者的信息与联动配置；
- **不弹出任何 Dialog**；
- 信息内容中**移除**「坐标」与「是否可站立」字段。

#### 3.2 数据结构调整

地图 JSON 中 `placedCharacters` **废弃**，改为在 `characterSlots` 上直接承载参与者的联动配置：

```jsonc
{
  "characterSlots": [
    null,
    {
      "characterId": 5,
      "themeColor": "#FFCC00",
      "triggers": [
        {
          "trigger": "click",
          "targets": [
            { "type": "character", "id": 7, "effect": "highlight", "color": "red" },
            { "type": "item",      "id": 12, "effect": "highlight", "color": "blue" },
            { "type": "cell",      "x": 3, "y": 4, "effect": "highlight", "color": "red" },
            { "type": "region",    "id": "rg_a1b2c3", "effect": "highlight", "color": "blue" }
          ]
        },
        { "trigger": "touch", "targets": [ /* ... */ ] }
      ]
    },
    { "characterId": 7, "themeColor": "#FFFFFF", "triggers": [] },
    null, null, null
  ]
}
```

**迁移规则**
- 若旧数据中存在 `placedCharacters`，将其 `themeColor` 与 `triggers` 迁移到对应 `characterId` 的 `characterSlots` 元素上；
- 迁移后删除 `placedCharacters` 字段；
- 迁移失败（找不到对应槽位）时，写入第一个空槽位。

#### 3.3 发布校验规则调整

v0.3.0 中的 P1~P6（角色数 = n、行列唯一、每行每列有可站立格）**全部废弃**。

**新的发布校验规则**

| 编号 | 规则 | 说明 |
|---|---|---|
| P1 | 参与者数量 ≥ 1 | 至少有一个参与者 |
| P2 | 每个参与者必须有头像 | 无头像的参与者视为未启用，不计入 |
| P3 | 区域之间无交叉格 | 沿用 |
| P4 | 多格物品完整在画布内、无图层冲突 | 沿用 |
| P5 | 所有参与者的触发配置中引用的对象必须存在 | 角色 / 物品 / 方格 / 区域引用有效 |

> 数独式约束（v0.3.0 的 P1~P6）取消，因为参与者不再进入地图。

#### 3.4 编辑器右侧信息抽屉：参与者信息

点击参与者框中的头像后，右侧信息抽屉展示：

```
┌─ 参与者：村民A ────────────────────────────┐
│ [头像 96×96，背景为主题色]                  │
│ 名称：村民A          ♂  性别：男            │
│ 角色 ID：villager_a                         │
│                                             │
│ 主题色：                                     │
│ [色板 ▾]  当前 ■ #FFCC00                    │
│ （蓝色系不可选）                            │
│                                             │
│ ── 触发效果 ──                              │
│ [点击时] [触碰时]   ← Tabs                  │
│                                             │
│  ▼ 点击时                                   │
│   · 角色 村民B      [高亮] [红/蓝] [删除]   │
│   · 物品 篝火       [高亮] [红/蓝] [删除]   │
│   · 方格 (3,4)      [高亮] [红/蓝] [删除]   │
│   · 区域 森林区     [高亮] [红/蓝] [删除]   │
│   [+ 添加对象]                              │
│                                             │
│ [从参与者区移除]                            │
└─────────────────────────────────────────────┘
```

**与 v0.3.0 的差异**

| 项 | v0.3.0 | v0.3.1 |
|---|---|---|
| 展示形式 | Dialog 弹窗 | **右侧信息抽屉** |
| 坐标字段 | 有（C3, R4） | **删除** |
| 是否可站立字段 | 有 | **删除** |
| 「从地图移除」按钮 | 有 | **改为「从参与者区移除」** |
| 「保存 / 取消」按钮 | 有 | **保留**（在抽屉底部） |

**交互细节**
- 点击参与者框 → 抽屉自动展开；
- 点击画布空白格或另一个对象 → 抽屉切换到对应内容；
- 抽屉编辑的配置直接写入 `characterSlots[i]`，`dirty = true`；
- 抽屉内「保存」按钮：仅在本地草稿变更明显时启用（或采用自动保存，由用户全局保存按钮统一提交）；
- **不弹任何 Dialog**。

#### 3.5 效果渲染调整

**触发方式**：所有联动效果的触发源为**参与者**（在右侧信息抽屉被选中时的预览，或在作品预览页被点击时），不再依赖"参与者进入地图格子"这一前置。

**渲染规则**（沿用 v0.3.0）

| 对象 | 效果 | 渲染 |
|---|---|---|
| 角色 | 高亮角色 | 头像外圈参数色描边 3px + `scale 1.08`，1s |
| 物品 | 高亮物品 | 物品图外覆盖半透明参数色蒙层（`opacity 0.45`），1s |
| 方格 | 高亮方格 | 该格背景层临时替换为参数色纯色块，1s |
| 区域 | 高亮区域 | 区域内所有格背景层临时替换为参数色纯色块，1s |

**高亮层顺序**：网格底色 → 背景层物品 → 区域填充 → 物件层物品 → 区域边框 → **高亮层** → 网格线 → 悬停 / 选中效果 → 区域名称标签。

**触发预览入口**
- 编辑器：在右侧信息抽屉中点击「预览点击效果」/「预览触碰效果」按钮；
- 作品预览页：左侧参与者列表点击 → 触发；
- 触发后效果持续 1s。

#### 3.6 撤销 / 持久化

- 抽屉内所有变更作为**单次原子操作**入撤销栈（可选，也可按字段保存）；
- 保存草稿时，`characterSlots` 中携带 `themeColor` 与 `triggers`；
- 发布时带入 `versions.data`。

#### 3.7 服务端校验（zod schema）

```ts
const TargetSchema = z.discriminatedUnion('type', [
  z.object({ type: z.literal('character'), id: z.number(), effect: z.literal('highlight'), color: z.enum(['red', 'blue']) }),
  z.object({ type: z.literal('item'),      id: z.number(), effect: z.literal('highlight'), color: z.enum(['red', 'blue']) }),
  z.object({ type: z.literal('cell'),      x: z.number(), y: z.number(), effect: z.literal('highlight'), color: z.enum(['red', 'blue']) }),
  z.object({ type: z.literal('region'),    id: z.string(), effect: z.literal('highlight'), color: z.enum(['red', 'blue']) }),
]);

const SlotSchema = z.object({
  characterId: z.number(),
  themeColor: z.string().regex(/^#[0-9A-Fa-f]{6}$/).default('#FFFFFF'),
  triggers: z.array(z.object({
    trigger: z.enum(['click', 'touch']),
    targets: z.array(TargetSchema),
  })).default([]),
}).nullable();

// characterSlots 长度 === gridSize
```

**引用存在性校验**
- `character.id` 必须等于该地图某个参与者的 `characterId`；
- `item.id` 必须在地图 `cells` 中存在；
- `cell.(x, y)` 必须在 `[0, gridSize)` 内；
- `region.id` 必须在地图 `regions` 中存在。

**验收**
- 点击参与者框 → 右侧抽屉展示信息，无弹窗；
- 抽屉中无「坐标」「是否可站立」字段；
- 主题色、触发效果编辑保存后持久化；
- 发布校验按新规则（P1~P5）执行；
- 编辑器内预览触发效果、作品预览页触发效果均正常。

## 2. 优化

### OPT-601 ♂ ♀ 符号上色

**背景**：性别符号当前为默认黑色，视觉上无区分度。

**要求**

| 性别 | 符号 | 颜色 | 色值建议 |
|---|---|---|---|
| 男 | `♂` | 淡蓝 | `#7DB9E8`（或 `#93C5FD`） |
| 女 | `♀` | 淡粉 | `#F4A9C0`（或 `#F9A8D4`） |

**应用范围**
- 角色管理页列表项；
- 角色管理页详情表单标题区（可选）；
- 编辑器右侧参与者信息抽屉；
- 作品预览页左侧参与者列表。

**样式细节**
- 符号与名称之间留 4px 间距；
- 字号与名称一致（12px）或略大（13px）；
- 不建议加粗，避免过于抢眼；
- 与文本混排时垂直居中对齐。

**色盲友好备选（可选实现）**
- 除颜色外增加形状区分：男 `♂`、女 `♀` 本身形状已有差异，无需额外区分。

**验收**
- 男角色列表项显示淡蓝色 `♂`；
- 女角色列表项显示淡粉色 `♀`；
- 编辑器抽屉、预览页一致。

## 3. 数据迁移

本版需要一次性迁移脚本，按顺序执行：

1. **性别字段规范化**
   - `UPDATE characters SET gender = 'male' WHERE gender IS NULL OR gender IN ('other', 'unknown');`
   - 添加 `CHECK (gender IN ('male', 'female'))`；
   - 修改默认值为 `'male'`。

2. **地图 JSON 结构迁移**
   - 对每个 `map_projects.draft_data` 与 `map_versions.data`：
     - 若存在 `placedCharacters`：
       - 遍历每一项，把 `themeColor` 与 `triggers` 写回 `characterSlots` 中对应 `characterId` 的位置；
       - 删除 `placedCharacters` 字段；
     - 若 `characterSlots[i]` 为 `null` 但有对应 `characterId` 的 `placedCharacters` 项 → 视情况填入；
   - 迁移在事务中执行，提供 dry-run 模式。

3. **发布校验规则更新**
   - 服务端移除旧的 P1~P6（数独规则）；
   - 应用新的 P1~P5（见 3.3）。

4. **前端文案替换**
   - 「角色槽位」→「参与者」；
   - 「槽位」→「参与者框」；
   - 「从地图移除」→「从参与者区移除」。
