## 2. FEAT-O01 难度 tag 颜色改淡

### 2.1 现状

`GAME_DIFFICULTY_COLORS` 是五档饱和色（`#22C55E` / `#84CC16` / `#EAB308` / `#F97316` / `#EF4444`），
`GameCard` 在其上铺 `text-white`。整块 tag 在卡片里是最抢眼的元素，压过了封面与名称。

### 2.2 设计

1. `GAME_DIFFICULTY_COLORS` 改为同色系的**浅色底**（100/200 档）。
2. 新增 `GAME_DIFFICULTY_TEXT_COLORS`——底色变浅后白字读不清，改用同色系**深色字**（700/800 档）。
3. `GameCard`：`backgroundColor` 取浅底，`color` 取深字，去掉 `text-white`。
4. `GameDeployDialog` 的五档按钮同口径（`text-white` → 深字），选中态的 `boxShadow` 继续用浅底。

### 2.3 验收

- 卡片上难度 tag 是浅底深字，不再是一片高饱和色块。
- 部署弹窗五档按钮同样是浅底深字，选中态仍可辨。
- `GAME_DIFFICULTY_COLORS` / `GAME_DIFFICULTY_TEXT_COLORS` 两表键集合与 `GAME_DIFFICULTY_LEVELS` 完全一致。

## 4. FEAT-O05 ~ O07 琢玉台与 `/maps`

### 4.1 现状

`/projects` 页标题「地图」，导航第一项「地图」，数据层叫 `projects`（`api/projects.ts`、
`hooks/useProjects.ts`、`projectKeys`、`ProjectsPage`）。

### 4.2 设计

- **O05**：制作端别名「琢玉台」——**只在控制台头部的 logo 后面追加**：在地图页时
  头部显示为 `图标 · 格物 · 琢玉台`（`BrandLogo` 新增 `suffix` 参数，只在 `/maps` 生效）。
  **页面本身不改叫法**（SPEC-O19，见下）：`document.title` 仍是 `地图 · 格物`，
  页面大标题仍是 `地图`，导航第一项标签仍是 `地图`。
- **O06**：路由 `/projects` → `/maps`，`/projects` 保留为重定向。
  数据层同步改名：

  | 旧 | 新 |
  | --- | --- |
  | `pages/ProjectsPage.tsx` / `ProjectsPage` | `pages/MapsPage.tsx` / `MapsPage` |
  | `api/projects.ts` / `projectsApi` | `api/maps.ts` / `mapsApi` |
  | `hooks/useProjects.ts` / `useProjects` / `projectKeys` | `hooks/useMaps.ts` / `useMaps` / `mapKeys` |

  HTTP 端点 `/api/projects*` 是内部接口、用户不可见，按裁定 R2 **不动**（与 v0.5.1 保留
  `/api/games*` 同一口径）。
- **O07**：控制台头部右侧「入局」按钮 → `navigate('/play')`。

### 4.3 SPEC-O19：琢玉台只挂在 logo 后面

用户澄清（v0.5.4 实现后）：「只是 logo 后面加琢玉台，地图管理 `/maps` 页面还是叫地图」。

据此收窄 O05：

| 位置 | 是否出现「琢玉台」 |
| --- | --- |
| 控制台头部 logo 后缀（在 `/maps` 时） | ✅ `[Logo] · 格物 · 琢玉台` |
| `/play` 右上角按钮 | ✅ 「进入琢玉台」 |
| `/maps` 页面大标题 | ❌ 仍是「地图」 |
| `document.title` | ❌ 仍是「地图 · 格物」 |
| 导航标签 | ❌ 仍是「地图」 |

一句话：**琢玉台是制作端控制台的别名，挂在品牌行上；页面里的名词一律保持「地图」**，
否则点导航「琢玉台」进去看到标题「地图」会自相矛盾。

### 4.4 验收

- `/maps` 可访问，`/projects` 重定向到 `/maps`。
- 头部（在 `/maps` 时）：左 `[Logo] · 格物 · 琢玉台`、中导航（第一项「地图」）、右「入局」。
- 页面大标题与 `document.title` 都是「地图」；`MapsPage.tsx` 里**剥注释后**不含「琢玉台」。
- 全仓无残留的 `useProjects` / `projectsApi` / `projectKeys` 引用。

## 5. FIX-O08 ~ FEAT-O11 `/items` 页

### 5.1 O08 去掉两条提示

- `ItemDetailForm`：删掉分类为「背景」时的 `背景类型恒定可站立` 文案分支
  （规则本身不变——`canStandFor()` 仍是唯一真源，只是不再解释）。
- `AppearanceField`：删掉 `不上传图片也能启用，画布上以该色块展示`
  （物品与角色共用，两处一起消失）。

### 5.2 O09 列表不溢出圆角

`ItemListPanel` / `CharacterListPanel` 的外框是 `rounded-lg border`，内部的
`VirtualList` 是 `overflow-y-auto` 的**方形**滚动容器——滚动条与行 hover 背景的直角
会顶到圆角之外。修法：外框加 `overflow-hidden`，行内 hover 背景不再越界，
滚动条也被裁进圆角内。两页共用同一处改法。

### 5.3 O10 纯色块灰色透明边框

`AppearanceField` 的 `ColorInput` 只有 `ring-1 ring-border`，白色时与背景几乎同色。
加一层**灰色半透明边框**（`border border-black/20`），白块也能看清边界；
物品与角色创建弹窗共用，一次生效。

### 5.4 O11 分类改为按钮式 radio

`ItemsPage` 的「分类」筛选、`CreateItemDialog` 与 `ItemDetailForm` 的「分类」字段
都由 `<select>` 改为**按钮式 radio**（`role="radiogroup"` + `role="radio"` +
`aria-checked`），与「外观」字段已有的分段控件同一视觉语言。

### 5.5 验收

- 物品页看不到那两条提示；角色页也没有「不上传图片…」。
- 列表滚动到底部时滚动条与行背景都在圆角内。
- 纯色块（含纯白）有可见的灰色边框。
- 三处分类控件均为按钮，`<select>` 不再出现。

## 6. FEAT-O12 / O13 参与者框

### 6.1 O12 头像与提示词之间展示角色名称

`ParticipantPanel` 的卡片自上面下是：标号 → 头像 → 提示词（clue）。
在头像与提示词之间插入一行**角色名称**（`character.name`，截断 + `title` 兜底）；
空槽位不渲染。

### 6.2 O13 标号放大并移到角落

- `PARTICIPANT_SEQ_FONT_SIZE` 12 → 14，徽标高度 16 → 20、最小宽 20。
- 徽标定为 `top: -1px; left: -1px`，**去掉自己的上边线与左边线**
  （`borderTopWidth: 0` / `borderLeftWidth: 0`），
  圆角只保留右下（`borderRadius: '0 0 6px 0'`）——
  上、左两条边直接复用卡片的边框线，视觉上贴死在角落。

### 6.3 验收

- 参与者框：头像下方是角色名，再下方是提示词。
- 标号字号变大，四角贴合：徽标上沿/左沿与卡片边框重合，只有右下是圆角。
- 编辑器 / 谜题编辑器 / 游戏页 / 预览页四处共用同一组件，同步生效。

## 7. FIX-O14 ~ O18 谜题编辑器

### 7.1 O14 去掉角色面板提示

`PuzzleEditorLeftPanel` 里的
`点击角色可选中；点击「加入」放入右侧参与者区，再从参与者区拖拽完成放置。`
整段删除。

### 7.2 O15 主题色弹框

`ThemeColorDialog`：

1. hex 输入框**前**放 `ColorInput`（原生取色器），两者双向同步；
2. 去掉「应用」按钮——`Input` 的 `onBlur` 与合法即时输入已足够，`ColorInput`
   的 `onChange` 本身就是一次应用；
3. 去掉末行「色块 + hex」的预览行（输入框前的 `ColorInput` 已是预览）。

### 7.3 O16 基本信息-联动主题色不提供调色板

`PuzzleInfoDrawer` 撤掉 v0.5.3 加上的 `ColorPalette`（该项下保留 `ColorInput` +
hex 输入 + 名称 + key）。调色板只留给参与者主题色弹框。

### 7.4 O17 key 输入框失焦

**根因**：调色板每一项 `<li key={`${entry.key}-${index}`}>` 把 **key 值**编进了 React
的 `key`。改 key 时 React 判定整行是「新节点」→ 卸载重建 → 输入框失焦。
**修法**：`key` 只取稳定的行下标 `index`，与内容变化脱钩。

### 7.5 O18 保存后画布跳回左上角

**根因**：`useSavePuzzle.onSuccess` 用 `setQueryData` 写回详情，`detailQuery.data.updatedAt`
随之变化；`PuzzleEditorPage` 的初始化 effect 以 `${id}:${updatedAt}` 为 key，
于是 `puzzle.init()` 重跑，把 `zoom` / `pan` 重置为 `1` / `{0,0}`（顺带清空撤销栈）。
**修法**：

1. `persist()` 成功后记下本次写入的 `updatedAt`（`lastSavedAtRef`）；
   初始化 effect 遇到「来自自己这次保存」的详情时**跳过**重初始化；
2. `puzzleStore.init()` 在 `puzzleId` 未变时**保留** `zoom` / `pan`——
   即使真的被外部刷新（409 冲突重载），视图也不跳。

### 7.6 验收

- 谜题编辑器：角色面板无提示文案；主题色弹框无「应用」按钮与末行预览，输入框前有取色器；
  基本信息调色板消失；key 输入连续打字不失焦。
- 保存（工具栏保存与 Ctrl+S）后画布位置与缩放不变，撤销栈不清空。

## 11. 风险

- **路由改名**：`/projects` 的书签与既有链接依赖重定向兜底（已保留）。
- **难度色淡化**：需要同步文字色，否则白字在浅底上不可读（§2.2 已处理）。
- **保存不重初始化**：必须同时挡住「自己保存」与「外部刷新」两条路径，
  否则 409 冲突重载时视图也会跳（§7.5 两条同时做）。

| **R4**（**已被 SPEC-O19 取代**） | ~~「琢玉台」同时用于导航标签、页面标题与 document.title~~ → **只作为头部 logo 的后缀** | 用户澄清：「只是 logo 后面加琢玉台，地图管理 `/maps` 页面还是叫地图」。见 §4.3 |

| **R9** | 列表圆角溢出用 `overflow-hidden` 修，不改虚拟列表的高度计算 | 裁切是表现层问题，窗口化算法不该为此改动 |
| **R10** | 保存保持视图做成「跳过自己保存的重初始化」+「init 保留 zoom/pan」双保险 | 单做前者挡不住 409 重载，单做后者仍会清掉撤销栈 |
