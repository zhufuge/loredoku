# 需求 + 设计：编辑器左面板刷新按钮 + 当前资源芯片的 ×（v0.7.7）

> **状态**：**已实施**（2026-10-25）。需求即本文，设计即本文；实施记录见 §7。
>
> 需求原文：
> ```
> v0.7.7
> - 添加地图和谜题编辑器中，资源和角色的面板的内容刷新图标按钮，点击后获取最新的资源和角色
> - 地图编辑工具栏的当前选择资源后加一个 x 按钮，点击后去掉当前选中资源
> ```

## 0. 一句话

两件事：① 地图编辑器的**资源**面板（搜索框右侧）、谜题编辑器的**角色**面板（头部）各加一个 `RefreshCw` 图标按钮，点一下重新拉取该列表，不用整页重载；② 地图编辑器底部工具条的「当前放置资源」芯片右侧加一个 `×`，点一下取消当前选中资源。

重载编辑器的代价不是「慢」，而是**丢状态**：撤销栈、视口（缩放 + 平移）、未保存的改动全在内存里。资源与角色是**别的页面**（`/assets`、`/characters`）维护的数据，编辑过程中被改是常态 —— 之前两个编辑器都只在挂载时取一次（`refetchOnWindowFocus: false`，`main.tsx` 的全局缺省），所以作者加完资源必须退出再进来。

## 1. 改之前是什么样

- `useAssets({ isActive: true })` / `useCharacters({})` 都是普通 `useQuery`，编辑器挂载时取一次；
  之后只在下述时机自动更新：本页自己的 mutation 成功后 `invalidateQueries`。
- **别的标签页做的事看不见**：在 `/assets` 新建一个资源、在 `/characters` 加一个角色，回到编辑器
  标签页，两个面板都还是旧列表。窗口聚焦也不会重取（全局 `refetchOnWindowFocus: false`）。
- 唯一的补救是刷新整个浏览器页面，代价是**撤销栈清空**、视口回默认、未保存的改动要重做。
- `/assets`、`/characters`、`/maps`、`/puzzles` 这些列表页本来就有「刷新」按钮（`variant="outline"`
  的文字按钮），只有编辑器里没有 —— 因为编辑器要的是「不动就地重取」。

## 2. 边界

| 做 | 不做 |
|---|---|
| 面板内一个 28px 图标按钮，贴着它所刷的列表（资源在**搜索框右侧**，角色在头部） | 工具栏 / 顶部菜单里的全局刷新 —— 它要刷哪个列表说不清 |
| 只刷**这一个**列表（资源 or 角色） | 顺手把地图 / 谜题本体也重取 —— 那会把作者正在改的草稿冲掉 |
| 取数中图标转圈 + 按钮禁用 | 成功 / 失败的 toast —— 列表本身就在眼前，`isError` 已有「加载失败」文案 |
| 地图编辑器刷新后清理**悬空选中** | 谜题编辑器同样处理选中的角色 —— 那边只是详情面板的高亮，不会往草稿写值（见 §5） |
| 区域 tab、收起的角色细条不显示按钮 | 给区域也做刷新 —— 区域是草稿里的本地数据，没有远端来源 |

## 3. 实现

### 3.1 一个共用按钮

`web/src/components/common/RefreshButton.tsx`：

```tsx
<RefreshButton label="刷新资源" refreshing={assetsQuery.isFetching} onRefresh={() => void assetsQuery.refetch()} />
```

- `label` 同时是 `title` 与 `aria-label`；取数中 `title` 变「刷新资源中…」、`aria-busy` 置位。
- `refreshing` 为真时 `disabled` —— **防连点**，否则长按会堆一串请求。
- 图标 `RefreshCw` 在 `refreshing` 时挂 `animate-spin`。
- 手写 `<button>` 而不是 `<Button size="icon">`：`size="icon"` 是 40×40，塞进角色面板那 40px
  高的头部会顶破边框；面板里其他按钮都是 28px 这一档。

### 3.2 两个面板

| 面板 | 位置 | 可见条件 |
|---|---|---|
| `EditorLeftPanel`（地图 · 资源） | **搜索框右侧同一行**（初版在 tab 头右侧，收尾时挪出头部 —— 40px 的头部留给两个 tab） | 只在 `tab === 'assets'` 时渲染 |
| `PuzzleEditorLeftPanel`（谜题 · 角色） | 头部右侧，排在「收起」左边 | 只在展开态渲染（收起态是 40px 细条） |

两者都新收 `refreshing: boolean` + `onRefresh: () => void` 一对 prop，页面负责传
`query.isFetching` 与 `() => void query.refetch()` —— 组件不知道 react-query 的存在，测试里给个 `vi.fn()` 就能钉。

`refreshing` 用 `isFetching` 而不是 `isLoading`：`isLoading` 只在**首次**加载为真，重取时恒为
`false`，用它会得到「点了没反应」的观感。

### 3.3 刷新后的悬空选中（只在地图编辑器）

`MapEditorPage` 新增一个 effect：资源列表换身份后，若 `editor.selectedAssetId` 指向的资源
**或** `selectedVariantId` 指向的形态已经不在列表里，就 `setSelectedItem(null, null)`。

不清的后果不是报错，而是**悄悄写坏草稿**：画布会把那个已经不存在的 `variantId` 落进
`DraftAnchorItem`，渲染时 `resolveAssetVariant` 回退到首形态 —— 作者看到的是「放下去的东西
长得不对」，而不是「你没选中」。

这条 effect 对**所有**导致列表变化的原因生效（刷新、以及 mutation 后的失效重取），
所以在 `/assets` 里停用一个正在使用的资源，回到编辑器也会自愈。

### 3.4 顺带做掉：当前资源芯片的 ×（地图编辑器）

`EditorBottomBar` 的「当前放置资源」芯片原来只有一种点法：展开左面板。可它最有用的时候
恰恰是**左面板收起时**（那时它是唯一的选中指示）—— 想取消选中却只能先把面板叫出来，
再点同一张瓦片，或者去按 Esc。

- 芯片由 `Button` 换成 `div` 外壳（底色仍是 `TOOLBAR_ICON_ACTIVE_CLASS`），里面两个可点区：
  左边「缩略图 + 名称 + 形态名」→ `onRevealItems`；右边 24px 的 `X` → `onClearSelection`。
  两个都是 `<button>`，不用嵌套按钮，也不靠 `stopPropagation` 抢事件。
- 页面传 `editor.setSelectedItem(null, null)` —— 与「切换图层」「Esc」走同一条路径，
  清的同一对 id，左面板的高亮、画布预览框都会跟着消失。
- `×` 仍遵守「未选中整块不渲染」，所以不存在「空芯片带个 ×」的形态；
  点 `×` 不会顺带展开面板。

## 4. UI 细节

- 视觉与面板里既有的图标按钮同一档：`h-7 w-7 rounded`、`text-muted-foreground`、
  悬停 `bg-slate-200/70`（深色 `slate-700/70`）—— 与「收起 / 展开角色列表」「tab 选中态」同源。
- 地图编辑器里按钮与搜索框同一行（`flex items-center gap-2`，搜索框 `flex-1`、按钮
  `shrink-0`），落在搜索框右端；tab 头部保持 v0.7.6 的样子（两个 tab 各占一半，不多一个按钮位）。
- 按钮没有文案，只有图标；`title` / `aria-label` 承担说明。
- 按钮落在 `AssetPalette` 内部（`onRefresh` 可选，不传就不渲染）而不是左面板外层 ——
  它跟搜索框是同一类操作（都作用于整份列表），放在一起才有「先在列表里找、找不到就刷新」的顺序感。

## 5. 与既有机制的关系

- **撤销栈**：不受影响。刷新只替换 `useQuery` 的缓存，不碰 `editorStore` / `puzzleStore`
  的 `past` / `future`（唯一写 store 的是 §3.3 那个 `setSelectedItem(null, null)`，
  而选中项本来就不进撤销快照）。
- **草稿 dirty**：不受影响 —— 刷新不写草稿，也不会把 `dirty` 洗白。
- **谜题为什么不清理悬空选中**：`unplacedCharacterId` 只决定左面板的高亮与详情抽屉的内容，
  角色被删时列表里就没有这一项了，悬空的只是一个 id，不会写进 `PuzzleDraft`。
  花名册里已加入的参与者引用的是**另一个**字段（`characterSlots[].characterId`），
  刷新列表不会改动它 —— 那是谜题的数据，该由作者显式删。

## 6. 明确不做

- **自动轮询 / SSE**：两个列表一天改不了几次，为一个几乎不变的数据挂定时器不划算。
- **窗口聚焦自动重取**：全局 `refetchOnWindowFocus: false` 是有意的（编辑器切来切去会冲掉
  正在编辑的界面状态），这里不做特例。
- **刷新范围扩大到地图 / 谜题本体**：那是「重新载入」，会丢改动，必须走既有确认流程，
  不能藏在一个图标按钮后面。
