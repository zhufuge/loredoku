> **状态**：已完成。

> 勾选后可在地图中放置到背景修饰层。背景/背景修饰/物品3种可同时放置在一个格子上，且每种最多1个」

## §0 范围与口径

| # | 事项 | 落点 |
|---|---|---|
| ① | 新增「背景修饰层」，插在网格分隔线与阻挡遮罩之间 | §1 |
| ② | 资源-物品加「背景修饰」复选框，勾选后只能放该层 | §2 |
| ③ | 背景 / 背景修饰 / 物品可在同一格并存，各至多一个 | §3 |

两处由用户当面裁定（`ask_user_question`）：

- 勾了「背景修饰」的物品**只能**放背景修饰层，**不再**出现在普通物品层的资源列表里 —— 选
  「只能放背景修饰层（推荐）」。理由是同一件资源出现在两个层里，作者分不清自己这次放的是哪一层。
- 背景修饰**先固定一格**。用户原话：「先固定一格，后续和物品一样会设计连续放置的联动效果」。
  于是 `resolveVariantFootprint` 对它强制返回 1×1，与背景资源同一条规则。

## §1 新图层：`backgroundDecoration`（z 31）

`packages/shared/src/constants/grid.ts`：

```ts
export const MAP_LAYER_ORDER = [
  … 'gridSeparator', 'backgroundDecoration', 'blockingMask', …
] as const;
```

`MAP_LAYER_Z` 只多一项 `backgroundDecoration: 31`。**其余 15 层的数值一律没动** ——
相邻两层之间原本就留了 2 的间隙（`gridSeparator` 32、`blockingMask` 30），31 正好居中。
所以不需要重排任何层，也不必改任何既有渲染代码的 `zIndex`。

图层表随之 15 → 16 层，`docs/layer-priority.md` 的 §1 命名表、§2 次序表、单行链条、
§3 各层说明（原 §3.10 起全部后移一位，新增 §3.10）、§6 迁移记录都已同步。

渲染侧新增 `MapDecorationLayer`（`packages/web/src/components/map/MapAssetLayers.tsx`），
结构照抄 `MapBackgroundLayer`：逐格 `.filter(([, cell]) => cell.decoration)`、key 前缀 `deco-`、
铺满整格不内缩。四个画布入口（地图预览 / 谜题预览 / 游戏页 / 编辑器画布）都挂上了，
紧跟各自的 `<MapBackgroundLayer>`。

## §2 资源侧：「背景修饰」开关

「背景修饰」是**物品资源上的一个布尔开关**，不是第三种 `AssetType` —— 资源仍然是
`type: 'item'`，只是它的归属层变了。

- 数据：`assets.decoration` 新列（`notNullable().defaultTo(false)`，迁移见 §5）；
  `Asset` 上它是**可选**字段（`decoration?: boolean`），理由与 v0.10.6 的
  `AssetVariant.w/h` 相同：旧导出包没有这个键，缺席 = `false`。
- 规则单点：`assetRules.ts` 新增
  ```ts
  export function assetLayerFor(asset: Asset): 'background' | 'decoration' | 'item'
  export function decorationFor(type: AssetType, decoration: boolean): boolean
  ```
  前者是「这件资源属于哪一层」的唯一答案，`canPlaceAssetOnLayer` 与资源调色板的过滤都改走它；
  后者保证背景资源永远不带修饰（与 `blockingFor` 同一形状）。
- 服务端：`createAssetSchema` / `updateAssetSchema` 都 `.transform` 过 `decorationFor`，
  切回 `type: 'background'` 时顺手把 `decoration` 归 `false` —— 与 `blocking` 的处理一模一样。
- 界面：资源详情表单在「阻挡」旁边多一个「背景修饰」复选框，只在 `type === 'item'` 时出现。
- 编辑器左面板：图层切换从两档变三档（`背景层` / `背景修饰` / `物品层`），
  `EDITOR_LAYERS` 与 `LAYER_LABELS` 同步。

## §3 三样并存

`DraftCell` 新增 `decoration?: DraftAssetRef`（与 `background` 同构），
`draftCellSchema` 是 `.strict()` 的，也要跟着加一项。

所以一个格子现在最多有四项：

| 键 | 层 | 占格 |
|---|---|---|
| `background` | 背景层（z 20） | 恒 1 |
| `decoration` | 背景修饰层（z 31） | 恒 1 |
| `item` | 物品层（z 38） | `w × h`（v0.10.6 起由形态决定） |
| `itemRef` | ——（v0.6.0 前的 `oldRef`，仅兼容） | —— |

三者**互不顶替**：`placeDecoration` 只写 `cell.decoration`，不碰另外两个键。

橡皮擦的顺序变成 **物品 → 背景修饰 → 背景**（`resolveEraseTarget`），
`isEmptyCell` 也把 `decoration` 计入「有内容」。底部工具条的橡皮擦提示同步改成这条链。

## §4 迁移

`packages/server/src/db/migrations/20260101000050_v0109_asset_decoration.ts`：

- `up`：给 `assets` 加 `decoration` 布尔列，`notNullable().defaultTo(false)`。
- `down`：删列。

**已放的修饰格不会随回滚消失** —— `maps.data.cells[].decoration` 是纯 JSON，
回滚只丢「哪些资源被标记为修饰」这件属性，重新升级后格子里的内容照旧。
实测 `db:rollback` → `db:migrate` 往返通过。

## §6 没做的

- 没给背景修饰做**多格**：用户明确说「先固定一格」，后续与物品一起做连续放置的联动效果。
- 没做背景修饰的**连续放置**（拖动一次铺一排）—— 同上。
- 没做第三档 `AssetType`：修饰是物品上的开关，资源库的类型筛选仍是「背景 / 物品」两档。
- 没把「背景修饰」加进主题的缺省风格 —— 它是每件资源自己的属性，不是画布外观。
- 没给 `itemRef`（旧键）加修饰对应物：那个键只为读老草稿存在，新数据不写。
- 没做图层重排：新层用 31，避开既有 15 层，无需重新编号。
