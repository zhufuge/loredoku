# v0.11.1 — 播放器打包从 SPA 改成静态页

## 0. 范围与口径

v0.11.0 交出的播放器产物是**一个 SPA 入口**：`dist-player/index.html` 加一堆
`assets/*`，所有路由靠 React Router 在浏览器里切。部署契约（`docs/v0.9.0.md` §9）
因此要求托管方把 `/loredoku/<任意非文件路径>` 重写成 `/loredoku/index.html`。

问题是**纯静态托管通常做不到这件事**：

- GitHub Pages 的官方文档只保证**站点根**的 `404.html` 生效
  （https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site ）；
  子目录里放一份 `404.html` 会不会被服务，没有权威说法。
- 就算那份兜底页生效，深链的状态码仍是 **404** —— 不是 200。

所以 v0.11.0 的发布脚本额外复制了一份 `loredoku/404.html`，那是「成了更好、不成
与不加相同」的碰运气方案。

本版把「玄学」换成确定的东西：**每个地址在产物里都是一个真实存在的文件**。
一个产物只装一个主题、关卡清单就在 `manifest.games` 里 —— 该有哪些地址，构建时
完全是已知信息，没有理由留到运行时靠重写规则去猜。

口径：

- **仍然由浏览器渲染**。这些页面就是同一份入口 HTML，只是换了标题、放在不同的
  目录里。页面里的资源是 `base` 开头的绝对路径（`/loredoku/assets/…`），放多深
  都成立。
- **不做 SSR**。曾评估过 `react-dom/server` + `StaticRouter` 真预渲染内容：游戏页
  是 canvas，预渲染只能出一具空壳，还要把 react-query 的预取与 `useEffect` 里的
  浏览器 API（localStorage、ResizeObserver、字体）全部隔离开 —— 改动大、容易碎，
  收益只是「HTML 里有内容」。本版要解决的只是**地址不存在**，不解决这个。
- **发一个主题、一个产物**（沿用 v0.9.0 的约定）。

## 1. 每路由一份真 HTML

新增 `packages/web/scripts/staticPages.mjs`，两个纯函数：

```js
playerPages({ code, themeName, games })
// → [{ dir: 'hlm/play', title: '红楼梦 · 格物' },
//    { dir: 'hlm/play/puzzle-hlm-sishan', title: '撕扇子作千金一笑 · 格物' }, …]

withTitle(html, title)   // 换掉 <title>，其余字节不动
```

路由清单与 `src/player/router.tsx` 一一对应：

| 路由 | 产物里的文件 |
| --- | --- |
| `/loredoku/` | `index.html`（入口，`<Navigate>` 跳到列表页） |
| `/:code/play` | `<code>/play/index.html` |
| `/:code/play/:key` | `<code>/play/<key>/index.html` |

落盘由 `packages/web/scripts/bundleAssets.mjs` 的 `closeBundle` 做 —— 那里本来就要
把 `player.html` 改名成 `index.html`，顺势拿改好的那份当模板：

```js
closeBundle() {
  if (existsSync(from)) renameSync(from, to);   // player.html → index.html
  const bundle = peek();                        // preview 时没有包，已有页面留着
  if (!bundle) return;
  const template = readFileSync(to, 'utf8');
  for (const page of playerPages({ code, themeName, games })) {
    mkdirSync(path.join(outDir, page.dir), { recursive: true });
    writeFileSync(path.join(outDir, page.dir, 'index.html'), withTitle(template, page.title));
  }
}
```

**标题为什么要写进 HTML**：分享链接的预览、JS 还没跑起来的首屏、以及
「这一关叫什么」这件事本身，都不该等 React 挂载完才知道。原来 `GamePage.tsx:338`
在运行时设 `document.title`，现在两者一致（同一份 `game.name`），不冲突。

**目录名安全**：`code` 与 `key` 来自资源包（作者填的值），直接当目录名之前要过
白名单 `^[A-Za-z0-9._-]+$` 并单独挡掉 `.` / `..` —— 否则一个 `..` 的 key 就能让
`path.join` 把文件写到产物外面去。写文件是**构建期**发生的，这条不是纸面洁癖。

## 2. 地址带结尾斜杠

产物里是一份目录，静态服务器对目录的标准地址是带斜杠的那个（`/loredoku/hlm/play/`）。
所以 `bundleLoad.ts` 的两个拼地址函数加了结尾斜杠：

```js
themeHrefOf(code)        // `/${code}/play/`
gameHrefOf(code, key)    // `/${code}/play/${key}/`
```

不带斜杠也能用 —— 但会先吃一个 301 再回来，地址栏跟着跳变，复制分享时像是两个
地址。`router.tsx` 里 `<Navigate>` 的目标也改成走 `themeHrefOf()`，不再手拼。

React Router 6.30 对结尾斜杠是宽容的（实测 `createMemoryRouter` 带
`basename:'/loredoku'`，`/loredoku/hlm/play/` 命中 `/:code/play`、
`/loredoku/hlm/play/puzzle-hlm-sishan/` 命中 `/:code/play/:key` 且 `params` 正确），
所以不会掉进 `*` 兜底、不会形成「去斜杠 ↔ 加斜杠」的循环 —— 这是本版开工前先
验掉的那个风险。

## 3. 发布脚本去掉 404 那一路

`scripts/publish-player.mjs`：

- **删掉 `--no-404`** 与 `loredoku/404.html` 的生成。深链不再需要兜底页；站点里
  残留的旧 `404.html` 会在「清空 `loredoku/` 再整体写入」时一并消失。
- **发布前核对页面齐不齐**。新增 `missingPlayerPages(distDir, code)`：读产物里的
  `manifest.json`，用**同一个** `playerPages()` 算出该有哪些页面，逐个看文件在不在。
  少一份就少一个能直接打开的地址，所以在写盘之前就报错 —— 发布完才发现更麻烦。
  旧产物（v0.11.0 及以前）会在这里被拦下来，报错里直接写了「去掉 `--no-build`
  重新构建一次」。
- 步骤从 `[1/4]…[4/4]` 收成 `[1/3]…[3/3]`（少了一步复制 404）。

## 4. 验证与回归

- `packages/web/scripts/staticPages.test.mjs`：16 个用例 —— 页面清单与数量、主题
  编码/关卡 key 直接当目录名、不能当目录名的值（`/`、`..`、空格、空串、重复 key）
  一律报错、`withTitle` 只换标题（跨行 `<title>`、缺 `<title>` 时补进 `<head>`、
  标题里的 HTML 特殊字符转义）。
- `scripts/publish-player.test.mjs`：35 个用例 —— 上一版 30 个里删掉 `no404` 的
  3 个（含「默认值里有 no404」）、加 1 个**反向**用例钉住「`--no-404` 现在会报
  不认识」；新增 4 个 `missingPlayerPages` 用例（齐了返回空、缺列表页、缺某一关、
  连 manifest 都没有）。
- 真实构建：`npm run build:player -- --outDir=dist-player/v0111` 打出 7 个页面
  （1 列表 + 6 关），插件自己打印 `静态页：7 个（1 个列表页 + 6 个关卡页）`；
  抽查标题 —— 列表页 `红楼梦 · 格物`、撕扇页 `撕扇子作千金一笑 · 格物`。
- `npm run typecheck` 三个 workspace 全过；`packages/web` 83 文件 / 1201 用例全过
  （`bundleLoad.test.ts` 的地址断言同步成带斜杠的版本）；根 `scripts/` 64 用例全过。

## 5. 没做的

- **没预渲染内容**（见 §0）。要做的话是另一件事：把 `GamePage` 的初始化从
  `useEffect` 里拆出来，而不是在构建脚本里再补一层。
- **没管未知地址**。产物里没生成的地址（例如 `/loredoku/hlm/play/打错的key`）仍然
  是托管方的 404 页，而不是播放器自己的「这一关不存在」。那是包的清单里压根没有的
  东西，静态产物无从预先表达；真要兜住只能回到「404 页 + SPA」，与本节目标相反。
- **没改 dev server**。`npm run dev:player` 仍然用 `bundleAssets` 的
  `configureServer` 做内存 fallback —— 改一行代码就能刷新，没必要每次重新摊页。
  dev 里地址不带斜杠也能进，产物里带斜杠，两边都能用（路由对斜杠宽容）。
- **没动 v0.11.0 的文档**。`docs/v0.11.0.md` §7 里关于 `404.html` 的那段保留原样
  （历史文档不改），本版的变化记在这里。
