## 1. 修复

### FIX-301 禁止点击拖动格子内容

**现象**
- 编辑器已移除「拖动格子内容」的功能入口，但在画布上按下鼠标拖动仍会触发物品/角色的拖动逻辑；
- 与区域选择工具的拖拽框选**互相冲突**：区域模式下拖拽时物品层也会响应，导致选区异常。

**根因**
- 物品层 / 角色层的 `pointerdown` 事件仍在监听拖拽，未随功能移除同步清理；
- 事件冒泡未阻断，选区层与物品层同时响应。

**修复要求**

1. **移除格子内容拖拽逻辑**
   - 删除物品层、角色层上的 `pointerdown` → 拖动 → `pointerup` 落位整套逻辑；
   - 移除相关的 `dragging` 状态与 `DragGhost` 组件在**画布内移动**场景的使用（从物品栏/角色槽位拖入画布的能力**保留**）。

2. **物品/角色在画布内**仅保留以下交互
   - 单击选中（展示右侧信息）；
   - 右键上下文菜单（可选，若已实现）；
   - 删除（通过选中后 `Delete` 键或右侧面板按钮）。

3. **事件层级明确**

   | 工具模式 | 画布指针事件接收者 |
   |---|---|
   | 选择 | 交互层（命中检测物品/角色/区域标签/空格） |
   | 区域 | **仅**选区层；物品/角色/标签层 `pointer-events: none` |
   | 橡皮 | 交互层（仅清除逻辑） |
   | 角色 | 交互层（仅从槽位拖入，落位后不再拖动） |

4. **物品/角色层统一设置**
   - `pointer-events` 由父层按工具模式切换：非选择/橡皮模式时设为 `none`；
   - 命中检测改由统一的交互层通过坐标反查，避免 DOM 层级竞态。

**验收**
- 选择工具下在画布上按住物品拖动 → 无任何移动；
- 区域工具下拖拽框选 → 物品/角色不响应，选区正常累积；
- 从物品栏/角色槽位拖入画布的功能仍可用。

### FIX-302 区域矩形选择再次修复

**现象**
1. **点击一格后拖动**：会触发物品/角色拖动（应被 FIX-301 修复），同时选区未扩展；
2. **先点击一格，再点击另一个角**：期望形成的矩形只选中了第二次点击的那一格，第一次点击的格被丢弃。

**根因分析**
1. 起点的记录在 `pointerdown` 时被写入，但第二次点击的 `pointerdown` 会**覆盖**起点而非作为终点处理；
2. 缺少「已有点击起点 + 第二次点击 = 矩形对角」的状态机；
3. `pointerup` 未按起止点展开矩形，只把当前格加入。

**修复要求**

#### 1.3.1 选区状态机（明确两种输入方式）

```ts
type RegionDraftState =
  | { phase: 'idle' }
  | { phase: 'pointer-dragging'; anchor: Cell; current: Cell }
  | { phase: 'click-anchor'; anchor: Cell };   // 已有单击锚点，等待第二次点击
```

**交互流程**

| 操作 | 触发 | 行为 |
|---|---|---|
| `pointerdown` 在空白格（无锚点） | 进入 `pointer-dragging`，`anchor = 当前格` | 开始预览矩形 |
| `pointermove` | 更新 `current` | 实时渲染矩形预览 |
| `pointerup`（位移 ≥ 4px） | 提交：矩形 `[min..max]` 全部加入选区 | 回到 `idle` |
| `pointerup`（位移 < 4px，即点击） | 进入 `click-anchor`，`anchor = 当前格` | 单格已加入选区，等待第二次点击 |
| 第二次 `pointerdown`（`phase === 'click-anchor'`） | 以两次点击为对角，形成矩形 | 进入 `pointer-dragging`，`anchor = 第一次锚点`，`current = 当前格` |
| 第二次 `pointerup`（位移 < 4px） | 提交矩形并回到 `idle` | 展开矩形范围内所有格加入选区 |
| `Esc` / 切换工具 | 清除锚点 | 回到 `idle`（选区内容是否清空见下） |

**关键规则**
- **两次点击视为矩形对角**：第二次点击后立即按矩形展开全部格加入选区，而非仅加入当前格；
- 双击同一格（两次点击同位置）→ 视为该格 toggle 选中/取消；
- 已有锚点状态下，`pointerdown` **不应清空**已有选区（避免误丢已选内容）；
- 拖拽框选时，矩形内所有格**追加**到选区（按住 `Alt` 为减选，按住 `Shift` 为强制追加）；默认行为为追加，不做替换，避免用户已选内容丢失。

#### 1.3.2 与 FIX-301 协同
- 进入区域工具时，物品层/角色层 `pointer-events: none`（FIX-301）；
- 区域工具期间，交互层仅处理选区逻辑，不触发任何拖动。

#### 1.3.3 可视化
- 拖拽过程中实时渲染**虚线蓝色矩形边框 + 半透明蓝底**；
- `click-anchor` 状态下，锚点格显示**明显的十字角标**或加粗选中环，提示用户"再点一次形成矩形"；
- 顶部选区操作条文案在 `click-anchor` 状态时提示：「已选起点，请点击对角格或拖拽框选」。

**验收**

| 场景 | 期望 |
|---|---|
| 单击 A 格 | A 加入选区，进入 click-anchor，A 显示角标 |
| 再单击 C 格（与 A 成对角） | A~C 矩形内全部格加入选区 |
| 单击 A 后再拖拽到 C | 同拖拽框选效果 |
| 拖拽 A→C | 矩形内全部格加入选区 |
| `Shift` 拖拽 | 追加 |
| `Alt` 拖拽 | 减选 |
| `Esc` | 清除锚点，保留已选内容（再按一次清空选区） |
| 切换工具 | 清空选区与锚点 |

### FIX-303 点击角色后不放置到地图

**现象**
- 在角色槽位点击角色后，编辑器进入「等待落位」状态，鼠标移动到画布会显示幽灵预览，点击画布即放置角色；
- 产品上**不需要**该行为。

**修复要求**
- 移除「点击角色 → 进入落位模式」的逻辑；
- 角色进入地图**仅**通过以下方式：
  1. 从左侧角色槽位**拖拽**角色到画布可站立格；
  2. 从右侧信息抽屉中（可选，若已有）操作；
- 单击槽位中的角色仅做「选中」效果（高亮边框 + 右侧展示角色信息），不触发落位；
- 单击已放置在地图上的角色仅做「选中」效果，不进入拖动模式（与 FIX-301 一致）。

**验收**
- 单击槽位角色 → 仅选中，鼠标移到画布不显示幽灵预览；
- 拖拽槽位角色到画布 → 正常放置；
- 单击地图上角色 → 右侧展示信息，无落位/拖动行为。

### FIX-304 画布方格边界线合并

**现象**
- 画布上每条网格线渲染为**多条独立 1~2px 线段**（每个格子的四边各绘一次），相邻格之间出现双线，视觉上线条加粗且不匀。

**修复要求**

采用「**只画内部分隔线与外边框**」的方式，确保相邻格共享一条线：

1. **内部分隔线**
   - 竖直分隔线：`n - 1` 条，位于 `x = i * cellSize`，`i ∈ [1, n-1]`；
   - 水平分隔线：`n - 1` 条，位于 `y = j * cellSize`，`j ∈ [1, n-1]`；
   - 宽度 2px，颜色 `#000000`。

2. **外边框**
   - 沿画布四周绘制一圈 3px `#000000` 边框；
   - 与内部分隔线不重叠（分隔线只画内部，边框只画外围）。

3. **推荐实现**
   - 使用单个 `<svg>` 覆盖画布，分别绘制 `n-1` 条竖线、`n-1` 条横线、以及一个 `<rect>` 作为外边框；
   - 或使用 CSS `repeating-linear-gradient` + `border`；
   - **禁止**每个格子画四边再拼接。

**验收**
- 相邻格之间只有一条线，粗细一致；
- 画布外边框完整闭合，无断线、无重叠加粗。

### FIX-305 最右与最下边界线缺失

**现象**
- 当最后一列/最后一行填满物品时，画布最右侧或最下方的边界线被物品图覆盖，显示为缺失。

**根因**
- 物品图渲染层级高于网格线层；
- 外边框绘制在物品层下方，被覆盖。

**修复要求**

1. **渲染层级**（从下到上）：
   ```
   网格底色 → 背景层物品 → 区域填充 → 物件层物品 → 区域边框 → 角色
   → 网格线（内部分隔线 + 外边框） → 悬停/选中效果 → 区域名称标签
   ```
2. **网格线必须绘制在物品层之上**，确保任何物品都不遮挡网格线；
3. 外边框使用 3px 宽，位于网格线层内，覆盖画布四周，**不因物品填充而消失**；
4. 物品图 `overflow: hidden` 严格裁剪在格子内，不越过外边框；
5. 多格物品同理，其渲染矩形不得超出画布外边框范围。

**验收**
- 填满所有格子后，四条外边框线完整可见；
- 物品图与网格线不产生叠压错位；
- 缩放、平移时网格线始终完整。

### FIX-306 新建物品/角色后自动选中并切换

**现象**
- 新建物品或角色后，列表虽刷新，但详情区仍停留在旧对象；
- 用户需手动点击新对象才能查看/编辑。

**修复要求**

1. **列表页行为**
   - 新建成功后：
     - 列表刷新（`invalidateQueries`）；
     - **自动高亮并选中新创建的对象**；
     - 右侧详情区加载新对象数据；
     - 列表滚动至该项可见区域（若使用虚拟滚动）；
     - Toast 提示「已创建」。

2. **编辑器内行为**
   - 若编辑器处于打开状态（例如从编辑器内打开物品抽屉新建物品）：
     - 新建成功后，**物品抽屉自动切换到该物品所在的分类 Tab**（背景 / 物件）；
     - 该物品在抽屉中**自动高亮/标记**（如短暂闪烁边框），提示用户其位置；
     - 编辑器地图数据不受影响（除非用户主动使用）。

3. **实现要点**
   - 通过 API 返回的 `id` 驱动选中状态；
   - 选中状态由 URL query（如 `?id=123`）或本地 store 管理，**推荐使用 URL query** 便于分享与刷新保持。

**验收**
- 新建物品后，列表自动选中新物品，右侧详情立即展示该物品；
- 新建角色后同理；
- 刷新页面后，若 URL 仍带 `id`，选中状态保持。

### FIX-307 已加入的角色不能被移除

**现象**
- 角色已从槽位拖入地图，放置在某可站立格上；
- 在右侧信息抽屉（或角色信息弹窗）中点击「从地图移除」/「×」按钮；
- **无任何反应**：角色不消失、不回到槽位、无 Toast 提示、无报错。

**根因分析（按可能性排序）**

1. **按钮未绑定实际处理函数**
   - 「×」或「从地图移除」按钮渲染出来，但 `onClick` 为空、指向未实现的方法、或调用了一个已重命名/删除的旧 action。

2. **`returnCharacterToSlot` action 未实现或未落库**
   - Store 中声明了该 action，但实现体为空；
   - 或仅修改了本地 `placedCharacters` 数组，未同步把角色写回 `characterSlots`，导致 UI 判定"角色仍在地图"而未重渲染。

3. **状态不可变性被破坏**
   - 直接用 `splice` / `array[i] = ...` 修改 `placedCharacters` 或 `characterSlots` 后未返回新数组；
   - Zustand 未检测到引用变化，组件不重渲染。

4. **槽位已满导致静默失败**
   - 撤下角色时需要找到空槽位写回；若 `characterSlots` 已无 `null` 位置，实现里可能直接 `return` 而无任何提示。

5. **权限/状态判断拦截**
   - 若存在 `viewMode === 'version'`（只读版本）或 `saving === true` 等状态，按钮被 `disabled` 或 `pointer-events: none` 但未显示为禁用样式，用户误以为可点。

6. **命中检测**：按钮点击被上层蒙版、抽屉滚动容器或 `pointer-events` 拦截。

**修复要求**

#### 1.7.1 功能实现：撤下角色

**行为定义**
- 点击右侧信息抽屉（或角色 Dialog）中的「从地图移除」/「×」后：
  1. 角色从 `placedCharacters` 中移除；
  2. 角色写回 `characterSlots` 中**原槽位**（若该槽位已被其他角色占用，则写入第一个空槽位）；
  3. 若所有槽位均被占用（理论不应发生，因为槽位与角色一一对应），展示 Toast 提示「无可用槽位，请先清理槽位」并**不执行移除**；
  4. `dirty = true`，可被撤销；
  5. Toast 提示「已移除角色」；
  6. 右侧抽屉切换到该角色对应的槽位选中态（若适用）。

**Store Action 补充定义**
```ts
returnCharacterToSlot(characterId: number): void {
  // 1. 从 placedCharacters 找到并移除
  // 2. 计算目标槽位：
  //    - 优先尝试原槽位（如果 placedCharacters 中记录过 originSlotIndex）
  //    - 否则取 characterSlots 中第一个 null 的下标
  // 3. 写入 characterSlots[slotIndex] = { characterId }
  // 4. 若已存在同 characterId 的槽位，则跳过写入，避免重复
  // 5. 触发 dirty = true，推送历史快照
}
```

**数据结构建议**
- `PlacedCharacter` 增加可选字段 `originSlotIndex?: number`，用于在移除时优先回到原槽位，保持槽位顺序稳定。

#### 1.7.2 交互与状态

| 场景 | 行为 |
|---|---|
| 选择/悬停状态 | 按钮正常可点击，`cursor: pointer` |
| 点击后 | 立即触发 `returnCharacterToSlot`，无需二次确认（可通过撤销恢复） |
| 只读版本模式（`viewMode === 'version'`） | 按钮**隐藏**或**置灰**并附 tooltip「只读版本不可编辑」 |
| 保存中（`saving === true`） | 按钮置灰，蒙版已拦截整体交互 |
| 移除后 | 抽屉收起或切换到该角色在槽位上的信息 |
| 移除后 `Ctrl/Cmd + Z` | 角色回到原位（地图坐标与槽位均恢复） |

#### 1.7.3 撤销栈支持

- `returnCharacterToSlot` 必须**纳入撤销历史**：
  - 快照需包含 `placedCharacters` 与 `characterSlots` 两个字段；
  - 撤销时二者一并回滚；
  - 避免出现"角色回到槽位但地图上仍显示"或反之。

#### 1.7.4 防重复点击

- 点击后按钮立即进入短暂的 `loading`/禁用态（例如 200ms 或直到状态更新完成），防止快速连点导致同一角色被多次处理。

#### 1.7.5 排查项（确保落地）

- [ ] 按钮的 `onClick` 已绑定 `returnCharacterToSlot(characterId)`；
- [ ] 该 action 在 Zustand store 中已实现且返回新数组/新对象；
- [ ] `characterSlots` 与 `placedCharacters` 的更新在同一 action 内**原子完成**；
- [ ] 组件订阅了 `placedCharacters` 与 `characterSlots`，任一变化都能触发重渲染；
- [ ] 无 `pointer-events: none` 或 z-index 覆盖在按钮上；
- [ ] `viewMode === 'version'` 时按钮正确隐藏/置灰；
- [ ] 已写入历史栈，可撤销。

**验收标准**

| 场景 | 期望 |
|---|---|
| 点击已放置角色的「×」/「从地图移除」 | 角色立即从地图消失，回到左侧槽位 |
| 点击后查看槽位区 | 该角色出现在原槽位（或首个空槽位） |
| 点击后按 `Ctrl/Cmd + Z` | 角色恢复至地图原坐标，槽位清空 |
| 快速连点 × 3 次 | 只触发一次移除，无异常 |
| 只读版本模式查看 | 按钮不可用或不存在 |
| 保存中点击 | 无响应（蒙版已拦截） |
| 浏览器刷新 | 若已保存，角色确实在槽位中 |

## 2. 优化

### OPT-301 标尺去掉背景

**变更**
- 移除标尺的 `background-color`（原 `#F9FAFB`）；
- 保留文字与当前行列的高亮（高亮可继续使用浅色背景，仅高亮区块有背景）；
- 标尺边框（底部/右侧分隔线）可选保留 1px 浅色，或一并移除；建议**保留浅色分隔线**以便区分标尺与画布，但背景透明。

**验收**
- 标尺区域背景透明，视觉上仅显示行列号；
- 悬停行列时对应数字高亮。

---

### OPT-305 无图片自动停用

**规则**
- 物品或角色在以下情况**自动切换为停用状态**（`is_active = false`）：
  1. 创建时**未上传图片**（物品图片 / 角色头像）；
  2. 编辑时**删除已有图片**；
- 自动停用后：
  - 该物品/角色不再出现在编辑器的物品栏 / 角色槽位选择列表中；
  - 若已存在于某地图中，**数据保留**（不自动清除引用），但编辑器中展示为「已停用」占位（灰色蒙层 + 提示）；
  - 停用后用户可重新上传图片 → 手动点击「启用」恢复；
- 上传图片后**不自动启用**，需用户显式点击「启用」；避免误操作。

**接口调整**
- `POST /api/items/:id/image`：上传成功后**不改变** `is_active`；
- `DELETE /api/items/:id/image`：删除成功后**自动**将 `is_active` 置为 `false`；
- `POST /api/items`：若请求体未带图片（或后续上传失败），创建成功后 `is_active = false`；
- 角色同理，作用于 `/api/characters/:id/avatar` 与创建接口。

**前端交互**
- 物品管理页：未上传图片的项显示「未启用（缺图片）」标签；
- 删除图片时弹窗提示：
  ```
  删除图片后，该物品将自动停用。
  [取消] [删除并停用]
  ```
- 编辑器物品抽屉：不展示停用物品。

**验收**
- 新建未上传图片的物品 → 列表显示为停用状态；
- 删除已有图片 → 自动停用，且地图引用数据保留；
- 上传图片后仍需手动启用才出现在编辑器物品栏。
