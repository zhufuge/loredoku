## §1 删掉「合辑」（`theme_deployments` / `theme_deployment_puzzles`）

### 1.1 它原来是什么

v0.8.0 §9 引入的两张表：

```
theme_deployments(id, theme_id, slug, name, description, cover_path, …)
theme_deployment_puzzles(deployment_id, puzzle_id, sort_order)
```

一行 = 一个「合辑」（一串关），成员表按 `puzzle_id` 记顺序。玩家从
`/play/theme/:slug` 进来，顺着 `sort_order` 一关一关玩；导出包也按这个顺序排。

### 1.2 为什么现在能删

两件事把它挤掉了，都在 v0.8.3 之后发生：

1. **顺序有了自己的位置。** `games.sort_weight`（v0.8.3 §6.2）＋ 部署页就地改权重
   （v0.8.5）之后，「关卡顺序」这个事实只有一个真源。合辑的 `sort_order` 是第二套，
   两边不一致时谁也说不清该信谁 —— 导出包按合辑排，部署页按权重排。
2. **交付变成一个包。** 播放器（`/loredoku/...`）读的是 `manifest.json`，关卡清单
   就在包里；合辑那层「目录」在包里没有对应物，只剩一个 slug 没人读。
   主题级「一键上线」（`POST /api/themes/:code/deploy`）也跟着失去了意义 ——
   它当年做的就是「把这批关部署成单局，再写一条合辑」。

### 1.3 做了什么

**数据库**：新增迁移 `20260101000045_v092_drop_theme_deployments.ts`，先删成员表
（它有一条指向 head 表的外键）再删 head 表；`down()` 按 v0.8.0 的原样重建结构
（**不恢复数据**，行随表一起没了）。

**服务端**：

| 位置 | 删除 |
|---|---|
| `repository/themeRepository.ts` | `toDeployment` / `findDeploymentBySlug` / `findDeploymentByTheme` / `deploymentEntries` / `getDeployment` / `listDeployments` / `upsertDeployment` / `deleteDeployment` / `latestPublishedPerRoot` |
| `service/themeService.ts` | `listDeployments` / `getDeployment` / `getDeploymentBySlug` / `deployTheme` / `updateDeployment` / `removeDeployment`；`deleteTheme` 里那条「主题下还有合辑，请先删除合辑」的单独拦截 |
| `controller/themeController.ts` | 五个合辑处理器 + `deploy` |
| `router/themes.ts` | `themeDeploymentsRouter` 整块 + `POST /:code/deploy`（`bundle` 保留） |
| `router/index.ts` | `/api/theme-deployments` 前缀 |
| `bundleService.ts` | `orderByCollection` —— 包的关卡顺序直接用 `listGameRowsByTheme`（`sort_weight` 升序、`slug` 兜底），与部署页同一把尺子 |

**共享层**：`ThemeDeploymentEntry` / `ThemeDeploymentSummary` / `ThemeDeploymentRow` /
`ThemeDeploymentPuzzleRow`、`createThemeDeploymentSchema` / `updateThemeDeploymentSchema`
及其类型，全部删除。

**前端**：

  `useThemeDeployments` / `useRemoveDeployment` 一起走）。
- `GamesPage` 回到**一张列表**：原来「主题大卡 + 单个游戏」两段互斥，现在一关一张卡；
  `ThemeCollectionCard` 与 `themeGameHref` 删除。
- `ThemePlayPage.tsx`（`/play/theme/:slug` 合辑页）整个删除。
- 游戏页顶栏不再有「从哪个主题进来」这一档：`useTheme` / `themeHref` 从 `GameSource`

## §2 长按计时环可以配图

### 2.1 需求

玩家在格子上**按住 500ms 放头像**时，会画一圈进度环（v0.7.11）。作者想把它换成
自己画的图；不配就还是原来那圈白弧。

### 2.2 数据形状

`themes.data` 多一个键：

```ts
/** v0.9.2 §2：长按放置参与者时那圈计时环的图。缺了 = 内置白弧。 */
pressRing?: ForbiddenSymbolImage | null;   // { path: 'themes/<id>/press-ring/<uuid>.webp' }
```

与 `forbiddenSymbol` / `toolIcons` **同一个形状、同一条规矩**：读取时兜底，不是
「新建时拷一份」。所以换一张图，本主题下所有关卡（含已发布的）下次打开就是新的。

`themeDataSchema` 是 `.strict()` 的，所以这一项必须同步写进 schema —— 否则作者一
上传就 400。

### 2.3 服务端

- `POST /api/themes/:code/press-ring`（`forbiddenSymbolUpload` 单文件）→ 回更新后的整份主题。
- `DELETE /api/themes/:code/press-ring` → 删掉 `data.pressRing`。
- 图片走 `utils/image.ts` 的 `processPressRingImage`：与禁止符号同一条「只写一张
  缩放 webp、长边 256」的通道，目录 `themes/<id>/press-ring/`。256 对环够用
  （环的外接方形最大就是格子，实测 152px 上下）。

### 2.4 渲染：图换样子，不换刻度

`PressRing`（`components/common/PressRing.tsx`）多一个 `imageUrl`：

- **没配**：与改动前完全一致（可选底轨 + 一圈白弧，`stroke-dashoffset` 走
  `.press-ring-arc` 那条 `linear` 关键帧）。
- **配了**：不画白弧、也不画底轨，画 `<image>` 铺满整格，用一条 **`<mask>` 里的
  几何圆环**（`r = 半格`、`strokeWidth = 整格`，所以遮罩本身是一个圆面）按同一条
  关键帧顺时针揭开 —— 一块**扇形**在长，读法是「已经按了多久」。

为什么不是「整张图直接贴上去」：环回答的是「还要按多久」，换成插画不能把刻度弄丢
（`design-system.md` §2 第 4 条：进度类动画必须 `linear`，且不能被
`prefers-reduced-motion` 压掉）。扇形遮罩复用同一个 `--press-ring-duration` /
`--press-ring-length` 变量，所以**图模式与白弧模式的时间轴是同一个**。

`MapGamePressRing` 加 `imageUrl` 透传；`GamePage` 用 `resolvePressRing`（新文件
`lib/pressRing.ts`）把主题那份解析成站内地址。

### 2.5 主题页面

概览页新增一张卡 **「长按计时环」**，交互与「禁止符号」卡一字不差：左 64px 预览
（没配时画一枚虚线圆占位）、「上传环图 / 更换 / 移除」，选中文件即上传、点移除即
回默认。按钮文案用「上传环图」而不是「上传图片」，是为了和禁止符号卡在同一屏里
能分辨（两张卡都在概览页，同一句文案会让人点错）。

### 2.6 导出包

环是**主题级、所有关卡共用一张**，所以不逐关复制：`bundleService` 只装一份到
`files/ring/press-ring.<ext>`，路径写进 `manifest.theme.pressRing`（与
`difficultyLevels` 同一个位置、同一条「没配就不写键」）。播放器从 manifest 读，
`fileUrl` 拼包根 —— 与禁止符号 / 工具图标在包里是「逐关内联」不同，因为那两张
本来就可能被单关覆盖。

### 2.7 验证

- `shared`：`themeDataSchema.pressRing` 两条（缺省 / null / 正例；路径不能跳、形状
  只能有 `path`）。
- `web`：`PressRing.test.tsx` 三条（没配 = 两枚 circle + 无 `<image>`；配了 =
  `<image>` + 扇形遮罩几何 + 只剩一枚 circle；两种模式的时长变量相同）；
  `lib/pressRing.test.ts` 三条；`ThemeOverviewPage.test.tsx` 一条（没配给入口、
  配了渲染图、移除直接发请求）。
- `server`：`themeBundle.test.ts` 一条 —— 配了环 → 包里 `files/ring/` 一份、
  `manifest.theme.pressRing` 指过去、hash 进 manifest.files；没配 → 一个键都不多。
- 真浏览器：`/hlm/overview` 渲染出「长按计时环」卡与「上传环图」按钮。

## §3 清除按钮的长按：环 → 方块内的扇形扫描

### 3.1 需求与问题

> 「清除按钮的长按，不要加载环，改成按钮方块内，扇形扫描加载」

原来清除按钮和棋格共用 `PressRing`（v0.7.10 定的「同一个手势只有一种样子」）。那圈环
在棋格上是对的 —— 一格空白，环沿着格子边画。但在按钮上不对：

- 按钮是 **48px 高**的方块，里面已经有一枚 **32px** 的图标（v0.9.0 §17 放大过）；
- 环画在 40px 的方框里，正好把图标圈住 —— 环一出现，读成「这枚按钮坏了」，而不是
  「正在按住」；
- 两者抢的是同一块地方，越放大图标越挤。

### 3.2 做法

新增 `components/common/PressSweep.tsx`：不画环，改往**按钮自己的方块**里填。

- 一层 `absolute inset-0 rounded-[inherit]` 的覆盖层，背景是
  `conic-gradient(主色 var(--press-sweep-angle), transparent 0)`；
- 角度由 `index.css` 里注册成 `<angle>` 的 `--press-sweep-angle` 从 0 推到 360
  （`@property` 已注册，才能插值 —— 与 `.paper-shade` 的 `--glow-r` 同一个理由）；
- 起点就是锥形渐变的**默认起点**（12 点钟）。这里**不能**照抄环那边的
  `rotate(-90)`：环是 SVG，圆形路径的 0° 在 3 点钟方向才要转，渐变天生从上往下
  数，再转一次会跑到 9 点钟（实测：第一版就是这么错的，90° 扫出的是左上象限）；
- 图标包一层 `relative`，让它压在扇形**之上**：扇形是绝对定位的，按绘制顺序会盖住
  普通流内容，不抬一层就会把图标染色。

保留的规矩：线性（它是倒计时）、取消即卸载、不接指针事件、`prefers-reduced-motion`
下不被压掉（它是那里唯一的进度信息）。

### 3.3 与环的取舍

| | 棋格上的 `PressRing` | 按钮上的 `PressSweep` |
|---|---|---|
| 画什么 | 一圈弧，沿格子边 | 一片扇形，填满方块 |
| 动在哪 | SVG 呈现属性（合成线程） | 每帧重画渐变（主线程） |
| 尺寸依据 | `cellSize` | 按钮自己的盒子 |
| 主题配的环图 | 生效（v0.9.2 §2） | **不生效** —— 那是棋格的插画 |

主线程这一条说清楚代价：方块不到 100×48、渐变只有两个色标、只在按住的这
640ms 里存在（抬手即卸载）。换成逐帧 `setState` 才是不能接受的那个。

### 3.4 阈值 500 → 800ms

> 「清除的长按时间加长一点」

两个长按此前共用 `GAME_LONG_PRESS_MS = 500`，但后果不是一个量级：棋格长按是
「把这一位放到这一格」，放错撤销一步就回来了；清除按钮长按是**整盘放置一次抹掉**，
虽然也能回退，读起来仍像丢过东西。同一个 500ms 让后者触发得太容易。

新增 `GAME_CLEAR_LONG_PRESS_MS = 800`，**只给清除这一枚**：

- `startClearPress` 的定时器改用它；扇形的时长同步成
  `800 − GAME_PRESS_RING_DELAY_MS = 640ms`，扫满那一帧仍是清空发生的那一帧；
- 棋格那边一个数都没动（环仍是 `500 − 160 = 340ms`）；
- 出场延迟 `GAME_PRESS_RING_DELAY_MS = 160` 两边共用 —— 单点不闪这条规矩一致。

两个常量各管一件事，别再合并回去：合并那天一定会有人为了「清空更安全」而顺带把
放置也拖慢。

### 3.5 验证

- 新增 `PressSweep.test.tsx` 两条（时长 / 切点来自属性且不带 `from`；`seq` 变化
  必须重建节点，否则连按第二次会看到一块已经填满的方块）。
- `GamePage.press.test.tsx` 那条改成观察 `.press-sweep`：单点不出现、按住过 160ms
  出现、抬手消失，并且**同一时刻棋格那圈 `.press-ring-arc` 不该被画出来**。
- `GamePage.press.test.tsx` 再加一条钉**时间差**：按住清除按钮 560ms 时棋盘原封
  不动、扇形还在扫；到 880ms 已清空、扇形已收。这条会同时抓住「有人把清空的阈值
  改回 500」和「扇形时长与阈值脱钩」。
- 真浏览器量像素（无头 Chrome + `sharp`，96×48 的方块、`primary/0.28` 叠白底）：
  用 `animation-play-state: paused` + 负 `animation-delay` 冻在四个时刻取样 ——
  0% 什么都不画、25% 是右上象限（90°）、50% 是右半边（180°）、99% 已近满；
  起点确实在 12 点钟且顺时针。颜色实测 `rgb(197,211,220)`，与
  `hsl(205 45% 36% / 0.28)` 叠白底一致。

## §5 没做的

- **合辑数据不备份**：用户要求删表，迁移里没有「先导出成 JSON」那一步。真要留档，
  只能在跑迁移前自己 `pg_dump` 那两张表。
- **计时环不做「每关各配一张」**：需求写的是「在主题页面配置」。真要按关覆盖，
  形状与禁止符号那三级兜底一样，加一个 `PuzzleDraft.pressRing` 即可 —— 这一版不加。
- **环图的 `onError` 回退**：与禁止符号同一个取舍（`docs/v0.8.6.md` §6）——
  文件被手工删掉时浏览器画破图，不额外回退到白弧。
