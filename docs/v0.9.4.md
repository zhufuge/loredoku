## §1 字体补「雯麝怡」

`font-extra-chars.txt` 是「谁遇到缺字谁加一行」的人工清单：默认 `charset=common`
只覆盖 GB2312 一级（3755 字），一级之外的字会被裁掉、渲染时退回系统字体 ——
不报错、不显示豆腐块，但那个字不是手写体。清单里原本只有「薇」。

这一版加上 **雯 / 麝 / 怡**（晴雯、麝月、怡红院），重跑

```bash
npm run fonts --workspace @loredoku/web
```

产物 `霞鹜文楷-Regular.woff2`：**4705 → 4708 字，925 → 926 KB**（三个字
合计约 1 KB，仍然不值得为了几个字换整档 `gb2312`）。`src/assets/fonts/README.md`
里的示例输出同步成「补字 4 / 4708 字 / 926 KB」。

清单被误删不会让构建报错，只是字悄悄退回系统字体，所以 `build-fonts.test.ts`
加了一条：把「薇 / 雯 / 麝 / 怡」钉在清单上。

## §2 失败结算卡：只报结论

### 2.1 改了什么

| | 之前 | 现在 |
|---|---|---|
| 标题 | 提交未通过 | **结果** |
| 正文 | 下面这些参与者的位置还不对，改完可以再提交一次。 | **你没有找出所有人的位置！x/n 正确。未能结案。** |
| 名单 | `<ul>` 列每位「未放置 / 位置不对」+ 编号与姓名 | **整块删除** |
| 按钮 | 继续游戏 / 重新开始 | 不变 |

「结果」与通过的「定案」是同一层级的两个词：一个说结案了，一个说还差一步，
都不再重复播报成绩。`x/n` 是后来补上的**距离感**（见 §2.3），不点名、不报用时。

### 2.2 为什么可以删名单

v0.9.3 起，提交后棋盘上的参与者会被**逐人圈成绿 / 红**；谁不对、在哪一格，
玩家已经看见了。弹窗再列一遍编号是同一份信息的第三次表述（判卷 → 圈 → 名单），
还把一张结算卡读成了调试报告。

连带清理（`GamePage.tsx`）：

- `GameResult` / `pendingResultRef` 的失败态从 `{ kind:'failed'; blame: [...] }`
  收成 `{ kind:'failed' }`；
- 不再调用 `summarizeIssues`、`nameOf` 也只为判卷服务；
- `lib/gamePlacement.ts` 里 `summarizeIssues` / `PlacementBlame` 已无调用点，
  连同 `gamePlacement.test.ts` 的「失败的名单归并」两条用例一起删掉
  （**`participantLabel` 保留** —— `validatePlacement` 的文案还在用它）；
- `CheckItem` 那段注释里「没有头像的几位仍在 `blame` 里出现」同步改掉。

通过那一侧（定案卡 + 印章）一个字没动。

### 2.3 追加：正文报 `x/n 正确`

同日晚间把失败正文定成：

```
你没有找出所有人的位置！x/n 正确。未能结案。
```

`x` / `n` 都在**按下提交那一刻**算好，随结果一起存进 `result`，不是弹窗打开时
回头读棋盘：

- `n` = 名册里非空槽的数量（`slots.filter(Boolean).length`，空槽不参与判卷）；
- `x` = `buildCheckItems(...)` 里 `passed` 的人数 —— 也就是这一轮会被圈成
  **绿色**的圈数。判卷与呈现共用同一份 `validation.issues`，所以「绿圈 1 个」
  和「1/3 正确」永远对得上；没落头像的人必然带 `unplaced` issue，不会混进 `x`。

失败态因此从 `{ kind: 'failed' }` 扩成 `{ kind: 'failed'; correct; total }`，
`pendingResultRef` 同步；弹窗分支收成 `result?.kind === 'failed' ? … : null`，
让 TS 能窄化出这两个字段。

为什么这不是「又把名单列回来」：数量是**一格摘要**，不带身份、不带坐标，玩家
看见的是「还差几个人」，不是「谁错了」。绿圈已经把身份说完了，这里只补一个
总数，好让「差一位」和「差三位」有个可对照的刻度。

## §3 校验遮罩：四处独立完整遮罩

### 3.1 分层，不再挖洞

中间版本曾用四块 `fixed` 元素围着画布挖洞（量 `getBoundingClientRect`、四块拼
「视口 − 洞」）。晚间按用户要求改成**四处各自完整的遮罩**，把 `canvasRef` /
`checkHole` / `useLayoutEffect` / `checkScrimBands` 这一整套测量与拼接全删掉：

| 位置 | 挂载点 | 作用 |
|---|---|---|
| 左栏 | `<aside>` 内 `absolute inset-0`，`z-index: UI_Z.saveMask`（40） | 整栏压暗，并挡住名册 / 题面 / 主题开关的点击 |
| 右栏 | 同上（这一栏为此加了 `relative`） | 整栏压暗，挡住工具 / 视图簇 |
| 中列 | `<main>` 内 `absolute inset-0`，`z-index: UI_Z.saveMask`（40） | 铺满整个地图区，压住标尺条带与画布四周留白 |
| 地图区 | `canvasBase` 那个 div 的**子元素** `absolute inset-0` | 只压暗纸的底色 |

关键的层级安排在中列与画布纸之间：中列那层 `z-index = saveMask(40)`，而画布纸
（`game-canvas`，带 `transform`）在校验期间被临时抬到 `saveMask+1 = 41`。于是
中列遮罩压在**纸之外**的一切（留白、标尺、纸的投影）之上，却压不到棋盘本身 ——
棋盘照常明亮，只有纸四周的空白被压暗。正常游戏时画布纸不挂这一层 `z-index`，
不影响标尺压在纸边之上的默认层级（标尺 `UI_Z.ruler = 10` 仍低于纸）。

「只压暗纸底」那层（第四处）依旧在 `MAP_LAYER_Z.canvasBase = 10`，最小的内容层
`backgroundLayer = 20`，其余一路到 `mouseCursorBox = 46`；它是底色层的子元素，
自然被所有内容层盖住 —— 格子背景图、物品、头像、区域标签、校验圈（实测最高
42）都在它之上。于是既不用挖洞、不用量视口矩形，也不用随缩放平移重算：它本来
就在画布容器里，跟着纸一起 `transform`。

`main` 仍保留 v0.9.3 的 `pointer-events-none`（核对期间棋盘只读）；左右两栏的
遮罩是真实元素且默认接指针，所以两栏点不动；中列与地图区那两层额外带
`pointer-events-none`，纯视觉，不抢命中测试。

与「只有地图边框内不遮挡」那一版的差别：现在中列画布外的空白与标尺**也被遮**
（用户后续要求），棋盘内容照常清晰，纸底变暗，左右两栏整栏压暗。

### 3.2 颜色：与弹窗 overlay 同一层

中间曾按「边框色透明色」做过一版（外框色 `#4A3F35` 压 0.7 + `multiply`），
晚间定稿改成**弹窗遮罩的颜色**。理由：逐人校验与结算弹窗是同一个「暂停操作、
请看这里」的状态，不该一个偏墨、一个偏黑；玩家从核对过渡到弹窗时也不该看见
底色换了一次。

`dialog.tsx` 把那一层抽成常量，弹窗与四处遮罩共用（`CheckScrim` 组件统一渲染）：

```ts
export const DIALOG_OVERLAY_TINT_CLASS = 'bg-black/60';
// DialogOverlay: cn('sheet-fade fixed inset-0 z-50', DIALOG_OVERLAY_TINT_CLASS, …)
// CheckScrim:    cn(DIALOG_OVERLAY_TINT_CLASS, 'absolute inset-0', …)
```

Tailwind 仍能扫到这个字面量并生成 CSS；改弹窗遮罩那天，校验遮罩自动跟着改。
随之删掉：`hexToRgb` / `GAME_CHECK_SCRIM_ALPHA`、`checkScrimColor`、
`mix-blend-mode: multiply`。黑色 60% 在深浅两套主题下都只压暗，不需要混合模式
（实测浅色左栏 232→93、深色右栏 23→9）。

结算弹窗一出现四处遮罩一起撤掉 —— Radix 自己有**同一层** overlay，两层叠起来
会黑得过头。

## §5 没做的

- **不把名单做成「可展开的详情」**。用户要的是不列，藏起来仍是列。
- **不把 `x/n` 展开成名单 / 逐人明细**。计数是摘要，展开就回到 §2.2 删掉的调试报告。
- **不把棋盘本身压暗**。中列遮罩 `z-index: 40` 刻意压在画布纸（`z-index: 41`）之下，
  所以棋盘照常明亮、只压四周留白与标尺；若把棋盘也压暗，逐人校验的绿 / 红圈就
  会一起被蒙住，失去了「圈一圈揭开」的聚光效果。
- **不把失败文案做成可配置**。这一句是界面在说话，不是作者的声音（定案卡里那段才是）。
- **不给遮罩加渐变方向 / 动画**。三处都是纯色平涂，它只表示「这一段时间别动」；
  动起来反而会和棋盘上的扇形扫描抢注意力。
- **不给校验遮罩另配颜色 / 透明度 / 混合模式**。它与弹窗 overlay 是同一个状态，
  颜色只从 `DIALOG_OVERLAY_TINT_CLASS` 来；外框色那一版已按用户修订撤掉。
- **不再量视口矩形、不再挖洞**。三处遮罩都是完整的 `inset-0`；地图区靠图层
  顺序让内容露出来，比四块拼接少一整套测量 / clamp / resize 逻辑。
- **不把地图区遮罩抬到内容层之上**。用户选的是「只压暗纸底」，格子、物品、
  头像、校验圈都必须保持清晰；盖住它们就回到「整张地图区压暗」那一档了。
- **不给中列画布外的空白 / 标尺单独补遮罩**。本次范围只有左右两栏 + 画布底色层；
  要连这些一起压暗，得回到全屏遮罩那一版。
