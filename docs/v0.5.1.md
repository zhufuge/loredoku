# 地图编辑器系统需求文档（v0.5.1）

**文档类型**：版本需求与验收（本文档只定义需求、设计与验收口径，不含代码实现）
**修订记录**：2026-10-16 首版 —— **纯色块（背景色）+ 游戏路由 `/play` + 游戏页精简**
**适用范围**：物品模块（`/items`）、角色模块（`/characters`）、游戏模块（`/play`、`/play/:slug`）
**前置版本**：v0.5.0（`docs/v0.5.0.md`）
**实现载体**：`packages/shared` + `packages/server` + `packages/web`（**三包全动**：新增数据库列 + 迁移）

> **本版主题：让「没有图片」也能用，让玩家页面更干净。**
>
> - **纯色块**：物品与角色都可以**不上传图片**，选一个颜色（默认白色）就能**启用**——
>   这就是「纯色块类型」，它在画布 / 头像位上**以背景色块的形式展示**。
> - **游戏路由**：`/games` 与 `/games/:slug` 统一改为 `/play` 与 `/play/:slug`。
> - **游戏页**：顶栏只留「返回箭头 + LOREDOKU / 游戏名 + 规格」；封面、难度、来源、
>   人数、底部大段说明全部去掉；**放置编号不再让参与者框变淡**（只有放头像才淡）。
>
> 一句话记法：**无色块不图片， `/play` 开门，游戏页只留名字和格数。**

### 0.2 与 v0.5.0 的行为差异（用户可见）

| 场景 | v0.5.0 | v0.5.1 |

| 新建物品 / 角色 | 必须上传图片后才能「启用」 | 可选「纯色块」类型：选颜色（默认白）即可启用，**无需图片** |

## 1. FEAT-L01 物品纯色块

### 1.1 数据

`items` 表新增一列：

| 列 | 类型 | 约束 | 含义 |
|---|---|---|---|
| `bg_color` | `text` | 可空 | 纯色块颜色，`#RRGGBB`。`NULL` = 非纯色块（图片类型） |

`Item` 领域对象同步新增 `bgColor: string | null`（与 `imageUrl` 平级）。

### 1.2 创建与编辑

- **新建物品弹窗**（`CreateItemDialog`）新增「外观」二选一（`图片` / `纯色块`）：
  - 选「纯色块」时出现颜色选择器，**默认 `#FFFFFF`（白色）**，必填；
  - 选「图片」时与现行为完全一致（图片在详情里上传）。
- **物品详情表单**（`ItemDetailForm`）原「图片」区升级为「外观」区：
  - `图片` → 现有 `ImageUploader`；
  - `纯色块` → 颜色选择器（默认白），图片上传区隐藏；
  - 两种模式可在保存间来回切换：切到「纯色块」时 `bg_color` 落值；切回「图片」时 `bg_color` 置 `NULL`（**已上传的图片不被删除**，切回即恢复）。
- **启用条件放宽**：`启用` 按钮的可点条件从「已上传图片」改为「**已上传图片或有背景色**」。
- **徽标文案**：停用态的 `未启用` / `已停用` 判定同样放宽（有任一外观资源即 `已停用`，否则 `未启用`）。
- **删除图片的连带修正**（OPT-305 收窄）：删除图片时，**若该物品有背景色则不停用**；无背景色才维持「删图即停用」。

### 1.3 校验

`bgColor` 存在时必须匹配 `^#[0-9a-fA-F]{6}$`（新增常量 `BG_COLOR_PATTERN`），否则 400。

## 2. FEAT-L02 角色纯色块

与 §1 完全同构，作用于 `characters.avatar_*` 一族：

| 列 | 类型 | 约束 | 含义 |
|---|---|---|---|
| `bg_color` | `text` | 可空 | 纯色块颜色，`#RRGGBB`。`NULL` = 非纯色块（头像类型） |

- `CreateCharacterDialog` / `CharacterDetailForm` 增加同样的「外观」二选一 + 颜色选择器（默认白）。
- `Character.bgColor: string | null`。
- 启用条件、徽标、删除头像的连带停用规则与 §1.2 一致。
- 角色详情表单里该区标签从「头像」改为「外观」，上传区说明不变。

## 3. SPEC-L03 纯色块的渲染（在背景展示该色块）

**总规则：`bgColor` 非空 → 该条目按纯色块渲染（色块优先于图片）；`bgColor` 为空 → 按图片渲染（现状不变）。**

### 3.1 物品（画布）

| 层 | 组件 | 行为 |
|---|---|---|
| 层 12 背景层 | `MapBackgroundLayer` | 无图片且有 `bgColor` 时，格子铺满 `backgroundColor: bgColor`（原来直接 `return null`） |
| 层 4 物体层 | `MapObjectLayer` | 同上，按占格 `w × h` 铺满；`fitMode` / hover  lift 逻辑对色块不适用（色块无图片） |

编辑器左侧物品栏（`ItemPalette` → `ItemThumbnail`）与物品列表缩略图同步显示色块。

### 3.2 角色（头像位）

| 位置 | 组件 | 行为 |
|---|---|---|
| 参与者面板头像圆 | `ParticipantPanel`（`CharacterThumbnail shape="plain"`） | 无头像且有 `bgColor` 时，圆内铺满该色（替代现在的「名称首字」） |
| 游戏放置层头像 | `MapLayers.ParticipantAvatar` | 无头像且有 `bgColor` 时，画该角色的色圆（`objectPadding` 内缩） |
| 角色列表 / 参与者弹窗 | `CharacterThumbnail` | 同上：`circle` 形状铺色 + 保留 1px 边框；`plain` 形状铺色 |

### 3.3 兼容性

- 游戏快照（`MapGameSnapshot`）只存地图 + 谜题 JSON，物品 / 角色**实时现查**——纯色块对已部署游戏**自动生效**，无需回填、无需迁移存量快照。
- `bgColor` 不进入任何 JSON 结构（`MapDraft` / `PuzzleDraft` 均不含物品 / 角色本体），**JSON 版本号不变**（仍为 `MAP_JSON_VERSION = 3` / `PUZZLE_JSON_VERSION = 1`）。

## 4. FEAT-L04 游戏路由统一改为 `/play`

| 旧 | 新 |
|---|---|
| `/games` | `/play` |
| `/games/:slug` | `/play/:slug` |

- `router.tsx` 两条路由同步改名；旧路径**不注册**（不做 301 迁移，本机工具无需外链稳定性）。
- 所有跳转改为新路径：`GameCard`（卡片点击 / 回车）、`GamePage`（返回按钮 ×2）、`PuzzlesPage`（「已部署」徽标）、`GameDeployDialog` 里的访问路径预览文案。
- **API 不变**：`/api/games*` 是内部接口，用户不可见，本版不动（实现期裁定 R2）。
- `document.title` 文案不变（`游戏 · 格物` / `{name} · 格物`）。

## 5. 游戏页改版（SPEC-L05 ~ SPEC-L09）

### 5.1 SPEC-L05 放置编号时，参与者框不变淡

- 现状（SPEC-G05 §5.3 + SPEC-J05）：参与者**有任何标记**（编号或头像）就让 `ParticipantPanel` 的卡片变淡。
- 新规则：**只有头像落格**（`placement.kind === 'participant'`）才变淡；放置 / 切换 / 移除**编号**框保持原样。
- 实现：`lib/gamePlacement.ts` 新增纯函数 `avatarPlacedParticipantIds(board)`（只收头像），`GamePage` 的 `placedSlotIndices` 改用它；`ParticipantPanel` 组件本身**零改动**。
- `placedParticipantIds`（「有任何标记」集合）保留，供测试与其它查询使用，其文档注释注明变淡已改走 `avatarPlacedParticipantIds`。

### 5.2 SPEC-L06 ~ SPEC-L09 左栏上块精简

左栏上块（原「游戏信息」卡）重写为：

```
[←] LOREDOKU
ABC 5x5
```

- **SPEC-L06**：不展示封面（移除 80×56 封面缩略图与首字占位）。
- **FEAT-L07**：返回箭头之后展示 **LOREDOKU**（品牌名，用户原话 "LOREDUKO" 取项目名拼写 **LOREDOKU**，实现期裁定 R1）；**游戏名称放到下一行**，格式 `{游戏名} {格数}x{格数}`（如 `ABC 5x5`）。
- **SPEC-L08**：不展示难度徽标；不展示「来自地图 v{n}」；不展示参与者人数。
- **SPEC-L09**：移除左栏底部整段操作说明（原 ~150 字提示）。
- 右栏工具栏、提交校验弹窗、画布与两个游戏图层**完全不动**。
- 左栏宽度（256px）不变；上块去掉内容后自然变矮，参与者面板获得更高空间。

## 10. 实现期裁定

| # | 裁定 | 理由 |
|---|---|---|
| R1 | 品牌名取 **LOREDOKU**（与包名 `loredoku` 一致），不采用用户原话的拼写 "LOREDUKO" | 用户原话是口头转写；仓库、包名、界面右上角品牌统一为 `LOREDOKU`，避免两处拼写不一致 |
| R2 | **`/api/games*` 保持不变**，只改页面路由 | API 是内部接口、用户不可见；改名要动 server 路由 / 仓库 / 全部客户端调用，收益为零。`wording.test.ts` 显式断言「API 仍是 `/games`」以免后来者误改 |
| R3 | 新建物品 / 角色时**仍是停用态**（`is_active: false`），放宽的是「启用按钮可点」而非「自动启用」 | 保持既有 OPT-305 的「创建 → 上传/选色 → 手动启用」心智，避免无声地允许空壳条目进入画布调色板 |
| R4 | **色块优先于图片**：`bgColor` 非空时一律按色块渲染，不看有没有图 | 让「外观」二选一在渲染侧也有唯一解释；切回「图片」即把 `bg_color` 置 `NULL`，已上传的文件**不删**（§1.2） |
| R5 | 删图 / 删头像的停用判定写成 `is_active = CASE WHEN bg_color IS NULL THEN false ELSE is_active END` | 一条 SQL 原子完成，避免「先读再写」的竞态；`clearImage` / `clearAvatar` 各自的语义收窄后仍保留 OPT-305 对纯图片条目的行为 |
| R6 | `placedParticipantIds` **保留不动**，新增 `avatarPlacedParticipantIds` 供变淡使用 | 前者是「有任何标记」集合，唯一性规则与其它查询仍依赖它；新增纯函数让「变淡」这条 UI 规则独立演进，`ParticipantPanel` 组件零改动 |
| R7 | 迁移**不回填**、JSON 版本号**不变**（`MAP_JSON_VERSION = 3` / `PUZZLE_JSON_VERSION = 1`） | 物品 / 角色本体不进入任何 JSON（地图草稿 / 谜题 / 游戏快照都是引用 id），实时现查自动获得色块能力，存量游戏无需修复 |
| R8 | 纯色块对象层**不参与 hover lift** | lift 是「图片浮起」的视觉延伸；一整块颜色浮起会露出下方边界，反而更像 bug。`MapObjectLayer` 内把 `lifted` 收窄为 `hovered && liftOnHover && !item?.bgColor` |
| R9 | 参与者头像位色块用 `backgroundClip: 'content-box'` 加内缩圆 | 与图片分支的 `padding` 内缩保持一致，色块不会顶到格子边；`ParticipantPanel` 走 `shape="plain"`，由父级主题色圆盘裁剪 |
