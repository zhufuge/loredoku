## §2 区域标题居中

### 问题

`docs/v0.2.1.md` §2.1.3 定的算法是：取区域**最底部行**的格子，按 `x` 排序后取**中位数那一格**作为 `labelCell`：

```ts
const row = cells.filter(([, y]) => y === maxY).map(([x]) => x).sort((a, b) => a - b);
const middle = row[Math.floor(row.length / 2)];
return [middle, maxY];
```

渲染端再把这个格子**居中**：`left = (anchor[0] + 0.5) * cellSize`。

底部行格数为**奇数**时没问题（中位格就是中间那格，+0.5 正好是行中心）。**偶数**时就右偏半格 —— `Math.floor(len / 2)` 取到的是两个中位格里靠右的那个。

实测（map 17155，`GET /api/maps/17155/map`）：`gridSize 5`，`rg_5a9dff5d`「穿廊」的格子含 `[3,4]` 与 `[4,4]`，`labelCell` 是 `[4,4]`。格子 80px 时标签落在 `left: 360px`，而这一行跨 x 240–400、真正的中心是 **320**。同一张图的「正房」「下房」底部行各 3 格（奇数），`left: 120` 是对的。

### 做法

**渲染时按「锚点那一行里本区域格子的像素跨度中点」定位**，而不是「锚点格的格心」。

- `packages/web/src/lib/region.ts` 新增 `labelRowCenterX(cells, anchorY): number | null`：
  ```ts
  const row = cells.filter(([, y]) => y === anchorY).map(([x]) => x);
  if (row.length === 0) return null;
  return (Math.min(...row) + Math.max(...row) + 1) / 2;
  ```
  - 行内 3 格 `[0,1,2]` → `(0 + 2 + 1) / 2 = 1.5`，与原来的「中间那格 + 半格」**完全一致**；
  - 行内 2 格 `[3,4]` → `(3 + 4 + 1) / 2 = 4`，落在两格接缝上，不再偏右；
  - 锚点那一行没有本区域的格子（作者把 `labelCell` 挪走了）→ `null`，调用方退回 `anchor[0] + 0.5`。
- `packages/web/src/components/map/MapOverlayLayers.tsx`：`left` 由 `(anchor[0] + 0.5) * cellSize + offset.x` 改成 `centerX * cellSize + offset.x`，其中 `const centerX = labelRowCenterX(region.cells, anchor[1]) ?? anchor[0] + 0.5;`。

**没有改 `computeLabelCell`**，也没有改 `labelCell` 的 schema：`packages/shared/src/schemas/mapDraft.ts` 把它约束成 `z.tuple([coordSchema, coordSchema])`、`coordSchema` 是 int，本来就不允许半格。半格只应存在于**渲染**，不该写进草稿。

### 第一版为什么没修对

第一版在 `DraftRegion` 上加了一个 `defaultLabelCell` 字段，让 `computeLabelCell(cells, defaultLabelCell?)` 优先返回它。这条路是**死路**，已全部回退：

- 没有任何 UI 写入 `defaultLabelCell` —— 全仓只有类型定义与几处 `?? null` 兜底，恒为 `undefined`；
- 真正决定位置的是 `labelCell`，而它由 `editorStore` 的四处（`createRegion` / `toggleRegionCell` / `updateRegion` / `setGridSize`）每次重算并持久化；
- 因此**存量数据**（如 17155 里已经写死的 `[4,4]`）永远不会被修正 —— 而用户报的正是存量数据。

### 验证

`src/lib/region.test.ts` 的 `describe('labelRowCenterX')` 4 条：偶数行取接缝、奇数行与原行为一致、忽略别的行的格子、锚点行没有格子时返回 `null`。

`src/components/map/MapRegionLabelLayer.test.tsx` 新增 2 条位置断言（格子 40px）：

- 底部行 `[3,4]`+`[4,4]`、`labelCell [4,4]` → `left: 160`（按格心会是 180）；
- 底部行 `[0,4]`+`[1,4]`+`[2,4]`、`labelCell [1,4]` → `left: 60`（奇数行不变）。

真浏览器（1280×900，`/hlm/maps/17155/edit`）：三枚标签 `left` 分别是正房 204、下房 204、**穿廊 544** —— 穿廊从改前的右偏半格移到两格接缝上，与「下房」那一列对齐。

## §3 地图编辑点击标题弹信息框（与谜题/游戏做区别）

### 问题

v0.10.2 把区域标签从 `<button>` 改成不接管指针的 `<span>`，理由是「标签用 `translate(-50%, -100%)` 悬在格子上沿，盖住的往往不是自己区域的格子」。地图编辑里这个取舍是错的：作者点标题就是要编辑那块区域。

### 做法

- `packages/web/src/components/map/MapOverlayLayers.tsx`：`MapRegionLabelLayer` 新增可选 prop `onSelect?: (id: string) => void`。
- `packages/web/src/components/map-editor/EditorCanvas.tsx`：新增可选 prop `onSelectRegionLabel?: (id: string) => void`，透传。
- `packages/web/src/pages/MapEditorPage.tsx`：传入 handler；`PuzzleEditorPage.tsx` 与游戏页**不传**，行为不变。
- **判据就是「传没传 `onSelect`」**：传了才接管指针，没传保持 v0.10.2 的「点标签 = 点底下那格」。这样谜题编辑器与游戏页一行代码都不用改。

### 两处必须同时做对，缺一不可

第一版只做对了一半，两个问题各修一次：

**① 拦截必须挂在 `pointerdown`，不能只挂 `click`。**
画布选格发生在容器自己的 `onPointerDown`（`EditorCanvas.handlePointerDown` → `selectCellAt`），而 `pointerdown` 早于 `click`。只在 `onClick` 上 `stopPropagation()` 的话，按下那一刻格子已经被选中了 —— 信息框虽然弹出，选区却跑到了标题底下那一格。

```tsx
onPointerDown={onSelect ? (event) => { event.stopPropagation(); } : undefined}
onClick={(event) => { event.stopPropagation(); onSelect?.(region.id); }}
```

不 `preventDefault()`：它会抑制兼容的 `click`，标签就再也点不开了（文字选中已由 `select-none` 挡住）。

**② 只设 `selectedRegionId` 不够，抽屉读的是 `selection`。**
`EditorInfoDrawer` 渲染分支看的是 `selection`（`selection?.type === 'region'` 才画区域信息），只设 `selectedRegionId` 会弹出**空面板**——这正是 v0.7.0 点左侧区域列表踩过的坑（见 `packages/web/src/lib/editorFocus.ts` 里 `regionFocusSelection` 的注释）。

所以 handler 必须与左侧列表项走**同一对动作**：

```tsx
guardMapInfo(() => {
  if (editor.activeTool !== 'select') setTool('select');
  editor.setSelection(regionFocusSelection(regionId));
  editor.setSelectedRegion(regionId);
  setInfoOpen(true);
});
```

### 验证

`MapRegionLabelLayer.test.tsx` 新增 `describe('区域标签吃掉按下（v0.10.7）')` 2 条：

- 传了 `onSelect`（地图编辑）→ 从标签发出的 `pointerdown` **不冒泡**到 `document.body`；
- 没传（游戏页 / 谜题预览）→ 照常冒泡。

监听必须挂在 `document.body` 上，不能挂在测试自己的根容器上：React 把合成事件的监听器也挂在根容器那一层，同一节点上的原生监听器照样会触发（`stopPropagation()` 只截断后续节点）。

`EditorCanvas.hit.test.tsx`：

- 原「点区域标题覆盖的那块像素：选中它底下那一格」保留，注释补明它现在钉的是**游戏页 / 谜题预览**那条路径；
- 新增「地图编辑：点区域标题只选区域，不再顺带选中底下那一格」—— 断言 `onSelect` / `onSelectRegion` 都没被调用、`onSelectRegionLabel` 收到 `rg_a`；测试的 `render()` 扩了一个可选 prop 参数。

真浏览器（1280×900，`/hlm/maps/17155/edit`）：

- 真实鼠标点击「穿廊」→ 右侧抽屉显示「区域信息 / 包含 13 格 / rg_5a9dff5d / 名称 穿廊」，**没有**坐标 `C# R#` 行 ⇒ 走的是区域分支、格子没被选中；
- 点同一行的普通格心 → 抽屉显示「坐标 C3 R3 / 背景层 / 物品层」，格子选择照旧。

## §5 没做的

- 没把 `labelCell` 改成允许小数 —— 它是草稿数据、写库字段，半格只应存在于渲染；
- 没给谜题 / 游戏页加区域标题点击弹窗（用户明确要求「与谜题和游戏有区别」）；
- 没在区域信息框里加「把标题固定到当前位置」的交互 —— 当前算法是纯函数式的底部行居中，还没有「作者手动挪标题」这个需求；
- 没改 `computeLabelCell` 的返回值——它继续返回整格，作为**锚点行**的标识；像素级的水平居中交给 `labelRowCenterX`。
