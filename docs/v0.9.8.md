## §1 线索文本上下居中

名册卡（`ParticipantPanel`）的线索区是固定 72px 高的三行位，原来 `items-start` ——
线索只有一两行时，字挤在顶上，下半截空着，卡片看起来「没写完」。

改成 `items-center`：短线索在 72px 里居中，三行满的线索照样撑满（`line-clamp-3`
的裁剪行为不变，居中不影响溢出）。

只动这一个对齐方式，不动线索区高度、字号、行高 —— 那三样是排版基准，跟着卡尺寸走。

## §2 定案更大、印更斜

`VerdictMark` 是列表卡封面与游戏内遮罩**共用的同一个组件**，一次改动两处同时生效：

| | v0.9.7 | v0.9.8 |
|---|---|---|
| 字（卡片 / 遮罩） | `text-5xl` / `text-8xl` | **`text-7xl` / `text-9xl`** |
| 印角度 | −8° | **−14°** |

**角度有两份，必须一起改**：一份是 `VerdictStamp` 的 `-rotate-[14deg]` 类（静态
停住的角度），另一份是 `index.css` 里 `@keyframes stamp-press` 的收尾帧
（`55%` / `78%` / `to` 三处 `rotate(-14deg)`，`from` 从 `-18deg` 相应改到 `-24deg`
以保持「从更斜转正」的回弹）。只改一处的话，「有没有播动效」会停在两个不同角度。

印的尺寸上限（52%）、上提量（`-mt-[0.55em]`）、原色不翻色都沿用 v0.9.7 第六批。

### 2.1 卡片上的「定案」也倾斜、改半透明；游戏内的印让开一段

用户（第三批）：

> - 游戏列表定案卡片的定案二字也倾斜，颜色改成半透明的。
> - 定案游戏内的印章再向右150px向上50px。

**卡片上的字**：`VerdictMark` 里只有 `onDark === false`（= 列表卡封面）那一档改：

- `text-foreground` → **`text-foreground/40`**（半透明 40%）。那是蒙在封面上的一个
  印迹，不是一条要读的标题；实心字压在缩略图上太抢眼。
- 加上 **`-rotate-[14deg]`**，与印章同一个角度 —— 字与印是同一次盖下去的两部分，
  一正一斜会读成两件事。

**两处都改成粗体**（用户第四批：「内外两个定案字体改成粗体」）。这里有个坑：
`.font-kai` 写着 `font-synthesis-weight: none`（v0.7.9 的理由是「文楷只有 400 一档，
糊边加粗像劣质国风」），所以只挂 `font-bold` 是**无效**的 —— 字重照样 400。
这一处显式放开：`[font-synthesis-weight:auto]`，让浏览器合成粗体。其余用文楷的地方
（页标题、名册、正文）不受影响，那条禁令在那些地方仍然成立。

遮罩里的两处（`onDark`，游戏内的定案遮罩）**除了加粗之外保持原样**：结案那一刻
「定案」就是结论本身，要看得清，不能半透明。

**游戏内的印**：`VerdictMark` 新增 `stampOffset?: { x, y }`（px），只传给了 `GamePage`
的遮罩（`{ x: 150, y: -50 }`）。卡片上不传，位置不变。

为什么用 `translate` 属性而不是 `transform`：`stamp-press` 的关键帧写的就是整条
`transform`（`scale` + `rotate`），偏移挂上去会被那次动画覆盖 —— 印会先跳回原位再
弹回来。`translate` 与 `transform` 正交，两者叠加，动画期间偏移也不会丢。

## §3 定案卡恢复 hover 放大

v0.9.7 第四批曾把定案卡的封面缩放一起去掉，理由是「结案是既成事实，该稳稳停着」。
这一版用户要回来，口径分开看：

- **几何推进（`scale`）恢复**：它是「这张卡可点」的通用手感，结案卡仍能点进去看
  成绩，不该独缺这一下。
- **鼠标光源（`--glow-x` 那两层 `LIGHT_LAYERS`）仍不演**：v0.9.7 的禁令继续有效，
  定案卡 `completed` 时 `onPointerMove` 仍是 `undefined`、光层整组不渲染。

两处封面元素（`<img>` 与无封面时的占位 `div`）都去掉 `!completed &&` 的前置条件。

## §4 计时与完成时间不共存

用户：「有完成时间时，重置计时。计时开始走时，清空完成时间」。

一句话：**一局只要重新开跑，它就不再是「已定案」的那一局**。落点两处，
都在 `GamePage.tsx`：

1. `resetTimer()` —— 重新开始 / 再玩一次都走这里。在 `resetGameTimer(...)` 之后补
   `clearGameCompletion(storageId)`：归零用时，同时把完成记录一起清掉。
2. `resumeTimer()` —— 表从「停」转「走」的那一刻。补同一句。

第 2 处看起来是重复，但两条路径不重叠：`restart` / `replay` 走 `resetTimer`（表本来
就在走），未通过弹窗的「继续游戏」和关闭弹窗走 `resumeTimer`（表是停的）。
后者的清空是幂等的 —— 未通过的局本来就没有完成记录，清了也无害。

**这条改变了一处既有行为**：已完成关卡点「再玩一次」后，完成记录没了，列表页那张卡
不再显示完成时间与定案遮罩。这是「计时与完成时间互斥」的必然结果 —— 记录描述的是
「那一局」，重开就是新的一局。

## §5 动效归悬浮的 `×`，且只在**落笔**那一刻演

用户：「标记x点击方格放置时，应该是悬浮的x有动效，而不是放置的x有动效」。

原先 `forbidden-pop`（从 0.35 倍弹到 1.16 倍、带一点回正旋转）挂在**放置层刚落下的
`×`** 上。玩家手一动，先看到的是指针底下静止的图跳过去，再看到身后那一格自己弹了
一下 —— 因果是反的。动效应该演在手指尖上的那个东西。

- **摘掉**：`MapGamePlacementLayer` 里两条 `×` 渲染路径（配了标记图的 `<img>`、
  没配图时的 `<text>×</text>`）都不再挂 `forbidden-pop`。放下的 `×` 直接出现。
- **搬过去**：`MapGameToolHintLayer` 里两条悬停预览路径挂上 `forbidden-pop` ——
  配了标记图时的 `<img>`、没配图时的 `<text>`。

**触发时机：落笔，不是「指针进入方格」。** 这一条与「动效归属」是两件事：让悬浮的
`×` 带类只解决了「演在谁身上」，没有解决「什么时候演」。第一版把预览的 `key` 绑在
格子坐标上（`hint-${cell.x},${cell.y}`），于是**每换一格都重挂载、都弹一次** ——
鼠标扫过棋盘像一路在划，动效变成了「移动反馈」。

现在是两个独立的量（都在 `GamePage`）：

| | 作用 |
|---|---|
| `forbiddenPop`（只增） | 提示层在**两支同款动画**之间换名字（`forbidden-pop` / `forbidden-pop-alt`）：`animation-name` 一变，CSS 动画从头播。只增不减。 |
| `forbiddenPopCell`（有时限） | **刚落笔的那一格**（`"x,y"`）。提示层只在自己正停在这一格时挂动效类；落笔后开 `GAME_PLACE_PULSE_MS`（400ms）窗口，到期归 `null`。 |

类必须退掉：不退的话，指针离开棋盘再进来时那个新元素一挂载就带着类，会在「鼠标进入
方格」时又演一遍 —— 那正是要避免的那件事。而且这枚 `×` **跟着指针走、是同一个 DOM
节点**：只用一个「窗口开着」的布尔量，玩家点完立刻挪到隔壁格，它会带着类飞过去、
在新格子上又弹一次。收窄到具体那一格才没有这个漏洞。

### 5.1 动效改成纯放大缩小，且不许「闪一下」

用户（两轮）：

> - 点击出现悬浮的 x 的动效时，动效改为放大缩小。
> - 放置的 x 出现会浮现到悬浮的 x 上，然后闪现一下回到后层，不要闪现。

**动效本身**：`@keyframes forbidden-pop` 从「0.35 倍淡入 + 转 −18° + 过冲到 1.16」
改成 `1 → 1.18 → 1` 的纯放大缩小，两端都停在 1、全程不小于 1，也不再有旋转。

为什么连淡入一起去掉：悬停这枚与刚落下的那枚**尺寸与位置完全重合**（同一格、同一个
`GAME_FORBIDDEN_FONT_RATIO`），它盖在身后那枚上面。动画头几帧比身后那枚小，落下的
`×` 就从四周露出来、随后又被盖回去 —— 这正是用户说的「浮现上来又闪现回后层」。
只放大缩小时没有会露出来的缝，也就没有闪。

**「闪现」还有第二个来源**：重播动画原来靠换 React `key` 重挂载（先是按格子键，
后来按落笔令牌）。`<img>` 一换身份，浏览器在新元素画出第一帧之前有一帧空白 ——
身后那枚照样从缝里露一下。现在**不换 key**：元素身份不变，只把 `animation-name`
在 `forbidden-pop` / `forbidden-pop-alt` 两支之间轮换（`pop % 2`）。名字一变动画
照样从头播，画面不断。两支关键帧逐帧相同，只为「换名字」这个手段而存在。

编号的 `place-pop`（「盖章」）**不动** —— 用户只提标记 `×`。

顺带把 `GamePlacementPulse` 从 `Record<string, number | null>` 收紧成
`Record<string, number>`：`×` 不再进这张表，那个 `null` 分支已无处可去。
`dispatchCell` 的 forbidden 分支也不再调 `markPulse`。

## §6 橡皮：先演退场，再清空

用户：「清除按钮，点击方格时，如果方格有放置，触发放置的x或序号或参与者的动效，
再清空」。

直接 `clearCell` 的话，格子上的东西瞬间消失，玩家只看到画面重绘了一次 —— 分不清刚
擦掉的是哪一格，按住滑过一片时完全跟不上。

现在是**两拍**：

1. `dispatchCell` 的 `clearing` 分支先看这一格有没有放置。没有 → `return false`，
   连动效都不播（空格上本来就没东西可擦）。
2. 有 → `eraseCell(x, y)`：把格子记进 `erasing`（`Set<string>`），放置层据此给那一格
   挂 `erase-out`（缩小到 0.45 + 淡出）；`GAME_ERASE_MS = 220` 之后才
   `updatePlacement(clearCell)`。

**三种放置形态共用同一支退场**（`components/map/MapGameLayers.tsx`）：头像在容器
`div` 上、编号整格套一层 `<g>`、`×` 在图/字形自身上。玩家要看见的是「刚才那一格被
我擦掉了」，不是「编号有编号的擦法、头像有头像的擦法」。

**每格各记各的 timer**（`eraseTimersRef`）。按住滑过好几格时，几段退场应当并排演，
而不是后一格把前一格的定时器顶掉 —— 那会让前一格永远停在半透明。

`@keyframes erase-out` 的 `animation` 带 `both`：动画结束后元素要保持末帧的透明，
直到页面把它摘掉，否则最后几毫秒会闪回原样。

## §8 没做的

- **不把定案字号做成可配置**。它是版式常量，两处共用同一个组件，跟着 `large` 走。
- **不给 `×` 的放置补一个更轻的入场动效**。用户要的是「放置的 `×` 不要有动效」，
  静默出现就是他要的；再补一支轻的等于没改。
- **不给「指针进入方格」补动效**。悬浮的 `×` 只在落笔那一刻弹，换格是纯移动 ——
  第一版按格子键重播，读起来像每挪一下都在划笔，已在同版内改正（见 §5）。
- **不把落笔动效做成「跟着指针走」**。它钉在落笔的那一格上（`popCell`）；跟着指针
  走的预览是同一个 DOM 节点，不按格子收窄就会把动效带到隔壁格（见 §5）。
- **不给 `×` 的放大缩小补淡入或旋转**。淡入会让它一开头比身后那枚小、露出落下的
  `×`；旋转会让边缘扫出去。纯缩放是唯一不会露出缝的做法。
- **不用 React `key` 重挂载来重播动画**。换 key 会让 `<img>` 有一帧空白，正是
  「闪一下」的来源；改用两支 `animation-name` 轮换（见 §5.1）。
- **不让卡片上的「定案」也半透明**（即不把 `onDark` 与 `large` 合成一个开关）。卡片
  与遮罩是两种用途：一个是封面上的印迹，一个是结论本身。现在按 `onDark` 分档，两处
  各自取合适的浓度（见 §2.1）。
- **不把印章偏移做成可配置**。`{ 150, -50 }` 是这一屏的版式常量，跟着 `large` 那一路
  传给 `GamePage`，作者不需要调它。
- **不改 `.font-kai` 的 `font-synthesis-weight: none`**。那条禁令对页标题、名册、正文
  仍然成立（楷体糊边加粗不好看）；只有「定案」这两个大字在组件里单独放开，见 §2.1。
- **不给卡片上的「定案」加粗体字重文件**。为两个字多背一份 900 KB 的 woff2 不值得，
  浏览器合成粗体在这个字号上够用。
