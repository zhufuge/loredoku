# v0.5.9 — 地图侧命名重构

> 本版**不改行为**：只把地图相关的前后端文件、目录、类型、常量与接口前缀从 `project*`
> 统一成 `map*`，并把封面目录搬到 `maps/`、物品图目录搬到 `items/`。README 说的「地图 /
> 谜题」术语，这次在代码里也对上了。
>
> 现状说明在 [`docs/map-management-and-editor.md`](./map-management-and-editor.md) —— 本文
> 只回答「为什么这么改、改了哪些」，改完功能那份要同步。

## 0. 一句话

`project` 是已经消失的 `map_projects` 表留下的名字。表早改叫 `maps` 了，代码里却还有一层
`projectRepository` / `ProjectGridCard` / `/api/projects`。本版把这层名字清掉：**元素叫
地图，代码就叫 map**。

## 1. 需求与裁定

| # | 需求 | 裁定 |
|---|---|---|
| 1 | 地图页面相关前端文件与组件从 project 改为 map，如 `MapEditorPage` / `MapViewPage` | 目录、组件、页面、API 客户端、hook 全部对齐；路由参数 `:projectId` → `:mapId`（§2） |
| 2 | 后端上传封面路径迁到 `maps` 文件夹 | 磁盘目录 `storage/uploads/maps/` + `cover_path` 前缀，一次迁移带过（§4） |
| 3 | 检查页面对应前后端的文件夹与文件命名，优化成对应元素名 | `project*` 全量改名；顺带清掉无调用者的 `card` / 旧画布 schema 别名（§3） |
| 4 | 后端上传目录 `storage/uploads/cards` 改成 `items` | 磁盘目录 + `items.image_path` 前缀一起改，`processCardImage` 顺势改叫 `processItemImage`（§4.2） |

**不改的东西**（有意为之）：

- `maps` 表的索引 / 序列仍叫 `map_projects_*`（PG 的 `RENAME TABLE` 不会跟着改；动它要 raw SQL，
  收益只有可读性）。
- `CARD_ROTATIONS` / `CardRotation` 保持原名 —— 历史迁移 `20260101000004_create_map_cells.ts`
  直接 import 它，改常量名就得改历史迁移，越界。
- `stores/editorStore.ts` 保持原名：它同时是地图画布的 store 与两个编辑器共用的
  `Selection` 类型来源，改成 `mapEditorStore` 反而让 `lib/editorFocus`（谜题编辑器也用）
  指向一个带 map 前缀的模块。

**旧接口前缀**：`/api/projects` 与 `/api/projects/*` 在 `router/index.ts` 里重定向到
`/api/maps`，308 且保留余下路径与查询串；`/api/cards → /api/items` 走同一个 helper。没有用
`router.redirect()` —— 它不展开目标里的 `:path*`，子路径会跳到字面量 `/api/maps/:path*`；
也没有用 `router.use()` 中间件 —— 中间件只在某条路由命中时才执行，而旧前缀下一条路由都没有。
所以注册成 `all` 路由，在 handler 里设 `308` + `Location`。

## 3. shared

| 旧 | 新 |
|---|---|
| `schemas/project.ts` | `schemas/map.ts` |
| `Project` / `ProjectDetail` / `ProjectStatus` / `ProjectRow` | `MapEntry` / `MapDetail` / `MapStatus` / `MapRow` |
| `PROJECT_*` 常量 | `MAP_*` |
| `MapResponse.project` | `MapResponse.map` |
| 谜题草稿 `map.projectId` | `map.mapId` |

顺带清掉两个**没有任何调用者**的遗留模块：

- `schemas/card.ts`：v0.2 把 card 改叫 item 时留的别名（`createCardSchema = createItemSchema`
  …）。真正在用的 `createItemSchema` 在 `schemas/item.ts`，别名只在自己的测试里出现。
- `schemas/mapCanvas.ts`：合并前那套「一次 PUT 整份画布」的 schema（`saveMapSchema` /
  `mapCellSchema`，格子还带 `cardId`）。草稿读写早已走 `saveMapDraftSchema`。里面唯一仍被
  `mapDraft.ts` 使用的 `regionColorSchema` 已搬进 `mapDraft.ts`，其余删除。

`types/domain.ts` 里同样没有调用者的旧画布类型 `MapCell` / `RegionData` / `MapData` 与
`CardUsage` / `CharacterUsageDetail` 一并删除；`ItemUsage` 直接定义，不再是 `CardUsage` 的别名。

**谜题导入兼容**：谜题草稿的地图引用从 `projectId` 改成 `mapId`。导入的是用户手里的旧 JSON，
键名不能强制，所以 `puzzleMapRefSchema` 用 `z.preprocess` 收下旧键并归一化；库里已存的草稿
读取时也走同一层兼容（`mapDraftCompat`）。

## 4. 上传目录迁移

两个目录都换了名，各一个迁移，理由相同：只改 DB 不搬盘会让旧图全部 404，只搬盘不改 DB 也一样 ——
所以两件事必须放在同一个迁移里，这是唯一能保证「库里指向的文件真的在那儿」的地方。
目录已经手工搬过的环境（目标已存在）跳过搬运；`down` 方向同理。

### 4.1 地图封面 `projects/` → `maps/`

`packages/server/src/db/migrations/20260101000023_v059_cover_folder_maps.ts`：

- `up`：搬 `storage/uploads/projects/` → `storage/uploads/maps/`，并把 `maps.cover_path` 的
  `projects/` 前缀改成 `maps/`；
- `down`：反向搬目录、反向改前缀。

### 4.2 物品图 `cards/` → `items/`

`packages/server/src/db/migrations/20260101000024_v059_item_image_folder_items.ts`：

- `up`：搬 `storage/uploads/cards/` → `storage/uploads/items/`，并把 `items.image_path` 的
  `cards/` 前缀改成 `items/`；
- `down`：反向。

`cards` 表在 v0.2 就改叫 `items` 了，目录名却留在旧语汇里。同时把上传函数
`processCardImage` 改成 `processItemImage`（参数名 `cardId` → `itemId`，目录 `'cards'` → `'items'`），
免得代码里还留着「卡片」这个词。
