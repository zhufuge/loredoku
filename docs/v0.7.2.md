## 0. 一句话

七件事：

1. **版本条目「看」和「改」分开**：地图与谜题的版本行，点击封面 / 名称 = 只读预览
   （同眼睛按钮），「编辑」另立一个按钮放在预览后面。
2. **谜题编辑器补上 `?v=` fork 态**：点「编辑」只进编辑器、**不建行**；点「保存」才
   fork 出新草稿；没保存之前**没有发布按钮**。
3. **部署弹窗的封面默认取谜题封面**（谜题有封面时），不选文件就把它复制成游戏封面。
4. **日间模式按钮加深**：按钮底色与 hover 都往下压一档。
5. **谜题行「已部署」独立成列**（原先贴在名称后面）。
6. **列表行 hover 有背景高亮**（地图 + 谜题）。
7. **方格最小 32px**；**地图预览加平移按钮（默认选中）**。

## 1. 改之前是什么样

- **谜题版本行**：封面 / 名称的主点击 = 「编辑此版本」，走的是**立即 fork**
  （`POST /puzzles/:id/versions/:n/fork`），也就是点一下列表就在库里多出一条草稿行，
  再跳进编辑器。想「先看一眼再决定改不改」只能点眼睛按钮；而随手点一下封面就多一条
  草稿，是这个交互最贵的地方。
- **地图版本行**：封面 / 名称的主点击 = 「以此为底稿新建」，带 `?v=` 进编辑器
  （保存才 fork，行为已经是对的），但**没有独立的「编辑」按钮** —— 想进编辑器只能点封面。
- **谜题编辑器**：没有 `?v=` 态。v0.7.1 §5.5 曾把这条当作「与地图有意不同」写进文档，
  理由是「画布太大、也没必要在保存时才落行」。实际用起来这条差异站不住：地图能做到、
  谜题也应该能；而且「点一下多一条草稿」正是 §2.1 那个交互成本的来源。
- **部署弹窗**：封面区只认「这个游戏已经传过的封面」，谜题的封面（创建谜题时传的那张）
  完全用不上，作者每次部署都要再选一次图。
- **谜题列表「已部署」**：徽标挤在名称右侧，名称一长就被挤掉，且整列宽度随名称浮动。
- **列表行**：没有 hover 底色，鼠标在一屏十几行里找不到落点。
- **方格**：`MIN_CELL_SIZE = 90`，既是自适应缩放下限，也是「基本信息 → 方格边长」的
  可填最小值 —— 24×24 的板子在笔记本上必然溢出视口，只能横向拖着看。
- **地图预览**：能平移（空格 + 拖拽 / 中键），但**没有任何按钮**，不知道的人只能滚动。

## 2. 谜题列表

### 2.1 版本条目：主点击 = 预览，编辑另立按钮

| 入口 | 草稿行 | 版本行 |
|---|---|---|
| 封面 / 名称 点击 | 进编辑器 | **只读预览**（`/puzzles/{id}/view`） |
| 耳朵（预览按钮） | 预览草稿 | 预览版本 |
| **编辑（新按钮）** | —（封面点击已经是编辑） | **`/puzzles/{id}/edit?v={n}`** |

- 新按钮排在预览按钮**后面**，图标 `SquarePen`（与「编辑信息」的裸铅笔区分开：
  那个改的是名称 / 描述 / 封面，这个进编辑器改谜题本体）。
- 只在版本行渲染。草稿行的封面 / 名称点击本身就是「进编辑器」，再挂一个编辑按钮
  是同一个动作的两个入口。
- 卡片（`PuzzleGridCard`）只服务草稿块，因此不加这个按钮；版本块恒为列表行。

### 2.2 已部署独立一列

版本行名称后面不再夹徽标，改成固定宽度的 `部署` 列：已部署打徽标，未部署留空
（不是整列不渲染 —— 行内要按列对齐，缺一格会让后面的列漂）。草稿行也占这一列的空间，
否则两块的行宽对不上。

### 2.3 行 hover

行容器加 `transition-colors hover:bg-accent/60`。`accent` 在日间模式已被 §7 压深，
拿它当 hover 底色和菜单项的 hover 是同一档，视觉上「同一个交互系统」。

## 3. 谜题编辑器：`?v=` fork 态

### 3.1 数据源

`?v={n}` 只是「这一屏是 fork 态」的标记，`:puzzleId` 仍然是**被点的那一行自己的 id** ——
版本行本身是一条完整的 `puzzles` 行（带整份画布副本），所以 `GET /api/puzzles/:id` 与
`/api/puzzles/:id/map` 直接就能喂满编辑器，不需要新的读取端点。这与地图列表
（`/maps/{versionRowId}/edit?v={n}`）完全同构。

### 3.2 进去时不建行

「编辑」按钮只做 `navigate`，不发任何写请求。没保存就离开 = 什么都没发生
（`?v=` 态下 `puzzleId` 还是版本行 id，版本行只读，不可能被写脏）。

### 3.3 保存时才 fork

```
点「保存」
  → POST /api/puzzles/:id/versions/:v/fork   body: { data: 编辑器当前草稿 }
  → 服务端校验（角色存在 / 联动引用对**版本自带的画布**合法）
  → INSERT 一条草稿行（同血统，名字「{版本名} (自 v{n})」，data.name 同步改名）
  → 前端 adopt 新行身份（画布 / 撤销栈 / 视口都不动）
  → replace 到 /puzzles/{新行 id}/edit
```

- **为什么 replace 而不是 push**：此后所有操作（再保存 / 发布 / 部署）都必须落在新行
  id 上；不留历史，用户按返回不会回到「还没落库的 fork 态」这个中间态。
- **adopt 而不是重新 `init`**：重新初始化会把缩放打回 1×、清掉撤销栈，而画布内容一个
  字节都没变。`puzzleStore.adoptSavedEntry(detail)` 只换身份字段（id / 名称 / 描述 /
  `updatedAt` / `status`），随后 `initKeyRef` 记下新 key，让 init effect 判定成
  「同一份内容」跳过。
- **命名**：与地图一致，行名 `{版本名} (自 v{n})`（查重兜底），`data.name` 跟着改 ——
  行名与 JSON 名是两个必须同源的副本。作者想改名去列表的「编辑信息」或基本信信息。

### 3.4 发布按钮的出现时机

| 状态 | 状态徽标 | 发布按钮 | 保存按钮 |
|---|---|---|---|
| fork 态（未保存） | 不渲染（这一屏既不是草稿也不是版本） | **不渲染** | **可用**（哪怕没改过东西 —— 保存就是「生成新草稿」这个动作本身） |
| 保存后（已到新行） | 草稿 | 渲染 | 有改动才可用 |
| 普通草稿编辑 | 草稿 | 渲染 | 有改动才可用 |

`EditorToolbar` 因此多一个 `canSave?: boolean`：缺省仍按 `dirty` 判定，fork 态由页面传
`true`。发布按钮的隐藏方式沿用 `onPublish` 不传即不渲染（不是 disabled —— 一个点不动的
按钮只会让人猜原因）。

> **地图同一条修正**：地图编辑器早就有 `?v=` 态，但它的「保存」在 fork 态下同样按
> `dirty` 判定，于是「点编辑 → 直接点保存」什么都不会发生。v0.7.2 一并修掉
> （`canSave={dirty || forkFrom !== null}`）。

### 3.5 版本历史弹窗

「编辑此版本」原先直接 fork + 跳转。既然列表的编辑按钮已经改成「进 `?v=` 态」，
这里也统一成 `navigate('/puzzles/{id}/edit?v={n}')` —— 同一个动作在全应用只有一个
副作用（不建行），用户点错地方也不会莫名多出草稿。

## 4. 部署弹窗：封面默认取谜题封面

显示优先级（同一套规则决定「看到什么」与「提交什么」）：

| 情况 | 封面区显示 | 提交时 |
|---|---|---|
| 选了新文件 | 新文件的本地预览 | 上传该文件 |
| 重新部署、游戏已有封面 | 游戏封面 | 保持不动 |
| 点了「移除」 | 空 | `clearCover: true` |
| 谜题有封面（前三者都不成立） | **谜题封面** | 把谜题封面**复制**成游戏封面 |
| 谜题也没封面 | 空（虚线框「选择图片」） | 不传 |

- 复制走**前端**：部署成功后 `fetch(谜题封面 URL)` → `File` → `POST /games/:id/cover`。
  与「创建谜题时选的封面在建行之后才传」是同一条既有约定，服务端一个字都不用改；
  而且拿到的是**游戏自己的副本**（服务端会重新编码 + 出缩略图），谜题后来换封面 /
  删封面都不会让游戏封面变成悬空路径。
- 文案分三种：「已选择：xxx.jpg」/「当前为该游戏已上传的封面。」/「默认使用谜题封面，
  可替换。」—— 作者得知道这张图是「已经是我的」还是「只是默认」。

## 5. 地图列表

与谜题同一套（§2.1 / §2.3）：

- 版本行：封面 / 名称点击 = 预览（`/maps/{id}/views`），新增**编辑**按钮 →
  `/maps/{id}/edit?v={n}`；
- 草稿行：封面 / 名称点击 = 进编辑器（`/maps/{id}/edit`），不加编辑按钮；
- 行 hover 高亮。

## 6. 日间模式按钮加深

只动日间模式（`.dark` 的底色全不动 —— 深色下按钮本来就压得住；只给深色补上自己那一档
hover 值，免得沿用日间的色值）：

| 变量 | 改前 | 改后 | 影响 |
|---|---|---|---|
| `--primary` | `221.2 83.2% 53.3%` | `221.2 83.2% 48%` | 「保存」「部署」「新建」等实心主按钮 |
| `--secondary` | `210 40% 96.1%` | `210 40% 92%` | 卡片主按钮、选中态、徽标 |
| `--accent` | `210 40% 96.1%` | `210 40% 90%` | hover 底色（菜单项 / ghost / outline） |

hover 本身也换写法：`bg-primary/90`、`bg-secondary/80` 这类**降透明度**的悬停，在浅色
底上会让颜色**变浅**（白底叠 90% 的蓝 = 更亮的蓝）。改成**各自一档的 hover 色**
（`--primary-hover` / `--secondary-hover` / `--destructive-hover`，tailwind 里配成
`hover: 'hsl(var(--x-hover))'`）—— 日间比底色深一档，深色也各给自己的一档。
（落地时没走 `hover:brightness-90`：那是滤镜，会把按钮里的文字和图标一起压暗，
再与 `disabled:opacity-*` 叠加时颜色不可预期。）

## 7. 方格最小 32px

`MIN_CELL_SIZE` 90 → **32**（先落到 48，同日按追加要求再放到 32，见 §13）。它同时是两件事：

1. 「基本信息 → 方格边长」的可填下限（`MAP_STYLE_CELL_SIZE_MIN`，schema 同一条约束）；
2. 自适应缩放的**下限** —— 24×24 的板子在常见窗口下不再溢出视口。

方格变小会等比缩小线宽 / 字号（`cellScale = cellSize / BASE_CELL`），32px 时 scale ≈ 0.267：
2px 的分隔线变成 0.53px（刚好还在 `LINE_WIDTH_MIN = 0.5` 之上，不会消失），外框 1.6px，
字号一律被 `FONT_SIZE_MIN = 9` 兜住。
`DEFAULT_CELL_SIZE` 仍是 `MIN_CELL_SIZE` 的别名（只是「测量前的占位值」，自适应一跑就被覆盖）。

## 8. 地图预览平移按钮

头部工具区（标尺 / 缩放 / 重置那一组）最前面加一个手形开关，**默认打开**：

- 开启后**左键拖动即平移**（不必按空格、不必中键），光标 `grab`；
- 预览页是只读的，左键本来没有别的含义 —— 默认能拖才符合「看画」的直觉；关掉后左键
  只剩悬停高亮；
- 平移会置 `userAdjusted`，自适应重算不再把视图弹回去（与滚轮缩放同一条规则）；
- 与「空格按住拖拽」「中键拖拽」并存，互不排斥。

### 12.3 谜题 fork 态（§3）

- `useForkPuzzleVersion({ navigate: false })`：hook 里只有 `navigate !== false` 才 toast +
  跳转 —— 编辑器要自己决定落地时机，所以让它安静地把结果交回来。
- `useEditorSave` 的 `mutation` 参数改成结构化对象（`{ isPending, mutateAsync }`），
  页面按 `forkFrom` 分流到 `forkSaveMutation`（带 `data`）或普通 `saveMutation`。
- `onSaved` 的 fork 分支，顺序不能换：
  ```ts
  initKeyRef.current = `${data.id}:${data.updatedAt ?? ''}`;
  puzzle.adoptSavedEntry(data);          // 只换身份，画布 / 撤销栈 / 视口不动
  toast.success(`已基于 v${forkFrom} 生成新谜题`);
  window.setTimeout(() => navigate(`/puzzles/${data.id}/edit`, { replace: true }), 0);
  ```
  先写 `initKeyRef` 再 adopt：随后的 detail 到达时 key 已匹配，init effect 不会把刚保存的
  画布重播一遍。`setTimeout(0)` 是让出一帧再换 URL —— 同步 `navigate` 会让新 id 的取数与
  adopt 落在同一批 state 更新里，页面闪一次空画布。
- 发布按钮用「不传 `onPublish` 即不渲染」隐藏（`onPublish={forkFrom === null ? … : undefined}`），
  状态徽标同理传 `null`（fork 态既不是草稿也不是版本）。
- `canSave={puzzle.dirty || forkFrom !== null}`；地图编辑器同步成
  `editor.dirty || entryDirty || forkFrom !== null`。
- `PuzzleVersionHistoryDialog`：「编辑此版本」不再调 fork，改成关弹窗 + `navigate(?v=n)`，
  `busy` 只剩 `remove.isPending`。

### 12.4 部署封面（§4）

- 显示与提交共用一个派生值，避免「看到谜题封面、提交的却是别的」：
  ```ts
  coverSource = picked > none(移除) > game > puzzle > none
  inheritedCover = coverSource === 'game' ? existingGame.coverUrl
                 : coverSource === 'puzzle' ? puzzle.coverUrl : null
  ```
- `lib/fileFromImageUrl.ts`：`fetch` → 校验 `response.ok` 与 `content-type` 前缀 `image/` →
  `arrayBuffer()` → `new File([buffer], baseName.ext, { type: mime })`。读 `arrayBuffer()`
  而不是 `blob()`：跨 realm 的 `Blob`（undici 的）喂给 jsdom 的 `File` 构造函数会被拒。
  任何一步失败都返回 `null` —— 封面是锦上添花，不该让部署整体失败。
- `useDeployGame` 的 `mutationFn`：`cover` 优先上传，否则 `coverFromPuzzleUrl` 复制一份，
  两者都没有就不动封面。复制走前端，服务端零改动，而且游戏拿到的是**自己的副本**。

### 12.5 日间模式（§6）——与设计稿的唯一出入

§6 原写 `hover:brightness-90`，落地改成**新增 hover token**：`--primary-hover` /
`--secondary-hover` / `--destructive-hover`（日间各比底色深一档，深色各给自己一档），
tailwind 配 `hover: 'hsl(var(--x-hover))'`，`button.tsx` 三处换成 `hover:bg-*-hover`。
理由见 §6 末尾：`brightness-*` 是滤镜，会把按钮里的白字和图标一起压暗。

### 12.6 方格 32（§7）

- `MIN_CELL_SIZE = 32`；`DEFAULT_CELL_SIZE` 是它的别名，因此**测量前**的占位格宽也从 90
  变成 32 —— 首帧更小、自适应随后接管，没有可见跳变。
- 32px 时 `cellScale ≈ 0.267`：分隔线 0.53px（`LINE_WIDTH_MIN = 0.5` 之上）、外框 1.6px、
  字号落 `FONT_SIZE_MIN = 9`，两者都是既有护栏，不需要新常量。
- 连带更新的断言：`canvasScale.test`（`cellScale` 用 `MIN_CELL_SIZE / BASE_CELL` 表达、
  `itemPadding` 3 → 2、最小尺寸 metrics 改成按比例算）、`canvasSize.test`（区间文案
  90~240 → 32~240；**1440×900 下 24×24 算出来是 36，不再被下限夹住**，用例改成
  「不低于下限且明显小于中等板子」）、`mapStyle.test`（拒收 40 → 拒收 31、边界值 90 → 32）、
  `editorStore.test`（clamp 后是 `MIN_CELL_SIZE`）、`ruler.test`（下限处字号已被
  `FONT_SIZE_MIN` 兜住，比例断言改用 `BASE_CELL × 0.75`）。

### 12.7 预览平移（§8）

- 判定收口成 `lib/grid.ts` 的 `startsPan({ button, spaceHeld, panMode })`：中键恒平移；
  左键需要空格或手形开关；右键 / 侧键一律不算。三条入口并存，互不排斥。
- `MapViewPage`：`panMode` state（**初值 `true`**）+ `Hand` 图标按钮（`aria-pressed`，开启时套
  `bg-accent text-accent-foreground`）+ `cursor: spaceHeld || panMode ? 'grab' : 'default'`。
  开关只活在这一次访问里（不像标尺那样写 localStorage）：需求是「默认选中」，记住上次反而
  会让第二次进来变成「默认没选」。
  平移本身仍走原来的 `panRef` 拖动，`userAdjustedRef` 照旧置位，自适应不会把视图弹回去。

### 12.9 顺手修掉与踩过的坑

1. **地图编辑器 fork 态点保存没反应**：`canSave` 原先按 `dirty` 判定，而 fork 态下「一进来
   什么都没改就点保存」正是要支持的动线。已随 §3.4 一并修掉。
2. **`GamePage.test` 的「落盘」用例一直在依赖巧合**：它点是视口 (450, 350)，而测试没有真的
   跑过自适应（jsdom 尺寸恒为 0，`ResizeObserver` 也是桩），棋盘停在「测量前的占位格宽」。
   90px 时 450 / 90 = 第 5 格（9×9 内），48px 时 450 / 48 = 第 10 格（越界），于是什么都不落盘。
   修法是先点一下「重置视图」让自适应真的跑一遍，再按视口正中点击（正中恒为中间那一格）。
3. **jsdom 的 `Blob` 陷阱**：`new Response(new Blob([...], { type }))` 里那个 Blob 不是合法
   `BodyInit`，会被 `String()` 成 `"[object Blob]"` 且 `type` 丢失 —— 测试夹具改成字符串
   body + 显式 `content-type` 头；实现侧改用 `arrayBuffer()` + 读响应头，正好也绕开了这个问题。
