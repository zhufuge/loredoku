# 需求 + 设计：参与者编号展示配置 + 游戏中放大提示（v0.6.4）

> **状态**：**已实施**（2026-10-20，含一轮修复）。设计即本文；落地记录见 §8，修复记录见 §9。
> 需求原文：
> ```
> 参与者编号展示配置（在参与者信息中），输入文本，用于展示到左上标号（记录映射），
> 默认为序号（拖动改变位置时序号会更新，但不覆盖映射），以配置为主，未配置时展示序号。
> 游戏中，添加触碰或点击参与者时，放大展示地图中参与者和参与者编号，用于提示当前放置的情况。
> ```

## 0. 一句话

两件事：

1. **编号展示配置**——参与者信息抽屉里多一个「编号展示」输入框（≤6 字）。填了就用它当左上
   标号与棋盘里的编号；没填就还是序号。映射记在槽位条目上（`CharacterSlotEntry.
   displayNumber`），**拖动改位置只更新序号、不覆盖配置**。
2. **触碰 / 点击放大**——游戏里悬停或点击参与者卡片时，把该参与者**在地图上已有的东西**
   （头像、自己的编号字形）放大展示，提示「这一位当前放在哪」。

## 1. 改之前是什么样

- 左上标号写死是序号：`participantSequence(index)` = `index + 1`。想给参与者一个「甲」
  「K1」式的编号，只能改名字，而名字在别处（抽屉标题、提示语）另有用途。
- 游戏页点参与者卡片只是为了「进入放置模式」，地图上没有任何反馈——放过的格子在哪、
  现在点的是谁，玩家得自己在 9×9 棋盘里找。

## 2. 目标

| # | 目标 | 怎么算达成 |
|---|---|---|
| 1 | 编号可配置，缺省为序号 | 抽屉加「编号展示」输入框；空 = 序号 |
| 2 | 拖动不覆盖配置 | 配置存在**条目**上，`swapSlots` 搬整个条目；序号是渲染时按位置现算 |
| 3 | 所有展示位一致 | 面板标号、游戏棋盘编号、悬停预览共用 `participantBadgeText` 一个映射 |
| 4 | 游戏中提示当前放置情况 | 悬停 / 点击参与者 → 该参与者在地图上的头像与编号放大 |

## 3. 设计

### 3.1 存什么：条目上的一个可选字段

```ts
/** 左上标号 / 棋盘编号展示的文本；缺省或空 = 序号。 */
displayNumber?: string | null;
```

- 加在 `CharacterSlotEntry`（谜题草稿 `characterSlots[i]`），**随谜题冻结进发布快照**，
  游戏页直接读，不需要任何新的发布期计算。
- schema（`characterSlotEntrySchema`，`.strict()`）声明即收：`z.string().trim().max(
  PARTICIPANT_DISPLAY_NUMBER_MAX).nullable().optional()`。**不升 `PUZZLE_JSON_VERSION`、
  无迁移**——可选字段 + 缺席即旧行为，和 v0.6.3 的 `rosterCols` 同一个理由。
- 长度上界 6（`PARTICIPANT_DISPLAY_NUMBER_MAX`）：编号要能被一眼扫完，且棋盘 9 宫格里
  一格只有三分之一格宽（见 §4.2 的收缩算式）。

### 3.2 唯一映射：`participantBadgeText`

```ts
participantBadgeText(slot, index) // 配置（trim 后非空）？ 配置 : String(index + 1)
```

所有展示位都走它：谜题编辑器面板、谜题预览、游戏页名册、游戏棋盘 9 宫格、悬停预览。
**任何一个位子都不许自己 `slot.displayNumber ?? index + 1`**——空串 / 纯空格的「配了但
等于没配」这种边界只在一个地方处理。

### 3.3 写入路径：清空 = 删字段

- `ensureEntry`（水合 / 导入规范化）：trim 后非空才保留 `displayNumber`，否则**不留
  `undefined` 字段**（JSON 里多一个 `displayNumber: undefined` 的键没有意义）。
- `setParticipantConfig` 的 patch 收 `displayNumber?: string`：空串走删字段分支，与
  `positionConditions: []` 的处理同构。
- 抽屉里 `displayNumber` state 由 `slot.displayNumber ?? ''` 播种，placeholder 是
  「序号 N」——**placeholder 就是缺省值的自解释**，省掉一行说明文字。

### 3.4 为什么序号永不覆盖配置

序号 = `index + 1`，**渲染时从槽位位置现算**；配置存在条目上，拖动走 `swapSlots` 搬的是
整个条目。两条数据流永不相交：拖动 → 序号变、配置跟着人走；改配置 → 序号不受影响。
「以配置为主，未配置时展示序号」因此是结构保证，不是靠某处 if 兜的。

## 4. 设计：触碰 / 点击放大

### 4.1 激活态复用

游戏页本来就有 `linkageActivation`（MOD-802 的单激活状态机：`enter` / `leave` / `click` /
`restore` / `escape`）。v0.6.4 直接复用它——名册卡片悬停发 `enter/leave`、点击发 `click`，
`activeParticipantId`（0 基槽位号）传给放置层时 +1 换成棋盘编号（棋盘从 1 编号）。

### 4.2 放置层：`activeParticipantId`

`MapGamePlacementLayer` 新 prop `activeParticipantId?: number | null`（1 基，`null` =
无激活）：

- **头像**：`scale(GAME_ACTIVE_PARTICIPANT_AVATAR_SCALE)`（1.3）+ 一圈
  `boxShadow` 高亮环，`transform-origin: center`，150ms 过渡。别人不变。
- **编号字形**：只放大**属于该参与者自己**的字形（`GAME_ACTIVE_PARTICIPANT_NUMBER_SCALE`
  1.5），描边同比例放大保持线重；**共用格子里别人的字形不放大**——共享格不等于整格属于
  激活者。
- 预览页 / 编辑器不传这个 prop，行为零变化。

## 7. 收益与代价

- 收益：编号从此是**数据**不是**位置副产品**；「甲 / K1」式编号在名册与棋盘完全一致；
  游戏里点谁放大谁，放置情况一目了然。
- 代价：多一个可选字段与一个 helper；棋盘 9 宫格的字形可能是文本（见 §9 的适配算式）。
- 明确不做：编号唯一性校验（两位参与者可以配同一个文本——映射是展示层的，不是标识符）；
  按编号搜索。

## 9. 修复记录（2026-10-20，v0.6.4 fix）

> 反馈原文：
> ```
> 在游戏里，方格内展示的编号也要替换为填写的值（如果有的话）
> ```

§4 只改了放置层的**交互**（放大），漏了 9 宫格字形与悬停预览的**文本**——它们还在渲染
裸 `participantId`。也就是说配了「甲」的参与者，名册标号是「甲」，棋盘里仍是「3」。

### 9.1 两处渲染位改走 `participantBadgeText`

- **放置层 9 宫格**（`MapGamePlacementLayer`）：字形文本 = `participantBadgeText(
  slots[participantId - 1], participantId - 1)`。
- **悬停预览**（`MapGameToolHintLayer`）：预览必须承诺**和放置时一样的标签**，否则配了
  编号的参与者会「悬停显示 3、放下变成甲」。顺带把它的 prop 从 `themeColors: Map` 换成
  `slots`——颜色与标签同一个来源，GamePage 里那个平行的 `themeColors` memo 一并删掉。

### 9.2 文本比数字宽：`glyphFontSize` 收缩算式

9 宫格每格只有三分之一格宽（`GAME_NUMBER_GRID = 3`），而编号最长 6 字。新增纯函数：

```ts
glyphFontSize(text, boxWidth, fontSize)
// 宽字符（CJK / 全角，≥ U+2E80）记 1 em，其余记 0.62 em；
// 估算宽度超过盒子就按比例缩字号——数字（历史情形）永不触发收缩。
```

两层（放置 / 预览）都走它，描边随字号同比例缩放。两位参与者不会因为谁的编号长而互相压字。

### 9.3 踩坑：浮点使能的字符串断言

旧代码描边是 `numberStroke * glyphScale` = `(10×0.08)×1.5` = `1.2000000000000002`，新
算式是 `(10×1.5)×0.08` = `1.2`——数学等价，`String()` 后不同。`MapGameLayers.v064.test.tsx`
里那条 `expect(strokeWidth).toBe(String(...))` 因此挂掉。**教训：跨浮点乘法链的断言用
`toBeCloseTo`，别用字符串相等**。已改为数值近似。

### 9.4 落地清单

- `web/src/lib/gamePlacement.ts`：`glyphFontSize`。
- `web/src/components/map/MapGameLayers.tsx`：两层编号文本 + 收缩；提示层 prop 换 `slots`。
- `web/src/pages/GamePage.tsx`：删 `themeColors` memo，提示层传 `slots`。
- 测试：`gamePlacement.test.ts`（收缩算式 3 例）、`MapGameLayers.v064.test.tsx`（配置文本 /
  主题色 / 收缩 / 预览层 3 例）。
