# 需求：游戏页摆放进度本地存档 + 视图缩放（v0.6.2）

> **状态**：**已实施**（2026-10-19）。设计即本文；落地记录见 §9。
> 需求原文：
> ```
> v0.6.2
> 游戏页面/play/:slug
> - 添加游戏记录存在localstorage中，保存棋盘上的放置的参与者/参与者编号/禁止符号，第二次进入时还能继续游玩
> - 增加放大缩小按钮
> ```
>
> **背景**：游戏页 `/play/:slug` 是玩家端的唯一游玩界面（`docs/v0.4.0.md` §6 起）。
> 它渲染部署时冻结的快照，棋盘状态（`GamePlacementState`）只活在 React state 里 ——
> 刷新、关标签页、第二天再来，一切归零。视图侧同样被钉死：v0.4.0 验收时**主动移除**了
> 缩放簇，理由是「画布固定自适应」，于是小屏或大棋盘上看细节只能靠眯眼。

## 0. 一句话

棋盘进度按 slug 存进 localStorage，进页面自动恢复（头像 / 编号 / 禁止符号 + 已提交标记）；
右栏补回缩放簇与 Ctrl+滚轮、空格拖拽，缩放范围沿用全站 25%~400%。

## 1. 现状

| 项 | 现状 |
|---|---|
| 棋盘状态 | `useState<GamePlacementState>`，无任何持久化 |
| 撤销栈 | 内存内，上限 `GAME_PLACEMENT_HISTORY_MAX = 200` |
| 已提交标记 | `useState<boolean>`，只在本次会话内有效 |
| 视图 | 只有自适应 `fit` + 标尺开关；`zoom` 恒为 `1`，无平移 |
| localStorage | 只有「标尺显隐」「主题」「地图页视图模式」三个 UI 偏好 |

游戏页没有任何账号体系，"进度" 天然是**这台浏览器**的进度 —— 这正是 localStorage
的适用面，也决定了它的边界（换设备、换浏览器看不到，见 §8）。

## 2. 目标

1. 玩家摆到一半离开（刷新 / 关页 / 第二天再进），回来时棋盘还是原样：
   参与者头像、参与者编号、禁止符号三样都在，「已提交」的勾也留着。
2. 右栏能放大缩小，能重置视图，放大后能看到角落（需要平移）。

## 3. 存档设计

### 3.1 存什么、不存什么

| 内容 | 存 | 理由 |
|---|---|---|
| 棋盘 `board` | ✅ | 头像 / 编号 / 禁止符号全在这一个结构里（`GamePlacementBoard`） |
| 已提交 `submitted` | ✅ | 勾没了玩家会以为进度丢了 |
| 撤销 / 重做栈 | ❌ | 跨会话撤销没有意义，且体积随操作数增长 |
| 当前工具态 `mode` | ❌ | 回来时应该是「空手」状态，不是还举着禁止符号 |
| 选中 / 悬停的参与者 | ❌ | 一次性交互态 |
| 视图 `zoom` / `pan` | ❌ | 每次进页面按窗口自适应，和只读预览页一致（§8） |

### 3.2 键与载荷

```
key: loredoku.game.progress.<slug>
```

```jsonc
{
  "v": 1,                 // 结构版本，变了就整条丢弃
  "gridSize": 9,          // 指纹
  "participantCount": 6,  // 指纹
  "submitted": false,
  "board": {              // 与渲染层同一个 GamePlacementBoard
    "1,1": { "kind": "participant", "index": 2 },
    "2,3": { "kind": "numbers", "entries": [1, 4] },
    "4,4": { "kind": "forbidden" }
  }
}
```

按 slug 分键：换一局就是另一条记录，互不覆盖。键里不放用户 id（没有账号）。

### 3.3 指纹与失效

存档带 **`gridSize` + `participantCount`** 两个指纹。读的时候与当前游戏不一致 → 整条
当没存过。

同一 slug 可以重新部署（`POST /api/puzzles/:id/games` 覆盖部署），换了地图版本或换了
谜题名单之后：

- 坐标的**含义**变了（4×4 的 "3,3" 与 9×9 的 "3,3" 不是同一格）；
- 编号的**指向**变了（编号 3 已经是另一个人）。

此时「尽量恢复」只会得到半张对不上的棋盘，比空白更让人困惑。所以不迁移、不清洗成
半截，**整条丢弃**。

### 3.4 清洗规则（`sanitizeBoard`）

指纹相同也可能读到脏数据（手改、旧版本残留、写到一半）。逐格清洗，**不清洗整条**：

| 情况 | 处理 |
|---|---|
| 键不是 `"x,y"` 数字对 | 丢掉 |
| 坐标越界（`>= gridSize`） | 丢掉 |
| `participant` 的 `index > participantCount` | 丢掉 |
| `numbers` 里超出名单的编号 | 从 entries 里摘掉；摘空了就丢整格 |
| `numbers` 只有合法编号 | 保留 |

写之前也过一遍同样的清洗 —— 存档里不留说不通的格子。

### 3.5 写入时机：一个出口

所有改变棋盘的操作都走 `updatePlacement(updater, submitted?)`：

```
算新状态 → 与旧状态同一引用则直接返回（拒绝的落子不写盘）
        → 更新 state + 存档镜像 → 写 localStorage
```

覆盖的入口：放头像 / 放编号 / 放禁止符号 / 清单格 / 长按清空 / 撤销 / 提交。
集中一处是为了避免「新增一个操作忘了存」这类问题。

- **空盘且未提交** → 删掉整条键（`writeGameProgress` 自己判），玩家清空后不留垃圾记录。
- **空盘但提交过** → 保留（那条勾要活到下次进来）。
- **写失败**（无痕模式、配额满）→ 静默吞掉：**玩得下去**比存得下来重要。
- **读失败**（JSON 坏、`getItem` 抛异常）→ 当作没存过，从空白开始。

### 3.6 恢复流程

进入页面、快照到手后（`draft` 可用）：

1. 用当前 `{ gridSize, participantCount }` 读存档；
2. 读到 → `{ board, past: [], future: [], submittedPastLength: 0 }`，并恢复 `submitted`；
3. 没读到 → `createGamePlacementState()`；
4. 棋盘非空时给一条 toast「已恢复上次的摆放」，否则静默。

`hydratedKeyRef` 记住水合过哪一局（`slug|gridSize|participantCount`），保证：

- StrictMode 双调用不会重复恢复、重复提示；
- 同一局的数据刷新（react-query refetch）不会把玩家刚摆的东西盖回存档版本；
- 真的换了游戏才重新水合。

## 4. 缩放与平移

### 4.1 控件

右栏（原「只有标尺开关」的位置）变成视图簇，自上而下：

```
[ + ] 放大
100%  当前比例（等宽数字，避免跳动）
[ − ] 缩小
[ ⟲ ] 重置视图
[ ▤ ] 标尺开关
```

到达 `ZOOM_MIN = 0.25` / `ZOOM_MAX = 4` 时对应按钮 `disabled`。步长 `ZOOM_STEP = 0.1`，
与编辑器 / 预览页共用 `clampZoom`。

### 4.2 锚点

| 手势 | 锚点 |
|---|---|
| 按钮 | **视口中心** —— 按钮在右栏，但用户看的是画布中间；以按钮为锚点棋盘会往一边跑 |
| Ctrl / ⌘ + 滚轮 | **指针位置**（与预览页一致） |

### 4.3 与放置手势的隔离

游戏页左键单击/长按是**放置**，所以平移必须用不冲突的手势：

- 按住 **空格** + 左键拖拽；
- **中键**拖拽。

两个细节：

1. 空格按下时 `preventDefault`，避免浏览器把空格当翻页 / 点击聚焦；
2. `pannedRef` 记录本次手势是否真的拖动过 —— 拖完松手浏览器仍会补一个 `click`，
   不吞掉就会顺手在落点上放一个编号。

### 4.4 自适应与手动调整的取舍

沿用预览页的规则：**用户手动调过视图（缩放 / 平移）之后，容器尺寸变化不再强制重排**，
否则拉一下窗口就把辛苦对准的视图打回原形。「重置视图」同时做三件事：`zoom = 1`、
居中、清掉「用户调整过」标记，把布局交还给 `ResizeObserver`。

标尺开关仍会触发一次 `fit`（预留边带宽度变了），因此也会把缩放归 1 —— 与预览页
现状一致，不在本版改动。

## 6. 测试

**`packages/web/src/lib/gameProgress.test.ts`（19 例）** —— 存档规则：

- `sanitizeBoard`：三类放置原样保留、越界与非法键丢弃、超名单编号摘除且空格消失；
- `parseStoredProgress`：正常载荷、版本不符、指纹不符、schema 不符、非对象、空盘
  （未提交 → `null`；已提交 → 保留）、脏格被清洗而非整条丢弃；
- localStorage 往返：按 slug 分键不串味、空盘未提交删键、空盘已提交保留、坏字符串、
  指纹变化、`setItem` / `getItem` 抛异常、空 slug。

**`packages/web/src/pages/GamePage.test.tsx`（5 例）** —— 页面接线（mock 掉 4 个数据 hook）：

- 读到存档 → 计数器显示「已放置 3 个」，且读完之后存档**没有被清掉**（水合顺序的守卫）；
- 已提交的存档 → 提交按钮回到「已提交」态；
- 存档指纹不符（换了网格）→ 空盘；
- 用禁止符号落一格 → localStorage 里出现对应的 `forbidden`（写入路径）；
- 缩放簇：100% → 110% → 90% → 重置回 100%。

`jsdom` 的元素尺寸恒为 0，页面用例给中列塞了一个固定矩形，`fit` / `zoomBy` 才有可断言的
几何；`ResizeObserver` 与 `matchMedia` 由测试内替身提供。

## 7. 收益与代价

**收益**

- 摆到一半可以走人，长局（十几个人、上百次标记）不再一次坐完。
- 刷新不再等于清盘 —— 以前误按 F5 就全没了。
- 小屏 / 大棋盘能放大看细节，放大后能拖到角落。

**代价**

- 多了一条「本地状态」，与快照版本之间多了一层需要指纹校验的关系（§3.3）。
- 同一浏览器多标签页同时玩同一局会互相覆盖（后写的赢），见 §8。
- 游戏页的状态从「纯内存」变成「内存 + 磁盘」，写入路径必须集中（§3.5）。

## 8. 遗留（明确不做）

- **跨设备 / 跨浏览器同步**：需要账号或服务端存根，本版没有账号体系。
- **多标签页实时同步**：不做 `storage` 事件广播 —— 同一局开两个标签页属于异常用法。
- **存档管理 UI**（列表 / 手动清除 / 导出）：清空棋盘（长按清除）即清存档，够用。
- **撤销栈落盘**：跨会话撤销没有意义，且会让载荷随操作数膨胀。
- **视图状态落盘**：每次进页面按窗口自适应，符合「一进来就能玩」的预期。

### 9.2 与设计的偏差

1. **`submitted` 进了同一个 `updatePlacement` 出口**，而不是单独写一次盘。否则提交时
   会出现「棋盘写了、标记还没写」的窗口；现在两个字段一次落盘。
2. **`readGameProgress` 需要显式传指纹**，不在内部去读游戏数据 —— 它因此完全不知道
   路由与快照，测试可以直接喂任意 meta。
3. **恢复提示只在棋盘非空时给**。空盘且提交过的存档只恢复那个勾，此时弹「已恢复上次的
   摆放」会让人以为棋盘上有东西。
4. **`fit` 兼任「重置视图」**：加 `setZoom(1)` 与清 `userAdjustedRef`，而不是新写一个
   `resetView` —— 两者要做的事完全一样，多一个函数只会让「哪个才是复位」变得含糊。
