# v0.5.8 — 地图版本管理优化专项

> 本版只做**地图的版本管理与创建/编辑器入口**，谜题侧只在被连带影响时改动。专项分三
> 阶段、全部记在本文内、**不升版本号**：一阶段（§1~§10）表改名与尺寸真源收敛；二阶段
> （§11）页面与路由；三阶段（§12~§13）发布反馈收敛 + 合并设计指针。
>
> 现状说明在 [`docs/map-management-and-editor.md`](./map-management-and-editor.md) ——本文
> 回答「为什么这么改」，那份回答「现在是什么样」，改完功能两份都要同步。

## 0. 一句话

画布尺寸从「建图时填一次、DB 存一列」改成「进编辑器时初始化、只活在草稿里」；地图列表的
工作条目与版本条目从此**长得完全一样**；发布弹窗去掉备注，只留二次确认。

## 1. 需求与裁定

| # | 需求 | 裁定 |
|---|---|---|
| 1 | 名称后展示版本号，没有则「草稿」；两种条目展示相同 | 徽标只看 `versionNo`，两种条目共用一套 DOM（§2） |
| 2 | 版本/草稿单列且对齐，时间列、操作列对齐，操作为图标 | 固定宽度：`w-14` 版本 / `w-52` 时间 / `w-32` 操作（§2） |
| 3 | 新建地图对话框删尺寸字段与「不可修改」描述 | 字段整体移除，不是禁用（§3） |
| 4 | 连续点击会生成多个版本草稿；**不要一进编辑页就保存** | 删 FIX-F03 首次自动保存；版本条目不再点击即 fork（§4） |
| 5 | 卡片与封面缩小，hover 内缩 | `aspect-[4/3]` + 封面动效（§2） |
| 6 | 无尺寸记录时弹窗初始化：填尺寸或导入 | `MapInitDialog`，两条出路都是显式动作（§4.3） |
| 7 | 发布弹窗去备注，改二次确认 | 输入框删除，`notes` 一路删到 DB（§5） |
| 8 | `map_projects→maps` 删 `grid_size`；`map_games→games`；`map_versions` 删 `grid_size`+`notes` | 一个迁移做完（§6） |

## 2. `/maps`：两种条目同一套 UI

**徽标**：`entry.versionNo !== null ? v{n} : '草稿'`，只保留名称后那一格。v0.5.7 及以前
工作条目写「已发布 v3」、副信息再写一遍「地图 v3」（同一数字出现两次）；用
`versionNo ?? currentVersionNo` 则会让**发布过的工作条目也顶个 v3**，与「草稿」语义相反。
`currentVersionNo` 仍服务「预览取血统最新版」，只是不再是徽标来源。「共 N 个版本」整段
删除（版本列已说清，计数没有信息量）。

**卡片**：封面 `aspect-[4/3]`（正方形是 v0.5.3 为看全棋盘定的，但四列下近 240px 高，把
名称时间挤到底部要滚动）；默认 `scale-[1.2]` 裁中间、hover `group-hover:scale-100` 全览
（一阶段是 1→0.95，只有 5% 幅度，肉眼几乎看不出）；首字母占位不缩放；网格
`sm:2 / lg:3 / xl:4 / 2xl:5`，骨架同步，再宽也不铺满。操作区 = 主按钮 + 三点菜单 + 删除
（删除是破坏性操作，不进菜单）。

**三点菜单**（`components/project/EntryActionsMenu.tsx`）：编辑信息 / 预览 / 复制（复制
仅工作条目）。自绘而非引 dropdown 库（本仓无此依赖，三项菜单不值一个 Radix）；浮层
`createPortal` 到 `<body>` + `position: fixed`，坐标在 `useLayoutEffect` 里量、`scroll`
（capture）/`resize` 重算——原来它是卡片内的 `absolute`，被封面的 `overflow-hidden`
裁掉下沿，网格最后一行点不中。**外部关闭的 `pointerdown` 必须排除菜单自身**：portal 后
菜单不在容器里，不排除会先卸载浮层、菜单项 `click` 永不触发。预览可用性看
`versionNo ?? currentVersionNo`，都为 `null` 时禁用而非按 `kind` 藏起来。

**列表列**：封面 → 名称 → 版本/草稿（`w-14 tabular-nums`，`v9`/`v10` 不错位）→ 描述 →
时间（`w-52 text-right`，绝对时间）→ 操作（`w-32 justify-end`，四个图标）。原来单独占列
的 `n × n` 移除——创建时不再有尺寸，未初始化时这列常空，空列正是「不对齐」的来源。

**移除的两个入口**：新建谜题（`/puzzles` 页的版本选择器本来就是唯一入口）、编辑此版本
（fork 属于版本历史的操作，编辑器内的面板仍有入口；它也是需求 #4「连续点击生成多个条目」
的直接来源）。

## 3. 新建地图对话框

删 `DialogDescription` 的「创建后画布尺寸（n × n）不可修改。」（v0.5.8 起这句是假的，
编辑器里能改），换成「创建后进入编辑器，先设置画布尺寸。」；删尺寸输入框与
`createProjectSchema.gridSize`（只剩 `name` / `description`）。编辑对话框的「画布尺寸
不可修改。」同样换成「画布尺寸在编辑器里调整。」

## 4. 编辑器：不自动保存 + 初始化弹窗

### 4.1 为什么不自动保存

v0.3.10 FIX-F03 会在首次进入时若 `draft.style === null` 自动 `persist()` 一次，本意是让
渲染内容与草稿一致。它依赖 `maps.grid_size` 有值（`parseDraft` 用 `emptyDraft(grid_size)`
兜底），所以「未初始化」根本不存在。列删掉之后：`mapQuery` 失效（发布 / 改尺寸 / 保存）
让 effect 重跑 → 自动保存跟着重跑、每次写一个新 `draft_updated_at` → 列表快速点同一条目
就写出一串草稿修订。处理就是整段删除（连 `basicInfoPersistedRef`），进编辑器只
`editor.init()`，一个字节都不写；用户点保存、改尺寸、导入时才写。

### 4.2 「未初始化」成为显式状态

`MapResponse.draft` 改成 `MapDraft | null`，服务端 `parseDraft` **不再用 `emptyDraft()`
兜底**——兜底会把「未初始化」伪装成「已有默认画布」，前端再也分不出来；且 `grid_size`
已删，兜底尺寸也无处可取（`GRID_SIZE_DEFAULT` 只留给区域 CRUD 那条只读路径，那条路在
未初始化时本来就到不了）。

### 4.3 初始化弹窗

`components/editor/MapInitDialog.tsx`，两条出路：填尺寸走 `PATCH /projects/:id/grid-size`
（`resizeDraft` 在草稿为空时新建一份只带 `gridSize` 的草稿，成功后 query 失效重拉）；
导入走 `POST /projects/:id/map/import`，**不走**编辑器原有的「覆盖当前画布？」二次确认
（那时画布还是空的），用 `initImportRef` 区分来路。弹窗**没有取消按钮**（关掉它也没有
画布可渲染，返回列表走左上角），尺寸输入框自动聚焦、回车即开始编辑。

### 4.4 发布前置校验

未初始化的地图调发布拿到 400「请先在编辑器里初始化画布尺寸」，而不是关于 `null` 的堆栈。
正常 UI 到不了这一步（弹窗挡着）。

## 5. 发布弹窗

# 第二阶段（同一专项的后续修订，不升版本号）

## 11. 页面与路由

### 11.1 需求与裁定

| # | 需求 | 裁定 |
|---|---|---|
| 1 | 三点下拉在卡片底部展示不全 | 浮层 portal 到 `<body>` + fixed 跟随（§11.2） |
| 2 | 卡片最大一行 5 个 | 网格加 `2xl:grid-cols-5`，骨架同步（§2） |
| 3 | 封面默认只展示中间，hover 缩小展示全部，幅度再加大 | 默认 `scale-[1.2]`、hover 归 1（§2） |
| 4 | 不展示「共 x 个版本」；名称后**是版本才展示**版本号 | 徽标只看 `versionNo`（§2） |
| 5 | 视图切换记录到 localStorage | `loredoku.maps.view`（§11.5） |
| 6 | 列表里 maps 内容覆盖 version，点击两条 id 一样 | 根因：两类条目都进同一个 `/editor/:projectId`；版本条目改去自己的预览（§11.6） |
| 7 | `/editor/:id` 改 `/maps/:id/edit` | 直接改名，旧路径注销不重定向 |
| 8 | `/maps/:id/:version/view` 改 `/maps/:id/views` | 版本号移进 `?v=`，缺省取最新发布版本（§11.7） |

### 11.2 三点菜单 portal（现象与做法见 §2）

层级仍走 `UI_Z.drawer`，不写裸 `z-index`。§2 里「`pointerdown` 比 `click` 早」的注释在
portal 之后有了反面：外部关闭必须排除菜单自身，否则早触发反而让菜单项收不到事件。

### 11.3 卡片：五列 + 封面动效

网格 `sm:2 / lg:3 / xl:4 / 2xl:5`，加载骨架同一组类名；封面默认 `1.2`、hover 归 `1`，
动效从「放大裁切 → 全览」而不是原有的 5% 微缩。

### 11.4 徽标与元信息

见 §2：徽标来源由 `versionNo ?? currentVersionNo` 改为只看 `versionNo`，「共 N 个版本」
删除后卡片副信息只剩「尺寸（可能缺省）· 更新时间」。

### 11.5 视图持久化

`loredoku.maps.view`：`'list'` → 列表，其余（含 null / 脏值）→ 网格。初值
`useState(readStoredView)`，切换后一个 effect 写回。与 `MapVersionViewPage` 的
`RULER_STORAGE_KEY` 同构，不新增工具模块。

### 11.6 版本条目的主点击

**根因**：一阶段两类条目都进 `/editor/:projectId`，而版本条目的 `projectId` 是**拥有它的
maps 行 id**——于是点工作条目与点它的任一版本条目 URL 相同，编辑器里展出的是当前草稿，
版本快照被覆盖。

**裁定**：主点击按 kind 分叉，版本条目进自己的只读预览。**未动的**：版本条目的「编辑
信息」仍打开拥有它的工作条目——`map_versions` 没有 name/description/cover 列，快照不可
改名，这条分叉去不掉（记入状态文档；三阶段合并表后自然消失）。

> 后续修订：版本条目主点击已改为**带 `?v={n}` 进编辑器、保存时生成草稿**（§13），只读
> 预览保留给图标；fork 命名带来源。

### 11.7 路由改名

| 旧 | 新 | 说明 |
|---|---|---|
| `/editor/:projectId` | `/maps/:projectId/edit` | 控制台统一讲 `/maps/...` |
| `/maps/:projectId/:versionNo/view` | `/maps/:projectId/views` | 版本号移进 `?v=` |

旧路径**不注册、不重定向**（同 v0.5.4 `/games` → `/play` 先例：本地工具，无外部书签）。
缺省 `?v=` 时读 `project.currentVersionNo` 取最新发布版本，没发布过或 `?v=` 不存在都走
「地图版本不存在或加载失败。」；返回按钮从 `/projects` 改成 `/maps`。连带改动：
`MapsPage.handleOpen` / `handlePreview`、`EditorPage` 两处、`useVersions` 的 fork 导航、
`MapVersionViewPage` 参数解析、四个测试文件的路径锚点。

### 11.8 验证证据

三包 typecheck 0 错误；web **57 文件 / 821 例**全绿（一阶段 816，本阶段 +5）；未新增迁移，
shared / server 无代码改动（纯前端）。

# 第三阶段

## 12. 发布成功反馈收敛

**裁定**：发布完成只提示，不跳转。删除 SPEC-K10 §7.2 的成功弹窗（「查看该条目」/「预览」
两个去处），成功路径改为 `toast.success('已发布 v{n}', { description: '已在地图列表新增
条目。' })`——版本号是用户唯一还想知道的结果信息。

细节：不保留「空弹窗只显示版本号」（弹窗必带关闭按钮要人点一下，toast 自动消失，既然
不需要跳转就没有理由用更差的形态）；流程状态不再回传页面，`useEditorPublish` 的
`publishedVersion` / `setPublishedVersion` 与 `EditorPublishFlow` 两字段一并删除，hook
自行消费 `PublishResult.version`（校验失败的「无法发布」弹窗保留，那是错误路径）；
`usePublishProject` 依旧零 toast（数据 hook 只管失效缓存）——测试双锚：hook 内必须有、
`useVersions` 内必须没有，防止以后两边都有或两边都没有。

**验证证据**：三包 typecheck 0 错误；`EditorPage.publish.test.ts` 13 例绿；web 全量
**57 文件 / 821 例**（本阶段只改锚点，未新增用例）。

> **v0.5.8 第三阶段修订**：「弹窗只留二次确认文本」保留，但**多一个版本号输入框**
> （默认血统 `MAX+1`，可改任意正整数、可填空洞号，血统内唯一含软删行）。详见 §13 与
> 设计 §4.2；弹窗标题与确认文本里的 `v{n}` 跟着输入框走。

## 13. `map_versions` 合并进 `maps`（**已实施**）

完整设计见 [`docs/map-table-merge-design.md`](./map-table-merge-design.md)，此处只记结论：

- **删除语义**：版本软删（`deleted_at`，界面不展示、号仍占用、误删可救）、草稿硬删（不
  牵连版本）→ 不需要归属列；唯一约束用部分唯一索引 `(root_id, version) WHERE
  version<>'draft' AND deleted_at IS NULL`。
- **结构**：`draft_data` 改名 `data`，删 `status` / `current_version_no`（改推导，API
  字段名保留）；发布 = INSERT 新 maps 行（name/desc/cover 快照从此真实存在）；加 CHECK
  `version='draft' OR data IS NOT NULL`（版本行必须有快照）。
- **URL 形状不变，`:id` 语义明确为 `maps.id`**（版本行与草稿行都是 maps 行，不再借「拥有
  它的工作条目」这一层）；合并后**版本条目的「编辑信息」取消**——快照不可变，§11.6 末
  的不一致不再靠「跳去工作条目」掩饰，而是动作本身消失。
- **API 路由改名已定**：`/api/projects*` → `/api/maps*`，但**排在合并之后单独一步**，
  不与结构迁移混批（设计 §16）。
- **版本号可自定义**（对 §12 的修订）：弹窗预填 `MAX+1`、可改任意正整数、记录所填值，
  血统内唯一（含软删行）；`publishSchema` 加回可选 `version`。名称可重复性不受影响
