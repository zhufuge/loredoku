# v0.5.8 — 地图版本管理优化专项

> 需求原文见会话记录。本版只做**地图的版本管理与创建/编辑器入口**，谜题侧
> （`puzzles` / 部署）只在被连带影响时改动。
>
> 相关背景：地图管理页与编辑器的**现状说明**在
> [`docs/map-management-and-editor.md`](./map-management-and-editor.md) —— 本文回答
> 「为什么这么改」，那份回答「现在是什么样」。改完功能后两份都要同步。

## 0. 一句话

画布尺寸从「建图时填一次、数据库存一列」改成「进编辑器时初始化、只活在草稿里」；
地图列表的工作条目与版本条目从此**长得完全一样**；发布弹窗去掉备注，只留二次确认。

## 1. 需求与裁定

| # | 需求 | 裁定 |
|---|---|---|
| 1 | 名称后展示版本号，没有则展示「草稿」；不展示「地图 vx」；已发布版本和草稿展示相同 | 徽标统一为 `v{n}` / `草稿`，两种条目共用一套 DOM（见 §2） |
| 2 | 列表：版本/草稿单独一列且对齐，时间列对齐，操作列对齐，操作均为图标 | 四列固定宽度：`w-14` 版本 / `w-52` 时间 / `w-32` 操作（见 §2） |
| 3 | 新建地图对话框删掉「创建后画布尺寸不可修改」描述与画布尺寸字段 | 字段整体移除，不是禁用（见 §3） |
| 4 | 点击已发布版本的地图后连续点击会生成多个版本草稿；**不要一进编辑页面就触发保存** | 删掉 FIX-F03 的首次进入自动保存；版本条目也不再「点击即 fork」（见 §4） |
| 5 | 地图卡片缩小、封面小一点；hover 时封面向内缩小 | `aspect-square` → `aspect-[4/3]` + `group-hover:scale-95`（见 §2） |
| 6 | 进入编辑页时若无尺寸记录，弹窗初始化：填尺寸，或导入初始化 | 新弹窗 `MapInitDialog`，两条出路都是显式动作（见 §4） |
| 7 | 发布弹窗去掉备注输入框，改为二次发布确认文本 | 输入框删除，`notes` 列、字段、参数一路删到 DB（见 §5） |
| 8 | `map_projects → maps` 且删 `grid_size`；`map_games → games`；`map_versions` 删 `grid_size` 与 `notes` | 一个迁移做完，PG 不重命名索引/序列（见 §6） |

## 2. `/maps`：两种条目同一套 UI

### 2.1 徽标

```
版本条目        v3
工作条目·已发布  v3      ← currentVersionNo
工作条目·未发布  草稿
```

v0.5.7 及以前工作条目写「已发布 v3」、副信息里再写一遍「地图 v3」——同一个
数字出现两次，且版本条目的徽标是 `v3` 而工作条目是「已发布 v3」，肉眼要分辨。
现在只保留名称后那一格。

### 2.2 卡片

- 封面 `aspect-square` → **`aspect-[4/3]`**。正方形是 v0.5.3 SPEC-N04 定的
  （「棋盘是 n×n，只有方形框能看全封面」），但四列网格下一张方形封面有
  `~240px` 高，把名称和时间挤到底部还要滚动。4:3 仍能辨认内容。
- hover 动效挂在 `<img>` 上：`transition-transform duration-200 ease-out
  group-hover:scale-95`。无封制的首字母占位不缩放（那不是图片）。
- 操作区：**进入编辑**（主按钮）+ 三点菜单 + 删除。删除是破坏性操作，不进菜单。

### 2.3 三点菜单

`components/project/EntryActionsMenu.tsx`，三项：编辑信息 / 预览 / 复制。

自己实现而没有引 dropdown 库：本仓库没有这个依赖，菜单只有三项、只在地图页
出现，一个受控的 `relative` 容器比加一个 Radix 依赖便宜。点击容器外关闭用
`pointerdown`（比 `click` 早，不会先触发菜单项）。浮层层级走 `UI_Z.drawer`。

预览的可用性：`entry.versionNo ?? entry.currentVersionNo`，两条都为 `null`
（从没发布过的工作条目）时禁用，而不是按 `kind` 把按钮藏起来——藏起来会让
用户以为版本条目没有预览。

### 2.4 列表

列结构：封面 → 名称 → **版本/草稿** → 描述 → **时间** → **操作**。

| 列 | 对齐手法 |
|---|---|
| 版本/草稿 | `w-14 shrink-0 tabular-nums`（`v9` / `v10` 不错位） |
| 时间 | `w-52 shrink-0 text-right`（绝对时间，不用相对时间） |
| 操作 | `w-32 shrink-0 justify-end`，四个图标按钮 |

原来单独占一列的 `n × n` **被移除**：创建时不再有尺寸，未初始化的地图这一列
会经常是空的，而空列会把后面的列推得参差不齐——正是本版要修的「不对齐」。

### 2.5 从列表页移除的两个入口

- **新建谜题**（`/puzzles?new=...`）：谜题在 `/puzzles` 页新建，那里的版本
  选择器本来就是唯一入口。
- **编辑此版本**（fork）：fork 是「从这个旧版本开一条新的工作条目」，属于
  版本历史的操作，编辑器里的版本历史面板仍有入口。它同时也是需求 #4 那个
  「连续点击生成多个条目」的直接来源——列表页不再提供点击即 fork 的按钮。

## 3. 新建地图对话框

删掉两样东西：

1. `DialogDescription` 的「创建后画布尺寸（n × n）不可修改。」—— 这句在 v0.5.8
   起是假的（编辑器里能改），换成「创建后进入编辑器，先设置画布尺寸。」
2. 画布尺寸输入框与 `createSchema` 里的 `gridSize`。`createProjectSchema` 只剩
   `name` / `description`。

**编辑地图**对话框的「画布尺寸不可修改。」同样换成「画布尺寸在编辑器里调整。」

## 4. 编辑器：不自动保存 + 初始化弹窗

### 4.1 为什么不自动保存

v0.3.10 FIX-F03 加过一条：首次进入编辑器时若 `draft.style === null`，自动
`persist()` 一次并 toast「已保存默认地图基本信息」。它的初衷是让「编辑器渲染的」
和「草稿里存的」一致。

在 v0.5.8 之前这条规则依赖 `maps.grid_size` 有值（`parseDraft` 用 `emptyDraft(
grid_size)` 兜底），所以「未初始化」这个状态根本不存在。列删掉之后：

- `mapQuery` 失效（发布、改尺寸、保存）会让 effect 重跑；
- 旧的自动保存跟着重跑，每次写一个新 `draft_updated_at`；
- 用户在地图页快速点同一条目时，会连续进/出编辑器，写出一串草稿修订。

**处理方式就是需求给的那句：不要一进编辑页面就触发保存。** 整段 FIX-F03 连
`basicInfoPersistedRef` 一起删除，进编辑器只 `editor.init()`，一个字节都不写。
用户主动点保存、或改尺寸/导入时才写。

### 4.2 「未初始化」成为一个显式状态

`MapResponse.draft` 改成 `MapDraft | null`：

- 服务端 `parseDraft` **不再用 `emptyDraft()` 兜底**——兜底会把「未初始化」
  伪装成「已有一个默认画布」，前端就再也分不出来；
- `maps.grid_size` 已删，兜底尺寸也无处可取（`GRID_SIZE_DEFAULT` 只作为区域
  CRUD 那条只读路径的兜底，那条路在未初始化时本来就到不了）。

### 4.3 初始化弹窗

`components/editor/MapInitDialog.tsx`。两条出路：

| 动作 | 实现 |
|---|---|
| 填尺寸 → 开始编辑 | 复用 `PATCH /projects/:id/grid-size`（`resizeDraft` 在草稿为空时新建一份只带 `gridSize` 的草稿），成功后 query 失效重拉，`draft` 不再为 `null` |
| 导入地图 | 打开隐藏的文件选择框；解析成功后直接走 `POST /projects/:id/map/import` |

导入这条路**不走**编辑器原有的「覆盖当前画布？」二次确认——那时候画布还是空的，
没有东西可覆盖。`handleImportFile` 用 `initImportRef` 区分两种来路。

弹窗没有取消按钮：关掉它编辑器也没有画布可渲染，返回列表要走左上角返回。
尺寸输入框自动聚焦，回车等于「开始编辑」。

### 4.4 发布的前置校验

未初始化的地图调发布会拿到 `请先在编辑器里初始化画布尺寸`（400）而不是一个
关于 `null` 的堆栈。正常情况下 UI 上根本到不了这一步（弹窗挡着）。

## 5. 发布弹窗

去掉备注输入框。`AlertDialogDescription` 补一句「发布后该版本不可修改。」作为
二次确认文本，按钮仍是 `确认发布` / `保存并发布`（dirty 时）。

连带删除：

- `map_versions.notes` 列；
- `MapVersionSummary.notes` / `MapVersionDetail.notes` / `MapVersionEntry.notes`；
- `PublishedMapVersion.notes`；
- `publishSchema` 的 `notes`（保留 schema 本身并设 `.strict()`，旧客户端多传
  `notes` 会被明确拒绝，而不是静默忽略）；
- `useEditorPublish` 的 `publishNotes` state、`useVersions` 的 `{ notes }`
  mutation 变量、`versionsApi.publish(id, notes)` 的第二个参数。

版本历史弹窗与版本预览页里展示 `notes` 的两处也一并移除。

## 6. 数据库

一个迁移：`20260101000020_v058_map_version_cleanup.ts`。

| 改动 | 说明 |
|---|---|
| `map_projects` → `maps` | `ALTER TABLE ... RENAME TO` |
| `maps` 删 `grid_size` | 连带删掉 v0.2.3 加的 `map_projects_grid_size_check` |
| `map_versions` 删 `grid_size`、`notes` | 尺寸从快照 `data.gridSize` 派生 |
| `map_games` → `games` | 只改名，`grid_size` 等列不动 |

**PG 的 `ALTER TABLE ... RENAME TO` 不会重命名索引、约束与序列。** 所以
`map_projects_root_id_index`、`map_projects_id_seq`、`map_games_puzzle_id_unique`
这些名字原样留着——和 v0.2.0 `cards → items` 时 `cards_id_seq` 的遗留同源。
功能不受影响，故不做额外重命名（多一条 raw SQL 就多一个可失败点）。

`down` 把两列加回来并从 JSON 回填（`COALESCE((data->>'gridSize')::int, 8)`），
所以迁移是可逆的。

## 10. 已知不一致（本次未改）

1. **`games.grid_size` 仍是独立列**。需求只说 `map_games` 改名，没说删列。它
   现在从 `puzzles.grid_size` 来，而后者也没删——部署时照旧工作。若要彻底收敛
   到「尺寸只在草稿里」，得连 `puzzles.grid_size` 一起删，那是谜题侧的改动。
2. **索引与序列名还是旧表名**（见 §6）。要改就得在迁移里加 raw SQL，收益仅是
   可读性。
3. **`/api/projects*` 路由没跟着表改名**。表叫 `maps` 了，URL 还是 `/projects`。
   前端 API 常量同样。改名会动到前后端所有调用点与文档，超出本版范围。
