# v0.8.2 — 三个屏幕的欠账：门牌、当前、动作

> **状态**：已实施（2026-10-29）。
> **来源**：一次针对「系统配置 · 主题」「`/:code/overview`」「新建弹窗里的主题展示」
> 三处的设计评审（22/40，Acceptable）。用户定的三条口径：三块都改、**概览页只做
> 入口页**（不填状态区）、主题识别色**新增一个字段**。
> **范围**：`packages/web` 为主，`packages/shared`（`ThemeData.accent` + schema）。
> 无迁移 —— `themes.data` 是 JSONB，加键只动 schema。

## 0. 一句话

v0.8.0 把主题做成了工作空间，v0.8.1 把边界补严；这一版修的都不是「有没有」，
而是「说不说得清」：**主题卡认不出自己是谁**（色带读了一个没人写的字段）、
**系统配置页认不出你在哪**（没有当前标记）、**弹窗里最该被看见的那一格最不像字段**
（14px 的标签被降成 12px、40px 的行被压成 30px 的胶囊）。

## 1. 主题识别色 `data.accent`

### 1.1 之前那条色带是空的

`ThemesPage` 的卡顶有一条 8px 色带，读的是 `theme.data.linkageColors`。这个字段
在 **v0.5.0 FEAT-K14** 就从地图风格搬到了谜题（`PuzzleDraft.linkageColors`），
主题级的 `linkageColors` 只剩「新建谜题时拷贝过去的缺省」这一层意思 ——
而全仓**没有一个界面会写它**（`ThemeStyleRow` 只回写 `data.style`）。

所以两张卡的色带永远是 `bg-muted` 的一条灰线。实测渲染：`background-color` 与
卡片底色几乎同值，读者看到的是一条比边框略深的发丝。

### 1.2 新增 `data.accent`

| 项 | 值 |
|---|---|
| 位置 | `themes.data.accent`（JSONB 内的键，无迁移） |
| 格式 | `#RRGGBB`，复用 `BG_COLOR_PATTERN`，可选 |
| 归属 | 主题的**门牌色** —— 界面认人用 |
| 不归属 | 不是「缺省」：**不进资源包、不进画布、不影响任何渲染** |

它和同层的 `style` / `linkageColors` 刻意不同：那两个是「新建内容时深拷贝过去的
初始值」，`accent` 只回答「这一屏属于哪个世界」。这条界线写进了 `ThemeData` 的
注释 —— 下一个加字段的人要先回答「它是缺省还是门牌」。

### 1.3 编辑入口只有一处

`⋯ →「编辑主题信息」`（原「重命名」）。名字改了，因为这一格现在管三样：
名称 / 描述 / 识别色；还叫「重命名」就是谎。

- 没设过时**不先摆一个色块** —— 一进门就是某个颜色等于替作者做了决定，
  所以先给一个「选一个颜色」的按钮；
- 设过之后是取色器 + 等宽色值 + 「清除」。清除落成**删键**，不是写空串
  （schema 是 `.optional()` 不是 `.nullable()`）；
- `data` 是**整份覆盖**（`themeRepository.updateTheme` 直接写 JSONB），所以保存时
  要把当前 `data` 铺开再改 `accent` —— 只发 `{accent}` 会把 `style` 一起抹掉。

### 1.4 色带的位子总是占着

```tsx
<span aria-hidden className="h-2" style={accent ? { backgroundColor: accent } : undefined} />
```

第一版写的是「没有色带就整条不渲染」。截图里立刻露馅：同一排卡片，设过识别色的
那张整体往下挪了 8px —— 标题、编码、描述全错开一条带子的高度，两卡并排像两张
没对齐的价签。现在 8px 的**位置**永远在，只有颜色是有条件的。

## 2. 系统配置 · 主题

### 2.1 当前那一间要看得出来

这一页唯一的用途是「换一间工作台」，而两张卡长得一样、顶栏的 config 形态也不
渲染 `ThemeSwitcher` —— 作者得靠记忆分辨自己在哪。

系统配置挂在 `AppShell variant="config"` 下，**没有 `WorkspaceContext`**
（Provider 在 `WorkspaceLayout` 里）。所以当前编码读 `readLastThemeCode()`：
它是切换器与工作空间路由写下的那个键（`loredoku.lastTheme`，v0.8.1 §3 换的键）。

只用来**标一下**，不参与跳转：换浏览器就没有记忆，这时不标 —— 不编一个当前出来。

标记是两件事：卡上一枚 `当前` 徽标 + `aria-current="page"`，边框换成
`border-primary/50`（两处都用 `--primary`，而不是新加一个色）。

### 2.2 取数失败不再伪装成空态

```ts
const themes = themesQuery.data ?? [];   // 旧：500 与「0 个主题」长得一模一样
```

接口失败时页面会说「还没有主题，先创建一个吧」—— 作者会真的去建第三个主题。
现在错误态是独立分支：标题 + 服务端那句话 + 「重试」（`refetch`）。

空态也顺手收了一处：页头已有「新建主题」，空态卡里不再放第二个同义按钮。

### 2.3 卡片：把宽度用上

实测改之前：`grid-template-columns` = `400px 400px 400px`，两张卡 → 右侧整列空着；
1024 下变两列 500px，卡片内容仍竖排在左半边。

现在：

| 项 | 之前 | 现在 |
|---|---|---|
| 网格 | `sm:2 / xl:3` 固定列 | `repeat(auto-fit,minmax(300px,1fr))` —— 列数跟着卡片数塌缩，不留整列空位 |
| 卡片 | 400×164，内容竖排 | 608×128（两主题时），左「名字/编码/描述」右「几关在线 + 库计数」 |
| 数字 | 混在两行文字里 | 右对齐的 24px 楷体数字（与概览四格同一个家族） |

计数口径也改了：`4 关 · 4 关在线` 里同一个「关」出现两次，数字相等时像 bug。
现在主位只说**对外结果**（`8 关在线`），库计数在右侧两行（`51 资源 · 8 地图`
/ `32 角色 · 8 谜题`）—— 和 v0.8.0 §18「主行是结果、次行是库」的原意对齐。

## 3. 概览页：只做入口页

用户的口径是**入口页**：四个门 + 可见的事实，不在这里堆状态区。所以这一版只做减法
和「把死的变活的」，没有新增数据区块。

| 之前 | 现在 |
|---|---|
| 页尾一段：「这一页以后会长出更多可配置项（字体、联动调色板）…」 | **删掉**。这是设计说明，不是界面文案；它坐在页面唯一的收尾位置，把「看一眼就懂」收尾成「这页还没做完」 |
| `8 关在线` + 一串只读等宽路径 | 路径变成**真的入口**（`target="_blank"`，带 `↗`）；没有合辑时只说事实（`还没有合辑`），不再教人点「上线」 |
| 缺省风格：`未设置` + 26 字说明 | 说明**变成链接本身**：`去设一张地图的风格 →`（`text-primary`）—— 一句说明兼一条路，不用记菜单在哪 |
| 事实卡三行 | 四行：编码 / **识别色** / 缺省风格 / 上线 |

识别色在概览是**只读的一行事实**（色块 + `#RRGGBB`）。取色器不摆在这一页 —— 摆了
就等于给「告诉你这是什么」的页面加一个设置项。它也不再挂一句「主题列表里那条色带」
（见 §7）。

## 4. 新建弹窗里的主题那一行

四个新建对话框（资源 / 角色 / 地图 / 谜题）共用 `ThemeScopePill`。改之前实测：

| 量 | 值 |
|---|---|
| `主题` 标签 | 12px / `text-muted-foreground` |
| `名称` `业务 ID` `类型` 标签 | 14px / `font-medium` / 前景色 |
| 锁定态胶囊高度 | 30px |
| 上下输入框高度 | 40px |

也就是说：**四个字段里最该被看见的那一格，是唯一一个不像字段的**。它还用了
`border-dashed` —— 而在本仓，虚线的既有语义是「未选择的上传位」（`ImageUploader` /
`CoverPicker`）与「说明条」（`ParticipantDrawer` / `ExportBundleDialog`，都带
`bg-muted/40`）。一条没有底色的虚线读起来是「待填」，不是「已定」。

现在：

```
主题   红楼梦 · 当前工作空间          ← 锁定：14px 标签 + 14px 值 + 12px 原因，行高 min-h-10
主题   [ 红楼梦 ▾ ]   创建后不可更改   ← 可换：Select 回到 h-10（原来是圆角胶囊 h-9）
```

锁不再靠**形状**表达（胶囊、虚线、灰底），而是靠「这行没有输入框」这件事本身 ——
这正是 §16.7 想要的效果，但上一次用了一个会被读成「待填」的形状去说「已定」。

> **后续（§14）**：这一行后来又整个撤掉了 —— 锁得再好看，它也没让人做任何决定。
> 现在工作空间里根本没有「主题」这一行；下面那段描述只说明它曾经长什么样。

同时给业务 ID 补了一条 11px 说明（资源 / 角色两个弹窗）：

> 前缀 hlm_ 已填好，接着写后半段

v0.8.1 §6 预填了前缀，但那个值在框里就是普通文字 —— 作者看不出它是前缀，可以整段
删掉，也可以改成别的主题的。说明只解释「已经替你写好了什么」，**不强制**：
真要强制得动 schema（见 §7）。

## 7. 二次收紧：删掉三句旁白

第一轮落地后，用户点了三处不要：

| 被删的字 | 在哪 | 为什么该删 |
|---|---|---|
| `地址与资源包里都是它，创建后不可改` | 概览 · 编码行 | 事实行只回答「是什么」。编码改不了这件事由**结构**表达：`⋯` 里的编辑弹窗没有「编码」这一格（见 §8.1），不需要在三个地方各写一遍 |
| `主题列表里那条色带` | 概览 · 识别色行 | 它在解释**另一个屏幕**的呈现。读者要么记得那条带子，要么根本不知道它在说什么；两行灰色小字唯一确定的效果是把 4 行事实变成 8 行 |
| `新建、改名、删除` | 主题切换器 · 主题配置项 | 出口不需要说明自己是个出口。原来这行副标题还把菜单项撑到 40px，比三条主题项都高 —— 一个跳到别处的入口，看起来反而比「切到这个世界」更重 |

顺手清掉的同类：`这个主题下新画的地图会从它开始`、`上线之后才有包可导`、
`在 ⋯ 的「编辑主题信息」里选`、`还没有合辑，点「上线」生成`。留下的只有**事实值**
和**动作**（`去设一张地图的风格 →`、`/play/theme/<slug> ↗`）。

还有一句是过期的：页头描述 `还没有描述 —— 在「重命名」里补一句`。那个菜单项
v0.8.2 已改名「编辑主题信息」，而这句在说一件读者本来就会去做的事。现在只剩
`还没有描述`。

实测（无头 Chrome，1440 / 1024，浅 / 深）：四行事实**全部 40px**，删掉小字后没有
一行塌高或挤压；菜单四项**全部 32px**（原来是 32 / 32 / 32 / 40），右侧编码仍然对齐。
`web` 1000 / 81 全过，`typecheck` 干净。

## 8. 第三次收紧 + 导出包的口径

### 8.1 编辑弹窗里最后两段说明

| 被删的字 | 为什么 |
|---|---|
| `只在系统配置的主题列表里认出这个空间，不进资源包、不影响画布。` | 识别色的定位是**实现约束**，不是读者要知道的事。它是给写代码的人看的一句话，写进了这里就该写进类型注释（`ThemeData.accent` 有），不必占界面 |
| `编码 hlm 不可改 —— 它已经进了地址和资源包。` | 这个弹窗里根本没有「编码」这一格。**没有输入框就是不可改**，再用一句话解释一遍，等于承认读者会怀疑它 |

顺带删掉 `⋯` 里那条 `disabled` 的「风格 · 在地图的「基本信息」里设」：一个动作
列表里最不该有的就是点不动的一项。缺省风格去哪儿设，概览页那一行已经有链接。
菜单现在三项：导出资源包 / 编辑主题信息 /（分隔线）/ 删除主题，全部 32px。

识别色的口径（写在这里给后面的人）：**只在系统配置的主题列表里认空间**。
`bundleService` 的 `theme.json` 只发 `code / name / description / exportedAt`，
`data` 不进包；画布与播放器没有任何一处读 `data.accent`。

### 8.2 导出包：清单与服务端同一把尺子

`DeploymentsPage` 原来把 `gamesQuery.data`（**全站**）交给 `ExportBundleDialog`：

- 清单里会列出别的主题的关，而服务端只打当前主题 ——「清单 12 关、包里 8 关」，
  而且这种差永远没人能对上；
- 当前主题一关都没上线时，按钮仍然可点（判空用的是全站数据）；
- 现在多一个 `deployedGames`：按 `workspace.themeCode` 过滤**全部在线关**。
  注意它与列表用的 `games` **不是同一个集合** —— 列表为了不重复展示排掉了合辑
  里的单局，包里却必须有它们。

清单底部的数字也改了：原来写 `8 关 · 51 资源 · 32 角色`，取的是主题库总数，而包
只带这些关引用到的资源 —— 一句话「只带这些关实际引用到的资源，不是整个主题库」
在旁边自相矛盾。现在只报 `共 8 关`，与清单逐行对得上。

| 新增测试 | 钉住的事 |
|---|---|
| `导出清单只列当前主题的关` | 别的主題的关不出现；`共 1 关` |
| `进了合辑的关不出现在列表里，但仍算在导出清单里` | 列表与导出用的是两个集合，别让「列表看不见」变成「包里没有」 |

`web` 1002 / 81 全过（+2），`typecheck`、`build` 干净。实测导出弹窗：概览入口与
部署页入口都列当前主题 8 关，底部 `共 8 关`。

## 9. 顶栏切换器的图标 → 识别色圆点

触发器原来是 `Layers` + 主题名 + 箭头。`Layers` 是「一排叠起来的作品」——它描述
的是**内容形状**，而这一格在回答的是「我在哪个世界」；更糟的是每个主题长得
一模一样，顶栏因此成了唯一一处「换主题时看不出变化」的地方。

现在文字前是一枚 10px 圆点，颜色取 `theme.data.accent`：

| 状态 | 呈现 |
|---|---|
| 设过识别色 | 实心圆点（`backgroundColor: accent`）+ `ring-1 ring-inset ring-foreground/15` |
| 没设过 | `bg-muted-foreground/30` 的灰点 —— 诚实地说「这间还没挑颜色」，不拿模板色顶上 |

`ring-foreground/15` 而不是 `ring-border`：border 在深色下比 accent 还深，圈就白
画了；foreground 一个 token 在两种明暗里都成立（浅色是半透明墨、深色是半透明宣）。

`Layers` 只剩「概览」导航项在用 —— 那个位置说的确实是内容形状，保留。
`ThemeSwitcher.test.tsx` +2：文字前是识别色、没设色时是灰点且不复用图标。
`web` 1004 / 81 全过。

## 10. 菜单里每一行也带自己的识别色

§9 那颗点只回答「**你现在在哪**」。可换主题时要做的判断是「**另一间是什么样**」——
只看名字与编码（`默认 / default`、`红楼梦 / hlm`），两行在视觉上是同一个东西，
点一下才知道换过去长什么样。色点补的正是这一步：菜单一展开就能看出每间的门牌色。

现在一行是四格：`勾选（当前）· 色点（哪一间）· 名字 · 编码`。勾选与色点各答一件事，
谁也不顶替谁 —— 当前那行既要有勾（它在这），也要有色（它是这间）。

| 细节 | 做法 |
|---|---|
| 圆点尺寸 / 描边 | 抽成文件内的 `AccentDot`，触发器与菜单共用一套 —— 两处各写一份必然漂移 |
| 取色 | 每行读**自己**的 `theme.data.accent`，不是抄触发器那间 |
| 没设色 | 灰点（`bg-muted-foreground/30`），与触发器口径一致 |
| 「主题配置」那行 | 齿轮后加一枚 10px 占位，让它的字与主题名对齐 —— 出口不是第三个主题，但字要站同一条线 |

行高仍是 32px（三行全部实测 32 / 32 / 32），菜单宽度不变（`w-52`）；`typecheck` 干净。

`ThemeSwitcher.test.tsx` +1：两行各自取自己的 accent、没设的那间是灰点（不是
抄上一行的颜色）。
`web` 1005 / 81 全过，`build` 通过。

## 11. 配置页顶栏：去掉斜杠，「返回工坊」挪到日夜开关之后

两处都是**位置的语言**问题，不是配色问题。

| 之前 | 现在 | 为什么 |
|---|---|---|
| `LOREDOKU · 格物` **`/`** `⚙ 系统配置` | `LOREDOKU · 格物`　`⚙ 系统配置` | 斜杠是面包屑语法，说的是「右边这段挂在左边那段之下」。可「系统配置」并不挂在「格物」之下 —— 它是同一层级的另一处地方；而且品牌里已经有「· 格物」这个分隔符，紧跟一条斜杠等于一句话里打两个断。位置关系交给父级 `gap-5`（与工坊形态里导航的起点是同一个 20px） |
| 右侧：`返回工坊` · `日夜` | 右侧：`日夜` · `返回工坊` | 两种形态的**右上角最后一位都该是「离开这一处」**：工坊是「游戏」，配置页是「返回工坊」。原来出口排在日夜开关前面，同一趟来回里它会左右横跳一格 |

## 12. 概览四格：图标放大到 24px，并与顶栏共用一份

### 图标原来有两份

`AppShell` 的 `navItems` 里写着一份，`ThemeOverviewPage` 的 `COUNT_LINKS` 里写着
另一份。**地图**是最明显的那个：顶栏是 `Map`（摊开的地图），概览是 `MapPin`
（定位针）。读者恰恰是「先在顶栏看见它，再在这四格里找它」—— 两处不是同一个
形状，等于每次都在心里做一次「这两个是一个东西吧」的确认。

现在图标挪进 `lib/moduleIcons.ts`：

```ts
export const MODULE_ICONS: Record<ModuleKey, typeof Package> = {
  overview: Layers, assets: Package, maps: Map,
  characters: Users, puzzles: Puzzle, deployments: Rocket,
};
```

顶栏与概览都从这里取。`ModuleKey` 是全集的键 —— 以后再加模块，漏了一枚图标在
类型检查时就报，而不是等到看见两处长得不像。

`COUNT_LINKS` 顺手瘦身：不再带 `icon`，也不再带 `field`（它和 `module` 一直是
同一个值），只写 `module` + `label`，图标与计数都按 `module` 取。

### 16px → 24px，描边同时降到 1.5

lucide 的 `stroke-width` 是**用户单位**，会跟着尺寸放大：16px 时实际 1.33px，24px
时就是 2px（粗一半）。所以放大不能只改 `h-4 w-4` → `h-6 w-6`，还要把描边压到
|1.5，让它回到原来的视觉重量 —— 只是「更大」，不是「更粗」。

| 项 | 之前 | 现在 |
|---|---|---|
| 图标尺寸 | `h-4 w-4`（16px，描边 ≈1.33px） | `h-6 w-6`（24px，`strokeWidth={1.5}`） |
| 垂直对齐 | `items-center`（与「数字 + 标签」整块居中，落点在两者之间） | 图标 `self-start`：与**数字那一行**起头对齐 |
| 地图图标 | `MapPin` | `Map` —— 与顶栏同一枚 |

`self-start` 是刻意的：数字是这一格的主语、图标是它的量词，两者该在同一条线上
起头；居中的话图标会掉到数字与标签之间的缝里，看起来像「浮着」。

### 实测（无头 Chrome，1440 / 1024，浅 / 深）

```
四格图标   24×24，stroke-width=1.5，距卡片左边 17px，顶部与数字对齐
卡片       1440 下 299×70；1024 下 235×70（仍是四列，未挤压）
顶栏地图   lucide-map h-4 w-4   ←→   概览地图 lucide-map h-6 w-6（同一枚，只是尺寸不同）
```

`ThemeOverviewPage.test.tsx` +1：四格图标都在（4 枚）、地图是 `lucide-map` 而不是
`lucide-map-pin`、尺寸是 `h-6` 且描边为 `1.5`。
`web` 1008 / 81 全过，`typecheck`、`build` 干净。`design-system.md` §3.11 的
四格形状同步更新。

## 13. 「进入工坊」落到概览

玩家侧 `/play` 右上角那枚按钮是**从外面进屋的唯一一道门**，它落的是 `/maps`。

可工作空间从 v0.8.0 起就有自己的首页了（`/:code/overview`，也是顶栏导航第一项），
路由里 `/:themeCode` 的 index 也重定向到它。只有这枚从玩家侧进来的按钮还落在
某一间房里 —— 于是「工坊的首页是概览」这句话，在全站唯一一个「从外面看进来」的
位置上不成立。

现在它落 `overview`。顺手把另外两处同类的旧落点一起收了：

| 入口 | 之前 | 现在 | 为什么 |
|---|---|---|---|
| `/play` · 进入工坊 | `/hlm/maps` | `/hlm/overview` | 进屋先到门口，不是先到画布 |
| 工作空间内的 404 | 「返回地图列表」→ `maps` | 「回到概览」→ `overview` | 名字也对不上了（导航里没有「地图列表」这一项），而且 404 该送回门口 |
| 主题切换器认不出当前模块 | `maps` | `overview` | 在 `/hlm`（或一个不存在的段）上换主题，不该替作者挑定一间房 |

**没有改动**的落点：旧地址 `/maps`、`/assets`（书签兜底，仍按原模块走）；
`MapEditorPage` / `MapViewPage` 的「返回」仍回地图列表 —— 那是从编辑器退出来，
回它来的那一页才对。

实测（无头 Chrome，全新 profile 即没有 `loredoku.lastTheme`）：

```
从 /play 点「进入工坊」→ /default/overview   （标题「默认 · 概览 · 格物」，导航高亮「概览」）
/hlm/nope 的 404 按钮  → 「回到概览」/hlm/overview
```

测试 +2：新增 `GamesPage.test.tsx`（点「进入工坊」→ `/hlm/overview`）；`ThemeSwitcher`
加一条「认不出模块时落概览」。`web` 1010 / 82 全过，`typecheck`、`build` 干净。

## 14. 新建弹窗里不再复述主题

§4 把作用域行做成了「一行事实」，还特意让它的标签回到 14px、行高对齐 40px 的输入框。
可问题从来不在它长得像不像字段 —— **它不让人做任何决定**。

工作空间里，主题由地址定：`/hlm/assets` 是资源页，顶栏那枚识别色圆点旁写着「红楼梦」。
弹窗里再来一行 `主题　红楼梦 · 当前工作空间`，是同一句话在同一个屏上的第三遍。
而弹窗里每一行都该回答一个「必须由你决定」的问题 —— 名称、业务 ID、类型、外观，
哪一个都不是复述。

所以四个新建弹窗里，主题由上下文决定时**整行不画**：

| 弹窗 | 之前 | 现在 |
|---|---|---|
| 新建资源 / 新建角色 | `主题　红楼梦 · 当前工作空间`（只读） | 不画 |
| 新建地图 | 同上；封面重试时是 `主题　红楼梦 · 已创建` | 都不画 |
| 新建谜题 | `主题　红楼梦 · 来自底图`（选完版本才出现） | 不画 |

`ThemeScopePill` 随之改名 `ThemeScopeField`，并删掉 `locked` / `lockedHint` 两个
prop、`Lock` 图标与「取不到当前主题就不渲染」那条分支 —— 让一个没人传的 prop
留在组件里，等于给下一个人留一个「这功能好像还在」的错觉。

### 留下的那一半

**没有工作空间上下文时仍然要问。** 旧地址（`/maps`）、整屏入口、单测里，没有任何
东西能回答「建到哪个世界」，这时才出现下拉；而且只有一间主题时不画 —— 一个只有
一项的下拉不是选择，是通知。

```
有工作空间   → 无此行
无工作空间 + 2 间以上 → 主题 [ 红楼梦 ▾ ]  创建后不可更改
无工作空间 + 1 间     → 无此行（自动取第一间）
```

### 实测（无头 Chrome，1440，浅 / 深）

```
新建资源  512×582   label 6 枚，全部 14px/500，select 0 个
新建角色  512×664   label 6 枚，全部 14px/500，select 0 个
新建地图  512×490   label 2 枚
新建谜题  512×796   label 2 枚（选中版本后也只多一句「画布尺寸由底图决定」）
```

四个弹窗里 `select[aria-label="主题"]` 数量均为 0，`当前工作空间` 字样为 0。
每个弹窗比之前矮 **56px**（40px 的行 + 16px 的 `gap-4`），字段间距仍是均匀的 16px。

谜题弹窗里还留着那句 `画布尺寸 6×6 由所选地图版本决定，创建后不可修改。` ——
它说的是**取不到的信息**（尺寸会锁死），不是复述屏幕上已有的东西，所以不删。
