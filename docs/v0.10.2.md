## §1 问题：线索被截断，滚动条有三层

改前竖屏（375×812，7×7）实测：

- 名册里每张横卡的线索 `<span>` 都带 `line-clamp-3`，线索区高度固定按三行算。7 位参与者
  的线索 11~42 字，三行（48px）之外的部分被省略号吃掉 —— 而线索正是玩家要反复对照的
  东西，截断等于把最需要的半句藏起来。
- 卡片高度由 `COMPACT_CARD_MIN_HEIGHT = 80` 兜底、内容撑高：线索两行的卡 80、三行的 82。
  **卡片高度和线索行数脱钩**，长的被 clamp、短的留白。
- 滚动链上有三层各自可滚的容器：

  | 层 | 来源 | 改前 |
  |---|---|---|
  | 面板容器（题面 + 名册那一块） | `GamePage.tsx` | `max-md:overflow-y-auto` + `max-md:flex-1` |
  | 全局线索 | `GameBrief.tsx` 根 `<section>` | `max-h-[min(24svh,220px)] overflow-y-auto` |
  | 名册滚动区 | `ParticipantPanel.tsx` | `min-h-0 flex-1 overflow-auto` |

  手指滑在名册上滚的是第三层，全局线索停在上方不动；要看完线索得把手指移到纸条上再滚
  一次。名册 wrapper 那一层因为 `max-md:overflow-x-auto`，`overflowY` 被浏览器算成
  `auto`，实际是第四个（滚不动的）滚动容器。

## §2 线索读全，卡片跟着内容长高

`packages/web/src/components/map-editor/ParticipantPanel.tsx`，线索 `<span>` 的 className：

```tsx
className={cn(
  compactPortrait ? 'text-left' : 'line-clamp-3 text-center',
)}
```

原来是无条件 `'line-clamp-3 text-center'`，再给 `compactPortrait` 追加 `text-left`。现在
两条互斥：**桌面竖卡截断，竖屏横卡不截断**。

| 项 | 桌面竖卡 | 竖屏横卡 |
|---|---|---|
| 线索区 | 固定 `CLUE_AREA_HEIGHT = 72` | 高度由内容决定（`height: undefined`） |
| 截断 | `line-clamp-3` | 无，读全 |
| 行高 | `CLUE_LINE_HEIGHT = 20` | 16（v0.10.1 定的） |
| 卡片高度 | `PANEL_CELL_HEIGHT + NAME + CLUE` 写死 | `minHeight: COMPACT_CARD_MIN_HEIGHT` 兜底 + 内容撑 |

**为什么桌面不改**：桌面那张竖卡有 72px 的线索区，卡片大小固定、名册像一张表格，
三行之后收省略号是版式的一部分；而且桌面上鼠标悬停有 `title` 全文可看。

**为什么竖屏不能也靠 `title`**：触屏没有悬停。`title` 在手机上要么不出现，要么要长按
（而长按在棋盘上已经绑了「放头像」）。

**为什么保留 `minHeight`**：线索短的卡（两行 32px）如果不兜底会矮到 64 左右，和旁边
四行的卡差出一大截，两列网格看起来会参差。80 是「两行线索 + 名称」刚好需要的高度。

## §3 竖屏下线索与名册连成一段一起滚

三处同时放开，让外层容器成为**唯一**滚动区：

| 文件 | 改动 | 为什么 |
|---|---|---|
| `components/game/GameBrief.tsx` | 根 `<section>` 追加 `portrait:max-md:max-h-none portrait:max-md:overflow-visible` | 放开高度上限、交出滚动条 |
| `components/map-editor/ParticipantPanel.tsx` | 滚动区 `overflow-auto` → `compactPortrait ? 'overflow-visible' : 'overflow-auto'` | 名册不再自己滚 |
| `pages/GamePage.tsx` | 名册 wrapper 追加 `portraitFit && 'max-md:flex-none portrait:max-md:overflow-visible'` | 不再参与高度分配，且不再是第二个滚动容器 |

### 3.1 为什么必须用 `portrait:max-md:` 而不是裸 `max-md:`

`max-md:` 在 740×360 的横屏手机上也命中。横屏下面板容器走的是
`portraitFit ? 'max-md:flex-1' : 'max-md:max-h-[38svh] max-md:flex-none'` 的**后者**（限高
38svh），此时名册必须自己滚，否则内容会被裁掉。`portrait:` 把这一批改动限定在「窄且
竖着」的局面，横屏手机原样不动（实测见 §10.1）。

### 3.2 那个「漏了 `overflow-visible` 就白干」的坑

第一版只给名册 wrapper 加了 `max-md:flex-none`，实测 `overflowY` 仍是 `auto`：

> CSS 里只要有一个轴是 `auto`，另一个轴就会被算成 `auto`（`visible` 会提升为 `auto`）。

wrapper 上原有的 `max-md:overflow-x-auto`（v0.10.1 给 24 人名册准备的横向滚动）让这一层
成了第二个滚动容器，触屏滑动可能被它吃掉。竖屏名册是 `minmax(0, 1fr)` 的弹性轨道、
本来就不横向溢出，所以竖屏直接 `portrait:max-md:overflow-visible` 让位。

### 3.3 为什么 wrapper 还要 `flex-none`

面板容器（唯一滚动区）是 `max-md:flex-1` 的 flex 容器，名册 wrapper 原本 `flex-1`。
放开名册内部滚动之后，`flex-1` 会把 wrapper 压成容器剩下的那点高，多出来的卡片只能
**溢出** —— 滚动条在祖先上，但高度分配没给内容留位置。改 `flex-none` 之后容器的
`scrollHeight` = 线索 + 全部卡片，滚得到底。

## §4 封面：编辑器里看到的和列表卡上看到的是同一张

### 4.1 问题：两把尺

同一张封面图，界面上有四个地方画它：

| 位置 | 组件 | 改前比例 |
|---|---|---|
| 编辑器「基本信息」抽屉的预览框 | `components/common/CoverPicker.tsx` | `MAP_COVER_ASPECT` = **16:10** |
| 新建 / 编辑地图对话框的预览框 | 同一个 `CoverPicker` | 同上 |
| 地图列表的网格卡片 | `components/map/MapGridCard.tsx` | **`aspect-[4/3]`** + 默认 `scale-[1.2]` |
| 谜题列表的网格卡片 | `components/puzzle/PuzzleGridCard.tsx` | **`aspect-[4/3]`** + 默认 `scale-[1.2]` |

列表行（`MapListRow` / `PuzzleListRow`）的缩略图是 `h-10 w-16`，本来就在 16:10 上，
`CoverPicker` 也是 16:10 —— **只有两张网格卡片的 `4/3` 是异类**。

裁切的差距不止比例。`scale-[1.2]` 那层放大只保留中间 `1 / 1.2 ≈ 83%`，等于在 4:3 之上
再裁一刀。存量封面几乎都是正方形（实测 `storage/uploads/maps/**`：1000×1000、900×900、
320×320、1081×1133、768×768），正方形图在 16:10 里上下各裁 18.75%、在 4:3 里只裁 12.5%，
再叠 1.2 又多裁一圈 —— 三个裁法叠下来，配好的封面回到列表就认不出了。

### 4.2 做法

两张网格卡片各改两处（`MapGridCard.tsx` / `PuzzleGridCard.tsx`）：

```tsx
style={{ aspectRatio: String(MAP_COVER_ASPECT) }}
className="relative block w-full cursor-pointer overflow-hidden border-b bg-muted/40"
```

- 比例写进行内样式、取 shared 的常量，而不是写 `aspect-[16/10]` 类：**常量是唯一真源**，
  以后调一次三处一起变。
- 图片去掉 `transition-transform duration-image ease-in-out scale-[1.2] group-hover:scale-100`，
  只留 `h-full w-full object-cover`。要让「配置时看到的」和「卡片上看到的」逐像素一致，
  就不能有那层放大。

`docs/map-management-and-editor.md` §2.3 的封面那一行同步改写（原写着 `aspect-[4/3]` +
`scale-[1.2]` + hover 缩回）。

### 4.3 验证

用一张 800×800、四边写着 `L` / `R`、正中写着 `CENTER` 的测试图当封面，同一张图在两处
各量一次：

| 位置 | 改前 | 改后 |
|---|---|---|
| 卡片封面框 | `294×221`（ratio **1.333**） | `294×184`（ratio **1.6**） |
| 卡片上能看到的标记 | 只有 `CENTER` | **`L` / `CENTER` / `R` 全部可见** |
| 抽屉预览框 | `287×179.38`（`aspect-ratio: 1.6 / 1`）、能看到 `L`/`CENTER`/`R` | 不变 |

改后的卡片与抽屉预览看到的是同一块视野。谜题列表同构，实测一致。

## §5 补字「麒麟黛冢」与定案后仍可展开描述

### 5.1 四个字不在 GB2312 一级

区域标签字体是**裁过字**的霞鹜文楷（`docs/v0.7.4.md` §2）：`charset=common` 只留 GB2312
一级（3755 字）+ ASCII + 常用标点，一级之外的字一律被裁掉。被裁掉不会显示豆腐块 ——
回退链会顶上，代价是那一个字不是手写体。

「麒麟黛冢」四个字里没有一个是 GB2312 一级的，所以它们一直在由回退链画。

修法不是换整档字集（`gb2312` 是 6763 字、约 1.6 MB，+70%），而是往
`packages/web/scripts/font-extra-chars.txt` 加一行：

```
# 2026-11-12（v0.10.2）：「麒麟黛冢」—— 地图 / 关卡名里用到，均不在 GB2312 一级
麒麟黛冢
```

再 `npm run fonts --workspace @loredoku/web` 重裁。这份清单跟着仓库走，每次裁字都会并进
`common` 与 `gb2312`，重跑不会把字丢掉。

实测（脚本打印）：

| 项 | 改前 | 改后 |
|---|---|---|
| 字集补字字数 | 8 | 8（`薇雯麝怡` → `薇雯麝怡麒麟黛冢`，本次 +4） |
| 产物字数 | 4708 | **4712** |
| `霞鹜文楷-Regular.woff2` | 948020 B | **949616 B**（+1596 B） |

四个字一共 1.6 KB，比换整档便宜两个数量级。解 woff2 的 cmap 逐个核对：`麒` / `麟` /
`黛` / `冢` / `薇` / `雯` / `麝` / `怡` 全部在字表里（`glyph codepoints: 4592`）。

> 顺带一个坑：`document.fonts.check('16px "霞鹜文楷"', '龘')` 对**任何**字都返回 `true`
> —— 它判的是「字体能画出这个字吗」，而 `font-display: swap` 的回退链总会给一个答案。
> 核对有没有裁进去只能看 cmap，不能看 `fonts.check`。

### 5.2 定案后「展开全文」点不动

v0.9.7 立的规矩：结案的那一局，「与地图及物品人物」都不该再有交互 —— 左栏整条 `<aside>`
挂 `pointer-events-none`，只有标题块自己用 `pointer-events-auto` 豁免（所以返回箭头与
主题开关照常可点）。

题面里那枚「展开全文」不是标题块的，于是跟着一起失灵。而它**不是游戏动作** ——
是读作者写的那段话，定案了也该能读全；同一段描述在竖屏下还能从头部那枚图标打开弹框，
桌面端却读不全，说不通。

修法：只给这一枚按钮加 `pointer-events-auto`
（`packages/web/src/components/game/GameBrief.tsx`）：

```tsx
className={cn(
  'pointer-events-auto ml-auto mt-1 flex w-fit items-center gap-0.5 text-2xs text-muted-foreground',
  'transition-colors duration-fast ease-out hover:text-foreground',
  'focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring',
)}
```

CSS 允许 `pointer-events-none` 的祖先下面有 `pointer-events-auto` 的孩子。线索纸条的
悬停抬起与名册仍然锁着 —— 只放开这一枚。

实测（1280×800、`/play/puzzle-hlm-zanghua-hard`，112 字描述，往 localStorage 写
`loredoku.game.completed.<slug>` 造出定案态）：

| 项 | 值 |
|---|---|
| `aside` 的 `pointer-events` | `none`（定案态生效） |
| 祖先链上挡指针的节点 | `section[data-testid="game-brief"]` / 面板容器 / `aside`，3 层 |
| 这枚按钮自己的 `pointer-events` | **`auto`** |
| 按钮中心点的 `elementFromPoint` | `BUTTON[data-testid="game-brief-description-toggle"]`（命中它自己，没被遮罩档住） |
| 点击后 | `aria-expanded: "true"`、文案变「收起」、`webkitLineClamp: "none"`、描述高 63 → **147** |

## §6 点区域标签、点物品溢出的那圈画，都按格子分割线落点

### 6.1 两处各自接管指针的地方

画布容器（`EditorCanvas` / `GamePage` 的 `<main>`）的 `onPointerDown` 里第一件事就是
`toCell(clientX, clientY)` —— 把屏幕像素按 `clientToCell` 换算成格子。可这条路上原来站着
两个不听话的中间层，它们把按下事件 `stopPropagation()` 掉了，容器根本收不到：

| 位置 | 原来 | 为什么错 |
|---|---|---|
| 区域标签（`MapOverlayLayers.tsx` 的 `MapRegionLabelLayer`） | 一枚 `<button class="region-label pointer-events-auto …">`，`onPointerDown` / `onClick` 都 `stopPropagation()`，点了就 `onSelect(region.id)` | 标签用 `translate(-50%, -100%)` 悬在格子上沿，**它盖住的往往不是自己那块区域的格子**，而是上一格。点「标题压住的那块像素」于是选中的是区域、不是那一格 |
| 物品显示框（`MapAssetLayers.tsx` 的 `MapItemLayer`） | `pointerEvents: interactive ? 'auto' : 'none'`，`onPointerDown` / `onClick` 都 `stopPropagation()` 并回传**锚点格** | 显示框由 `itemRectStyle` 给出，被 `scale`（25%~400%）与 `offsetX/Y`（单位格）撑到脚位之外。那一圈溢出画压在别的格子上时，点它命中的是这件物品、交出去的还是它的锚点格 |

悬停那边其实早就对了：`hitItemKey` 按**脚位** `w×h` 判命中，`hitTestCell` /
`resolveItemAnchor` 也按脚位把点映射回锚点 —— 错的只有 DOM 层的 `pointer-events`。所以
这次不是给命中判定加逻辑，而是把这两个中间层从指针链上摘掉。

### 6.2 做法：把指针交回画布容器

`MapRegionLabelLayer`：

```tsx
// 标签不再接管点击：按下会冒泡到画布容器的 onPointerDown，由它按
// clientToCell 换算成格子。仍留 pointer-events-auto 是因为悬停要能点亮
// 它自己那块区域（标签可能被 labelCell / 偏移推到盘面之外，那里没有格子可悬停）。
<span className="region-label pointer-events-auto absolute select-none whitespace-nowrap">
```

- 从 `<button>` 换成 `<span>`（它已经不是一个能按的按钮了），删掉 `onPointerDown` / `onClick`，
  签名里的 `onSelect` 一并删掉；`select-none` 是因为按住拖动时不该选中文字。
- 三个调用点（`EditorCanvas`、`GamePage`、`MapViewPage`、`PuzzleViewPage`）里那两处传了
  `onSelect` 的也一起删掉 —— 其中 `GamePage` 本来就没传，点它等于白吃一次点击。

`MapItemLayer`：整层 `pointerEvents: 'none'`，签名里的 `interactive` / `onPointerDown` /
`onClick` 全部删除（`EditorCanvas` 里那个 `selectInteractive` 计算也一起消失）。脚位里的点击
不会丢：画布容器拿到的格子坐标进 `selectCellAt` → `hitTestCell` → `resolveItemAnchor`，
落在 `w×h` 里的点照样映射回锚点格，信息面板照样是那件物品。

**区域信息也没丢**：`EditorInfoDrawer` 取区域的逻辑本来就是「`selection.type === 'region'`
就按 id 找，`type === 'cell'` 就 `regionAt(regions, x, y)`」。点格子仍会带出它所属的区域，
只是入口从「点标签」改成了「点那一片格子里的任意一格」。

## §7 方格大小退出主题设置

### 7.1 已经做对了一半

「方格大小」不是风格，是**这张图自己的尺寸**：同一个 168px 放在 4×4 和 20×20 的图上
完全是两种粗细。v0.8.6 §1 已经据此把它从主题概览页的「地图初始样式」表单里拿掉了
（`THEME_STYLE_FIELDS` 是 `MAP_STYLE_FIELDS` 过滤掉 `cellSize` 的派生表），服务端
建新地图拷风格时也自己置了 `null`（`mapCanvasService.ts` 的 `initialStyle`）。

改前实测确认这一半是干净的：`/hlm/overview` 的 `document.body.innerText` 里
`方格大小` 不存在；「地图初始样式 · 红楼梦」弹窗的分组只有 网格 / 边框 / 物品 / 标签 /
光标。

### 7.2 还剩一处漏口：差异弹窗

`packages/web/src/components/map-editor/ThemeStyleRow.tsx` 是「基本信息」抽屉底部
那一行（`风格来自主题「红楼梦」 · 与主题 N 项不同`），它比对的是
`diffMapStyle(style, themeStyle)` —— 而 `diffMapStyle` 遍历的是**完整的**
`MAP_STYLE_FIELDS`，`cellSize` 是那张表的第一项。

改前实测（`/hlm/maps/15420/edit` → 「基本信息」→「查看差异」）：弹窗正文是
`主题风格 · 红楼梦 网格1 方格大小 168px → 146px …`。

三个动作都受它牵连：

| 动作 | 原来的行为 | 问题 |
|---|---|---|
| 比对 | `diffs` 含 `cellSize` | 弹窗常驻一条「与主题不同」，而这一项在两处都改不到 |
| 应用主题风格 | `onApplyThemeStyle(themeStyle)` 整份替换 | 这张图定死的 146px 被抹成主题的 168px |
| 设为主题风格 | `style` 原样写进 `data.style` | 主题里留下一个谁也看不见、谁也改不到的 168 |

### 7.3 做法：一份清单管住三处

`THEME_HIDDEN_STYLE_KEYS`（原本是模块内的 `const`，现在 export）就是「主题设置里
不出现的键」这份清单，`ThemeStyleRow` 三个动作各自按它收口：

```ts
// 1. 比对：看不见的项不算差异
const diffs = useMemo(
  () => diffMapStyle(style, themeStyle).filter((entry) => !THEME_HIDDEN_STYLE_KEYS.has(entry.key)),
  [style, themeStyle],
);

// 2. 应用：只灌看得见的项（逐项写回，不是整份替换）
export function applyThemeStyle(style: MapStyle, themeStyle: MapStyle): MapStyle {
  return THEME_STYLE_FIELDS.reduce(
    (next, field) => writeStyleValue(next, field.key, field.read(themeStyle)),
    style,
  );
}

// 3. 设为：看不见的键归零
export function stripThemeHiddenStyle(style: MapStyle): MapStyle {
  return [...THEME_HIDDEN_STYLE_KEYS].reduce<MapStyle>(
    (next, key) => writeStyleValue(next, key, null),
    style,
  );
}
```

两个 helper 与 v0.8.6 §1 的 `resetThemeStyle` 是同一个招式（逐项 `writeStyleValue`），
理由也一样：整份替换连看不见的键一起盖，是「改不到的东西被顺手改掉」的另一面。

**`diffMapStyle`（shared）本身没改** —— 它按字段表老实比对是对的，过滤是「主题设置
这一侧」的决定，不该塞进一个通用的比对函数。`mapStyleDiff.test.ts` 里那条
「`diffMapStyle` 恰好返回 `[{ cellSize, 自适应 → 48px }]`」原样通过。

顺手对齐了同一处的一个旧漂移：`ThemeStyleRow` 里原本手写
`const grouped = ['网格', '边框', '标签', '光标']`，漏了「物品」—— 物品描边类的差异
一直被静默过滤掉。现在直接用 shared 的 `MAP_STYLE_DIFF_GROUPS`。

## §8 六处搜索框都有 × 一键清空

### 8.1 改前：只能按住退格

全站六个搜索框各自手写了一遍「`relative` 包裹 + 绝对定位放大镜 + `Input`」，没有一处
有清空按钮：

| 位置 | 尺寸 | 清空方式 |
|---|---|---|
| `pages/AssetsPage.tsx` | `h-10 pl-9` | 按住退格 |
| `pages/CharactersPage.tsx` | `h-10 pl-9` | 按住退格 |
| `pages/MapsPage.tsx` | `h-10 pl-9` | 按住退格 |
| `pages/PuzzlesPage.tsx` | `h-10 pl-9` | 按住退格 |
| `components/map-editor/AssetPalette.tsx` | `h-9 pl-9` | 按住退格 |
| `components/puzzle/PuzzleEditorLeftPanel.tsx` | `h-8 pl-8 text-xs`（裸 `<input>`） | 按住退格 |

四个列表页更别扭：`keywordInput` 经 300ms 防抖才提交成 `keyword` 去请求后端，退格到空
的这几百毫秒里列表还是旧结果，看不出「清干净了没有」。

### 8.2 做法：收成一个共享件 `components/common/SearchInput.tsx`

```tsx
<input ... /> {value.length > 0 ? (<button aria-label="清空搜索">×</button>) : null}
```

三档尺寸按现有六处归纳成一档对象，不只是缩字号 —— 小框里的放大镜和右侧留白也得跟着缩：

```tsx
const SIZE_CLASSES: Record<SearchInputSize, { icon: string; input: string }> = {
  md: { icon: 'left-3 h-4 w-4', input: 'h-10 pl-9 pr-9' },   // 四个列表页
  sm: { icon: 'left-3 h-4 w-4', input: 'h-9 pl-9 pr-9' },    // 资源调色板
  xs: { icon: 'left-2.5 h-3.5 w-3.5', input: 'h-8 pl-8 pr-8 text-xs' }, // 谜题编辑器角色面板
};
```

三处细节：

1. `pr-9`（或 `pr-8`）**常驻**，不是只在有内容时留 —— 否则清空按钮出现的那一刻文字会横向跳一下。
2. **只有 `value.length > 0` 时才渲染按钮**。空框上挂一枚点不动的 ×，读屏还会念出来。
3. 点完 `onValueChange('')` 之后 `inputRef.current?.focus()` —— 清空是「重新搜」的起点，不该再点一次框。
4. 组件**不替调用方 trim**。四个列表页的防抖靠原始输入判断变化，这里 trim 的话
   「输入一个空格」会被吞成同一次提交。

按钮本身是裸 `<button>` + Tooltip（`RefreshButton` 的范式）：`IconButton` 的
`size="icon"` 是 40×40，塞不进 36 / 32 高的框；位置用 `absolute right-1`，**在包裹 div
内部** —— 资源调色板的刷新按钮必须仍是那个 div 的下一个兄弟（既有用例钉着
`refreshButton().previousElementSibling?.contains(search)`）。

## §9 「定案」竖排、印章靠右、「再玩一次」不提前渲染

### 9.1 「定案」从「宽的两字」变成「窄的一列」

改前是 `<span>定案</span>` 一行两字、`tracking-[0.25em]`；印章用负 `margin-top` 从下面提上来压住字的下缘（v0.9.7）。两个字横着排时这一块是**宽大于高**的，印只能往下找位置。

改成竖排只加一条 `[writing-mode:vertical-rl]`：

```tsx
'relative z-0 font-kai font-bold [font-synthesis-weight:auto] tracking-[0.25em]',
'[writing-mode:vertical-rl] whitespace-nowrap',
```

不用「拆成两个 `<span>` + `flex flex-col`」：拆开就得自己管两行之间的行距，而这里要的恰好是 `tracking-[0.25em]` 那点字距 —— 竖排之下它自动作用在「定」与「案」之间，一行代码就够，字数若变多也不会折错。

**`whitespace-nowrap` 是必须的**（第一版漏了，实测两个字并排成两列）：竖排的换行方向是「换到**左边**一列」，字距一撑、盒子一矮就折行 —— 实测 `定` 落在右列 `x 645`、`案` 落在左列 `x 517`，字块变成 256×192 的「两列」。禁掉换行之后才老实上下叠，字块变成 128×320。

容器也跟着改：根 div 由 `flex flex-col` 改成 **`flex items-center`**（左边一列字、右边一枚印横着排）；印的负边距由 `-mt-[0.55em]` 改成 **`-ml-[0.55em]`**（压的轴从上提换成左压，量沿用同一个 em，`large` 与卡片两档字号仍然同比例叠压）。

### 9.2 印章挪到字列右下角

竖排之后字列右侧空出来了，印顺势挪过去。两处各给一份偏移，**按字号档位等比**：

| 位置 | 字号 | `stampOffset` | 效果 |
|---|---|---|---|
| 地图遮罩（`large`） | `text-9xl`（128px） | `{ x: 8, y: 40 }` | 压在「案」的右上角 |
| 列表卡封面 | `text-7xl`（72px） | `{ x: 5, y: 22 }` | 同一构图的小一号 |

卡片那一份是 128→72 的比例（0.5625）缩出来的：`8 × 0.5625 ≈ 5`、`40 × 0.5625 ≈ 22`。卡片不传时用的是 `items-center` 的默认居中，印会正压在「案」字中间。

游戏内那一份之前是 v0.9.8 定的 `{ x: 150, y: -50 }`（往右上让开，避开字心）；竖排之后那个位置已经飞到字块外面去了，所以整组重算。**没有再往右加**是因为再推就贴到遮罩边缘 —— 桌面 1280 下棋盘遮罩的右边界离字列只剩约 170px，印宽 197。

### 9.3 整块再靠右：`shift`

用户看过竖排之后又提了一句「排版整体再靠右一些」。要挪的是**字和印一起**，不是再挪印 —— 两者相对位置已经定了，再动印就变回「印离字太远」。所以 `VerdictMark` 多了一个可选 prop：

```tsx
shift?: { x: number; y?: number };
```

它挂在根 div 上、走 `translate` 属性（与 `stampOffset` 同一个理由：`transform` 整条被印的 `stamp-press` 关键帧占着）。游戏内传 `shift={{ x: 72 }}`：

```tsx
style={
  scale === 1 && !shift
    ? undefined
    : {
        ...(scale === 1 ? null : { zoom: scale }),
        ...(shift ? { translate: `${shift.x}px ${shift.y ?? 0}px` } : null),
      }
}
```

为什么原本居中还会读成偏左：字列只有 128 宽、右边一枚 197 宽的印，整块的外接盒是 311 —— 盒子居中时**视觉重心**（那列字）落在左半个盒子里。第一版是 48px（1280 下整块从 `x 601` 挪到 `x 649`），用户看过之后又说「字和印再靠右一些」，于是加到 **72px**：1280 下整块落在 `x 673`、字列 `x 688`、印右缘 `969`（`stamp 197×201 @ (798, 338)`），仍在遮罩里且不再偏左；375/320 竖屏下整块跟着 `zoom` 同比例缩，整块分别 `222×229 @ x 128`、`186×191 @ x 111`，印右缘 `358 ≤ 375`、`303 ≤ 320`，不溢出。

### 9.4 大小自适应屏幕：除棋盘之外再按可见区收一道

用户：「且大小要自适应屏幕」。原先只有一道口径 —— 棋盘边长（`boardSize / 480`，v0.10.0）。横屏手机上这条口径是**错的**：棋盘按作者配的 `cellSize` 能有 924 见方，算出来「不用缩」，而 `<main>` 此时只剩 106 高 —— 实测整块 `311×320 @ (292, −37)`，字的顶边跑到可见区外面。

所以 `verdictMarkScale` 多收一个可选参数：

```ts
export function verdictMarkScale(boardSize: number, stage?: VerdictStageBox | null): number
```

- `byBoard = boardSize / VERDICT_BASE_BOARD`
- `byStage = min(stage.width / VERDICT_MARK_WIDTH, max(0, stage.height - VERDICT_BUTTON_BLOCK) / VERDICT_MARK_HEIGHT)`
- 取 `Math.min(byBoard, byStage)`，`>= 1` 返 1，否则 `Math.max(VERDICT_MIN_SCALE, …)`

三个常量：`VERDICT_MARK_WIDTH = 384`、`VERDICT_MARK_HEIGHT = 320`（1280×800 实测整块 311×320 再叠 72px 右移 ⇒ 横向占 383，取整）、`VERDICT_BUTTON_BLOCK = 64`（`gap-6` 24 + 按钮 `h-10` 40 —— 按钮不跟着缩，算可用高度时先扣掉）。

`stage` 由 `GamePage.tsx` 里一个新的 state 提供，`<main>` 就是那个画布容器（`containerRef`），`fit()` 与它的 `ResizeObserver` 每次经过时同步一对宽高；尺寸相同就原样返回，不会因为一次量测就重渲染。还没量过（`null`）时 `byStage` 取 1 —— 只按棋盘算，挂载那一瞬不会闪一下小的。

实测：740×360 横屏由 `zoom 1 / mark 311×320 @ y −37` 变成 `zoom 0.5 / mark 156×160 @ (346, 43)`，完全落在可见区内；1280×800 仍是 `zoom 1`、375×812 仍是 `0.714583`、320×568 仍是 `0.597917` —— **桌面与竖屏的既有表现一个像素没动**。

| 已完成再进入 | 遮罩上有「再玩一次」、`disabled: false` |

### 9.6 「再玩一次」：这一局里一次都不提前渲染，关上卡之后才出来

判据原来只有一条 `!result`（结算卡此刻开没开着）：

```tsx
{!result ? (<Button data-testid="verdict-replay" …>再玩一次</Button>) : null}
```

问题在「通过之后那 1 秒」。`finished` 已经置真（定案遮罩在场），而 `result` 要等
`GAME_VERDICT_HOLD_MS` 之后才落 —— 这一秒里 `!result` 成立，**按钮先画出来**；结算卡一弹
它又被撤掉；关上卡再补回来。一进一出闪了两下，用户看到的就是「先出现又消失又出现」。
用户的原话是「从一开始就不要渲染，后面再渲染出来」。

所以多一个记号 `verdictDismissed`（结算卡在本局关过），判据取并集：

```tsx
{revisitedRef.current || verdictDismissed ? (<Button data-testid="verdict-replay" …>再玩一次</Button>) : null}
```

- `revisitedRef.current` —— 「已完成再进入」那一版。一进来就盖着遮罩、表停在 00:00，
  按钮就是这一屏唯一的出口（v0.9.6 定的行为，不动）；
- `verdictDismissed` —— 这一次是刚通过，且 `closeResult` 已经把结算卡关上。置真的地方
  只有 `closeResult`（且只在 `result.kind === 'passed'` 时），清掉的地方是 `replay()`
  与读档 effect（换关时不该带着上一关的记号）。

两者都不成立 = 刚通过那 1 秒，定案遮罩单独在场：这一屏只是结论，不给出口。

中间还走过一次弯路：用户先说「校验通过后展示定案和印章时不展示再玩一次；重新进入时才
展示」，按字面理解成「只有『已完成再进入』才给」，判据一度只写 `revisitedRef.current`。
紧接着用户补「改为关闭弹窗后显示」—— 他要的不是永久不给，是结论与出口分两拍；再补
「从一开始就不要渲染」才补齐了「头一秒也别画」这一层。

用例：`packages/web/src/pages/GamePage.test.tsx` 新增「定案遮罩单独在场的那一秒：还没有
「再玩一次」」（推进四个 `GAME_CHECK_STEP_MS` 后遮罩在、`role="dialog"` 不在、按钮不在；
再推 `GAME_VERDICT_HOLD_MS` 卡落下时仍不在）；「关掉通过的结算卡：遮罩仍在，并补出
「再玩一次」」保持 `not.toBeNull()`。「已完成再进入」那条（按钮一开始就在）原样通过。

### 9.7 列表卡上那一份按封面缩

游戏内那档的缩放口径（棋盘 + 可见区）到卡片上不成立：卡片封面是 `aspect-square`，`/play` 四列时只有 **136px 见方**，而 `text-7xl`（72px）竖排的「定案」本身就有 192 高 —— 整块比封面还高。实测 `word 113×192 @ (-3, 1462)` 对封面 `136×136 @ (17, 1491)`：字探出封面上沿 29px、左边探出 20px。用户：「字和印大小自适应还不够，在卡片小的占据面积太大了」。

所以卡片这一档自己量一次封面（`CompletionOverlay` 里加 `coverRef` + `coverBox` state，`ResizeObserver` 有就挂、没有就只量首帧），再交给一个新函数：

```ts
export function verdictCardScale(box?: VerdictStageBox | null): number
```

- `ratio = min(box.width * VERDICT_CARD_FILL / VERDICT_CARD_MARK_WIDTH, box.height * VERDICT_CARD_FILL / VERDICT_CARD_MARK_HEIGHT)`
- `>= 1` 返 1（**只缩不放**），否则 `Math.max(VERDICT_MIN_SCALE, ratio)`
- `box` 为 `null` / 宽高 `<= 0` 时返 1 —— 与 `verdictMarkScale` 同一个理由：挂载那一瞬不闪一下小的

三个常量：`VERDICT_CARD_MARK_WIDTH = 168`、`VERDICT_CARD_MARK_HEIGHT = 192`（实测整块 168×192）、`VERDICT_CARD_FILL = 0.78`（**整块最多占封面短边的 78%**，四边留出封面的底）。0.78 是取舍出来的：再大会把蒙版那层 `bg-background/55` 读成一张纯色块，再小字就看不清了。

实测 136×136 的封面：`zoom 0.548438`、字块 `62×105 @ (30, 1506)`、印 `64×64 @ (73, 1539)` —— 整块落在封面里。`GamesPage.test.tsx` 11 条原样通过（卡片上的「定案」`textContent` 仍是连续两个字）。

- **没给线索加「展开 / 收起」**。用户说的是「展示要全」，那就一次画完；再加一个开关
  等于把「要不要读全」的决定推回给玩家。

- **没给 `diffMapStyle` 加「忽略某些键」的参数**。加参数等于把「主题设置不列什么」
  这个 UI 侧的决定塞进一个通用的比对函数；过滤留在 `ThemeStyleRow` 里，清单与
  `THEME_STYLE_FIELDS` 共用同一份 `THEME_HIDDEN_STYLE_KEYS`。
- **没动地图「基本信息」抽屉里的方格大小**。那是这张图自己的尺寸（`MapInfoDrawer`
  的 NumberField + 「恢复自适应」），与主题无关，删了就没法给单张图定死格子边长。
- **没让「设为主题风格」顺便清理主题里其它存量残留**。它现在只把
  `THEME_HIDDEN_STYLE_KEYS` 里的键归零；主题里若还留着别的历史字段（旧版本写过、
  现在字段表里已经没有的键），仍然原样不动 —— 那不是本次的题。
- **没把六处搜索框都改成同一个尺寸**。三档（`h-10` / `h-9` / `h-8`）是各自所在容器的
  既有高度决定的 —— 列表页的搜索框与排序下拉同一行、资源调色板那一行还挂着刷新按钮、
  谜题编辑器的角色面板整个只有 32px 一档。统一成 40 只会把后两处撑开。
- **没给搜索框加「按 Esc 清空」**。`Escape` 在谜题编辑器里已经绑给「取消当前操作」
  （`useEditorShortcuts`），在这里再抢一次会让「按 Esc 退出选中」偶尔变成「清空搜索」。
- **没给清空按钮加过渡动效**。它随内容出现与消失，是状态的一部分；淡入淡出反而让
  「框里还有没有字」读起来更慢。
- **没让 `SearchInput` 沿用 `onChange` 的原签名**。`onValueChange(next: string)` 比
  `onChange(event)` 少一层 `event.target.value` —— 六处调用方拿到的都是字符串，没必要
  把 DOM 事件透出去。
- **没把「定案」拆成两个 `<span>`**。拆开就得自己排两行之间的行距；现在靠
  `writing-mode: vertical-rl` + `tracking-[0.25em]` 让既有的字距变成行距，一个字都不必
  单独包。代价是必须同时挂 `whitespace-nowrap`（§9.1 的坑）。
- **没给印章偏移抽成常量或比例函数**。两处（遮罩 `{8, 40}`、卡片 `{5, 22}`）是同一构图
  按字号 128→72 缩出来的结果，写死两对数比引一层 `scale` 换算更好读 —— 它们各自只出现
  一次，也不跟着别的参数变。
- **没动结算卡里的「再玩一次」**。用户说的是遮罩上那一颗；弹窗里那四颗（关闭 / 再玩一次 /
  返回谜题列表 / 下一关）是另一处的出口，结算卡开着时它本来就该有。
- **没让「已完成再进入」的遮罩自动收起**。这一局仍然一进来就盖着定案遮罩（v0.9.6 定的），
  「再玩一次」就摆在它上面 —— 点它才撤掉遮罩回到奔跑状态。
- **没把 `shift` 做成百分比或按可见区自适应**。72px 是在桌面 1280 上调出来的一次性偏移，
  竖屏下它跟着 `zoom` 同比例缩、印右缘仍在框内（§9.3 的实测）；做成比例会多一条参数，
  而这一块的位置本来就只有「略微偏右」这一个要求，极左极右都没有场景。
- **没把卡片档与游戏内档统一成一个缩放入口**。两档的口径本来不同：游戏内那档要「扣掉按钮那块、按可见区算」，卡片那档要「按封面算、留 22% 的底」。硬合会把按钮高度这类只有遮罩才有的概念塞进卡片路径。共用的是 `VerdictStageBox` 这个类型与 `VERDICT_MIN_SCALE` 这条下限。
- **没给卡片的「定案」按封面换字号档**。现在仍是 `text-7xl` + `h-24` 的印，靠 `zoom` 整体缩；换档（比如小封面用 `text-5xl`）会多一条断点，而 `zoom` 已经让整块落在封面里了。
- **没让卡片的 `VERDICT_CARD_FILL` 跟着卡片列数变**。四列时封面 136、两列时 291，两处都用 0.78 —— 大封面上字看起来会更满，但整块仍在外接盒里，构图一致。要按列数调就得知道网格列数，那是列表页的事。
- **没给 `verdictMarkScale` 的可见区口径加「最少留多少边距」**。现在只扣了按钮那一块
  （`VERDICT_BUTTON_BLOCK`），没有留第二道内边距 —— 缩下来之后整块是贴着可见区边界算的。
  再扣一圈要为新常量定值，而 `VERDICT_MIN_SCALE = 0.5` 已经兜住了「不至于缩没」。
- **没把遮罩本身改成按可见区铺**。`verdict-scrim` 仍是 `absolute inset-0`、挂在画布纸里
  （跟着缩放平移走，v0.9.6 的做法），所以横屏下它的矩形仍是 924×924、比可见区大。
  要改得让它脱离画布纸、另量一次 `<main>` 的矩形 —— 那会丢掉「跟着纸走」这个特性，
  而用户要的是「字别顶出去」，缩放已经解决了。
