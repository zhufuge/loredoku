## §1 问题：线索被截断，滚动条有三层

改前竖屏（375×812，7×7）实测：

- 名册里每张横卡的线索 `<span>` 都带 `line-clamp-3`，线索区高度固定按三行算。7 位参与者
  的线索 11~42 字，三行（48px）之外的部分被省略号吃掉 —— 而线索正是玩家要反复对照的
  东西，截断等于把最需要的半句藏起来。
- 卡片高度由 `COMPACT_CARD_MIN_HEIGHT = 80` 兜底、内容撑高：线索两行的卡 80、三行的 82。
  **卡片高度和线索行数脱钩**，长的被 clamp、短的留白。
- 滚动链上有三层各自可滚的容器：

  | 层 | 来源 | 改前 |
  |---|---|---|
  | 面板容器（题面 + 名册那一块） | `GamePage.tsx` | `max-md:overflow-y-auto` + `max-md:flex-1` |
  | 全局线索 | `GameBrief.tsx` 根 `<section>` | `max-h-[min(24svh,220px)] overflow-y-auto` |
  | 名册滚动区 | `ParticipantPanel.tsx` | `min-h-0 flex-1 overflow-auto` |

  手指滑在名册上滚的是第三层，全局线索停在上方不动；要看完线索得把手指移到纸条上再滚
  一次。名册 wrapper 那一层因为 `max-md:overflow-x-auto`，`overflowY` 被浏览器算成
  `auto`，实际是第四个（滚不动的）滚动容器。

## §2 线索读全，卡片跟着内容长高

`packages/web/src/components/map-editor/ParticipantPanel.tsx`，线索 `<span>` 的 className：

```tsx
className={cn(
  compactPortrait ? 'text-left' : 'line-clamp-3 text-center',
)}
```

原来是无条件 `'line-clamp-3 text-center'`，再给 `compactPortrait` 追加 `text-left`。现在
两条互斥：**桌面竖卡截断，竖屏横卡不截断**。

| 项 | 桌面竖卡 | 竖屏横卡 |
|---|---|---|
| 线索区 | 固定 `CLUE_AREA_HEIGHT = 72` | 高度由内容决定（`height: undefined`） |
| 截断 | `line-clamp-3` | 无，读全 |
| 行高 | `CLUE_LINE_HEIGHT = 20` | 16（v0.10.1 定的） |
| 卡片高度 | `PANEL_CELL_HEIGHT + NAME + CLUE` 写死 | `minHeight: COMPACT_CARD_MIN_HEIGHT` 兜底 + 内容撑 |

**为什么桌面不改**：桌面那张竖卡有 72px 的线索区，卡片大小固定、名册像一张表格，
三行之后收省略号是版式的一部分；而且桌面上鼠标悬停有 `title` 全文可看。

**为什么竖屏不能也靠 `title`**：触屏没有悬停。`title` 在手机上要么不出现，要么要长按
（而长按在棋盘上已经绑了「放头像」）。

**为什么保留 `minHeight`**：线索短的卡（两行 32px）如果不兜底会矮到 64 左右，和旁边
四行的卡差出一大截，两列网格看起来会参差。80 是「两行线索 + 名称」刚好需要的高度。

## §3 竖屏下线索与名册连成一段一起滚

三处同时放开，让外层容器成为**唯一**滚动区：

| 文件 | 改动 | 为什么 |
|---|---|---|
| `components/game/GameBrief.tsx` | 根 `<section>` 追加 `portrait:max-md:max-h-none portrait:max-md:overflow-visible` | 放开高度上限、交出滚动条 |
| `components/map-editor/ParticipantPanel.tsx` | 滚动区 `overflow-auto` → `compactPortrait ? 'overflow-visible' : 'overflow-auto'` | 名册不再自己滚 |
| `pages/GamePage.tsx` | 名册 wrapper 追加 `portraitFit && 'max-md:flex-none portrait:max-md:overflow-visible'` | 不再参与高度分配，且不再是第二个滚动容器 |

### 3.1 为什么必须用 `portrait:max-md:` 而不是裸 `max-md:`

`max-md:` 在 740×360 的横屏手机上也命中。横屏下面板容器走的是
`portraitFit ? 'max-md:flex-1' : 'max-md:max-h-[38svh] max-md:flex-none'` 的**后者**（限高
38svh），此时名册必须自己滚，否则内容会被裁掉。`portrait:` 把这一批改动限定在「窄且
竖着」的局面，横屏手机原样不动（实测见 §5.1）。

### 3.2 那个「漏了 `overflow-visible` 就白干」的坑

第一版只给名册 wrapper 加了 `max-md:flex-none`，实测 `overflowY` 仍是 `auto`：

> CSS 里只要有一个轴是 `auto`，另一个轴就会被算成 `auto`（`visible` 会提升为 `auto`）。

wrapper 上原有的 `max-md:overflow-x-auto`（v0.10.1 给 24 人名册准备的横向滚动）让这一层
成了第二个滚动容器，触屏滑动可能被它吃掉。竖屏名册是 `minmax(0, 1fr)` 的弹性轨道、
本来就不横向溢出，所以竖屏直接 `portrait:max-md:overflow-visible` 让位。

### 3.3 为什么 wrapper 还要 `flex-none`

面板容器（唯一滚动区）是 `max-md:flex-1` 的 flex 容器，名册 wrapper 原本 `flex-1`。
放开名册内部滚动之后，`flex-1` 会把 wrapper 压成容器剩下的那点高，多出来的卡片只能
**溢出** —— 滚动条在祖先上，但高度分配没给内容留位置。改 `flex-none` 之后容器的
`scrollHeight` = 线索 + 全部卡片，滚得到底。

## §4 封面：编辑器里看到的和列表卡上看到的是同一张

### 4.1 问题：两把尺

同一张封面图，界面上有四个地方画它：

| 位置 | 组件 | 改前比例 |
|---|---|---|
| 编辑器「基本信息」抽屉的预览框 | `components/common/CoverPicker.tsx` | `MAP_COVER_ASPECT` = **16:10** |
| 新建 / 编辑地图对话框的预览框 | 同一个 `CoverPicker` | 同上 |
| 地图列表的网格卡片 | `components/map/MapGridCard.tsx` | **`aspect-[4/3]`** + 默认 `scale-[1.2]` |
| 谜题列表的网格卡片 | `components/puzzle/PuzzleGridCard.tsx` | **`aspect-[4/3]`** + 默认 `scale-[1.2]` |

列表行（`MapListRow` / `PuzzleListRow`）的缩略图是 `h-10 w-16`，本来就在 16:10 上，
`CoverPicker` 也是 16:10 —— **只有两张网格卡片的 `4/3` 是异类**。

裁切的差距不止比例。`scale-[1.2]` 那层放大只保留中间 `1 / 1.2 ≈ 83%`，等于在 4:3 之上
再裁一刀。存量封面几乎都是正方形（实测 `storage/uploads/maps/**`：1000×1000、900×900、
320×320、1081×1133、768×768），正方形图在 16:10 里上下各裁 18.75%、在 4:3 里只裁 12.5%，
再叠 1.2 又多裁一圈 —— 三个裁法叠下来，配好的封面回到列表就认不出了。

### 4.2 做法

两张网格卡片各改两处（`MapGridCard.tsx` / `PuzzleGridCard.tsx`）：

```tsx
style={{ aspectRatio: String(MAP_COVER_ASPECT) }}
className="relative block w-full cursor-pointer overflow-hidden border-b bg-muted/40"
```

- 比例写进行内样式、取 shared 的常量，而不是写 `aspect-[16/10]` 类：**常量是唯一真源**，
  以后调一次三处一起变。
- 图片去掉 `transition-transform duration-image ease-in-out scale-[1.2] group-hover:scale-100`，
  只留 `h-full w-full object-cover`。要让「配置时看到的」和「卡片上看到的」逐像素一致，
  就不能有那层放大。

`docs/map-management-and-editor.md` §2.3 的封面那一行同步改写（原写着 `aspect-[4/3]` +
`scale-[1.2]` + hover 缩回）。

### 4.3 验证

用一张 800×800、四边写着 `L` / `R`、正中写着 `CENTER` 的测试图当封面，同一张图在两处
各量一次：

| 位置 | 改前 | 改后 |
|---|---|---|
| 卡片封面框 | `294×221`（ratio **1.333**） | `294×184`（ratio **1.6**） |
| 卡片上能看到的标记 | 只有 `CENTER` | **`L` / `CENTER` / `R` 全部可见** |
| 抽屉预览框 | `287×179.38`（`aspect-ratio: 1.6 / 1`）、能看到 `L`/`CENTER`/`R` | 不变 |

改后的卡片与抽屉预览看到的是同一块视野。谜题列表同构，实测一致。

## §6 没做的

- **没给线索加「展开 / 收起」**。用户说的是「展示要全」，那就一次画完；再加一个开关
  等于把「要不要读全」的决定推回给玩家。
- **没把卡片高度做成完全等高**。线索两行的卡 80、四行的 98 —— 强制等高要么给短卡留
  大片空白，要么把长卡的线索再截断，两者都与本条需求相反。
- **没改桌面那张竖卡的 `line-clamp-3`**。桌面卡片尺寸固定、名册像表格，截断是版式；
  鼠标悬停有 `title` 兜底。用户这次说的是竖屏那批。
- **没在横屏手机上也让线索读全**。横屏下面板只有 38svh、名册必须自己滚，放开截断会让
  单张卡比可见区还高，滑起来找不到边界。这一条与 v0.10.1 §9 的「没处理横屏手机的高度」
  是同一笔账。
- **没把 `GameBrief` 的 `max-h` 整个删掉**。桌面端左栏仍需要它（线索多时会挤掉名册），
  只是竖屏用 `portrait:max-md:max-h-none` 放开。
- **没给名册 wrapper 加 `overflow-y-visible` 而是用了 `portrait:max-md:overflow-visible`**。
  单写一个轴会留下另一个 `auto`，还是要靠「一轴 auto 另一轴也变 auto」这条规则吃掉滑动。
- **没做滚动位置记忆**。切回关卡时从顶部开始，与改造前一致。
- **没给线索纸条的 `animationDelay` 做调整**。`clue-note` 的逐条入场（每张 45ms、最多
  6 档）不受本次改动影响。
- **没改 `MAP_COVER_ASPECT` 的值**。16:10 是 v0.4.2 定的（游戏封面也用它），本次是让列表
  卡片来对齐它，不是反过来。
- **没给 `CoverPicker` 加 `aspect` prop**。三处都该是 16:10，多一个可配项只是多一条能配错
  的路。
- **没保留卡片的 `hover` 缩放动效**。`scale-[1.2] → scale-100` 本身是个好看的细节，但它
  恰好是「卡片比预览更近一点」的那一刀；两者不可兼得时选了一致。
- **没动列表行缩略图**。`h-10 w-16` 本来就是 16:10，且不裁切。
- **没改历史封面文件**。存量封面多是正方形，16:10 下会被裁掉上下各 18.75% —— 这是内容本身
  的形状问题，不是显示 bug；要改得重新上传按 16:10 裁好的图。
