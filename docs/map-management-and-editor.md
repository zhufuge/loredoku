## 1. 术语与对象模型

| 术语 | 代码 / 字段 | 含义 |
|---|---|---|
| 地图 | `maps` 行 | 一个可编辑的画布作品，实际含义是「一个工作条目」 |
| 行类型 | `maps.version` | `'draft'` = 工作条目；纯数字字符串（`'1'`/`'2'`…）= 已发布版本。v0.5.8 第三阶段起两者同表 |
| 工作条目 | `MapEntrySummary.kind = 'draft'` | 地图列表里**可编辑**的那一条（血统内可以有多条，fork 出来的也是） |
| 版本条目 | `MapEntrySummary.kind = 'version'` | 发布时插入的**不可变快照**行，只读；`deleted_at` 非空 = 已删除（界面不可见，数据仍在） |
| 血统 | `maps.root_id` | 由同一原型派生出的所有工作条目与版本共享的根 id |
| 草稿 | `maps.data`（`MapDraft \| null`） | 工作条目当前存的内容；`null` = **未初始化**（创建时不带画布尺寸，编辑器会弹初始化窗）。版本行的 `data` 是快照，恒非空 |
| 画布尺寸 | `data.gridSize` | 唯一真源。v0.5.8 起 DB 无对应列（`maps.grid_size` 已删） |
| 发布 | `POST /api/maps/:id/versions` | 请求体可带 `version`（不传 = 血统 `MAX+1`）；把当前草稿快照成**一条新的 maps 行** |
| 派生 / fork | `.../versions/:versionNo/fork` | 以某个旧版本为起点**新建**一个工作条目 |
| 形态 | `asset_variants` 行 / `variant` | 一个资源的一种「样子」。**中文一律称「形态」，代码与数据层一律 `variant`**（`AssetVariant`、`variantId`、`/variants`、`asset_variants`）；两套叫法指的是同一个东西，不要混写成「变体」。v0.6.1 时库里叫 `asset_forms` / `formId` |

对象关系：

```
root_id = A 的血统
├── 工作条目 A（version = 'draft'，draft 随保存滚动）
│     └── 发布 → 版本行 v1, v2, v3 …（version = '1'/'2'/'3'，不可变，累积在同一血统上）
└── 从 v2 派生 → 工作条目 B（version = 'draft'，root_id 仍是 A）
      └── 发布 → v4（编号取整个血统的 MAX + 1，不是 B 自己的 +1）
```

五条不变式：

1. **发布不覆盖工作条目**。发布只是新增一条版本行，当前草稿原封不动，作者可以继续改、继续发下一版。
2. **版本号跨血统递增且不回收**。默认号 = `MAX(version) + 1`（**含软删行**），在 `root_id` 范围内算。所以 fork 出来的新条目第一次发布叫 v4 而不是 v1；删掉 v3 之后再发布也不会重新产出 v3（谜题快照还对得上）。
3. **版本是不可变快照**。没有「回滚」操作 —— fork 就是「从旧版本开始改」，再加一个回滚等于同一件事的破坏性写法，会覆盖进行中的工作条目。
4. **「未初始化」是一等状态，不是「默认尺寸的空画布」**。创建地图不再收集尺寸（§2.5），所以草稿可以是 `null`：服务端不兜底、`MapResponse.draft` 可空、编辑器弹初始化窗（§3.2），三层配合把这个状态一路透到用户面前。此时发布返回 400「请先在编辑器里初始化画布尺寸」。
5. **版本行是只读行**。合并后版本行也是合法的 `maps` 行，`/api/maps/:id` 的写入口都能直达它，所以改名 / 改描述 / 画布 PUT / 调尺寸 / 封面 / 复制 / 再发布一律 400「已发布的版本不可修改」（发布是 400「只有草稿可以发布」）。删除是唯一例外，且分流：草稿行**硬删**（不牵连版本）、版本行**软删**（界面消失、行还在、号仍占用）。

### 2.2 工具栏控件

| 控件 | 取值 | 行为 |
|---|---|---|
| 搜索框 | 文本 | **300ms 防抖**后作为 `keyword` 提交到后端，并把两块页码都重置为 1；匹配名称 |
| 排序 | 按更新时间（默认）/ 按名称 | 后端排序，`order=desc`，切排序时两块页码都重置；**两块都生效**（v0.5.8 第九阶段起版本块也跟随它，默认即「最新发布在上」） |
| 视图 | 网格（默认）/ 列表 | 两套渲染，动作按钮完全相同；**只作用于草稿块**（版本块恒为列表）；**选择持久化**在 `localStorage['loredoku.maps.view']`，刷新后沿用 |
| 分页 | 每块每页 **12** 条，**两块各有一条翻页条** | 只有上一页 / 下一页，不跳页；**单页时翻页条整条隐藏**（块标题已写总数）；删到当页空了会自动收敛到最后一页 |

「条目类型」三态筛选与「按地图归组」开关已在 v0.5.8 §15 删除：正文分块天然实现「只看草稿 / 只看版本」。归组当时靠版本块固定的血统排序（`rootId` 升序、版本号降序）兼顾，**v0.5.8 第九阶段版本块改按时间排序后，这层便利取消** —— 要看同一张图的各版本，用搜索框筛名称。

**两块各自分页**（v0.5.8 第四阶段）。同一端点 `GET /api/maps` 带 `kind=draft|version` 发两个请求，各带页号、各拿 `total`，所以「草稿 27 / 版本 32」是各自的总数而不是当前页条数，翻版本块也不会把草稿块翻走。并集分页时期两块共享一页，版本密集时某一页可能只出现版本块、草稿全在别页，页码也对不上任何一块——这是拆开的直接原因。**排序一律在服务端**（客户端只能重排当前页，跨页会乱）：v0.5.8 第九阶段起版本块不再固定血统顺序，改为和草稿块一样跟随 `sort` / `order`，默认 `updatedAt` 倒序，即最新发布的版本在最上面。

### 2.3 条目的信息与徽标

v0.5.8 起**两类条目共用同一套 DOM**（`MapGridCard` / `MapListRow` 内没有 `entry.kind` 分叉），差别只在数据。但 v0.5.8 §15 把正文拆成「草稿」「版本」两块后，**卡片只出现在草稿块**——版本块恒为 `MapListRow`，所以「封面 / 卡片上的时间」这几行只对草稿块有意义（尺寸与列表行的时间两块都有）：

| 元素 | 工作条目（草稿块） | 版本条目（版本块） |
|---|---|---|
| 封面 | `aspect-[4/3]` 预览（v0.5.8 从正方形改矮一档），无封面时显示名称首字；默认 `scale-[1.2]` 放大裁中间（四边被 `overflow-hidden` 切掉），**hover 卡片时缩回 `scale-100` 展示全部**（v0.5.9，v0.5.8 是 1 → 0.95，幅度太小） | 列表行左侧 `h-10 w-16` 缩略图，不缩放、不裁切 |
| 徽标 / 版本列 | **整格不渲染**（v0.5.8 第五阶段）——卡片名称后没有徽标，列表行也没有那一列 | 卡片：名称后一格 `v{n}`；列表行：名称与描述之间独立一列 `v{n}`（`w-14`、等宽数字） |
| 尺寸 | 卡片副信息行里与时间**相邻**（两者分两边）；列表行独立一列 `n × n`（`w-16`、等宽数字）。未初始化打 `—` 占位（v0.5.8 第七阶段） | 同左 |
| 描述 | 最多两行截断（列表行里占满徽标让出的宽度） | 同左 |
| 时间 | 卡片副信息行里紧跟在尺寸右边（`x 分钟前更新`，相对时间） | 列表行右对齐的绝对时间（`w-52`） |

尺寸之所以不整格隐藏（原卡片是「未初始化就整段不渲染」），是因为列表行要按列对齐：缺一格会让描述与时间整体左移。`—` 也顺带表达了「这张图还没设画布尺寸」。

徽标**只写 `v{n}`**，不再出现「已发布 v3」「地图 v3」这种前缀。判定**只看 `versionNo`**：v0.5.8 用 `versionNo ?? currentVersionNo`，发布过的工作条目也会顶个 `v3`，与草稿语义相反；v0.5.9 起工作条目不再有徽标。**v0.5.8 第五阶段把草稿那一格整体去掉**：分块之后草稿块里条条都是草稿，徽标与版本列都是把「草稿」重复 N 遍。所以卡片上的徽标、列表行里的版本列都只在 `versionNo !== null` 时渲染。「共 N 个版本」元信息已删除（版本列已经说清是哪一版）。

网格最大一行 **5** 个（`2xl:grid-cols-5`；`sm:2 / lg:3 / xl:4` 逐档加），再宽也不铺满——封面要够大才认得出。

主点击按 kind 分叉（v0.5.8 §13）：**草稿进编辑器，版本进「以此为底稿新建」**——同样进编辑器，但带 `?v={n}`，画布装的是版本快照，**保存时才 fork 出新草稿**（详见 §3.18）。v0.5.8 早期两者都去 `/editor/:mapId`，而版本条目的 `projectId` 就是拥有它的 maps 行 id，点哪条都展出一份草稿、版本内容被覆盖；v0.5.9 一度改成只读预览，但那样「基于旧版本继续改」没有入口。只读预览仍保留在菜单 / 列表的眼睛图标里。

### 2.4 两类条目共用的动作

| 动作 | 网格视图 | 列表视图 | 说明 |
|---|---|---|---|
| 主点击 | 点封面 / 名称 | 点封面 / 名称（外加卡片上的「进入编辑」次按钮） | **看 / 改分开**（v0.7.2）：草稿行 = 进编辑器 `/maps/{mapId}/edit`；版本行 = **只读预览** `/maps/{mapId}/views`（与眼睛按钮同一个动作） |
| 编辑 | — | `SquarePen` 图标（排在预览之后） | 版本行才有：`/maps/{mapId}/edit?v={v}`（v0.5.8 §13，进的时候不建行、保存时才生成新草稿，见 §3.18）。草稿行的封面点击本身就是编辑，不再挂第二个入口。图标与「编辑信息」的裸铅笔刻意区分：那个改名称 / 描述 / 封面，这个进编辑器改画布本体 |
| 编辑信息 | 三点菜单 | 铅笔图标 | 对话框：名称、描述、封面（画布尺寸在编辑器里调，见 §2.6）。**仅工作条目**——版本行的 name / description / cover 是发布时的快照，改名就破坏了「版本不可变」（v0.5.8 第三阶段） |
| 预览 | 三点菜单 | 眼睛图标 | 打开 `/maps/{mapId}/views`；草稿行预览的是**它自己的画布**，版本行预览的是那一行。**从没发布过的工作条目禁用**（标题提示「还没有已发布的版本可预览」） |
| 复制 | 三点菜单 | 复制图标 | `POST /api/maps/:id/duplicate`，复制出一个新的独立条目。**仅工作条目**——版本是冻结快照，复制它既不能改也产不出有用的新图（v0.5.8 §13 裁定） |
| 删除 | 垃圾桶图标 | 垃圾桶图标 | 工作条目 → `DELETE /api/maps/:id`，**硬删草稿行**（版本行不再跟着消失，v0.5.8 第三阶段），二次确认「将同时删除画布上的所有物品与区域，不可恢复。」；版本条目 → `DELETE .../versions/:versionNo`，**软删**，确认「该版本条目将被永久删除」。v0.7.1 起谜题自带画布**副本**，删地图版本不再牵连任何谜题。 |

三点菜单（`EntryActionsMenu`，v0.7.1 从 `components/map/` 移到 `components/common/` 并泛化到「条目摘要」公共形状，地图与谜题列表共用；谜题的版本条目多一项「部署」）是自绘的：`pointerdown` 监听容器外关闭，层级 `UI_Z.drawer`。v0.5.9 起浮层 **portal 到 `<body>`** 并用 `position: fixed` 跟随按钮——v0.5.8 它是卡片内的 `absolute` 子元素，卡片的 `overflow-hidden`（封面圆角需要）会把探出下沿的菜单裁掉，网格最后一行尤其明显。菜单项按 `entry.kind` 分流：工作条目三项（编辑信息 / 预览 / 复制），版本条目**只剩「预览」**——v0.5.8 第三阶段把「编辑信息」也去掉了，快照列不可改。

> v0.5.7 及以前，版本条目有「查看效果 / 新建谜题 / 编辑此版本」三个按 kind 分叉的动作；v0.5.8 把它们收敛成与工作条目同一组，「新建谜题」改从谜题页进入，「编辑此版本」（fork）只留在版本历史面板。

### 2.5 新建地图

| 字段 | 约束 |
|---|---|
| 名称 | 必填，1 ~ 100 字；**不要求唯一**——可以与其他地图同名（v0.5.8 第六阶段） |
| 描述 | 选填，≤ 500 字 |
| 封面 | 选填，PNG / JPEG / WebP / SVG，≤ 2 MB，预览框 16:10 |

**没有画布尺寸字段**——v0.5.8 起尺寸不进创建流程，对话框描述改為「创建后进入编辑器，先设置画布尺寸。」首次进入编辑器时弹初始化窗（§3.2）。

封面是**文件**、其余是 JSON，所以写入分两步：先建行拿到 id，再上传封面。上传失败时对话框**保持打开**并记住已创建的 id，主按钮变成「重试上传」——重试只补传图片，不会建出第二张地图。

### 2.6 编辑地图信息

名称、描述、封面三样。封面有三态：保留 / 更换 / 移除，「移除」是显式动作，保存时才真正删除。对话框描述固定为「画布尺寸在编辑器里调整。」名称同样不查重，改成与别人一样的名字是允许的。

### 2.7 状态与边界

- **加载中**：8 个骨架卡。
- **加载失败**：一句错误信息 + 「重试」。
- **空块整块隐藏**：某一块没有条目时，标题与容器都不渲染；只有两块都空才出空态——搜索无结果「没有匹配的地图」，否则「还没有地图，创建一个开始吧」+「新建地图」按钮（v0.5.8 §15 之前「只看版本」的空态分支已随筛选器删除）。
- **删除进行中**：按钮转圈、弹窗禁止 Esc 关闭。

## 3. 地图编辑器 `/maps/:mapId/edit`

独立全屏路由，不在 `AppShell` 内——所以没有全局头部，主题开关挂在编辑器自己的工具栏上。

### 3.1 布局

```
┌──────────────────────────────────────────────────────────────┐
│ ← [名称] [草稿 / 已发布 vN] [未保存]  🌗 │ 导入 导出 基本信息 版本历史 预览 │ 保存 发布 │
├───────────┬───────────────────────────────┬──────────────────┤
│ 资源 | 区域 │                               │  信息框 / 基本信息 │
│           │            画布                │  320px（占据空间）  │
│  背景层/物品层│      ┌─ 底部浮动工具条 ─┐      │                  │
│  三列缩略图 │      └──────────────────┘      │                  │
└───────────┴───────────────────────────────┴──────────────────┘
```

两个右侧面板（信息框 / 地图基本信息）是编辑区那一行的**兄弟节点**（v0.7.4）：打开就从画布那儿拿走 320px，画布收窄并由自适应重新适配，不再被浮层盖住。它们的开合互斥，信息框收起时右侧留一条 8px 窄条。谜题编辑器用的是同一个 `EditorInfoDrawer`，但传 `layout="overlay"`，保持浮层形态（那边三个右侧面板都是浮层，见 §6）。

### 3.2 初始化弹窗（草稿为空时）

创建地图不带尺寸，所以 `MapResponse.draft === null`。此时页面主体**整体让位**给「初始化『{地图名}』」弹窗——它不是可以关掉的弹窗（关掉也没有可渲染的画布），没有取消按钮，返回列表走左上角返回键。两条出路：

- **填尺寸**：输入框自动聚焦，回车即提交；走 `PATCH /api/maps/:id/grid-size`，服务端在草稿为空时新建一份只带 `gridSize` 的草稿。成功后 query 失效重拉，`draft` 不再是 `null`，页面主体随即渲染。
- **导入地图**：打开隐藏的文件选择框，读一个之前导出的 `MapDraft` JSON 写入草稿。画布还是空的，没有「覆盖」可言，所以**不走** §3.15 的二次确认。

尺寸范围与创建时代一致：**2 ~ 24**，默认 6。

### 3.3 顶部工具栏

| 控件 | 说明 |
|---|---|
| ← 返回 | 回地图列表（未保存会先被拦，见 §3.16） |
| 名称 | 只读展示，超长截断 |
| 状态徽标 | `草稿` / `已发布 v{n}` |
| `未保存` 徽标 | 仅在 dirty 时出现，**本身就是快捷键**：点一下立即保存 |
| 主题开关 | 三态（跟随系统 / 浅色 / 深色） |

| 预览 | v0.7.4：进只读预览页。**先落库再跳** —— 抽屉里未应用的改动先应用、dirty 则走一次保存，成功后 `navigate('/maps/:id/views', { state: { from: 'editor' } })`；预览页的返回键据此回编辑器（§4）。fork 态与谜题编辑器不渲染这个按钮 |

### 3.4 左面板

宽 280px，两个 tab：

**资源**
- 图层切换：`背景层` / `物品层`（对应 `EditorLayer.background` / `item`）。
- 搜索：匹配资源**名称、code 或形态名**。
- 三列缩略图；点选即选中，再点同一项取消。选中后底部提示「已选中资源，点击画布放置；再次点击可取消」。
- **一张瓦片 = 一个形态**，两层同一套规则：一个资源有几个形态就有几张瓦片，瓦片上的
  小字是**形态名**（单形态资源显示 `1 格`——v0.7.6 起形态不再有占格可印）。
- 列表只显示 `type` 等于当前图层的资源，因此背景层里看不到物品类资源。
- 资源来源是 `isActive: true` 的资源，停用的不出现在调色板里。
- 选中态是「资源 + 形态」一对：`editorStore.selectedAssetId` / `selectedVariantId`。
- **刷新按钮**（v0.7.7）：与搜索框同一行、贴在它右侧的 `RefreshCw`（不占 tab 头部），点一下重取资源列表
  （`useAssets({ isActive: true })` 的 `refetch`）—— 别的标签页刚加过资源时不用整页
  重载（重载会丢撤销栈与视口）。取数中图标转圈且按钮禁用；**区域 tab 没有这个按钮**
  （区域是草稿里的本地数据，没有可刷的东西）。刷新后若选中的资源或形态已不在新列表里，
  选中会被清空 —— 否则画布会往草稿里写一个不存在的 `variantId`。

**区域**
- 顶部「区域工具 (R)」按钮，等价于切到区域工具。
- 下方是区域列表：名称、`{n}格`、删除。**没有编辑按钮**——点条目即在右边信息框里改
  （与点画布上的区域标签是同一个面板，见 §3.9）。

面板**任何工具下都可点**（v0.7.0 fix：原先区域工具激活时整块半透明锁死）。点资源 /
点区域条目 = 取消当前功能并切换到对应功能，与橡皮擦同逻辑：点资源 → 回选择 / 放置
（store 的 `setTool` 离开区域工具时会连圈选草稿一起清掉，不会留下不能确认的半截选区），
点区域条目 → 聚焦该区域并弹出信息框。

### 3.5 画布工具

| 工具 | 快捷键 | 行为 |
|---|---|---|
| 选择 / 放置 | `V` | 单击选格、点区域标签选区域；选中物品后单击画布放置 |
| 区域选择 | `R` | **自由笔刷**：按住涂抹，鼠标划过的格子都进选区 |
| 橡皮擦 | `E` | 按 **物品层 → 背景层** 的顺序逐层清除；物品层是单格物品还是多格物品按其占位展开 |
| 平移 | `H` | 拖动画布平移视图（与拖空白区 / `Space` / 中键同一条路） |

区域笔刷的方向（v0.7.0）：**起点格已在选区里 → 整笔清除**，`Alt` 永远强制清除；否则整笔
添加。一笔之内方向固定——所以选错了涂回去就能删掉单个格子，不需要整个「清空」重来。
矩形选中模式已删除。

工具互斥（v0.7.0 fix）：橡皮擦 / 平移 / 区域工具下，左面板的资源与区域**照常可点**——
点资源即回「选择 / 放置」并选中它，点区域条目即聚焦该区域（信息框弹出），当前功能同时
取消。切换工具（按钮 / 快捷键都算）离开区域工具时，未确认的圈选草稿一并清空。

放置规则：
- **背景层只接受 `type === 'background'` 的资源**。层不对时提示「该资源不能放在当前图层」，不写入。
- 物品层接受任意类别（`blocking = true` 的资源也允许，只是该格会被标成阻挡）。
- 落位恒占 **1 格**（v0.7.6：形态不再声明脚位），悬停预览框也就是一格。想让它看起来更大，用格子信息框里的「大小」（`scale` 只改显示，占格仍是 1）。
- 落位时锚点冻结三件事：`assetId`、`variantId`、`w`/`h`（背景层只冻结前两件）。新放置的 `w`/`h` 恒为 1；老草稿里冻结的 2×2 仍然照旧占格、照旧渲染——想换占位只能擦掉重放。

视图操作：
- 平移：底部工具条的「平移」按钮、拖画布外的空白区、或按住 `Space` 拖、或鼠标中键拖。
- 缩放：底部工具条按钮，或 **`Ctrl/Cmd + 滚轮`**（普通滚轮不缩放，避免和页面滚动抢），范围 `0.25 ~ 4`、步进 `0.1`。滚轮缩放锚点跟随指针，按钮缩放锚点是视口中心——两者都走画布的同一条路（`EditorCanvasHandle.zoomByStep` / wheel handler），都会把视图标记为「用户已调整」，自适应居中从此让位（v0.6.3 fix：按钮路径曾漏了这个标记，被居中 effect 打回 100%）。
- 标尺：顶条 = 列号（`C1…`）、左条 = 行号（`R1…`），长轴跟随棋盘（远端超出视口被裁掉是应有的）。**薄轴各自定尺**（v0.7.0 fix）：列条按「字形高度 + 间距」，行条还要再加 `R24` 这类标签的**宽度**——只按高度算，行号会被条子自己的 `overflow: hidden` 拦腰裁掉，放大越厉害裁得越多。薄轴放得下就贴在棋盘边外侧，放不下（棋盘边顶到视口边缘，或放大后棋盘已伸出视口）就改贴视口边缘，标签完整、代价是轻微压住棋盘边上的几列。

悬停（v0.7.13）：
- 指针停在**同一件**已放置物品上满 **1 秒**，浮出一张小纸片报出**资源名称**。这个是画布层的
  行为，不是编辑器专有 —— 地图编辑、谜题编辑、地图预览、谜题预览、游戏页五处一致。
- 名字取自 `assets.name`（不是形态名）。物品层在预览 / 游戏页是 `pointer-events: none`，
  所以原生 `title` 在那儿从来不弹；命中改为按坐标算（以脚位为准，落在 `scale` 撑出去的
  那圈画上不算），位置也按显示框算：浮在物品上方 6px，第一行物品翻到下方，
  贴画布左右边时改贴边对齐。纸片长相与 `Tooltip` 同源（`TOOLTIP_SURFACE_CLASS`）。
- 换一件物品、移出画布都会立刻收掉，重新数满 1 秒；物品找不到资源时不弹。

### 3.6 底部浮动工具条

从左到右：

1. 四个工具按钮：选择 / 区域 / 橡皮擦 / **平移**（当前工具淡灰底高亮，见下）
2. `资源` 开关（收起 / 展开左面板）
3. **当前放置资源芯片**：缩略图 + 资源名，资源有多个形态时再带形态名；**未选中时整块不渲染**（没有占位框、没有文案，v0.7.0 §13）。有选中与工具选中态同档底色（实心 slate-200）。左面板收起时这是**唯一**能看出「点画布会放什么」的地方，点它把左面板开回来（已开则无动作）。芯片右侧的 `×`（v0.7.7）取消当前选中资源（`setSelectedItem(null, null)`，与切换图层 / Esc 同一条路径），不用先展开面板
4. 标尺开关（选择会存进 `localStorage['loredoku.editor.ruler']`，下次打开沿用）
5. `n×n` 画布尺寸按钮 → 打开「调整画布尺寸」对话框
6. 缩放组：`−` / 百分比（点击重置 100%）/ `+` / 适应画布
7. 撤销 / 重做

> 缩放的 `−` `+` 改的是**查看比例**，不改方格大小；方格大小在「基本信息」里。

> **工具栏底色梯度**（v0.7.0 fix）：shadcn 的 `secondary`/`accent` 在浅色主题同值 ≈ slate-100，选中 / 悬停都几乎看不出底色。编辑器与游戏页的工具栏图标按钮统一下沉一档：**选中态 = 实心 slate-200**（深色 slate-700，悬停再深一档），**未选中悬停 = 半透明 slate-200/70**（深色 slate-700/70），两个常量收口在 `web/src/lib/toolbarButtons.ts`（`TOOLBAR_ICON_ACTIVE_CLASS` / `TOOLBAR_ICON_HOVER_CLASS`）。左面板的 tab 选中态同档。

### 3.7 地图基本信息抽屉

从右侧展开的表单，宽 320px，五段。它**占据**编辑区右侧一块空间（v0.7.4，不再浮在画布上），关掉时不渲染。**它是一个表单**：所有控件改的是本地草稿；按「保存」只把草稿应用到页面（画布样式与尺寸立刻生效，名称 / 封面先改标题与预览），**一个请求都不发** —— 真正写库统一由工具栏「保存」完成（§3.11）。「取消」/ `×` / 切到别的焦点在 dirty 时会先问一句。

| 段 | 字段 | 取值 | 说明 |
|---|---|---|---|
| 基本 | 名称 / 描述 | 必填 ≤ 100 字 / ≤ 500 字 | 与列表「编辑信息」是同一组字段；名称为空时「保存」置灰 |
| | 封面 | PNG / JPEG / WebP / SVG，≤ 5 MB | 与新建 / 编辑对话框共用一个选择器；可更换、移除，移除后还能「恢复封面」 |
| 画布 | 画布尺寸 | 2 ~ 24 格 | 与「调整画布尺寸」是同一个量；缩小会让越界内容被移除 |
| | 方格大小 | 32 ~ 240 px，或**自适应** | 自适应时按窗口算；手动指定后窗口变化不再改变它。右侧 ↺ 恢复自适应。下限 32 同时也是自适应的下限（v0.7.2，24×24 的板子不再溢出视口）；32px 时 `cellScale ≈ 0.267`，分隔线 0.53px（`LINE_WIDTH_MIN` 之上）、字号落 `FONT_SIZE_MIN` |
| 线条 | 画布外框 | 线宽 1~12、颜色 | 骑在画布边界上，与网格最外一圈描边线是同一条线（v0.7.0 起，外侧画法已废弃） |
| | 网格分隔线 | 线宽 1~12、颜色 | `n × n` 只有 `n−1` 条横线 + `n−1` 条竖线 |
| | 鼠标光标框 | 线宽、颜色、阻挡色、阴影环色 | 跟随指针，画布最高层 |
| | 操作光标框 | 线宽、颜色、外扩距离 0~8 | 固定在当前操作格，画在最外侧 |
| 区域 | 区域轮廓线 | 线宽 **1**~12、颜色 | **区域外观的缺省值**：区域信息框默认填入这里，只有不同的字段才记到区域自己身上。下限 v0.7.4 由 4 降到 1 |
| | 区域高亮线 | 线宽 1~12、颜色 | 悬停 / 联动激活时出现，连续闭合，结束时 150ms 淡出 |
| | 区域标签 → 字体 | 字体下拉：**系统默认** + `packages/web/src/assets/fonts/` 里的每一款 woff2（构建时自动发现；源 TTF 放 `packages/web/fonts-source/`，`npm run fonts` 裁字转换，24.7 MB → 925 KB；一级之外的零散缺字写进 `packages/web/scripts/font-extra-chars.txt` 后重跑） | v0.7.4。存的是**字体名**（`WenKai`、`霞鹜文楷`），渲染时加引号挂到系统回退链前面；本构建没带的名字留在草稿里、按回退链画，老草稿的 `serif` 等内置 key 以「（当前）」出现 |
| | 区域标签 → 字号 | 字号 9~48、颜色 | 「描边 + 填充」绘制，深浅底都可读 |
| | 区域标签 → 描边 | 描边 1~12、颜色 | |
| | 区域标签 → 高亮 | 字号 9~48、颜色 | 区域被悬停或激活时切换成这一套；高亮字号永不小于常规字号 |
| | 区域标签 → 高亮描边 | 描边 1~12、颜色 | |
| 标尺 | 文本大小 | 9~32 px | 基准值，随方格尺寸等比缩放；操作格所在行列 +2px |
| | 文本到地图的间距 | 0 ~ 32 px | 参与标尺条厚度的计算；行条的厚度还要加上 `R{格数}` 标签的宽度（v0.7.0 fix） |

所有数值都是「基准值」：随方格尺寸等比缩放，**不随查看比例（zoom）变化**。

名称 / 描述 / 封面与画布样式一样只是本地草稿：抽屉里按「保存」后标题和封面预览立刻变，库里没变；工具栏「保存」才 PATCH 条目行、再上传 / 删除封面文件。这样一次编辑只产生一次写库，不会出现「名字改了、描述没改」的半成品。

> v0.5.8 前「首次进入自动落盘」（把解析后的默认值整体写一次）已移除：进编辑器只读不写，默认值在内存里按 `DEFAULT_MAP_STYLE` 解析（§5.1），用户显式保存时才落盘。

### 3.8 区域

**圈选**：区域工具（`R`）→ 自由笔刷涂抹 → 底部出现选区条（显示已选格数、清空、确认创建、取消）。
**起点格已在选区里的笔画是清除**，所以单个错格直接涂回去删掉，不用整个清空。

**两道校验**：
1. 确认时若格数为 0：toast「请先选择至少一个格子」。
2. 若选区不连通（四邻接）：弹「区域必须是相连的方格」，停在选区上让作者改。

**创建对话框**（`RegionDialog`，v0.7.0 起只管创建）：

| 字段 | 约束 |
|---|---|
| 区域 ID | 必填，字母 / 数字 / 下划线，≤ 64，全局唯一；新建时自动生成 `rg_xxxxxxxx` |
| 区域名称 | 必填，≤ 100 字 |
| 冲突处理 | **仅与现有区域有重叠时出现**：`覆盖`（从其它区域移除冲突格）/ `跳过`（冲突格不入新区） |

**编辑在右边信息框里**（§3.9）：名称、区域 ID、以及三组样式——区域轮廓线、区域高亮线、
区域标签（字体（具体字体，v0.7.4）/ 字号 / 描边 / 高亮 / 高亮描边，后四行各是「大小 + 颜色」
两个输入框）。表单**默认填入「地图基本信息」里的缺省值**；按「保存」时与缺省相同的字段
**不记录**，只有不同的才写进区域自己的 `style`。展示与渲染一律以区域自身配置为主、缺省值为兜底
（`resolveRegionStyle(地图级, region.style)`，全项目唯一合并点）。

**图层次序**（v0.7.0 fix）：区域轮廓线位于**画布外框与网格分隔线之上、物品图层之下**——
区域边界不会被网格线 / 外框切碎，物品图仍压在轮廓线之上。轮廓 SVG 用 `overflow: visible`，
贴画布边界的那条边整条画出（不裁成半条宽）。完整 15 层次序见
`docs/layer-priority.md` §2。

> v0.7.0 之前区域存的是 `color` / `borderWidth` / `fillOpacity` 三个字段，编辑在一个独立
> 弹窗里；旧数据由迁移 `20260101000030_v070_region_style.ts` 升级（`borderWidth` 与当地图
> 级缺省不同才记 `style.outline.width`），填充透明度与填充色整体废弃。

**删除**：二次确认「删除区域「{名称}」？区域会从草稿中移除。」删除可撤销。

### 3.9 信息抽屉

右侧第一条面板（与基本信息面板互斥，打开一个就关掉另一个），点格子或区域标签时打开。v0.7.4 起它**占据**编辑区右侧 320px（不再浮在画布上），画布跟着收窄；收起时留下 8px 窄条，点它展开。

- **格子分支**：坐标（`C3 R5`）、背景层物品（缩略图 + 名称 + #id）、物品层物品（缩略图 + 名称 + 占位 `w×h`，老草稿才可能大于 1）、所在区域摘要、快捷操作「清空本格」「清空物品层」。多形态资源的行会额外显示 `· 形态名`。
- **物品层的展示变换**（v0.7.5）：物品下面多三行 —— 「大小」（等比例，25~400%，步长 5）、「偏移」（X / Y，单位**格**，-4~+4，可负）、以及真有变换时出现的「复位」。这些只改**画出来的**大小与位置（可以画到脚位之外），占格 `w×h` 不变，所以占格 / 擦除 / 碰撞都不受影响；改动即时生效、一步一条撤销记录。只读环境（谜题编辑器）不给控件，只在有变换时显示一行摘要 `展示 150% · 偏移 (0.25, -1) 格`。停在脚位里的**任意一格**都能看到并编辑那个物品（以前非锚点格显示「空」）。
- **区域分支**（v0.7.0 起是**可编辑表单**）：名称输入框、区域 ID 输入框、三组样式（轮廓线 / 高亮线 / 标签五行，布局与「地图基本信息 → 区域」完全一致），以及「保存」「删除」两个动作按钮（「定位」在 v0.7.4 删除 —— 区域本来就是在画布上点开的，视图居中另有底部「适应画布」与 `Ctrl/Cmd+0`）。草稿未保存时离开编辑器会被拦下（§3.16）。
- 无选中时一句引导：「在画布上点击格位或区域标签查看详情」。
- 窄条与面板的层次：面板 `UI_Z.infoDrawer`(20)、基本信息 `UI_Z.drawer`(30)。

### 3.10 撤销 / 重做

- 撤销栈上限 **50** 步，存的是「画布快照」：格内容 + 区域 + 图层样式 + 画布尺寸。
- 样式（基本信息）、区域增删改、放置、擦除、清空、改尺寸**都在栈内**。
- 视图状态（缩放、平移、当前工具、选中）**不进栈**——撤销不会把画面甩回别处。
- 快捷键 `Ctrl/Cmd+Z` / `Ctrl/Cmd+Shift+Z`，与底部按钮等价。

### 3.11 保存

- **单一写入口**：工具栏的「保存」、`未保存` 徽标的点击、`Ctrl/Cmd+S`、发布前的「先保存」、调整尺寸前的「先保存」、v0.7.4 起**预览前的「先保存」**——全部走同一个函数。基本信息抽屉的「保存」**不写库**，只把草稿应用到页面（见 §3.7）。
- **一次保存做什么**：① 整份草稿（画布内容 + 样式 + 尺寸）；② 名称 / 描述有变则 PATCH 条目行；③ 封面有变则上传新文件或删除旧封面；④ 画布尺寸相对保存前变了，再调 resize 让服务端裁掉越界内容。每一步都只在**真有变化**时才发，所以只改名字时不会顺带重写一遍画布。
- **进入编辑器不触发保存**（v0.5.8）：FIX-F03 的「首次进入自动落盘」整条移除。挂载只 init 画布，不写任何请求——否则 query 失效会让 effect 重跑，在地图列表快速点击同一条目就写出一串草稿修订。现在「进编辑器」与「保存」是两个独立的用户动作。
- 保存中有全屏遮罩；请求返回后遮罩再保留 150ms 做淡出，避免闪烁。
- 保存成功即清 dirty，并把返回的 `currentVersionNo` / `status` 写回徽标。
- **不做并发锁**（v0.5.8 第八阶段）：保存是**后写覆盖**，请求只带 `data`，服务端不看任何修订号、也不会 409。两个会话同时编辑同一张图时，最后一次保存胜出。原来的 `maps.draft_updated_at` 列（草稿修订号 + CAS 令牌）已整列删除，`MapResponse.updatedAt` 与编辑器 store 里的 `updatedAt` 一并移除。
- **发布后不会重建画布**：编辑器的重新载入判定只剩两条 —— 换了一张图（`projectId` 变）才整份重载；同一张图下版本号 / 状态变了（发布、删版本、恢复）只刷版本徽标，视口原地不动。改名 / 换封面也不再触发重载（判定里没有修订号这一项了）。代价是另一会话保存草稿时本页不自动重载 —— 与其在用户画到一半时换掉画布，不如让最后一次保存胜出。

### 3.12 调整画布尺寸

入口：底部工具条的 `n×n` 按钮，或基本信息里的「画布尺寸」。

- 滑块 + 数字输入（2 ~ 24，失焦时取整并夹到范围内）。
- 中间是**新旧尺寸对照预览**：保留的格子绿色、将被裁掉的格子红色。
- 下方列出「将被移除」清单：越界物品（名称 + 占位 + 坐标）、部分格子越界的区域。
- 确认时：先保存（若 dirty）→ 再请求后端裁剪 → toast 报告移除数量（背景 x、物品 y、区域 z），没有移除则只说「画布已调整」。
- 基本信息里的尺寸**不走这条**：它先只改本地画布，等工具栏「保存」时随整份草稿一起写，再由 resize 接口裁掉被截断的物品 / 区域（§3.11）。

### 3.13 发布

流程：

1. 点「发布」→ 弹「发布为 v{n}？」，标题里的 `n` 跟着下面的输入框走。文案说清两件事：会新增一个带 v{n} 标记的条目、**当前工作条目不会被覆盖**（可以继续编辑并发下一版），并补一句「发布后该版本不可修改。」
2. **没有备注输入框**（v0.5.8 移除 `map_versions.notes`）；上面的确认文本就是二次确认。
3. **版本号输入框**（v0.5.8 第三阶段）：默认预填血统 `MAX+1`，可改成任意正整数（**不必连续**，可以填空洞号）。失焦即查重：非正整数、或血统内已存在该号（提示「版本号 v{n} 已存在于该地图血统中，请换一个」）都拦住，确认按钮点了也不会发请求。软删的版本不在前端列表里，这类重号由服务端 400 兜底。**没改输入框就不传 `version`**，交给服务端续号，免得拿着过期的默认值撞号。
4. dirty 时按钮文案为「保存并发布」，并提示「有未保存的修改，将先保存再发布」；否则「确认发布」。
5. 后端校验（见 §5.3）不通过 → 弹「无法发布」，逐条列出问题。**未初始化**（草稿为 `null`）时根本走不到这一步——接口先返回 400「请先在编辑器里初始化画布尺寸」。
6. 成功 → **只弹 toast**「已发布 v{n}」（副文案「已在地图列表新增条目。」），不弹窗、不跳转（v0.6.0：曾经的「查看该条目 / 预览」成功弹窗整段删除）。想预览去地图列表点该条目即可。

### 3.14 版本历史

弹窗列出**整个血统**的版本，每行：`v{n}`、是否「当前」、发布时刻、`n×n`、参与者 / 区域 / 物品计数。行操作：

- **查看效果** → 只读预览页。
- **编辑此版本** → fork 出一个新工作条目（标题提示「以此版本为起点新增一个条目」），完成后关闭弹窗。
- **删除** → **软删**该版本行（界面消失、行保留、号不回收；v0.7.1 起谜题自带画布副本，删版本不影响任何谜题）。

说明文案：「本图历史上发布过的所有版本（含从别条条目继承来的）。『编辑此版本』会新增一个条目，不会改动这条版本。」

**没有「回滚」**（理由见 §1 不变式 3）。

### 3.15 导入 / 导出 JSON

- **导出**：把当前草稿序列化成 `MapDraft` v4 下载，文件名 `{地图名}-{id}.json`。
- **导入**：读文件 → `mapDraftSchema`（`.strict()`）校验 → 二次确认「导入会覆盖当前画布内容，导入后可通过撤销回退」→ 写入。
- **从初始化弹窗进来的导入不走二次确认**（§3.2）：画布还是空的，没有「覆盖」可言，校验通过即写入。
- **旧版文件明确拒绝**：v2 及更早的草稿带 `characterSlots` 或 `style.linkageColors`。因为 schema 是 strict 的，静默丢弃这两块会让人以为参与者导入成功了，所以单独提示「该 JSON 是旧版（含参与者 / 联动主题色），请先移除这两部分，或改用导入到谜题」。
- 导入后**不自动保存**，仍可撤销。
- **字段结构不在这里**：`MapDraft` / `PuzzleDraft` 的每个键、取值范围与默认值见 [`docs/data-json.md`](./data-json.md)。

### 3.16 未保存保护

- **应用内跳转**（返回、点导航、改地址）由路由 blocker 拦下，弹确认。
- **刷新 / 关标签页**由 `beforeunload` 拦下。
- **切换焦点**（点格子、点区域标签、开基本信息抽屉）不丢内容，但若基本信息抽屉里有未保存修改会先弹「保存 / 放弃」。
- **未写库的基本信息同样算 dirty**：抽屉里按过「保存」但还没点工具栏「保存」时，`未保存` 徽标亮着，离开编辑器会被拦下 —— 否则名称 / 封面这类只在本地改过的值会悄悄丢掉。
- **信息框里未保存的区域表单同样算 dirty**（v0.7.0）：区域编辑搬进抽屉后，「改了样式没按保存」和基本信息一个待遇。
- **Esc 的优先级**：先关基本信息抽屉（dirty 时先问），再清格子 / 物品 / 区域焦点。
- **「预览」不弹确认**（v0.7.4）：它是「看完再改」的往返动作，所以先保存再跳；保存失败就停下不跳。真正离开编辑器（返回列表 / 改地址）仍走上面的确认。

### 3.18 基于版本新建（fork 态）

从地图列表点版本条目进入的是编辑器，但**挂的是 fork 态**：URL 形如 `/maps/:id/edit?v={n}`。

- **只装载、不写库**：数据源是版本快照（`useVersionDetail`），不是工作条目的草稿（草稿可能是 `null`，快照必然完整）。随便改、改完直接走，什么都不会发生。页面**不挂常驻横幅**——进页面时什么都还没发生，说「会生成新草稿」只是噪音；新草稿真的落库之后才 toast 告知「已基于 v{n} 生成新草稿 / 原版本未改动」。`?v=` 指向不存在的版本 → 「地图版本不存在或加载失败。」。
- **保存才 fork**：第一次保存走 `POST /api/maps/:id/versions/:no/fork`，body 带那一刻的 `editor.toDraft()` → 服务端 INSERT 一条新 maps 行（`root_id` 继承血统），命名「{原名} (自 v{n})」（撞名才追加「副本」序列）→ 客户端 `markSaved` 后 **replace** 到 `/maps/:id/edit`（新行 URL）。replace 必须晚一拍（`setTimeout(0)`），否则未保存保护读到的还是旧 `dirty`，会把自己拦下。
- **fork 态点发布**：先落盘、再提示「已生成草稿 / 请再次点击「发布」」——发布 mutation 创建时绑的是旧行 id，fork 之后闭包已过期。
- **保存按钮在 fork 态恒可用**（v0.7.2）：`canSave` 传 `dirty || forkFrom !== null`。「一进来什么都没改就点保存」是这条动线的核心用法（保存 = 生成新草稿这个动作本身），按 `dirty` 禁用会让它点不动。
- **未保存保护**按 `/maps/` 前缀判断（不只是编辑器路径），这样 replace 到新 URL 时不会被旧 `dirty` 拦。

版本历史面板里的 fork 仍走老行为：不带 `data`，直接用快照复制一份草稿。

> 谜题编辑器有同一套 `?v=` fork 态（v0.7.2，`/puzzles/:id/edit?v={n}`）：进的时候不建行、保存时才 `POST .../versions/:v/fork { data }`，之后 adopt 新行身份并 replace。差异只有一处：谜题 fork 态**不渲染**状态徽标，且**不渲染发布按钮**（`onPublish` 不传即不渲染），要等新草稿真的落库才出现。

## 4. 版本只读预览页 `/maps/:mapId/views`

一张已发布版本的纯画布预览，无编辑能力：

- 头部：← 返回、地图名、`v{n}` 徽标、`n × n` 徽标、「只读预览」。返回键的去向按**来路**决定（v0.7.4）：从编辑器头部「预览」进来（`location.state.from === 'editor'`）时回 `/maps/:id/edit`、标题「返回编辑器」；直接打开 URL（列表点眼睛、版本历史「查看效果」）回地图列表。
- 控件：**平移开关**（手形图标，v0.7.2，**默认打开**、不持久化）、标尺开关（选择持久化）、缩小 / 百分比 / 放大 / 重置视图、主题开关。
- 画布：悬停高亮、缩放（`−` / `+` / 重置视图三个按钮，**没有滚轮缩放**）、平移三条入口并存——平移开关打开后左键直接拖、按住 `Space` 拖、鼠标中键拖（判定收口 `lib/grid.ts` 的 `startsPan`；开关开着时光标 `grab`），与编辑器同一套渲染层集合（不渲染游戏专属层）。
- 加载失败：「地图版本不存在或加载失败。」+ 返回地图列表。

**一条 URL 只由 `:mapId` 决定看什么**（v0.7.1 起，`?v=` 退役）：`maps` 合并后草稿行与版本行都自带 `data`，一个 id 就是一屏内容，再没有「草稿行去血统里找最新版本号」这一步。

| `:mapId` 命中 | 渲染 |
|---|---|
| 版本行 | 该行 `data`（发布时冻结的快照） |
| 草稿行 | 该行 `data`；`null` 时显示「该草稿还没有画布」 |
| 软删版本行 | 照常渲染（读取口不过滤软删，与 fork 源同口径） |

旧路径 `/maps/:id/:versionNo/view` 与 `/editor/:id` 一并注销，不加重定向（本地工具，无外部书签）。

## 5. 数据与接口

### 5.1 草稿结构（`MapDraft` v7）

```ts
{
  version: number;        // 7
  gridSize: number;       // 2 ~ 24
  cells: Record<"x,y", DraftCell>;   // background / item
  regions: DraftRegion[];
  style?: MapStyle;       // 缺省时按 DEFAULT_MAP_STYLE 解析
}
```

`MapDraft` **不包含** `characterSlots`，`MapStyle` **不包含** `linkageColors`——参与者与联动调色板都属于谜题，不在地图里。

画布格子 `DraftCell` 的键：`background`（背景资源引用，`{ assetId, variantId? }`，恒占 1 格）、`item`（物品实例锚点，`{ assetId, variantId?, w, h, scale?, offsetX?, offsetY? }`）、`itemRef`（多格占位引用）。

v0.7.5 的三个展示字段都是**可选**的，缺键 = 恒等（`1 / 0 / 0`），它们本身没有升版本号（v0.7.6 的改名才把 `MAP_JSON_VERSION` 推到 8）：`w` / `h` 是**脚位**（占格、擦除、碰撞），`scale` / `offsetX` / `offsetY` 只是**展示**（等比例倍数、按格偏移，允许画到脚位之外）。三个字段都存在锚点上，跨格物品共享一个变换。

`item.variantId` / `background.variantId` 指向资源的一个**形态**（v0.7.6 之前叫 `formId`，迁移已改写，schema 仍认旧键并归一化）。`item` 的 `w`/`h` 是**落位时**冻结的占格：v0.7.6 起新放置恒为 1，老草稿保留原值。`variantId` 是**可选**的：更早的画布没有这个字段，渲染时回退到资源的首形态；若它指向的形态已被删除，同样回退首形态（`resolveAssetVariant`，全项目唯一判定点）。背景资源也可以有多个形态，背景层放置时把选中形态的 id 写进格子里。

`DraftRegion` = `{ id, name, cells, labelCell?, style? }`。`style` 是 `RegionStyleOverride`
（深 partial：`outline` / `highlight` / `label` 三组各字段可选），**只记与地图级缺省不同的
字段**，全同则整个键缺席；渲染与编辑都走 `resolveRegionStyle(地图级, region.style)` 合并
（v0.7.0）。旧三字段 `color` / `borderWidth` / `fillOpacity` 已删除，迁移见
`20260101000030_v070_region_style.ts`。

`version` 的历史：v0.6.0 由 3 升到 4（`object` → `item`、`itemId` → `assetId`、`objectRef` → `itemRef`），v0.6.1 由 4 升到 5（物品锚点加 `formId`）、再由 5 升到 6（背景引用加 `formId`，背景资源放开多形态），v0.7.0 由 6 升到 7（区域样式三级化 + 区域填充退役），v0.7.6 由 7 升到 8（锚点键 `formId` → `variantId`，迁移 `20260101000035` 逐行改写）。

v0.7.4 的 `style.regionLabel.fontFamily` **没有**再升版本号：它从枚举变成了「字体名」字符串，是一次**放宽** —— 旧的 `system` / `sans` / `serif` / `kai` / `mono` 仍然合法（`fontFamilyStack` 照旧给它们回退链），缺键的旧草稿由 `resolveMapStyle` 补 `system`，写回时自然带上。新写的字体名在老构建里会被枚举拒掉，但那只是「旧版本读不了新草稿」，不是数据损坏，也没有迁移可做。

`GET /api/maps/:id/map` 的响应里草稿可以是 `null`（未初始化）；服务端**不**用 `emptyDraft()` 兜底——兜底会把「还没初始化」伪装成「已有一块默认画布」，初始化弹窗就永远没有出场机会。

### 5.2 接口

前缀是 `/api/maps`。v0.5.9 之前写作 `/api/projects*`，旧路径由服务端 308 重定向到对应新路径（前端已无调用）。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/maps` | 条目列表分页（`MapEntrySummary`；v0.5.8 第三阶段起是**单表查询**，`kind` 由 `version` 列判定，软删行不出现）。**参数 `kind=draft\|version` 可选**：传了只返回该类、`total` 也只算该类（`/maps` 两块各自分页就走这条）；不传是并集口径。两块都跟随 `sort` / `order`，默认 `updatedAt` 倒序 |
| POST | `/api/maps` | 新建地图（**不带画布尺寸**） |
| PATCH / DELETE | `/api/maps/:id` | 改名称 / 描述；删除 |
| POST | `/api/maps/:id/duplicate` | 复制 |
| POST / DELETE | `/api/maps/:id/cover` | 上传 / 移除封面 |
| GET / PUT | `/api/maps/:id/map` | 读 / 写整份草稿。PUT 只收 `{ data }`，**后写覆盖**（不做乐观并发、不会 409） |
| PATCH | `/api/maps/:id/grid-size` | 调整画布尺寸（返回被移除内容的计数）；**草稿为空时它兼任「初始化」** |
| GET / POST | `/api/maps/:id/map/export` · `/import` | 导出 / 导入 JSON |
| POST | `/api/maps/:id/versions` | 发布（请求体可带 `version`，不传 = 血统 `MAX+1`；`.strict()`——旧客户端多传 `notes` 会被明确拒绝；对版本行调用 400「只有草稿可以发布」） |
| GET | `/api/maps/:id/versions` | 血统内全部版本 |
| GET | `/api/maps/:id/versions/:versionNo` | 单个版本详情（软删行 404） |
| POST | `/api/maps/:id/versions/:versionNo/fork` | 派生新工作条目 |
| DELETE | `/api/maps/:id/versions/:versionNo` | 删除版本（**软删**：界面不可见、行保留、号不回收） |

`MapVersionSummary.gridSize` / `PublishedMapVersion.gridSize` 字段**保留**，但从草稿快照 `data.gridSize` 派生，不再来自 DB 列——所以版本历史弹窗、新建谜题对话框一行都不用改。

**`:id` 一律指 `maps.id`**：版本相关端点（`/versions`、`/versions/:no`、`/fork`、`DELETE`）先用它解析血统根，再在血统内按版本号定位，所以传工作条目 id 或版本行 id 都能用（`/maps/:id/views` 同理，见 §4）。

写入口对版本行的护栏：`PATCH` / 画布 `PUT` / `grid-size` / 封面 / `duplicate` → 400「已发布的版本不可修改」；`POST .../versions` → 400「只有草稿可以发布」；通用 `DELETE` 按行类型分流（草稿硬删 / 版本软删）。读取（详情、画布 GET、版本详情）照常允许。

**谜题侧（`/api/puzzles`）与底图有关的两个参数**（v0.7.3）：`PUT /api/puzzles/:id`（保存草稿）与 `POST /api/puzzles/:id/versions/:n/fork` 的请求体都可带 `mapSource: { mapId, versionNo }`。它表达的是「这一次把底图换成这一份已发布版本」——服务端与存量快照的来源相同就直接短路（零查询），不同才去 `maps` 读那份版本、校验方格尺寸一致，再用**它**的画布覆盖 `data.map`。所以底图永远来自服务端读出来的冻结快照，客户端提交的 `data.map` 依旧被无视。谜题版本的画布不跟着地图版本变化（谜题自带副本），这条只在保存那一刻生效一次。

### 5.3 发布校验规则

发布前服务端逐条检查草稿，任一条不过就整批返回（`PUBLISH_VALIDATION_FAILED`），编辑器弹窗逐行列出：

| `rule` | 触发条件 | 文案示例 |
|---|---|---|
| `bounds` | 格子 / 区域坐标越出 `gridSize` | `单元格 (3, 25) 超出边界`、`区域「森林」的单元格 (0, 24) 超出边界` |
| `item_reference` | 引用了不存在的资源 id | `资源 #42 不存在` |
| `object_out_of_bounds` | 多格物品的占位矩形越界 | `物品 #7 (2×3) 越出画布` |
| `region_overlap` | 两个区域占用同一格 | `区域「森林」与「湖泊」在 (3, 4) 重叠` |
| `region_connected` | 区域不是四邻接连通 | `区域「峡谷」不是连通区域` |

草稿为 `null`（未初始化）时更早一道：`400`「请先在编辑器里初始化画布尺寸」。

## 6. 与其他模块的边界

| 边界 | 规则 |
|---|---|
| **谜题编辑器** | 复用同一套画布与信息抽屉，但画布**只读**：工具固定为 `select`、所有写回调是空函数、抽屉传 `readOnly`。地图与谜题共用 `MapLayers` 的绘制，不共用写状态。<br>v0.7.3：谜题的基本信息还装 名称 / 封面（封面在草稿落库后上传）；顶部工具栏多一个「引入新地图」——只接受**同尺寸**的已发布地图版本，换的只是 `data.map`（画布 + 地图名 + 版本号），并顺手摘掉指向旧画布的联动目标，整件事一个撤销步。服务端由 `mapSource` 重新读版本快照，客户端的画布一律被覆盖。<br>v0.7.4：地图编辑器的右侧信息框改成占据空间，谜题编辑器给它传 `layout="overlay"` —— 那边的参与者信息框与谜题基本信息仍是浮层，只改一个反而更不一致。<br>v0.8.6：基本信息抽屉多一块「禁止符号」—— **上传一张图**，代替玩家侧标记排除项时那枚默认的 `×`（左 64px 预览，右「选择图片 / 更换」「移除」；选完立即上传，path 进抽屉草稿，随「保存」一个撤销步写入 `PuzzleDraft.forbiddenSymbol`）。v0.8.7 起这一题**不配就跟随主题**（概览页的「禁止符号」卡片）：解析顺序是「谜题 → 主题 → ×」，抽屉预览画的正是最终会用的那张并注明「跟随主题」；新建谜题不再把主题那份拷进草稿，所以主题换图对跟随的关卡（含已发布的）立刻生效，「移除」就是回到跟随。 |
| **资源模块** | 地图只**引用**资源（`assetId` + `variantId` + 落位 `w`/`h`）。资源改名 / 停用、形态换图 / 换纯色都会实时反映在画布上（外观现查）；落位宽高不会——它在放置时就冻结进锚点了。调色板只取 `isActive` 的资源。形态被草稿引用时不可删除（409）。**背景与物品两类资源都可有多个形态**；v0.7.6 起形态不再有占格，两类资源的唯一差别只剩「背景层一格一格刷、物品层可缩放」。 |
| **角色 / 参与者** | 地图里**没有**参与者。v0.5.0 起角色与联动完全归谜题，所以编辑器左面板只有「资源 / 区域」两个 tab，`EditorTool` 也保留了 `'character'` 成员但不再有入口。v0.6.3 起**连排版也归谜题**：花名册的**列数**是谜题的属性（`PuzzleDraft.rosterCols`，最多 6），行数由它推出；`ParticipantPanel` 在拿到列数时按列排版、面板宽度撑到刚好装下矩阵（≤6 列无横向滚动条，算式含 aside 自己的 1px 分隔线，见 `rosterPanelWidth`），拿不到时退回自动排版。v0.6.3 fix：槽位标号左上角按卡片半径圆角（`PARTICIPANT_SLOT_RADIUS`）；谜题编辑器的「角色」列表在参与者满时默认收起。v0.7.7：谜题编辑器的角色面板头部也有一个刷新按钮（`刷新角色`，重取 `useCharacters({})`），收起成 40px 细条时不渲染 —— 细条放不下第二个按钮，而那时本来就加不进角色了。v0.7.13：角色自己可以带**参与者默认值**（`characters.color` / `display_name`，都可空），在角色页里配；「加入」那一刻抄进槽位的 `themeColor` / `displayNumber`，之后两边互不影响（槽位存的是副本），没配就是白色 + 序号。详见 `docs/v0.7.13.md` §11。 |
| **界面色主题**（浅色 / 深色） | 画布是**内容**，不随浅色 / 深色变：地图背景、资源图、区域轮廓线 / 高亮线 / 标签、标尺与各类框线都用作者设定的颜色。深色下出现「深色外壳 + 浅色画布」是正确结果。 |
| **内容主题**（v0.8.0 的「主题」） | 与上面那条**不是一回事**：这里的主题是资源 / 地图 / 角色 / 谜题的**边界**（`theme_id`），不是界面配色。两处要分清：<br>① 地图属于某个主题，`theme_id` 建行后不可改；画布引用的资源必须同主题（v0.8.0 §8 护栏 1，服务端拦）。<br>② 主题的**地图初始样式**（`themes.data.style`，v0.8.6 前的叫法是「缺省风格」）只在**新建地图那一刻**拷进草稿（§5 的 S3 快照式），之后不追溯。拷的时候**不含方格大小** —— 它随画布尺寸变，是每张图自己的（v0.8.6 §1.3）。编辑器的「基本信息」抽屉底部常驻一行「风格来自主题「X」」（§16.8），差异弹窗给两个反向动作：`应用主题风格`（改本图，写入抽屉草稿）/ `设为主题风格`（改主题，本图成为缺省）。<br>③ 主题卡片的色带取 `themes.data.linkageColors` 前 3–4 色 —— 那是**作者自己的调色板**（引用作品的颜色），不违反「画布不随界面变」，也不给界面新增配色；没有 `linkageColors` 时退回 `muted`，不发明颜色。 |
| **游戏页面** | v0.7.1 起游戏只**引用一条谜题版本行**（`MapGameDetail.map` = 该行自带的画布副本，`puzzle` = 该行的名册 / 调色板），`games.snapshot` 已删。冻结性由「版本行只读」保证：改草稿不影响已上线的游戏，要改就得发布新版本、再部署那个版本。 |
