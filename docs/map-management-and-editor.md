# 地图管理与编辑页 · 功能说明

**文档类型**：功能说明（非需求文档，随代码演进维护）
**适用范围**：`/maps`（地图管理）、`/editor/:projectId`（地图编辑器）、`/maps/:projectId/:versionNo/view`（版本只读预览）
**代码落点**：`packages/web/src/pages/{MapsPage,EditorPage,MapVersionViewPage}.tsx`、`components/{project,editor,map}/`、`stores/editorStore.ts`

---

## 1. 术语与对象模型

| 术语 | 代码 / 字段 | 含义 |
|---|---|---|
| 地图 | `map_projects` 行 | 一个可编辑的画布作品，实际含义是「一个工作条目」 |
| 工作条目 | `MapEntrySummary.kind = 'draft'` | 地图列表里**可编辑**的那一条，同一地图永远只有一条 |
| 版本条目 | `MapEntrySummary.kind = 'version'` | 发布时插入 `map_versions` 的**不可变快照**，只读 |
| 血统 | `map_projects.root_id` | 由同一原型派生出的所有工作条目与版本共享的根 id |
| 草稿 | `draft`（`MapDraft`） | 工作条目当前存的内容，编辑器直接读写它 |
| 发布 | `POST /api/projects/:id/versions` | 把当前草稿快照成一条版本条目 |
| 派生 / fork | `.../versions/:versionNo/fork` | 以某个旧版本为起点**新建**一个工作条目 |

对象关系：

```
root_id = A 的血统
├── 工作条目 A（唯一可编辑，draft 随保存滚动）
│     └── 发布 → 版本条目 v1, v2, v3 …（不可变，累积在同一血统上）
└── 从 v2 派生 → 工作条目 B（root_id 仍是 A）
      └── 发布 → v4（编号取整个血统的 MAX + 1，不是 B 自己的 +1）
```

三条不变式：

1. **发布不覆盖工作条目**。发布只是新增一条版本条目，当前草稿原封不动，作者可以继续改、继续发下一版。
2. **版本号跨血统递增**。`nextVersionNo = MAX(version_no) + 1`，在 `root_id` 范围内算。所以 fork 出来的新条目第一次发布叫 v4 而不是 v1。
3. **版本是不可变快照**。没有「回滚」操作 —— fork 就是「从旧版本开始改」，再加一个回滚等于同一件事的破坏性写法，会覆盖进行中的工作条目。

## 2. 地图管理页 `/maps`

路由别名：`/projects` 会 `replace` 重定向到 `/maps`（旧书签兼容）。页面 `document.title` 为「地图 · 格物」，h1 为「地图」——「工坊」只出现在全局头部的字标后缀，不进这一页。

### 2.1 页面骨架

```
┌─────────────────────────────────────────────────────┐
│ 地图            （副标题：创建、管理并编辑你的地图。）  [新建地图] │
├─────────────────────────────────────────────────────┤
│ [搜索框] [排序▾] [条目类型▾] □按地图归组   [网格|列表] │
├─────────────────────────────────────────────────────┤
│ 卡片网格（默认）或单列列表                            │
├─────────────────────────────────────────────────────┤
│                    第 1 / 3 页 · 共 27 个 [上一页][下一页] │
└─────────────────────────────────────────────────────┘
```

### 2.2 工具栏控件

| 控件 | 取值 | 行为 |
|---|---|---|
| 搜索框 | 文本 | **300ms 防抖**后作为 `keyword` 提交到后端，并把页码重置为 1；匹配名称 |
| 排序 | 按更新时间（默认）/ 按名称 | 后端排序，`order=desc`，切排序时页码重置 |
| 条目类型 | 全部条目 / 只看工作条目 / 只看版本条目 | **纯前端**筛当前页，不改变总数（页脚仍报全量） |
| 按地图归组 | 复选框，默认关 | 把当前页按 `rootId` 排序、同一血统内工作条目在前、版本号降序 |
| 视图 | 网格（默认）/ 列表 | 两套渲染，动作按钮完全相同 |
| 分页 | 每页 **12** 条 | 只有上一页 / 下一页，不跳页 |

「条目类型」和「按地图归组」是**视图层**开关：它们只重排 / 过滤已取回的这一页，因此默认状态下页面与未加这两个开关时逐像素一致。

### 2.3 条目的信息与徽标

| 元素 | 工作条目 | 版本条目 |
|---|---|---|
| 封面 | 方形（`aspect-square`）预览，无封面时显示名称首字 | 同左 |
| 徽标 | `草稿`；发布过则为 `已发布 v{n}` | `v{n}` |
| 描述 | 最多两行截断 | 同左 |
| 副信息 | `n × n` · `地图 v{n}` · `x 分钟前更新` | `n × n` · `该地图共 {n} 个版本` · `发布于 2026-10-17 18:20` |

点击封面：工作条目进入编辑器；版本条目直接走「编辑此版本」（fork）。

### 2.4 工作条目的四个动作

| 动作 | 落点 | 说明 |
|---|---|---|
| 编辑 | `/editor/{projectId}` | 打开画布编辑器 |
| 编辑信息 | 对话框 | 改名称、描述、封面（不能改画布尺寸） |
| 复制 | `POST /projects/:id/duplicate` | 复制出一个新的独立条目 |
| 删除 | `DELETE /projects/:id` | 二次确认：「将同时删除画布上的所有卡片与区域，不可恢复。」 |

### 2.5 版本条目的四个动作

| 动作 | 落点 | 说明 |
|---|---|---|
| 查看效果 | `/maps/{projectId}/{versionNo}/view` | 只读画布预览（见 §4） |
| 新建谜题 | `/puzzles?new={projectId}:{versionNo}` | 跳到谜题页并预选这张地图版本 |
| 编辑此版本 | `POST .../fork` | **不修改**该版本，派生出一个新工作条目 |
| 删除 | `DELETE .../versions/:versionNo` | 确认文案：「该版本条目将被永久删除，引用它的谜题会失去这个画布版本。」 |

版本条目**不能改名、不能换封面**——快照就是快照。

### 2.6 新建地图

| 字段 | 约束 |
|---|---|
| 名称 | 必填，1 ~ 100 字 |
| 描述 | 选填，≤ 500 字 |
| 画布尺寸 n | 整数，**2 ~ 24**，默认 **6** |
| 封面 | 选填，PNG / JPEG / WebP / SVG，≤ 2 MB，预览框 16:10 |

封面是**文件**、其余是 JSON，所以写入分两步：先建行拿到 id，再上传封面。上传失败时对话框**保持打开**并记住已创建的 id，主按钮变成「重试上传」——重试只补传图片，不会建出第二张地图。

### 2.7 编辑地图信息

名称、描述、封面三样。封面有三态：保留 / 更换 / 移除，「移除」是显式动作，保存时才真正删除。画布尺寸在这一层不可改。

### 2.8 状态与边界

- **加载中**：8 个骨架卡。
- **加载失败**：一句错误信息 + 「重试」。
- **空态**按原因分三种：搜索无结果「没有匹配的地图」；只看版本且一条版本都没有「还没有已发布的版本，在地图编辑器里发布一个试试」；其余「还没有地图，创建一个开始吧」。版本空态**不给**「新建地图」按钮——新建出来的是地图，不是版本，在那个筛选下点了也看不见。
- **删除进行中**：按钮转圈、弹窗禁止 Esc 关闭。

## 3. 地图编辑器 `/editor/:projectId`

独立全屏路由，不在 `AppShell` 内——所以没有全局头部，主题开关挂在编辑器自己的工具栏上。

### 3.1 布局

```
┌──────────────────────────────────────────────────────────────┐
│ ← [名称] [草稿 / 已发布 vN] [未保存]  🌗 │ 导入 导出 基本信息 版本历史 │ 保存 发布 │
├───────────┬──────────────────────────────────────────────────┤
│ 物品 | 区域 │                                                  │
│           │                    画布                          │
│  背景层/物体层│                                          [信息抽屉]│
│  搜索物品   │        ┌─ 底部浮动工具条 ─┐                     │
│  三列缩略图 │        └──────────────────┘                     │
└───────────┴──────────────────────────────────────────────────┘
                                              [地图基本信息抽屉] →
```

### 3.2 顶部工具栏

| 控件 | 说明 |
|---|---|
| ← 返回 | 回地图列表（未保存会先被拦，见 §3.15） |
| 名称 | 只读展示，超长截断 |
| 状态徽标 | `草稿` / `已发布 v{n}` |
| `未保存` 徽标 | 仅在 dirty 时出现，**本身就是快捷键**：点一下立即保存 |
| 主题开关 | 三态（跟随系统 / 浅色 / 深色） |
| 导入 / 导出 | 见 §3.14 |
| 基本信息 | 开合「地图基本信息」抽屉；打开时会清掉当前的格子 / 区域焦点 |
| 版本历史 | 见 §3.13 |
| 保存 | 实心主按钮，**未 dirty 时置灰** |
| 发布 | 描边次按钮，**不因 dirty 置灰**（是否要「先存再发」由确认弹窗按 dirty 分形态处理） |

### 3.3 左面板

宽 280px，两个 tab：

**物品**
- 图层切换：`背景层` / `物体层`（对应 `EditorLayer.background` / `object`）。
- 搜索：匹配物品**名称或 code**。
- 三列缩略图；点选即选中，再点同一项取消。选中后底部提示「已选中物品，点击画布放置；再次点击可取消」。
- 列表只显示 `category` 等于当前图层的物品，因此背景层里看不到物体类物品。
- 物品来源是 `isActive: true` 的物品，停用的不出现在调色板里。

**区域**
- 顶部「区域工具 (R)」按钮，等价于切到区域工具。
- 下方是区域列表：名称、`{n}格`、编辑、删除。

面板的可交互性随工具变化：区域工具激活时整块半透明且不可点（避免中途换物品打断选区）；橡皮擦时降至 50% 不可点。

### 3.4 画布工具

| 工具 | 快捷键 | 行为 |
|---|---|---|
| 选择 / 放置 | `V` | 单击选格、点区域标签选区域；选中物品后单击画布放置 |
| 区域选择 | `R` | 拖框（矩形）或涂抹（自由笔刷）圈格子，形成区域草稿选区 |
| 橡皮擦 | `E` | 按 **物件层 → 背景层** 的顺序逐层清除；物件层是单格物品还是多格物品按其占位展开 |

放置规则：
- **背景层只接受 `category === 'background'` 的物品**。层不对时提示「该物品不能放在当前图层」，不写入。
- 物件层接受任意类别（`canStand = false` 的物品也允许，只是该格会被标成不可站立）。
- 多格物品按整体占位矩形落位。

视图操作：
- 平移：拖画布外的空白区、或按住 `Space` 拖、或鼠标中键拖。
- 缩放：底部工具条按钮，或 **`Ctrl/Cmd + 滚轮`**（普通滚轮不缩放，避免和页面滚动抢），范围 `0.25 ~ 4`、步进 `0.1`，缩放锚点跟随指针。
- 没有独立的「手型工具」按钮——拖空白区就够了。

### 3.5 底部浮动工具条

从左到右：

1. 三个工具按钮（当前工具高亮）
2. **仅区域工具时**出现：矩形 / 自由笔刷
3. `物品` 开关（收起 / 展开左面板）
4. 标尺开关（选择会存进 `localStorage['loredoku.editor.ruler']`，下次打开沿用）
5. `n×n` 画布尺寸按钮 → 打开「调整画布尺寸」对话框
6. 缩放组：`−` / 百分比（点击重置 100%）/ `+` / 适应画布
7. 撤销 / 重做

> 缩放的 `−` `+` 改的是**查看比例**，不改方格大小；方格大小在「基本信息」里。

### 3.6 地图基本信息抽屉

从右侧滑出的表单，宽 320px，四段。**它是一个表单**：所有控件改的是本地草稿，只有按「保存」才落到画布与草稿上；「取消」/ `×` / 切到别的焦点在 dirty 时会先问一句。

| 段 | 字段 | 取值 | 说明 |
|---|---|---|---|
| 画布 | 画布尺寸 | 2 ~ 24 格 | 与「调整画布尺寸」是同一个量；缩小会让越界内容被移除 |
| | 方格大小 | 90 ~ 240 px，或**自适应** | 自适应时按窗口算；手动指定后窗口变化不再改变它。右侧 ↺ 恢复自适应 |
| 线条 | 画布外框 | 线宽 1~12、颜色 | 画在最外圈之外，与格内内容几何不重叠 |
| | 网格分隔线 | 线宽 1~12、颜色 | `n × n` 只有 `n−1` 条横线 + `n−1` 条竖线 |
| | 鼠标光标框 | 线宽、颜色、阻挡色、阴影环色 | 跟随指针，画布最高层 |
| | 操作光标框 | 线宽、颜色、外扩距离 0~8 | 固定在当前操作格，画在最外侧 |
| | 区域轮廓线 | 线宽 4~12、颜色 | 改线宽会同步写入所有现存区域，并作为新建区域的缺省值 |
| | 区域高亮线 | 线宽 1~12、颜色 | 悬停 / 联动激活时出现，连续闭合，结束时 150ms 淡出 |
| 区域标签 | 字体大小 / 描边大小 | 9~48 / 0~12 | 「描边 + 填充」绘制，深浅底都可读 |
| | 字体颜色 / 描边颜色 | 颜色 | |
| | 高亮字体大小 / 高亮字体颜色 / 高亮描边颜色 | 同上 | 区域被悬停或激活时切换成这一套 |
| 标尺 | 文本大小 | 9~32 px | 基准值，随方格尺寸等比缩放；操作格所在行列 +2px |
| | 文本到地图的间距 | 0 ~ 32 px | 同时参与标尺条厚度的计算 |

所有数值都是「基准值」：随方格尺寸等比缩放，**不随查看比例（zoom）变化**。

**首次进入自动落盘**：若这张地图的草稿里 `style == null`（从未存过基本信息），编辑器在首次打开时把「解析后的默认值 + 画布尺寸」整体写一次，并 toast「已保存默认地图基本信息」。这样「看到的」和「存着的」从此是同一份；且已 dirty 时不会触发（不会替用户提交进行中的修改）。

### 3.7 区域

**圈选**：区域工具 → 矩形拖框或笔刷涂抹 → 底部出现选区条（显示已选格数、「起点已锚定」状态、清空、确认、取消）。

**两道校验**：
1. 确认时若格数为 0：toast「请先选择至少一个格子」。
2. 若选区不连通（四邻接）：弹「区域必须是相连的方格」，停在选区上让作者改。

**创建 / 编辑对话框**：

| 字段 | 约束 |
|---|---|
| 区域 ID | 必填，字母 / 数字 / 下划线，≤ 64，全局唯一；新建时自动生成 `rg_xxxxxxxx` |
| 区域名称 | 必填，≤ 100 字 |
| 区域颜色（填充） | 7 个预设 + 自定义取色器 |
| 边界线宽 | 4 ~ 12，缺省取「基本信息」里的区域轮廓线宽 |
| 填充透明度 | 0 ~ 1，步进 0.01 |
| 冲突处理 | **仅新建且与现有区域有重叠时出现**：`覆盖`（从其它区域移除冲突格）/ `跳过`（冲突格不入新区） |

边界线**颜色**不在这里改，由「基本信息 → 区域轮廓线」统一控制；区域自己的 `color` 只用于填充。

**删除**：二次确认「删除区域「{名称}」？区域会从草稿中移除。」删除可撤销。

### 3.8 信息抽屉

右侧第二条抽屉（与基本信息抽屉互斥），点格子或区域标签时打开：

- **格子分支**：坐标（`C3 R5`）、背景层物品（缩略图 + 名称 + #id）、物件层物品（缩略图 + 名称 + 占位 `w×h`）、所在区域信息、快捷操作「清空本格」「清空物件层」。
- **区域分支**：颜色点 + 名称 + 「包含 N 格」+ 边界线宽 + 填充百分比，以及「编辑」「定位」「删除」。
- 无选中时一句引导：「在画布上点击格位或区域标签查看详情」。
- 收起时右侧留一条 8px 的窄条，点它展开。

### 3.9 撤销 / 重做

- 撤销栈上限 **50** 步，存的是「画布快照」：格内容 + 区域 + 图层样式 + 画布尺寸。
- 样式（基本信息）、区域增删改、放置、擦除、清空、改尺寸**都在栈内**。
- 视图状态（缩放、平移、当前工具、选中）**不进栈**——撤销不会把画面甩回别处。
- 快捷键 `Ctrl/Cmd+Z` / `Ctrl/Cmd+Shift+Z`，与底部按钮等价。

### 3.10 保存

- **单一写入口**：工具栏的「保存」、`未保存` 徽标的点击、`Ctrl/Cmd+S`、基本信息抽屉的「保存」、发布前的「先保存」、调整尺寸前的「先保存」——全部走同一个函数，写的是**整份草稿**。所以不会出现「工具栏保存了但基本信息没保存」这种分歧。
- 保存中有全屏遮罩；请求返回后遮罩再保留 150ms 做淡出，避免闪烁。
- 保存成功即清 dirty，并把返回的 `currentVersionNo` / `status` 写回徽标。
- **发布后不会重建画布**：发布的响应只更新版本徽标；只有草稿的 `updatedAt` 真的变了才重新初始化编辑器（重新初始化会重置缩放与平移）。

### 3.11 调整画布尺寸

入口：底部工具条的 `n×n` 按钮，或基本信息里的「画布尺寸」。

- 滑块 + 数字输入（2 ~ 24，失焦时取整并夹到范围内）。
- 中间是**新旧尺寸对照预览**：保留的格子绿色、将被裁掉的格子红色。
- 下方列出「将被移除」清单：越界物品（名称 + 占位 + 坐标）、部分格子越界的区域。
- 确认时：先保存（若 dirty）→ 再请求后端裁剪 → toast 报告移除数量（背景 x、物体 y、区域 z），没有移除则只说「画布已调整」。

### 3.12 发布

流程：

1. 点「发布」→ 弹「发布为 v{n}？」。句子明确说：会新增一个带 v{n} 标记的条目，**当前工作条目不会被覆盖**，可以继续编辑并发下一版。
2. 可选填发布备注（例：「修正了区域边界」）。
3. dirty 时按钮文案为「保存并发布」，并提示「有未保存的修改，将先保存再发布」；否则「确认发布」。
4. 后端校验（见 §5.3）不通过 → 弹「无法发布」，逐条列出问题。
5. 成功 → 弹「已发布 v{n}」，两个去处：「查看该条目」（回地图列表）/「预览」（打开只读预览页）。

### 3.13 版本历史

弹窗列出**整个血统**的版本，每行：`v{n}`、是否「当前」、发布时刻、备注、`n×n`、参与者 / 区域 / 物体计数。行操作：

- **查看效果** → 只读预览页。
- **编辑此版本** → fork 出一个新工作条目（标题提示「以此版本为起点新增一个条目」），完成后关闭弹窗。
- **删除** → 删除该版本行。

**没有「回滚」**（理由见 §1 不变式 3）。

### 3.14 导入 / 导出 JSON

- **导出**：把当前草稿序列化成 `MapDraft` v3 下载，文件名 `{地图名}-{id}.json`。
- **导入**：读文件 → `mapDraftSchema`（`.strict()`）校验 → 二次确认「导入会覆盖当前画布内容，导入后可通过撤销回退」→ 写入。
- **旧版文件明确拒绝**：v2 及更早的草稿带 `characterSlots` 或 `style.linkageColors`。因为 schema 是 strict 的，静默丢弃这两块会让人以为参与者导入成功了，所以单独提示「该 JSON 是旧版（含参与者 / 联动主题色），请先移除这两部分，或改用导入到谜题」。
- 导入后**不自动保存**，仍可撤销。

### 3.15 未保存保护

- **应用内跳转**（返回、点导航、改地址）由路由 blocker 拦下，弹确认。
- **刷新 / 关标签页**由 `beforeunload` 拦下。
- **切换焦点**（点格子、点区域标签、开基本信息抽屉）不丢内容，但若基本信息抽屉里有未保存修改会先弹「保存 / 放弃」。
- **Esc 的优先级**：先关基本信息抽屉（dirty 时先问），再清格子 / 物品 / 区域焦点。

### 3.16 快捷键

| 键 | 作用 |
|---|---|
| `Ctrl/Cmd + S` | 保存 |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` | 重做 |
| `Ctrl/Cmd + 0` | 视图居中 |
| `Space`（按住） | 平移预备（配合拖拽） |
| `Esc` | 逐级退出（见 §3.15） |
| 方向键 | 移动格子选中 |
| `V` / `R` / `E` | 选择 / 区域 / 橡皮擦 |
| `Delete` / `Backspace` | 擦除当前选中格 |

**焦点在输入框 / 文本域 / contenteditable 内时全部不触发**——所以在「发布备注」里按 `S` 不会误保存。

## 4. 版本只读预览页 `/maps/:projectId/:versionNo/view`

一张已发布版本的纯画布预览，无编辑能力：

- 头部：← 返回、地图名、`v{n}` 徽标、`n × n` 徽标、「只读预览」、发布备注。
- 控件：标尺开关（选择持久化）、缩小 / 百分比 / 放大 / 重置视图、主题开关。
- 画布：悬停高亮、缩放（`−` / `+` / 重置视图三个按钮，**没有滚轮缩放**）、`Space` 或鼠标中键拖拽平移，与编辑器同一套渲染层集合（不渲染游戏专属层）。
- 加载失败：「地图版本不存在或加载失败。」+ 返回地图列表。

## 5. 数据与接口

### 5.1 草稿结构（`MapDraft` v3）

```ts
{
  version: number;        // 3
  gridSize: number;       // 2 ~ 24
  cells: Record<"x,y", DraftCell>;   // background / object
  regions: DraftRegion[];
  style?: MapStyle;       // 缺省时按 DEFAULT_MAP_STYLE 解析
}
```

`MapDraft` **不包含** `characterSlots`，`MapStyle` **不包含** `linkageColors`——参与者与联动调色板都属于谜题，不在地图里。

### 5.2 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/projects` | 条目并集分页（`MapEntrySummary`） |
| POST | `/api/projects` | 新建地图 |
| PATCH / DELETE | `/api/projects/:id` | 改名称 / 描述；删除 |
| POST | `/api/projects/:id/duplicate` | 复制 |
| POST / DELETE | `/api/projects/:id/cover` | 上传 / 移除封面 |
| GET / PUT | `/api/projects/:id/map` | 读 / 写整份草稿 |
| PATCH | `/api/projects/:id/grid-size` | 调整画布尺寸（返回被移除内容的计数） |
| GET / POST | `/api/projects/:id/map/export` · `/import` | 导出 / 导入 JSON |
| POST | `/api/projects/:id/versions` | 发布 |
| GET | `/api/projects/:id/versions` | 血统内全部版本 |
| GET | `/api/projects/:id/versions/:versionNo` | 单个版本详情 |
| POST | `/api/projects/:id/versions/:versionNo/fork` | 派生新工作条目 |
| DELETE | `/api/projects/:id/versions/:versionNo` | 删除版本 |

### 5.3 发布校验规则

发布前服务端逐条检查草稿，任一条不过就整批返回（`PUBLISH_VALIDATION_FAILED`），编辑器弹窗逐行列出：

| `rule` | 触发条件 | 文案示例 |
|---|---|---|
| `bounds` | 格子 / 区域坐标越出 `gridSize` | `单元格 (3, 25) 超出边界`、`区域「森林」的单元格 (0, 24) 超出边界` |
| `item_reference` | 引用了不存在的物品 id | `物品 #42 不存在` |
| `object_out_of_bounds` | 多格物品的占位矩形越界 | `物品 #7 (2×3) 越出画布` |
| `region_overlap` | 两个区域占用同一格 | `区域「森林」与「湖泊」在 (3, 4) 重叠` |
| `region_connected` | 区域不是四邻接连通 | `区域「峡谷」不是连通区域` |

## 6. 与其他模块的边界

| 边界 | 规则 |
|---|---|
| **谜题编辑器** | 复用同一套画布与信息抽屉，但画布**只读**：工具固定为 `select`、所有写回调是空函数、抽屉传 `readOnly`。地图与谜题共用 `MapLayers` 的绘制，不共用写状态。 |
| **物品模块** | 地图只**引用**物品（`itemId` + 落位宽高）；物品改名 / 停用会实时反映在画布上。调色板只取 `isActive` 的物品。 |
| **角色 / 参与者** | 地图里**没有**参与者。v0.5.0 起角色与联动完全归谜题，所以编辑器左面板只有「物品 / 区域」两个 tab，`EditorTool` 也保留了 `'character'` 成员但不再有入口。 |
| **主题** | 画布是**内容**，不随浅色 / 深色变：地图背景、物品图、区域填充、标尺与各类框线都用作者设定的颜色。深色下出现「深色外壳 + 浅色画布」是正确结果。 |
| **游戏页面** | 游戏读的是**版本快照**（`MapGameSnapshot`），不是工作条目的草稿。所以改草稿不会影响已上线的游戏，必须发布新版本并在谜题里改用该版本。 |

## 7. 已知不一致（待裁定）

梳理时发现的、代码与文案/直觉不符的地方，如实记录，未在本次改动中处理：

| # | 现象 | 说明 |
|---|---|---|
| 1 | 新建地图对话框写「创建后画布尺寸（n × n）不可修改」，但编辑器底部工具条提供「调整画布尺寸」 | 该文案是「创建时确定初始值」时代的残留。实际行为是：**创建与编辑信息时不能改，进入编辑器后可以改**。 |
| 2 | 版本历史弹窗的说明固定为「当前工作条目：草稿（未发布）」 | 工作条目发布过之后，这句与实际状态（已发布 v{n}）不符。 |
| 3 | 「条目类型」筛选与「按地图归组」只作用于当前页 | 分类后可能出现「只看版本条目，本页 3 条，页脚却写共 27 个」。默认状态（全部 / 不归组）不受影响。 |
