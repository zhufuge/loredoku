## §1 问题：竖屏下大棋盘只有左上角看得见

v0.10.0 把三栏改成了「上抽屉 / 中棋盘 / 下横条」，棋盘终于有了整屏宽度。但格子大小
仍走 `computeCellSize` 那套**桌面**算法：

```
ideal = min( 按宽度算的格子, 按高度算的格子 )   → 夹在 32 ~ 240
```

24×24 的棋盘在 375 宽里按宽度只能分到 ~12px 一格，撞上 32px 的下限后棋盘变成 864px 宽
——屏幕里只露出左上角，要看到别处只能靠拖动。

`docs/v0.6.2.md:15` 当初给大棋盘配「放大后能拖到角落」正是为了解决这个；但拖拽靠
`pointerdown` 的**中键 / 空格 + 左键**，触屏两样都没有。改前实测（375×812）：

| 关卡 | gridSize | 棋盘边长 | 结果 |
|---|---|---|---|
| `puzzle-the-treasure-hunt` | 24 | 864 | 只看得到左上角 |
| `puzzle-outdoor-painting` | 6 | 660 | 超出视口 285px |
| `puzzle-dao` | 2 | 236 | 刚好 |

## §2 竖屏按宽度铺满

### 2.1 判定：窄**且**竖着

```ts
export const PORTRAIT_BREAKPOINT = 768;          // Tailwind 的 md

export function isPortraitViewport(width, height): boolean {
  if (!Number.isFinite(width) || !Number.isFinite(height)) return false;
  if (width <= 0 || height <= 0) return false;
  return width < PORTRAIT_BREAKPOINT && height > width;
}
```

两个条件缺一不可：

- **只看宽度不够**。手机横过来（740×360）宽度也在 768 以下，但那时受限的是**高度**，
  按宽度铺满会把棋盘顶出上下边；而且横屏下视图簇仍然在（`max-md` 不成立？成立 ——
  但 `portrait` 不成立），玩家自己调得回来。
- **不用 `matchMedia('(orientation: portrait)')`**。`testing/matchMedia.ts` 那个桩的
  `matches` 恒等于「是否深色」、不认 query —— 一旦用它判定，整条分支在测试里失真。
  宽高比是同一件事，而且是个纯函数，好测。

判定量的是 **`window`** 而不是画布容器：CSS 那半边（`portrait:max-md:hidden`）判的就是
窗口，两边必须是同一个条件，否则会出现「按钮收起来了、棋盘还按桌面排」这种半吊子状态。
`PORTRAIT_BREAKPOINT` 是两边共同的出处。

### 2.2 算法：`computeWidthFitCellSize`

```ts
export const PORTRAIT_MIN_CELL_SIZE = 8;

export function computeWidthFitCellSize({ width, gridSize, insets, gap = BORDER_WIDTH, max = MAX_CELL_SIZE }) {
  const available = Math.max(0, width - insets.left - insets.right);
  const share = (available - (gridSize - 1) * gap) / gridSize;
  return Math.max(PORTRAIT_MIN_CELL_SIZE, Math.min(max, Math.floor(share)));
}
```

与 `computeCellSize` 的三处差别都是有意的：

| | 桌面那套 | 竖屏这套 | 为什么 |
|---|---|---|---|
| 约束轴 | 宽高取小 | **只看宽度** | 竖屏要「一屏看全宽」；为了塞进高度把棋盘缩成一条缝更糟 |
| 下限 | `MIN_CELL_SIZE` 32 | `PORTRAIT_MIN_CELL_SIZE` 8 | 24×24 在 375 宽上只有 ~12px 一格，守 32 就必然溢出 |
| 取整 | `Math.round` | `Math.floor` | 宁可少半像素，也不让棋盘比可用宽度多出一线 |

`extraMargin` 在竖屏下传 0：桌面那圈 `EXTRA_MARGIN`（24）是画面呼吸，375 宽上左右各
留 40 等于白扔 80 像素 —— 足够再放一整列。

### 2.3 纵向：贴住上边，不是居中

`centeredPan` 在「棋盘比可视高度还高」时会把上下两头各切掉一块，顶上那截**永远够不着**。
竖屏已经没有平移手段了，所以换成 `topAlignedPan`：横向居中，纵向装不下时贴住 `insets.top`，
至少保证「第 1 行看得见」。

### 2.4 竖屏下不听地图样式里的 `cellSize`

`effectiveCellSize(autoCellSize, style)` = `style.cellSize ?? autoCellSize` —— 作者在
地图样式里填了格子大小就用他的。这在桌面是对的，但竖屏下会把「按宽度铺满」整个抵消：
`puzzle-the-treasure-hunt` 的地图样式写着 `cellSize: 36`，24×36 = 864px，正是要消灭的那个
数。所以竖屏下直接取 `autoCellSize`：

```ts
const cellSize = portraitFit ? autoCellSize : effectiveCellSize(autoCellSize, style);
```

横屏与桌面一个字都没动。实测 12 关的 `puzzle.style.cellSize` 全是 `null`（填了值的是
`map.style.cellSize`，属于作品内容），所以这条在现有数据上不会被触发 —— 但代码不能假设。

## §3 收掉视图簇与标尺

### 3.1 做法：纯 CSS，不做条件渲染

右栏那簇（放大 / 百分比 / 缩小 / 重置视图 / 显示 / 隐藏标尺）追加一个类：

```tsx
'portrait:max-md:hidden'
```

`mt-auto` 与 `border-t` 都留着 —— `GamePage.test.tsx` 的「右栏布局（v0.9.0 §17）」断言
`toolbar().lastElementChild.className` 含 `mt-auto`，能查到那四枚 `button[aria-label=…]`
和 `100%` 文本；「锁定态四枚都 disabled」那条也指着它们。隐藏用的是 CSS，元素仍在树里，
这些断言原样成立。

标尺条（`MapRulerStrips`）跟着一起不画：开关都收起来了，还留 28px 的刻度边，等于让玩家
为一条关不掉的边付宽度。它在 `fit` 里靠 `showRulers && !portrait` 参与 inset 计算，渲染时
用 `showRulers && !portraitFit`。

### 3.2 为什么不是条件渲染

- **媒体查询才是这件事的真源**。转屏 / 拖窗口时 CSS 立刻生效，不必等一次 `fit` 跑完再
  React 重渲染 —— 条件渲染会有「棋盘已经按宽度排了、按钮还在」的一帧。
- **按钮留在树里还有用**。无障碍工具与既有测试仍拿得到它们；隐藏 ≠ 消失。

## §4 自动补出的 `×`：由中间向四周依次浮现

### 4.1 问题：三十个 `×` 同时出现，眼睛读成「屏幕闪了一下」

放下一个头像，程序会沿它的整行整列补上 `×`。24×24 的盘上最多一次补 46 格，它们是在
同一次 `commit` 里写进 board 的 —— React 一次性渲染，浏览器一次性上屏。v0.9.8 之前
这些 `×` 是**静默出现**的（那一版刻意把入场动效收给了悬停的那一枚），所以没人抱怨；
但棋盘一旦按宽度铺满（§2），`×` 的尺寸也跟着变小、数量感更强，「同一帧里长出一圈黑点」
就更像故障而不是反馈。

### 4.2 做法：三件事分开做

| 层 | 改动 | 为什么在这一层 |
|---|---|---|
| 次序 | `autoForbiddenCells` 按曼哈顿距离排序 | 它本来就是「算出要补哪些格」的那个函数，次序是它输出的一部分 |
| 波次 | `autoForbiddenWavePlan` 把 key 换算成环号 | 落子之前就要知道有哪些格，不能等 `placeParticipant` 返回 |
| 动画 | `.forbidden-wave` / `-alt` + 行内 `animation-delay` | 延迟是每格一个数，只能走行内样式 |

```ts
// lib/gamePlacement.ts
cells.sort((a, b) => a.distance - b.distance || 列差 || 行差);
export function forbiddenWaveRing(key, origin) { /* 曼哈顿距离 */ }
export function autoForbiddenWavePlan(input): Array<{ key; ring }> | null {
  if ((input.variant ?? 'number') !== 'image') return null;
  return autoForbiddenCells(input).map((key) => ({ key, ring: forbiddenWaveRing(key, origin) }));
}
```

同一环内再按「上→下、左→右」定序，纯粹是为了**确定性**：同样的棋局每次都得是同一个
次序，否则测试没法钉，人眼也会在两个方向上看出不同的疏密。

### 4.3 为什么在落子之前算

`placeParticipant` 收 state、回 state，**不回「这一手新增了哪几格」**。要拿到那个信息，
要么改纯函数签名（会让 20 多条既有用例跟着动），要么在调用处用同一份输入再算一遍。
选了后者：`autoForbiddenCells` 是纯函数、输入完全相同，算出来的次序与真正落盘的一致 ——
`gamePlacement.test.ts` 里那条「波次计划与真正落盘的格子完全一致」就是钉这件事的。

### 4.4 节奏

| 常量 | 值 | 来历 |
|---|---|---|
| `GAME_FORBIDDEN_WAVE_STEP_MS` | 45 | 24 格最远 23 圈 = 1035ms。再快就成「雾一样整体浮出来」，再慢 24×24 要等近两秒 |
| `GAME_FORBIDDEN_WAVE_MS` | 1200 | 末圈延迟 + 动画时长 + 余量，到点把整张表清空 |

动画本身是 `opacity: 0 → 1` 配上 `scale: 0.55 → 1.06 → 1`，`--motion-base`（180ms）。
`both` 是必须的：延迟期间停在第一帧（透明），否则会先按终态闪一下再缩回去。

**两支同名动画**（`.forbidden-wave` / `.forbidden-wave-alt`）的理由与 v0.9.8 那两支
`forbidden-pop` 相同：连着放两位时，若每次都挂同一个类名，浏览器认为 `animation-name`
没变、不重播；换 React `key` 会重挂节点，`<img>` 有一帧空白。

### 4.5 `prefers-reduced-motion`

那条媒体查询里的 `*` 只压 `animation-duration`，**不动 `animation-delay`** —— 所以在这里
单独补了一条 `animation-delay: 0ms !important`（`.clue-note` 当年踩的是同一个坑）。
不补的话，「减少动态效果」的用户会看到：一瞬间全部出现，实则全都还在等自家的延迟。

## §5 竖屏重排：头部一行、棋盘、题面与名册、工具栏

### 5.1 问题：v0.10.0 的抽屉在半屏被棋盘吃光之后没意义了

v0.10.0 把左栏折成一个可开合的抽屉，理由是「375 宽的屏上 256px 的名册会把棋盘挤没」。
但 §2 让棋盘按宽度铺满之后，竖屏的纵向分配变成了：头部 + 棋盘 + 抽屉按钮 + 底部工具栏
—— 抽屉一打开棋盘只剩 305 高，收起时名册又完全看不见。玩家要边看线索边落子，这个折中
不成立。

### 5.2 做法：`display: contents` + `order`，DOM 一个节点都不搬

左栏 `<aside>` 在窄屏下变成 `max-md:contents` —— 它自己不再生成盒子，三个孩子（头部块、
题面、名册）直接成为外层 `flex flex-col` 的成员，于是只用 `order` 就能排出：

| order | 谁 |
|---|---|
| 1 | 头部（返回 / 标题 / 时间 / 主题） |
| 2 | 棋盘 `<main>` |
| 3 | 题面 + 名册（`max-h-[38svh]`、整块 `overflow-y-auto`） |
| 4 | 底部工具栏（四枚工具，横排） |

**为什么不动 DOM**：

- 右栏必须仍是 `querySelectorAll('aside')` 的最后一个（v0.9.0 §17 的用例钉着），左栏必须
  仍是第一个、且 `style.width` 必须还是 `rosterPanelWidthFor` 算出的那串像素（v0.6.3 的
  用例钉着）。搬节点会把这两条一起打破。
- `ParticipantPanel` 与谜题编辑器、作品预览共用。改结构等于同时改那两处的排版。

`display: contents` 的代价是那个盒子消失了：左栏那层 `CheckScrim`（核对时盖住左栏的
遮罩）没了依附，窄屏下补 `max-md:hidden` 收掉；指针锁定改由面板容器自带的
`pointer-events-none` 负责。

### 5.3 头部收成一行

窄屏下标题块变成 `flex items-center gap-2`，里面几样按 `order` 排：返回 `1`、标题 `2`、
时间 `3`、描述图标 `4`、主题 `5`。第一行那个 `<div>` 自己也 `max-md:contents`，否则它会
独占一行。`BrandLogo` 窄屏隐藏 —— 有棋盘、有标题，品牌位让给标题。

### 5.4 卡片横过来：左头像，右上名称，右下线索，每行固定 2 张

`ParticipantPanel` 新增 `compactPortrait?: boolean`（只有游戏页会传），它做四件事：

1. `layout` 直接 `deriveLayout(slots.length, 2)` —— 谜题配的 `rosterCols` 在窄屏没有意义，
   2 张卡就占满屏宽。
2. 根 `<aside>` 去掉内联 `width`、改成 `w-full flex-1`；矩阵轨道从固定 `110px` 换成
   `repeat(2, minmax(0, 1fr))`，`minWidth: max-content` 也去掉（弹性轨道下它会撑溢出）。
3. 卡片**不搬 DOM，只换网格**：`grid grid-cols-[auto_minmax(0,1fr)] grid-rows-[auto_auto]`，
   头像 `col-start-1 row-span-2`，名称 `col-start-2 row-start-1`，线索
   `col-start-2 row-start-2`。桌面那套 `flex flex-col items-center` 原样不动。
4. 头像从 94px 收到 `COMPACT_AVATAR_SIZE = 44`，左内边距 20px 让开序号徽标 —— 放大到 94
   会把右边两行字挤成一道竖缝。

## §6 竖屏：去掉地图阴影，描述挪进弹框

### 6.1 不要地图阴影

画布纸片那圈右下硬影出自 `lib/mapStyle.ts` 的 `canvasShadowStyle(style)`（`boxShadow:
${offset}px ${offset}px 0 rgba(...)`，`CANVAS_SHADOW_ALPHA = 0.3`），返回的对象被摊进画布
底色层的 `style`，`CHECK` 与缩放都跟着它走。

竖屏下**不展开它**（`...(portraitFit ? null : canvasShadowStyle(style))`），只改游戏页这
一处调用：

- 这个函数被四个地方调用（游戏页、作品预览、地图预览、编辑器画布），只有游戏页的竖屏
  是这个用例。
- 更关键的是 `lib/mapStyle.test.ts` 钉着两条 `boxShadow` 字面量（`'36px 36px 0 rgba(0, 0,
  0, 0.3)'`、`'48px 48px 0 rgba(47, 42, 36, 0.3)'`）—— 给函数加一个 `enabled` 参数会让
  这两条变成「传了 false 的时候刚好不返回」，测的就不是那个函数本身了。**在调用处决定
  展不展开**，函数保持纯的。

理由不是「阴影不好看」：桌面那圈投影说的是「一张纸摆在桌上」。棋盘按屏宽铺满之后，纸比
视口窄不了几像素，右下那圈影只会从格子和边框的缝里露出一道脏边 —— 桌上没有桌沿可投。

### 6.2 描述改挂头部图标的弹框

`GameBrief` 新增可选 `hideDescription?: boolean`：只画线索、不画描述，并且早退条件从
「描述与线索都空」改成「该画的都空」。游戏页竖屏传 `portraitFit`。

触发入口是头部一行里那枚 `FileText` 图标（`aria-label="谜题描述"`，`max-md:order-4`），
**只在 `portraitFit && puzzleDescription.trim().length > 0` 时渲染** —— 没有描述就不挂一
枚点开是空卡的按钮。弹框复用 `components/ui/dialog.tsx` 的 `Dialog`（它自带
`onInteractOutside` 的 `preventDefault`，点遮罩关不掉，符合仓库约定），正文用
`whitespace-pre-wrap` + `max-h-[60svh] overflow-y-auto`，**不再 `line-clamp-3`** —— 弹框
就是为了读全文。

**为什么描述搬走、线索留下**：描述是开局的背景说明，读一遍就够；线索是解题时要反复对照
的。竖屏一屏只够放棋盘 + 名册，把只在开头有用的一段固定占掉高度不划算。

桌面端这条路径整个不生效：`portraitFit` 恒 `false` ⇒ 描述仍在面板里、图标不渲染。

## §7 竖屏留白与工具按钮

### 7.1 四边留白：`portraitInsets()`

第二批之后，竖屏的棋盘高度仍是「可用高度 − 桌面那圈 `CANVAS_PADDING + EXTRA_MARGIN`」算出来
的；第四批把留白改成竖屏自己的一套：

```ts
export const PORTRAIT_MARGIN_X = 8;
export const PORTRAIT_MARGIN_Y = 12;
```

- **左右 8**：375 宽的屏上每 8px 就是一整列格子，桌面那 40px 等于白扔两列半。
- **上下 12，比左右大 4**：棋盘上边贴着标题栏、下边贴着题面面板，四面一样宽会读成「两块
  拼在一起」；但也不能更多 —— 竖屏一屏 812 高，上下多给的每一像素都是从线索与名册里扣的。

### 7.2 棋盘那块的高度：`portraitStageHeight()`

`<main>` 在竖屏下加 `max-md:flex-none` 与行内 `height: portraitStageHeight(gridSize, cellSize)`
（= `gridSize × cellSize + PORTRAIT_MARGIN_Y × 2 + PORTRAIT_STAGE_EXTRA`，`PORTRAIT_STAGE_EXTRA
= 32`）。**算出来**而不是继续 `flex-1` 的理由：棋盘宽高已经由格子定死，若这块还吃剩余空间，
2×2 这种小棋盘会在下面拖出一大片空白，而面板反而只有 `38svh`。省下的高度全给面板容器
（`flex-1` + `min-h-0`，内部整块可滚）。

那 32px 额外高度的落点取决于棋盘装不装得下：装得下时 `centeredPan` 把它平摊到棋盘上下
两条缝（每边 16），装不下时 `topAlignedPan` 贴上边、32px 全落在棋盘与题面面板之间。两种
情况都是为了不让三块钱贴成一片 —— 最后一行格子与第一张线索纸条挨太紧会读成同一块。

横屏手机（`portraitFit === false`）仍旧走老样子：面板 `max-h-[38svh] flex-none`，不参与分配。
两者都用 `flex-1` 的话，740×360 那块 360 高会被棋盘和面板平分，名册直接压成一条缝。

### 7.3 全局线索上方加 `max-md:pt-3`

面板紧贴棋盘下边框，而线索纸条只按字宽收身（`w-fit`），第一张顶着那条线会读成被切一半。
桌面端不加：标题块自带 `p-3` 下边距，再加就成了双份。

### 7.4 工具按钮：图标 2rem，按钮变长条、底栏 54 高

| | 桌面 | 竖屏 |
|---|---|---|
| 图标 | `h-8 w-8`（2rem = 32px） | `h-8 w-8`（同档，不另放大） |
| 按钮 | `h-12 w-full` | `max-md:h-full`，落在 `portrait:max-md:h-[54px]` 的底栏里，四枚等分 |
| 宽度 | 撑满 84px 的右栏 | `max-md:w-auto max-md:min-w-0 max-md:flex-1` |

32px 图标配 44px 方钮在手指下太小，而这四枚是每一手都要点的。图标保持 2rem（与桌面
同档，再大就会从棋盘与名册里抢高度），改成**底栏固定 54 高、四枚等宽的长条钮** ——
一排放得下，也不必有正方形那套对称。54 高与 `h-full` 都用 `portrait:` 限定，横屏手机
与桌面退回原样。

**`max-md:px-0` 不能少**：`Button` 未传 `size` 时自带 `size.default = 'h-10 px-4 py-2'`，
`px-4` 让每枚的 min-content 变成「图标宽 + 32」，`flex-1` 缩不过 min-content，实测就是
`103 / 103 / 71 / 71` 四枚不等宽。压掉内边距之后四枚都是 87px（375 屏，`(375 − 16 − 3×4) / 4`）。

**两个包层 `span` 也要 `max-md:w-auto`**：回退与提交外面包着一层接指针的 `span`（v0.9.1 §1
的禁用态光标方案），它原本是 `block w-full` —— `w-full` 会把 flex 基准算成整条栏宽，四枚
就分不匀。

既有用例 `GamePage.test.tsx` 断言四枚图标的 class 含 `h-8` 与 `w-8`，竖屏沿用同一档，
不必追加新类。

## §9 没做的

- **没把 `PORTRAIT_MIN_CELL_SIZE` 做成配置**。8 是「24 格 × 375 宽」逼出来的数，再低
  格子就点不准了；做成可配只会多一个没人改的旋钮。
- **没在竖屏下重开平移**。棋盘已经一屏看全，平移没有目标；真出现比屏幕还宽的棋盘，
  贴住上边、横向居中已经是最优解。
- **没改编辑器**。`docs/design-system.md` §5.10 那条「编辑器零响应式」仍原样留在账上，
  用户这次说的是游戏页。
- **没碰 `matchMedia` 桩**。整件事走纯函数 + CSS，`testing/matchMedia.ts` 一动没动。
- **没给「隐藏」加过渡**。`portrait:max-md:hidden` 是即时切换的；转屏时棋盘本来就要重排，
  再叠一个淡出只会让人以为卡了一下。
- **没动触摸设备的长按菜单**（`docs/v0.7.10.md:453`）：棋盘容器仍然没有拦 `contextmenu`。
- **没处理横屏手机的高度**。740×360 下高度只剩 110px，这是「竖屏优先」的直接代价；真要
  救得给横屏单开一套（例如名册改回左侧竖条），那是另一版的活。
- **没给 `compactPortrait` 做开关**。它只在游戏页传 `portraitFit`；编辑器与作品预览传
  `false`，「组件级选择」比「媒体查询级选择」更好控 —— 那两个页面本来就有自己的响应式账。
- **没把水波纹做成「一圈一圈」的 CSS 动画**。试过用 `animation-delay` 已经是延迟的全部
  信息量，再用 keyframes 画环只是把同一个数换个地方写；环号是数据、延迟是它的函数。
- **没给自动补的 `×` 加声音 / 触感**。
- **没给 `canvasShadowStyle` 加开关参数**。它被四处调用，而测试钉着两条 `boxShadow` 字面
  量；在调用处决定展不展开，函数保持纯粹（§6.1）。
- **没把描述弹框做成桌面端也有**。桌面左栏放得下，面板里直接读更省一步；用户这次说的是
  竖屏。
- **没在弹框里放线索**。线索要边解题边对照，进弹框反而多一次开合；`GameBrief` 只关掉
  描述那一段，`hideDescription` 也不是「整块不画」。
- **没给 `portraitInsets` 做可配参数**。8 / 12 是「375 宽、812 高」上量出来的两个数，
  再调就是另一种取舍；做成参数只会多两个没人改的旋钮。
- **没在横屏手机上单独排一套**。`max-md:` 在 740×360 上照样命中，所以面板容器走的是
  「`portraitFit ? flex-1 : max-h-[38svh] flex-none`」的后者；横屏高度本来就只剩 360，
  底栏 54 高是 `portrait:` 限定的，横屏退回原来的 87 —— 这一条与 §9 那条「没处理横屏
  手机的高度」是同一笔账，仍留给另一版。
- **没把工具按钮改成正方形**。用户明确说「可以不用正方形，可以长一些」；四枚等分的长方形
  一排放得下 2rem 图标，正方形则要在 375 宽里挤出 4 × 54 的宽度，做不到。
- **没给按钮加 `basis-0`**。压掉 `px-4` 之后 `flex-1` 已经能把四枚拉平；再叠 `basis-0`
  在 `w-full` 的桌面态下会改掉右栏那套竖排，不值。
