## 0. 一页速览

三层结构，越往下越不该越权：

```
① Token     index.css 的 HSL 变量 + tailwind.config.ts 的映射      ← 颜色 / 圆角 / 两层阴影 / 字号
② 基础组件   components/ui/*（16 个，shadcn 体系）                  ← 变体由 cva 定义
③ 组合模式   面板 / 抽屉 / 工具条 / 列表行 / 空状态                   ← 靠 className 拼，无组件封装
```

**七条必须记住的**

1. 颜色只走语义类（`bg-background`、`text-muted-foreground`、`border-border`…）。定色是例外，
   现在只剩弹窗遮罩的 `bg-black/60`。
2. **状态用 `success` / `warning` / `destructive`，元信息用 `secondary`** —— 别写
   `amber-100` / `emerald-600` 这类定色，也别给「v3」这种名词染状态色（§1.1）。
3. **字号有六档**（11 / 12 / 14 / 16 / 18 / 24）：微文字用 `text-2xs`，正文只有 `text-sm`，
   **不要再写 `text-[Npx]`**（§4.1）。
4. 想改观感：改 `index.css` 的两套变量，不要改组件。改一处漏一处，深色模式立刻留白疤。
5. 作品内容（地图背景、资源色块、区域色、区域标签字体、画布高亮）**不随主题变**，它们不是皮肤。
6. 浮层层级用 `UI_Z`（`shared/constants.ts`），别写 `z-*`；唯一例外是导航栏，见 §5.3。
7. 五个工坊页共用 `PageHeader` + 24/16/12 三档间距（§3.1、§4.3）——
   **版式一致是功能，不是偷懒**：同一件事在五页有五种写法，才是真正要修的 bug。

## 1. Token

### 1.1 颜色

**状态色只表达状态**：文字用 `text-success` / `text-warning`，徽标底用
`bg-success/10` / `bg-warning/10`。元信息徽标（`v3`、`12 × 12`、`背景 / 物品`）
保持 `bg-secondary` —— 它们是名词，不是状态，染色就变成装饰。

**难度热力档**（`--difficulty-{very-easy,easy,medium,hard,expert}-{bg,fg}`，明暗两套）：
5 档是「竹青 → 芽绿 → 赭黄 → 柿橙 → 绛」的单向坡，表达一根刻度尺。`shared/constants.ts`
的 `GAME_DIFFICULTY_*_COLORS` 存的是 `var(...)` 字符串，调用处是内联 style，所以自动跟随主题。

v0.8.6 起这条坡是**兜底**：档上没写 `color` 的才走它（内置五档、以及所有没动过颜色的
存量主题）。

v0.8.3 起**分级的档数是主题定的**（概览页可增删，见 `docs/v0.8.3.md` §3）；v0.8.6 起
每一档还带着**数字档位**（`level`，就是落库的那个值），并且**可以自定义颜色**
（`docs/v0.8.6.md` §3）。于是取色有两条路：

- 档上写了 `color`（`#rrggbb`）→ 用 `color-mix` 混出徽章：底色 `20% 这颗色 + --card`，
  字色 `42% 这颗色 + --foreground`。混的是 token，所以浅色下是淡彩块 + 深字、深色下是
  暗彩块 + 浅字，**一颗色两套主题都成立**，不必存两份；
- 没写 → 按它在分级里的**相对位置**落到那条内置坡上（三档得到「竹青 / 赭黄 / 绛」，
  八档则相邻两档共用一格）。存量主题因此一个像素都不变。

三条规矩：

- 取色只走 `difficultyBadge()` / `difficultySwatchColor()`（`shared/difficulty.ts`），
  不要在组件里 `GAME_DIFFICULTY_COLORS[game.difficulty]` —— 那张表只有内置五个键，
  而且 `game.difficulty` 现在是数字；
- 档位数字不在分级里（档被删了）时退回 `--muted` 中性灰 + 「第 N 档」；
- **分级从哪来要说得清**：工坊里的页面（部署页、导出清单）由 `DifficultyBadge` 自己读
  `useWorkspace().theme`；播放页（`/play`、`/play/theme/:slug`）在 `WorkspaceLayout` 外面，
  得用 `useDifficultyTiersByCode()` 按 `themeCode` 查好、经 `GameCard` 的 `tiers` 传下去
  （`docs/v0.8.6.md` §3.6）。谁都不给，徽章就落回内置五档 —— 在播放页上那意味着作者配的
  名字与颜色一个都不出现。

两个历史坑，写在 `index.css` 注释里，别重新踩：

- 浅色下 `secondary` 与 `accent` 曾经同值（96.1% 近白），选中与悬停分不出来（v0.7.0）。
  现在两者差 2 个亮度点，并且有独立的 `*-hover` 变量。
- `hover:bg-x/90` 在白底上是**变浅**，与「悬停=加深」相反。v0.7.2 起一律用 `*-hover` token。
- **透明度的值必须在刻度里**（0/5/10/20/…/100）。`bg-success/12` 会被 Tailwind
  **静默丢弃**，徽标变成没底色的一行字（v0.7.8 踩过）。非标准值要写 `/[0.12]`。

**工具栏底色**：`--toolbar` / `--toolbar-hover` / `--toolbar-foreground`，v0.7.8 起存在，
随调色板一起转暖（38 色相）。**只有这一组**在 `tailwind.config.ts` 里映射成
`hsl(var(--x) / <alpha-value>)`，所以 `bg-toolbar/70` 可用 ——「未选中只是悬停」
要的就是半透明那一档。用途见 §3.4。

**导航选中态**是全站唯一的彩色 chrome：`bg-primary/10 text-primary`（v0.7.8）。
工具条不跟 —— 画布上已经有 primary 的选框，两处都染色会打架。

**说明文字的对比度下限**（v0.7.9 §3）：`text-muted-foreground` 在**悬停底**（`hover:bg-accent`）
上是最苛刻的一格 —— 列表行悬停时描述文字就落在那里。调 `accent` / `muted` 之前先量这一格，
当前 4.67（浅）/ 4.72（深）；纸底 5.85、卡片 6.21。

**作品内容色不在这里**：地图背景、资源色块、区域色、画布上的搜索高亮（`HIGHLIGHT_BLUE`）、
按亮度选的黑/白文字，都属于作者的作品，**不随主题变**。判据 §0 第 4 条。

**UI 的文字与图标一律走 token，不内联写 hex**（v0.7.12 §14）。一个十六进制只能服务
一个主题 —— 谜题编辑器那行「参与者 4/4」写死 `#1F2937`，日间 13.60:1、夜间 **1.22:1**，
从 v0.6.x 起在夜里一直是不可读的。而且内联 `color` 的优先级高于类选择器：只补一个
`text-foreground`，旧值仍然赢，症状不变、代码却看着像修好了。改这种地方要先**删**
inline，再加类。`grep "color: '#"` / `text-[#` 在 `src/**/*.tsx` 里应当只剩数据默认值。

### 1.2 圆角

```css
--radius: 0.375rem;   /* lg = 6px · md = 4px · sm = 2px */
```

v0.7.9 §3：从 8px 压到 6px —— 8px 圆角配通用投影是 SaaS 卡片的配方。三级台阶各差 2px，
形状开始像「切出来的纸边」。

代码里实际出现四档：`rounded-lg`（卡片、对话框）、`rounded-md`（按钮、输入、tab）、
`rounded`（4px，图标按钮、小徽标 —— 不随 `--radius` 变）、`rounded-full`（芯片、圆点、头像）。

### 1.3 字体

**界面字体**：`tailwind.config.ts` 没有配置 `fontFamily`，正文走 Tailwind 默认的
`ui-sans-serif, system-ui …`（Windows 落微软雅黑 / macOS 落苹方）。

**唯一的例外是 `.font-kai`**（v0.7.9 §4）：`PageHeader` 的 `h1` 与 404 的 `h1` 用霞鹜文楷。

```css
.font-kai { font-family: '霞鹜文楷', 'Kaiti SC', … , ui-serif, serif; font-synthesis-weight: none; }
```

`font-synthesis-weight: none` 是必须的 —— 文楷只有 400 一档，浏览器给粗体做的「糊边加粗」
会让楷体笔画糊成一团。标题的重量交给字号（24px），不交给字重。**别再往正文上铺楷体**：
那是「廉价国风」那一端。

**作品字体**（只作用于地图上的区域标签，不进界面皮肤）：

- 自带：`霞鹜文楷-Regular.woff2`，925 KB，4705 字（GB2312 一级 + 补字清单）。构建期由
  `scripts/build-fonts.mjs` 裁字集，运行时由 `import.meta.glob` 扫目录发现。
- 系统栈：`system` / `sans` / `serif` / `kai` / `mono`，只有 `system` 还在选择器里，
  另四个保留是为了老草稿还能画。
- 加字 / 加字体的操作见 `packages/web/src/assets/fonts/README.md`。

### 1.4 阴影

**两层，都是暖色**（v0.7.9 §3）：Tailwind 的 `shadow-sm/md/lg/xl` 用的是 `rgb(0 0 0 / α)`，
黑影子落在米黄纸上会发灰发脏。取值在 `index.css` 的变量里，明暗各一套：

| Token | CSS 变量 | 语义 | 用在哪 |
|---|---|---|---|
| `shadow-paper` | `--shadow-card` | 静置的纸：一条贴边接触影 | `Card`、资源瓦片悬停、参与人头像 |
| `shadow-lifted` | `--shadow-float` | 离开纸面：接触影 + 大范围扩散 | `Dialog` / `AlertDialog`、三个右侧抽屉、底部胶囊工具条、`EntryActionsMenu`、`GameCard` 悬停 |
| —（只有变量） | `--shadow-hover` | 手指碰上去那一档：比纸重、比浮层轻，**不出自己那一格** | 名册卡片悬停（§3.10）；110px 的格子挨着 14px 的缝，`--shadow-float` 会漫到邻居身上 |

规律没变：**整块面板不浮（靠 `border` + 底色差），只有「临时浮在画布上 / 模态之上」的东西才给
阴影**。新加面板时不要顺手 `shadow-paper`，那会破坏「越临时越浮」的语义。

> **唯一一处不在这三档里**：画布自己那道投影（v0.8.7 §6）。色取 `style.canvasFrame.color`
> + 固定 0.3 alpha、`6px 6px 0` 的硬影，收在 `lib/mapStyle.ts` 的 `canvasShadowStyle()`。
> 它随**主题**变而不随明暗界面变 —— 画布是「作品」，同一张地图在浅色与深色下应该是同一张纸。
> `--shadow-*` 那三档是**界面**的材质，两者不要互相借用。

> 不要写 `shadow-[var(--shadow-card)]`：Tailwind 的任意值阴影**先判断是不是颜色**，`var(...)`
> 分不出来，会编译成 `--tw-shadow-color` —— 类存在、产物里查得到、页面上没有阴影。
> 必须走 `theme.boxShadow`（与 `/12` 同一种静默失败，见 §1.1）。

### 1.6 动效（v0.7.10）

取值在 `index.css` 的 `:root`，映射在 `tailwind.config.ts`。**时长按用途分，不是按数值分**（`glow` / `retract` 是 v0.7.12 补的第五、六档）：

| Token | 值 | 用途 |
|---|---|---|
| `duration-fast` | 120ms | 反馈：按下、悬停变色、图标 |
| `duration-base` | 180ms | 状态：弹层进出、抽屉、交叉淡入 |
| `duration-slow` | 260ms | 结构：整块位移（320px 抽屉全滑） |
| `duration-image` | 360ms | 画面：卡片封面缩放归位 |
| `--motion-glow` | 700ms | 光进来：纸背光光圈漫开（只在 CSS 里用，未映射到 Tailwind） |
| `--motion-retract` | 520ms | 光出去：同一个光圈收回，仍比进来（700ms）短 |
| `--motion-tint` | 560ms | 色铺开：名册卡片的主题色从头像那枚圆长到整张卡（v0.7.14） |

| Token | 值 | 语义 |
|---|---|---|
| `ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 默认出场（指数减速） |
| `ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 来回切换、封面缩放（两头均速） |
| `ease-in` | `cubic-bezier(0.7, 0, 0.84, 0)` | 离场（加速离开） |
| `--motion-ease-spread` | `cubic-bezier(0.33, 0, 0.25, 1)` | 扩散：从一点摊开成一整片（起手匀、收尾长），给光圈与主题色铺开用 |
| `--motion-ease-retract` | `cubic-bezier(0.4, 0, 0.7, 1)` | 收回：起步轻、收尾缓慢停住，只给光圈用（不用「到终点仍全速」的加速曲线，那看起来像被剪断） |

硬约定：

1. **裸写 `transition-colors` 就是对的**。`transitionDuration.DEFAULT` 与
   `transitionTimingFunction.DEFAULT` 都指向 token，全站 41 处裸写因此自动统一。
   只有需要别的节奏时才写 `duration-*`；**不要再写 `duration-[0-9]+`**（已清零）。
2. **弹层用 `.sheet-fade`，不要用 `animate-in`**。`animate-in` 把 `animation-duration` 写进了
   变体选择器（特异性 0,2,0），`duration-*`（0,1,0）压不动 —— 写了也不生效。`.sheet-fade`
   还额外给退场 75% 的时长。
3. **居中元素不做 transform 动画**。`-translate-x-1/2 -translate-y-1/2` 会被关键帧里的
   `transform` 整条覆盖，动画期间面板偏离中心半屏。居中弹层只动透明度。
4. **进度类动画必须 `linear`**（v0.7.10 §3.3）。长按进度环（`.press-ring-arc`）的长度就是
   「还剩多少时间」，全站其他动画都走指数减速，唯独这里缓动会说谎：前段飞跑、后段拖住，
   用户读到的时间比实际短，松手就白按。同理，它**不能被 `prefers-reduced-motion` 压掉** ——
   压到 0.01ms 会让环瞬间画满，用户以为按一下就够了。
5. **想让一块画面「亮起来」，加影不加光**（v0.7.10 §10）。`soft-light` / `screen` 在亮底上
   都有算术天花板（`soft-light` 最亮只到 `sqrt(Cb)`，93% 亮的纸最多抬 3 个色阶），
   往里叠白光只会得到一层灰纱。正确做法是 `multiply` 一层暖色暗角把周围压下去，
   再用一个小半径的近白热斑点住光心 —— **对比度给出「光」，白光本身给不出**。
6. **提示的等待分两档，按「在找」还是「在看」分**（v0.7.13 §2）。找按钮是 320ms
   （`tooltip.tsx` 的 `delayDuration`）；看画面上那件东西是什么是 1000ms
   （`ITEM_NAME_TIP_DELAY_MS`）。密排的目标不能用找按钮的节奏 —— 鼠标扫过去会下起
   提示雨，每一张都在你走开之后才长出来。

`prefers-reduced-motion` 在 `index.css` 末尾统一兜底；只要往仓库里加新动画，就该确认它落进
了那条规则（尤其是带属性选择器、特异性较高的新规则）。保留项：`.animate-spin`（放慢）、
`.animate-pulse`（放慢）、`.highlight-fade`（原样）、`.press-ring-arc`（原样，功能性的时间刻度）、
`.loredoku-word__l`（v0.7.12：换成静态全亮 —— 压成 `0.01ms` 会停在关键帧最后一帧、
也就是 `opacity: .3`，整串字几乎看不见）、`.loredoku-tick`（v0.7.12：整个收起，
一个不动的单字没有意义）。

> 加载字标另有一档时长不在上表：**周期**（不是过渡）。1500ms 走完一遍八个字母、
> 每字错开 100ms；按钮里的翻牌格 1440ms / 8 帧，`linear`。周期不是「变化」，
> 归不到 `duration-*` 那六档里，见 §3.8。

## 3. 组合模式

### 3.1 页面骨架

`AppShell`：`sticky` 顶栏 **`min-h-14`**（宽屏即 56px）+ `max-w-7xl` 居中 + `px-6 py-6` 正文。
顶栏用 `min-h-14` 而非 `h-14`，是为了让窄屏换行后的第二行把顶栏撑高，而不是溢出到正文上。

外壳有**两种形态**（v0.8.0 §18）：

| 形态 | 路由 | 顶栏 |
|---|---|---|
| **工作空间** | `/:themeCode/*` | 品牌 + 六个模块 + 右侧「主题切换器 · 日夜开关 · 游戏」 |
| **系统配置** | `/settings/*` | 品牌 + 「系统配置」+ 右侧「日夜开关 · 返回工坊」，**没有模块** |

两种形态的**右上角最后一位都是出口**：工坊是「游戏」，系统配置是「返回工坊」——
所以日夜开关永远排在它前面（v0.8.2）。品牌后面不挂 `/`：斜杠是面包屑语法，
而「系统配置」不挂在「格物」之下，位置关系交给 `gap-5`（v0.8.2）。

模块六项固定顺序（**概览** → 资源 → 地图 → 角色 → 谜题 → 部署），窄屏只换行、不折叠成菜单。

**主题不是导航里的一项，而是地址的第一段**（v0.8.0 §18）：`/hlm/maps`、`/hlm/overview`。
上一版把它做成第六个模块 + 每页顶上一条 40px 作用域条（已删）—— 那等于说「你在哪个世界」
是一件私人的、不可分享的偏好，可它决定了整屏内容。现在顶栏里没有「主题」入口，取而代之的是
紧挨日夜开关的**主题切换器**（当前主题名 + 下拉）：换主题保留当前模块，菜单底部【主题配置】
通向系统配置页。系统配置是一间机房 —— 从这里不直接干活，所以一进来就该看出自己离开了内容。

**页头模板**：五个工坊页一律用 `components/layout/PageHeader.tsx` ——
`标题（h1）+ 一句话副标题 + 右侧主操作`。不要再手写 `<h1>` 页头，也不要把页级主操作
塞进某一行控件里。

```
页头  ──24px──  工具条  ──16px──  列表/网格           ← 地图 / 谜题
页头  ──24px──  主从两栏                              ← 资源 / 角色
页头  ──24px──  行列表（一个工作空间里的在线内容）     ← 部署
页头  ──24px──  五格计数入口 ──16px──  信息卡 ──16px──  两张清单卡  ← 概览（/:code/overview）
页头  ──24px──  主题卡片网格                          ← 系统配置 · 主题
```

页根是 `space-y-6`；工具条属于列表，与列表一起包在 `space-y-4` 里。三档间距
（24 页面级 / 16 块级 / 12 控件级）是这一版定下来的节奏，见 §4.3。

页面标题惯例：`document.title = '地图 · 格物'`；在工作空间里带上主题名 ——
`红楼梦 · 地图 · 格物`（`useEffect` 里设，依赖 `workspace?.theme.name`）。

### 3.2 页面版式

- **资源 / 角色**：同页主从，两页共用同一句 `grid gap-6 lg:grid-cols-[340px_1fr]` ——
  左 340px 列表（`space-y-3`：搜索 → 筛选 → 列表），右侧自适应详情（`Card p-6`，唯一
  用 `p-6` 的卡片，因为它是表单页），窄屏自动堆叠。两页左栏的筛选控件都是 `w-auto`。
- **地图 / 谜题**：列表页（网格或行）+ 进入编辑器 / 预览页；没有同页详情。
  网格最多 **4 列**（`sm:2 lg:3 xl:4`）—— 正文上限 `max-w-7xl`，再加列只会让卡片变小。
- **部署**：单块行列表，无主从、无工具条。
- **游戏 / 预览 / 编辑器**：整版 `h-screen` 或独立顶栏，不走 `AppShell`。

### 3.3 编辑器面板

地图 / 谜题编辑器的四块：左面板（列表）、画布、右侧信息抽屉、底部工具条。

- 左面板宽度 `280px`，收起态 `40px` 细条（**谜题编辑器例外**：v0.7.13 起收起后整列
  不渲染，「展开」的箭头挪到参与者标题行左侧 —— 那条细条只为「把自己展开」而活，
  却常驻占着一条边）。按钮挂法见 `ParticipantPanel` 的 `headerLeading`：绝对定位，
  标题仍按 `text-center` 居中于整块面板（分一格会让标题往右偏 14px）。
- 右抽屉宽度 `320px`（`w-80`），两种贴法：**内联**（画布旁边推挤布局，`max-w-[50vw]`，
  无阴影）与**覆盖**（浮在画布之上，`max-w-[85vw]` + `shadow-xl` + `backdrop-blur`）。
  同一份内容两套贴法，选哪个由画布宽度决定。
- 面板头高统一 `PARTICIPANT_HEADER_HEIGHT = 40`（shared 常量），左面板、参与面板、
  抽屉标题栏共用同一个高度值，保证横向对齐。
- 抽屉用 `UI_Z.drawer`，信息框用 `UI_Z.infoDrawer`。

### 3.4 工具条图标按钮（三态）

> v0.7.9 §5：图标按钮一律走 `<IconButton>`（`components/ui/icon-button.tsx`），
> 不再手写 `title` + `<Button size="icon">`。下面这组底色常量仍然由 `IconButton` 的
> `className` 传进去。
>
> **三条例外**（此时回到 `<Button size="icon">` + `title`/`aria-label`）：
> 24px 行内微按钮（抽屉 / 对话框列表行里、且多数只在 hover 时出现——提示会跟着按钮一起闪）、
> 分段控件（互斥且状态即信息，用 `aria-pressed`，不套提示）、分页箭头（`‹ ›` 只有一义）。

`lib/toolbarButtons.ts` 集中了工具条 / 面板按钮的三个常量（v0.7.8 起全部走语义 token，
调用处不再出现 `dark:`）：

```ts
TOOLBAR_ICON_ACTIVE_CLASS = 'bg-toolbar text-toolbar-foreground hover:bg-toolbar-hover'
TOOLBAR_ICON_HOVER_CLASS  = 'hover:bg-toolbar/70'
PANEL_ICON_BUTTON_CLASS   = 'flex h-7 w-7 items-center justify-center rounded text-muted-foreground transition-colors hover:bg-toolbar/70 hover:text-foreground'
```

- **ACTIVE**：选中态（实心底）。用于工具条按钮、tab、导航选中项、芯片外壳。
- **HOVER**：未选中态的悬停（半透明底）。给已经是 `<Button>` 的元素补底色时用。
- **PANEL_ICON**：面板 / 抽屉里的 28px 图标按钮成套 class（刷新、收起、展开…），
  调用处只补 `shrink-0` 之类的宽度。

尺寸：28×28（`h-7 w-7`）是工具条与面板的标准图标按钮档；`h-6 w-6`（24）只出现在芯片上的
小 `×`；玩家端右栏用 48px（`h-12`）——触屏尺寸，属于另一套。

地图工具条、谜题底栏、游戏页右栏共用同一套，**新增面板按钮不要再手写这串 class**。
导航栏自 v0.7.8 起不在这套里 —— 它用 `bg-primary/10 text-primary` 表示「你在哪」（§1.1）。

### 3.5 列表的两种形态

- **网格卡**（`MapGridCard` / `PuzzleGridCard`）：缩略图 + 标题 + 元信息，用于视觉优先的浏览。
  封面 4:3；网格最多 4 列（§3.2）。
- **列表行**（`MapListRow` / `PuzzleListRow` / 部署行的内联实现）：左缩略图 + 中标题/副标题 +
  右操作菜单，`border-b` 分隔，用于扫读与批量操作。

**行列表共用一套列语法**（v0.7.8 §10 统一，行高 64）：

| 列 | 宽度 |
|---|---|
| 缩略图 | 64×40（`h-10 w-16`） |
| 名称 | `w-48`（`shrink-0`，内部 `truncate`） |
| 弹性中列 | `flex-1` 描述 / 访问路径 |
| 时间 | `w-52`（`formatDateTime` 唯一档） |
| 操作 | `w-40` |

两个页面之间来回切，右边缘应该落在同一列上。新增第三种行列表时先套这张表。

**部署行比这张表多三列**（v0.8.5）：难度徽标、尺寸 `w-16`、顺序 `w-14`，都夹在名称与
弹性中列之间；中列里放的是**访问路径的中段**（`hlm-sishan`），`/play/` 与 `puzzle-`
两段都不显示 —— 每一行都一样的东西不提供信息（完整路径留在 `title` 里，v0.8.5 §3）。顺序
那一格是 `SortWeightCell`：平时是一个数字，点开变输入框，回车与失焦同一条收口路径，
**值真的变了**才写回。

**谜题列表行**（v0.8.5 §6）比这张表多三列：部署徽标 `w-16`、尺寸 `w-16`、编码 `w-36`。
编码那列原来放的是**底图来源**（`地图名 vN`）—— 追溯用得上，读列表时只是同一串字反复
出现；换成编码之后，这一列回答的是「这一关对外是谁」，也正是部署时预填路径的那一串。

**分组行列表**（v0.8.0 §16.4，部署页）：同一套列语法外面的两档高度 ——

| 行 | 高度 | 样子 |
|---|---|---|
| 分组头（主题名） | **40**（`h-10`） | `text-2xs` + `text-muted-foreground` + `border-b`，右侧放组级动作（「导出包」） |
| 组内单局行 | **40**（`h-10` + `pl-10`） | 名称 + 徽标 + 右侧操作；缩进表示「它是上面那一行的细节」 |

分组头比内容行矮一档是故意的：它不是一条内容，是一个**标题 + 一个组级动作**。
单局行压到 40 而不是 64，是因为它已经靠缩进降级了 —— 再配 64 的缩略图会把它顶回和
合辑行同级。

v0.8.0 §18：工作空间里的部署页只剩**一个**组（当前主题），组头仍然保留 —— 它挂着
「导出包」这个**主题级**动作，没有组头那个按钮就无处安放。

两种形态由 `localStorage` 记住，键名分别是 `loredoku.maps.view` 与 `loredoku.puzzles.view`，
默认网格。

### 3.6 空状态

空状态固定**四**种句式，`text-muted-foreground` 居中（列表页 `text-sm`，面板内 `text-xs`）：

```
还没有资源，先创建一个吧          ← 无数据
没有匹配的资源                    ← 有数据但搜索无果
暂无角色                          ← 面板内的短句（空间小，去掉「先…吧」）
「红楼梦」里还没有地图            ← 这个工作空间里还没有（`ScopedEmpty`）
```

搜索无果与真的没数据**必须分开说** —— 前者要提示「换个关键词」，后者要提示「去创建」。
第四种（`ScopedEmpty`）与「无数据」的区别在**按钮**：它带的动作是「在「红楼梦」下新建地图」，
主题已经填好。别把作者丢回「全部」去新建 —— 那会让他再选一次，而 `theme_id` 建行后不可改
（v0.8.0 §8 护栏 2），选错了只能删了重来。

v0.8.0 §18 起这就是工作空间里的**常态**空态：地址已经说明了主题，所以句子总能点名，
泛化句式只留给没有主题上下文的场合（全屏页、单独渲染的组件）。

结构（v0.7.8 统一）：工坊六个列表页都是 **一句说明 + 一个主按钮**，不配图标；
容器内边距按宽度分两档 —— 340px 窄栏 `p-8`，全宽页 `p-12`。
**图标只出现在玩家首页**（`GamesPage`）：那是欢迎页，用大图标 + 两行说明 + 描边按钮，
与工坊的空状态是两套语言。

### 3.7 危险操作

一律 `AlertDialog` 二段式：标题是问句（`删除形态「关闭」？`），描述说清**后果与兜底**
（「画布上已放置的占位不受影响；若该形态正被地图使用，服务端会拒绝删除」），
按钮 `variant="destructive"`，进行中文案变「删除中…」并禁用。

### 3.8 加载态（v0.7.12）

**一个来源**：`components/common/LoredokuLoader.tsx`，五个出口。不要再往页面里写
`<Loader2>` —— 那是 Lucide 的通用圈，v0.7.12 之前散落 25 处，是全站最像模板的一笔。

| 处境 | 组件 | 说明 |
|---|---|---|
| 整屏（查看页 / 编辑器） | `LoadingScreen` | 字标 22px + 一句「正在加载画布…」 |
| 弹窗正文、面板里的大块空白 | `LoadingBlock` | 字标 14px + 可选说明；**说明只在能说得更具体时才给** |
| 保存蒙版 | `LoredokuLoader size="sm"` | 字标 11px + 「保存中…」并排 |
| 一行文字里的状态位（页头、`busy` 行） | `InlineLoading` | 一格翻牌 + 一句话 |
| 按钮 pending | `LoredokuTick` | 一格翻牌 + 按钮自己的文案（「保存中…」），**不要**再挂 `role="status"` |

五条约定：

1. **骨架屏不加字标**。骨架的职责是预告**内容的形状**，比「正在加载」具体得多；
   叠上去是同一句话说两遍，还会把形状盖掉。
2. **文案不重复动效已经说完的话**。「正在加载…」四个字配一个字标是废话；要说就说
   「正在加载已发布的地图版本…」。说不出来就留白。
3. **字标只给「区域」，翻牌格才给「行内」**。字标插进一行文字会把一行读成两行。
4. **短加载不出现**（v0.7.12 §9）。四个出口的根节点都挂 `load-delayed`：200ms 内
   结束的加载一帧都不画，超过才用 160ms 淡上来。翻牌格**不挂**（它和按钮文案同时
   出现，晚到会让标签跳一下）；骨架屏走 `load-skeleton`（迟到 + 呼吸，两条动画写成一串）。
   自己写新加载块时挂 `load-delayed`，别直接写 `opacity` 过渡。
5. **两道门要是同一张脸**（v0.7.12 §10）。整屏路由（编辑器 / 查看页 / 游戏）先等分包、
   再等数据，两屏都必须是 `LoadingScreen` + **同一句文案**（`router.tsx` 的
   `screenFallback`），否则同一段等待会被讲成两遍、还换个位置。第二道门由
   `useLoadDelayed` 判定「接力」（800ms 内不重新迟到），别自己给加载块写死延迟。

**字标里的 R-E-D 是品牌朱**（v0.7.12 §8）：LOREDOKU 第 3–5 个字母正好拼出 RED，
用与图标**同一支墨** —— 日间 `#5C2223`；夜间不另配近似值，照抄图标那条
`invert(1) hue-rotate(180deg)`（`.dark .loredoku-ink-red`），同一支墨过同一条工序，
色值必然一致。翻牌格**不染**：它落在按钮里吃 `currentColor`，实底按钮上朱墨会消失。

### 3.9 玩家页左栏的题面（v0.7.14）

目前只有一处：游戏页的「题面」（`components/game/GameBrief.tsx`）。它夹在标题与名册之间，
是一段**流里的文字**，不是浮层 —— 这块区域本身没有材质、没有层级；有纸影的是里面**一张
一张的线索纸条**，那是离散的物件，和名册卡片同一类。

| 项 | 值 | 理由 |
|---|---|---|
| 位置 | 左栏：标题 → 描述 → 线索 → 参与者 | 四段读起来是同一段话的四个部分（哪一局 / 要我做什么 / 多什么条件 / 这些人怎么站） |
| 分隔线 | **一条都没有**（含标题区原来的 `border-b`） | 线会把「条件」和「人」切成两个不相干的区域，而线索说的正是这些人 |
| 左边缘 | `pl-4`(16px)，与标题行的游戏名同一条竖线 | 标题是 `p-3 + pl-1`；描述若从 12px 起头，4px 错位挨着五行文字就成了「没对齐」 |
| 描述 | `text-xs` / `leading-[1.75]` / `text-muted-foreground`，收起态 `line-clamp-3` | 作者的话，退一档；超三行折起来，「展开全文 ⌄」靠右（贴左会被读成第四行） |
| 线索 | 纸条：`rounded-md border bg-card` + `shadow-paper`，**`w-fit` 收身 + `mx-auto` 居中 + `text-center`**，正文 `text-foreground/90`，**无序号** | 纸条边界已经说明「换了一条」，序号会把并列的条件读成步骤；静置时用「躺在纸上的纸」那档影子。收身：撑满一栏时右边空半张纸，读起来像「表格里的一行」 |
| 悬停 | `hover:-translate-y-0.5` + `hover:shadow-lifted`，`transition-[box-shadow,transform]` 180ms | 只动**物理层**：影子加深、抬 2px。无指针、无主色描边、无放大 —— 那三样才是承诺「点下去会发生什么」 |
| 入场 | `.clue-note`：`translate 0 4px` + 淡入，260ms，每条错 45ms（封顶 6 条） | 八条同时冒出来只读到「一堆」。`translate` 不用 `transform`、`both` 必写 —— 也正是这条留出了悬停动 `transform` 的缝 |
| 高度 | `max-h-[min(46vh,340px)]` + 自己滚 | 描述上限 500 字；该滚的是题面，不能把名册挤没 |
| 空态 | 描述与线索都没有 → 返回 `null` | 标题与名册之间不留一段没有内容的空隙 |

四条判断规则：

1. **整块区域不要伪装成浮层**。给一段左栏文字整体加材质 / z-index，是在说「我可以被拖走」——
   它不会。v0.7.14 初稿正是浮纸（`shadow-paper` + `UI_Z.gameBrief` + 折叠），改到流里之后
   那三样一并删掉。**但**里面一张一张的东西（线索纸条）可以有纸影：那是「桌上摆着几张
   纸条」，不是「这整块能飘」。
2. **行文共用一条左边缘，物件按自己大小居中**。标题与描述都在 16px；线索纸条是**物件**，
   `w-fit mx-auto` 摆正中间（v0.7.14 第三轮）；参与者卡片也在 8px 的格子里 —— 卡片与纸条
   都是「桌上摆着的东西」，不像文字那样需要对出一条竖线。
3. **作者的话里不出现界面标签**，也不因为「是作者写的」就换字体：描述是五行正文，用 sans
   （§2.1 的「别再往正文上铺楷体」）；楷体只留给**一句**结束语 —— 它一局只出现一次，
   是这本书翻到最后的那一行。
4. **不交互的元素，hover 只能动物理层**。线索纸条不是按钮：它悬停时抬 2px、影子从
   `shadow-paper` 换到 `shadow-lifted`（v0.7.14 补充），但**没有**指针、主色描边、放大 ——
   那三样是「点下去会发生点什么」的承诺，v0.7.10 删掉的那批假交互正是只做了承诺。
   判据：把声音关掉看那一下变化，如果它读成「这张纸被抬起来一点」就通过，读成
   「可以点」就过头了。

### 3.10 名册卡片的触碰态（v0.7.14）

`components/map-editor/ParticipantPanel.tsx`。这是全站唯一**能点、能拖、又有自己的颜色**
的卡片，所以它的悬停态要同时说三件事：我在这儿、我是谁、我被拿起来了。

| 项 | 值 | 理由 |
|---|---|---|
| 线 | 静置 1px `border-border`；**悬停不给描边上色**；选中 = 1px 主色描边 + 2px 主色外扩（同色相接，3px 一整条，**中间不留纸色**） | 1px 描边 + 4px 处的 2px 环且中间有缝 = 同一条边上的两道颜色；描边收成透明又会在框与卡片之间留下一圈空白。同色相接才是一条边 |
| 角上的徽标 | 内圆角 = 卡片半径 − 描边（5px）；填主色时再加 `0 0 0 1px` 同色外扩 | 徽标贴 padding box 的角，用外半径会切出一道 1px 纸白；同心之后两条抗锯齿的弧仍会在交界漏白，外扩让它们合成一条 |
| 抬升 | `translate: 0 -2px`，180ms | 与选中时那次鼓起（`roster-select-pop`）同一条轨：动画开头不会被抹平，落下也不跳 |
| 影子 | `--shadow-hover`（`0 2px 4px .06 + 0 8px 18px -8px .18`） | **不用** `--shadow-float`：28px 扩散在 110px 卡 + 14px 格距的名册里会漫到邻居的缝里，看着像整片脏了 |
| 填充 | 参与者**本人**的主题色，α = 0.16，**铺在内容下面**（`z-index: -1` + 卡片 `isolate`） | 0.12 与纸底只差 15 个色阶；0.20 开始读成色卡、压住 11px 的线索。白色参与者退回主色 —— 白上加白等于什么都没发生。负层级不加 `isolate` 会沉到卡片底色之下、什么都看不见 |
| 铺开 | `@property --tint-r` 0.5 → 320px，圆心在头像正中，560ms / `--motion-ease-spread` | 只动**半径**：整层 `scale` 会把渐变的软边一起放大、中途扫出一圈硬边；整层淡入则读成闪烁，看不出从哪儿开始 |
| 收回 | 520ms / `--motion-ease-retract`（基线规则） | 与本仓所有「进入慢、退出快」的规矩一致；开关只是根节点上的 `data-tint`，不留 React 状态 |

五条判断规则：

1. **一个状态一道线，而且这一道线不能断**。要区分「路过」和「点住」，靠的是层数之外
   的东西 —— 这里靠线更粗（3px vs 2px）、抬起、序号徽标反色。反过来，为了「不要两条线」
   而把描边收成透明、让框与卡片之间留一圈纸色，同样不行：那圈空白读作「框浮在外面」。
2. **颜色属于那个人，不属于界面**。卡片铺的是参与者的 `themeColor`，不是主色 ——
   名册是一排人，颜色是他们各自的记号（和地图上的头像圆是同一个色）。
3. **圆的扩张要看得见起点**。这层色从头像长出来，所以圆心必须落在头像正中
   （`--tint-y` 由组件按实际头像尺寸算，不是写死的 55px）；铺满时整张卡是均一的
   一层，不能留一块没染到的角 —— 渐变半径要覆盖到最远的那个角。
4. **染的是纸，不是人**。这层色只铺卡片这块纸，头像那一枚圆要原样留着 —— 它是
   「这层色属于谁」的答案，被同一层色盖住就什么都不成立了。实现上必须让它成为**底色**：
   绝对定位的兄弟在绘制顺序里排在普通流内容之上，只靠「放在第一个子节点」是不够的。
5. **触碰态跟着手势走，不跟着人走**。点亮说的是「此刻正被拿着」，所以手势一结束就得退：
   头像落定（手上空了）之后，名册的 2px 环、铺色、棋盘上这位的联动高亮与 1.3× 放大
   要一起收（v0.8.7）。**短按落编号不算** —— 那只是草稿，这位还在手上。状态分了两份
   （`mode` 管选中、`activation` 管触碰），收场只收一份就是这里最容易出的错。

### 3.11 主题的三张卡与一行作用域（v0.8.2）

主题相关的界面只有三块，写法各自不同，别互相借。

| 块 | 形状 | 边界 |
|---|---|---|
| 设置页 · 主题卡 | `a` + `rounded-lg border bg-card`，顶 8px 识别色带，左文右数 | **不用 `<Card>`**：它是整块可点的链接，`Card` 的 `shadow-paper` 在悬停时会让「浮起来」和「点得动」两件事混在一起 |
| 概览 · 五格计数 | 同上（链接、无阴影、`p-3`），24px 图标（`strokeWidth={1.5}`，`self-start`）+ 24px 楷体数字 + 11px 标签 + 右侧箭头 | **五格一行**（资源 / 地图 / 角色 / 谜题 / 部署），`lg:grid-cols-5`；1440 下 237px、1024 下 186px 仍容得下「24px 图标 + 数字 + 箭头」，第六格才需要另起一块。图标取自 `lib/moduleIcons.ts` 的 `MODULE_ICONS` —— 与顶栏导航**同一枚**（v0.8.2 §12）。第五格数的是 `counts.games`（部署行），不是谜题数（v0.8.3 §2） |
| 概览 · 信息卡 | `<Card>` + `divide-y`，行 `min-h-10`，左 64px 标签 | 四行固定：名称 / 编码 / 描述 / 识别色。这里是「这个空间是什么」，值后面**不许**长出控件，也不许塞操作指引（v0.8.3 §3 删掉了「缺省风格」「上线」两行） |
| 概览 · 清单卡（v0.8.3） | `<Card>` + `CardHead`（楷体标题 + 右侧「编辑」），正文是**多栏清单** | 两张：**地图初始样式**（四组 26 项，`columns-1 lg:columns-3` 多栏、每组 `break-inside-avoid`，组内 `dl` 两列「名字 —— 值」，颜色给色块 + hex）与**难度分级**（一排徽章）。清单是**读**，表单在弹窗里；清单里不许出现控件 —— 一行里放一个输入框，二十几行就是二十几个「有没有保存」的疑问（v0.8.3 §2 / §3）。**头里只有标题和按钮，不写副标题**；按钮的视觉文案统一是「编辑」，`aria-label` 拼上标题（`编辑地图初始样式`）—— 两个同名按钮对屏幕阅读器读不出区别（v0.8.6 §1.2）。**方格大小不在清单里**：它随画布尺寸变，一张图一个数，属于那张图的「基本信息」（v0.8.6 §1.3）。版式见 `docs/v0.8.6.md` §1.4：组是**栏里的一段**，不是横跨整行的分段标题 —— 那种写法每组都要另起一行，组尾剩下一两个空格，右半边全是洞。点「编辑」打开的**弹窗**照「地图基本信息」抽屉的骨架：384px 单栏、分区带下边框与问号、行用 `Row`、光标两个框各围一个边（v0.8.6 §1.6）—— 同一批字段在清单里读、在弹窗里改，两处必须长得像同一件事 |
| 概览 · 页头动作（v0.8.3） | 两个 `size="sm"` 按钮：`outline` 编辑信息 + `ghost` 删除主题 | **不设 `⋯`**：`⋯` 里只剩两个动作时，菜单比按钮贵；`⋯` 是在动作 ≥4 个时才划算的收纳。<br>「上线」与「导出资源包」都已搬到部署页 —— 概览回答静态问题，「出门」发生在部署页（v0.8.3 §1） |

三条规矩：

1. **色带的位置永远占着 8px**。识别色是可选的，位置不是 —— 否则同排卡片里只有设过色
   的那张往下挪 8px，标题全错行（v0.8.2 §1.4）。
2. **识别色走 `data.accent`**，卡片上不许写定色；它是作者的**门牌**，不是界面皮肤，
   所以它不随主题明暗变，也不进资源包。
3. **动作平铺，不藏 `⋯`**（v0.8.3 §1）。页头动作 ≤3 个时一律平铺：主操作 `default` /
   `outline`，破坏性用 `ghost` + `hover:text-destructive`。这套界面里 `⋯` 只在「同一个
   对象有 4 个以上动作、且其中多数是低频的」时才出现。
4. **作用域行（`ThemeScopeField`）只在真的能选时出现**（v0.8.2 §14）。主题由地址
   决定时（工作空间内的四个新建弹窗），这一行**整行不画** —— 地址 `/:code/...` 与
   顶栏的主题名已经说了两遍，弹窗里再说第三遍只是占掉 41px 却不让做任何决定。
   还有得选、且主题不止一间时，它是 `<Label>` 同档（14px / medium）、`min-h-10`
   与输入框对齐的下拉。

## 4. 事实上的梯级

这部分**不是设计出来的，是被用出来的** —— 记录下来是为了改动时有据可依，不是背书。

### 4.1 字号

**六档，v0.7.9 §4 定下来的**。这一栏以前记的是「事实上 4 档混用、没有 token」，现在反过来：
token 是唯一入口。

| Token | 字号 / 行高 | 用途 |
|---|---|---|
| `text-2xs` | 11 / 16 | 徽标、计数（`草稿 12`）、`格`、快捷键提示 |
| `text-xs` | 12 / 16 | 元信息：时间、尺寸、描述、卡片副标题 |
| `text-sm` | 14 / 20 | **正文、按钮、表单、列表主行**（唯一正文档） |
| `text-base` | 16 / 24 | 列表页的 section 标题 |
| `text-lg` | 18 / 28 | 对话框标题 |
| `text-2xl` | 24 / 32 | 页标题（`PageHeader` 的 `h1`，用 `.font-kai`） |

- **不再写 `text-[Npx]`**。10px 已全部并入 11px（中文 10px 在 1x 屏上已经在糊，而 10 与 11
  之间从来没有语义分工）。
- 唯一在梯级外的是 `GenderBadge` 的 ♂/♀ **符号** 13px —— 12 会缩成小点、14 会抢过徽标文字，
  代码注释里标了它是「光学尺寸，不是文字档位」。
- 徽标是 `px-1.5 py-0.5 text-2xs`。

### 4.2 控件高度

**四档，且只允许四档**（v0.7.9 §1.3）：

| 档 | 值 | 用途 |
|---|---|---|
| T1 | 28（`h-7`） | 面板 / 抽屉里的图标按钮（`PANEL_ICON_BUTTON_CLASS`） |
| T2 | 32（`h-8`） | 工具条图标按钮、分段控件内的按钮、分页箭头 |
| T3 | 36（`h-9`） | 紧凑文字按钮（`size="sm"`）、底栏胶囊按钮、主题切换 |
| T4 | 40（`h-10`） | 标准控件：`Input`、`Select`、主按钮、`size="icon"` |

24px（`h-6`）只允许出现在**底栏芯片内的 `×`** 这类附在别的东西上的小符号，不作为独立控件；
`LinkageDialog` 里那 6 个 24px 片段按钮已经在 v0.7.9 升到 T1。

### 4.3 间距

三档职责分明（v0.7.8 §10 定下来的）：

| 档 | 值 | 用在哪 |
|---|---|---|
| 页面级 | 24（`space-y-6`） | 页头 → 正文 |
| 块级 | 16（`space-y-4`） | 工具条 → 列表；页面内的分区之间 |
| 控件级 | 12（`space-y-3`） / 8（`gap-2`） / 4（`gap-1`） | 表单字段之间 / 按钮组 / 图标与文字 |

`gap-1.5`（6）偶见于按钮内图标与文字之间。卡片内 `p-4`，主从页右侧表单 `p-6`。
没有 24px 以上的页面内留白 —— 地图 / 谜题的「草稿」「版本」两块之间是唯一的 32px
（`space-y-8`），因为那是两个独立数据集，不是同一块里的分区。

| ~~5.8~~ | ~~`--radius: 0.5rem` 偏软~~ | — | **已解决（v0.7.9 §3）**：压到 `0.375rem`（6px），三级台阶各差 2px | — |
| 5.9 | **剩余 `title=` 96 处** | 列表行、部署页、若干截断文本 | 大多数是「被截断文本的补全」，合理的；`IconButton` 已覆盖 54 处，余下 17 个图标按钮按 §3.4 的三条例外保留 | 低：外链那枚是 `<a target="_blank">`，换掉要先定「中键新标签页」怎么保留 |
| 5.10 | **编辑器零响应式** | `EditorLeftPanel` 280 + 画布 + 抽屉 320 | 1024 宽时画布只剩 424px，窄屏没有降级提示 | 中：要先决定「窄屏收起左面板，还是干脆给一句提示」 |
| 5.11 | **`VirtualList` 固定 480px** | `components/ui/virtual-list.tsx` | 1366×768 上左栏底部落在折线以下；主从页在窄屏堆叠时，详情表单排在 480px 滚动区之后 | 中：改成视口自适应会牵动主从页的高度契约 |
| 5.12 | **重新取数时变淡只在 2 个页面上有** | `MapsPage` / `PuzzlesPage` 有 `isFetching && !isLoading` 的 `opacity-60`；`AssetsPage` / `CharactersPage` / `DeploymentsPage` / `GamesPage` 没有 | 同一个「后台在取数」的状态，四个页面毫无表示 | 低：包一层容器即可；但这属于**状态反馈**（v0.7.9 §1 那条线），不是动效，别混进来 |
| 5.13 | **游戏页棋盘只能用指针操作** | `pages/GamePage.tsx` | `keydown` 只处理 Escape（退出模式）与空格（平移）；放编号 / 放头像 / 禁止符号 / 清除全部只由 pointer 触发，键盘用户无法完成任何摆放 | 高（无障碍）：要先把棋盘做成可聚焦的格子网格（`role="grid"` + 方向键导航），牵动渲染结构 |
| 5.14 | **棋盘没拦 `contextmenu`** | 同上 | 触摸设备按住约 500ms 会弹系统菜单，与长按阈值撞在同一段时间上 —— v0.7.10 §3 的进度环会被打断 | 低：桌面端（主场景）不受影响；「要不要禁掉右键菜单」是新的交互决定，不该夹在动效改动里做 |
| 5.15 | **`ring` / `foreground` 等 token 不支持透明度修饰符** | `tailwind.config.ts` 的 `colors` | 定义成 `hsl(var(--ring))` 而没有 `<alpha-value>` 占位符，于是 `ring-ring/50` 里的 `/50` 被**静默丢掉** —— 类还在、产物里查得到，画出来仍是实心（v0.8.5 §5.4 因此放弃了「软环」方案；与 v0.7.9 §3 记的 `shadow-[var(--shadow-card)]` 是同一类失败） | 低-中：加 `<alpha-value>` 在不写修饰符时行为不变；但要逐 token 确认没有地方依赖「修饰符无效」的现状 |

> 5.6 容易被高估：初稿曾记为「大量卡片层层嵌套」，实测 `rounded-lg border` 只有 4 处，
> 主力是 `border-b` 分隔的面板与行。所以这条债的真实分量是**版式语言不统一**，
> 而不是「卡片泛滥」—— 优先级排在最后。
