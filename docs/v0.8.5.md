> **状态**：已实施（2026-10-30）。同一版收了三批需求。
> **来源**：用户的八条 ——
>

## 0. 一句话

八条里五条在**减**：一个放完就不该留的选中态、一列每行都一样的前缀、一行没用的来源、
一段路径前缀、标题下那句「业务 ID：xxx（不可修改）」。加的三条各有理由 —— 顺序可就地改、
谜题有个**本来就是地址形状**的编码、输入框的焦点环从框外贴回描边。封面那条不在其中：不是
界面坏了，是那些行里本来就没有图，属于 2026 年的旧账。

## 1. 参与者放下之后，名册不再「举着他」

### 1.1 症状

在游戏页点一位参与者（名册卡片出现双环），长按格子放上头像 —— 头像落下了，**卡片还亮着**。
界面在说「你还举着这位」，可头像只有一张。玩家下一次点格子会以为要放第二个，实际落的是编号。

### 1.2 改法

`gamePlacement.ts` 新增一个纯函数：

```ts
export function modeAfterPlacement(mode, variant): GameOperationMode {
  if (mode.kind !== 'placing') return mode;
  return variant === 'image' ? { kind: 'idle' } : mode;
}
```

`GamePage.dispatchCell` 在放置成功后调用它，模式变了才 `setMode`（返回同一个对象时跳过，
省一次渲染）。

**编号（短按 / 按住滑）故意不退出。** 同一位参与者的编号会落在很多格上 —— 一行线索里
可以有好几个数字；每落一次都要回名册重点一下，等于把连续标注变成反复点卡片。头像是一次
动作，编号是一串动作，两者的收尾本来就不同。

### 1.3 实测

无头 Chrome 打开 `/play/puzzle-hlm-sishan`，用真实鼠标事件驱动：点名册第一张卡 → 长按
C4R1 → 头像落下、同行同列补出 5 个 `×`（「已放置 6」）→ **卡片外圈的双环消失**，只剩
放置态的变暗。接着在相邻格单击一次，计数仍然是 6 —— 手上确实空了。

## 2. 封面：不是渲染坏了，是那条行里没有图

先排除渲染：13 条部署里有 2 条有封面（Fireside Beach、The Treasure Hunt），它们在列表里
**画得好好的**（`naturalWidth 400`、卡片 62×38）。所以问题在数据：

| | 有封面的行 |
|---|---|
| 13 条部署 | **2** |
| 41 条谜题 | 14 |

原因在时间线：v0.7.2 §4 定下「谜题封面是游戏的默认封面」，但那次复制发生在**重新打开
部署弹窗**的那一刻。在那之前部署的行，`games.cover_path` 一直是空的，于是列表退回首字母。

### 2.1 为什么是迁移，而不是读的时候回退

读时回退（`cover_path ?? puzzle.cover_path`）更省事，但会碰两件事：

1. **快照**。部署出来的游戏是那一版谜题的快照（整条 CONS-K16 链都建立在这上面）。读时
   回退意味着旧游戏的封面会跟着谜题一起变 —— 快照就不再是快照，已上线的老关会换脸。
2. **「移除封面」**。部署弹窗有这一项（OPT-W03 §3），它把 `cover_path` 写成 `null`。读时
   回退分不出「从没设过」和「作者明确删了」，会把删掉的图又变回来。

所以写成一条一次性迁移：`20260101000042_v085_game_cover_backfill.ts`，

```sql
UPDATE games g SET cover_path = pz.cover_path
  FROM puzzles pz
 WHERE pz.id = g.puzzle_id
   AND g.cover_path IS NULL AND g.deleted_at IS NULL
   AND pz.cover_path IS NOT NULL
```

每个游戏认的是**它自己那一版**谜题的封面（`games.puzzle_id`），不是同名谜题的最新版。

**结果**：本地库里 3 条旧部署拿到图（13 → 5）。剩下 8 条仍然没有 —— 它们的谜题本身就没
封面，那是作者没做过图，不该由代码发明。

## 3. 部署页的路径：只留尾段，再剥掉 `puzzle-`

### 3.1 只留尾段，复制按钮一起撤

`/play/` 在每一行都一样，却占着最宽的一列（`flex-1`）。现在只显示 `game.slug`，
完整地址留在 `title` 里，要真打开就在右边那颗外链按钮上。

复制按钮随之删干净：`copyPath`、`copiedKey` 状态、`Check` / `Copy` 图标、`toast`
（这一页再无别的提示）。理由很简单 —— **一个不是完整地址的字符串，复制出去没有用**。

合辑行同理（显示 `deployment.slug`），并且补了一个 64×40 的文件夹位：两行的名称列因此
从同一个 x 起，读起来是一张表。

### 3.2 连 `puzzle-` 那一段也不显示

`/play/puzzle-hlm-sishan` 里的 `puzzle-` 是 v0.4.1 给 `/play/` 底下留的**命名空间**
（`GAME_SLUG_PREFIX`），不是这一关的信息 —— 每一行都以它开头，读起来像页头的复读。

- 展示：`shared/gameSlug.ts` 新增 `stripSlugPrefix(slug)`，只剥前缀，别的一个字都不动
  （`splitSlug` 是给输入框回填用的，连难度后缀一起剥，不能拿来显示）。
- 部署页两处（单局行、合辑行）都过它；合辑的 slug 本来就没有这个前缀，属于空转。
- **地址本身没变**，完整路径仍在 `title` 里，旁边那颗「在新标签页打开」也一直在。

### 3.3 为什么不动 URL 本身

把 `puzzle-` 从地址里去掉会同时产生两种形状的路径（老链接带前缀、新链接不带），而
`puzzle-` 对老链接是既成事实 —— 只改显示，不动契约。

## 4. 顺序列：点开就改，变了才写

### 4.1 界面

`SortWeightCell`（`components/game/SortWeightCell.tsx`）：平时是 `序 0`，点开变输入框。

| 动作 | 结果 |
|---|---|
| 回车 | 提交 |
| 失焦 | 提交（与回车同一条收口，不区分「确认」与「离开」） |
| `Escape` | 取消，恢复原值 |
| 值没变 | 只收起，**不发请求** |
| 空 / `1.5` / 超 ±999 | 只收起，不发请求（这一格没有弹窗承载错误提示，把非法值交出去只会得到 400） |

前面那个「序」字是必要的：这一列没有表头，一个孤零零的 `0` 会被读成上一列的残留
（第一版就是这样，截图里像脏点，改后才读得懂）。

### 4.2 端点

新增 `PATCH /api/games/:id`，body 只认 `{ sortWeight }`。

不走部署端点重发整份负载，是因为那会顺手把 `name` / `slug` / `difficulty` 一起写回去，
而列表上的值可能已经比弹窗里的新 —— 改个顺序不该有别的副作用。

| 层 | 行为 |
|---|---|
| `gameWeightUpdateSchema`（shared） | `sortWeight` **必填**、整数、±999。缺键是错误，不是「沿用上一次」 |
| `gameService.updateGameSortWeight` | 校验 → 写一列 → 返回新摘要；没有这条活行就 404 |
| `gameRepository.updateGameSortWeight` | `where id + deleted_at is null`，`affected === 0` 视为不存在 |
| 前端 `useUpdateGameWeight` | 成功后只刷 `gameKeys.all`：顺序是服务端的事实，列表不本地重排 |

### 4.3 排序本身

「按权重排」在 v0.8.3 就已经是服务端的事（`ORDER BY sort_weight ASC, slug ASC`），这一版
没有改规则 —— 改的是**可改性**：此前只能打开部署弹窗重填，现在列表上就地能改。

实测（hlm）：把「撕扇子作千金一笑」的顺序改成 9 → 回车 → 行立刻沉到列表底部；再改回 0，
它回到原位，其余 7 行的顺序值一个都没动。

## 5. 输入框的焦点环：去掉那一圈「框外的缝」

对这一条的起点是一句提问 ——「输入框的点击样式为什么和 shadcn/ui 的不一样」。差的不是
颜色也不是粗细，是 **`ring-offset-2`**。

### 5.1 差在哪

对照 `ui.shadcn.com` 现行 registry（`styles/new-york/input.json`，2026-10-30 取）：

| | 改前（我们） | 上游现行 | 这次 |
|---|---|---|---|
| 环宽 | `ring-2` | `ring-1` | **保留 `ring-2`**（§5.4） |
| 与描边的距离 | `ring-offset-2`（环在框外 2px） | 贴边，**无 offset** | 跟上游：删 offset |
| 聚焦时的描边色 | 不变，始终 `--input` | 染成环色 | **不跟**（§5.4） |
| 过渡 | 无 | `transition-colors` | 不跟（没有颜色在变，过渡是空转） |
| 高度 | `h-10` | `h-9` | 不动（§5.5） |
| 底色 | `bg-background` | `bg-transparent` | 不动（§5.5） |

`button` 同一条：删 `focus-visible:ring-offset-2`，其余不动。

### 5.2 为什么「点下去那一下」差别被放大

三件事叠在一起：

1. **`:focus-visible` 对文本框，鼠标点也算。** 这是规范要求的 —— 能输入文字的控件，无论
   键盘还是指针聚焦，都算「需要焦点提示」。所以按钮点下去不亮、输入框点下去亮，不是 bug。
2. **`ring-offset-2` 把焦点态切成三层。** offset 在描边与环之间掏出 2px 的空隙，用
   `ring-offset-background` 指定的颜色填。于是从外到内是：2px 蓝环 → 2px 底色空隙 →
   1px 灰描边 → 框内。
3. **那 2px 是「页面底色」，不是「所在表面的颜色」。** 输入框大多坐在 `bg-card` 的对话框
   与卡片里，于是这条缝比周围纸面暗一档 —— 它不参与构成边界，只在那里显形。

### 5.3 实测：缝没了，环贴在描边上

无头 Chrome（`--remote-debugging-port` + CDP）把真实类名渲染在 `bg-card` 的纸上，聚焦后
用 `sharp` 沿输入框左边缘横向逐点读像素（0.5 CSS px 一步，deviceScaleFactor 2）。

**改前**（焦点态）：

| x（CSS px） | 颜色 | L* | 是什么 |
|---|---|---|---|
| −3 … −2.5 | `rgb(63,123,166)` | 49.5 | 2px 的环 |
| −2 … −0.5 | `rgb(248,246,242)` | 96.9 | **offset 的空隙**（页面底色） |
| 0 … +0.5 | `rgb(222,216,207)` | 86.6 | 1px 描边（`--input`） |
| +1 起 | `rgb(248,246,242)` | 96.9 | 框内底色 |

**改后**（焦点态）：

| x（CSS px） | 颜色 | L* | 是什么 |
|---|---|---|---|
| −2 … −0.5 | `rgb(63,123,166)` | 49.5 | 2px 的环，**贴着描边** |
| 0 … +0.5 | `rgb(222,216,207)` | 86.6 | 1px 描边，**聚焦时不变色** |
| +1 起 | `rgb(248,246,242)` | 96.9 | 框内底色 |

钉住三件事：

- **外框从 5px 收到 3px**（旧：环 2 + 缝 2 + 描边 1；新：环 2 + 描边 1）。
- **缝真的消失了**：改后在 x−2.5 处已经是卡片本身的 `rgb(254,253,251)`（L\* 99.3），
  而改前那里是 96.9 的 `--background` —— **ΔL\* 2.4**。单看几乎察觉不到，但它恰好夹在
  描边与蓝环之间，正是「看着不如 shadcn 干净」的具体来源，不是错觉。
- **描边颜色没被环吃掉**：聚焦前后 `borderColor` 都是 `rgb(222,216,207)`。这是 §5.4 那条
  决定的可验证后果。

### 5.4 为什么没跟着上游「1px + 描边染色」

上游把环压到 1px，同时让描边自己变成 `--ring`，两条合起来才是 2px 的边。第一条能跟，
**第二条不能**：边色在这套界面里是语义通道 —— 7 处用 `border-destructive` 标「这一格填
错了」（`GameDeployDialog` 的路径与权重、`CreatePuzzleDialog` / `EditPuzzleDialog` 的编码、
`PuzzleInfoDrawer` 的名称与描述、`ParticipantDrawer` 的线索）。

「聚焦时给描边上色」那条规则的优先级（类 + 伪类）高于调用处的 `border-destructive`（单个
类），一旦加上，**用户在报错的字段里继续打字时，红边会变蓝** —— 越改越看不出哪儿错。
所以：环宽留在 `ring-2`（它本来就是对的），只把 offset 拿掉。

也没用「3px + 50% 透明度」那版软环：`tailwind.config.ts` 里 `ring` 是
`hsl(var(--ring))`，没有 `<alpha-value>` 占位符，Tailwind v3 会把 `/50` 静默丢掉 ——
类还在、产物里查得到，画出来仍是实心（与 v0.7.9 §3 记的 `shadow-[var(--shadow-card)]`
是同一类失败）。已记进 `design-system.md` §5.15。

改动的四个文件：

| 文件 | 改动 |
|---|---|
| `ui/input.tsx` | 删 `ring-offset-background` 与 `focus-visible:ring-offset-2`；补一段注释说明为什么只删 offset |
| `ui/textarea.tsx` | 与 `Input` 逐字一致 |
| `ui/select.tsx` | 同上；v0.7.8 §3 的结论保持不变，只追加一条「跟着去掉了 offset」 |
| `ui/button.tsx` | 删 `focus-visible:ring-offset-2`，补注释 |

### 5.5 没动的两处

- **`h-9` 没跟。** 会牵动 `Select`、按钮和一整排表单的对齐。v0.7.8 §3 为「搜索框与下拉
  底边差 4px」专门把 `Select` 提到 `h-10`，那是**量过**的结论，比重抄一遍上游模板可信。
- **`bg-transparent` 没跟。** 会让输入框跟着所在表面走，改变「输入框比纸面深一档」的既有
  观感。这与「点击样式」无关，属于另一场外观改动。

顺便记一处：`dialog.tsx` 的关闭按钮仍是 `focus:ring-2 + ring-offset-2` —— 上游自己也还是
这样（同日核对 registry）。它是 16px 的图标，环贴边会顶到 X 上，所以跟着上游留 offset。
`GameDeployDialog` 难度徽标的选中环、`SortWeightCell` 的就地输入框也都留着 —— 前者是
「选中」不是焦点，后者本来就是 `ring-2` 无 offset，这次之后反而与 `Input` 一致了。

## 6. 谜题卡片：来源那一列换成编码

「来源」在这里指 `地图名 vN`：谜题的画布是创建时从某张地图版本复制来的，这个来源不参与
任何后续逻辑，只在列表里做追溯。

- `PuzzleListRow`：整列拿掉（`w-36`），**换成编码**（见 §7）。
- `PuzzleGridCard`：`尺寸 · 地图名 vN · 更新时间` → `尺寸 · 编码 · 更新时间`。

一张地图常常喂着好几关，于是这一列在一屏里反复出现同一串字；而作者真正需要一眼看到的
「这一关对外是谁」（编码）反而没有位置。换掉的正是这一格。

**顺带**：部署页行里那行「来源：{谜题名} v{版本}」也一起撤了。部署页回答的是「在线的是
什么」，不是「它是从哪一版谜题生成的」；要追版本，谜题列表里就写着。

## 7. 谜题编码（`code`）

### 7.1 它解决什么

部署弹窗的路径默认值一直是「名称 slug 化」：

```
午夜花园 → slugify → '' → 无法根据名称生成访问路径，请手动填写
```

中文名推不出任何东西（Q13 从 v0.4.1 起就是这个状态）。编码就是补上这一环：建谜题时写一串
**本来就是路径形状**的字，部署时直接拿它当中段。

```ts
PUZZLE_CODE_PATTERN = /^[a-z0-9]+(-[a-z0-9]+)*$/   // 与 ASSET_CODE 故意不同：这个用连字符
PUZZLE_CODE_MAX_LENGTH = 48
```

字符集与路径对齐（小写 + 数字 + 连字符），所以 `hlm-sishan` 落进 `/play/puzzle-hlm-sishan`
时中间不需要任何转写。资源 / 角色的编码用下划线（`hlm_banana`），因为它们只在 JSON 里被
引用 —— 同一个词，两套字符集，理由不同。

### 7.2 存储

`puzzles` 表加一列 `code`（`varchar(48)`，**可空**）。

可空是刻意的：这一版之前的谜题没有它，迁移**不发明**编号（`puzzle-12` 之类只是把「没有」
伪装成「有」）。这些谜题部署时退回按名称推导 —— 也就是 v0.4.1 的老行为，Q13 那句提示仍在
（服务端 `resolveSlug` 的兜底分支）。

**不加唯一约束**，原因只有一条：同一条谜题的**草稿行与版本行共用一个编码**（编码是这一关的
身份，不是版本的属性），唯一索引会把它们判成冲突。所以查重放在两个真正的入口：

| 入口 | 规则 |
|---|---|
| `createPuzzle` | 同主题内不重，撞了 409「编码「x」已经被这个主题的另一个谜题用过了」 |
| `updatePuzzle`（改码） | 同上；值没变则跳过（查重看不见「自己」） |
| `duplicatePuzzle` | 复制品另取一个没被占的：`x-2`、`x-3`…（原样复制会让两条谜题抢同一个路径） |

改编码**写整条血统**（`where root_id = ?`），不只是那一行：版本行是快照，但快照的是内容，
不是「这一关叫什么」。只写草稿行的话，列表里同一条谜题的版本行会显示旧编码，部署那条版本
时预填出来的也是旧值。

### 7.3 迁移

`20260101000043_v086_puzzle_code.ts`：加列 → 回填 → `down` 只撤列。

### 7.4 部署时自动填入

- 前端（`GameDeployDialog`）：中段默认值 = `slugify(activePuzzle.code)`，没有编码才退回
  名称。**改名字不再改路径** —— 编码才是地址的来源，改名只改显示名。
- 服务端（`gameService.resolveSlug`）：请求里没给 `slug` 时，兜底也先看编码
  （`buildDefaultSlug({ name: code ?? name })`）—— API 直连也拿得到同样的结果。

存量谜题（编码为 `null`）在弹窗里仍然是「名称 slug 化」，作者要么手填路径，要么先去「编辑
谜题」补一个编码。后者是这一版给存量谜题留的补写入口。

## 8. 资源与角色的编码搬进信息区

原来标题下面挂着一行小字：

```tsx
<h2>{asset.name}</h2>
<p>业务 ID：{asset.code}（不可修改）</p>
```

三件事一起改：

| 之前 | 现在 |
|---|---|
| 标签叫「业务 ID」 | 叫「编码」 |
| 挂在标题下、跟着标题一起滚动消失 | 进「基本信息」，与名称并排 |
| 一行「（不可修改）」的说明 | 不写；框本身改不动就够了 |

输入框用 `readOnly` 而不是 `disabled`：值要能选中、复制（作者常常要把 `hlm_banana` 贴进
联动的 JSON），`disabled` 的灰底既不能选中又读起来像「加载中」。

同一套措辞同步到别处：两个新建弹窗的标签与校验文案（`请输入编码` / `编码过长` / `编码仅
允许字母、数字与下划线`）、三个搜索框的占位符（`搜索名称 / 编码`）。

- **产物核对**（`dist/assets/index-*.css`）：`:focus-visible` 下不再有
  `--tw-ring-offset-width: 2px` —— 它现在只剩两处：`ring-offset-2{…}`（难度徽标）与
  `ring-offset-2:focus{…}`（对话框关闭按钮）。`focus-visible:ring-2` 的 `--tw-ring-shadow`
  仍是 `calc(2px + var(--tw-ring-offset-width))`。
- **像素探针**：§5.3 那两张表。为了让「改前」的类名重新出现在产物里，临时加过一个只放字符串
  的 `src/legacy-probe.tsx`，验完删除并重建，产物哈希回到改造后的值；探针脚本一并删除。

一个顺手踩到的坑：改完重建，产物里仍然有 `border-ring:focus-visible{border-color:…}`
这条规则 —— 来源是 `input.tsx` 注释里那句引用。**Tailwind 的扫描器只看文本、不看语法**，
注释里写出的类名会照样生成。把措辞改成「聚焦时给描边上色」后重建，规则消失。注释里引类名
等于往产物里塞死代码。

## 10. 没有做的

1. **复制链接没有了。** 现在要一条可分享的地址，只能从地址栏复制，或新标签页打开后复制。
   如果以后确实需要，做法是「整行悬停才出现一枚复制图标」，而不是把长路径放回来。
2. **合辑行没有顺序。** 合辑内部仍按 `sort_order`（v0.8.3 §6.2），`theme_deployments`
   也没有 `sort_weight` —— 那一列在合辑行上是空的，不是 0。
3. **封面是共享路径，不是复制文件。** 迁移把谜题那张图的**路径**写进 `games.cover_path`。
   目前没有任何代码 unlink 封面文件（删封面只把列写 null），所以两个行指同一个文件是安全的；
   哪天要加「删行即删文件」，得先处理这层共享。
4. **谜题本来没有封面的行仍然是首字母。** 迁移只补「本来就该有」的，不发明图。
5. **存量谜题的编码是「反推」来的**，不是作者写的。已部署的那些从游戏路径剥出来（够用），
   没部署过的一律是 `null` —— 列表里显示 `—`，要补就得去「编辑谜题」写一个。
6. **编码可以重复**（没有数据库约束，只在入口查）。理论上并发两次创建能撞出两条同码谜题；
   单机工坊里不值得为它上分布式锁，而且真撞了也只是部署时选路径发现冲突（那个流程本来就
   有「覆盖」）。
7. **改编码不会改已部署的路径**。路径是给持链接的人的承诺，只有重新部署才会按新编码重填。
8. **`puzzle-` 仍留在 URL 里**（见 §3.3）。真要把它从地址里去掉是另一场迁移：老路径保留、
   新路径不带前缀，中间还得处理「两种形状并存时 `splitSlug` 怎么反解」。
9. **谜题的第二层筛选没有跟着改**：搜索仍只认名称 / 描述 / 版本号，编码不进关键词
   （`listPuzzleEntries` 的过滤条件没动）。加它是三行，但会把「搜 hlm-」变成一次全表扫，
   等有人真要它再说。
10. **焦点环比上游那版宽。** 我们是一条 2px 蓝环 + 1px 灰描边（总 3px），上游是「1px 环 +
    染色的描边」（总 2px）。这是拿「保住错误态的红边」换的（§5.4）—— 除非哪天把错误态从
    边色改成别的通道（比如只留框下那行红字），否则这 1px 不好省。
11. **全站还剩一处带缝的环**：对话框右上角的关闭按钮（§5.5）。要统一就先得决定它在
    `rounded-sm` 的 16px 图标上贴边好不好看。而输入框「比纸面暗一档」这件事也还在 ——
    这次只去掉了焦点态那条缝，`bg-background`（L\* 96.9）放进 `bg-card`（99.3）里，
    未聚焦时仍是一块略暗的纸。
12. **`ring` 仍不支持透明度修饰符**（§5.4、`design-system.md` §5.15），所以「软环」这条路
    要先改 token 才走得通。
