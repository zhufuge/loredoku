# v0.11.7 — 玩法说明：弹框、两枚问号、第一次进来自己弹

## 0. 范围与口径

一句话：**游戏页有了一份「怎么玩」的说明** —— 右栏最下面一枚圆形问号（竖屏在头部
日夜模式按钮左边）打开它；第一次进任意关卡时它会自己弹一次，之后不再自动弹。

口径五条：

1. **说明说的是「这套界面怎么操作」，不是「这一关怎么解」**。四段里三段（规则、操作、
   工具）讲的是点谁、按什么、哪个按钮管什么 —— 它们不随谜题变，作者也不必每关重写。
   谜题自己的规矩（谁在场、谁能和谁同处一室）由题面与线索回答，弹框里只留一句
   「一局的具体规则以题面为准」把两者分开。
2. **「看过」记在这台设备上，与哪一关无关**。键是 `loredoku.game.helpSeen`，
   和存档、计时并列放在 `localStorage` —— 它是本地状态，不进服务端，也不进导出的包。
3. **记账在弹框打开那一刻就写**，不等玩家点「知道了」。他可能直接点遮罩外、或者
   直接开始下棋，那两种也算看过一次；若等关闭才记，每次刷新都会再弹一遍，那就成了
   挡路的浮层而不是说明。
4. **两枚问号各管一个断点，不搬 DOM**。桌面那枚沉在右栏最下面（`GameToolRail`），
   竖屏那枚在头部（`GamePlayerAside`），各用 `hidden` / `portrait:max-md:hidden`
   决定露哪一枚。右栏在竖屏是底部横条，把问号塞进去会跟「视图簇」抢位置；而头部
   那一行本来就空着。两边共用同一个 `helpOpen`，所以永远只有一层。
5. **弹框等这一页的数据与资源都到了才自动弹**。说明里说的「点参与者」「长按格子」
   得有对象可指；压在骨架屏上的说明既点不到也看不懂。
6. **「工具」那一段的图标与工具条同源**。作者把清除 / 撤回 / 提交换成主题的图之后，
   说明里画的就是那几张图；标记用这一关自己那枚 `mark`。写死四枚内置图标的话，
   玩家会拿说明去对一个画得不一样的按钮。

## 1. 弹框

`packages/web/src/components/game/GameHelpDialog.tsx`：

```tsx
export function GameHelpDialog({
  open,
  onOpenChange,
  toolIcons,
  markImageUrl,
}: GameHelpDialogProps): JSX.Element
```

- `<DialogContent className="max-w-md" data-testid="game-help-dialog">`，标题「玩法说明」。
  **只留标题、没有副标题**：四段标题（目标 / 规则 / 操作 / 工具）已经把这一页说完，
  再加一句「先看一遍这四段」只是重复。
- 正文四段（`Section` + `Lines` / `ToolLines`），整块 `max-h-[62svh] overflow-y-auto` ——
  手机上这一段比一屏长，弹框里再套一个滚动容器就够了：

| 段 | 条数 | 内容 |
| --- | --- | --- |
| 目标 | 1 句 | 利用线索找出所有人物所在的位置 |
| 规则 | 3 条 | 每行和每列各有一人 / 「旁边」指同一区域内的上下左右一格 / 「上方」指参考物所在行的北边所有行（下 / 左 / 右同理） |
| 操作 | 4 条 | 点击人物：选择 / 点击格子：添加·移除标记（编号）/ 长按格子：放置人物（头像）/ 拖动：在多个格子中做标记 |
| 工具 | 4 条 | 标记 / 清除 / 撤回 / 提交 —— **每条前面画工具条上那一枚图标** |

- 底部一枚「知道了」关掉。标题**可见**（与 v0.11.6 那个描述弹框相反）：那一个是
  「用户刚点了同一枚图标」，这一个可能是自动弹出来的，得先告诉玩家这是什么。

### 1.1 工具那一段的图标

工具条上画什么，说明里就画什么 —— 换成主题的图之后两边不会各说各的。解析顺序与
`lib/toolIcons.ts` 同源（`resolveToolIcons`）：

```
谜题自己的 toolIcons  →  主题的 data.toolIcons  →  内置 lucide 图标
```

- 三枚动作（清除 / 撤回 / 提交）走 `toolIcons[kind].imageUrl`；「标记」没有主题图标，
  用这一关自己那枚 `mark` 的图（`GamePage` 传 `markImageUrl`）。
- 解析不到就画内置：标记是红 `×`（`text-destructive`），其余是 `Eraser` / `Undo2` / `Send`。
- 图片一律 `h-4 w-4 object-contain` + `aria-hidden`：图标在这一行只是「说的是哪一枚按钮」，
  文字已经把它叫出名字了；`dark:invert dark:hue-rotate-180` 让作者上传的深色线稿在深色
  主题下仍看得见。

## 2. 记账

`packages/web/src/lib/gameHelp.ts`：

```ts
export const GAME_HELP_SEEN_KEY = 'loredoku.game.helpSeen';
export function readGameHelpSeen(): boolean;
export function markGameHelpSeen(): void;
```

- 读：只认字符串 `'1'`。别的值（旧版本写过、被手改过）都算没看过 —— 宁可多弹一次。
- 读失败（隐私模式、存储被禁）返回 `false`，写失败静默 —— 那种环境下页面还得能玩，
  不能因为记不住这件事就崩。
- 为什么不用 `sessionStorage`：玩家关掉标签页明天再进来，说明仍然应该已经看过一次。

## 3. 自动弹的那一次

`packages/web/src/pages/GamePage.tsx`：

```tsx
useEffect(() => {
  if (!detail || resourcesLoading || readGameHelpSeen()) return;
  markGameHelpSeen();
  setHelpOpen(true);
}, [detail, resourcesLoading]);
```

三个条件分别对应：这一关的数据到了、资源齐了、这台设备还没看过。

## 4. 两枚问号

| 位置 | 文件 | 何时可见 |
| --- | --- | --- |
| 右栏最下面（视图簇之下） | `packages/web/src/components/game/GameToolRail.tsx` | 桌面；`portrait:max-md:hidden` |
| 头部，日夜模式按钮左边 | `packages/web/src/components/game/GamePlayerAside.tsx` | 竖屏；`hidden max-md:flex` |

- 右栏那枚排在视图簇**之后**，所以 `mt-auto` 仍把「视图簇 + 问号」这一组顶到底边 ——
  视图簇从此不再是最后一个子元素，而是倒数第二个（既有那条布局用例已按此改写）。
- 头部那枚把 `ThemeToggle` 的 `max-md:order-5` 让给了它，自己改成 `order-6`。
- 两枚都用 `IconButton`（`aria-label` 与悬浮提示同源，都是「玩法说明」）。
- 图标 `h-4 w-4`，与它正上方的视图簇（放大 / 缩小 / 重置 / 标尺）同一档：那一簇也是
  次级操作，问号跟它们排在一起，画得比它们大就会显得这一栏有两套字号。

两个测试细节值得记一笔：

- **Radix 把弹框内容 portal 到 `document.body`**，`container.querySelector` 找不到它 ——
  查询要用 `document`（第一次就是这么红的）。
- **两个游戏页测试的 `beforeEach` 都要预置「已看过」**。它们清空 `localStorage` 之后
  若不预置，一个 `role="dialog"` 会压在棋盘上：`pointerdown` 打到遮罩、按钮被
  `aria-hidden` 掉，几十条用例会一起红，而它们其实一点都没坏。

浏览器实测（播放器产物，1254×620）：首次进 `puzzle-hlm-sishan` 自动弹，四段齐全；
「工具」四条各画一枚图，与右栏工具条上那四枚**逐一对得上**（标记的 `×`、清除的笔、
撤回的回环、提交的印）。这一段在 620px 高的窗口里要往下滚一格才看得到（正文
503px / 可视 384px），底部「知道了」不随滚动走。

## 6. 补：定案卡的标题淡一档

`packages/web/src/components/game/GameCard.tsx` 的标题：

```tsx
<h3
  className={cn('truncate font-medium', completed ? 'text-muted-foreground' : undefined)}
  title={game.name}
>
```

- **只退标题，不动名字之外的任何东西**。封面上已经盖了「定案 + 印」，结论写在封面上；
  标题再和没做过的那几张一样黑，整张卡会读成「还能再挑一次」。
- **退到 `text-muted-foreground` 就停**，不写更淡：玩家挑关卡时仍要一眼看清这一关叫什么，
  淡到读不清就变成「不可用」而不是「已完成」。
- 两个列表页（工坊的 `/:themeCode/play` 与播放器的 `/:code/play`）共用同一张 `GameCard`，
  所以一处改完两边都对。实测已完成卡标题 `rgb(103, 94, 86)`，未完成的仍是 `rgb(35, 30, 26)`。

按 AGENTS.md「界面外观不写断言」，这条没有加用例（断言 Tailwind 类名属于外观）。

## 7. 没做的

- 不做「逐关不同」的说明：那是题面（`puzzle.description` / `puzzle.clues`）的职责。
- 不做「设置里重新显示一次」的开关：清掉 `localStorage` 就能再看，为一个提示语加一
  项设置不值当。
- 不做示意图（参考图里规则那两张小棋盘）：画布是 canvas 组件，把它塞进弹框要另造一份
  静态示意图，收益不如把话说清楚。
- 不做「看完才允许下棋」的强制引导：这是一份说明，不是闸门。
