## §1 工坊：裁掉 ≠ 没适配

评审在 375×812 上量到的是两份不同的坏：

| 页面 | 现象 | 后果 |
|---|---|---|
| `/hlm/maps`（全部六个列表页同款） | 文档宽 **561px**、视口 375px，多出的 **186px** 落在一个 `overflow` 裁切区里 | 顶栏右侧那一簇（主题切换器 / 日夜 / 游戏）整块看不见，也滚不到 |
| `/hlm/maps/15420/edit` | 顶栏自身 **532px** 宽、`overflow` 不可滚 | `保存` 在 x 366–446、`发布` 在 x 450–532 —— **永久停在屏外**，窄屏上这两条路等于不存在 |

根因是同一条：`components/layout/AppShell.tsx` 顶栏右侧的 `div.ml-auto.flex.items-center.gap-2`
固定 **222px**（主题切换器 94 + 日夜 36 + 游戏 76 + 两道 8px 间距），`ml-auto` 不给它收缩的
余地，`nav` 又只认 `flex-wrap`，于是内容比视口宽、被外层裁掉。

**「不做移动端适配」不等于「让它坏掉」**：不做适配说的是「不重排成手机版」——
真去重排，1024 宽时画布就只剩 424px，左侧资源 / 图层面板 280 与右侧抽屉 320 摊不开。
但「被裁掉」是另一回事：内容看不见、也够不着，那不是难看，是功能缺失。

## §2 做法：给工坊一个下限宽度

### 2.1 两个常量

`packages/web/src/lib/layout.ts`（新文件）：

```ts
export const WORKSHOP_MIN_WIDTH = 1024;
export const WORKSHOP_MIN_WIDTH_CLASS = 'min-w-[1024px]';
```

1024 不是随手取的：`docs/design-system.md` §5.11 与 §5.10 记的两个数 ——
`VirtualList` 固定 480px、编辑器左面板 280 + 抽屉 320 —— 在 1024 宽时画布还剩 424px，
这是这套版式**开始能将就**的宽度。再窄下去不是「挤」，是「没有画布」。

类名与数字分成两个导出，是因为 Tailwind 的 JIT 只认**字面量**：`min-w-[${N}px]`
这样的模板拼接扫不到、不生成任何 CSS。两个常量手写一致，改宽度时两处一起改。

### 2.2 五处挂载点

| 文件 | 位置 | 角色 |
|---|---|---|
| `components/layout/AppShell.tsx` | 根 `<div className={cn('flex min-h-screen flex-col', WORKSHOP_MIN_WIDTH_CLASS)}>` | 六个列表页 + 概览 + 系统配置（走 `AppShell` 的全部） |
| `pages/MapEditorPage.tsx` | 根 `<div className={cn('flex h-screen flex-col overflow-hidden', WORKSHOP_MIN_WIDTH_CLASS)}>` | 地图编辑器 |
| `pages/PuzzleEditorPage.tsx` | 同上 | 谜题编辑器 |
| `pages/MapViewPage.tsx` | 同上 | 地图只读预览 |
| `pages/PuzzleViewPage.tsx` | 同上 | 谜题只读预览 |

后四个必须单列：它们是**整屏页**，路由在 `AppShell` 之外（`router.tsx` 那条注释写的
「整屏：编辑器」），吃不到外壳那条下限。

### 2.3 为什么不需要 `overflow-x: auto`

`packages/web/src/index.css` 的 `@layer base body` 只有 `@apply bg-background
text-foreground antialiased;` —— 全站没有任何 `overflow-x: hidden`。所以根容器撑出
视口之后，滚的是文档本身（`documentElement.scrollWidth` 变大、`window.scrollX` 能走）。
**加一条 `overflow-x` 反而会把滚动困在内层**，这一版没加。

### 2.4 为什么不是 `flex-wrap`

`nav` 已经是 `flex-wrap`。再让右边那簇也换行，375 宽上顶栏会长成三四行 —— 实测
`nav` 被压到 62px 宽 × **356px** 高，六项各占 56px、每行一个字（「概」「览」）。
那是把桌面工具切碎，不是适配。

## §3 方格大小：26 关里有 23 关的棋盘装不下

`packages/web/src/pages/GamePage.tsx` 算格子时走的是这一行：

```ts
const cellSize = portraitFit ? autoCellSize : effectiveCellSize(autoCellSize, style);
```

而 `effectiveCellSize` 的语义是「作者写了就用作者的」：

```ts
export function effectiveCellSize(autoCellSize: number, style: MapStyle): number {
  return style.cellSize ?? autoCellSize;
}
```

于是 `fit()` 里那套按 `<main>` 宽高算出来的 `autoCellSize`，只要作者在「基本信息」里填过
方格大小就整个作废。`<main>` 是 `overflow-hidden`，还不可滚，超出的部分直接被切掉、
没有任何提示。

28 关实测（`GET /api/games` + 逐关 `/api/games/slug/<slug>`）：

| 项 | 数 |
|---|---|
| 配了 `map.style.cellSize` | **26 / 28**（110 / 116 / 132 / 136 / 140 / 146 / 148 / 150 / 168） |
| 装得下 | 3 |

具体裁切量（改前）：

| 视口 | 页面 | `main` | 棋盘 | 裁上 | 裁下 |
|---|---|---|---|---|---|
| 1440×900 | `/play/puzzle-hlm-kanposanchun-hard`（7×7，作者 132） | 1103×900 | 924 | 0 | **42** |
| 1280×800 | 同上 | 943×800 | 924 | **32** | **92** |
| 1024×768 | 同上 | 687×768 | 924 | **48** | **108** |
| 1280×800 | `/hlm/maps/15420/view` | 1280×744 | 730 | 0 | **24** |
| 1280×800 | `/hlm/puzzles/4358/view` | 1280×744 | 730 | 0 | **24** |
| 1280×800 | `/hlm/maps/15420/edit` | 1000×744 | 730 | **29** | 0 |

24×24 的 `puzzle-the-treasure-hunt`（作者 36）在 1280×800 下是 864，比可用高 692 多出 172。

竖屏早在 v0.10.1 就绕开了这条路（`portraitFit` 时不看 `style`），桌面一直没有。

## §4 做法：作者值降级成上限

### 4.1 `effectiveCellSize`

```ts
export function effectiveCellSize(autoCellSize: number, style: MapStyle): number {
  const authored = style.cellSize;
  if (typeof authored !== 'number' || !Number.isFinite(authored)) return autoCellSize;
  return Math.min(authored, autoCellSize);
}
```

为什么不是直接忽略作者值：存量 78 张图带着 36~168 的数是作者「这张图别铺太大」的意图，
屏变宽时允许它长到 240 正是这句话的另一个方向。压上限既解决了裁切，也没把作者的意图
整条扔掉。

### 4.2 渲染下限 32 → 8：`RENDER_MIN_CELL_SIZE`

只压上限还不够：24×24 在 1280×800 下可用高 692，减掉 23 条格间只剩 646，一格最多 26.9；
旧下限 `MIN_CELL_SIZE = 32` 会把它抬到 32，棋盘又变 768、继续被切。缩小是能救的，
切掉是救不回来的，所以渲染下限独立成一档：

```ts
/** v0.10.3：渲染用的下限。… */
export const RENDER_MIN_CELL_SIZE = 8;
```

`MIN_CELL_SIZE = 32` 保留 —— 它仍是**作者能写进 `style.cellSize` 的下限**
（`MAP_STYLE_CELL_SIZE_MIN`，schema 在用），只是不再管渲染。

缩放兜底已经在了：`cellScale = cellSize / 120`，格子 8px 时 `cellScale ≈ 0.067`，
而 `scaleLineWidth` 有 0.5 下限、`scaleFontSize` 有 9px 下限，不会画出 0 宽线或不可读的字。

### 4.3 `Math.round` → `Math.floor`

同一处顺手改的：

```ts
return Math.floor(Math.min(max, Math.max(min, ideal)));
```

理由和竖屏那条（`computeWidthFitCellSize`）一样 —— 宁可每格少半像素，也不让棋盘比可用
区域宽出一线。**这条不是先想到的，是测试逼出来的**：新加的「每个格数都装得下」用例第一次跑
就报 `expected 794 to be less than or equal to 792`，四舍五入正好多出 2px。

### 4.4 撤掉「基本信息」里的方格大小

`MapInfoDrawer` 的「画布」段现在只剩「画布尺寸」一行。连带清掉的东西：

| 位置 | 删掉的内容 |
|---|---|
| `MapInfoDrawer.tsx` | `<Row label="方格大小">` 整块（`NumberField #map-info-cell-size` + ↺ 恢复自适应）、`autoCellSize` prop、`cellSizeValue` / `cellSizeHint`、`RotateCcw` / `MAP_STYLE_CELL_SIZE_MIN/MAX` / `clampCellSize` 三个 import |
| `MapEditorPage.tsx` | `autoCellSize` state、`<EditorCanvas onAutoCellSize>`、`<MapInfoDrawer autoCellSize>` |
| `PuzzleEditorPage.tsx` | `autoCellSize` state、`<EditorCanvas onAutoCellSize>` |
| `editorStore.ts` | `setCellSizeOverride`（声明 + 实现，唯一调用者是测试） |

字段、schema、`resolveMapStyle`、`clampCellSize`、`mapStyleDiff` 的字段项全部保留 ——
存量数据照常读，主题里那个 168 也照常在（v0.10.2 起已不参与比对）。

## §6 没做的

**工坊那一半**

1. **没做工坊的移动端重排** —— 用户裁定不做。窄屏上能滚，但体验仍是「桌面工具缩小看」。
2. **没加「请使用桌面端」的提示** —— 那是选项 B，用户选了 A。
3. **没让下限宽度跟视口自适应** —— 1024 是常量，不分「平板竖握」与「手机」两档。
4. **没动玩家侧 `/play`** —— 它本来就不溢出，且有自己的竖屏排布（v0.10.0 / v0.10.1）。
5. **没修 `AppShell` 顶栏本身的结构问题** —— 右侧那簇仍不收缩。下限宽度只是让它
   「滚得到」，没有让它「装得下」；真要装下得重排顶栏，那是另一件事。
6. **没处理 `LoadingScreen` 的 `h-screen`** —— 整屏加载态在窄屏下仍以 375 宽居中，
   横向滚动条出现的一瞬间会跳一下。空态只活几百毫秒，暂不处理。
7. **没把响应式策略写进 `docs/design-system.md` 的正式章节** —— 只在 §5.10 那条已知
   债务里标了「设计决定」，没有新开一节讲全站响应式（那是全站级的话题，值得单独写）。

**方格大小那一半**

8. **没有真的从 schema 删 `cellSize`。** `mapStyleSchema` 是 `.strict()`，删字段会让
   78 张存量图解析失败（`unrecognized_keys`），得先写迁移清库。收益只是少一个已经
   看不见的键。
9. **没有迁移存量数据。** 78 行 `data.style.cellSize` 原样在库里，现在只当上限读。
10. **没有改 `MIN_CELL_SIZE = 32`。** 它变成纯「作者输入范围」的常量
    （`MAP_STYLE_CELL_SIZE_MIN`），语义与渲染脱钩。
11. **没有给 `RENDER_MIN_CELL_SIZE` 在下限之下再兜滚动。** 极小窗口（比 8px × 格数还小）
    仍会溢出被裁，只是已到像素级不可用的程度。
12. **没有区分四页的下限。** 游戏页 / 两个预览页 / 两个编辑器共用 `computeCellSize`，
    一起降到了 8。
13. **没有让「定案」遮罩跟着变。** `verdictMarkScale` 吃 `total`，棋盘变小后它更容易
    落在 `zoom 1` —— 实测遮罩表现正常，但没针对性调整。
14. **`setCellSizeOverride` 是直接删的**，没有留一个 `@deprecated` 过渡期。
    它的唯一调用者就是抽屉那一行。
