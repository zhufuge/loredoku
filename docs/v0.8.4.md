# v0.8.4 — 精简测试：只钉行为

> **状态**：已实施（2026-10-30）。
> **来源**：用户一句话 ——「精简测试，测试时间过长，清除一些界面、布局和文本上的测试，
> 当前界面改动可能会比较大」。
> **范围**：`packages/web` 的测试文件（整删 23 个、部分删 7 个）、
> `scripts/run-tests.sh` + 新增 `scripts/run-tests.mjs`、`AGENTS.md` §4.2 / §4.3、
> `.gitignore`。**没有源码改动** —— 删掉的是断言，不是功能。
>
> 编排上它原本是 v0.8.3 收尾的一节（旧编号 §16）。v0.8.3 已经「已实施」，而这一笔
> 是给**下一次界面大改**让路的准备动作，不是 v0.8.3 的补丁，所以拆出来单独立一份。

## 0. 一句话

测试从「证明这一屏长这样」退回「证明数据与地址没坏」：**能让人看见的不测（除非它坏了
会变成看不见的错），看不见的必须测。** 顺带把跑测试的 86 次进程启动压成 1 次，2 分半
变成 9 秒。

## 1. 起因

两条一起说：测试跑一次要 **2 分 30 秒**；而接下来界面还要大改，一堆断言钉的正是要改的
地方 —— 文案、类名、谁排在谁前面。它们不会告诉你有东西坏了，只会告诉你有东西变了。

## 2. 时间花在哪

`user` 时间 5.4 秒，`real` 2 分 30 秒 —— 差额几乎全是进程启动：旧脚本按文件循环
`vitest run`（86 个文件 = 86 次 Node 启动），而这么写是有原因的，脚本注释里写着：
一次收集多个文件时，本机文件系统会拒写临时目录（EPERM），vitest 静默漏收。

这次把三条路都量了一遍：

| 跑法 | 时间 | 收集 |
|---|---|---|
| 逐文件（旧） | 2m30s | 87 / 87，1051 条 |
| 一次收集，默认并发 | 11.2s | 偶发漏 1 个文件，并带一条 EPERM |
| 一次收集，`--no-file-parallelism` | 65.7s | 87 / 87，1051 条 |

漏收是真的，但不是每次都发生；而 `--no-file-parallelism` 把并行收益几乎全吐了回去。
所以改成：**一次收集跑完，再拿报告对着磁盘上的文件列表核一遍，漏了谁补跑谁**。
正常情况补跑 0 个文件。

`scripts/run-tests.sh` 由此变成薄壳，逻辑在 `scripts/run-tests.mjs`：

1. 递归找磁盘上所有 `*.test.ts(x)`；
2. 一次 `vitest run --reporter=json`；
3. 报告里没有的文件逐个补跑；
4. 报告都没写出来（收集阶段就崩）→ 整包退回逐文件。

跨了一个数量级：

| | 文件 | 用例 | 时间 |
|---|---|---|---|
| 改前 web | 87 | 1051 | 2m30s |
| 改后 web | 64 | 880 | **9.2s** |

`--serial` 留给共享一个数据库的包。`server` 直接默认用它：一次并行跑里
`assetVariants.test.ts` 整个文件报失败，单跑又是 11 / 11 全绿 —— 并行收集时两个文件
同时造删资源，撞上了。11 秒换一次偶发红不值，串行 33 秒。

## 4. 判据

删每一条之前问一句：**它错了，会有人看到坏掉的东西吗？** 答案落在两堆里：

| 断言的东西 | 去留 | 为什么 |
|---|---|---|
| 文案字符串 | 删 | 文案是产品决定，改成什么样都不该报错 |
| Tailwind 类名、DOM 顺序、尺寸、透明度、颜色 | 删 | 布局与观感，界面还要改 |
| 渲染的回退规则（形态丢了画什么、空态 vs 错误态） | 留 | 错了玩家会看到空白或一句误导 |
| 写回的数据（payload 有哪些键、没改时不带那个键） | 留 | 错了是「保存不生效」这类真 bug，人眼看不出来 |
| 地址与跳转（模块前缀、死链的去处） | 留 | 书签与分享链接会坏 |
| 草稿 / 未保存 / 脏数据 | 留 | 丢作者输入，且只有用久了才会撞上 |

一句话：**能让人看见的不测（除非它坏了会变成看不见的错），看不见的必须测。**

## 5. 代价

1. **外观不再有自动网**。改样式之后靠无头浏览器截图 + 量像素确认（这条一直是本项目
   验收视觉的做法，只是不再把结果写进测试）。
2. **删掉的断言语义没消失，只是不再钉在这一层**。比如「空态里不该有第二个新建按钮」
   本质是「空态只有一个入口」—— 以后它再出错，应该做成一条行为断言，而不是数按钮。
3. 数量降下来之后更该守住：新加测试若在测文案与布局，代码评审时退回（`AGENTS.md`
   §4.2 已写明这条）。

## 6. 验证

- web **880 / 64**（9.2s）、shared **254 / 20**（2.7s）、server **207 / 14**（33s，串行）；
  `typecheck`、`build` 全绿。三包合计从原来的 2 分 40 秒上下压到 45 秒左右。
- 删掉的文件全部是纯测试文件，没有一个被源码引用；`typecheck` 与全量跑过两遍确认。

## 7. 没有做的

1. **`npm test` 那条路没动**。各 workspace 仍各自 `vitest run`，与 `scripts/run-tests.sh`
   并行存在 —— 顺手改容易变成两套入口互相打架，等真有人天天用 `npm test` 再说。
2. **外观验收没有补自动化**。截图 + 量像素仍靠手跑；要做的话是另一件事（视觉回归），
   不是测试精简的一部分。
