# 界面打磨：一致性 · 布局 · 配色（v0.7.8）

> **状态**：**已实施**（2026-10-26）。
>
> 需求原文：
> ```
> polish 全部页面
> layout 优化所有页面的布局，在v0.7.8
> colorize 优化所有页面和功能的颜色
> ```
>
> 依据：`.impeccable.md`（设计意图）+ `docs/design-system.md`（现状清单与债务）。
> §1–§9 是 polish（一致性修补），§10 是布局优化，§11 是配色改造 —— 三轮同一版连续做，
> 前两轮只做减法、不引入新视觉方向，配色轮才换掉整块调色板。

## 0. 一句话

把「同一件事在五个页面有五种写法」的地方收敛成一种：定色改语义 token、五处手写 `<select>`
换成一个组件、列表徽标高矮不齐的字号拉平、三处过时文案和两处错位缩进修掉。**观感只做减法，
不加新装饰**。

布局部分（§10）同理：五个工坊页共用**一个页头模板**，页头到正文 24px、工具条到列表 16px，
网格最多 4 列，两处「行列表」共用一套列语法 —— 没有一处是为了好看而加东西。

配色部分（§11）是**换掉整块调色板 + 让颜色承担状态含义**：工坊原来穿的是 shadcn 默认的
冷蓝 SaaS 皮肤（宝蓝主色、210–217 冷灰），现在换成**宣纸底 + 墨字 + 靛（石青）交互色 +
绛（oxblood）危险色**，并把「已启用 / 已发布 / 未保存 / 已部署 / 校验失败」这些状态从灰徽标
和写死的 amber/emerald 里救出来，收成 `success` / `warning` 两个 token。不改版式、不加装饰、
不动作品内容色。

## 1. 工具栏底色改吃语义 token

**问题**：`lib/toolbarButtons.ts` 与另外 4 个组件里写死 `bg-slate-200 / dark:bg-slate-700`
这类定色。深色模式必须成对写 `dark:`，漏一处就在深色下留白疤 —— 而实际已经漏了 7 个文件。

**做法**：`index.css` 新增三个变量（明暗两套），`tailwind.config.ts` 暴露为 `toolbar` 颜色组，
**并且只有这一组支持 `/透明度`**（`hsl(var(--toolbar) / <alpha-value>)`）——

```css
:root { --toolbar: 214.3 31.8% 91.4%;  /* slate-200 */ }
.dark { --toolbar: 215.3 25% 26.7%;     /* slate-700 */ }
```

取值与原 slate 值**完全等价**，所以换 token 后观感零变化，只是调用处不再出现 `dark:`。

**替换的 6 处**：`toolbarButtons.ts`、`AppShell`（导航选中/悬停）、`RefreshButton`、
`EditorLeftPanel`（背景层/物品层切换）、`PuzzleEditorLeftPanel`（展开/收起）、
`PuzzleBottomBar` / `EditorBottomBar`（缩放百分比、芯片上的 `×`）。

芯片上那个 24px 的 `×` 原来用 `slate-400/50`（比芯片底色深一档），改成 `hover:bg-toolbar-hover`
—— 语义同为「在激活底色上再压深」，浅色下略浅一点，换来无 `dark:` 配对。

## 2. 面板图标按钮收成一个常量

同一串 28px 图标按钮的 class（`flex h-7 w-7 … hover:bg-…`）原本在 5 个文件里各写一遍，
且都带着 `dark:` 尾巴。新增 `PANEL_ICON_BUTTON_CLASS`，`RefreshButton` 与谜题面板两处直接引用。

> 这属于「三处以上重复」才值得抽的门槛；抽屉关闭、tab 之类的**一次性**按钮不强行套。

## 3. `<select>` 统一成一个组件

**问题**：全项目 5 处手写 `<select>`（资源筛选、角色筛选、地图排序、谜题排序、形态填充方式），
各自写 class，且**三种高度**：`h-9`、`h-10`、组件内的 `h-9`。同排的搜索框是 `h-10`，
所以资源/角色页的下拉比搜索框矮 4px，底边不齐。

**做法**：

- `ui/select.tsx`：`h-9 → h-10`、`ring-1 → ring-2` + `ring-offset-2`、`bg-transparent → bg-background`
  —— 与 `Input` 逐项对齐（这是 `design-system.md` 债务 5.4 的兑现）。
- 5 处手写全部换成 `<Select>`；需要按内容收窄的加 `className="w-auto"`。

## 4. 页面级对齐

- **地图 / 谜题页的视图切换器**：外框原来是 `p-1` + `size="icon"`（40px 按钮）→ 整块 **48px 高**，
  比同一行的搜索框、排序下拉（40px）高出 8px。改成外框 `h-10 px-1` + 按钮 `h-8 w-8`，
  按钮在 40px 框内居中（含 border 后内容区 38px，32px 按钮上下各 3px）。
- **资源页筛选行**：状态下拉带 `w-full`，在 `flex flex-wrap` 里会独占一整行，把类型分段控件
  挤到上一行。改 `w-auto` 后两者并排，与角色页的「筛选只有一行」节奏一致。

## 5. 空状态统一

工坊五个列表页（资源 / 角色 / 地图 / 谜题 / 部署）统一为**一句说明 + 一个主按钮**：

- 部署页去掉了那个 `Rocket` 图标（其余四页都没有）。图标只留给**玩家首页**（`GamesPage`），
  那是欢迎页，本来就是另一套语言（大图标 + 两行说明 + 描边按钮）。
- 容器内边距继续保持两档：340px 窄栏用 `p-8`，全宽页用 `p-12` —— 这是按容器宽度分档，
  不是随手写的，见 `design-system.md` §3.6。

## 6. 「未保存」徽标补深色配对

`EditorToolbar` 的 amber 徽标只有 `bg-amber-100 text-amber-700`，深色界面里会跳出一块高亮浅黄。
补 `dark:bg-amber-950 dark:text-amber-300`，与 `GameDeployDialog` 的警告文案同一套 amber 档。

> 全项目剩余定色只有 4 处语义色：成功对勾 `emerald-600`、禁止符号 `red-500`、
> 部署对话框的 amber 警告（已有 dark 配对）、以及这枚 amber 徽标。它们都属于「状态色」，
> 项目没有 warning / success token，暂不扩张 token 表。

## 7. 徽标字号拉平到 11px

**问题**：同一类圆角小徽标，列表行用 `text-[10px]`，网格卡 / 页面头 / 版本对话框用 `text-[11px]`。
更糟的是**同一页面内**也不齐：资源详情页「启用中」是 `text-xs px-2`、「已停用」是
`text-[10px] px-1.5`。

**做法**：徽标一律 `px-1.5 py-0.5` + `text-[11px]`。改了 7 处：`AssetListPanel`×2、
`CharacterListPanel`、`GenderBadge`、`AssetDetailForm`×2、`CharacterDetailForm`×2。

10px 中文在 100% 缩放下已经偏小，11px 是这类徽标的实际下限；把「徽标 = 11px」定成规则后，
`design-system.md` §4.1 里那条「两档微文字」的矛盾就少了一半。

## 9. 有意不改的三件事

1. **字号收编（约 45 处 `text-[11px]`）**：值已经一致，缺的是 token。要不要把 11px 定为
   `text-2xs`、以及 `text-xs` 是否保留，属于设计系统决策，单独一步做比夹在打磨里安全。
2. **右侧抽屉标题栏 44px vs 左面板头 40px**：抽屉是浮层、不总是与面板并排，44px 给关闭按钮
   更多呼吸空间；改它会牵动抽屉内部的滚动高度。记录在案，不改。
3. **导航栏 `z-30`**：绕过 `UI_Z` 是事实，但它与 `UI_Z.drawer` 同级且分属不同堆叠上下文，
   改错会真的盖住抽屉。打磨阶段不动风险未知的堆叠，留给专门一轮。

## 10. 布局：页头、节奏与两处真实的错位

这一节是「布局优化所有页面」的落地。原则先摆出来：**自用工坊里，版式一致的收益来自
「下一次不用重新找东西」，不来自花样**。所以五页共用一套骨架，差异交给内容密度去承担。

### 10.1 页头统一成 `PageHeader`

**问题**：同一个「标题 + 一句话 + 主操作」有三套写法。

| 页面 | 主操作位置 | 按钮文案 |
|---|---|---|
| 地图 / 谜题 / 部署 | 页头右侧 | 有（「新建地图」…） |
| 资源 / 角色 | **左栏搜索行的尾巴上** | **无 —— 一个裸 `+` 图标，连 `title` 都没有** |

**做法**：新增 `components/layout/PageHeader.tsx`，五个工坊页共用。资源 / 角色的「新建」
搬到页头，左栏搜索行只留搜索框。

- 标题与副标题 `space-y-1`，比「标题块 → 正文」的 24px 紧 —— 两者是一组。
- `flex-wrap` + `gap-y-3`：窄屏主操作换行，不挤压标题。
- `min-w-0` 在左块：长标题截断自己，不会把按钮顶出去。

顺带修掉一个可访问性问题：那个裸 `+` 按钮**没有可访问名**（无文案、无 `title`、无
`aria-label`），屏幕阅读器只会读出「按钮」。

### 10.2 页面节奏：24 / 16 / 12

**问题**：地图 / 谜题页的三块（页头、工具条、列表）间距**都是 20px**（`space-y-5`）。
三块等距 = 没有层级，squint test 里工具条读起来像第三个独立板块，而它其实属于列表。
同时 `design-system.md` §4.3 写的是「页面块之间 `space-y-6`」，代码和文档对不上。

**做法**：

```
页头  ──24px──  工具条  ──16px──  列表        ← 地图 / 谜题
页头  ──24px──  主从两栏                      ← 资源 / 角色 / 部署
左栏内：搜索 ──12px── 筛选 ──12px── 列表
```

页根 `space-y-6`，工具条与列表包进 `space-y-4` 的容器。三档（24 / 16 / 12）职责分明：
**页面级 → 块级 → 控件级**。

### 10.3 网格断点倒挂

**问题**：地图 / 谜题页的网格是 `sm:2 lg:3 xl:4 2xl:5`，但正文容器上限是 `max-w-7xl`
（1280）。窗口跨过 1536px 时列数 +1、容器不变，于是**卡片反而变小**：

| 视口 | 列数 | 卡片宽度 |
|---|---|---|
| 1280 | 4 | 296px |
| 1536+ | 5 | **234px** |

窗口越宽卡片越小 —— 断点在和容器上限打架。

**做法**：撤掉 `2xl:grid-cols-5`（地图 1 处、谜题 2 处，含加载骨架），列数到 4 为止。
要更多列得先把容器放宽，那是另一件事。

### 10.4 部署行与地图行共用一套列语法

**问题**：两页都是「缩略图 + 名称 + 弹性中列 + 时间 + 操作」的行列表，却各写一套尺寸：

| 列 | `MapListRow` | 部署行（改前） |
|---|---|---|
| 缩略图 | 64×40 | **80×48**（行高 72 vs 64） |
| 名称 | `w-48` | **`w-56`** |
| 时间（同一个 `formatDateTime`） | `w-52` | **`w-44`** |
| 操作 | `w-40` | **`w-32`** |

**做法**：部署行对齐到 `MapListRow` 的档位。改完两页行高都是 64、右边缘都在同一列上，
在两个页面之间来回切不再有「表格跳了一下」的感觉。

### 10.5 三处零碎错位

| # | 问题 | 做法 |
|---|---|---|
| 1 | `AppShell` 顶栏 `h-14` 写死，导航却 `flex-wrap` —— 窄屏换到第二行会被 56px 的框裁掉、压在正文上 | 改 `min-h-14` + `py-2`。宽屏仍是 56px（36px 内容 + 16px 内边距 < 56，取大），窄屏自然长高 |
| 2 | 资源页筛选行：分段控件 32px、右侧下拉 40px，同一行下边缘差 4px | 分段控件加 `h-10`，按钮随 flex 拉伸填满 —— 一行只允许一种控件高度 |
| 3 | 角色页状态下拉 `w-full`，在 340px 窄栏里是一条横贯整栏的空框；资源页同一件事却是 `w-auto` | 统一 `w-auto`，读成筛选芯片 |
| 4 | 404 用 `py-24` 挂在正文顶端下面一截 | 改 `min-h-[60vh]` 居中，与路由加载占位同一档 |

### 10.6 看过但**没有**改的

- **编辑器（地图 / 谜题）与两个预览页**：整版是 `h-screen flex-col overflow-hidden` +
  `h-14 shrink-0` 顶栏 + `min-h-0 flex-1` 主区，四块（左面板 280 / 画布 / 抽屉 320 /
  浮动工具条）的位置由画布决定，没有可收敛的「页面版式」。四者的顶栏都是 `h-14 px-4`，
  已经是一套。
- **左栏 `sticky`**：曾想让资源 / 角色页的左栏跟随滚动（改长表单时列表不丢），**放弃** ——
  左栏内容是「搜索 40 + 筛选 36 + 虚拟列表 480 ≈ 590」，视口高度低于 590 + 80（顶栏 + 间距）时，
  固定定位会让左栏底部永远滚不到。要做对得先把虚拟列表高度改成视口自适应，属于另一轮。
- **详情卡片的 `p-6`**：全项目卡片是 `p-4`，只有主从页右栏是 `p-6`。这是**表单页**，
  需要更多呼吸，保留。

## 11. 配色：墨 · 宣 · 靛 · 绛

这一节是「优化所有页面和功能的颜色」的落地。原则：**换掉整块调色板 + 让颜色承担状态含义**，
不改版式、不加装饰、不动作品内容色。

### 11.1 为什么是这四个颜色

| 角色 | 取色 | 为什么 |
|---|---|---|
| 底 / 字 | 宣纸 `40 30% 96.5%` → `#F9F7F3`；墨 `28 14% 12%` → `#231E1A` | 中性色相挪到 28–40（暖），不再是 210–217 的冷灰。这是「纸感」的全部来源 —— 不靠贴纸纹理，靠中性色的色相。 |
| 交互（primary） | 石青 / 靛 `205 45% 36%` → `#326385` | 青花瓷蓝压在一张米黄纸上。饱和度从 83% 砍到 45%：它要当**墨线**用（选中框、活动 tab、链接），当宝蓝用会跳出来喊。 |
| 危险（destructive） | 绛 `2 58% 46%` → `#B93631` | 与 logo 的 `#5C2223` 同族，比纯红灰一档。朱批的颜色，不是警告牌的红。 |
| 状态 | 竹青 `#2F6A4E` / 赭石 `#8C4E17` | 见 §11.2。 |

深色是反相的「夜墨」：底 `#1A1714`（暖黑，不是 `#000`），primary 抬成浅靛 `#75A9C7`
配墨字，绛抬成 `#D06F6C` 配墨字 —— 与浅色下「深底浅字」的关系对称。

**没选的两条路**，记下来免得以后重新纠结：

- *全黑白的书斋风*（primary 也是墨色）。干净，但选中态和描边会退化成同一个黑，
  编辑器的「这块被选中了」就没了第二层信号。
- *朱砂当 primary*。最「东方」，但 `destructive` 也是红 —— 保存按钮和删除按钮
  同色，在 AlertDialog 里会出事。绛只留给危险，朱砂的味道靠 logo 撑着。

### 11.2 状态色：从「灰徽标」到「有含义的徽标」

加两个 token（`index.css` 明暗两套 + `tailwind.config.ts` 暴露）：

```css
:root { --success: 152 38% 30%;  --warning: 28 72% 32%; }
.dark { --success: 150 32% 62%;  --warning: 34 65% 62%; }
```

徽标写法统一为 **`bg-success/10 text-success`**（`/10` 是刻度内的透明度，
原因见 §11.6）。落地的地方：

| 位置 | 原来 | 现在 |
|---|---|---|
| 资源 / 角色详情「启用中」 | `bg-secondary` 灰 | `bg-success/10 text-success` |
| 资源 / 角色详情「已停用 / 未启用」 | `bg-muted` | 不变（停用就该安静） |
| 编辑器工具栏「已发布 v3」 | `bg-secondary` 灰 | `bg-success/10` |
| 编辑器工具栏「草稿」 | `bg-secondary` | 不变（草稿是常态，不该染色） |
| 版本对话框「当前」 | `bg-secondary` | `bg-primary/10 text-primary` |
| 版本对话框 / 谜题列表 / 谜题卡「已部署」 | `bg-secondary` | `bg-success/10` |
| 编辑器工具栏「未保存」（§6 那枚 amber 徽标） | `amber-100 / amber-700` + 手写 `dark:` | `bg-warning/10 text-warning` |
| 部署页「已复制」对勾 | `text-emerald-600` | `text-success` |
| 部署对话框「原路径将失效」 | `amber-600 / dark:amber-500` | `text-warning` |
| 玩家页「排除」工具图标 | `text-red-500` | `text-destructive` |
| 玩家页「提交未通过」原因徽标 | `bg-secondary` 灰 | `bg-destructive/10 text-destructive` |

原则：**只有「状态」染色，「元信息」保持中性**。`v3`、`12 × 12`、`背景 / 物品`
这类徽标仍然是 `bg-secondary` —— 它们是名词，不是状态，染了就变成装饰。

> §6 曾经判断这 4 处语义色「项目没有 warning / success token，暂不扩张 token 表」——
> 本节就是那个「暂」的兑现，`emerald-600` / `red-500` / amber 两处全部收编。

### 11.3 深色模式下真的坏掉的三处

这三条不是审美问题，是功能问题：

1. **`text-destructive` 在深色下只有 2.0:1**。旧的 `.dark --destructive: 0 62.8% 30.6%`
   在 `222 4.9%` 的底上几乎看不见 —— 而它被用在 59 处（删除图标、表单错误提示）。
   抬到 `2 52% 62%`（5.27:1）。顺带把浅色也从 `0 84% 60%` 压到 `2 58% 46%`
   （3.76 → 5.39）：这个 token 同时当文字和填充，只有 L46 是两边都过 AA 的一档。
2. **保存蒙层是写死的白**。`EditorShell` 的 `rgba(255,255,255,0.6)` 在深色下点保存时
   会在一整屏深色上糊一层白。改成 `hsl(var(--background) / 0.7)`。
3. **难度徽标是 5 个浅色 hex**（`#DCFCE7 / #ECFCCB / #FEF9C3 / #FFEDD5 / #FEE2E2`），
   深色下跳出 5 块亮补丁。改成 CSS 变量对（`--difficulty-*-bg` / `-fg`），明暗两套；
   `shared/constants.ts` 里那两条常量现在存 `var(...)`，三个调用处（游戏卡、部署行、
   部署对话框）一行都不用改。色相是「竹青 → 芽绿 → 赭黄 → 柿橙 → 绛」的**单向热力坡**
   —— 它是一根刻度尺，不是五个分类色。

顺带一处：地图「缩放」对话框的预览网格原来写死 `rgba(239,68,68,.25)` /
`rgba(34,197,94,.25)`，现在是 `destructive` / `success` 的 22% 淡染 ——
「要移除的格子 / 留下的格子」本来就是这两个语义。

### 11.4 导航：全站唯一的「你在哪」

顶栏五个入口的选中态从**中性灰实心**换成 `bg-primary/10 text-primary`。

理由：冷蓝时代整块顶栏没有一点颜色，导航选中和悬停靠一档灰的深浅区分，扫视成本高。
工具条（`--toolbar*`）**保持中性**，不跟着染色 —— 画布上已经铺着 primary 的选框和
虚线预览框，两处都染色会打架。

### 11.5 toast

`sonner` 的 `richColors` 用的是它自带的 5 组 Tailwind 淡色（成功 `#ecfdf3`、信息
`#f0f9ff`），在宣纸和夜墨上都像贴纸。现在把它的 5 组变量改指向本项目 token：
**底色永远是卡片，只有文字和描边带状态色**。

这里有个坑：sonner 在组件挂载时把样式插到 `<head>` **末尾**，所以覆盖选择器必须比
`[data-sonner-toaster][data-theme='light']` 更具体，写成 `html [data-sonner-toaster][data-theme]`。

### 11.6 踩到的坑：`/12` 不在 Tailwind 的透明度刻度里

徽标一开始写的是 `bg-success/12`。构建完全静默 —— 类**没有生成**，徽标会变成没有底色
的一行字（`/12` 不在 Tailwind 默认的 `opacity` 刻度 0/5/10/20/…/100 里）。
改成 `/10` 后产物里确认有：

```css
.bg-success\/10{background-color:hsl(var(--success) / .1)}
```

**教训**：用非标准透明度必须写 `/[0.12]`，并且构建后去 `dist` 里 grep 一下类名 ——
这类失败不会报错，只会「样式没生效」。

### 11.7 有意不改

- **作品内容色**：地图背景、资源色块与外观、区域色、区域标签字体颜色、难度以外的
  画布颜色（`MapGameLayers` 的描边、`region.ts` 按亮度选的黑/白文字、
  `ParticipantPanel` 的 `#1F2937`）。判据是 `.impeccable.md` 原则 4：
  **它会不会被导出到游戏里** —— 会，就不属于皮肤。
- **画布的 `HIGHLIGHT_BLUE = '#90CAF9'`**：搜索命中框、操作光标、效果色共用它。
  它要压在**任意颜色的地图美术**上，不能跟着界面主题走（浅蓝在深色美术上也读得出）。
  改它会牵动 `canvasLayers.test.ts` 的 4 条断言，收益是零。
- **`--radius: 0.5rem`**：`design-system.md` 债务里记着「压到 0.25–0.375 会更纸/木」，
  但那是形状不是颜色，留给下一轮单独做（改它等于改每个组件的观感）。
- **`--toolbar` 仍与 primary 并列存在**：没有把它并进 `secondary`，因为
  「工具条选中」和「次级按钮」在深色下的对比需求不同（前者要压过画布）。
