# v0.5.5 · 收尾：清理、精简与文档

> 版本定位：**不新增任何功能**，只做仓库卫生。五条任务全部是「让下一个打开这个仓库的人（人或 Agent）更快进入状态」；第一轮交付后又追加两条更锋利的清理要求（§1 第二段、§6），合共七条。

---

## 1. 需求原文

```
v0.5.5
- 清理测试中间产物
- 精简优化掉一些注释
- 精简优化掉一些测试用例
- 简化 README.md
- 生成 AGENTS.md
```

第一轮交付后又追加了两条更锋利的清理要求（原文照录）：

```
- 删除低价值注释，类似「// FEAT-K01: 谜题（原「作品」）」这种注释和文本修改等注释，
  这类只存在历史文档中的词，没必要遗留在注释中，都可以删除
- 删除低价值测试用例，例如 brandLogo.test.tsx 这种检查文本的，
  一个文本改动或调整，没必要写测试用例，这样会增加测试成本
```

对应本版 §6（CLEAN-02）。

---

## 2. 总体思路

v0.5.0 ~ v0.5.4 连续五个版本都在**加东西**，仓库里积累了三类只有成本没有收益的存量：

| 类型 | 症状 | 本版处理 |
|---|---|---|
| 生成物 / 中间产物 | `dist` 里躺着编译过的测试文件；每个包都有一个 `vitest.config.ts.timestamp-*.mjs` | 删掉，并且**堵住产生它的配置**（否则下次 build 复发） |
| 逐版累积的注释 | 一段注释解释的是 v0.3.x 的某次决策，读代码的人要先读三段历史才能知道现在是什么 | 压缩成单行 / 短块，**一条决策引用都不丢** |
| 逐版累积的测试 | 同一个契约在物品 / 角色、背景层 / 物体层各写一遍；32 个测试文件各带一份 8 行 glob 前导 | 能合并的合并成 `describe.each`，能共用的抽成 helper，纯健全性用例删掉 |

原则：**压缩篇幅，不压缩信息**。凡是带 `OPT-*` / `FEAT-*` / `SPEC-*` / `MOD-*` / `BUG-*` / `FIX-*` 编号的注释一律保留（那是回查需求文档的索引），只把叙述性文字压掉。

第二轮（§6）把第一轮的保守边界推翻了两处：**「这里故意不叫 X」式注释**与**品牌 / 页面文案测试**。第一轮担心「删了防回退的锚点，后人重新踩坑」，但追加要求点破了真正的成本结构——这类锚点守护的是**一次性的改名动作**，而它会让此后**每一次**文案微动都付出一轮改测试的成本。锚点的价值是递减的（改名完成后历史就翻篇了），测试的成本是持续的。

## 3. CLEAN-01 清理测试中间产物

### 3.1 删掉的产物

| 路径 | 数量 | 说明 |
|---|---|---|
| `packages/{server,shared}/vitest.config.ts.timestamp-*.mjs` | 28 | Vitest 的配置缓存戳，每次跑测试重写，进 git 纯属噪音 |
| `packages/shared/dist` | 1 | 构建产物（且含有编译后的测试文件，见 3.2） |
| `packages/web/dist` | 1 | 构建产物 |

**没有删**：`packages/server/storage/uploads/**`（251 个文件 / 1.6 MB）。它是 gitignore 的运行时数据，**数据库行引用这些图片**，删了会让已部署游戏与详情页的头像 / 物品图全部 404。

### 3.2 根治：`shared` 不再把测试编译进 `dist`

`packages/shared/tsconfig.build.json` 原本是：

```jsonc
{
  "include": ["src/**/*.ts"]
}
```

`src/**/*.test.ts` 因此被一起编译，`dist` 里出现 `constants.test.js` 这类文件。消费者（server / web）通过 `package.json` 的 `exports` 直接引 `./src/*.ts`，**编译后的测试文件对任何人都没有用途**。

改为：

```jsonc
{
  "include": ["src/**/*.ts"],
  // v0.5.5 CLEAN-01: consumers import ./src/*.ts via `exports`, so emitting
  // compiled **tests** into dist/ was pure clutter.
  "exclude": ["src/**/*.test.ts"]
}
```

> 踩坑记录：第一次只写了 JSONC 注释、漏写 `exclude` 数组本身，`tsc -b` 静默通过、`dist` 依旧有 `.test.js`。JSONC 的注释不会改变语义。

验证：`npm run build -w @loredoku/shared` 后 `ls dist | grep -c test` = **0**。

## 4. OPT-01 精简注释

### 4.1 做法

用 Python 精确替换脚本逐文件压缩，每个替换都带 `raise SystemExit('MISS: …')` 断言——**匹配不上就当场失败**，不允许静默漏改。每批改完立刻 `npm run typecheck` + 跑 shared / server 测试。

压缩手法：多行叙述块 → 单行或 3~4 行短块；把「历史 + 原因 + 结论」三段式压成「结论 + 编号」；示例表格压成一行。**所有决策编号原样保留**。

## 5. OPT-02 精简测试用例

### 5.1 抽取共享源码读取入口（本版最大的一块）

精简前，每个源码级测试文件都带一段 8 行前导：

```ts
const sources = import.meta.glob('./**/*.{ts,tsx}', {
  query: '?raw',
  import: 'default',
  eager: true,
}) as Record<string, string>;
```

**32 个文件、54 处 glob 调用**，而且是同样三个决定的重复：raw 导入、eager 加载、`\r\n` 归一化。更要紧的是 key 形态随文件所在目录漂移（`'./X.tsx'` vs `'../item/X.tsx'`），迁移一个文件就可能让另一处断言静默拿到 `''`。

新增 `packages/web/src/testing/source.ts`（85 行，非测试文件），作为**唯一入口**：

| API | 用途 |
|---|---|
| `readSource(path)` | 读 `src/<path>` 原文，CRLF 已归一化。**路径一律相对 `src/`** |
| `codeOf(path)` | 上面的结果再剥掉块注释与整行 `//` 注释 |
| `productionKeys()` | 全树生产代码路径（排除 `*.test.*`） |
| `tsxIn(dir)` | 某目录下所有 `.tsx` 的 `[path, source]` |
| `segment(src, start, end)` | 切出大文件里的某一个函数；标记找不到 **throw** |

glob 用字面量 `/src/**/*.{ts,tsx}`（Vite 静态展开，且从任何测试目录都命中同一批文件）。迁移后：

- `import.meta.glob` 在 `packages/web/src` 下**只剩 helper 里那一处**（其余两处是注释里的说明）；
- 4 个测试文件里各自重复定义的 `stripComments` 全部删除，改调 `codeOf()` / `stripComments()`；
- 3 个文件里各自重复定义的 `segment()` 全部删除，改调 helper 版。

> 迁移是分批做的，中途确实出了几次事故，都记在 §13 裁定里（Python 行式替换越界吞代码、`readSource` 收到 glob pattern 等）。**结论：这类机械重构要逐文件跑测试，不能只靠 typecheck。**

## 6. CLEAN-02 第二轮：删历史名词注释与文案测试

> 对应 §1 第二段需求原文。第一轮做完五条任务后追加的两条，执行对象正是第一轮**明确保留**的两类——§4.3 的「镜像注释」与 §5.3 点名的 `brandLogo.test.tsx`。

### 6.1 判定规则：什么算「低价值」

「都可以删除」动手前先把边界钉死，否则会顺手删掉结构性防护：

| 删 | 留 |
|---|---|
| 读源码 + grep 文案字符串的断言（`expect(source).toContain('<中文>'`、`not.toContain('<中文>'`） | **渲染级**断言（`createRoot` + `act`，查 DOM 而不是查源码文本） |
| 改名记录注释（`原「作品」`、`became`、`is gone`、`went away`） | 结构标识符（英文组件名 / prop / hook / 常量名，如 `id: 'items'`、`MAP_LAYER_ORDER`） |
| 删除记录注释（「X 字段已删」「X 路由已不在」）与文件头历史段 | 夹具数据、校验与行为提示信息（`gameSlug` 校验文案、`puzzleRefs` 错误信息、放置层提示） |
| —— | `not.toContain('<死字段名>')` 这类**结构性死代码防护**（`item_triggers`、`linkageColors` 不再出现） |

一句话：**测试守护「现在的规则」，不守护「历史上的某次改名」**。前者在规则变化时才需要同步，后者改完就该退役。

### 6.4 结构契约不一起删：`EditorBottomBar` 的 label → id

const ids = Array.from(tabs.matchAll(/id: '(\w+)'/g)).map(m => m[1]);

## 11. 测试计划

本版没有新功能，测试策略是**回归 + 结构性自检**：

1. 每批注释精简后立刻 `npm run typecheck` + 跑 shared / server。
2. 每批测试迁移后跑受影响的文件；全部迁移完跑三包全量。
3. 结构性自检（脚本化，不靠肉眼）：
   - `grep -rn "import.meta.glob" packages/web/src` 应只剩 `testing/source.ts` 一处；
   - 每个从 helper 导入的名字都在文件里被用到（防留下未用 import）；
   - 测试文件里不出现连续三个空行（机械替换的残迹）；
   - `find packages -name "*.test.*"` 的行数对比 HEAD。
4. 交叉重复检测：对所有 `it()`  body 做归一化哈希，找出跨文件的逐字重复（抓到了 §5.3 后两条）。
5. 第二轮（§6）每个文件改完立刻逐文件跑，另加两个结构自检——机械删除最容易留下的两种残迹：
   - **空用例**：`it('…', () => {})`（掏空了断言却忘了删 `it` 行）——抓到 1 处，`EditorPage.publish.test.ts` 因此仍报 14 例；
   - **嵌套块注释**：`/**` 行紧跟 `/**` 行、`*/` 行紧跟 `*/` 行（替换的起止子串落在注释块内部）——抓到 7 处，typecheck 一度报 40 个错误，见 §13 R14。
