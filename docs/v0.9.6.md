## §1 偏移是什么

区域标签现在钉在 `labelCell` 的**上沿居中**（`left = (x + 0.5) * cellSize`、
`top = (y + 1) * cellSize - 2`）。这个锚点对多数区域合适，但标签可能压到相邻的
桌沿、物品或另一块区域的轮廓上 —— 而 `labelCell` 只能整格地挪，「往右 12px」
这种微调做不到。

这一版给每块区域各加一份偏移：

```
left = (anchor.x + 0.5) * cellSize + offset.x
top  = (anchor.y + 1) * cellSize - 2 + offset.y
```

| | 值 |
|---|---|
| 单位 | **画布像素**（随 `zoom` 缩放，不随格子大小变） |
| 范围 | `-200 … 200`（`REGION_LABEL_OFFSET_MIN/MAX`） |
| 缺省 | `{ x: 0, y: 0 }` |
| 存哪 | `DraftRegion.style.label.offset`（可选，两轴都可缺） |

**为什么是画布像素而不是格子比例**：「往右 12px」在 4×4 和 12×12 的盘面上说的是
同一件事；「往右半格」会随格子大小漂移，而作者调偏移时想的是「这枚标签压到别的
东西了」，不是「按格算的间距」。它跟着纸一起 `transform`，所以缩放时不必另算。

**为什么上下限存在**：超过一格半之后作者自己也说不清标签跑哪去了，而工具栏里
没有「标签在画面外」这种提示。±200 足够推到相邻两三格之外。

## §2 数据形状

```ts
// 存储侧（只记差异）：两轴都可缺
export interface RegionStyleOverride {
  outline?: Partial<RegionLineStyle>;
  highlight?: Partial<RegionLineStyle>;
  label?: Partial<RegionLabelStyle> & { offset?: Partial<RegionLabelOffset> };
}

// 解析侧（渲染读的那一份）
export interface RegionStyle {
  outline: RegionLineStyle;
  highlight: RegionLineStyle;
  label: RegionLabelStyle;
  /** v0.9.6：区域标签的位置偏移。缺省 `{ x: 0, y: 0 }`。 */
  labelOffset: RegionLabelOffset;
}
```

**偏移挂在 `RegionStyle` 这一层，不塞进 `label`**：

- `RegionLabelStyle` 是 `MapStyleRegionLabel` 的别名，而地图级缺省**不该有**
  「标签往哪偏」这一项 —— 它对一块区域合适、对另一块就不合适。塞进 `label`
  会让 `DEFAULT_MAP_STYLE`、`mapStyleDiff` 的字段表、主题风格表单都被牵连，
  而那些地方根本没有这个值。
- 单独的 `labelOffset` 让存储变体也直白：`RegionStyleOverride.label.offset`
  与其它 label 字段同一条「只记非 0」的规矩，两轴都 0 时整块不落盘。

**为什么存储侧允许一轴缺席**：只改横向的作者不该被迫填纵向。解析时缺席按 0 算。

## §3 编辑入口

`RegionStyleEditor` 是两处共用的（地图基本信息的「区域」缺省 + 区域信息）。
这一版给它加一个 `showOffset` 开关：

| 位置 | `showOffset` | 理由 |
|---|---|---|
| 区域信息（`EditorInfoDrawer`） | **开** | 偏移属于这块区域自己的标签 |
| 地图基本信息（`MapInfoDrawer`） | 关 | 地图级没有这一项；给了也是 0，改了没地方存 |

没有把组件抄一份：两处的排版（字体 / 字号 / 描边 / 高亮 …）必须永远一致，
一个开关比重写一遍便宜，也不会分叉。

「位置偏移」那一行是两个 `NumberField`（后缀 `x` / `y`），嵌在「区域标签」小节
底下 —— 它调的是同一件事（这枚标签长在哪），不该另起一节。

## §5 没做的

- **不给偏移加「拖拽标签」的直接手势**。画布上拖标签听起来更快，但标签是
  `pointer-events-auto` 的按钮（点它是选中区域），拖拽会和「点一下选中」抢手势；
  而且偏移只有 ±200 这个量级，输入框够用。
- **不做「整块区域的标签一起偏」的地图级缺省**。地图级缺省对所有区域生效，而
  需要偏移的通常只有一两块 —— 给全局加一项会让另外那几块也跟着动。
- **不让偏移跟随格子比例**。见 §1：作者调的是「推开一点」，不是「按格算间距」。
- **不在 `mapStyleDiff` 里加这一项**。那是「主题缺省 vs 地图」的对照表，而偏移
  没有主题级/地图级的存在形式。
- **不为偏移单独做撤销粒度**。它和字体、字号一样跟着区域保存走一次撤销步 ——
  拆细之后，改一个数值要按两三次撤销才回得去。

## §6 计时规范与三个时间

用户原文（逐条照录）：

> - 首次进入，开始从 00:00 计时
> - 离开时，记录时间 a
> - 再次进入，从 a 开始继续
> - 提交时，暂停计时 b
> - 通过时，记录为完成时间 c；后续都是 00:00 开始
> - 未通过，点击取消继续游戏时，从 b 继续计时；如果重新开始，则从 00:00 开始
> - 已完成再次进入，定格 00:00，点再玩一次时再开始计时
>
> 三个时间：
> - 计时：进行游戏就会计时
> - 完成时间：记录最后一次完成时间（重复完成，仅记录最后一次）
> - 最后离开时间：上一次游玩离开的时间

**a / b / c 都是计时读数（`mm:ss`），不是墙钟时刻**：「再次进入，从 a 开始继续」
只有在 a 是累计用时时才说得通；卡片占位符也写的是 `00:00`。

| 时间 | 存哪 | 谁读 |
|---|---|---|
| 计时（累计用时） | `loredoku.game.timer.<id>` 的 `elapsedMs` | 游戏页、卡片 |
| 完成时间 | `loredoku.game.completed.<id>` 的 `elapsedMs` | 卡片（优先） |
| 最后离开时间 | 同一条计时存档的 `elapsedMs` + `leftAt` | 卡片（无完成记录时） |

**「最后离开」不另开一条键**：它和累计用时都在「离开这一局」时落盘，两者是同一
份存档的两个字段。`leftAt`（ISO 墙钟）只供卡片 `title` 悬停，版面显示的是
`formatElapsed(elapsedMs)` —— 用户要的 a 是读数。

**完成记录改为「最后一次为准」**：v0.9.5 是首次为准（当时把卡片读成凭证、不是
排行榜），用户明确「重复完成，仅记录最后一次」后改成覆盖写。

**`resetGameTimer` 只归零用时、不删键**：「重新开始」= 这一局从 00:00 重来，但它
仍然是「我来玩过」，卡片该显示 `00:00` 而不是退回「从没玩过」。旧实现里
`writeGameTimer(…, 0)` 直接删键，会把这个语义一起抹掉。

**已完成再次进入**：水合时读到有效完成记录 → `startFrom = 0`、
`runningSinceRef = null`、`timerRunning = false`、`finished = true`。表定格 00:00，
`replay()`（遮罩上的「再玩一次」）才把它放回跑道。

## §7 卡片版式（第二行）

```
（左边）n × n   难度        （右边）【时间图标】00:00
```

- 时间格按「**完成优先，否则取最后离开**」挑一个（用户确认的口径）：
  有完成记录 → 那一局的完成用时；没完成但玩过 → 上次离开时表上的读数；
  都没玩过 → `00:00`。
- **版面上不加「完成 / 离开」前缀**：用户给的占位符是「【时间图标】00:00」，
  图标已经说了「这是一格时间」；12 张卡的页脚再各加两个字会挤成一团。具体是
  哪一种，交给 `title`（悬停才看）。
- **已完成卡片在印章基础上加「定案」两个字**。v0.9.5 是「没配印就整块不画」
  （理由是「空蒙版弄脏封面」）；加了文字之后这条理由不成立 —— 「定案」本身就说
  清了状态，所以覆盖层现在总是出现，印仍只在配了图时画。

## §8 定案遮罩与结算

用户原文：

> 游戏校验通过后，将地图方格用遮罩遮住，上面展示和谜题卡片一样的定案+印章
> （位置也相同）放在地图遮罩上，印章添加印下去的动效。然后再弹窗。
> 校验通过后，右侧按钮都置灰不能用。
> 已完成的游戏再次进入时，还是校验完成时的效果，但左中右测遮罩不用展示，只留
> 地图方格遮罩，同时再有个再玩一次的按钮在遮罩上。
>
> （追加）定案弹窗里的印章和动效就不需要了。

**三处共用一张脸**：`VerdictMark.tsx` 提供「定案在上、印在下、竖排居中」，卡片封面
与地图遮罩都调它（`large` 只放大、不改排法）。用户说「位置也相同」—— 分两套排法
迟早会在某一版里一横一竖。

**通过的两段节奏**：逐人校验圈完 → **撤掉圈与四处校验遮罩**、盖上定案遮罩
（`GAME_VERDICT_HOLD_MS = 1000`，让 `.stamp-press` 420ms 的动效落定）→ 弹结算卡。
圈是过程、定案是结论，两样同时在场会读成「还在校验」。未通过照旧立刻弹。

**结算卡不再有印章**：印是「盖在纸上」的东西，弹窗是一张浮起来的卡；搬到遮罩
之后卡里再放一枚就成了重复播报。

**右侧四枚按钮置灰**：`toolsLocked = finished`，标记 / 清除 / 回退 / 提交一起
`disabled`。棋盘已经定格在结案那一帧，再摆一颗头像改的是一局已结束的棋；要动
就得先点「再玩一次」。

**「再玩一次」的判定**：结算卡**没开着**时遮罩上就有它。刚通过 + 卡还开着时不画
（卡里已有同一颗）；关掉弹窗后补上 —— 否则按钮全灰、遮罩盖着棋盘，玩家没有出口。
已完成再进入时直接有。

## §10 没做的（计时 / 定案部分）

- **不给「完成 / 离开」两种时间加文字前缀**。见 §7：图标已经说明这一格是什么。
- **不把 `leftAt` 显示成墙钟时刻**。a / b / c 是计时读数，墙钟只进 `title`。
- **不在弹窗里保留印章**。用户明确「定案弹窗里的印章和动效就不需要了」。
- **不做「已完成 3 / 8」这类计数**。这次用户只要卡片上的时间与印。
- **不给偏移 / 定案做额外的撤销粒度**。跟着各自那次保存走一步。
