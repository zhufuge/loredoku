# v0.11.9 — 品牌字标换成活字

## 0. 范围与口径

一句话：页头那枚品牌字标从**图片**换成**文字** —— Courier Prime Sans 的 `LOREDOKU`。
logo 图片本身留在仓库里（用户要求不删），只是不再被任何代码引用。同一版里还给游戏列表页
铺了一层落花背景（§5）。

口径四条：

1. **字体走现成管线**：源 ttf 放 `packages/web/fonts-source/`（已 gitignore，不进提交），
   `npm run fonts --workspace @loredoku/web` 按 `--charset common` 裁成 woff2 落进
   `packages/web/src/assets/fonts/`。这个目录被 `lib/fonts.ts` 的 `import.meta.glob`
   自动登记进 `document.fonts`，制作端与播放器两个入口在启动时各调一次
   `registerBundledFonts()` —— 不需要新增任何注册代码。
2. **仍是黑 + 朱两色**：八个字母走前景色，第 3–5 个（RED）走 `.loredoku-ink-red`，
   与加载字标（`LoredokuLoader`）同一条规则、同一支朱。
3. **`height` 口径不动**：页头 22、`AppShell` 20、播放器 16，调用点一处没改。
4. **入口无变化**：两个 Vite 入口都 `import '@/index.css'`，样式与字体自动同时在。

## 2. 设计裁定：一行字怎么排

**尺寸。** 旧图在 `height` 那个框里只画 16.19px 高的墨迹（22px 档，`viewBox` 四周是留白，
`docs/v0.5.6.md` §14.3 量过），所以「标题多大」的既有答案是 **`height` 的 73.6%**。
活字没有那圈留白，于是字号按墨迹等高倒推：`LOREDOKU` 全大写，墨迹高就是大写高，
即字体的 `sCapHeight`（1187/2048 em）：

```
fontSize = round(height × 0.736 ÷ 0.5796)      // 22 → 28、20 → 25、16 → 20
```

**行高不压。** 行盒交给字体自己的度量（这台机器上 `normal` 是 `1.5em`），不去按 `height`
反推行高：墨迹在盒里的位置只跟字号有关，行高只决定盒比墨迹高出多少 —— 压行高能省下的
那几像素，正好是字母上下的伸缩余量，省掉它们只会让行盒与墨迹挤在一起。
于是容器的盒高比 `height` 高（22 档 → 42），宿主行也跟着长高一点（列表页页头行 36 → 42）。

**上下对齐。** 要对齐的是两段字的**墨迹框**，不是基线：中文墨迹整体压在基线下约 `0.03em`，
拉丁大写只坐在基线上 —— 只把基线摆平，字标看着还是高一截（先试过 `align-items: baseline`，
量下来仍然高 2px 左右，弃）。整串字 `translateY(0.071em)` 把大写墨迹压到与「· 格物」同高同底。
这个数是量的，不是算的：3× 放大逐列扫墨迹，`111–161` 对 `110–161`（图像 px，÷3 即 CSS px）。
它是 `em` 值，字号按 `height` 走，所以 22 / 20 / 16 三档同时成立。

**语义。** 它已经是文字了，不再冒充图形：去掉 `role="img"` / `aria-label`，屏幕阅读器按常规
读 `LOREDOKU`。`data-testid="brand-logo"` 保留（旧测试与文档都按这个名字找它）。

**外层可以压字号。** 字标与「· 格物」两个字号都读 CSS 变量（`--brand-size` /
`--brand-wordmark-size`），不给就按 `height` 算。列表页在窄屏把字标收到 22 / 14、主题名抬到 24，
一屏里「这是哪个世界」比「这是哪个产品」重要；两个字号同比例缩，墨迹对齐的 `em` 位移跟着走。

**为什么逐字母拆 `<span>`。** 只为一件事：让 RED 三字母上朱色。等宽字体的字距不靠
kerning，拆开不动间距。

**字还没到时。** `registerBundledFonts()` 只登记不预载，首帧可能落在回退链上；回退链给的
是等宽（`ui-monospace` / `Courier New`），宽度几乎一致，不会跳版。播放器的
`loadBundledFonts()` 用汉字采样串预载，Courier 没有汉字、不会被它拉下来 —— 这是有意的：
字标不是首屏正文。

## 5. 游戏列表页的落花

`GamesPage`（`/:code/play`）铺了一层落花背景：`PetalField` 固定满视口、`pointer-events-none`、
`aria-hidden`，始终压在最底层当背景，页面滚动时一直在动。

**切精灵图。** `assets/peach_petal_sprites_16.png` 是 8 × 8 的 16px 格子（64 片蜜桃色花瓣，
朝向各不相同），`background-size` / `background-position` 按每片的目标尺寸算 —— 不拆成 64 张图，
也不上 canvas。

**上场几片。** 不写死总数：片数 = 视口面积 ÷ `areaPerPetalPx`，再夹在 `minPetals`–`maxPetals`
之间 —— 手机上一小把，宽屏上多得起来但不会铺满。只在挂载时算一次：落花是背景，转屏 / 拖窗口
时重排等于把正在下的花重洗一遍，那一下比密度不完美更扎眼。

**深度。** 每片抽一颗 `depth`（0 远 → 1 近），大小、透明度、亮度、饱和度按它插值，模糊与下落
速度取反：越远越小、越淡、越糊、越慢、摆幅越窄。纵深感是这一颗数推出来的，不是五条独立随机数 ——
独立随机会出现「又大又糊还落得慢」这种不存在的花。

**不折线。** 纵向落与横向摆拆成两条动画：纵向匀速落走 `translate` 属性（`petal-fall`，linear），
横向摆 + 自转走 `transform`（`petal-drift`，`ease-in-out` + `alternate`）。横向掉头时
先减速到 0 再反向加速，所以看不到原来那种「走到边上猛一折」的直角。两条各写各的属性，互不覆盖。

**翻面单独一层。** 翻比摆动慢，一条动画塞不进两个时长，所以花瓣是两层元素：外层摆、内层翻
（`.petal-flip` 只做 `perspective(240px) rotate3d(轴, ±flipDeg)`，精灵图也挪到这一层，翻的是花本身）。
`flipDeg` 压到六十来度起步、不到一百二（初版到 260°，会整片翻到背面）；`rotate()`（z 轴）
另给一点倾角，两轴一起转才不像贴纸。周期由 `TUNING.flipS` 单独控制，比 `driftS` 长。

**翻面的轴也是随机的。** 全绕竖轴转，一屏花像一排翻书页；轴改成花平面里的随机一条线
（`--petal-flip-x/y` = `cos θ, sin θ`，`θ ∈ [0, π)`）：横轴上下翻、竖轴左右翻、斜轴斜着翻，
同一屏里三种都有。0°/90° 是偶发，大多数落在中间，这才是花瓣被风吹时的样子。

**旋钮。** 全在 `PetalField.tsx` 顶上的 `TUNING`：`sizePx` / `opacity` / `brightness` /
`saturation` / `blurPx` / `areaPerPetalPx` / `minPetals` / `maxPetals` / `durationS` / `driftS` / `flipS` / `swayVw` / `spinDeg` / `flipDeg`，都是区间或阈值。
改一处即可，组件不吃 props。

**一道灰边。** 花瓣本身是奶油色，贴在纸色背景上等于没有；`filter` 末尾垫了一层
`drop-shadow(0 1px 2px hsl(var(--foreground) / 0.14))` —— 浅色下是灰边，深色下是微光。

**减少动态。** `prefers-reduced-motion: reduce` 下整层 `display: none`：纯装饰，六十片花定在
半空比没有更糟。

另外「· 格物」里那颗点补了 `select-none` —— 字标本来就不可选，只有这个点是漏网的。

## 6. 列表页的液化玻璃

卡片与按钮的底色从实心纸面换成一层玻璃：`background-color: hsl(var(--card) / 0.125)` +
`backdrop-filter: blur(6px) saturate(120%)`，背后飘过的花瓣被虚成一团色，不再是贴在同一张纸上。
八分之一而不是一半：半透明时那层纸还是读得出来，花瓣只是「透过来」；再淡两档，页面底色和花
才真的成为玻璃后面的东西，虚化也才看得出来。

**为什么非虚化不可。** 降透明度只让人「看见背后」，背景本身没被折射，读起来就是一张灰纸；
`backdrop-filter` 才是「隔着玻璃」。`saturate(120%)` 把虚化后擦灰的花瓣颜色提回来一点；模糊压到 6px 是因为再虚下去，花瓣在玻璃后面就成了一团糊，看不出是花。

**玻璃的厚度。** 只有一道 `hsl(var(--foreground) / 0.12)` 的边框加那道斜向亮面。用 `--foreground`
而不是白色：浅色下是压暗的边线，深色下是提亮的高光，同一套值两个主题都成立 —— 写死一层白色高光，
深色下就成白疤（`AGENTS.md` §3.2）。**不在里面再垫一圈内阴影**：上下各一条一深一浅的内阴影，
上缘就是「边框 + 暗线」双重、下缘几乎看不见，一打眼就歪；而且 `hover` 换边框色时那圈内阴影
还压在原处，看着像高亮没盖住旧边框。

**用在哪。** 只有两种面：`GameCard` 封面下方那条页脚（`liquid-glass` 进页脚的 `div`），
以及**有底色**的按钮 —— 「进入工坊」、出错 / 空主题卡片里的按钮、空档的「看全部」，还有难度过滤里**未选中**的档位。
选中那一档仍是不透明朱色：玻璃底下压一层实色只会把红弄脏，何况它本身就是「当前筛选」的信号。
透明按钮（`ghost`，如页头的主题开关）不加：它本来就没有底色，罩一层玻璃只会多出一个没内容的框。

**卡片本体不垫玻璃。** 卡片 `bg-transparent`，封面是不透明的图直接盖住上半；只有下半那条页脚印在
页面背景与落花上。整块罩玻璃等于给封面蒙一层雾，而封面是作品内容，不该被背后那层花影响。

**hover 只有一种颜色。** 难度档位不再单独把边框染成 `primary/40`，而是和其它按钮一样
`hover:bg-accent`（边框保持玻璃那道 `--foreground / 0.12`）—— 同一页里两套 hover 语言，
人会以为哪一组是「另一个东西」。

**断点用现成的 `sm`，不新加 `orientation` 媒体查询。** 竖屏手机几乎没有宽过 640 的，
而桌面窗口再窄也该走这套紧凑布局 —— 「竖屏」在这页的真实含义就是「窄」，多一个媒体查询
只多一条以后要维护、却永远测不到差异的分支。


## 8. 页头透明 + 全局滚动条 + 只滚卡片区

四条要同时成立：页头透明（花瓣从字后面透过来）、落花只有一层且始终当背景、滚动条是窗口那一条、
滚起来的只有卡片。

**单层落花与「卡片从页头下穿过去」不能共存。** 花在页头之下、卡片又在花之上，那卡片必然盖住页头；
页头一透明就透出封面 —— 注入透明实测，字与地图封面直接叠成一片。所以不跟卡片抢 z，改让卡片在
页头下沿就被**裁断**。

- 页头不盖色：`.pinned-header` 只剩 `position: sticky; top: 0; z-index: 1`。它敢透明，是因为没有
  东西从它底下走。
- 卡片区 `.cards-viewport`：`position: sticky; overflow: hidden`，`top` 与高度由页头高度算
  （`calc(100dvh - 页头高)`），钉在页头下沿。滚出去的部分被它自己裁掉，所以它没有滚动条。
- 卡片轨道 `.cards-track` 的 `translateY(-window.scrollY)` 由 `GamesPage` 的 effect 直接写：
  页面滚多少，卡片就移多少。滚的是窗口，滚动条自然是全局那根，指针停在哪都能滚。
- 页面要补一段空白 `scrollRoom = 卡片总高 − (一屏 − 页头高)`，全局滚动范围才够长；滚到底时最后
  一张卡片的下沿正好贴住视口下沿。
- 高度会变：`ResizeObserver` 盯着页头与卡片轨道，改字号、换档位、转屏都重新量，`window.resize` 同理。
- 页头下沿不压阴影、也不压渐隐：切边本身就是提示（卡片在自己那块里被裁断），再加一道影子
  只是给这块带子添了不属于它的重量。曾经有两版（`--shadow-float` 四周带影、14px `::after` 渐隐），
  都收掉了。
- 带子里的纸宽按「上紧下松」分：字标行 → 主题块 32（`mt-8`）、主题块 → 难度档位 20（`mt-5`），
  档位到裁切线 28（`pb-7`）。档位是列表的控制器，压得离卡片近一点、离主题说明远一点，它才不会
  被读成主题信息的第三行。轨道自己 `pt 0`（卡片顶边就贴在裁切线上）、`pb 48`（滚到底最后一行
  不啃视口下沿）。竖屏对应 16 / 8 / 20 / 0 / 48。
- 被否掉的几条路：页头不透明（花瓣被挡在带子外面）；页头里再铺一层 `contained` 花（用户否掉：
  花只能有一个）；根节点 `h-dvh overflow-hidden` + 卡片区自己 `overflow-y-auto`（滚动条缩在
  `max-w-7xl` 里、指针必须先落进卡片区）；页头透明 + `backdrop-filter`（`0.72` / `blur(10px)`、
  `0.86` / `blur(8px)` 两档，带子里花瓣色像素只有 150 / 87，带外 5354 —— 9–26px 的花直接糊没）。
- 证据（1254 × 800）：页头高 260、`backgroundColor: rgba(0, 0, 0, 0)`；卡片区 `sticky`、`top 260`、
  高 540、`overflow: hidden`、`offsetWidth - clientWidth = 0`（没有第二条滚动条）；轨道高 1013；
  补偿 473 = 1013 − 540，正好等于 `maxScroll 473`；`scrollTo(0, 320)` 后轨道
  `transform: translateY(-320px)`；滚到底最后一张卡片 `bottom = 752` = 视口高 800 − 轨道 `pb 48`；
  `elementFromPoint(300, 40)` 落在页头、`(300, 400)` 落在卡片。390 × 844 时轨道 558 < 可见 635，
  补偿 0、页面本来就不滚。
- 玻璃没被这层 `transform` 打断：在花瓣层插一块 `#d0206a` 探针压在页脚玻璃下，探针中心从
  `(208, 32, 106)` 变成 `(242, 129, 174)` —— 背后照旧被采样。


## 9. 没做的

- **不删 logo 图片**：用户明确要求保留，它仍是品牌图源；不被 import 就不会进 `dist/`。
- **不追跨平台逐像素**：`0.071em` 是照这台机器的中文字体量的（「格物」走系统 UI 字体）。
  换 PingFang / Noto 时中文墨迹离基线的那点余量差零点几 px，字标就跟着偏零点几 px ——
  肉眼不可见，不为它上运行时测量。
- **不动「· 格物」**：它仍是 UI 字体 + `0.82 × height`，与 §2 的字标墨迹等高对齐；
  换成同一支打字机字体只加工作量，不解决任何现存问题。
- **不改字标的 8 个字母内容**：名字里的 RED 仍从 `indexOf` 算，不写死下标。
- **落花不做开关**：不挂暂停按钮、不随风速改密度、不随主题换图；它本来就不吃点击且
  `pointer-events-none`，不碍事就不添控件。
- **不升 `package.json` 的版本**：仓库三个 workspace 一直是 `1.0.0`，版本只体现在 `docs/`
  与提交信息里。
